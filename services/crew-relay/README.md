# 로컬 초대 서버

Docker·Steam·스토브 없이 게임이 실행되는 컴퓨터에서 방 관리와 중계를 실행한다. **게임 세계는 호스트 게임이 실행·저장**한다. 이 서버에는 세계 파일이나 개인 장비를 저장하지 않는다.

## 기본 사용 기준 — 서로 다른 집

협동의 기본 사용·완료 확인 기준은 서로 다른 집의 인터넷 접속이다. 같은 Wi-Fi를 요구하거나 외부 접속을 차단하는 방식으로 제한하지 않는다. 아래 로컬 두 프로세스 확인은 개발 확인이며 실제 외부망 확인을 대신하지 않는다.

1. 호스트는 같은 버전의 실행 파일을 친구에게 전달하고 게임에서 **방 만들기**를 누른다. 호스트 자신의 초대 서버 설정은 기본 `ws://127.0.0.1:24680/relay`로 두어 내장 서버를 자동 시작한다.
2. 호스트 공유기에서 **외부 TCP 24680 → 호스트 PC의 내부 주소 TCP 24680**을 연결하고 PC 방화벽에서 허용한다. 호스트 PC 내부 주소는 공유기의 주소 예약 등으로 유지한다.
3. 친구는 **연결 설정 → 초대 서버**를 `ws://호스트의-공인-IP:24680/relay`로 지정하고, 전달받은 초대 코드를 입력해 참가한다.
4. 실제 외부 접속 여부는 친구 집이나 별도의 모바일 네트워크에서 확인한다. CGNAT·이중 NAT는 아래 제약을 따른다.

같은 Wi-Fi에서도 같은 방을 이용할 수 있다. 다만 **공인 주소 그대로** 접속하려면 공유기의 NAT loopback/hairpin 지원이 필요하다. 지원하지 않으면 같은 Wi-Fi의 참가자만 내부 주소를 사용하면 된다. 향후 별도 공용 중계 서버를 사용하면 LAN·외부 참가자가 동일한 서비스 주소를 사용한다. [공유기 제조사의 NAT loopback 설명](https://community.tp-link.com/en/business/stories/detail/1726).

## 기본 실행 — 게임에 내장

별도 프로그램을 실행하지 않고 **초대 코드로 연결 → 방 만들기**를 누른다. 기본 주소 `ws://127.0.0.1:24680/relay`에 서버가 없으면 게임 자체가 초대 서버를 시작한다. 다른 컴퓨터에서도 같은 게임 코드가 동작하며 Python·Docker 설치가 필요 없다. 서버를 포함한 Godot 실행 파일의 Windows 실기 확인은 아직 하지 않았다.

자동 실행은 호스트가 방을 만들 때, `ws://127.0.0.1:포트` 또는 `ws://localhost:포트` 설정에만 적용한다. 외부 서버 주소나 `wss://` 연결 실패를 임의의 로컬 방으로 대체하지 않는다. 기본 내장 서버는 LAN 접속도 받을 수 있도록 TCP 포트를 연다. 방을 닫으면 코드는 만료되고, 게임 프로세스를 종료하면 내장 서버도 종료한다. 같은 컴퓨터에서 다른 호스트 게임이 이미 실행 중이면 그 프로세스의 서버를 공유하므로 서버를 소유한 게임을 종료하면 그 서버의 다른 방도 종료된다. 독립적인 수명을 원할 때 아래의 별도 서버를 사용한다.

**호스트 주소와 초대 코드는 별개다.** 같은 Wi-Fi의 친구는 연결 설정을 `ws://호스트의-내부-IP:24680/relay`로 바꾸고 코드를 입력한다. 다른 집은 아래의 외부 접속 조건이 필요하다. 친구에게 같은 버전의 실행 파일을 전달하면 출시·스토어 등록 전에도 테스트할 수 있다.

## 선택 사항 — Python 별도 실행 (macOS)

Finder에서 `tools/start_crew_relay.command`를 더블클릭한다. 또는 저장소에서:

```sh
./tools/crew_relay_local.sh
```

Python 3.10 이상이 필요하다. 첫 실행 때만 인터넷에서 고정 버전 의존성을 받아 `.local/crew-relay/venv`에 설치한다. 시스템 Python 패키지를 변경하지 않는다. 이후에는 같은 실행 명령으로 바로 시작한다. 서버 터미널을 켜 둔 상태로 게임을 실행하며 `Ctrl+C`로 종료한다. macOS가 다운로드 파일의 실행을 막으면 터미널에서 위 명령으로 실행한다.

게임에서 **초대 코드로 연결 → 방 만들기 → 코드 복사**, 다른 게임에서 **코드 입력 → 친구 방 참가**를 사용한다. 진행 중에는 P 승무원 메뉴에서도 코드를 복사할 수 있다. 기본 초대 서버는 `ws://127.0.0.1:24680/relay`이며 **연결 설정**에서 바꾼다. 개발 환경 변수 `CREW_RELAY_URL`로도 지정할 수 있다. 이 주소는 친구의 PC에서는 친구 자신의 PC를 뜻한다.

## 같은 집의 다른 컴퓨터

```sh
CREW_RELAY_BIND=0.0.0.0 ./tools/crew_relay_local.sh
```

친구의 연결 설정에 `ws://서버-PC의-내부-IP:24680/relay`를 입력한다. 방화벽의 TCP 24680과 공유기의 기기 간 통신이 허용되어야 한다. 호스트도 동일한 서버를 사용한다. 초대 코드에는 서버 주소가 포함되지 않는다.

## 다른 집의 친구

현재 임시 서버를 외부에서 접근할 수 있어야 한다. 공유기 **TCP 24680 포트포워딩 → 서버 PC**, PC 방화벽 허용, 친구의 공인 주소 설정이 필요하며 통신사의 CGNAT·이중 NAT 환경에서는 추가 대응이 필요하다. 기존 IP 직접 게임의 UDP 24560과 구분한다.

초대 코드는 방의 참가 권한이며 IP를 암호화한 문자열이 아니다. 내 컴퓨터가 중계 서버인 경우 친구는 내 서버의 접속 주소를 알아야 하므로 내 공인 IP를 숨기는 구성이 아니다. 출시용 공통 중계 또는 플랫폼 연결에서는 서비스 주소를 게임 설정으로 제공할 수 있다.

이 서버의 기본 `ws://`는 로컬 개발용 평문 통신이다. 공개 운영용 TLS·계정 인증·IP별 접속 제한·운영 모니터링은 포함하지 않는다. 외부 운영 시 TLS 프록시의 `wss://`와 운영 인증/제한을 마련해야 한다. 코드와 프로필 재접속 자격은 로그에 남기지 않는다.

## 선택 사항 — Docker

```sh
./tools/crew_relay.sh up
./tools/crew_relay.sh status
./tools/crew_relay.sh logs
./tools/crew_relay.sh down
```

Docker 기본 포트 공개도 `127.0.0.1`만 허용한다. LAN 시험은 `CREW_RELAY_BIND=0.0.0.0 ./tools/crew_relay.sh up`. 네이티브 서버와 동시에 같은 포트를 사용할 수 없으므로 하나를 종료하고 다른 것을 실행한다. 이 Compose는 `locus-crew-relay` 프로젝트만 관리한다.

## 동작·교체 경계

- 서버가 12자리 무작위 코드와 방 내부 peer ID를 발급한다. 호스트는 항상 1, 게스트는 같은 방에서 재사용하지 않는 ID다. 호스트 포함 최대 6개 연결이며 게임의 기존 캐릭터·재접속 정원 검사도 별도로 유지한다.
- 클라이언트는 연결된 소켓의 실제 ID로만 전송한다. 게스트는 호스트에게만 보내고 호스트는 본인 방의 참가자에게만 전송한다. 채널·전송 모드와 Godot RPC 바이트를 전달하며 세계 내용을 해석하지 않는다.
- 호스트가 떠나거나 서버가 재시작되면 코드가 만료된다. 호스트가 저장 세계를 다시 열면 새 코드를 발급한다. 자동 호스트 이전·서버만 켜 둔 부재중 게임 진행은 없다.
- `FrontierCrewLocalRelay`는 게임 내장 서버이고 Python `server.py`와 같은 wire protocol 1을 구현한다. 내장 버전은 `/health` HTTP 엔드포인트를 제공하지 않는다.
- `FrontierCrewRelayPeer`는 개발용 WebSocket/TCP 구현이다. 게임이 비신뢰 전송을 요청해도 이 경로에서는 순서 있는 신뢰 전송이므로 손실 시 지연과 채널 간 대기가 생길 수 있다. 버퍼·메시지·방 수와 전송량 상한이 있으며 초과 연결은 종료한다. 실제 6인 인터넷 성능 보장은 아니다.
- `FrontierCrewSession.host(..., transport)`와 `join_transport(...)`가 Godot `MultiplayerPeer` 교체 지점이다. 기존 ENet 직접 접속도 유지한다. Steam·스토브/EOS SDK 로그인·플랫폼 로비·전송 어댑터·스토어 간 크로스플레이는 **아직 미구현**이다. URL만 변경해서 Steam/EOS로 연결되지 않는다.

## 최소 확인 재현

내장 자동 서버를 확인하려면 별도 서버를 끈 상태에서 실행한다. Python/Docker 경로를 확인하려면 해당 서버를 켠 상태에서 같은 명령을 사용한다.

```sh
python3 tools/check_crew_relay.py
./tools/godot.sh --script res://tests/check_crew_relay_lobby.gd -- --crew-ui-test --crew-folder=/tmp/locus-relay-lobby
```

첫 명령은 임시 프로필·세계로 두 Godot 프로세스의 입장·준비·시작·재접속·호스트 종료를 확인한다. 두 번째는 실제 Forward+ 대기실의 잘못된 코드·복사·나가기와 960×640 화면을 확인한다. 게임 테스트의 기존 전체 묶음이나 실제 인터넷 검증을 대신하지 않는다.
