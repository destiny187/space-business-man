## 1. 확정 요구사항과 설계 제안

**사용자 확정 방향**

- 낮은 티어의 첫 행성에서는 적은 작업으로 성과를 얻는다. 티어가 올라갈수록 복원할 지역과 환경 조건을 점진적으로 늘린다.
- 한곳의 작업으로 행성 전체를 복원하지 않는다. 다른 지역의 자원과 환경 문제를 다룰 이유를 만든다.
- 행성에서 **Tab을 누르면 행성지도**를 연다.
- 지표 광물은 지역의 땅·지형에 맞게 군집을 이루고, 군집 밖의 듬성듬성한 예외 배치도 유지한다. 행성마다 다른 공급 지역을 찾아갈 가치와 보상을 둔다.
- 지하 광물·보석·동굴은 기존 시드 생성 방식을 유지한다. 이번 지표 재배치에 맞춰 지하까지 재설계하지 않는다.
- 테라포밍 관련 수급·생산·복원·보상 구조를 구현한다. 추가 탐험 콘텐츠 개발은 별도다.
- T3 이상 시설은 설계도로 해금한다. 획득 콘텐츠는 별도 작업에서 연결하며, 이 작업은 보유 판정과 제작 권한 접점을 제공한다.

**이 문서의 설계 제안**은 지역 수·군집 비중·시설 영향 계산·지도 세부 조작·단계 보상 배분·개발 순서다. 수치와 새 제품/시설 이름은 밸런스 확정값이 아니다. 방향 승인과 코드 구현 승인을 구분한다.

기존 [환경 적합도·평가](04-terraforming-and-sales.md), [광물 ID·장비 제한](14-minerals-gems-and-enhancement.md), [생산 단계·제품](15-terraforming-production-progression.md), [행성 간 공급 역할](17-planet-specialization-and-supply.md)의 정의는 유지한다. **이번 지역 연결·지표 군집·지도·중간 보상의 상세 규칙은 이 문서를 소관으로 한다.** 과거 T5에서만 복수 지역을 다루는 제안은 아래 T2부터의 점진 확장으로 대체한다.

## 3. 한 행성 안의 작업 구조

```mermaid
flowchart LR
    A[착륙지의 작은 생활권] --> B[Tab 지도에서 필요한 공급 지역 확인]
    B --> C[현지 채집·운반·제품 준비]
    C --> D[수원·토양·오염원 현장에 설비 배치]
    D --> E[해당 지역 복원·중간 보상]
    E --> F[이웃 지역의 복원 조건 충족]
    F --> G[목표 지역망 안정화·최종 정산]
    E --> B
```

지역은 서로 다른 역할을 가진다. 착륙지는 조립·보관, 암반 지대는 구조재, 퇴적 분지는 토양 처리 원료, 얼음 지대는 급수, 오염원 주변은 직접 처리 현장이 될 수 있다. 모든 지역에 공장 전체를 다시 짓지 않고, 필요한 취수·처리·전력·저장 시설만 배치한다.

지역 역할은 시드가 정한 실제 지형과 자원 후보 안에서 고른다. 모든 행성에 얼음 지대·염호·인산염 분지를 보장하지 않는다. 현지에 없는 공급은 기존 직접 운송·Lotus의 지원 품목 범위로 보완한다. 행성 내부 분산과 기존 행성 간 특화를 함께 유지한다.

### 공간의 세 단위

| 단위 | 역할 | 완료 표시 |
| --- | --- | --- |
| 시설 작업 구획 | 실제 설비가 처리하는 주변 면적·물질 | 시설 영향 범위와 남은 처리량 |
| 환경 지역 | 수원·토양·기후·유입원을 공유하는 구역 | 해당 지역의 적합도·필수 조건·안정 상태 |
| 복원 사업 | 계약에서 선택한 지역과 연결 조건의 묶음 | 목표 지역 충족과 사업 완료 |

렌더 청크·광맥 타일·환경 지역은 서로 다른 단위다. 청크가 로딩되거나 지역 경계 한 걸음을 넘었다고 환경값이 재설정되지 않는다. 지역은 지형을 따라 이어지는 경계와 고유 ID를 가지며, 플레이어 주변 원을 따라 이동하지 않는다.

T1은 작은 지역 사업만 끝내도 정상 보상과 다음 진행을 얻는다. **‘정착 구역 복원 완료’와 ‘행성 규모 복원 완료’를 구분**한다. 전 행성 평가를 지원하지 않는 개발 단계에서는 지역 사업 완료만 표시한다. 전체 미방문 표면을 임의로 완료한 것으로 칠하지 않는다.

## 4. 시설 영향과 지역 연결

### 국소 처리

- 설비는 지원하는 문제·정격·영향 범위 안에서만 작동한다. 지역 한구석의 소형 설비 하나가 지역 전체를 즉시 처리하지 않는다.
- 지역 내부의 거친 작업 셀에 처리 대상량과 상태를 두는 방식을 제안한다. 여러 설비의 범위가 겹쳐도 처리 면적은 합집합으로 계산하고, 각 설비가 소비한 입력에 해당하는 처리량만 누적한다.
- 같은 종류의 설비 추가는 처리 속도나 실제 도달 범위를 늘릴 수 있다. 기초 필터를 늘려 특정 가스 분리 능력을 얻거나 정격 밖의 환경을 무시할 수는 없다.
- 토양·수질·생태는 지역에 남는다. 대기·열의 주변 파급은 명시된 지역 연결과 전달량으로만 반영한다. 광역 대기 처리는 후속 전용 능력과 별도 물질 장부를 요구한다.
- 같은 위치의 지면색·습윤·식생·안개는 그 위치의 상태를 읽는다. HUD에 ‘지역 복원’이라고 적는 것만으로 범위 분리를 완료하지 않는다.

### 연결의 종류

| 연결 | 실제 조건과 플레이 | 단순화의 경계 |
| --- | --- | --- |
| 자원 공급 | 원료/제품을 실제 화물로 운반해 현장 재고에 넣음 | 지도 연결선이 원격 재고 차감·자동 운송을 대신하지 않음 |
| 수원과 수요지 | 수원 확보·처리 후 현장 급수. 초기에는 직접 운반한 실제 급수 입력으로 충족 | 취수 시설 하나로 행성 모든 창고에 물을 생성하지 않음 |
| 오염원과 영향 지역 | 해당 현장에 대응 설비를 설치해 유입량을 줄임 | 물건만 기지로 가져와 원격으로 오염원을 제거하지 않음 |
| 지역 유지와 생태 | 해당 지역의 토양·물·기초 배양 조건을 유지한 뒤 인접 지역의 정착을 도움 | 새 야생종 탐사·먹이망 개발은 이번 필수 조건에서 제외 |

자연 유역 연결은 고정된 수원·방향·전달 한도를 가진 집계 모델로 제안한다. 구현할 때 기존 굴착 수면의 물량과 교환 지점을 하나의 장부로 연결해야 하며, 연결 전에는 급수 입력 방식만 사용한다. 환경 점수인 ‘물 확보’를 실제 물 부피로 곧바로 변환하거나 같은 물을 유역과 물리 수면에 두 번 더하지 않는다. 자유 배관·컨베이어·자동 운송망은 이번 범위에 넣지 않는다.

지역은 `미관측 → 문제 확인 → 처리 중 → 조건 충족 → 안정`을 표시한다. 중단 시 입력 부족·유입원 미처리·정격 부족 등 실제 이유와 추세를 보여 준다. 복원 중 필요한 보급이 끊기면 처리 정지 또는 예고된 환경 변화가 발생하되, 이미 처리한 토양과 고갈 광맥을 통째로 초기화하지 않는다.

## 5. 티어별 확장안

지역 수는 **한 표준 사업의 예시**이며 행성 전체 지역 수나 강제 방문 횟수가 아니다. 인접 구역만 잘게 쪼개 수를 채우지 않는다. 각 지역에는 서로 다른 공급·처리 역할이 있어야 한다.

| 티어 | 범위 예시 | 추가 환경 문제 | 수급·시설 변화 | 사업 완료 기준 |
| --- | --- | --- | --- | --- |
| T1 | 작은 1지역 | 기초 대기·온도·급수·입문 생태 | 기존 기초 재료·설비·배양 경로 | 작은 정착 구역의 기존 입문 조건 |
| T2 | 가까운 2~3지역 | 염분·토양, 지역별 급수 | 규소/인산염 공급지 등 현지 유효 군집과 필터/토양 제품, 외곽 현장 배치 | 선택 지역의 필수 조건과 실제 공급 충족 |
| T3 | 3~4지역의 유역/환경망 | 시드별 특정 가스 또는 수질 오염, 지속 유입원 1종 | 대응 분리/중화 제품·순환 모듈, 원인 현장의 처리 | 원인 제어와 영향 지역 복원·유지 |
| T4 | 4~5지역의 광역 사업 | 극한 열/냉기 또는 부식, 복수 유입의 상호 영향 | 내환경 합금·열교환·정밀 제어, 선택적 외부 공급 | 정격 충족·전달 한도 내 운영·핵심 지역 안정 |
| T5 | 5~6개 핵심 지역과 광역 계층 | 광역 대기·물 순환, 지역 간 유지·자립 조건 | 고급 전달/안정화 코어·순환 제품, 유지용 공급망 | 지역별 기준과 광역 물질·에너지 조건 모두 충족 |

T2의 ‘급수 지역’은 항상 새로운 얼음 채굴장을 뜻하지 않는다. 현지 얼음·운반 급수 중 가능한 경로를 고른다. T3부터의 오염 유형과 T4 극한 조건도 행성 프로필에서 선택한다. 티어가 높아도 해당 행성에 없는 문제를 체크리스트에 추가하지 않는다. 고티어에서 같은 설비 수·소모량·대기 시간만 배수로 늘리는 방식을 피한다.

T5 자립은 무한 자원 생성이 아니라 **명시한 관찰 기간 동안 입력·전력·물질 손실을 감당할 재고와 처리 능력**을 뜻한다. 완전 폐쇄 생태계를 자동 전제하지 않는다. 유지가 필요한 시설은 계속 필요하다고 보여 준다. 광역 처리가 아직 없는 개발 단계의 T5에 행성 전체 완료 보상을 먼저 제공하지 않는다.

환경 적합도 네 항목과 평균 산식은 [기존 소관](04-terraforming-and-sales.md)을 유지한다. 사업 평가는 평균만으로 통과시키지 않고 필수 지역·조건·관측·안정성을 모두 검사한다. 부분 완료 보상은 가능하지만 미관측 지역을 100점으로 간주하지 않는다. 협동 인원 때문에 같은 환경 점수가 바뀌지 않으며 기존 사업량 계수를 면적과 투입량에 중복 적용하지 않는다.

## 6. 지표 광물: 지질 군집과 희소 배치

### 두 층의 배치

1. **공급 군집:** 지역의 원래 지질·지형에 맞는 여러 작은 광맥을 띠·노두 주변·분지 가장자리처럼 이어서 배치한다. 한 덩어리를 오래 캐는 방식으로 되돌리지 않는다.
2. **희소 광맥:** 군집 사이에도 행성이 허용하는 자원의 작은 노출 광맥을 듬성듬성 둔다. 예상 밖의 소량 채집은 남기되 핵심 물량은 공급 지역에서 확보하는 편이 유리하게 한다.

조정 시작안은 자원별 지표 매장량 예산의 **70~85% 군집 / 나머지 희소 분포**다. 비율은 예시이며 모든 자원·행성에 일괄 확정하지 않는다. 군집 추가를 기존 분포 위의 무료 매장량 증가로 처리하지 않고, 자원별 총량·광맥 수·군집 수·개별 잔량을 따로 배분한다. 먼 거리만으로 무조건 풍부해지는 기존 보너스도 새 지표에서는 군집의 공급 역할과 함께 재조정한다.

### 지형에 따른 공급 후보

아래는 게임용 지질 배치 예시다. 실제 특정 천체의 자원 관측이나 제조법을 뜻하지 않는다. 행성 광물 후보에 없는 자원을 지면색만 보고 생성하지 않는다.

| 지역의 기반 지형·지질 | 군집 후보 | 이번 테라포밍에서의 가치 |
| --- | --- | --- |
| 금속질 암반·산화 노두 | 철·구리, 허용된 경우 니켈 | 여러 현장의 구조·전력·내환경 부품 |
| 밝은 결정질 암반·노출 능선 | 규소, 허용된 보조 광물 | 여과·제어 제품 |
| 퇴적 분지·층리가 드러난 완경사 | 인산염·암석 | 토양 기반재·활성 제품·기초 배양 입력 |
| 실제 얼음이 존재하는 노출 지대 | 얼음 | 급수·초기 물 처리, 수입 부담 감소 |
| 염류·알칼리 광화 지대 | 프로필이 허용한 리튬·희토류 등 | 축전·정밀 처리 계통의 후속 수요 |
| 화산성 노두·열수 지질 | 허용된 황·금속 | 해당 문제에 정의된 화학·내환경 제품 |

행성마다 주력 군집의 조합·위치·규모·접근 경로가 달라진다. 같은 지질의 다른 지역도 밀도와 보조 광물이 다를 수 있다. 필수 물량을 가진 군집에는 실제 도달·작업 공간이 있어야 한다. 절벽·수중·기반암 아래 배치만 남기거나, 해당 광물로 만드는 장비가 있어야 첫 물량을 얻는 순환 잠금을 만들지 않는다.

착륙지 주변은 출항 화물과 제한 보급을 포함해 첫 설비를 준비할 수 있게 한다. **Lotus v4가 허용한 기초 원료 한 종류의 현지 누락을 다시 전종 보장으로 덮어쓰지 않는다.** 초반 T2 설계의 연구 구매 없는 개방과 수동 작업 선택도 유지한다. 작은 T1 사업을 위해 여러 외곽 군집을 필수로 돌게 하지 않는다.

### 생성과 변화의 분리

- 지도·실제 지표·광맥 배치는 동일한 기반 지질/지형 샘플을 참조한다. 먼저 광맥을 무작위로 뿌린 뒤 지도를 그럴듯하게 칠하지 않는다.
- 광물 생성은 원래의 지질을 읽고, 복원으로 변하는 풀·눈·습윤 피복은 별도 상태다. 물을 공급하거나 토양색을 바꿔 광맥을 재생성하지 않는다.
- 군집 경계는 부드럽게 흐트러지고 군집 내부에도 빈 곳이 있다. 모든 노두에 광맥이 붙거나 일정 간격의 격자로 배치되지 않게 한다.
- 지표 군집 전용 시드/버전을 분리한다. **현재 지하 슬롯의 ID·난수·자원·위치·매장량·보석·고갈 이력은 유지**한다. 현재 코드는 지표 슬롯 수 뒤에 지하 슬롯을 배정하므로 지표 슬롯 수 변경으로 지하 ID가 밀리지 않도록 기존 지하 계산을 독립 보존해야 한다.
- 기존 새 은하의 지하 생성 방식을 그대로 재사용한다. 이번에 더 깊은 보석·새 동굴·지하 자원 보상을 추가하지 않는다.

## 7. 재료·제품·크레딧 수급과 보상

### 수급에서 소비까지

| 필요한 것 | 공급 경로 | 소비 목적 | 부족할 때의 경로 |
| --- | --- | --- | --- |
| 기초 철·구리·암석·얼음 | 출항 화물·현지 광맥·기존 Lotus 지원 | 첫 설비·보관·전력·기초 급수 | 보유 무료 지원 또는 감당 가능한 유료 지원/직접 운송 |
| 규소·인산염 등 처리 원료 | 해당 행성의 공급 군집, 다른 공급 행성 | 기존 필터·토양 제품과 지역 처리 | 같은 행성 다른 유효 군집 또는 직접 수입 |
| 내환경·분리·순환 제품 | 앞 단계 원료와 기존/후속 생산 설계 | 특정 문제 처리·영향 범위·유지 효율 | 필요한 능력을 가진 제품을 생산/운송. 현행 상점에 없는 제품 구매를 대안으로 가장하지 않음 |
| 공동 크레딧 | 실제 지역 복원 단계 보상·기존 정상 수익 | 지원 비용·이용권·정의된 사업 지출 | 앞 단계의 확정 성과 또는 초기 보유 자산으로 다음 필수 지출 충당 |

새 화폐·탐험 토큰·보석 의무 소비를 만들지 않는다. 원광·가공품·크레딧의 기존 역할을 사용한다. 신규 제품을 추가할 때는 [생산 소관 문서](15-terraforming-production-progression.md)에 입력·출력·최초 제작 가능 단계·소비처를 정의한다. 후속 사용자 요청에 따라 T3 이상 시설은 설계도 획득을 전제로 한다. 획득·정거장 판매는 [경제 소관 규칙](05-economy-and-progression.md)의 별도 작업이며, 여기에서 임시 무료 설계도를 지급하지 않는다. 기존 연구 해금 규칙을 우회하는 무료 상위 기술 지급도 하지 않는다.

조달 계획에는 **한 단계의 건설 물량 + 안정화까지의 운영 물량 + 필요한 운반/보급 여유**를 묶어 표시한다. 한 개의 부품 부족 때문에 매번 되돌아가게 하지 않는다. 현장 재고·개인 가방·공동 선박 화물·예약 물량을 구분하고, 지도에 보이는 다른 현장의 물건을 즉시 제작에 사용할 수는 없다.

### 특정 지역을 찾아간 보상

- **채집 보상:** 필요한 원료의 여러 광맥을 가까이에서 확보해 채집·운반 시간이 줄어든다. 희소 광맥은 소량 보충 역할이다.
- **복원 보상:** 수원 확보·오염원 제어·토양 복원처럼 실제 기능이 완성되면 계약의 중간 대금을 받는다. 단순 도착·지도 클릭만으로 반복 재화를 주지 않는다.
- **운영 보상:** 검증된 현지 급수나 원인 제어로 이후 투입 물량·손실이 줄어든다. 감소한 운영비도 지도와 설비에서 확인한다.
- **사업 확장:** 먼저 끝낸 지역의 성과가 다음 지역에 투자할 자금과 공급 여유를 만든다. 인접 지역은 언제든 조사·직접 작업할 수 있으며 강제 퀘스트 순서를 일반 잠금으로 만들지 않는다.

중간 보상은 계약 총액의 일부를 미리 나누어 지급하는 안을 사용한다. 예를 들어 T2의 수원·토양 단계에 각각 총액의 25%, 마지막 연결·안정화에 50%를 배분할 수 있다. 이는 예시이며 실제 총액·배분은 데이터로 정한다. **최종 정산액은 확정 계약 대금에서 이미 지급한 금액을 뺀 잔액**이다. 기존 마일스톤 보상과 겹치는 성과는 새 계약에서 대체 관계를 정해 이중 지급을 막는다.

계약·단계 ID마다 지급은 한 번이다. 시설을 철거/재건하거나 오염을 재발시켜 같은 단계 대금을 다시 받을 수 없다. 여러 승무원이 동시에 완료해도 공동 원장에 한 번 지급한다. 이미 적법하게 지급한 지역 보상은 단순 환경 저하로 소급 회수하지 않되, 최종 완료에는 현재 안정 조건을 다시 확인한다.

생산 거점 보유/인계는 기존 권한을 유지한다. 새 계약은 착수 시 정산 선택별 전체 지급 한도를 명시하고, 중간 지급 합계가 낮은 선택의 총 지급액을 넘지 않도록 배분한다. 같은 시설의 인계 대금과 계속 운영할 권한을 함께 얻지 않는다. 기존 계약의 지급률·진행을 소급 재계산하지 않는다.

현지 자원을 모두 고갈시킨 뒤에도 재접속 재생성으로 해결하지 않는다. 필수 단계의 예산과 접근 가능한 대체 공급 경로를 계약 생성 시 마련한다. 현재 Lotus가 제공하지 않는 규소·인산염·고급 제품은 새 무제한 보급 목록으로 조용히 추가하지 않는다.

## 8. Tab 행성지도

행성지도는 **어느 지역에 무엇이 있고, 어디를 바꾸었으며, 다음 물량을 어디서 조달할지** 보여 주는 공간 화면이다. [FIELD v1](../production/22-uiux-guide.md)의 지도·아이콘·상태 우선 원칙을 따른다.

### 입력과 공간 범위

- 지표 체류 중 Tab으로 현재 행성지도를 열고 같은 키 또는 Esc로 닫는다. 로버 탑승·지하 체류에서도 현재 행성의 지표 지도를 보되 지하 위치는 깊이 표식으로 구분한다. 새 지하 단면 지도는 후속이다.
- 우주 항해의 Tab은 기존 항해 화면을 유지한다. 행성지도에 항성계 지도 전환 진입점을 두어 기존 목적지·생산 거점 조회를 잃지 않게 한다. 원격 열람 중 실제 출항 권한/선박 상호작용을 우회하지 않는다.
- 확대/축소·드래그·현재 위치로 복귀·목적 표식을 제공한다. 다른 큰 메뉴와 중첩하지 않고 뒤의 이동·채집·발사·스캔·차량 조작 입력을 차단한다. 개인 지도를 열어도 협동 세계는 진행된다.
- 첫 지도는 현재 생성되는 지표 좌표와 지역 경계를 정확히 그린다. 확대 단계는 `현장 → 연결 지역 → 현재 지원하는 지표 범위`다. 궤도 대륙과의 정확한 일치·전 구면 지도를 이번 지도 이름만으로 약속하지 않는다. 범위 밖은 미지원, 미관측 지역은 미관측으로 서로 다르게 표시한다.

### 화면 구성

| 화면 요소 | 기본 표현 | 선택 상세 |
| --- | --- | --- |
| 바탕 | 실제 지형 기반 높낮이·암반·퇴적·얼음·수역 구분 | 지역 이름·지질·거리 |
| 자원층 | 공급 군집의 흐린 범위와 대표 광물 아이콘 | 발견 상태·확인한 잔량·채집 등급·제품 용도 |
| 환경층 | 처리된 면적·미복원 영역·문제 아이콘 | 지역 네 항목·제한 원인·유지 상태 |
| 시설·공급층 | 실제 시설 위치·가동/중단·연결선 | 현장 재고·소모품·처리량·중단 이유 |

지도 중앙은 공간을 크게 사용하고, 선택한 지역의 짧은 카드만 옆에 둔다. 자원·환경·공급 레이어를 전환해 모든 아이콘을 한 번에 덮지 않는다. 색과 함께 무늬·아이콘으로 미관측/처리/안정을 구분한다. 960×640에서도 지도 조작과 닫기·레이어 전환은 항상 보여야 한다.

### 관측 정보

기존 선박 조사에서 알 수 있는 자원 종류와 이번 기반 지형으로 **대략적인 공급 후보 지역**을 제시한다. 이것은 새로운 유적 탐험 기능이 아니라 조달 길 찾기다. 방문/기존 E 스캔으로 확인한 광맥만 정확한 위치·잔량을 공개한다. 후보 범위가 모든 매장량을 확정한 것은 아니다.

지하 보석과 광맥의 전체 좌표는 공개하지 않는다. 기존에 발견한 지하 대상은 지표 투영 표식과 깊이만 선택적으로 보여 준다. 공동 원정의 확인된 조달 정보와 지역 복원은 공유하고, 임시 목적지 표식은 개인 선택으로 둔다. 원격 지역 데이터가 오래되었다면 마지막 관측 시각을 표시한다.

## 9. 첫 대표 T2 사업 예시

다음은 규소·인산염이 실제로 허용된 행성의 한 사례다. 다른 행성에는 다른 공급 조합을 고른다.

1. 착륙지에서 출항 화물·현지 기초 광맥으로 최소 전력·작업 공간을 마련한다. 초기 지상 시설을 자동 배치하지 않는다.
2. Tab 지도에서 결정질 능선의 규소 후보와 퇴적 분지의 인산염 후보를 확인하고, 이번 필터/토양 제품 묶음에 필요한 물량을 표시한다.
3. 여러 작은 광맥이 모인 공급 지역에서 수동으로 채집한다. 로버·채광 로봇은 운송·반복 작업을 돕는 선택이며 필수가 아니다.
4. 준비한 필터와 급수 입력을 수원/급수 현장에 운반해 설비를 배치한다. 그 지역의 염분·급수 상태가 개선되고 해당 중간 대금이 지급된다.
5. 토양 활성 제품을 분지 현장에 투입한다. 두 지역의 색·습윤·식생 변화는 각자의 처리 범위에서 보이며 착륙지 밖 전체가 동시에 변하지 않는다.
6. 착륙지 정착 구역까지 필요한 실제 입력을 공급하고 각 목표 지역을 안정시킨다. 전체 사업의 조건을 충족하면 남은 대금을 정산한다.

공급 군집 수와 계약 지역 수는 같을 필요가 없다. 하나의 능선에서 두 현장 몫을 함께 채집하거나 수입품으로 보완할 수 있다. 다른 지역에 가야 하는 핵심 이유는 **그곳의 환경을 직접 처리해야 하기 때문**이며, 원료를 수입했다고 현장 작업까지 생략되지는 않는다.

## 10. 데이터·저장·협동 구현 제안

| 데이터 경계 | 맡을 상태 |
| --- | --- |
| `surface_region_manifest` | 시드·생성 버전·지역 ID/경계·기반 지질·공급 역할·문제 원형 |
| `surface_cluster_rules` | 기존 광물 ID 참조·군집/희소 예산·후보 위치·광맥 고유 ID |
| `regional_environment` | 작업 셀 상태·지역 유입원·처리량·관측·안정 이력 |
| `regional_links` | 연결 종류·방향·용량·실제 공급/전달 이력 |
| `terraform_contract_profile` | 고정 목표 지역·필수 조건·단계 보상·인원 사업량·정산 선택별 총액 |
| `planet_map_knowledge` | 확인한 지역/광맥·공동 조사 정보·관측 시각 |

명칭·저장 구조는 구현 제안이며 현재 파일이 존재한다는 뜻이 아니다. 원광 ID·제품 레시피·환경 점수 공식을 여기서 복제하지 않는다. 지도는 지형 샘플과 호스트 원장의 조회 결과를 표시하며 별도의 진짜 환경값을 갖지 않는다.

새 지표 군집·지역 계약 규칙은 새 세계 생성 버전에 적용하는 안을 기본으로 한다. 기존 세계는 미방문 영역도 기존 생성 버전을 유지하고 광맥·고갈·굴착·시설·계약·보상·지하를 재배치하지 않는다. 기존 세계의 Tab 지도는 기존 지형/관측을 읽는 범위로 지원하며 새 군집이 없는데 있는 것처럼 그리지 않는다. 기존 세계에 새 지역 사업을 이식하는 방식은 별도 이행 설계 후 적용한다.

호스트가 채집·제품 투입·가동 결과·환경 상태·단계 지급을 확정하고 저장 후 공개한다. 여러 지역에 나뉜 승무원은 각 위치의 환경을 받으며, 마지막 방문 지역의 상태가 다른 지역을 덮지 않는다. 부재중 환경 처리는 실제 입력·전력·용량이 허용하는 호스트 세션 시간만 집계한다. 현실 시간 오프라인 진행과 자동 화물 운송은 추가하지 않는다.

행성지도 때문에 전 지형·광맥·생물 Node를 로딩하지 않는다. 거친 지역 윤곽은 캐시하고 확대/관측한 타일만 상세 표시한다. 환경은 활성 작업 셀과 영향을 받는 연결을 집계하며, 기존 단일 환경 적용보다 늘어나는 갱신·패킷 비용은 첫 다지역 구현 단계에서 최소 범위로 확인한다.

## 11. 개발 순서와 완료 경계

아래는 전체 개발 순서다. 2026-09-09 첫 구현은 R01~R04의 T1/T2 지역 사업이며, 세부 완료 범위와 미연결 항목은 제작 기록에 둔다.

| 단계 | 개발할 것 | 최소 완료 확인 |
| --- | --- | --- |
| R01 지역 기반·저장 | 지형/지질 지역 ID·경계·구/신 버전 분리 | 같은 좌표의 지역 재현·기존 저장 보존 |
| R02 지표 공급·기본 지도 | 군집+희소 광맥·Tab 지형/자원/목적 표식 | 대표 새 행성에서 지도→군집→실제 채집, 기존 지하 ID/배치 보존 |
| R03 국소 환경·시설 범위 | 작업 구획·지역별 상태·위치별 풍경·환경 지도층 | 한 곳을 처리해 다른 곳까지 완료되지 않음, T1 작은 사업 유지 |
| R04 T2 지역 사업·중간 대금 | 대표 2~3지역·급수/토양 현장·실제 운반·단계 원장 | 대표 T2 채집→제품→현장 처리→지도 변화→단일 정산·저장 재개 |
| R05 T3 원인 처리 | 특정 문제 제품·유입원·영향 지역·부재중 집계 | 원인 미처리와 해결 후 결과 차이, 필요한 입력의 조달 가능성 |
| R06 T4 극한 조건 | 정격·내환경 제품·복수 영향의 단계 도입 | 기초 설비 증설과 전문 처리의 역할 차이 |
| R07 T5 광역 평가 | 지역망과 별도 광역 장부·유지·평가 | 국소/행성 완료 분리, 물질·보상 중복 없음 |

첫 플레이 묶음은 **R01~R04**로 삼고 T3~T5는 순차 확장한다. 지도와 군집만 구현한 상태를 테라포밍 고도화 완료로 기록하지 않는다. 추가 탐험 요소는 이 기반 위의 다음 변경으로 별도 기획한다.

모델·재질·시설 가동·효과는 [INK v1](../production/06-rendering-quality-standard.md)과 [Blender 공통 규격](../production/49-common-blender-art.md), 사운드는 [ElevenLabs 지침](../production/02-audio-and-elevenlabs.md)을 따른다. 기존 자산을 재사용해도 현재 게임의 실제 범위 변화·가동·재생 연결을 확인한다. 숫자와 지도 색만 바꾸고 지표 풍경이 전역으로 변하는 상태는 완료가 아니다.

프로젝트의 테스트 최소화 지시를 유지한다. 문서 변경에는 게임 테스트를 실행하지 않는다. 후속 구현은 해당 단계의 대표 실제 화면·핵심 동작·저장 확인으로 한정하고, 발견한 버그의 재현·원인·수정 확인이 필요할 때만 넓힌다. 전체 회귀·전 시드·6인·장시간 검증을 각 단계마다 관행적으로 반복하지 않는다.

R05의 구체적인 작업 목록은 [T3 테라포밍 구현 항목](../planning/14-tier3-terraforming-implementation.md)에 둔다. 탐험·설계도 획득 콘텐츠는 별도 작업이며 4현장·문제 2유형·전문 시설 구성은 구현을 위한 제안이다.

2026-09-09 후속: R05의 T3 원인 제어·두 문제 유형·전문 생산·네 현장·단계 정산은 [T3 제작 기록](../production/100-tier3-terraforming.md)에 구현했다. 탐험/설계도 획득과 R06~R07은 별도다.

## 12. 남은 조정 항목

- 지역 면적·거리·수, 군집 비율·총량·개별 광맥 잔량과 로버 화물에 맞는 조달 묶음.
- T3~T5의 실제 문제 프로필·제품·투입량·유지 예산과 기존 연구 해금 연결.
- 계약 총액·중간 지급 배분·생산 거점 보유/인계의 경제 균형.
- 자연 유역과 기존 물리 수면의 연결 범위, T5 광역 장부와 행성지도 확장 방식.
- 기존 세계에 새 지역 사업을 도입할지 여부와 별도 이행 범위.

현재 구현은 새 세계에 저장한 `regional_rules` 버전을 사용한다. 기존 세계에는 지역 계약을 강제로 추가하지 않는다. 예시와 실제 데이터 수치·확인 범위는 [구현 기록](../production/98-regional-terraforming-and-map.md)에서 구분한다.
