# 항해 중 해적 습격과 우주선 전투

2026-09-12 **개발 승인·두 이동 구간의 첫 구현**. 사용자는 항성계 이동 중 비행 해적 습격을 제안하고, 성간 이동과 같은 항성계 내부 이동 모두를 개발 대상으로 확정한 뒤 “응 개발진행해줘”로 실행을 승인했다. 원정선의 직접 교전·FINCH 독립 도주·인양·긴급 복구를 현재 원정에 연결했다. 실제 코드·Blender/INK·음원 재사용·확인 범위는 [첫 제작 기록](../production/139-pirate-flight-combat.md)을 따른다. [공동 원정선+소형 전투정 방향](27-ground-and-flight-combat.md)의 독립 포탑과 전투정 출격은 후속이다.

이 문서는 해적 습격의 단일 소관이다. **두 이동 구간 포함은 확정 요구사항**이다. 첫 구현은 아래 제안을 바탕으로 목적 항성계 감속 시점의 차단, 추격기/교란선, 기존 화물 보존을 채택했다. 수치와 세부 조작은 조정 가능한 초기 밸런스이며 별도 사용자 확정값으로 취급하지 않는다. 대기권 공중전·지상 폭격은 이번 범위에 포함하지 않는다.

## 2026-09-12 후속 확정 — 설명 최소화와 비행체 교신

사용자는 첫 위험 안내 외에 별도의 상황 설명을 띄우지 않고, 필요한 멘트는 비행체 간 교신으로 보여 주도록 요청했다. 접근 전조의 **해적 접근**만 중앙에 짧게 표시한다. 이후 습격/격퇴/추격 종료/복구 등의 단계 제목과 상시 조작 문장, 인양/정비 중이라는 문장을 표시하지 않는다. 구분자 점으로 묶은 안내도 제거한다.

기체 식별·실드/선체/열·공격 전조·탈출 표식과 상호작용 키/비용은 간결한 표식과 수치로 유지한다. 실제 실패 이유는 해당 작업을 시도했을 때만 알린다. 인양/정비 진행은 아이콘·진행 막대·실제 기체 동작으로 표현한다.

필요한 대사는 **발신 선박 → 수신 선박/편대**와 짧은 본문으로 화면 한쪽에 잠시 표시한다. 첫 구현은 교전 시작 때 해적의 호출과 도주가 성립했을 때 철수 교신이다. 매 타격·처치·상태 변화마다 대사를 넣거나 플레이어의 답변을 자동으로 만들어 주지 않는다. 호스트가 실제 상태 전환을 확정했을 때 살아 있는 해적 한 척을 발신자로 선택한다. 메뉴를 닫거나 저장을 다시 열었다고 과거 교신을 재생하지 않는다. 현재는 교신 자막이며 새 음성 대사를 생성한 것은 아니다. 실제 화면 확인은 [제작 기록](../production/139-pirate-flight-combat.md)을 따른다.

## 2026-09-12 후속 승인 — 공격 동작과 전투 표현 완성

사용자는 기체 가독성·공격 기동/애니메이션·피격/파괴의 세 가지 품질 개선을 승인하고 공격 모션의 완성도를 우선했다. 현재 추격기의 접근·감속 조준·실제 돌입/측면 통과·롤 이탈과 교란선의 감속·장치 전개·충전 사격을 적용한다. 날개·에어브레이크·벡터 노즐·포신이 각 단계에 맞춰 움직인다. 적 탄은 실제 이동 중 호스트 충돌 판정을 받으며 고정한 조준 지점에서 벗어나 회피할 수 있다.

기체 전용 보조광과 카메라, 실제 선체에 부착한 함포·포구 조준 보정, 부착형 실드 파문·선체 불꽃·무력화 회전과 지연 폭발/실제 부품 파편을 연결했다. 첫 위험 안내와 짧은 교신 규칙을 유지한다. 초기 수치·Blender 원본/INK·현재 원정 동작과 저장/음원 확인은 [품질 제작 기록](../production/141-pirate-combat-quality.md)을 따른다. 이번 승인은 기존 두 항해 구간의 전투 품질 고도화이며 독립 포탑·전투정 출격·대기권 전투의 개발 완료로 확대하지 않는다.

## 2026-09-12 후속 정정 — 폭발과 카툰풍 경고음

사용자는 어색한 폭발을 교체하고 조우에 항성계 진입음과 구별되는 전용 경고음을 요구했다. 이어 위협음에도 카툰풍 게임의 톤을 유지하도록 정정했다. 짧고 탄력 있는 전자 경보로 위험을 알리고, 거친 금속 경보나 공포스러운 위협 음색을 피한다. 폭발은 짧은 섬광·방향성 분출·식어가는 잔광·실제 부품 파편으로 표현한다. 첫 경고 외의 설명과 선박 교신 원칙을 유지한다. [구현·음원·실제 확인](../production/143-pirate-blast-and-warning.md).

## 1. 첫 경험

**항해 중 접근 신호 → 해적의 진로 차단 → 직접 조종으로 교전 또는 도주 → 전투정 회수·전리품 인양 → 원래 탐험 재개.**

예시: 다른 항성계로 향하던 원정선이 목적지 외곽에서 감속한다. 레이더 가장자리에 빠른 기체 두 척이 나타나고, 앞쪽의 넓은 기체가 교란 장치를 펼친다. 플레이어는 원정선을 돌려 교란선을 공격하거나, 측면으로 가속해 교란 범위 밖의 진출로를 노린다. 동료는 포탑으로 추격기를 떼어 내고, 보유한 전투정으로 측면을 공격할 수 있다. 적이 물러나면 남은 화물을 회수하거나 바로 목적지로 이동한다.

위의 기체 수와 장면은 목표 경험의 예시다. 전투 승리가 기초 자원·테라포밍 진행의 필수 조건이 되지 않으며, 매번 항해를 중단시키는 반복 의무로 만들지 않는다.

## 2. 어디에서, 얼마나 자주 만나는가

| 구간 | 개발 범위와 첫 설계 제안 | 이유·경계 |
| --- | --- | --- |
| 성간 이동 | 개발 대상 확정·목적지 외곽 감속 구간의 차단을 첫 안으로 제안 | 기존 항성계 비행 공간에서 교전하고, 소형 전투정도 같은 항성계 안에서 출격 가능 |
| 같은 항성계의 행성 간 이동 | 개발 대상 확정·원정선과 FINCH의 직접 비행/자동 접근 중 습격 | 실제 현재 위치에서 추격·도주·선택적 동료 지원, 다른 행성 승무원의 작업 유지 |
| 항성과 항성 사이의 순항 한복판 | 후속 후보 | 항로 중단·별도 교전 공간·남은 항로 재개·전투정 주소/회수의 새 규칙이 필요 |

성간 습격의 첫 안은 **성간 이동 도중의 감속 구간을 차단**하는 방식이다. 항성계 내부 습격도 같은 개발 계획에 포함하며, 출현 위치와 추격/복귀만 구간별로 나눈다. 두 구간을 개발한다는 결정이 순항 한복판의 별도 전장까지 확정했다는 뜻은 아니다. 보이지 않는 성간 공간 전체를 자유 비행 가능하게 만들거나, 순항 한복판 전투가 이미 가능한 것처럼 표현하지 않는다.

- 해적 활동권과 항로 위험도를 연결한다. 알려진 항로에는 출발 전 위험 표식을, 미확인 항로에는 정보 부족을 표시한다. 미방문 항성계의 상세 행성/자원을 미리 공개하지 않는다.
- 태양계 시작 연출·기본 조작 안내·첫 성간 출항에는 습격을 넣지 않는다. 첫 발생은 T2 탐험권부터 제안하며, 행성 티어와 별도로 항로의 해적 위험을 정의한다.
- 새 원정에는 원정선의 기초 방어와 도주 수단이 준비된 뒤 발생 자격을 준다. 무기·방어가 없는 기존 저장에 불시에 공격을 추가하지 않는다.
- 성간 이동은 출발 시 적격 항로에 대해 한 번만 발생을 결정해 저장한다. 내부 자동 접근은 이동 구간 ID, 자유 비행은 충분한 실제 이동 거리/시간을 채운 관측 구간 ID로 한 번 판정하는 안이다. 메뉴 열기·목적지 재선택·매 프레임을 새 추첨으로 취급하지 않는다.
- 취소·왕복·짧은 항로 반복·저장 재개로 즉시 재추첨하지 않는다. 한 이동 구간 최대 한 사건, 사건 후에는 항해 횟수와 활동 시간에 따른 완충 구간을 함께 둔다. **두 구간이 원정대의 완충 기록을 공유**해 성간 습격 직후 행성으로 향하다 다시 습격당하지 않게 한다. 첫 묶음의 동시 습격은 원정대당 하나를 제안한다.
- 빈도는 낮게 시작한다. 발생률·완충 시간·적 수는 구현 시 데이터로 조정하며 현재 확정 수치는 없다. 지상 날씨 확률을 해적 확률로 복사하지 않는다.
- 해적이 먼저 접근하고 공격할 수 있다. 구조 요청을 수락해야만 싸우는 기존 선택 사건과 다른 유형이지만, 짧은 전조와 실제 도주 경로는 항상 제공한다. 경고를 확인하는 팝업 클릭을 전투 시작 조건으로 삼지 않는다.

### 항성계 내부 습격의 차이

원정선으로 행성에 접근하거나 FINCH로 물자를 나르는 동안 해적이 **현재 비행 위치의 바깥에서 접근**한다. 별도 전장으로 순간 이동시키지 않는다. 자동 접근 중에는 전조와 함께 감속하고 수동 조종으로 인계한다. 자유 비행 중에는 조종을 그대로 유지한다. 원래 목적지는 보존하되 해결 뒤 플레이어가 접근을 재개한다.

- 위협은 실제 피습 선박을 대상으로 한다. 다른 행성에 있는 승무원을 강제 소환하거나, 떨어진 선박 모두에게 같은 피해·교란을 적용하지 않는다. 지상 생산/탐험은 계속한다.
- **FINCH는 운송선으로 유지하고 격파를 요구하지 않는다.** 기본 선체의 기동·보호 성능으로 도주할 수 있게 전조·적 수·추적 범위를 조정한다. 기본 도주가 확인되기 전에는 해당 선체를 습격 대상에 넣지 않는다. 전투정 구매나 친구의 구조를 운송 재개의 필수 조건으로 두지 않는다.
- 동료에게 현재 위치와 구조 핑을 공유한다. 지원자는 같은 항성계에서 직접 비행해 와서 추격기를 공격하거나 피습 선박을 호위한다. 다른 행성에서 즉시 발사·수리하거나 순간 합류하지 않는다.
- 교란 범위와 추적을 벗어나면 같은 행성으로 다시 자동 접근할 수 있다. FINCH 도주에 성간 항해를 요구하지 않는다. 직접 비행으로 실제 안전한 항만 보호 범위까지 도달하는 경로도 제안하되, WARDEN의 전투 AI·자동 구조가 이미 존재한다고 가정하지 않는다.
- 접안/하역·착륙/이륙 연출·지표 로딩 중에는 새 습격을 시작하지 않는다. 교전 중 F/자동 접근으로 즉시 착륙해 추격을 지우는 우회는 막고, 이탈 조건을 달성하면 원래 착륙 규칙을 다시 사용할 수 있게 한다.
- 무력화한 FINCH는 같은 항성계의 안전 지점에서 기초 이동을 복구하는 안이다. 개인 장비·배낭·해당 FINCH 화물을 같은 소유자에게 보존하며, 모선/공동 창고로 자동 하역하지 않는다. 이미 있는 접속 종료자 회수 기능을 전투 중 무제한 탈출로 사용하지 않도록 전투 회수 상태와 구분한다.

## 3. 교전과 도주

| 단계 | 실제로 일어나는 일 | 플레이어가 읽는 단서 |
| --- | --- | --- |
| 접근 경고 | 해적이 탐지 범위 밖에서 접근하며 대상 선박의 측면/전방을 점유 | 방향 표식·짧은 탐지음·멀리 보이는 추진광 |
| 차단 | 교란선이 장치를 펼쳐 일정 범위 안의 고속 항해를 방해 | 장치 동작·공간 경계·현재 가능한 탈출 방향 |
| 교전 | 추격기의 예고 사격, 회피·감속 선회·펄스포 추적 사격 | 적의 기수/총구·탄도·실드 파열·선체 피격 |
| 격퇴 | 교란선/호위의 손상에 따라 적이 철수하거나 무력화 | 실제 이탈·추진 고장·교란 종료 |
| 이탈 | 교란 범위를 벗어나 추적을 끊고 항로 재개를 준비 | 범위 밖 여부·추적 방향·짧은 재가속 반응 |
| 회수·재개 | 출격기 귀환과 선택적 잔해 인양 뒤 목적지 접근 또는 새 항로 선택 | 귀환 기체·화물 실물·기존 항해 표식 |

교란은 선체의 조종·일반 추진·부스트·함포를 정지시키지 않는다. **교란선을 격파하면 방해가 사라지고, 격파하지 않아도 범위 밖으로 나가면 도주할 수 있다.** 가장 느린 지원 선체의 기본 상태로도 사격을 피하며 범위를 벗어날 길을 마련한다. 전투선 구매가 도주의 전제는 아니다.

도주는 범위 밖 이동과 추적 단절을 일정 시간 유지한 뒤 기존 이동으로 연결하는 안이다. 성간 습격은 목적지 접근이나 유효한 새 성간 항로로, 내부 습격은 직접 비행·행성 자동 접근으로 복귀한다. FINCH에는 기존 성간 출발 금지를 유지한다. 피격 한 번마다 모든 진행을 초기화해 영원히 탈출하지 못하게 하지 않는다. 해적의 추적 거리·시간에도 상한을 둔다. 적 전멸, 전리품 전량 회수, 새 연구 해금을 이탈 조건으로 요구하지 않는다.

성간 습격은 감속 과정에서, 내부 습격은 현재 비행 공간에서 해적의 접근을 연속적으로 보여 준다. 공격은 해당 참가자의 전장·입력 준비와 전조가 끝난 뒤 시작하며 로딩 중 피해를 주지 않는다. 개인 메뉴를 여는 것으로 협동 전투가 정지하지는 않는다.

첫 전투는 원정선의 기본 무장으로 **약 1~2분 안에 격퇴나 도주를 선택해 마무리**하는 것을 시범 목표로 삼는다. FINCH는 더 짧은 도주 중심으로 별도 조정하고, 구조자가 도착할 때까지 버텨야 하는 목표를 강제하지 않는다. 현재 측정값·확정 플레이 시간은 아니다.

## 4. 직접 싸우는 방법

기본은 기존 외부 비행 시점에 연결하는 후방 3인칭 조종이다. 마우스 선회·W/S 추진·Shift 부스트를 유지하고, 좌클릭 함포 사격·우클릭 조준 보조를 제안한다. 메뉴 선택이나 행성 클릭이 함포 발사로 함께 처리되지 않도록 조종/전투/메뉴 문맥을 구분한다. A/D 등 기존 선회 키를 횡추력으로 바꾸는 안은 별도 조작 검토 후 결정한다.

- 원정선은 무거운 선회와 넓은 방어 사격 범위, 전투정은 빠른 가감속과 측면 진입으로 개성을 나눈다. 원정선도 혼자 조종하면서 전방 연동 무장으로 모든 첫 목표를 처리할 수 있다.
- 첫 무장은 펄스포 한 계열이다. 선행 조준점·사격 가능 각도·짧은 연속 사격과 방열을 보여 준다. 기본 사격에는 별도 예비탄 생산을 요구하지 않는 안이다.
- 실드와 선체 내구도를 구분하고 실드는 공격이 끊기면 회복한다. 파열음/표면 반응과 장갑 충격을 구별하며, 선체는 안전 확보 후 정비한다. 교전 중 즉시 무한 수리는 허용하지 않는다.
- 항해용 입자 차폐·열 제어·항법 안정은 전투 실드/장갑과 다른 성능이다. KESTREL·SWIFT·MULE의 항속·화물 역할을 전투 등급으로 바꾸지 않는다.
- 기본 방어 설비는 기존 원정선의 필수 기능과 임무 모듈을 빼앗지 않는 별도 무장 장착점으로 제안한다. 위치·전력·성능·개장 비용은 선체별 설계가 필요하다.
- 잠금 미사일·방향별 실드·엔진/무장 부위 파괴·복잡한 전력 배분은 후속이다. 첫 교란 장치는 역할을 읽는 약점이지만 모든 선박의 전면 부위 파괴 체계를 요구하지 않는다.

## 5. 해적의 첫 두 역할

| 후보 ID | 형태와 행동 | 대응 |
| --- | --- | --- |
| `pirate_raider` | 가늘고 비대칭인 개조 동체·노출 추진기. 측면 접근→조준 예고→짧은 사격→이탈/재접근 | 선회·부스트로 사선을 끊고 지나가는 구간을 추적 사격 |
| `pirate_interdictor` | 넓은 동체·전개식 교란 장치. 진출로를 가로막고 호위 뒤에서 느리게 위치 변경 | 장치가 펼쳐진 구간에 집중 공격하거나 교란 범위 밖으로 우회 |

첫 원정선 솔로 편성은 추격기 1척+교란선 1척부터 제안한다. 익숙해진 교전에는 추격기 2척+교란선 1척을 후보로 두고, 동시에 플레이어를 압박하는 수를 제한한다. FINCH에는 같은 편성을 그대로 쓰지 않고 추격기 1척의 짧은 추격부터 조정한다. 인원수는 실제 해당 전장 참가자를 기준으로 보고 다른 행성의 승무원 때문에 적을 강화하지 않는다. 인원수에 따라 적 체력을 단순 곱하지 않는다. 세부 수치는 현장 조종을 확인한 뒤 정한다.

해적의 세력명·기원·지도자·유인 여부는 미정이다. 첫 제작은 무인 약탈정을 제안해 기존 전투의 표현 범위와 맞춘다. CooperTech는 제조사이며 해적과 자동으로 동일시하지 않는다. Space Y WARDEN 순찰기를 해적 AI로 전환하거나 정상 기업 선박의 적대/피해를 이번 범위에 끼워 넣지 않는다.

## 6. 혼자와 협동

| 선택한 행동 | 하는 일 | 필수 직책이 되지 않도록 할 조건 |
| --- | --- | --- |
| 원정선 조종 | 회피·사격각 확보·전방 연동 함포·도주 방향 선택 | 혼자도 격퇴/도주 가능 |
| 직접 포탑 | 조종사의 선회와 별개로 측면 추격기를 공격 | 비어 있으면 제한된 조종 연동 방어로 처리, 자동 승리 화력은 제공하지 않음 |
| 소형 전투정 | 교란선 측면 공격·모선 추격기 차단 | 미보유여도 같은 사건 완수, 구입/수납/출격은 별도 단계 |
| 지원·정비 | 목표 핑·위협 관찰·제한된 방어 복구·전투 후 인양 | 수리만 강제하는 고정 직업 없이 조종/포탑과 교대 가능 |

최대 6명과 개인 장비·공동 선체 소유를 유지한다. 전투정은 기존 방향대로 같은 항성계에서만 출격하고 **FINCH를 자동으로 전투정으로 바꾸지 않는다.** 출격기 수·격납 크기·가격·대여와 좌석 수는 아직 미정이다. 여섯 명에게 전투정 여섯 대를 지급하는 설계가 아니다.

전투정 출격 중 공동 성간 출발은 보류하며 전투정·조종사·화물을 회수한 뒤 진행한다. 통신 단절은 즉시 귀환 완료로 취급하지 않는다. 안전한 구간에서 이탈 조종사를 회수하는 절차를 설계하고, 선체 무력화 때도 별도 출격기와 소유자를 빠뜨리지 않는다. 솔로의 전투정 출격은 모선의 안전 대기/기초 방어를 갖춘 단계부터 연다. 모선을 자동 무적 상태로 두거나 무방비로 방치하도록 강제하지 않는다.

## 7. 보상과 실패

격파된 기체에 소량의 정비 부품·금속·회수 화물을 남기고 실제 접근·인양·화물창 수납으로 얻는다. 선박 개조 부품/설계는 후속 성장 후보다. 함포로 격파했다는 이유만으로 개인 가방에 총기나 돈을 즉시 넣지 않는다. 기존 [우주 화물 인양](../production/118-freight-salvage.md)의 실제 회수 흐름을 확장하되 현재 사건/시장에 전리품 판매가 이미 연결됐다는 뜻은 아니다.

- 첫 실패는 원정선 무력화→같은 항성계의 안전한 외곽 지점으로 긴급 회수→기초 이동 복구를 제안한다. 정거장이 없는 항성계에서도 복구 가능해야 한다.
- 첫 묶음에서는 개인 장비·연구·영구 선체·기존 적재 화물을 보존하고, 아직 인양하지 않은 전리품을 포기하는 안을 추천한다. 이미 선적한 전투 전리품은 일반 화물과 동일하게 취급한다.
- 완전 수리는 공동 비용/정비 재료를 사용하는 안이지만, 잔고가 없어도 기초 이동을 복구하고 원정을 계속할 수 있다. 수리비·회수 연출·선체 내구도 복원량은 미정이다.
- 화물창이 가득 차면 현장에 남기거나 선택해서 싣는다. 같은 잔해의 보상을 재접속·재접근으로 복제하지 않으며 공동 화물을 인원별로 중복 지급하지 않는다.
- 도주하면 처치 보상이나 강제 벌금을 주지 않는다. 기존 무료 성간 항해와 구형 저장의 외곽 귀환 예외는 유지한다.

## 8. 현재 코드와 연결할 경계

현재 `crew_navigation.gd`의 항해 상태는 `idle/approach/jump`이며, 성간 항로의 진행·도착을 처리한다. `space_patrol.gd`는 정상 경비 편대의 접근 확인이다. 두 기능이 있다고 해적·발사·피해·항로 차단까지 구현된 것은 아니다. 첫 구현은 별도 `space_combat.gd`와 `crew.space_combat` 기록을 두고 항해·호스트·현재 비행 화면에 연결한다. 정상 경비 편대에는 피해를 주지 않는다.

첫 외곽 차단 구현에서는 목적 항성계의 공간/주소 전환과 목적 행성 자동 접근을 구분한다. 공간을 준비하고 감속·전조를 마친 뒤 전투 조종을 허용하며, 교전 중 자동 접근/착륙이 진행돼 위험을 건너뛰지 않도록 한다. 실제로 도달하지 않은 행성을 방문 완료로 기록하지 않는다. 교전 종료 후에는 같은 목표를 다시 선택할 수 있고 이전 선박의 항해 조건을 그대로 검사한다.

설계상 사건 유형은 `pirate_interdiction`이며 실제 저장의 사건 ID는 `pirate:<순번>`, 변형은 `stellar_arrival/local_transit`이다. 지상 사건 카탈로그와 분리된 항해 전투 기록을 사용한다. 신규 해적 정의·호스트 전투 상태·기체 표시를 공유하고 출현/이탈/목적지 복귀를 구간별로 처리한다. 기존 지상 무기/생물의 상태나 진행 중인 지상전 변경을 재작성하지 않는다. 발사 감각·실드 피드백 원칙은 공유하되 개인 실드 수치를 선박에 그대로 복사하지 않는다.

| 저장/권한 대상 | 제안 원칙 |
| --- | --- |
| 발생 | 세계/규칙 버전·구간 변형·항로/관측 구간 ID·발생 순번·위험도·발생/비발생 결과·공유 완충 기록을 호스트가 고정 |
| 교전 | 사건 ID·단계·항성계/위치·피습 선박 ID·실제 참가자·원래 목적지·해적 상태·선박 실드/선체·교란/추적 상태 보존 |
| 입력 | 조종/포탑의 점유자·발사 순번·시각·사거리/사격각·방열을 호스트 검증 |
| 결과 | 명중·피해·무력화·실드 파괴·인양은 호스트 결과, 클라이언트는 임시 발사 연출과 구분 |
| 이탈/합류 | 입력 만료·점유 해제·현재 사건 동기화, 새 적/전리품 재추첨 없음 |
| 세계 재개 | 전장 준비·짧은 경고 뒤 저장 단계 재개, 전체 참가자 부재 중 교전 정지 |
| 정산 | 인양/복구 결과를 한 번 기록하고 저장 실패 시 미확정 보상을 공개하지 않음 |

첫 적용은 새로 생성하는 원정의 `space_combat.version=1`을 대상으로 한다. 기존 세계의 항로·진행 중 항해·선체를 소급 변경하지 않으며, 기존 세계에 추가할 경우 별도 활성화/기초 방어 지급·호환 정책을 먼저 정한다.

| P04 협동 포탑 | 직접 포탑·조종 인계·핑·지원과 원격 입력 | 같은 적/피해를 공유하고 점유 경합·이탈 처리 |
| P05 전투정 출격 | 전투정 1종·확정 획득 경로·수납·출격/귀환 | 모선 방어와 별도 비행→안전 회수→공동 항해 재개 |

P01~P03은 **두 이동 구간의 습격·격퇴/도주·회수**를 완결하는 첫 묶음이며 P02b를 선택적 후속으로 생략하지 않는다. FINCH는 도주로 완결할 수 있다. P04~P05는 기존 공동선+전투정 방향을 완성하는 후속 묶음이다. 처음부터 피해·소유·저장을 호스트 기준으로 만들며 협동 기반을 마지막 단계까지 미루지 않는다. [27 문서](27-ground-and-flight-combat.md)의 C03/C04는 이전 전투정·구조 사건 우선안으로 남기고, 이번 해적 첫 상황의 제안 순서는 이 표를 따른다. 두 구간의 개발 방향은 확정했으며 상세 일정·커밋 수·세부 밸런스는 아직 정하지 않았다.

모델은 Blender 원본/내보내기·가동 포탑·교란 장치·추진/손상 표현을 만들고 [INK v1](../production/06-rendering-quality-standard.md)과 [공통 제작 규격](../production/49-common-blender-art.md)으로 실제 Forward+에서 검수한다. 음원은 ElevenLabs의 함포·실드/장갑 피격·교란 전조·추진·무력화·회수를 사용하며 새 생성 또는 기존 재사용 출처를 기록한다. 첫 제작에서 추격기·교란선·펄스포의 Blender 원본/게임용 모델을 제작했으며, 음원은 기존 ElevenLabs 제작물을 재사용했다. 새 함선 전용 음원 생성은 하지 않았다.

HUD는 [FIELD v1](../production/22-uiux-guide.md)을 따라 실제 기체·위협 방향·조준점·실드/선체·방열·탈출 방향을 우선한다. 긴 전투 로그·단계명·대형 경고창을 상시 띄우지 않는다. 확정 명중 표식은 호스트 결과에 연결하며 색 외에 모양·동작·소리로 상태를 구분한다.

개발 때는 각 단계의 해당 행동·화면·소리·저장과 필요한 최소 원격 입력만 확인한다. 버그 증거 없이 전체 회귀·반복 실행을 늘리지 않는다. 실제 규칙·Forward+ 화면·재생 경로·저장 확인과 미확인 범위는 [첫 제작 기록](../production/139-pirate-flight-combat.md)에 기록한다. 전체 회귀·6인 실접속·장시간 빈도 측정은 수행하지 않는다.

## 10. 첫 구현 뒤 남은 설계

1. 첫 구현은 목적 항성계 외곽 감속에서 차단한다. 순항 한복판 전장은 별도 확장이다.
2. 긴급 회수·수리비·습격 빈도의 초기 밸런스를 실제 탐험에 맞춰 조정한다. 현재 화물은 보존한다.
3. 원정선 방어의 첫 범위와 소형 전투정 도입 시점·수납/획득 경로.

두 이동 구간의 개발·공동 원정선+소형 전투정 방향과 지상전의 기존 승인은 다시 결정할 항목이 아니다. 해적의 전체 세력 이야기·보스·함대전·추가 무장은 첫 항해 습격의 손맛을 정한 뒤 확장한다.
