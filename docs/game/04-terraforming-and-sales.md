# 테라포밍·행성 판매

## 확정 요구사항

자동화 기반을 확대한 뒤 대기 조성, 행성 온도 등을 사람이 살 수 있는 환경으로 맞춘다. 테라포밍 결과에 등급을 매겨 행성을 판매하며, 수익으로 기술과 다음 행성을 구매한다. 고대 문명의 잔해 발견 등은 매각 가치를 높일 수 있고, 문명을 살리는 선택은 판매 단가를 크게 낮춘다.

## 환경 모델 — 설계 제안

실제 천체 물리 전체를 재현하기보다 원인과 결과를 이해할 수 있는 게임용 모델로 시작한다. 아래 수치·조건은 실제 거주 적합성 판정이 아닌 게임 규칙이다.

| 환경값 | 내부 표현 | 개선 수단 | 화면에서 보이는 변화 |
| --- | --- | --- | --- |
| 기체 조성·대기압 | 기체별 비율 합계 1, 압력 수치 | 대기 처리·기체 공급 | 하늘색·안개·먼지 |
| 독성 | 0~100 지수 | 정화 설비·적응 미생물 | 지표 오염·입자 |
| 평균 온도 | 게임 내 °C | 가열·냉각 설비 | 서리·열기·지면색 |
| 이용 가능한 물 | 0~100 지수 | 얼음 처리·물 공급 설비 | 물웅덩이·수면·습윤 지표 |
| 생태 정착 | 0~100 지수 | 미생물·식생·동물의 조건부 정착 | 식생 밀도·생물 활동 |
| 안정성 | 최근 환경 이력에서 계산 | 지속 운영·적절한 설비 조합 | 안정/변동 상태 표시 |

각 행성 또는 구매자 프로필에 목표 범위와 허용 한도를 둔다. 적합도는 목표에 가까울수록 높으며, 산소·압력·온도는 무조건 높인다고 좋아지지 않는다. 기체 비율과 물질 공급은 검증 가능한 방식으로 갱신하고, 음수·무한대·범위 초과를 허용하지 않는다.

### 환경 변화 계산

```text
다음 상태 = 현재 상태 + (가동 설비 효과 + 생물 효과 - 환경 손실) × 경과 시간
```

이 식은 계산 구조를 나타내며 각 변수의 단위가 다른 상태에 동일한 상수를 쓰라는 뜻은 아니다. 시설 입력, 전력 공급, 가동 여부를 먼저 확정한 뒤 실제 운영 시간에 해당하는 효과만 적용한다. 연료나 재료가 부족하면 효과도 함께 멈춘다. 생물은 적응 범위를 만족할 때만 증식·생산한다.

MVP에서는 대기·온도·물의 개선과 기초 생태 정착을 검증한다. 기초 생태 기술을 구매하면 표준 미생물의 정착 명령을 사용할 수 있게 하고, 물·온도·대기 조건을 충족할 때 생태 지수가 증가하게 한다. 이 기본 경로에는 랜덤 발견 재료를 요구하지 않는다. 복잡한 기체 반응, 지역별 기후, 유체 시뮬레이션은 확장 범위다.

## 평가 모델 — 설계 제안

각 항목의 적합도를 0~100으로 정규화한다. 대기 적합도는 기체 조성·압력·독성의 적합도 중 최솟값을 사용하여 치명적인 결함이 평균에 가려지지 않게 한다.

```text
Q = 대기 × 0.30 + 온도 × 0.25 + 물 × 0.20 + 생태 × 0.15 + 안정성 × 0.10
```

| 등급 | 총점 기준 초안 |
| --- | --- |
| S | 90 이상 |
| A | 80 이상 |
| B | 70 이상 |
| C | 55 이상 |
| D | 35 이상 |
| F | 35 미만 |

필수 조건인 대기·온도·물이 각각 적합도 60 이상이어야 B 이상의 등급을 받을 수 있다. 안정성 기준을 충족하지 못해도 최대 C로 제한한다. 먼저 점수 등급을 산출한 뒤 이 상한을 적용하고, 화면에는 제한 사유를 표시한다.

안정성은 최근 일정 기간 목표 범위 유지 여부로 평가한다. 프로토타입에서는 **최근 120초 동안 대기·온도·물 적합도 모두 60 이상 유지**를 안정 조건으로 제안한다. 이력 부족은 ‘관측 중’으로 표시하며 안정성을 충족한 것으로 간주하지 않는다. 기간과 점수 환산은 데이터로 관리한다.

**테라포밍 완료**는 B 이상과 필수 조건·안정성 충족을 의미한다는 초안을 둔다. D·F 행성도 현 상태로 매각할 수 있지만, 완료 보상과 높은 단가를 얻지 못한다. 등급과 매각 가능 여부를 구분한다.

## 판매 가격 — 설계 제안

```text
판매가 = max(0, (시장 기준가 × 환경 가치 배율(Q, 등급 상한)
                 + 반출하지 않은 발견의 가산액
                 + 행성에 남기는 시설·로봇의 잔존가치
                 - 정리 비용) × 문명 선택 계수)
```

- **시장 기준가:** 행성 규모·자원·계약 조건 등에 따른 기본 시장 가치다. 구매가와 무조건 같지는 않다.
- **환경 가치 배율:** 점수와 등급 상한을 함께 반영한다. 상한에 걸린 행성이 고득점만으로 상위 등급 가격을 받지 않게 한다.
- **발견 가산액:** 유적의 보존·조사, 정착 생태 등 행성에 실제 남는 가치를 반영한다.
- **잔존가치:** 남기는 시설·로봇의 평가액이다. 회수 대상은 제외한다. 높은 등급이라는 이유만으로 무한 제작·매각 이익이 나지 않도록 검증한다.
- **문명 선택 계수:** [이벤트 문서](06-exploration-and-civilizations.md)에서 정의하는 선택 결과를 가격에 반영한다. 원안의 문명 보존 선택에는 큰 단가 하락이 존재한다.

계수·가격표는 아직 미정이다. 유물을 반출 판매하면서 같은 유물의 잔존 가치를 행성에도 더하지 않는다. 독립적인 발견 기록 가산점은 별도 항목으로 정의하고 중복과 구분한다.

사업 성과 화면은 판매가 외에 **행성 구매비·이번 회차 현금 지출·별도 반출품 매각 수익·순현금 변화**를 분리한다. 영구 기술 구매비는 영구 투자로 따로 보여 준다. 게임 내 무료 채집 재료를 현금 지출로 중복 계산하지 않는다.

## 판매 절차 — 설계 제안

1. 현재 환경값·등급·가격 내역과 제한 사유를 미리 보여 준다.
2. 회수 가능 로봇·물품을 선택하고 우주선 한도를 확인한다.
3. 회수 대상의 작업·운반·제작 상태를 정리한다. 회수 로봇의 화물은 행성 보관함에 내리며, 별도 반출 대상으로 확정한 화물만 계승한다.
4. 최종 화면에서 남는 자산, 반출 자산, 예상 현금, 판매 후 접근 불가를 명시한다.
5. 최종 확정 시 시뮬레이션을 잠시 멈추고 동일한 시점의 평가·회수·재고 스냅샷을 검증한다.
6. 고유 거래 ID로 회수, 소유권 종료, 대금 지급을 하나의 저장 거래로 반영한다.
7. 정산 화면과 다음 행성 구매 화면으로 이동한다.

예상 화면은 취소 가능하다. 확정 후에는 해당 행성에 다시 건설·채집할 수 없다. 실패·중단·재접속 시 거래가 반만 적용되지 않도록 [세이브 설계](../technical/02-data-and-save.md)를 따른다.

## 구현 시 확인할 상황

등급 경계값, 가중치 합계, 필수 조건 미달, 안정화 직전 판매, 자원·전력 단절, 유물 반출 중복 가산, 로봇 회수 후 잔존가치 제외, 중복 판매 입력, 저장 실패 후 재개를 확인한다. 평가 화면에서 ‘무엇을 개선하면 다음 등급이 되는가’를 설명할 수 있어야 한다.
