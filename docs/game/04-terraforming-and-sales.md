### 종합 환경 적합도 — 현재 T1/T2 구현과 확장안

HUD에는 **‘환경 적합도 64%’ 막대 하나**를 표시한다. 펼친 상세도 대기·온도·물·생태 네 아이콘만 먼저 보여 준다. 각 항목은 인간의 기초 정착을 기준으로 한 게임용 0~100 점수다. 실제 의학적 거주 안전 판정이나 행성 복원 작업 완료율이 아니다.

```text
종합 적합도 Q = (대기 A + 온도 T + 물 W + 생태 B) / 4
A = min(산소 적합도, 기압 적합도, 일반 독성 적합도, 적용된 특정 가스 적합도)
T = 온도 적합도
W = min(물 확보 적합도, 적용된 염분/수질 적합도)
B = min(생태 정착도, 적용된 토양/서식 조건 적합도)
```

네 항목은 동등 가중치로 고정한다. 추가 문제는 가장 관련된 항목의 최소값에 반영하므로 가스 종류를 추가했다고 점수 분모가 바뀌지 않는다. 해당 프로필에 없는 조건은 최소값 계산에서 제외하고, 필요한 조건인데 미관측이면 ‘평가 중’으로 표시한다. 관측 전 상태를 임의로 0이나 100으로 채우지 않는다. 안정성은 현재 환경 상태 자체가 아니라 유지 관찰이므로 막대 평균에서 빼고 별도 작은 안정/변동 아이콘으로 표시한다.

현재 `FrontierEvaluator.environment_report`가 기존 `scores`를 재사용해 네 항목을 계산한다. 염분은 `100-salinity`, 토양은 기존 `soil` 지수, 신규 특정 가스는 `100-gas_load`를 개발 기본안으로 쓴다. 가스 부하는 게임용 0~100 처리 지수이며 ppm이나 산소 분율로 가장하지 않는다. 정확한 실제 수치가 필요한 경우는 별도 메타데이터다. 예시 `A=40,T=80,W=60,B=20`이면 Q=50이다.

평균은 약점을 숨길 수 있으므로 적용된 필수 항목 미달이 있으면 막대 옆에 경고 표식과 가장 부족한 원인 하나를 표시한다. 예: 평균 75라도 ‘대기 부적합’을 계속 알린다. 단일 막대가 안전 보장/계약 완료를 대신하지 않는다. 계약이 끝났어도 생태 20점의 기초 정착 지역은 100%가 아닐 수 있다. 현재 평가 범위는 ‘지역 환경’으로 표시한다.

도메인 결과는 `environment_report={version, scope_id, scores, overall, limiting_factors, observed, stable}`이며 호스트가 공개한 현장의 실제 환경값으로 HUD/단말이 함께 계산한다. 파생 점수를 별도 저장하지 않는다. 기존 `report()`의 가중치/판매가·이미 저장된 계약 점수·30초/120초 구 기준을 이 UI 변경으로 덮어쓰지 않는다. 새 계약 프로필은 별도 버전으로 선택하고 구 계약은 기존 조건을 유지한다.

최종 협동 승인: [인원별 사업량 기준](12-host-coop-and-crew.md)에 따라 처리할 물질량/복원 규모를 늘린다. 환경 적합 범위·종합 막대 산식·티어별 안정화 시간은 인원수에 따라 바꾸지 않는다. 동일 상태의 환경 점수는 참가자가 달라도 같다. 규모가 늘어난 양과 처리량을 한 번 연결하고, 면적/소모품에 다시 같은 인원 배율을 곱하지 않는다. 현재 지역 환경 코드에 이 처리를 구현한 것은 아니다.

## 확정 요구사항

자동화와 탐험의 성과로 대기·온도·물·생태를 개선하고 평가·사업 수익을 얻는다. 2026-09-06 확장에서는 **발견 연구·생물 이식·유적·자연·문명 지식을 환경 개선에 활용**하고, 다음 행성은 구매 대신 탐사로 선정한다. 원안의 인간 거주 환경과 등급별 판매는 유지하며, 원주민과 합의한 목표·보존·복원 계약도 추가 설계한다. 보호 선택의 기존 매각 단가 감소와 새 수익 경로의 관계는 [문명 설계](10-alien-civilizations-and-diplomacy.md)를 따른다.

이 문서는 확장 목표다. 아래 기존 점수·가중치·120초 안정화는 초기 게임 모델의 참고값이며 확대된 실제 행성의 검증값이 아니다. 현재 기초 지역 복원·계약은 구현했고, 다단계 생태·광역 시스템은 후속이다. 실제 범위는 위 현장 사업 기록을 따른다.

2026-09-07 확정 방향: 초반 행성은 간단한 기계로 복원 가능하게 유지하고, 깊은 단계의 테라포밍은 가공 재료와 고티어 제품을 요구한다. [생산 단계·고급 제품 설계](15-terraforming-production-progression.md)에 5단계 생산안, 처리 능력·제작 공정·선행 조건·저장 보존을 정리했다. 단계명과 레시피는 제안이며 현재 구현 완료가 아니다.

## 환경 모델 — 설계 제안

실제 천체 물리 전체 대신 원인과 결과를 설명하는 게임용 모델을 쓴다. 아래 환경값은 지역 또는 밀폐 구획의 기본 상태로 확장한다. 천체의 관측 원본과 테라포밍 변경값은 분리한다. 수치·조건은 실제 거주 적합성 판정이 아닌 게임 규칙이다.

| 환경값 | 내부 표현 | 개선 수단 | 화면에서 보이는 변화 |
| --- | --- | --- | --- |
| 기체 조성·대기압 | 기체별 비율 합계 1, 압력 수치 | 대기 처리·기체 공급 | 하늘색·안개·먼지 |
| 독성 | 0~100 지수 | 정화 설비·적응 미생물 | 지표 오염·입자 |
| 지역 온도 | 게임 내 °C | 열원·열 교환·반사·대기 조절 | 서리·열기·지면색 |
| 이용 가능한 물 | 0~100 지수 | 얼음 처리·물 공급 설비 | 물웅덩이·수면·습윤 지표 |
| 생태 정착 | 0~100 지수 | 미생물·식생·동물의 조건부 정착 | 식생 밀도·생물 활동 |
| 안정성 | 최근 환경 이력에서 계산 | 지속 운영·적절한 설비 조합 | 안정/변동 상태 표시 |

각 목표종·구역·구매자·협약 프로필에 목표 범위와 허용 한도를 둔다. 적합도는 목표에 가까울수록 높으며, 산소·압력·온도는 무조건 높인다고 좋아지지 않는다. 기체 비율과 물질 공급은 검증 가능한 방식으로 갱신하고, 음수·무한대·범위 초과를 허용하지 않는다.

### 환경 변화 계산

```text
다음 상태 = 현재 상태 + (가동 설비 효과 + 생물 효과 - 환경 손실) × 경과 시간
```

이 식은 계산 구조를 나타내며 각 변수의 단위가 다른 상태에 동일한 상수를 쓰라는 뜻은 아니다. 시설 입력, 전력 공급, 가동 여부를 먼저 확정한 뒤 실제 운영 시간에 해당하는 효과만 적용한다. 연료나 재료가 부족하면 효과도 함께 멈춘다. 생물은 적응 범위를 만족할 때만 증식·생산한다.

기존 MVP에서는 대기·온도·물의 개선과 기초 생태 정착을 검증했다. 기초 생태 기술을 구매하면 표준 미생물의 정착 명령을 사용할 수 있게 하고, 물·온도·대기 조건을 충족할 때 생태 지수가 증가하게 한다. 이 기본 경로에는 랜덤 발견 재료를 요구하지 않는다. 확장의 지역 기후·생태 상호작용은 아래 방식으로 단계 도입한다. 완전한 기체 반응·연속 유체 시뮬레이션까지 요구하지 않는다.

## 지역에서 행성으로 — 확장 설계 제안

| 규모 | 실제 바꾸는 것 | 평가 범위 |
| --- | --- | --- |
| 시험 구획·돔 | 제한된 대기·온도·토양·생물 | 서식지 내부, 외부는 별도 표시 |
| 지역·유역 | 물 공급·토양·국소 기후·생태 연결 | 개발 면적·유역·주변 파급 |
| 행성 | 광역 대기·에너지 수지·큰 물 순환 | 전체 목표 구역의 관측과 미확인 영역 |

한 구획에 나무를 심었다고 행성 전체 생태가 완료되지 않는다. 평균값에 심각한 지역 문제를 숨기지 않고 목표 구역 충족률·최악 지역·관측 미완료·유지 자원·복구 추세를 보여 준다. 전체 행성 계약은 필요한 관측 범위를 충족해야 하며 국소 사업에는 해당 범위의 등급만 부여한다.

환경 변화는 `국소 제어 → 물·토양 기반 → 선구종 → 공생·정착 → 안정화 → 광역 연결`의 단계로 제안한다. 단계 일부를 건너뛰거나 병행할 수 있지만 생물 입력과 생존 조건은 생략하지 않는다. 높은 행성 티어가 높은 현재 생태·평가 등급을 보장하지 않는다. [티어 구분](11-galaxy-tiers-and-seeds.md).

### 물질·에너지·시간

- 기체는 종별 양과 공급·소비·유출을 관리하고 비율은 그 결과로 구한다. 압력은 총량·부피·온도 또는 명시한 게임 근사식으로 계산한다. 비율만 바꿔 산소·물을 무한 생성하지 않는다.
- 물은 얼음·액체·증기·저장량·유입·유출을 구분한 집계 장부로 시작한다. 수위가 바뀌면 통로·기지·서식지가 영향을 받는다.
- 열 효과는 열원·입사광·반사·저장·이동·외부 방출과 연결한다. 국소 냉각의 폐열을 같은 행성에 버리는 일과 행성 전체 냉각을 구분한다. [NASA 에너지 수지](https://science.nasa.gov/ems/13_radiationbudget/).
- 생물 출현·이식·공생·실패는 [생태 문서](09-discovery-research-and-ecology.md)의 조건을 따른다. 체온만으로 열 효과를 부여하지 않는다.
- 시뮬레이션 시간·항해 압축·생태 반응 지연을 분리해 표시한다. 가상 기술과 시간 압축으로 플레이 가능한 속도를 만들되 실제 행성이 몇 분 만에 변한다고 설명하지 않는다.
- 추세와 예상 도달 시간을 보여 주고, 전력 단절·기질 소진·과증식에는 원인과 조절 방법을 안내한다. 관측 부족이면 정확한 예측값 대신 범위로 표시한다.

### 여러 해결 경로

| 문제 | 표준 산업 경로 | 발견 기반 대안 | 고려할 부작용 |
| --- | --- | --- | --- |
| 저온 | 발전·열 교환·차폐 온실 | 검증된 발열 생물, 축열 구조 | 연료·기질·해빙 수위 |
| 과열 | 차광·반사·대기 조절·방열 | 반사 군락·열 교환 소재 | 광합성·발전·인접 지역 폐열 |
| 물 부족 | 얼음 처리·운송·재활용 | 응결 구조·수맥·현지 수문 지식 | 실제 물 원천·염분·유역 영향 |
| 독성·빈약한 토양 | 화학 처리·토양 제조 | 적응 미생물·분해자·광물 촉매 | 반응 부산물·다른 종과의 경쟁 |

발견 대안은 조건에 따라 투자·운영·풍경을 바꾸며 무조건 표준 설비보다 좋은 정답이 되지 않는다. 자연 고유의 모습과 원주민 서식지를 보존한 테라포밍도 목표로 선택한다.

## 평가 모델 — 설계 제안

다음 가중치·등급은 인간 거주 목표의 초기 기준이다. 원주민·생물·복원 계약은 별도 목표 프로필과 필수 조건을 적용하고 평가 화면에 대상·범위를 표시한다. 각 항목의 적합도를 0~100으로 정규화한다. 대기 적합도는 기체 조성·압력·독성의 적합도 중 최솟값을 사용하여 치명적인 결함이 평균에 가려지지 않게 한다.

```text
Q = 대기 × 0.30 + 온도 × 0.25 + 물 × 0.20 + 생태 × 0.15 + 안정성 × 0.10
```

| 등급 | 총점 기준 초안 |
| --- | --- |
| S | 90 이상 |
| A | 80 이상 |
| B | 70 이상 |
| C | 55 이상 |
| D | 35 이상 |
| F | 35 미만 |

필수 조건인 대기·온도·물이 각각 적합도 60 이상이어야 B 이상의 등급을 받을 수 있다. 안정성 기준을 충족하지 못해도 최대 C로 제한한다. 먼저 점수 등급을 산출한 뒤 이 상한을 적용하고, 화면에는 제한 사유를 표시한다.

안정성은 최근 일정 기간 목표 범위 유지 여부로 평가한다. 프로토타입에서는 **최근 120초 동안 대기·온도·물 적합도 모두 60 이상 유지**를 안정 조건으로 제안한다. 이력 부족은 ‘관측 중’으로 표시하며 안정성을 충족한 것으로 간주하지 않는다. 기간과 점수 환산은 데이터로 관리한다.

**테라포밍 완료**는 B 이상과 필수 조건·안정성 충족을 의미한다는 초안을 둔다. 처분 권한이 있는 D·F 행성도 현 상태로 매각할 수 있지만, 완료 보상과 높은 단가를 얻지 못한다. 등급과 매각 가능 여부를 구분한다.

## 판매 가격 — 설계 제안

```text
판매가 = max(0, (시장 기준가 × 환경 가치 배율(Q, 등급 상한)
                 + 반출하지 않은 발견의 가산액
                 + 행성에 남기는 시설·로봇의 잔존가치
                 - 정리 비용) × 권리·협약 계수)
```

- **시장 기준가:** 평가 범위·규모·자원·계약 조건에 따른 가치다. 행성 진입 구매비와 연결하지 않는다.
- **환경 가치 배율:** 점수와 등급 상한을 함께 반영한다. 상한에 걸린 행성이 고득점만으로 상위 등급 가격을 받지 않게 한다.
- **발견 가산액:** 유적의 보존·조사, 정착 생태 등 행성에 실제 남는 가치를 반영한다.
- **잔존가치:** 남기는 시설·로봇의 평가액이다. 회수 대상은 제외한다. 높은 등급이라는 이유만으로 무한 제작·매각 이익이 나지 않도록 검증한다.
- **권리·협약 계수:** 실제 처분 가능한 범위와 개발 제한을 반영한다. 원안의 문명 보호에 따른 큰 매각 단가 감소를 연결하는 안은 [문명 문서](10-alien-civilizations-and-diplomacy.md)를 따른다. 복원 계약 대금·공동 운영 수익은 이 매각 식과 별도 항목이다.

계수·가격표는 아직 미정이다. 유물을 반출 판매하면서 같은 유물의 잔존 가치를 행성에도 더하지 않는다. 독립적인 발견 기록 가산점은 별도 항목으로 정의하고 중복과 구분한다.

사업 성과 화면은 판매가 외에 **항해·기지·운영 지출·단계 지급·반출품 수익·순현금 변화**를 분리한다. 영구 기술 구매비는 영구 투자로 따로 보여 준다. 게임 내 무료 채집 재료를 현금 지출로 중복 계산하지 않는다.

## 판매 절차 — 설계 제안

협동에서는 [공동 지출·정산 권한](12-host-coop-and-crew.md)을 먼저 검사하고 호스트가 단일 거래를 확정한다. 개인 평가 창은 세계를 멈추지 않으며 아래 확정 스냅샷만 일관된 시점으로 처리한다. 여러 참가자가 같은 판매를 요청해도 대금을 인원수만큼 지급하지 않는다.

1. 현재 환경값·등급·가격 내역과 제한 사유를 미리 보여 준다.
2. 회수 가능 로봇·물품을 선택하고 우주선 한도를 확인한다.
3. 회수 대상의 작업·운반·제작 상태를 정리한다. 회수 로봇의 화물은 행성 보관함에 내리며, 별도 반출 대상으로 확정한 화물만 계승한다.
4. 남는 자산·반출 자산·예상 현금·종료하는 개발 권한·남는 방문/교역 권한·유지 의무를 보여 준다.
5. 최종 확정 시 시뮬레이션을 잠시 멈추고 동일한 시점의 평가·회수·재고 스냅샷을 검증한다.
6. 고유 거래 ID로 회수, 해당 권리 이전·종료, 대금 지급을 하나의 저장 거래로 반영한다.
7. 정산 후 우주선·성도로 돌아가 다음 원정이나 허용된 재방문을 선택한다.

예상 화면은 취소 가능하다. 확정 후에는 종료된 권리로 다시 건설·채집·매각할 수 없다. 관찰·교역 등 재방문은 계약에 남은 권한을 따른다. 실패·중단·재접속 시 거래가 반만 적용되지 않도록 [세이브 설계](../technical/02-data-and-save.md)를 따른다.

## 구현 시 확인할 상황

등급 경계값, 가중치 합계, 필수 조건 미달, 안정화 직전 판매, 자원·전력 단절, 유물 반출 중복 가산, 로봇 회수 후 잔존가치 제외, 중복 판매 입력, 저장 실패 후 재개를 확인한다. 평가 화면에서 ‘무엇을 개선하면 다음 등급이 되는가’를 설명할 수 있어야 한다.
