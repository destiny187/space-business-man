# 로봇·자동화

## 확정 요구사항과 원안 예시

- 초기 기술도 구매해야 한다. 해당 기술과 자원을 확보하면 SCV처럼 작업하는 AI 장비를 제작한다.
- 제작한 로봇은 확률적으로 등급이 나뉘며 특성이 무작위로 정해진다.
- 원안 제작 예시: **mine사의 보급형 채광로봇 — 철 100, 구리 10**.
- 원안 특성 예시: **견고함 — 물리적 충격 피해 20% 감소**.
- 자동화장비를 생산하여 사업 규모를 키운다.
- 우수한 로봇을 회수해 다음 행성에 보내는 기술이 존재한다. 원안의 지구 회수에 더해 확장에서는 이동 우주선의 격납고를 통한 행성 간 계승을 설계한다. 우주선 성장으로 수송 능력이 증가한다.

재료량과 특성 수치는 원안 예시이며 최종 밸런스가 아니다. 회수·수송의 소관은 [경제·기술·계승](05-economy-and-progression.md)이다.

## 로봇 구성 — 설계 제안

아래 ‘MVP·첫 버전’은 초기 설계 범위다. 현재 1.2에는 3모델이 구현되어 있으며 후속 탐험용 역할은 마지막 절의 목표 제안이다. [구현 현황](../planning/03-implementation-status.md).

| 구분 | 예시 | 역할 |
| --- | --- | --- |
| 제조사 | `mine` | 외형·상품군·기본 성향 |
| 모델 | 보급형 채광로봇 | 가능한 작업과 기본 능력 |
| 등급 | 보급·개량·희귀 등 | 기본 성능 보정, 특성 슬롯 수 |
| 특성 | 견고함·절전·대용량 | 개별 강점과 용도 |
| 개체 | 고유 ID, 이름, 제작 이력 | 저장·회수·애착의 단위 |
| 현재 상태 | 체력, 배터리, 화물, 작업 | 행성에서의 실제 운영 상태 |

모델과 등급은 별개다. 낮은 등급의 고급 모델과 높은 등급의 입문 모델이 같은 역할로 합쳐지지 않도록 기본 작업 능력과 수치를 분리한다.

### 역할

첫 버전은 **채광과 보관함 운반을 모두 하는 채광로봇 하나**로 시작한다. 이후 전용 운반, 건설, 설비 정비, 탐사, 생태 관리, 전투 모델을 추가한다. 전용 운반 로봇이 없어서 첫 채광로봇이 작동하지 못하는 구조는 피한다.

## 제작 절차 — 설계 제안

1. 제작기에서 보유 기술, 재료, 전력, 배치 공간을 확인한다.
2. 확정 시 입력 재료를 작업 전용 보관분으로 이동하고 제작 작업 ID를 만든다.
3. 같은 시점에 등급·특성을 추첨하고 결과를 작업 ID에 저장한다. 플레이어에게는 완성 시 공개한다.
4. 진행도가 차면 로봇 인스턴스를 한 번 생성하고 작업을 완료 처리한다.
5. 전력 부족은 일시정지로 처리한다. 배치 공간 부족이면 완성 대기 상태를 표시한다.
6. 취소 시 아직 소비되지 않은 입력을 반환하고 작업을 폐기한다. 취소된 작업에서 로봇을 수령할 수 없다.

저장·재접속·중복 입력으로 결과가 다시 추첨되거나 로봇이 중복 생성되지 않아야 한다. 싱글플레이 로컬 파일을 직접 되돌리는 행위까지 방지하는 온라인 보안 시스템은 목표로 하지 않는다.

## 등급과 특성 — 설계 제안

MVP는 다음 세 등급으로 제작 재미를 먼저 확인한다. 아래 확률은 프로토타입용 초안이며 합계는 100%다.

| 등급 ID | 표시명 | 제작 확률 | 작업 속도 배율 | 특성 수 |
| --- | --- | --- | --- | --- |
| `standard` | 보급 | 70% | 1.00 | 1 |
| `improved` | 개량 | 25% | 1.15 | 1 |
| `rare` | 희귀 | 5% | 1.30 | 2 |

확장 시 더 높은 등급, 제조사별 분포, 고급 공정에 의한 등급 확률 개선을 검토한다. 첫 버전에 확정 천장·합성·재추첨 기능을 넣지는 않는다.

| 특성 ID | 표시명 | 효과 초안 | 적용 시점 |
| --- | --- | --- | --- |
| `sturdy` | 견고함 | 물리적 충격 피해 ×0.8 | 해당 피해 종류가 구현된 단계 |
| `efficient` | 절전 | 작업 배터리 소모 ×0.85 | MVP |
| `expanded_cargo` | 대용량 | 화물 용량 ×1.25 | MVP |
| `fast_miner` | 채광 최적화 | 채광 속도 ×1.10 | MVP |
| `heat_resistant` | 내열 | 고온 환경의 성능 저하 완화 | 환경 위험 확장 |

MVP에서는 효과를 실제로 체감할 수 있는 세 특성만 추첨한다. 미구현 효과는 추첨 목록에 넣지 않는다. 같은 특성은 중복 부여하지 않고, 슬롯보다 후보가 적으면 가능한 후보만 사용한다. 기본 성능 → 등급 → 특성 → 현재 환경·전력 상태 순으로 계산하며, 화면에는 최종 수치와 보정 사유를 보여 준다.

## 작업 배정과 상태 — 설계 제안

플레이어는 로봇을 선택해 특정 광맥 또는 작업 구역, 반납 보관함, 우선순위를 지정한다. 자동 작업은 지정 범위 안에서 수행한다. 수동 명령이 기존 예약 작업을 덮을 때는 이전 예약을 해제한다.

```text
대기 → 작업 탐색·예약 → 이동 → 채광 → 운반 → 하역 → 다음 작업
                       ↘ 충전 필요 → 충전 패드 이동 → 충전 → 작업 재개
                       ↘ 진행 불가 → 원인 표시 → 재탐색 또는 구조 대기
```

| 상황 | 처리 |
| --- | --- |
| 광맥 고갈 | 잔량·예약을 해제하고 지정 범위의 다음 광맥 탐색 |
| 화물 포화 | 지정 보관함으로 운반 |
| 보관함 포화 | 다른 허용 보관함 탐색, 없으면 화물을 유지하고 대기 |
| 배터리 부족 | 귀환 예상량과 여유분을 기준으로 선제 충전 |
| 전원 완전 고갈 | 제자리 구조 대기. 수동장비의 기본 구조 기능으로 기지 복귀 지원 |
| 경로 없음 | 일정 간격으로 재탐색하고 원인을 표시. 무한 이동·벽 통과 금지 |
| 같은 노드에 여러 로봇 | 작업 자리·채집량 예약으로 초과 채집 방지 |
| 시설 철거·행성 매각 | 예약을 해제하고 안전한 정산 절차로 넘김 |

로봇 상태는 ‘대기’ 하나로 뭉개지 않고 ‘충전기 없음’, ‘창고 가득 참’, ‘광맥 접근 불가’처럼 해결 가능한 이유로 표시한다. 초반에는 관리 대상 수를 작게 유지하고, 확장 단계에서 그룹 명령·구역 정책을 도입한다.

## 고장과 손실 — 설계 제안

MVP에는 로봇 영구 파괴를 넣지 않는다. 배터리 고갈과 정체를 통해 자동화 관리의 기본을 검증한다. 물리 피해·환경 위험·전투가 추가되면 내구도, 수리, 파손 부품 회수, 보험 여부를 별도로 확정한다. 원안의 견고함은 이 확장 단계에서 활성화한다.

## 구현 시 확인할 상황

제작 취소·재로드·중복 완료, 등급 확률 합계, 중복 특성, 동시 채굴, 창고 포화, 충전기 철거, 길 차단, 회수 직전 작업 중단을 확인한다. 첫 로봇이 플레이어 개입 없이 **채광 → 운반 → 하역 → 충전 → 복귀**를 반복할 수 있어야 한다.

## 탐험 확장의 자동화 — 설계 제안·미구현

| 역할 | 탐험과 연결되는 일 | 운영 제약 |
| --- | --- | --- |
| 탐사·측량 | 지질·기체 지도, 알려진 단서 주변 반복 관측 | 센서·통신 범위, 미탐사 깊이의 명시적 투입 |
| 지하 채광·운반 | 허용 지층 굴착, 광물·시료 수직 수송 | 통로 크기·안정도·충전·승강기 용량 |
| 연구 보조 | 시료 이송, 설정한 대조 실험 반복 | 표본 잔량·격리·전력 |
| 생태 관리 | 먹이 공급·개체군 조사·시험 구획 유지 | 적합 환경·서식지 권한·오염 차단 |
| 정비·구조 | 중계기·설비·차량 복구 | 접근 경로·수리 부품·귀환 여유 |
| 수송·회수 | 기지↔착륙선↔우주선 적재 | 화물·격납고·질량·기체 조건 |

작업 정책에 탐사 경계, 보호 지층·서식지, 문명 협약, 최소 유지 자원, 철수 조건을 둔다. 자동화가 원주민 시설을 임의로 파괴하거나 시험 생물을 무제한 방출하지 않는다. 명령으로 허용 범위를 바꿀 때 영향과 수행 불가 사유를 보여 준다.

지역을 떠나도 생산량·연료·환경 효과가 보존되어야 한다. 활성/집계/정지 범위는 [월드 시뮬레이션](../technical/03-universe-data-and-world-streaming.md)이 기준이다. 경로가 사라지면 화물·예약을 유지하고 구조 대기로 전환한다. 청크 경계·굴착 통로·수직 물류·선적 중단 후 복원을 검증한다.
