# 탐험·이벤트·문명

## 확정 요구사항과 원안 예시

행성 파밍과 탐험 중 이벤트가 발생한다.

| 발견 | 원안의 내용 |
| --- | --- |
| 고대 문명의 잔해 | 유물·고대 기술 획득 가능. 이후 행성 판매 시 더 높은 가치 |
| 야생 미생물 | 특정 환경에 적응하고 테라포밍에 활용 가능. 예: 황산 대기 적응, 산소 생성력 55 |
| 야생동물 | 테라포밍에 도움이 되거나 귀여워서 지구에서 판매 가능 |
| 문명 | 전투 AI로 파괴, 노예화, 살려두기 중 선택. 살리면 랜덤 기술·보물 보상, 행성 판매 단가 크게 하락 |

‘산소 생성력 55’는 원안의 게임 능력치 예시다. 시간당 산소 질량이나 기체 비율로 확정된 값이 아니며 실제 환경 효과로 환산하는 규칙은 별도 밸런스 대상이다.

## 이벤트 공통 구조 — 설계 제안

```text
탐지 단서 → 접근·스캔 → 발견 공개 → 행동 선택 → 결과 적용 → 기록·후속 영향
```

- 행성 시드·환경·구역 조건으로 후보와 위치를 정하고, 플레이어가 탐사하여 공개한다.
- 반복 채집에서도 이상 신호·유물 파편 같은 단서를 얻을 수 있다.
- 중요한 문명 선택은 우연한 접촉만으로 자동 확정되지 않는다. 결과 미리보기와 명확한 선택 화면을 제공한다.
- 발견 ID별로 상태와 보상 수령 여부를 저장한다. 재방문·재접속으로 보상을 중복 수령하지 않는다.
- 확정된 발견 내용과 보상 추첨은 저장한다. 이미 공개한 결과를 화면을 다시 열 때 바꾸지 않는다.
- 필수 생산 자원을 막는 랜덤 이벤트를 초반에 배치하지 않는다.

## 유적 — 설계 제안

행동은 조사, 추가 분석, 보존, 반출로 나눈다. 조사로 기록과 일부 가치를 얻고, 분석 기술이 있으면 고대 설계도를 해금할 수 있다. 반출한 유물의 물건 가치는 행성에 남지 않으며, 보존한 유적은 행성 평가에 가산할 수 있다.

유적 원형은 랜드마크·보호 구역으로 관리하여 일반 건축과 충돌 여부를 확인한다. 첫 이벤트는 ‘잔해 발견 → 스캔 → 가치 가산·도감 기록’으로 단순화한다. 고대 기술 분기와 유물 인벤토리는 확장한다.

## 미생물 — 설계 제안

| 속성 | 의미 |
| --- | --- |
| 적응 범위 | 활동 가능한 대기·온도·독성 조건 |
| 주요 효과 | 산소 생성, 독성 감소, 토양 개선 등 |
| 증식 속도 | 조건 충족 시 개체군 증가 |
| 유지 비용 | 물·기질 등 필요한 투입 |
| 부작용 | 다른 기체 소비·환경 변화·과증식 등 확장 요소 |

발견 후 분석·배양·정착을 거쳐 환경에 기여하게 한다. 황산 대기에 적응하는 미생물은 초기 독성 환경에서 도움이 되지만, 환경이 달라지면 번식 조건이 나빠질 수 있다. 원안의 능력치를 그대로 적용해 모든 행성의 정답이 되는 상황을 피한다.

MVP에는 기본 상점 기술로 확보한 표준 미생물 하나를 사용한다. 야생종 발견·포획·개체군 상호작용은 이후 추가한다. 따라서 첫 회차의 생태 달성이 랜덤 발견에 막히지 않는다.

## 야생동물 — 설계 제안

관찰·보호·서식지 제공·포획·반출을 가능한 행동 후보로 둔다. 테라포밍 기여와 지구 판매 가치는 구분한다. 행성에 정착시킨 개체를 동시에 지구에 팔 수 없다. 반출 슬롯, 생존 조건, 판매 절차는 확장 단계에서 정한다.

행성 환경에 맞는 실루엣·행동·음향으로 개성을 만든다. 생태 기여를 수치로만 보이지 않게 하고, 실제로 돌아다니거나 식생 주변에서 활동하게 한다.

## 문명 선택 — 설계 제안

다음 선택지 자체는 원안에 포함되어 있다. 표의 비용·상태·부작용은 구체화를 위한 제안이다. ‘살려두기’의 랜덤 보상과 큰 단가 하락은 확정 요구사항으로 보존한다.

| 선택 | 필요한 행동·비용 초안 | 즉시 결과 초안 | 행성·영구 진행 영향 초안 |
| --- | --- | --- | --- |
| 파괴 | 전투 AI·전력·수리 자원 투입 | 충돌 후 문명 제거 상태 | 정리 비용·생태 손실 가능, 문명 보상 없음 |
| 노예화 | 전투·통제 설비와 유지 비용 | 강제 노동·통제 상태 | 생산 보정 가능, 저항·관계 악화·유지 부담 검토 |
| 살려두기·보호 | 보호 구역과 개발 제한 수용 | 무작위 기술 또는 보물 보상 | 해당 행성 판매 단가 크게 하락, 발견·관계 기록 유지 |

노예화는 게임 내 강압적 선택으로 다룬다. 구체적 노동 시스템, 전투 방식, 저항·외교·평판, 표현 수위는 아직 확정하지 않는다. 확정되지 않은 불이익을 원안의 필수 규칙인 것처럼 구현하지 않는다.

### 선택과 거래 일관성

- 문명 발견 시 현재 선택 가능한 행동과 선행 기술, 알려진 결과를 표시한다.
- 보호 선택에서는 가격 하락이 있음을 확정 전에 알린다. 무작위 보상은 범주와 추첨 여부를 표시한다.
- 선택 확정과 결과 추첨·보상 지급을 같은 이벤트 거래로 기록한다.
- 최초 설계에서는 문명별 주요 선택을 한 번만 확정한다. 이후 보호 보상을 받은 뒤 즉시 파괴하여 할인만 제거하는 행동은 허용하지 않는다. 선택 전환을 추가하려면 별도 규칙을 설계한다.
- 문명 선택의 가격 영향은 [판매 가격 모델](04-terraforming-and-sales.md)에 반영한다. 동일 영향을 가산액·계수 양쪽에 중복 적용하지 않는다.
- 여러 문명이 있는 행성에서 계수를 어떻게 합칠지는 미정이다. 초기 문명 확장에서는 한 행성에 주요 문명 하나를 제안한다.

## 도입 순서와 검증

MVP에는 고정된 유적 이벤트 하나를 넣어 탐지·발견·기록·매각 가산의 연결을 확인한다. 이후 미생물·야생동물, 마지막으로 전투·문명 선택을 확장한다. 이 순서는 첫 버전의 범위 제안이며 원안 콘텐츠 삭제를 의미하지 않는다.

이벤트 재진입, 미완료 스캔 저장, 보상 중복, 반출 자산의 소유 위치, 선택 결과·가격 예고의 일치, 기술을 이미 소유한 경우의 대체 보상을 검증한다. 이미 소유한 기술 대신 보물을 주는 방식을 초안으로 둔다.
