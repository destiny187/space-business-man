# 자원 기반 단일 은하 오픈월드

## 이번 구현 목표

하나의 저장 세계에 100만 행성 주소를 유지한다. 항성계는 필요할 때 계산하고 지구에서 시작한다. 착륙 불가 거대행성은 지표 광맥을 갖지 않는다. 착륙 가능한 행성은 시드로 고정된 지질·주력/보조 자원·지하 보석·상위 소재 후보를 가진다.

지표는 기존 16.384km × 16.384km 스트리밍 지역을 사용한다. 완전한 구형 행성 전체를 연속적으로 걷는 구현은 아니다. 항성계 이동·궤도 접근·착륙은 기존 세션 전환을 사용한다. 이번에는 자원을 기존 지표·지하 탐험과 연결한다.

## 생성·저장 원칙

새 은하의 설정에 자원 생성 규칙 스냅샷을 넣는다. 기존 저장에 이 규칙이 없으면 기존 광맥을 유지한다. 지질 종류·자원 풀·지역별 광맥 ID·위치·수량·품위는 독립 시드에서 재현한다. 가까운 지역만 메시로 만들며 미방문 광맥 전체를 저장하지 않는다. 호스트가 채굴 잔량을 확정하고 변경된 광맥 기록을 저장해 재접속 재생성을 막는다.

새 자원은 기존 경제 자원 목록을 일괄 확장하지 않고 표시·운반에서 별도 광물 카탈로그를 조회한다. 기존 제작 재료는 유지한다. 보석 강화·신규 장비 레시피·지하 로봇 경로 개선은 이번 요구와 별개 후속 범위다.

## 플레이 경로

은하 항해 → 자원 구성으로 목적지 선택 → 착륙·개발 등록 → 지표 채집 또는 굴착으로 지하 광체 노출 → 배낭 운반·창고 반납 → 기존 건설·로봇 자동화. 신규 자원의 강화 소비처는 후속이며 이번에는 생성·발견·채집·저장을 연결한다.

분포·채집 등급·수량은 초기 밸런스 제안이다. 재현성, 가스 행성 제외, 지역 이동, 고갈 저장과 최소 실제 렌더/채집 흐름을 확인한 뒤 구현 상태를 기록한다.

## 구현 상태

위 구조를 구현했다. `FrontierMineralWorld`가 고정 규칙·시드에서 지역 광맥을 계산하며 `FrontierExpeditionBusiness`가 미변경 잔량을 원래 매장량으로 해석한다. 채집·로봇 배정 때만 필요한 잔량 항목을 만들고, 저장 검증은 각 주소를 다시 생성해 수량 범위를 확인한다. 기존 5개 기초 재고 키를 유지하면서 새 자원 키를 선택적으로 추가한다. 기존 `catalog.json`의 자원 순회 목록은 바꾸지 않았다.

품위 1~3은 광맥 시드 정보이며 현재 배낭에서 품위별 별도 스택이나 강화 수율로 사용하지 않는다. 행성 규칙은 저장된 `manifest.settings.resource_rules`가 원본이다. 규칙 없는 기존 저장은 원래 광맥 목록·검증을 사용한다. 현재 자원 생성 버전은 1이며 향후 규칙 변경은 버전별 생성기를 유지해야 한다.

고티어 권역은 실제 은하 지도 반경의 안쪽에 놓인다. 외곽→중심 반경 구간은 500~420 / 420~340 / 340~260 / 260~180 / 180~100이다. 티어 확률 표는 기존 `galaxy.json`이 원본이며, T4 이상 행성의 지하에서 최고급 공통 소재 후보가 활성화된다. 블랙홀은 반경 0의 지도 이정표로 렌더한다.

확인 결과·시각 자산·실제 사용법은 [제작 기록](../production/25-galactic-core-and-resource-world.md)을 따른다.
