## 데이터 원칙

- 표시 이름과 고유 ID를 분리한다. ‘mine사의 보급형 채광로봇’의 이름을 바꿔도 기존 로봇의 소유권·특성이 유지되어야 한다.
- 콘텐츠 정의는 `definition_id`, 개체는 `instance_id`로 참조한다. 노드 이름·노드 경로·화면 문구를 영구 식별자로 사용하지 않는다.
- 등급·특성·가격·레시피·목표 환경은 데이터에 둔다. 확정된 랜덤 결과는 개체·작업에 저장한다.
- 정의 데이터와 실제 인스턴스를 함께 검증한다. 누락된 참조, 음수 수량, 확률 합계 오류를 로딩 단계에서 발견한다.
- 기술·화물·보상·로봇·현금의 소유 위치를 분명히 한다. 같은 자산이 현지와 지구에 동시에 존재할 수 없다.

다음 JSON은 문서용 개념 예시다. 실제 Resource 스키마나 게임에서 바로 로드할 완성 파일은 아니다. 재료량은 원안 예시, 확률은 [로봇 문서](../game/03-robots-and-automation.md)의 프로토타입 제안이다.

  "manufacturer_id": "mine",
  "roles": ["mining", "hauling"],

## 세이브 방식

초기 구현은 **프로필·활성 행성·거래 결과를 하나의 스냅샷**에 넣는 방식을 제안한다. 사람이 읽을 수 있는 구조화 형식으로 시작하되, 크기·성능에 따라 변경 가능하게 저장 계층을 분리한다.

1. 변경 가능한 시뮬레이션 상태를 안정된 시점에서 수집한다.
2. 일관성 검사를 통과한 새 스냅샷을 임시 파일에 쓴다.
3. 파일 쓰기·검증이 끝난 뒤 기존 저장본을 교체하고 최근 정상 백업을 보존한다.
4. 실패하면 기존 정상 저장본을 유지하고 오류를 알린다.
5. 로딩 시 버전·필수 필드·자산 일관성을 검사하고, 필요한 마이그레이션 후 세계를 복원한다.

MVP에서 여러 저장 파일에 현금·행성·로봇을 나누어 갱신하면 부분 반영 가능성이 커지므로 피한다. 나중에 분리하면 별도 거래 로그와 복구 절차가 필요하다.

사업 재시작용 안전 시작점은 같은 저장 문서의 별도 블록으로 보관한다. 안전 시작점 자체를 재귀적으로 복사하지 않는다. 재시작 시 해당 시점 이후의 거래·보상·현지 자산도 함께 되돌리고, 복원 결과 전체를 한 번 저장한다. 자세한 적용 조건은 [경제·계승 문서](../game/05-economy-and-progression.md)를 따른다.

### 저장 시점

- 새 행성 구매·파견, 기술·우주선 구매, 로봇 제작 확정·완료, 주요 이벤트 선택, 행성 매각·회수 완료 시 저장한다.
- 일정 간격 자동 저장과 사용자 수동 저장을 제공한다. 임시 저장 주기는 60초를 제안한다.
- 실제 한 회차 진행에서 채광·운반·충전·제작·환경 안정화 중 저장·복원도 가능해야 한다.
- 자동 저장이 실패한 뒤 거래까지 성공한 것처럼 표시하지 않는다. 게임 상태와 디스크의 최신 확정 상태를 구분한다.

## 거래와 중복 방지

현금·재료·로봇을 다루는 주요 명령에는 고유 작업·거래 ID를 붙인다. 이미 완료된 ID를 다시 적용하면 결과를 반환하고 비용·보상은 다시 처리하지 않는다.

### 행성 판매 거래

```text
소유권·회수 한도 검증
→ 작업과 재고 정리
→ 평가·반출·잔존 자산 확정
→ 메모리에서 다음 전체 상태 작성
→ 전체 상태를 한 번 저장
→ 성공 시 다음 상태 활성화·정산 표시
```

쓰기 실패 시 이전 상태로 유지·복원하고 판매 완료를 표시하지 않는다. 저장은 성공했지만 완료 화면 전에 종료된 경우, 재접속 시 완료 거래 기록을 읽어 지구 정산 상태로 들어간다. 대금을 다시 지급하거나 로봇을 재복사하지 않는다.

### 랜덤 결과

- 행성 생성 시드와 실제 발견·제작의 추첨 상태를 구분한다.
- 제작을 확정할 때 등급·특성을 작업 기록에 저장하고 완료 시 그대로 로봇으로 옮긴다.
- 이벤트 선택 결과를 확정할 때 보상 추첨과 적용 상태를 함께 기록한다.
- 레어 상점 갱신 결과는 정산 회차에 묶어 저장한다.
- 콘텐츠 변경 후 확률표가 달라져도 기존 개체의 등급·특성을 다시 추첨하지 않는다.

## 불변 조건

- 모든 현금·자원·노드 잔량은 음수가 아니다.
- 로봇 인스턴스 하나의 위치는 현지·지구 보관·출발 편성·판매 완료 중 정확히 하나다. 편성은 보관 로봇에 대한 예약으로 구현할 수도 있지만 이 경우에도 소유 개체를 복제하지 않는다.
- 같은 행성은 한 번만 매각되며, 매각 완료 행성에서 채집·건설·보상 지급이 일어나지 않는다.
- 회수 슬롯 합계는 우주선 용량을 넘지 않는다.
- 확정 제작 결과와 완성 로봇 ID는 중복 생성되지 않는다.
- 자원 이동은 출발 감소와 도착 증가가 함께 발생한다.
- 환경 기체 비율 합계와 각 상태 범위가 유효하다.

## 버전 변경과 검증

필드 추가·ID 변경에는 스키마 버전과 마이그레이션을 둔다. 제거된 정의를 발견했다고 자산을 조용히 삭제하지 않는다. 대체·복구 또는 명시적인 호환 오류를 제공한다.

구현 시 저장 도중 중단, 손상 파일과 백업 복구, 구버전 로드, 제작 진행 복원, 매각 직전·직후 종료, 회수 로봇의 개체 동일성, 이벤트 중복 지급을 확인한다. 여러 저장 슬롯·클라우드 저장은 MVP 이후 범위다.

## 1.1 입문 안내 호환 필드

버전 1 저장 형식을 유지하고 `profile.onboarding`을 선택 필드로 추가했다. `enabled`, 중복 없는 `completed` 단계 ID 배열, `travel`(0~100), `mined`·`deposited`·`delivered`(0~100000 정수)를 검증한다. 이전 세이브에 필드가 없으면 가이드를 강제로 표시하지 않는다. 활성화할 때 필드를 생성하며 기존 거래·자원·장비 소유권은 유지한다. 단계 판정은 `FrontierOnboarding`, 실제 수치 기록은 이동·채집·반납·자동 하역을 수행하는 코드가 담당한다.

## 1.2 그래픽 설정 호환 필드

`profile.settings.graphics`는 선택 필드이며 `performance`, `balanced`, `high` 중 하나다. 필드가 없는 1.0/1.1 기록은 스키마 버전 변경 없이 읽고 `balanced`로 적용한다. 필드가 존재하면서 잘못된 타입·값이면 정상 백업 복구 대상으로 처리한다. 품질 변경은 즉시 렌더러에 반영하며 기존 `설정·진행 저장` 동작으로 디스크에 보관한다. 그래픽 프리셋 데이터는 게임 밸런스와 분리한 `data/graphics.json`에 있다. UI 선택 → 실시간 적용 → 파일 저장/읽기 → 월드 재생성의 연결을 `test_graphics.gd`에서 확인한다.

### 여러 지역을 안전하게 저장하는 방법

초기에는 작은 통합 스냅샷으로 검증하고, 청크 변경량 때문에 분리가 필요해지면 다음 방식을 실증한다.

1. 동일한 시뮬레이션 시각의 프로필·거래·선박·변경 청크를 수집한다.
2. 새 세대 ID 아래 변경 파일을 먼저 쓰고 해시·참조·자원 일관성을 검사한다. 미변경 청크는 기존 불변 파일을 참조할 수 있다.
3. 해당 세대 전체를 참조하는 매니페스트가 완성된 후 활성 매니페스트 포인터를 원자적으로 교체한다.
4. 중단·쓰기 실패 시 이전 완전한 세대가 활성 상태로 남는다. 실패한 세대를 거래 완료로 노출하지 않는다.
5. 최근 정상 백업이 참조한 파일까지 보존하고 참조되지 않은 오래된 세대만 정리한다. 로딩은 완전한 세대만 선택한다.

헤더만 새것이고 표본·지형·현금은 옛것인 조합을 복원하지 않는다. 파일 분할이 반드시 필요하다는 결론이나 성능 측정 결과는 아직 없다.

### 선적·이식·정산 거래

`조건/권한 검증 → 입력 예약 → 다음 전체 상태 작성 → 저장 성공 → 상태 활성화`를 공통으로 사용한다. 출발지·용기·도착지의 자산 이전과 실험 시료 소비는 같은 거래 안에서 반영한다. 로봇·생물·유물의 물리적 이동 연출은 확정 상태를 따르며 연출 완료 콜백만으로 중복 지급하지 않는다.

생물 배양으로 개체를 늘릴 때는 부모/배양 계통·실제 기질 소비·생산량을 기록한다. 같은 개체를 옮기는 거래와 새 개체를 만드는 배양을 구분한다. 표본을 이식한 뒤 원래 화물에서도 다시 이식하는 복제를 막는다.

정산의 단위는 행성 ID만이 아니라 **권리·계약·단계·버전**이다. 같은 대상의 같은 정산은 한 번만 지급하고 재방문은 별도 권한 검사로 허용한다. 기존의 ‘매각 행성은 접근 불가’ 불변 조건을 새 구조에 그대로 적용하지 않는다. 종료된 개발권으로 채집·건설·재매각하는 것은 계속 금지한다.

### 확장 불변 조건

- 프로필의 기본 세계는 단일 은하 ID이며 모든 성역·항로·천체 참조가 그 은하에 속한다.
- 티어·생물 사례 선택은 생성 매니페스트에 고정되고 환경 등급·관측 공개와 독립이다.
- 실물 자산은 현지·선박·보관소·이식 구획·인도 완료 중 하나의 소유 위치를 가진다. 예약은 복제가 아니다.
- 전력·기질·물·화물 용량과 생물실 조건이 실제 가동·산출·생존 상태에 일치한다.
- 상세/집계 시뮬레이션 전환에서 시간이 겹치지 않고 자원·개체군·환경 이력이 보존된다.
- 문명 협약 변경으로 이전 보상 수령 기록·미해결 의무가 사라지지 않는다.

### 기존 버전 1 저장의 전환 제안

원본 저장을 백업하고 별도 결과 파일로 변환한다. 기존 구매 행성은 가상의 `legacy_site`로 등록해 자산·진행·환경을 보존하고, 티어·은하 위치 배정은 명시된 호환 정책으로만 수행한다. 실제 천체로 허위 매핑하거나 기존 지형을 새 시드로 덮지 않는다. 이미 매각한 행성은 거래 이력으로 보존하고 다시 판매 가능한 현장으로 복구하지 않는다.

기존 우주선 등급→초기 선체/격납고, 지구 로봇→보관소, 기존 문명 선택→이전 사건 이력으로 변환할 표를 준비한다. 기존 발견에는 관측 기록만 우선 부여하고 살아 있는 표본을 자동 생성하지 않는다. 누락 에셋·제거 ID에는 복구 안내 또는 호환 실패를 제공하고 조용히 삭제하지 않는다. 신규 시작과 변환 시작을 별도로 검증하며, 이번 문서 작업에서 마이그레이션을 실행하지 않았다.

### 이후 구현 시 검증

같은 시드/버전 재현, 카탈로그 변경 후 기존 세계, 청크 쓰기 중 중단, 항해·선적·실험·이식·협약 지급 전후 종료, 생물실 전력 부족, 배양 계통·개체 수, 잘못된 ID, 매각 후 방문 권한, 버전 1 원본 보존·전환을 확인한다. 기존 테스트 통과를 이 확장의 검증으로 재사용하지 않는다.

## 협동 저장의 연결 — 제안·미구현

호스트 포함 최대 6인 협동에서는 기존 `profile` 하나를 전원의 개인 소유 기록으로 쓰지 않는다. **개인의 원본 캐릭터·장비, 호스트 세계·공동 사업, 해당 세계의 캐릭터별 상태**를 구분한다. 개인 장비는 읽기 전용 반입을 초기안으로 두고 이탈·추방·호스트 종료에도 원본 소유권이 유지되게 한다. 세계에서 새로 얻은 화물·장비·연구는 호스트 세계에 보존한다.

소유 위치 불변 조건은 실물 세계 자산에 적용한다. 반입한 개인 장비의 세션 표현은 소유권을 새로 발급한 거래 가능한 복제품이 아니다. 동일 캐릭터·원본 장비 참조의 중복 활성화를 막고, 운반 중 공동 화물은 이탈 때의 회수 위치를 저장한다. 접속 ID를 장기 소유자 ID로 사용하지 않는다.

합류·재접속의 스냅샷 기준, 확정 거래 응답, 호스트 장애·저장 복원·구버전 매핑은 [협동 네트워크·세션 저장](04-coop-networking-and-session-save.md)이 정의한다. 세계 간 영구 장비·보상 반출과 양쪽 프로필 갱신은 별도 결정 전까지 구현하지 않는 제안이다.
