# 에셋 버전 관리 — Git LFS와 생성 결과 분리

## 적용 방향

2026-09-06 사용자 요청으로 모델·음원·래스터 이미지를 Git LFS로 전환하고 재생성 가능한 대량 렌더 결과의 Git 추적을 해제한다. 코드와 에셋의 같은 버전을 복원하는 목적은 유지한다. 기존 공유 커밋 이력을 다시 쓰거나 강제 푸시하지 않고, 현재 색인의 에셋부터 LFS 포인터로 정규화한다.

| 대상 | 관리 방식 |
| --- | --- |
| 코드, Godot 장면/설정, 셰이더, SVG, JSON, 생성 스크립트, 제작·검증 매니페스트 | 일반 Git |
| Blender 원본, GLB/FBX, PNG/JPEG/WebP 등 래스터 이미지, 음원, 폰트, 보존하는 영상 | Git LFS |
| 실제 게임의 모델·UI 미리보기·음원, 승인 참조·대표 캡처·검토 모음판 | LFS로 계속 보존 |
| 생물 외형별 전수 이미지 `docs/production/media/bestiary/variants/` | 로컬 재생성 결과, Git 제외 |
| 조명·LOD 전수 이미지 `docs/production/media/bestiary/lighting/`, `lod/` | 로컬 재생성 결과, Git 제외 |
| `.godot/`, `builds/`, `test-results/`, Blender 자동 백업, 로그 | 기존 제외 규칙 유지 |

실제 규칙은 루트 `.gitattributes`와 `.gitignore`가 원본이다. 프로젝트 하위의 `.gitattributes`는 루트 규칙을 상속한다. 하위의 일괄 `text=auto`가 LFS 바이너리의 `-text`를 덮지 않도록 한다. `.import` 파일은 가져오기 설정이므로 원본 에셋과 함께 보존한다.

생물 600종의 기본 형상 렌더, 실제 UI 이미지, 구조군/외형 모음판과 제작 기록은 유지한다. 제외한 전수 캡처는 모델 원본이 아니며 게임 실행에서도 참조하지 않는다. 과거 문서의 전수 촬영 기록은 제작 당시의 결과이고, 이후 모든 개별 출력 파일을 Git으로 계속 보관한다는 뜻은 아니다. 제작 품질 기준은 그대로 유지한다.

## 새 작업 환경

Git LFS를 설치한 뒤 이 저장소에서 다음을 실행한다.

```bash
./tools/setup_assets.sh
./tools/godot.sh
```

설치 예시: macOS는 `brew install git-lfs`, Windows는 Git LFS 설치 프로그램을 사용한다. 저장소 복제 전에 `git lfs install`을 실행하면 clone/checkout에서 LFS 파일을 자동으로 받는다. 이미 복제했다면 위 스크립트가 저장소 전용 필터·pre-push 훅을 설치하고 `git lfs pull`로 현재 에셋을 받는다. GitHub의 소스 ZIP만 받아 게임 자산이 모두 포함됐다고 가정하지 않는다.

에셋을 수정한 뒤에는 평소처럼 해당 파일을 `git add`한다. 색인에는 포인터가, 작업 폴더에는 실제 파일이 남는다. `git lfs ls-files`로 추적 상태를 볼 수 있다. 이후 `git push`는 pre-push 훅을 통해 필요한 LFS 객체를 먼저 업로드한다. 훅이나 `filter.lfs.required`를 끄지 않는다. LFS 저장/전송 할당량은 일반 Git과 별도이므로 원격 업로드 오류가 나면 메시지에 따라 계정 상태를 확인한다.

## 제외한 캡처가 필요한 경우

일상 개발 중 자동으로 전체를 다시 만들지 않는다. 실제 모델 검수나 버그 원인 파악에 필요한 범위만 지정한다. 아래의 `--start=0 --end=1`은 첫 모델 한 개를 뜻한다.

```bash
./tools/render_bestiary.sh --stage=variants --start=0 --end=1
./tools/render_bestiary.sh --stage=lighting --start=0 --end=1
```

`lighting` 단계가 조명 두 장과 LOD 한 장을 함께 만든다. 전체 외형/조명 모음판을 다시 만들 때는 필요한 전수 캡처를 먼저 재생성해야 한다. 전수 파일을 읽는 `tools/bestiary/build_boards.py`, `build_review_boards.py` 등을 새 clone에서 곧바로 실행하면 제외된 입력 이미지가 없을 수 있다. 기존 모음판과 검증 JSON은 LFS/Git에 보존하므로 게임 실행을 위해 이 과정을 수행할 필요는 없다.

## 이력과 이번 적용 범위

공유 이력을 보존하는 전환이므로 과거 일반 Git blob은 남는다. 기존 `.git` 크기나 전체 이력을 받는 clone 비용이 즉시 줄어드는 작업은 아니다. 과거 blob까지 제거하는 이력 재작성과 강제 푸시는 별도 변경이며 이번에는 수행하지 않는다.

이번 작업은 로컬 Git LFS 설치, 추적 규칙, 기존 색인의 LFS 포인터 전환, 전수 캡처의 추적 해제와 로컬 원본 보존을 포함한다. 원격 반영에는 이 변경의 커밋·푸시가 필요하다. 진행 중인 다른 게임 개발 변경은 함께 스테이징하지 않는다. 게임 테스트·전수 렌더는 실행하지 않고 저장 방식 변경에 필요한 포인터·필터·원본 파일 무결성만 확인한다.

### 로컬 전환 확인

- LFS 자산 4,691개, 실제 파일 약 1,077.6MiB를 현재 색인에서 포인터 약 599.2KiB로 전환했다. 실제 바이너리는 작업 폴더와 로컬 LFS 객체 저장소에 보존한다.
- 재생성 캡처 13,800개, 약 269.0MiB는 Git 추적만 해제했다.
- 대상 로컬 파일 18,491개의 크기·SHA-256이 전환 전과 같음을 확인했다. 모든 LFS 포인터가 해당 원본 해시/크기를 가리키고 모든 제외 파일이 ignore 규칙에 해당한다.
- 기존 HEAD는 `77a31d0b`로 유지했다. 이 확인은 저장 방식의 무결성 확인이며 게임 기능 테스트가 아니다. 원격 LFS 업로드는 이번 작업에서 수행하지 않았다.
