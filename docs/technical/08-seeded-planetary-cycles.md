# 시드 기반 항성계·행성 낮밤과 천체 시간

2026-09-07 설계, 2026-09-08 **C16~C17 일반/동주기 첫 구현 완료**. 사용자 확정은 낮밤·태양·별 이동을 포함하고, 각 항성계 규칙을 현실적 범위에서 시드로 정하는 것이다. 아래 생성 범위·시간 압축·확률은 게임 구현을 위한 기본안이며 실제 외계행성 분포의 관측값이 아니다. [하늘 표현](../production/41-surface-atmosphere.md) · [개발 연결](../planning/10-ground-development-spec.md).

## 현실 근거와 게임 표현의 구분

- 낮밤 주기는 자전 주기와 항상 같지 않다. 지구 자전은 약 23.9시간이며, 수성은 자전 약 59일에 태양일 약 176일이다. 따라서 자전 값을 그대로 낮밤 길이로 쓰지 않는다. [NASA 지구](https://science.nasa.gov/earth/facts/), [NASA 수성](https://science.nasa.gov/mercury/facts/).
- 동주기 자전 행성은 공전과 자전 주기가 같아 항성을 향하는 낮 면과 반대 밤 면이 유지될 수 있다. 모든 착륙 행성에서 태양을 반복 상승/하강시키지 않는다. [NASA 외계행성 용어집](https://science.nasa.gov/exoplanets/glossary/).
- 공전 주기는 항성 질량·궤도 크기와 연결한다. 같은 별 주위 바깥 행성이 더 짧은 공전 주기를 갖게 무작위 추첨하지 않는다. [NASA 궤도·케플러 법칙](https://science.nasa.gov/solar-system/orbits-and-keplers-laws/), [NASA 중력·역학](https://science.nasa.gov/learn/basics-of-space-flight/chapter3-3/).

위 근거에서 **일관된 주기 관계를 유지하면서 시간을 압축하는 게임 모델**을 도출한다. 행성 전체 자전/대기 역학을 실시간 계산하는 모델은 아니다. 관측 자료는 `observed`, 자료에서 유도한 값은 `estimated`, 시드 값은 `generated`와 생성 버전을 저장한다. 태양계 참조는 실제 관측값을 우선하고 착륙 금지는 유지한다. 확인일 2026-09-07.

## 시드 계층과 물리 메타데이터

기존 `system_id/body_id`와 행성 주소·지형 시드는 보존한다. 새 독립 스트림 `derive(world_seed, system_id + ':astro:v1')`, `derive(system_seed, body_id + ':spin:v1')`을 사용한다. 모델/구름을 추가했다고 자전/자원 배치가 달라지지 않는다.

| 범위 | 생성/저장할 값 | 검증 경계 |
| --- | --- | --- |
| 항성계 | 중심 항성 질량·광도·반경·분광형, 기준 궤도면, 기준 시각 | 기존 분광형에 맞는 주계열 기본 프로필, 양의 유한 값 |
| 행성 궤도 | 물리 장반경 AU, 이심률, 공전 방향/주기, 초기 위상 | 기존 궤도 순서 유지, 항성 내부/서로 교차하는 궤도 금지 |
| 행성 자전 | `spin_state`, 축 방향, 자전 주기·초기 각도 | 분열 수준의 과속 자전 금지, 동주기/공명 관계 일치 |
| 관찰 지역 | 기준 위도·경도·지면의 북쪽 방향 | 같은 시드/지역은 같은 하늘. 평면 타일의 x축을 매번 임의 북쪽으로 지정하지 않음 |

첫 항성 프로필은 현재 M/K/G/F/A를 기준으로 정의 파일의 일관된 질량·반경·광도 묶음에서 시드 선택한다. 예시 기본값은 `(태양질량, 태양반경, 태양광도)`로 M `(0.3,0.3,0.012)`, K `(0.75,0.75,0.3)`, G `(1,1,1)`, F `(1.3,1.3,3)`, A `(2,1.8,20)`이다. 분광형 전체 범위나 실제 표본의 평균을 주장하는 표가 아니다. 세 값에 독립적인 큰 난수를 넣지 않고 검토된 프로필 변형을 늘린다.

기존 `orbit.radius/period`는 공간 압축·시각 공전용 수치다. AU/물리 초로 이름만 바꾸지 않는다. 새 `astro` 메타데이터에서 물리 궤도를 별도로 생성하고 궤도 순서·접근 가능한 행성·관측 원본을 유지한다. 기존 행성 환경값은 현재 게임 상태이므로 새 광도로 덮어쓰지 않는다. 극단적으로 일사 조건과 행성 원형이 어긋나는 후보는 새 세계 생성 시 명시적 가상 배경/조건으로 분리하거나 새 입문 후보에서 제외한다.

## 자전 상태 선택 기본안

| 상태 | 초기 생성안 | 플레이 표현 |
| --- | --- | --- |
| 일반 순행 | 자전 8~72시간의 로그 분포, 자전축 기울기 0~40° 중심 | 여러 길이의 낮밤과 일출/일몰 방향 |
| 느린 순행/역행 | 자전 72~6,000시간, 역행은 축 기울기 140~180°로 표현 | 긴 낮/밤, 역행에서는 다른 태양 이동 방향 |
| 동주기 | 원형에 가까운 근접 궤도에서 자전=공전, 축 기울기 0~5° | 낮/밤 면 고정, 경계 지역에 긴 황혼. 별 배경은 관성 방향에 따라 움직일 수 있음 |
| 3:2 공명 | 이심률 있는 근접 궤도의 후보, 자전=공전×2/3 | 긴 태양일. 공전 속도의 변화도 같은 궤도에서 계산 |

물리적 동주기 판정에는 나이·내부 구조·조석 소산 등 불확실성이 필요하므로 거리만으로 확정하지 않는다. 초기 게임 생성기는 공전 10일 이내에서 동주기 후보 가중치 0.8, 10~30일 0.4, 그 밖은 0을 기본안으로 쓰고, 동주기 미선정 근접 후보에 공명/느린 자전, 나머지에 일반 자전을 배치한다. 이 값은 **게임의 조건부 샘플링 가중치**이며 실측 발생 확률이 아니다. 대략적인 항성계 나이·조석 모델을 넣을 때 생성 버전을 올린다. 높은 기울기·특수 상태의 상세 출현 비중은 이후 콘텐츠 조정이며 구현자는 첫 버전에 일반/동주기부터 연결하고 나머지는 지원 상태를 명시한다.

새 첫 추천 행성은 일반 자전·낮밤 16~30시간, 낮은~중간 위도와 과도한 계절 없는 후보로 제한하는 온보딩 기본안이다. 세션 시작 시 무조건 낮으로 시간 되감기를 하지 않고 해당 시각의 낮 면 착륙 후보를 고른다. 이런 추천 필터가 모든 항성계에 동일한 하루를 강제하지 않는다.

## 시간과 방향 계산

일관된 단위에서 근사 공전 주기는 다음과 같다. 첫 버전은 중심 항성 하나의 2체 모델이며 쌍성은 후속이다.

```text
P_orbit_years = sqrt(a_AU³ / (star_mass_solar + planet_mass_solar))
omega_orbit = 2π / P_orbit_seconds
omega_spin = 2π / P_spin_seconds
```

이심 궤도는 평균 근점이각에서 케플러 방정식을 풀어 실제 방향을 구한다. 숫자 표시용 평균 태양일은 순행·축 정렬 근사에서 `2π / abs(omega_spin - omega_orbit)`이고 역행은 `2π / (omega_spin + omega_orbit)`다. 동주기는 분모 0을 무한 숫자로 UI에 노출하지 않고 ‘동주기 · 낮/밤 면 고정’으로 표시한다. 축 기울기는 벡터 회전으로 반영하고 역행 부호를 두 번 적용하지 않는다.

태양의 지표 방향은 `(항성 위치 - 행성 위치)`를 행성 자전 좌표계로 변환하고, 지역 위도/경도의 접평면으로 바꾼다. 별 배경은 관성 공간에 고정된 방향을 같은 자전/지역 변환으로 표시한다. 태양과 별의 이동을 별개 속도 난수로 만들지 않는다. 태양 고도에 따라 직사광·그림자·하늘 밝기를 연결하고, 극지/동주기에서 해가 안 뜨는 것은 오류로 보정하지 않는다.

**시간 압축 기본안:** 모든 생성 항성계에 동일하게 실제 플레이 1초=천체 60초를 사용한다. 지구형 태양일 24시간은 약 24분, 12시간은 약 12분이다. 100시간 행성은 약 100분으로 남기고 모든 행성을 20분으로 잘라 맞추지 않는다. 표시는 ‘현지 하루 24시간 · 플레이 약 24분’처럼 구분한다. 이는 현실 재현 비율이 아니라 게임 속도 설정이다.

호스트의 `active_sim_seconds`가 누적되는 동안만 천체 시계를 진행한다. `astro_elapsed = active_sim_seconds × 60 + epoch_offset`으로 공전·자전을 같은 시간에 평가한다. 채집 0.6초·가공 6초·배양 등 **산업 시간에 60을 곱하지 않는다.** 오프라인/호스트 종료 중 시간은 첫 범위에서 정지한다. 협동 개인 메뉴에서는 세계 시간이 흐르고, 저장/재접속은 같은 위상으로 돌아온다. 항성 간 이동 연출이 임의로 며칠을 더하지 않는다.

## 기존 항해와 연결할 때의 필수 경계

신규 천체 시간 버전의 공전 각도는 우주 화면·지상 태양 방향이 같은 원본을 사용해야 한다. 물리 장반경을 게임 반경으로 압축하는 표현 매핑은 유지할 수 있지만, 우주 화면에서는 옛 주기로 돌고 지상에서는 새 주기로 도는 이중 궤도는 새 버전 완료로 인정하지 않는다. 성간 출발/도착·자동 접근은 같은 시간의 천체 위치를 추적한다. 바뀐 주기를 기존 저장에 무조건 소급하지 않는다.

이전 저장은 `legacy_cycles`로 읽고 기존 공전/위상을 유지한다. 새 천체 모델을 활성화하는 이행에서는 현재 시각의 위상을 보존하고 물리 메타데이터·버전을 함께 저장한다. 호환 이행 전에는 옛 저장이 새 현실 주기를 쓰는 것처럼 표시하지 않는다. 행성/광맥 주소·기지 위치·계약·장비는 유지한다.

밤의 환경 기온은 이번 첫 연결에서는 기존 지역 평균값을 유지한다. 낮밤마다 계약이 자동 실패하는 열 손실이나 태양광 전력 0을 조용히 추가하지 않는다. 주야 기온·일사 발전을 실제 생산에 넣는 단계에는 축전·기저 발전과 운전 비용까지 시간 예산에 반영한다. 처음에는 태양광을 기존 통합 전력 수치로 두고 실제 발전 변동 미구현을 기록한다. 밤에도 도구/작업등·차량 전조등으로 기본 탐험이 가능해야 한다.

## 구현·확인 범위

예정 파일은 `data/planetary_cycles.json`, `scripts/domain/planetary_cycles.gd`. 기존 `universe.gd`는 생성/천체 위치, `crew_world.gd`·`world_store.gd`는 시계/저장, `crew_authority.gd`·`crew_surface_replica.gd`는 스냅샷, `surface_atmosphere.gd`·`surface_sky.gdshader`는 하늘/광원에 연결한다. 만 개 이상의 행성을 매 프레임 갱신하지 않고 현재 항성계와 관찰 지역만 평가한다. 클라이언트는 호스트 시각을 보간하며 환경 원장을 바꾸지 않는다.

최소 확인은 같은 시드의 일반 하루 재현, 낮→일몰→밤의 태양/그림자/별 방향, 동주기 태양 고정, 저장/합류 후 위상 보존, 기존 항해 도착 위치와의 일치다. 시간 가속은 확인용으로 한 구간만 사용하고 장시간 전체 행성 전수 검사를 관행적으로 수행하지 않는다. 기존 하늘·조명과 새 기능의 실제 연결/미연결을 제작 기록에 구분한다. 설계 작성 당시에는 실행하지 않았으며, 후속 실제 확인 범위는 아래 제작 기록을 따른다.

## 2026-09-08 구현 기록

C16의 데이터·독립 시드·계산과 기존 저장 호환 기반, C17의 신규 세계 공전·지표 낮밤·태양/별·구름·야간 광원·표시/음향을 연결했다. [C16~C17 제작 기록](../production/50-seeded-cycles.md)에 현재 활성 상태와 실제 확인 범위를 기록한다. 위의 `active_sim_seconds` 의미는 기존 저장 필드 `crew.navigation.orbit_time`이 담당한다. 같은 시간을 두 필드에 중복 누적하지 않는다.
