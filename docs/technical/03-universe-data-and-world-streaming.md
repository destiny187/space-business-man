2026-09-06 확장 설계. 실제 우주 데이터를 활용한다는 방향은 확정 요구사항이다. 아래 자료 선택·생성·스트리밍·검증 방식은 **설계 제안**이다. 초기 설계에서는 공식 자료 설명만 확인했다. 이후 E0-A에서 NASA PS 3개 천체의 실제 취득·고정 카탈로그·관측 화면·100만 주소의 지연 생성·3D 항해와 탐험 저장을 구현했다. 기본 세계는 단일 은하다. 성역·티어 분포·시드 계층·실재 천체와 가상 성역의 배치 관계는 [은하 생성 설계](../game/11-galaxy-tiers-and-seeds.md)를 따른다. 아래는 천체 원본과 로컬 월드 구현의 기술적 소관이다.

## 실제 관측과 게임의 경계

| 정보 층 | 예시 | 표시와 처리 |
| --- | --- | --- |
| 관측·문헌값 | 천체명, 항성 특성, 궤도 주기, 반지름 등 | 출처·단위·오차·상하한·문헌 버전 보존 |

| 게임 생성 | 지표 지형·동굴·자원 세부 분포·생물·유적·문명 | 생성 시드·버전 기록, 가상 요소 표시 |

외계행성의 카탈로그를 실제 지표 지도나 생명 확인 자료로 취급하지 않는다. 지도·생태를 모르는 경우 빈값을 유지하고 가상 생성층을 따로 만든다. 실재 행성과 가상 행성을 성도·도감에서 구분하되, 플레이 중에는 읽기 쉬운 한 줄 출처와 상세 정보 보기로 제공한다.

## 우선 자료와 용도

공식 문서 확인일: **2026-09-06**. 아래 URL은 출처이며 다운로드 완료를 뜻하지 않는다.

실제 카탈로그에 관측된 천체가 많다는 이유로 전부 착륙 가능 콘텐츠로 만들지 않는다. 암석 표면·대기·중력에 따라 접근 가능성을 나누고 가스 거대행성은 궤도 조사·위성·후속 부유 거점 같은 별도 목표로 다룬다. 선택한 카탈로그는 은하 전체의 완전한 목록도, 실제 천체의 균등한 표본도 아니다.

### 최소 데이터 매핑 제안

| 원천 필드 예 | 정규화 값 | 사용·검사 |
| --- | --- | --- |
| `pl_name`, `hostname` | 원천 천체명·항성명, 내부 고정 ID | 표시 이름 변경과 ID 분리, 별칭 중복 검토 |
| `pl_rade` | 반지름 m | 지형 스케일의 물리 기준; 음수·0 불가 |
| `pl_bmasse`, `pl_bmassprov` | 질량 kg, 값의 종류 | 최소 질량·추정 질량을 확정 질량과 구분 |
| `pl_orbper`, `pl_orbsmax`, `pl_orbeccen` | s, m, 무차원 | 계절·일사 모델의 입력; 궤도 주기를 자전 주기로 대체하지 않음 |
| `pl_insol` | 지구 대비 입사 복사량 | 에너지 입력의 기준, 물리 단위 변환 상수 기록 |
| `pl_eqt` | 평형 온도 K | 지표 실측 온도로 쓰지 않음 |
| `st_teff`, `st_rad`, `st_lum` | K, m, 태양 대비 광도 | `st_lum`의 로그 표현을 선형 광도로 변환 후 사용 |
| `ra`, `dec`, `sy_dist` | 적경·적위·거리와 기준계 | 관측 방향·항성계 배치, 표면 지도와 무관 |
| 제공되는 `err1`, `err2`, `lim`, 참조 필드 | 비대칭 오차·한계값·출처 | 값마다 보존, 빈값을 0으로 대체하지 않음 |

필드의 정확한 단위·질량 종류·평형 온도 의미는 [공식 열 정의](https://exoplanetarchive.ipac.caltech.edu/docs/API_PS_columns.html)를 기준으로 한다. 정규화기는 실제 조회 스키마를 먼저 확인하며 존재하지 않는 참조·오차 열을 가정하지 않는다. 충분한 정보가 없으면 중력·온도는 범위 또는 가상 모델값으로 표시한다.

생명체 거주 가능 지대는 액체 물에 관한 후보 조건이며 실제 거주·생명 존재를 보증하지 않는다. 게임에서도 해당 지대라는 이유만으로 테라포밍 성공을 보장하지 않는다. [NASA 거주 가능 지대 설명](https://science.nasa.gov/exoplanets/what-is-the-habitable-zone-or-goldilocks-zone/).

## 데이터 취득과 재현성

```text
공식 원천 조회 → 원본과 조회 조건 보관 → 단위·오차·중복 검증
→ 동일 문헌 해 선택·누락 표시 → 게임 후보 카탈로그 검토
→ 버전 고정 → 시드 기반 세계 생성 → 플레이 변경분 저장
```

- 매니페스트에 출처 URL, 조회문·조회 시각, 원본 해시, 선택 정책, 정규화 버전, 생성기 버전, 사용한 문헌을 기록한다.
- 문헌 간 모순·오류 의심값은 제외·검토 상태로 격리한다. 조용히 임의 수치로 고치지 않는다.
- 게임 실행 때 실시간 API에 의존하지 않고 검증된 소규모 카탈로그를 동봉한다. 인터넷 단절·원천 서비스 변경이 저장된 세계를 바꾸지 않게 한다.
- 원천 데이터 갱신은 새 카탈로그 버전으로 배포한다. 기존 세이브의 반지름·지형·생물·항로를 자동 재생성하지 않는다.
- 출처의 인용 지침·자료별 이용 조건을 취득 단계에 기록한다. 천문 데이터 사용과 기관 로고·사진·일러스트 사용을 별개로 확인한다.
- 실재 천체의 미관측 위성을 게임용으로 추가하면 `fictional_satellite`로 명시하고 관측 카탈로그와 분리한다.

## 현실성의 기준과 가상 기술

현실 원칙은 선택을 설명하는 데 쓴다. 낮은 중력에서 대기 유지가 어렵고, 물을 공급하려면 물질이 필요하며, 열은 이동하거나 우주로 방출되어야 한다. 작은 위성의 시작 사업은 밀폐 구역·차폐 서식지부터 제안한다. 작은 시설 몇 개만으로 어떤 천체든 곧바로 지구가 되게 하지 않는다.

현대 기술로 화성의 현지 이산화탄소만 동원한 테라포밍에는 큰 물질 제약이 있다는 연구를 참고한다. 이 게임은 대규모 수송·고도 에너지 기술·시간 압축을 가상 전제로 사용할 수 있지만, 그것이 현재 가능한 기술이라는 설명은 하지 않는다. [NASA 화성 테라포밍 연구 소개](https://www.nasa.gov/news-release/mars-terraforming-not-possible-using-present-day-technology/).

도약 항법, 외계 생물, 고대 장치, 가속된 생태 시간은 가상 설정으로 관리한다. 관측을 보강하는 추정과 가상 기술의 효과를 같은 ‘실제 데이터’ 표시에 넣지 않는다.

## 월드 표현의 실증안

| 후보 | 장점 | 확인할 비용·한계 |
| --- | --- | --- |
| 높이 지형+별도 동굴 | 지표 넓이·시각 품질을 빠르게 검증 | 돌출·굴착 연결·동굴 출입구 봉합 |
| 지역 밀도장/복셀+원거리 지표 | 국소 굴착과 지하 연속성 | 메시·충돌 재생성·경계 LOD·저장 용량 |
| 전체 구체·전면 복셀 | 전면 자유 굴착·구형 이동 | 좌표 정밀도·메모리·경로·제작·검증 범위 |

추천 실증은 두 번째 후보를 작은 지역에 적용하고, 첫 번째 후보와 같은 대표 장면으로 비교하는 것이다. 무한 맵·행성 핵까지 굴착·실제 축척 전체 표면을 다음 버전의 약속으로 두지 않는다. Godot 엔진·플러그인 지원과 라이선스·유지 상태는 구현 착수 시 확인한다. 기존 1.2의 평면 이동 구조가 그대로 확장된다고 가정하지 않는다.

### 좌표·청크·지속성

- 논리 위치는 `system_id / body_id / region_id / chunk_id / local_position`으로 표현한다. 실제 거리를 가진 우주 좌표와 근거리 물리 좌표를 분리한다.
- 청크 원형은 천체 시드와 생성기 버전에서 재현한다. 굴착·자원 고갈·구조물·수위·발견은 변경분으로 저장한다.
- 근거리만 세부 메시·물리·개체를 활성화하고 중거리·원거리는 단순 표현으로 전환한다. 시각 LOD가 바뀌어 자원·생물이 새로 지급되면 안 된다.
- 플레이어·로봇의 현재 위치, 작업 접근점, 진행 중 이동 통로를 필요한 범위에서 유지한다. 해제된 구역을 향한 작업은 집계 이동 또는 명시적 대기로 전환한다.
- 지형 편집은 변경 청크와 이웃 경계를 함께 갱신한다. 화면 메시뿐 아니라 충돌·내비게이션·유체 구획 연결까지 같은 버전으로 전환한다.
- 원점 이동과 지역 전환을 비교 실증한다. 좌표 보정 중 시설·로봇·카메라가 어긋나거나 저장 위치가 바뀌면 실패다.

### 활성·비활성 시뮬레이션 제안

| 범위 | 계산 | 진행 제약 |
| --- | --- | --- |
| 참가자 중 누구라도 방문 중인 지역 | 실제 이동·굴착·물류, 세부 환경 | 호스트가 한 번 계산; 모든 참가자의 관심 지역 합집합 유지 |
| 같은 행성의 준비된 다른 지역 | 보관 재고·물류·설비·생태 집계 | 입력·전력·경로 용량 안에서만 진행 |
| 다른 행성 | 초기 실증에서는 일시정지 | 출발 화면에서 정지 범위를 명시; 후속 원격 운영 별도 검증 |
| 혼자 하는 게임의 메뉴·세계 종료 | 초기 실증에서는 정지 | 오프라인 표본 사망·무한 생산 없음 |
| 협동의 개인 메뉴·게스트 이탈 | 호스트 세계는 계속 진행 | 개인 창이 다른 참가자의 시간을 멈추지 않음 |
| 협동의 팀 일시정지·호스트 종료 | 전원에게 정지/종료 상태 적용 | 합류·장애·복구는 협동 문서 기준 |

세부↔집계 전환 시 자원·개체군·환경·진행 시간을 인계하여 같은 시간을 두 번 계산하지 않는다. 큰 시간 압축은 안정된 한 단계씩 나누어 처리하고 위험 경보 시 멈춘다. 재방문 순간 대규모 미계산 생산을 한 프레임에 몰아 처리하지 않는다.

협동의 공유 우주선과 지표·지하 분업은 [호스트 협동](../game/12-host-coop-and-crew.md)을 따른다. 호스트의 활성 계산 영역과 각 클라이언트의 렌더/수신 영역을 구분하고, 6명이 흩어졌을 때의 비용을 측정한다. 한 시드가 실제 굴착·고갈·선체·승무원 상태 동기화를 대신하지 않는다. [관심 구역·동기화](04-coop-networking-and-session-save.md).

## 기술 인수 조건

데이터는 단위 변환·결측·오차·최소 질량·중복 천체·동일 시드·버전 고정·원천 API 없이 천체를 읽는 실행을 검증한다. 이는 협동 플레이의 통신을 없앤다는 뜻이 아니며 네트워크 접속은 별도 검증한다. 월드는 경계 왕복·굴착 후 저장·충돌 갱신·로봇 경로·지역 해제·환경 집계 인계·작업 중 저장을 확인한다.

성능은 프레임 시간 p95, CPU/GPU·메모리, 청크 생성 시간, 저장 크기·시간, 장거리 이동 중 멈춤을 기록한다. 최대 월드 크기·청크 크기·목표 프레임 예산은 같은 실제 플레이 장면을 Apple M2와 목표 Windows 기기에서 측정한 뒤 결정한다. 독립 아트 품질 장면의 화면만으로 대규모 월드 성능을 통과시켰다고 기록하지 않는다.


## E0-B 현재 구현과 기술 근거

[지형 생성](../../우주-비즈니스/scripts/world/terrain_field.gd) · [청크 메시](../../우주-비즈니스/scripts/world/terrain_mesher.gd) · [스트리밍](../../우주-비즈니스/scripts/world/terrain_streamer.gd) · [원거리 지표](../../우주-비즈니스/scripts/world/distant_terrain.gd).

밀도장의 동일 격자 모서리에서 교점을 재사용하는 marching tetrahedra로 근거리 메시를 만든다. 이웃 청크의 경계 교점과 앞면 방향을 검사하고 그 메시의 삼각형으로 충돌을 만든다. 굴착 구를 청크별로 색인하며 경계 법선 계산 여유까지 관련 청크를 갱신한다. 원거리 높이 지형에는 충돌을 두지 않고 근거리 충돌이 준비된 곳으로만 플레이어를 이동시킨다. 현재 원거리 LOD 경계의 시각 개선은 미완료다.

작업 결과 패킷은 완료 대기 이후 주 스레드에서만 읽는다. 장면 종료에서도 각 작업을 회수한다. [Godot WorkerThreadPool 공식 문서](https://docs.godotengine.org/en/stable/classes/class_workerthreadpool.html)는 작업 완료 대기가 자원 회수에 필요함을 설명한다. [ArrayMesh 공식 문서](https://docs.godotengine.org/en/stable/classes/class_arraymesh.html)의 시계 방향 앞면 규약을 따른다.

이 실증은 가까운 굴착 가능 밀도 지형과 먼 높이 지형의 혼합안이다. 높이 지형 단독은 같은 좌표 아래 겹치는 동굴 천장·바닥을 표현할 수 없으며, 전체 밀도 격자 상주는 규모에 비례한 비용을 만든다. 아직 동일 조건의 대안별 실측 비용 비교를 완료하지 않았으므로 혼합안의 성능 우위를 측정 결과로 주장하지 않는다.

공통 INK 조명의 지역 광원은 거리 감쇠를 연속 적용한다. 방향광에 사용하는 그림자 경계 임계값을 손전등에 적용하면 멀리 있는 면이 불연속적으로 꺼졌다. [Godot 공간 셰이더 문서](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/spatial_shader.html)의 `LIGHT_IS_DIRECTIONAL`과 `ATTENUATION` 정의를 따라 분기하며, 별도 실제 GPU 검사에서 거리별 밝기와 소등을 확인한다.

## galaxy-v3 현재 구조

[은하 생성 소관](../game/11-galaxy-tiers-and-seeds.md)의 125,000 항성계·100만 행성 주소를 사용한다. `system()`은 항성 ID·유형을 반환하고 `body()`는 항성 소유·종류·착륙 여부·게임 원궤도 반경/위상/주기를 반환한다. `position(manifest, ordinal, elapsed)`를 호스트 항해와 실제 렌더가 함께 사용한다. `navigation.orbit_time`은 세계 저장과 스냅샷에 포함한다. 대기 중 선체는 현재 행성의 이동분을 따라가며, 다른 목적지를 선택해도 원래 위치 기준을 유지한다.

행성 반지름 판정은 공통 `radius()`를 사용한다. 성간 도약은 항성 위의 안전 위치로 진입하고 항성 중심을 가로지르는 접근 경로는 상부를 우회한다. 이는 항성 회피용 경로이며 모든 행성·선박 충돌을 다루는 완전한 우주 물리계가 아니다. 은하 지도는 일부 대표 항성계만 그리며 주소 입력으로 전체 범위에 접근한다. 100만 개의 실제 Node나 동시 시뮬레이션을 생성하지 않는다.
