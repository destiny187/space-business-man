# SP11 — CooperTech 우주 단서와 지상 로봇

2026-09-10 구현. [기업 우주 설계](../game/23-corporations-and-space-presence.md), [SP11 계획](../planning/16-space-corporations-commits.md)을 따른다.

CooperTech 감시·봉인 화물의 E 정밀 조사를 완료하면 같은 항성계의 착륙 가능한 T2 이상 행성에서 시드로 생성된 폐기 로봇 사건을 찾는다. 시험시설의 행성을 먼저 확인하고 조건이 맞지 않으면 다른 행성을 확인한다. 착륙지 주변 최대 5×5 타일의 실제 사건 중 하나를 연결하며 적합한 사건이 없으면 좌표를 만들지 않는다. 우주 단서 때문에 별도 복제 로봇·임의 보상 사건을 생성하지 않는다.

## 연결과 실제 플레이

`coopertech_clues`는 출처 trace ID와 기존 지상 incident ID/행성 주소를 저장한다. 원래 시드 사건이 아직 저장되지 않았으면 같은 생성 행을 미발견 상태로 보존하며, 이미 발견/종결된 사건은 원래 상태를 유지한다. 실제 지상 로봇의 `seen`과 `claimed`에서 좌표 확보→발견→종결을 읽는다. 새 링크는 우주 조사 결과와 같은 저장으로 확정한다.

J에서 제조사 심볼·실제 로봇 모델·출처·좌표·현재 단계를 확인하고 목적 행성 또는 현장 지도에 표시할 수 있다. 지상 Tab 지도와 현장 방향/거리 표식이 같은 좌표를 가리킨다. 현장 로봇이 기동·조준·사격하고 플레이어가 실제 공격무기로 제압한 후 부품을 회수해야 종결된다. 단서 자체의 별도 보상은 없다. 기존 지상 사건의 호스트 판정·단발 부품/모듈 회수 규칙을 재사용한다.

신규 manifest의 `corporate_space.coopertech_links.version=1`에만 적용하며 기존 은하에 단서를 소급 생성하지 않는다. 기존 저장 호환용 콘텐츠 ID `illuti_dormant_combat_robot`은 유지하지만 사용자 표기와 디자인은 CooperTech다. 새로운 로봇 종류·우주 전투·다른 회사와의 적대 관계는 추가하지 않는다.

## 아트·음원·확인

SP02의 Blender 원본 `art/blender/incidents/robot.blend`, 내보낸 robot GLB와 제조사 표식을 재사용했다. 기존 Blender 렌더와 현재 Forward+ INK 지상 렌더에서 모델을 확인했고, 실제 기동/조준/공격·파괴·부품 회수에 연결했다. 새 비트맵/3D/음원 생성 없이 기존 ElevenLabs 로봇 기동/전투/회수음을 재생한다. 주관적 청음은 수행하지 않았다.

- `check_coopertech_clues.gd`: 19개 확인. 실제 호스트 E 조사, 동일 시드/사건 ID, 기존 저장, 중복 생성 방지, 착륙·기동·실제 교전 요청·부품 회수·중복 거부·저장/재로드.
- `check_coopertech_clues_play.gd`: 실제 Forward+ 원정 22개 확인. J/960px·행성지도·방향 표식·동일 로봇 기동/조준·기존 음원 재생·장비 발사/실제 F 회수·원본 단서 종결·저장/재로드. 장거리 이동은 접근 위치를 설정했다.
- 로봇 미리보기의 정면/크기를 보완한 후 J/지도만 재확인했다. 대표 캡처는 `media/coopertech-clues/`에 둔다.
- 전체 지상 기본 루프·T4/T5·전체 시드/장시간 성능 검사는 수행하지 않았다. SP09~11 다중 클라이언트/재접속은 후속 통합 기록에 둔다.
