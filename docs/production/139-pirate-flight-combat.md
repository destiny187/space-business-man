# 항해 해적 전투 첫 구현

2026-09-12. 사용자의 “둘 다 개발”과 “개발진행해줘”에 따라 [해적 습격 소관](../game/28-pirate-interdiction.md)의 P01~P03 첫 범위를 현재 `crew_expedition.tscn`에 연결했다. **성간 이동과 같은 항성계 내부 이동을 모두 포함**한다. 새 원정에서 적용하며, 독립 포탑·전투정 출격·대기권 공중전은 후속이다.

후속으로 기체 가독성·기동/공격 관절·피격/파괴를 고도화했다. 현재 모델·탄 판정·카메라·실제 확인은 [141 품질 기록](141-pirate-combat-quality.md)이 우선하며 아래 수치는 첫 제작 이력이다. 링크된 모델 렌더는 현재 교체 자산을 표시한다.

## 같은 날 후속 — 설명 문구를 교신으로 전환

사용자 정정에 따라 접근 전조의 `해적 접근`만 중앙 위험 안내로 남겼다. 전투/격퇴/추격 종료/복구의 단계명과 상시 함포/가속 설명, 이탈 방향이라는 문장, 인양/정비 중이라는 문구와 구분자 점을 없앴다. 교전 중 기존 항해 안내도 숨긴다. 기체 이름과 필수 상태 수치는 유지하고 포드는 마름모·거리·F, 정비는 공구 아이콘·R·비용, 작업 진행은 아이콘과 막대로 표시한다.

교전 시작과 도주 확정 때 살아 있는 해적이 짧게 교신한다. 발신 선박과 수신 선박/편대를 표시하고 본문은 각각 `앞의 선박, 거기 멈춰라.`, `추격 중지. 전 기체 복귀.`다. `space_combat.json`의 `radio`에 문구와 4초 표시 시간을 두고 호스트 이벤트 순번으로 전달한다. 첫 스냅샷/재접속의 과거 이벤트는 재생하지 않으며 메뉴를 열면 현재 교신을 지운다. 아직 나타나지 않은 구조선이나 사망한 적이 대사를 보내지 않으며 격퇴/회수마다 시스템 설명을 대사로 바꿔 넣지 않는다. **자막 교신이며 새 음성/효과음 제작은 없다.**

현재 원정의 Godot Forward+에서 `check_pirate_play.gd --radio-preview`로 해당 교신 흐름만 확인해 **8개를 통과**했다. 접근 전조, 실제 호스트의 호출/철수, 4초 뒤 사라짐, 메뉴 차단, 재진입 때 과거 교신 생략을 확인했다. 교전 중 기존 주행 안내를 숨기는 마지막 수정 뒤에는 `--radio-still`로 호출 화면만 다시 렌더했다. [첫 위험 안내](media/pirate-combat/radio-first-warning.png), [원정선 호출](media/pirate-combat/radio-contact.png), [960px 교신](media/pirate-combat/radio-contact-960.png), [철수 교신](media/pirate-combat/radio-withdrawal-960.png). 철수 캡처는 항해가 재개된 상태다. 로그는 로컬 `output/pirate-combat/radio-preview.log`, `radio-still.log`에 남긴다. 기존 전투 전체 검사·Blender 재제작·전체 회귀는 수행하지 않았다. 아래 첫 제작 캡처는 설명 정리 전 이력이다.

## 현재 플레이

- 성간 항해 출발 때 호스트가 항로의 습격 여부를 고정한다. 발생하면 목적 항성계 감속 끝부분에서 현재 비행 위치를 이어받아 자동 접근을 중단한다. 목적 행성은 방문 완료로 처리하지 않는다.
- 항성계 내부에서는 직접 비행·자동 접근 중 이동 시간과 거리를 채운 구간마다 판정한다. 원정선과 FINCH가 같은 발생 완충을 공유한다. T1·Sol·첫 목적 항성계·착륙/정거장·항성 위험 구간은 보호한다.
- 원정선에는 조종 방향과 연동되는 펄스포가 있다. 기존 마우스 선회·W/S 추진·A/D 선회·Shift 가속을 유지하고 좌클릭으로 사격한다. 호스트가 사거리·사격각·연사 간격·방열·실드/선체 피해를 확정한다. 첫 탄은 즉시 광선 교차 판정이며 실물 광선·피격·파괴를 표시한다. 우클릭 조준 보조·탄도 선행 조준·독립 포탑은 아직 없다.
- 추격기는 플레이어 주변을 선회하고 교란선은 넓은 동체와 전개 장치로 구역을 지킨다. 조준 전조 뒤 고정한 사선에 발사하므로 이동해서 피할 수 있다. 교란선을 남겨 둔 채 범위를 벗어나도 도주가 성립한다. 비무장 FINCH에는 추격기 한 척과 짧은 추격 상한을 사용한다.
- 실드는 비피격 시간이 지나면 회복한다. 선체가 무력화되면 같은 항성계의 안전한 가까운 공간으로 긴급 회수하고 기초 이동을 복구한다. 기존 화물·장비·연구를 잃지 않으며 잔고가 없어도 원정을 계속한다. 안전 확보 후 정지해 R로 유료 정비한다.
- 격파한 기체는 실제 회수 포드를 남긴다. 100m 이내에서 포드를 바라보고 정지한 뒤 F로 인양한다. 진행 시간이 끝나면 원정선 공동 화물 또는 해당 FINCH의 화물창에 한 번 넣는다. 공간이 부족하면 이유를 보여 주고 포드를 보존한다. 첫 전리품은 철·구리이며 전투 설계도/별도 판매 체계는 없다.
- 접속을 끊은 FINCH의 전투는 보류된다. 호스트가 기존 이탈 승무원 회수를 명시적으로 실행하면 화물을 보존하고 전투 기록도 정리한다. 접속 중인 승무원과 재접속 처리 중인 승무원은 이 경로로 강제 회수할 수 없다.

## 초기 밸런스와 단순화

수치는 `data/space_combat.json`으로 관리하며 사용자 확정 밸런스가 아니다.

| 항목 | 첫 값 |
| --- | --- |
| 습격 허용 | T2 이상, Sol·첫 목적 항성계 제외 |
| 성간 / 내부 구간 발생 확률 | 22% / 14% |
| 내부 관측 구간 | 움직인 시간 90초와 이동 거리 2,500m 모두 충족 |
| 사건 뒤 보호 | 공유 대기 600초와 두 이동 구간 보호 |
| 최초 접근 / 저장 재개 전조 | 8초 / 5초 |
| 원정선 / FINCH 편성 | 추격기+교란선 / 추격기 1척 |
| 추격 상한 | 원정선 100초 / FINCH 32초 |
| 도주 | 발생 지점과 교란 범위 밖 1,150m·4초 유지 |
| 무력화 회수 | 6초, 선체 35와 실드 절반 복구 |
| 완전 정비 | 공동 60 Cr, 안전 정지 후 2.5초 |
| 인양 | 100m, 정지 상태로 2.5초 |

지역 세력 영향·누적 화물 가치·인원 수에 따른 적 증강은 아직 없다. 전투 실드는 항해 내성과 분리된 고정 기본 수치다. 원정선 전투 속도에 제한을 두며 함포는 한 계열이다. 교란 장치 전체 부위 파괴 대신 교란선의 생존과 실물 거리로 방해를 판정한다. 첫 회수는 별도 구조선 모델 없이 기존 선체의 이동과 복구 상태로 표현한다. 미인양 포드는 사건 뒤에도 남으며 세계에 최대 24개를 보존한다.

## 호스트·저장 경계

`domain/space_combat.gd`가 발생 순번·구간 판정·상태·적·발사 결과·실드/열·잔해를 `crew.space_combat`에 보존한다. 기존 `crew_navigation.gd`는 감속 차단 접점·전투 속도·회수 중 조종 제한을 맡는다. `crew_authority.gd`와 `crew_session.gd`는 기존 입력 순번/만료·참가자/조종사 권한·공개 스냅샷·체크포인트 경로를 사용한다.

인양/정비 시작 요청은 기존 순번 영수증·세계 revision·저장 후 확정 절차를 거친다. 완료 시 실제 적재 공간과 공동 비용을 다시 검사한다. 반복 요청은 비용/전리품을 중복 정산하지 않는다. 중요 상태와 활성 교전의 주기 기록을 저장하며 저장 실패 시 호스트를 정지해 미확정 결과의 공개를 차단한다. 입력이 준비되지 않은 초기/재개 경고에서는 공격을 진행하지 않고, 진행 중 개인 메뉴를 열어 협동 전투 전체를 멈추지는 않는다.

**기존 저장에는 `space_combat`를 추가하지 않는다.** 새 세계에서만 규칙을 만들고 기존 세계의 진행 중 항해·화물·선체를 보존한다. 이미 전투가 시작된 새 세계를 다시 열면 같은 적·내구도·잔해를 복원한다. 콘텐츠 해시에 새 전투 설정을 포함하므로 참가자는 같은 버전을 사용한다.

## 확인한 범위와 한계

- `check_pirate_rules.gd`: **42개 통과**. 두 구간의 자연 항해 처리 접점, 실드·연사·격파·비격파 도주·완충 두 구간·화물 소유·중복 인양/비용·무력화·저장/재개·요청 저장 실패를 확인했다. 발생 접점 검사는 임시 확률 100%를 쓰고 복구하므로 실제 22%/14%의 체감 빈도 측정이 아니다.
- `check_pirate_recall.gd`: **8개 통과**. 두 peer의 참가/확인 절차·동일 교전 스냅샷·다른 선체 무장 거부·접속 중 회수 거부·오프라인 FINCH 회수와 화물 보존을 확인했다. 두 기기를 인터넷으로 연결한 검증은 아니다.
- `check_pirate_play.gd`: Godot 4.7.2 Metal Forward+의 현재 원정 장면에서 호스트 경고→사격/피격→파괴/포드, 음원 재생·메뉴 차단·960×640, FINCH의 추격/무력화/인양과 정상 저장 종료·재로드를 확인했다. `play5.log`는 **21개 통과, 포커스 입력 1개 실패**다. 이 실패는 Mac 잠금으로 테스트 창이 포커스를 받지 못한 원인으로 확인했다. 실제 조준/피격 검사는 `session.send_input`으로 현재 호스트 경로를 구동했다.
- 마지막 `--collector-only` 확인은 **7개 통과, 포커스 상태의 마우스 입력은 건너뜀**이다. 창 비활성 시 발사 준비 입력이 차단되는 동작, 전투 중 도착 제목을 생략하는 처리와 최종 글자 굵기를 확인했다. Mac 잠금 해제 상태의 실제 마우스 선회·클릭 손맛을 검증한 것으로 간주하지 않는다.
- Blender 렌더와 실제 Godot INK 렌더를 확인했다. 초기 화면의 수치 중복·안내 가림과 보호 구간 경계 조건을 수정했다. 규칙 테스트의 미생성 사업 원장, 회수 테스트의 안전하지 않은 고정 위치를 올바른 준비 상태로 고쳐 해당 검사만 다시 실행했다.

로그는 로컬 `output/pirate-combat/`의 `rules5.log`, `recall2.log`, `play5.log`, `input-check.log`, `blender.log`, `ink.log`에 남긴다. 사용자의 기존 저장과 실행 중 편집기를 종료하지 않고 `/tmp/space-pirate-play`의 독립 검수 저장을 사용했다. 전체 지상 회귀·6인 실접속·Windows·전 시드 장애물 배치·장시간 탐험 빈도/성능·완전한 조작/청감 검수는 하지 않았다. 독립 포탑·전투정 획득/출격·미사일·부위별 파괴·새 전투 설계도는 미구현이다.
