# SP07 — 시드 기업 진출권·거점·행성 간 항로

2026-09-10. 새 세계의 태양계 밖에 기업 활동을 연결했다. [SP 계획](../planning/16-space-corporations-commits.md)의 SP07이며, 실물 흔적·정비·보상 사건 전체가 완료된 단계는 아니다.

## 거점의 용도와 실제 범위

사용자는 제작 중 **회사별 거점의 용도를 명확히 하고, 같은 건물의 표식만 교체하는 형태를 피하라**고 요청했다. 이에 따라 아래 역할을 제작 기준으로 삼아 건물 구조·작업 장치·실루엣을 교체했다. 같은 CARRIER가 이용하는 선석 위치와 화물 인터페이스만 공통 규격이다.

| 회사 | 거점의 역할 | 이번 모델에 드러낸 구조 | 현재 작동 / 후속 |
| --- | --- | --- | --- |
| Space Y | 복원 행성 환경 운영과 물류 중계 | 기존 원통형 운영항, 환경 유지 탱크, 통신 설비 | 관리 행성·운송·경비 / 도시 방문 후속 |
| Lotus | 개척 보급과 선박 출동 | 내부가 열린 곡면 격납고, 보급 포드, 출동 갑판, 비대칭 통신 비콘 | 보급품 NPC 하역 / 이 거점에서 받는 의뢰·직접 보급 서비스 후속 |
| mine | 광물 집하와 자동 채집기계 정비 | 긴 노출 프레임, 저장조·깔때기·선별 롤러, 부품 정비 선반, 유압 하역 장치 | 선별 장치 모션·기계 부품 NPC 운송 / 실제 정비·채집 생산 원장 후속 |
| CooperTech | 전투로봇 시험과 봉인 수송 | 낮은 팔각 장갑 기지, 격리 시험 셔터, 장갑 보관고, 봉인 컨테이너, 감시 센서 | 센서 모션·봉인 장비 NPC 운송 / 시험장 입장·경계 대응·지상 단서 후속 |
| 철수한 물류항 | 기업 철수의 흔적 | 끊긴 연결대, 떨어진 선석, 꺾인 방열판과 빈 표식 | 운항 중단 / 회수·구조 사건 후속 |

Lotus의 기존 지상 보급 호출과 mine 자동 채광로봇은 기존 규칙을 유지한다. 위 신규 거점은 기업 전용 선석이며 새 시장·F 거래·정비 보상은 제공하지 않는다. CooperTech는 독립 전투로봇 회사이며 일루미나티 문양·설정을 사용하지 않는다.

## 생성·저장

- `corporate_space.expansion.version = 1`을 새 manifest에 보관한다. 버전이 없는 기존 저장에는 기업 거점·관리권·새 항로를 소급 추가하지 않는다.
- 지도 좌표의 180 단위 셀별 독립 난수로 운영 중심·개척 전선·산업 공급권·제한 연구권·쇠퇴 항로·미진출권을 고른다. 권역별 실제 입주율은 별도 데이터다. 현재 수치는 밸런스 초안이다.
- 지형·광물·동굴·궤도 난수를 소비하지 않는다. 이미 생성된 암석 행성을 후보로 고르고, 산업 공급권은 철 주산지에 우선순위를 준다. 최소 두 개의 적합한 행성이 없으면 기업 배치를 생략한다.
- 운영 중심에서 자유 착륙 후보가 세 개 이상일 때만 하나를 Space Y 복원 행성으로 지정한다. 적어도 두 개의 원래 자유 후보를 남긴다. 추천 첫 원정 항성계는 미진출권으로 보장하고 기존 정거장의 첫 목적지 제외는 유지한다.
- 관리 행성은 원래 시드 모델·지형 정보를 유지한 채 해양·녹색 육지·구름·대기·야간 운영 불빛을 표현한다. 실제 관측값이나 플레이어의 복원 성과를 덮어쓰지 않는다. 관리권에 따른 착륙 제한을 가스행성 재질 선택과 분리했다.
- 항성계마다 최대 두 거점과 하나의 왕복 항로를 만든다. `corp_<system>_<slot>` 주소 쌍을 정렬한 항로 ID와 선박 ID를 사용한다. 항로 양 끝은 공전하는 실제 거점이다. 이번 연결은 **같은 항성계 안의 서로 다른 행성 간 항로**이며 성간 물류망은 아니다.
- profile 캐시는 최대 96개다. 백만 행성/우주선 Node를 미리 생성하지 않는다. 새 배치 버전과 게임 시간을 저장하므로 재방문·재개 때 다시 추첨하지 않는다.

## 운항·관찰·지도

정상 항로는 Space Y CARRIER 2척이 8단계로 왕복한다. 회사 거점의 반대편에 Space Y 중계항이 있고 화물은 환경 유지 모듈·개척 보급품·광물/기계 부품·봉인 장비로 구분한다. 쇠퇴 항로에는 작동 중인 배를 넣지 않는다. 운영 중심은 기존 WARDEN 2기 편대와 센서 확인/복귀도 연결한다. 플레이어 피해·우주 교전·항해 허가 잠금은 없다.

각 클라이언트는 현재 항성계 선박만 만든다. 가까운/주시 선박은 0.1초, 먼 선박은 1초 간격으로 위치를 계산하고 중간 화면은 보간한다. 모델/가동부 목록을 캐시하고 기존 CARRIER/WARDEN LOD를 사용한다. 신규 거점은 최대 두 모델이며 별도 거점 LOD는 아직 없다.

호스트의 관심 선박 목록은 공동선과 출동 FINCH의 항성계 주소를 포함한다. 다른 항성계의 같은 좌표가 경비 확인을 유발하지 않는다. 경비 기록은 관심 항성계에만 생성하고 떠난 뒤 재접근 대기 시간이 지난 기록을 정리한다. 거래 재입고·가격·플레이어 운송을 변경하지 않는다.

가까운 거점을 주시하면 진행 링과 스캔음, 완료 신호 뒤 회사 심볼·시설 이름·화물/운영 상태가 나타난다. 완료한 행성/거점 식별은 기존 개인 항해 기록에 저장한다. 지도에서는 미확인 마름모가 식별한 회사 심볼로 바뀌며 두 끝을 조사한 항로만 표시한다. 전용 거점의 단계별 공유 조사 원장·J 기업 사건 기록은 SP08이다. 메뉴·성간 이동·비활성 화면에서는 주시 HUD와 불필요한 소리를 차단한다.

## 제작과 확인

- 원본/내보내기: `tools/build_corporate_relays.py`, `art/blender/ships/relay_*.blend`, `assets/models/ships/relay_*.glb`, `corporate_relays.json`.
- 공통 `ink_blender.py` / `ink_materials.json`, 곡면·모서리·기구·재질별 정적 메시 병합을 적용했다. 최종 디자인 revision은 2다. 선석/크레인 축은 NPC 하역과 맞추고 mine 선별기·CooperTech 센서 가동 축을 게임에 연결했다.
- Blender Cycles 4종과 Godot Forward+ / Metal INK 4종을 렌더했다. 실제 원정 25항목에서 권역별 모델·주시 식별·개인 기록 재개·Lotus 하역·가동부·완료음·960×640·메뉴 차단을 확인했다. 지도 공개 단계는 실제 지도 Control을 별도로 렌더해 확인했다.
- `check_corporate_regions.gd`: 시드 61739의 여섯 권역 대표 사례, 캐시를 비운 재생성, 지질 보존, 기존 저장 제외, 왕복 단계·천체/위성 여유, 관심 항성계 분리, 먼 거리 계산 빈도, 저장 후 ID/위치/위상 동일성을 확인했다.
- `check_traffic_sampling.gd`: 카메라가 원거리로 이동할 때 위치가 되돌아가던 보간 분모를 수정하고 같은 시각의 위치 연속성을 확인했다.
- `check_corporate_regions_play.gd`: 실제 현재 원정 화면을 사용한다. 재제작 중 항해 UI의 별도 미커밋 항해 내성 표시에서 혼합 들여쓰기가 발견되어 해당 들여쓰기만 정리한 뒤 화면 확인을 다시 수행했다. 그 항해 내성 기능은 SP07 커밋 범위가 아니다.
- 소리: 기존 ElevenLabs `sfx_orbital_scan`, `sfx_orbital_complete`, `sfx_vessel_engine`을 재사용한다. 출처는 `audio/manifests/space-experience.json`, 운항 용도는 `space-traffic-reuse.json`이다. 이번 거점의 완료 신호 재생 연결을 실제 창에서 확인했다. 새 음성/효과음 생성과 주관적 청감 평가는 수행하지 않았다.

다중 클라이언트 실접속·모든 시드/항로·장시간 성능·지상 기본 루프 전체 재검사는 수행하지 않았다. 지상 시설·도구·건축 코드는 이번 변경 대상이 아니다. SP08부터 흔적/조사, 이후 유실 화물·mine 정비·CooperTech 지상 사건 연결을 진행한다.
