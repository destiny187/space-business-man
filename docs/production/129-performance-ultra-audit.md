# 성능 실측과 울트라 그래픽 후보 조사

2026-09-11 사용자 요청에 따라 현재 원정의 성능을 실제 Forward+ 창에서 측정하고, 고사양 PC용 울트라 확장 여지를 조사했다. **울트라 프리셋은 아직 제품에 추가하지 않았다.** 이번 변경은 조사 기록과 별도 계측 도구의 호출 규격 수정이다. 이전 순차 구현은 [O01~O10 기록](128-performance-and-content-commits.md)을 따른다.

## 판단

현재 높은 옵션 위에 그림자·접지 음영·근거리 모델·지표 장식 품질을 올릴 여지는 있다. 다만 이번 M2 실행에서는 정지 화면의 픽셀 처리 비용과 보행 중 메인 스레드 지연이 함께 나타났다. 특히 최대 0.94초 보행 프레임은 GPU용 옵션을 추가하는 것만으로 해결할 수 없다. 먼저 광맥/시설 표시와 지상 갱신을 분산한 뒤, 울트라의 각 효과를 독립 선택 가능하게 개발하는 순서를 제안한다.

목표 사양 회신 전 조사 기준은 **2560×1440·60 FPS**다. 아래 수치는 Apple M2의 개발 환경 실측이며, 고사양 Windows PC의 달성 성능이나 권장 GPU를 의미하지 않는다.

## 측정 조건과 재현 자료

- Apple M2, GPU 10코어, 통합 메모리 24GiB. Godot 4.7.2 `ed1daf0bf`, Metal Forward+.
- 기준 HEAD `b7ad1e18` 이후의 현재 작업 폴더를 실행했다. 기존의 생물 제작·행성 표면 등 미커밋 변경도 포함하므로 순수 HEAD 빌드 성능으로 해석하지 않는다. 측정 시작 상태는 `output/performance-ultra-20260911/revision.txt`에 보존했다.
- 실제 `crew_expedition.tscn`의 로컬 호스트 1명. 사용자 저장 대신 앞선 확인용 세계의 복사본과 분리된 설정을 사용했다. 기존 에디터는 닫지 않았으며 약 10~11% CPU를 사용하던 공유 개발 환경이다. 백그라운드 부하와 온도를 완전히 통제한 벤치마크가 아니다.
- VSync와 FPS 제한을 해제했다. 창과 저장 PNG의 실제 크기는 1280×800 / 2560×1440으로 확인했다. Retina 배율 2를 렌더 해상도에 다시 곱하지 않았다.
- 초기 장면 준비 후 설정별 대기, 지형 대기열 확인, 추가 3초 준비를 거쳐 정지 12초 / 보행 20초를 수집했다. 지상 두 장면은 1440p 측정을 보행 후 위치에서 수행했으므로 800p와의 순수 해상도 배율 비교에 사용하지 않는다.
- FPS는 실제 `process_frame` 사이 경과 시간의 평균에서 계산했다. p95는 느린 쪽 5% 경계의 프레임 시간이며 낮을수록 좋다. 1% low는 가장 느린 1% 프레임 시간 평균의 역수다. 단시간 표본이므로 반복 측정의 신뢰구간은 없다.
- GPU 시간 조회는 이 환경에서 0을 반환했다. 결과에서 `null`로 처리했으며 GPU가 0ms라는 뜻이 아니다. 렌더 CPU 시간·`TIME_PROCESS`·물리 모니터를 전체 프레임의 정확한 CPU/GPU 분해로 사용하지 않았다.

| 장면 | 격리 세계와 실제 구성 |
| --- | --- |
| 생물 지상 | 시드 71503, Regulus 0002 d, 생태 표시 개체 16, 시설 0, 밤 |
| 시설 지상 | 같은 시드, Schedar 31632 h, 시설 7, 생태 표시 개체 0, 밤. 시설 앞 좌표 (-46, -882)로 이동 |
| 우주 외측 | 시드 61739, 화성 항만에서 외부 화면. 주로 우주선과 별이 보이는 방향 |
| 화성 근접 | 같은 우주 세계, 복원 화성의 밝은 면을 바라보도록 선박·카메라를 배치 |
| 낮 시설 | 시설 세계 복사본에서 착륙 경도만 낮으로 준비. 두 조명 조건 비교용 |

원자료는 모두 `output/performance-ultra-20260911/` 아래에 있다. `benchmark_current.gd`, `benchmark_planet.gd`, `benchmark_daylight.gd`가 실제 실행한 스크립트이며 각 장면 폴더에 `context.json`, `results.json`, `*-frames.json`, PNG를 보존했다. 프레임 원자료는 공개용 소스 자산이 아닌 로컬 재생성 결과다.

실행 형식은 다음과 같다. `--crew-folder`는 반드시 사용자 저장과 다른 확인용 복사본이어야 한다.

```sh

  --path "우주-비즈니스" \
  --script "$PWD/output/performance-ultra-20260911/benchmark_current.gd" \
  -- --crew-ui-test \
  --crew-folder="$PWD/output/performance-ultra-20260911/ground" \
  --scenario=ground
```

## 실제 결과

1280×800 정지 화면. 숫자는 평균 FPS / p95 프레임 시간(ms)이다.

| 장면 | 중간 | 높음 | 높음·렌더 배율 50% | 울트라 조명 실험 |
| --- | ---: | ---: | ---: | ---: |
| 생물 지상 | 35.8 / 42.8 | 25.9 / 62.5 | 50.8 / 33.0 | 18.7 / 70.2 |
| 시설 지상 | 36.4 / 81.5 | 28.8 / 87.0 | 35.6 / 77.3 | 17.3 / 135.4 |
| 우주 외측 | 47.1 / 46.6 | 38.2 / 68.1 | 40.7 / 59.6 | 27.3 / 67.0 |
| 화성 근접 | 미측정 | 32.6 / 71.3 | 52.7 / 38.5 | 미측정 |

생물 지상과 화성 근접은 내부 렌더 해상도를 낮출 때 개선이 커서 픽셀 처리 비용의 영향이 크다고 추정한다. 시설과 우주 외측은 개선 폭이 작아 다른 갱신·동기화 비용도 함께 확인해야 한다. GPU 타이머가 없으므로 특정 셰이더가 몇 ms라는 결론은 내리지 않았다.

| 높음 조건 | 평균 FPS | p95 ms | 최악 ms |
| --- | ---: | ---: | ---: |
| 생물 지상 20초 보행, 실제 84.5m | 9.9 | 299.9 | 936.5 |
| 시설 지상 20초 보행 | 23.0 | 159.2 | 496.2 |
| 생물 지상 2560×1440, 보행 후 | 9.4 | 143.3 | 195.8 |
| 시설 지상 2560×1440, 보행 후 | 9.8 | 163.3 | 208.5 |
| 우주 외측 2560×1440 | 11.2 | 147.4 | 242.9 |
| 화성 근접 2560×1440 | 12.7 | 121.3 | 162.4 |

생물 보행의 1% low는 1.13 FPS, 100ms 초과 프레임은 59개였다. 정지 평균 FPS보다 이동 중 멈칫하는 문제가 우선이다. 이전 최적화 커밋들의 동일 조건 변경 전 FPS를 측정한 것은 아니므로 이번 결과로 이전 개선율을 주장하지 않는다.

화성 근접에서 125% 렌더 배율은 32.6 → 25.8 FPS, p95 71.3 → 77.0ms였다. 실제 픽셀 수는 1.5625배다. 두 화면을 확인했으나 우주선 윤곽·행성 표면의 전체 인상 변화는 비용에 비해 작았다. 시간 경과에 따른 화성 회전이 있으므로 픽셀 단위의 동일 프레임 화질 비교는 아니다.

### 조명 실험의 범위

`ultra_lighting`은 높음 설정에서 방향광 그림자 8192, 지역광 atlas 4096, 필터 값 4, 태양 각도 0.5°, 캐스케이드 혼합, SSAO/SSIL High·전체 해상도, SSR 최대 스텝 96을 함께 적용했다. MSAA 4×, 렌더 배율 100%, 시야 4800m, 그림자 거리 220m는 유지했다. 이 복합 실험은 개별 효과의 기여도를 분리한 결과가 아니다.

생물/시설 밤 지상의 평균 FPS는 약 28% / 40% 감소했다. 엔진의 비디오 메모리 할당 카운터는 각각 약 138MiB 늘었다. 이는 M2의 실제 전용 VRAM 사용량이나 프로세스 전체 RSS를 뜻하지 않는다. 낮 시설에서도 실제 렌더를 확인했으며 전체 형태 변화보다 도구 표면·접촉부의 음영 변화가 중심이었다. 비용만 올린 조합을 울트라 완료로 취급하지 않는다.

낮 시설의 유효 재측정: 높음 22.1 FPS / p95 134.2ms, 조명 실험 15.4 FPS / p95 192.5ms. 준비 시 태양 높이는 0.986였다. 앞선 낮 측정은 큰 Git 인덱스 조회와 겹쳐 제외하고 daylight-interfered/에 별도 보존한 뒤 재측정했다.

8× MSAA 실행 자료도 남아 있지만 **유효 비교에서 제외**했다. Metal의 `supportsTextureSampleCount`를 직접 조회한 결과 이 Apple M2는 1/2/4만 지원하고 8/16은 지원하지 않았다. Godot 속성값을 설정할 수 있다는 사실만으로 실제 8× 렌더링을 확인할 수 없다. `metal-capabilities.log`에 근거를 보존했다.

## 보행 CPU 지연

기존 `tools/prepare_performance_audit.py`로 소스 사본을 만들고 83개 `_process` / `_physics_process` 콜백을 계측했다. 이번에 `authority.snapshot`의 추가 공통 자료 인자를 전달하도록 계측 래퍼를 수정했다. 제품의 네트워크 로직은 바꾸지 않았다.

별도 20초 보행에서 328프레임·100.6m를 기록했다. 계측을 넣은 별도 실행이므로 위 비계측 보행 FPS와 직접 비교하지 않는다. 아래는 콜백 내부에서 발생한 엔진 호출·대기까지 포함한 경과 시간이며, 순수 GDScript 연산량만의 수치는 아니다.

| 콜백 | 렌더 프레임당 누적 시간 평균 | 단일 호출 최대 | 판단 |
| --- | ---: | ---: | --- |
| `business_site_view._process` | 13.7ms | 243.3ms | 광맥·시설 표시 갱신이 큰 비용 |
| `surface_ecology._process` | 7.1ms | 53.7ms | 생물 배치·지면 조회·표현 갱신 비용 |
| `crew_surface_scene._process` | 5.0ms | 262.3ms | 관심 구역·원경·지면 등 지상 갱신 추가 분해 필요 |
| `crew_session._process` | 3.3ms | 32.4ms | 세션 갱신도 계속 추적할 대상 |
| `bestiary_actor._process` 전체 | 0.6ms | 0.55ms | 이 표본에서는 개별 생물 모션보다 상위 생태 갱신의 비용이 큼 |

추가 계측에서 `authority.snapshot`은 136회 총 91.9ms, 최대 1.10ms, 스냅샷 UI 적용은 최대 4.26ms, 저장 쓰기 한 번은 33.3ms였다. 원자료는 `walk-profile/cpu-walk.json`이다. 최대 936ms 프레임 전체가 위 한 함수 때문이라고 특정하지 않는다.

코드를 함께 읽었을 때 다음 작업이 유효하다.

1. `business_site_view.gd`는 광맥 타일이 바뀌면 `accept(ledger)`를 수행하고, 개별 모델을 완성할 때도 전체 상태를 다시 적용한다. 변경된 광맥/시설만 갱신하고, 모델·라벨 생성과 지면 조회를 예산 안에서 분산할 필요가 있다.
2. `surface_ecology.gd`의 주변 후보 생성·접지 조회·이동 자세 계산을 분리해 캐시하고, 멀리 있는 개체는 더 낮은 주기로 갱신한다. 리깅 품질·종 수·호스트의 실제 개체 판정은 유지해야 한다.
3. `crew_surface_scene.gd`의 관심 구역 이동·원경 재구성·지면 조회를 더 잘게 계측한다. 현재 청크 설치의 짧은 시간만으로 지상 전체 지연이 해결됐다고 판단하지 않는다.
4. 그 뒤 동일 보행 경로의 p95 / 100ms 초과 횟수를 재측정한다. 평균 FPS만을 완료 기준으로 쓰지 않는다.

## 현재 높음 옵션과 울트라 확장 후보

현재 원정은 `data/client_graphics.json`과 `scripts/ui/client_settings.gd`를 사용한다. 구형 `scripts/actors/graphics.gd`의 옵션을 현재 실행 화면의 설정으로 혼동하지 않는다. 다음 수치는 초기 제안이며 밸런스/품질 확정값이 아니다.

| 항목 | 현재 높음 | 울트라 후보와 구현 조건 |
| --- | --- | --- |
| 방향광 그림자 | 4096, 거리 220m, 각도 0°, 분할 혼합 꺼짐 | 8192, PCSS 각도 0.3~0.5°, 분할 혼합. 현재 저장 설정의 최대 4096 제한과 UI를 함께 확장 |
| 지역광 그림자 | atlas 2048 | 4096. 광원별 그림자가 필요한 범위를 먼저 제한 |
| SSAO / SSIL | 켜짐, 실제 엔진 기본 품질 Medium·절반 해상도 | High·전체 해상도 선택. INK의 밝은 면을 과도하게 검게 만들지 않고 효과별 비용을 분리 |
| 반사 | SSR 켜짐, 64스텝 | 96스텝 후보. 물/금속 등 반사가 실제로 보이는 장면에서 별도 비교 |
| AA / 렌더 배율 | MSAA 4×. 배율은 이미 50~150% 지원 | 기본 4× 유지, 125% 선택. 8×는 GPU 지원 확인 후 노출; 일괄 강제하지 않음 |
| 생물 모델 전환 | near→far 25m, 일반 시야 설정과 별개 | 예: 45~50m까지 기존 near 모델 유지. 개체 수·AI 범위와 분리 |
| 지표 장식 | 가시 거리 94m, 24m 타일·반경 3 | 예: 140~150m. 타일 생성 범위와 함께 조정해야 하며 먼저 생성 지연을 줄임 |
| 지형 | 2m 셀, 12셀 청크 | 현재 충돌·굴착 격자를 즉시 1m로 바꾸지 않음. 시각 전용 표면 세분화/노멀 디테일을 별도 검토 |
| 안개 / 간접광 | 체적 안개·SDFGI 꺼짐 | 습지·분진·동굴의 국소 안개, 선내/고정 시설의 반사·간접광부터 검토 |
| 고해상도 출력 | UI 목록 최대 2560×1440 | 3840×2160 선택, VRAM 비용 안내, 작은 UI와 윤곽 굵기 확인을 포함한 별도 작업 |

MSAA는 주로 형상 가장자리를 개선하며, 초과 해상도 렌더링은 셰이더 등 더 넓은 종류의 계단 현상에도 영향을 준다. TAA/FSR2는 움직이는 검은 윤곽의 흐림·잔상을 직접 비교한 뒤 선택지로 검토한다. 현재 UI의 업스케일러는 Bilinear/FSR1이며 FSR2를 사용 중이라고 기록하지 않는다. [Godot 3D AA 문서](https://docs.godotengine.org/en/stable/tutorials/3d/3d_antialiasing.html).

태양 각도를 키우는 PCSS는 그림자를 부드럽게 하지만 비용이 추가된다. SSAO/SSIL 해상도와 품질은 켜기/끄기와 별개의 옵션이다. SSR은 화면 밖 물체를 완전하게 반사하지 못하므로 스텝 증가로 모든 반사 문제를 해결할 수 없다. [빛과 그림자](https://docs.godotengine.org/en/stable/tutorials/3d/lights_and_shadows.html), [환경과 후처리](https://docs.godotengine.org/en/stable/tutorials/3d/environment_and_post_processing.html).

SDFGI를 절차 생성 세계에서 쓸 수는 있지만 굴착·신규 건설에 따른 차폐물 갱신과 비용을 설계해야 한다. 현재 게임에 전역 스위치 하나로 추가하는 우선순위는 낮다. [Godot SDFGI 문서](https://docs.godotengine.org/en/stable/tutorials/3d/global_illumination/using_sdfgi.html).

기존 모델 다수는 단색 INK 재질이다. 행성/지형에는 텍스처와 이방성 샘플러가 있으므로 실제 텍스처 경로는 개선 대상으로 삼되, 모든 모델에 4K/8K 옵션만 붙여 새 디테일이 생긴다고 가정하지 않는다. 곡면·모서리·기계 부품의 형태를 더 정교하게 하려면 Blender 자산 작업이 필요하다. 검은 외곽선·3단 명암을 유지하는 [INK v1](06-rendering-quality-standard.md)을 따르며 과도한 광택이나 실사 재질로 방향을 바꾸지 않는다.

## 제안하는 후속 커밋 순서

| 순서 | 독립 작업 | 최소 확인 |
| --- | --- | --- |
| P01 | 광맥·시설 표시의 전체 재적용 제거, 생성 분산 | 같은 지상 보행의 지연·누락·채집 대상 확인 |
| P02 | 생태/지면 조회 캐시, 원경·관심 구역 갱신 분산 | 생물 접지·보행·경계 이동 확인 |
| U01 | 울트라 프리셋과 개별 품질 항목, 설정 상한·저장 호환 | 재실행·기존 설정·지원하지 않는 AA fallback |
| U02 | 그림자·SSAO/SSIL 품질을 각기 연결 | 낮/밤·선내의 윤곽과 밝은 면, 항목별 비용 |
| U03 | 장식과 near LOD 거리 확대 | 생성 지연·메모리·팝인, 호스트 규칙 불변 |
| U04 | 4K 출력·선택적 125% 배율·업스케일러 검토 | 목표 Windows GPU에서 1440p/4K와 이동 중 잔상 |

이번에 구현 완료한 후속 단계는 없다. 목표 Windows PC, 6인 협동, 대규모 로봇 단지, 장시간 열 안정성, 4K, 동굴/수면의 모든 효과 조합은 미측정이다. 시설 측정과 CPU 계측 종료 시 `ObjectDB` 한 개 누수 경고가 남아 있으므로 종료 경고 0으로 기록하지 않는다. 일반 게임 규칙 전체 묶음은 실행하지 않았다.
