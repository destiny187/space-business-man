## O01 — 먼 거리의 내부 선

깊이 55m 이후 내부 명암선의 기여도가 0일 때 여덟 방향 법선·깊이와 중앙 법선의 읽기를 생략한다. 가까운 내부 선, 외곽선, 깊이/폭/색 기준과 투명 합성 순서는 유지한다. 설정의 실제 `crease_fade.y`를 읽으므로 다른 거리 기준도 따른다.

Godot 4.7.2 Metal Forward+ / Apple M2 / 960×640에서 실제 채광 로봇 모델 네 개를 원근/정사영과 거리 12/54/56/85m로 렌더했다. 변경 전 셰이더와 8개 조건의 2픽셀 간격 RGB 표본 차이는 모두 0이었다. 대표 근거리와 원거리 이미지를 직접 확인했다. 이는 이미지 동등성 확인이며 전체 게임 FPS 개선율 측정이 아니다.

검수 자료: `output/optimization-20260911/contours.json`, `contours.log`, `contour-*.png`. 게임 자산 원본·형상·음원은 변경하지 않았다. 이후 단계는 필요한 실행·화면·소리 확인만 수행하고 별도 버그가 있을 때 관련 검사를 좁혀 실행한다.

추가로 기존 경사면·투명 배치 고스트·실제 풀링 효과의 GPU 확인 3개를 실행해 실패 0을 확인했다(composition.log).


## O02 — 지형 청크 해제 분산

관심 구역 변경 시 바깥 청크를 즉시 전부 해제하지 않고 대기열에 둔다. 프레임당 최대 두 건의 분리/해제를 기존 3ms 설치 예산 안에서 시작하며, 다시 관심 구역에 들어온 청크는 보존한다. 굴착으로 교체된 청크는 시각·충돌·가림막을 함께 분리한 뒤 자원 해제를 다음 프레임들로 넘긴다. 충돌 준비 후 예산을 재확인하고, 굴착 묶음의 원자적 교체는 유지한다.

새 검사용 T1 원정에서 실제 Forward+ 지상 진입, 35.2m 이동, 관심 구역 변경과 해제 대기열 소진, 굴착 묶음 교체, 현재 채집기와 음원/효과 연결, 저장까지 9개 확인에서 실패 0이었다. 이동 전후와 굴착 화면을 직접 확인했다. 이 검사는 음원의 청취 검사가 아니며 일반 행동 규칙은 변경하지 않았다.

검수 자료: `output/optimization-20260911/field-retire.log`, `field/terrain.json`, `field/walk.png`, `field/excavation.png`. 이전 검사용 저장은 최신 생태 원형과 맞지 않아 사용하지 않고 새 저장을 만들었다. 사용자 저장은 건드리지 않았다.

한계: 엔진의 단일 자원 생성/해제 호출과 굴착 묶음 교체를 중간에 끊지는 않는다. 이번 실행의 지형 메인 처리 최대는 39.499ms, 개별 교체 최대는 2.629ms였다. 모든 프레임이 3ms 이하라는 의미가 아니며 지형 순간 지연의 완전한 해결로 기록하지 않는다.
