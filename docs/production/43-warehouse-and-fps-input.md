# 유한 창고·운송 화물·FPS 시점 — 2026-09-07

## 사용자 확정과 구현

행성 착륙 뒤 기본 창고 한 개를 유지하고, 개인 8칸과 별도로 기본 창고는 10칸을 사용한다. 자원/제품은 100개, 장비는 1개가 한 칸이다. 기존 B 건설의 창고를 추가하면 현장 공동 용량이 10칸씩 증가한다. 개별 건물마다 독립 원장을 두는 방식은 아니며 같은 행성의 창고끼리는 재고를 공유한다.

후속 사용자 요청에 따라 우주선에도 공동 10칸 창고를 둔다. **행성 창고는 해당 행성에 남고, 다음 행성에는 각자 배낭과 우주선 창고의 물건만 운송한다.** 참가자 수에 따라 우주선 창고가 늘어나지 않는다. 기존 개인 8칸은 유지한다. 배낭을 모두 비워야 출항하던 조건은 제거했으며 승무원의 귀환·준비·조종사 승인 조건은 유지한다.

F 현장 창고는 배낭과 창고를 나란히 연다. I의 공동 창고 탭에서 행성/우주선 창고를 선택하며, 착륙선 F 작업창에도 우주선 창고 진입을 제공한다. 실제 거래에는 대상 창고의 거리 조건이 적용된다. 드래그한 묶음만 옮기고 호스트 승인 후 수량을 갱신한다. 장비를 보관하면 장착 슬롯을 비우고 ID·등급·소유자를 보존한다. 다른 승무원의 장비는 꺼낼 수 없다. 자원과 가공품은 공동 재고다.

만재 시 수동 입고·보급·철거 환급을 거절하고 생산품은 출고 대기, 로봇은 남은 화물을 보유한 채 하역 대기한다. 추가 창고 철거는 줄어드는 용량과 환급 공간도 검사한다. 옛 초과 재고는 삭제하지 않고 표시하며 추가 입고를 막는다. 저장된 기존 암석 `crew.rock`을 단일 원본으로 유지하고 다른 선박 자원은 `crew.cargo`, 장비는 `crew.cargo_equipment`에 저장한다. 현장 장비는 `stored_equipment`에 보존하고 계약 인계 전 회수해야 한다. 사업 등록/다른 활성 계약과 별개로 탐사 현장의 기본 보관은 가능하다.

시점은 화면 배율에 영향받는 `relative` 대신 `screen_relative`를 사용한다. 마우스 입력의 프레임 누적을 끄고 이벤트에서 카메라 회전을 즉시 적용한다. 가속/평활화 없이 기존 감도·Y축 반전 설정을 유지하며 수직 시야를 ±89도로 넓혔다. 메뉴 중 시점 차단은 유지한다.

## 제작·확인

- 새 모델/음원 제작 없이 기존 Blender `art/blender/storage.blend` / 게임 `storage.glb`, 장비·광물 모델과 INK 렌더를 재사용했다.
- 실제 Metal Forward+ 창에서 착륙 창고 모델, 1280×800 및 960×640의 양쪽 격자, 마우스 누름/이동/해제로 발생한 드래그 입고, 원래 장비 ID 회수, 10칸 만재 거절/인수, 출항과 장소별 재고 보존·저장 읽기를 확인했다.
- 작은 화면에서 잘리는 문제를 재현하여 5×2 창고·작은 타일·보조 영역 숨김으로 수정했다. 관련 실행의 `WAREHOUSE_FAILURES 0`을 확인했다.
- 마지막 우주선 성공/실패 피드백은 기존 ElevenLabs `sfx_pickup_resource`, `sfx_build_invalid`를 승인 결과에 연결한다. 마지막 선내 확인도 `WAREHOUSE_CABIN_FAILURES 0`으로 승인/거절 음원 재생 연결을 확인했다. 검사 스크립트: `tests/check_warehouse_transfer.gd` (사용자 저장과 분리한 `--crew-folder` 필수).
- 전체 회귀·실제 다중 클라이언트·장시간 자동화는 실행하지 않았다. 로봇 만재 대기/완성품 출고 대기는 코드 연결 범위이며 이번 실제 창 검사에서 자동화 전 과정을 재실행하지 않았다. FPS 입력 수치와 즉시 회전은 확인했지만 하드웨어별 마우스 체감·고주사율 지연의 계측은 하지 않았다.

## 남은 범위

드래그는 선택 스택 입출고다. 슬롯 내부의 자유 재배열·수동 묶음 분할은 없다. 기존 초과 저장은 보존하므로 이미 넘친 저장의 총량이 자동 축소되지 않는다. 우주선 창고 확장·질량별 운송료·개인 물품의 다른 호스트 세계 반출은 이번 범위가 아니다. 생체 표본·로봇 격납고·선박 모듈은 기존 전용 체계를 유지한다.
