# SP09 — 유실 화물 회수와 항만 인계

2026-09-10 구현. [기업·우주 설계](../game/23-corporations-and-space-presence.md), [커밋 계획 SP09](../planning/16-space-corporations-commits.md)를 따른다. 실제 CARRIER 포드를 식별하고 선박 외부 거치대에 싣고 지정 항만까지 운반해 한 번 정산한다. SP08의 기록 조사를 실제 화물 이동으로 확장했다.

## 배치와 화물의 연속성

새 manifest의 선택 항목 `corporate_space.salvage.version = 1`을 사용한다. 태양계에는 화성 항만으로 돌아갈 포드 하나, 다른 항성계에는 운항 중인 SP07 항로 중 독립 시드 판정으로 일부에만 하나를 생성한다. 현재 지역 판정값 28%는 밸런스 초깃값이다. 미진출·철수 항로에는 배치하지 않는다. 기존 SP08 이하 은하에 설정을 소급 추가하지 않으며 기업 거점·지질·시장 재고를 재추첨하지 않는다.

ID는 `freight-v1:<system>`이다. 출처는 해당 항로의 첫 CARRIER이고, 인계처는 태양계 화성 항만 또는 지역 Space Y 중계항이다. 첫 운항 구간에서 출처 선박의 포드 슬롯 하나가 비어 보이고, 이후 정상 왕복은 다시 적재한다. 같은 사건은 운항 주기마다 재생성되지 않는다. 포드는 항만 접근로 부근에서 항만과 함께 공전하며 천천히 자세가 변한다. 매장 부품·압력 용기는 봉인하고 바깥 체결 부위만 손상된 모델이다.

## 실제 조작과 적재

수치·시간·대금은 `data/corporate_space.json`에 둔 초깃값이며 확정 밸런스가 아니다.

| 단계 | 조건과 실제 변화 |
| --- | --- |
| SOS → 송장 식별 | 2.6km 안에서 E 1.5초 유지. 출처·화물·인계 항만을 공개하고 지도와 J 현장 사건에 기록 |
| 회수 | 220m 안에서 E 5초 유지. 윈치 선을 연결하고 포드를 선체 아래 거치대로 이동한 뒤 가동 집게로 고정 |
| 직접 운반 | 공동 원정선 또는 FINCH의 외부 거치대 1개를 점유. 실제 부착 모델과 HUD·선박 관리 카드 표시 |
| 항만 인계 | 지정 항만의 별도 인계 설비 400m 안에서 E 3초 유지. 선박 집게를 열고 포드를 항만 거치대에 옮겨 고정 |
| 정산 | 인계 완료와 공동 자금 +350 C를 같은 저장에 확정. 선박 거치대 해제, 항만에 실제 포드 잔류, 지도/J 수령 기록 보존 |

회수·인계는 현재 선박의 조종사만 운용한다. 120m/s 이하이고 추진 입력을 놓은 상태에서 시작한다. 공전하는 대상에서 이탈하지 않도록 가까이서 장치를 운용하면 선박이 같은 공전 기준을 따라 상대 위치를 유지한다. 추진 입력을 넣으면 즉시 풀리며, 항로 변경 시에도 해제된다. 이 동작은 포드 회수나 인계의 성공 판정과 별개다.

시선·거리·속도·입력 만료·키 해제·메뉴 열기는 진행을 취소한다. 미완료 회수는 포드를 원래 대기 위치로, 미완료 인계는 선박 거치대로 되돌리는 시각적 복귀를 사용한다. 물리 로프 시뮬레이션은 아니다. 천체/거점 뒤를 투과해 조사하지 않는다. 수동 항해에는 포드·인계 설비의 안전 여유를 적용하고, 성간 출항 경로는 공전 이동 여유도 고려한다.

외부 거치대는 일반 원료 인벤토리와 별도다. 포드를 인계하기 전에는 착륙할 수 없다. 기존 이탈 FINCH 회수는 화물을 같은 선박 원장에 보존하며, 공용 FINCH의 다음 운항자로 키가 바뀌어도 적재 포드가 따라간다. 과거 인계 기록의 운항자 표기는 보존한다. 회수된 FINCH의 지상 주기 상태에 별도 외부 화물 모델을 추가하지 않았으며, 재출동하면 다시 표시한다.

## 호스트 저장과 표시

호스트는 현재 선박의 실제 항성계·위치·조종사·입력과 거치대 점유를 확인한다. 클라이언트의 완료/보상 요청 명령은 없다. `crew.freight_records`의 단계·적재 선박·시각이 사건 상태이자 외부 화물 원장이다. 단계 2에서만 거치대를 점유하며 같은 선박의 중복 점유를 거부한다.

단계 변경을 복제한 세계에 적용하고 저장 성공 후 공개한다. 인계 원장과 대금은 같은 세계에 기록한다. 아직 사업 원장이 없는 첫 원정도 인계 때 기본 원장을 생성한다. 저장 실패 시 기존 화물과 자금을 유지하고 공동 세계를 정지한다. 같은 송장을 계속 조사하거나 다시 접속해도 보상을 다시 지급하지 않는다.

이동 스냅샷은 최근 256개·현재 항성계·운반 중 포드를 보존한다. 실제 선박 위치와 진행 중 인계도 최대 공동선+FINCH 관심 범위로 전달한다. J의 전체 기록은 호스트 원장을 조회하며, 개인 지도는 받은 단계를 누적한다. 원거리의 오래된 개인 지도 표식은 재방문으로 보충한다.

## 제작과 확인

- Blender 원본·GLB 세 종: `lost_freight_pod`, `freight_cradle`, `freight_receiver`. 공통 제작 도구·산업 재질·곡면·실제 집게 피벗·Space Y 표식을 사용했다. 재생성은 `tools/build_freight_salvage.py`, 비용·해시·피벗은 `art/blender/ships/freight_salvage.json`에 기록했다.
- Cycles와 Godot 4.7.2 Forward+ / Metal INK 렌더에서 세 자산을 확인했다. 화물 카드도 같은 GLB의 투명 INK 렌더다. 실제 원정에서 윈치 이동·선체 부착·항만 잔류와 960×640 도감·지도 표시를 확인했다.
- `check_freight_salvage.gd`: 29항목, 실패 0. 신규/기존 저장 분기·고정 ID·출처 슬롯·거리/속도/조종사/시선/입력 만료·단계 저장·이동 항만 상대 정지·추진 해제·저장 실패·단발 지급·다시 읽기·FINCH 독립 위치·거치대 중복 거부·표시 원장을 확인했다.
- `check_freight_salvage_play.gd`: 20항목, 실패 0. 현재 원정의 실제 E 입력으로 세 단계를 완료하고 메뉴 입력/소리 차단·움직이는 포드/케이블·저장 후 잠금음·실제 적재/인계·자금 스냅샷·J/지도와 작은 화면을 확인했다. 검수용 접근 위치와 카메라를 사용하며, 긴 운송 구간 전체를 수동 비행한 검사는 아니다. 공전은 호스트 물리 틱에서 진행한다.
- `check_freight_borrowing.gd`: 공용 FINCH 키 변경 시 화물 이전·기존 수령자 보존·원장 유효성을 좁게 확인했다.
- 기존 ElevenLabs 구조 신호·궤도 조사·윈치·화물 체결·완료음을 재사용했다. 실제 재생과 메뉴 중단을 확인했고 새 생성/주관적 청감 평가는 수행하지 않았다. 출처와 용도는 `audio/manifests/freight-salvage-reuse.json`에 둔다.

전체 지상 기본 루프·다중 클라이언트 실접속·모든 시드·장시간 성능 검사는 수행하지 않았다. SP10 mine 정비, SP11 CooperTech 지상 단서, 우주 전투·플레이어 자동 운송·NPC 시장 재입고는 이번 범위에 포함하지 않는다.
