# SP08 — 기업 활동 흔적과 공동 조사

2026-09-10 구현. [기업·우주 설계](../game/23-corporations-and-space-presence.md)와 [SP08 작업 범위](../planning/16-space-corporations-commits.md)를 따른다. 회사별 실물과 주변 거점의 관계를 보여주고, 가까이 조사한 결과를 공동 저장·지도·J 도감으로 연결했다.

## 배치와 세 회사의 실물

새 manifest의 선택 항목 `corporate_space.traces.version = 1`을 사용한다. SP07 진출권 중 Lotus·mine·CooperTech의 실제 거점 옆에 해당 흔적 하나를 배치한다. 항성계당 최대 하나이며 기존 거점·지질·화성·항로의 배치 난수는 바꾸지 않는다. 최초 탐사권·미진출권·Space Y 관리권·철수 거점에 이 세 실물을 억지로 채우지 않는다.

| 회사 | 실물·가동부 | 읽을 수 있는 활동 |
| --- | --- | --- |
| Lotus | 세 곡선 반사대가 감싼 비콘·회전 신호 링 | 개척 항로와 보급 접근 유도 |
| mine | 광물통 두 개·교체 드릴·개방 정비대·대기 중인 서비스 암 | 채집 장비 정비와 산업 거점으로 이어지는 광물 집하 |
| CooperTech | 경사 장갑·이중 봉인 잠금쇠·회전 감시 헤드 | 전투로봇 시험 장비의 감시·봉인 운송 |

ID는 `trace:corp_<system>_0`이고 위치는 저장한 거점 상대 오프셋과 공전 시각으로 재현한다. 현재 항성계에만 모델을 생성한다. 수동 항해와 성간 출항의 안전 여유에 실물을 포함한다. 작동부는 실제 피벗 회전이며, 광물 생산·수리·봉인 해제의 성공 연출로 사용하지 않는다.

## 조사와 공개 단계

수치는 저장 데이터에 둔 초기 구현값이다.

1. **미확인:** 방문한 항성계 지도에는 빈 신호 원, 우주에서는 12km 안쪽의 보이는 실물에 신호 표식을 표시한다. 도감에는 아직 등록하지 않는다.
2. **회사 식별:** 2.6km 안에서 조준하고 E를 1.5초 유지한다. 회사·실물 이름·관련 거점이 드러나며 지도와 J 기업 항목에 `1 / 2`로 기록된다. 기존 SP07 행성 주시만으로 흔적 조사 단계를 얻지는 않는다.
3. **활동 기록:** 650m 안에서 E를 3초 유지한다. 외부 명판·항로/정비/봉인 기록을 읽어 `2 / 2`로 저장한다. 지도에는 체크 표시, J에는 실제 GLB 미리보기와 확보한 활동 설명을 표시한다.

두 단계 모두 90m/s 이하에서 조사한다. 시선 이탈·거리 초과·과속·입력 만료/해제는 진행을 끊는다. 항성·행성·위성·거점 뒤를 투과해 조사하지 않는다. 메뉴·설정·마우스 해제·성간 이동 중 입력을 차단한다. 조사 반경 안내·단계 점·진행 원·저장 후 완료음을 사용한다.

호스트는 실제 공동선 또는 해당 FINCH의 항성계·위치를 사용한다. 클라이언트가 조사 완료 ID나 위치를 제출하는 명령은 없다. 단계 변경을 먼저 저장하고 성공 시 세계/스냅샷을 교체한다. 저장 실패는 세계 정지와 기존 오류 경로로 전달하며 완료 단계를 공개하지 않는다. 재조사는 보상이나 중복 저장을 발생시키지 않는다.

공동 원장은 `crew.corporate_traces`에 ID별 단계만 보관한다. 이동 스냅샷에는 최근 256개와 현재 항성계 기록을 보내며, J 검색/페이지는 저장된 전체 원장을 조회한다. 개인 항해 기록은 받은 단계를 누적 보관해 지도에 사용한다. 새 참가자의 먼 과거 지도 표식은 해당 항성계 재방문으로 보충되며, 전체 공동 이력은 J에서 조회할 수 있다.

## 제작과 확인

- Blender 5.2.1: 세 원본 `.blend`, GLB, Cycles 렌더. `tools/build_corporate_traces.py`가 공통 산업 재질·곡면·제조 모서리·표식·정적 표면 병합을 사용한다. 출력 비용·피벗·SHA-256은 `art/blender/ships/corporate_traces.json`에 기록했다.
- Godot 4.7.2 Forward+ / Metal: 세 INK 단독 렌더, 실제 원정의 세 실물/가동부, 미확인→식별→기록 지도, 진행 HUD, 960×640 J 카드/상세를 확인했다. 도감 카드는 같은 GLB의 투명 INK 렌더다. 앞면의 심볼·잠금장치가 보이도록 미리보기 시점을 보정했다.
- `check_corporate_traces.gd`: 24항목, 실패 0. 같은 시드 재생성, 기존 SP07 저장 제외, 입력 중단/만료, 거리·속도·시야, 단계별 저장, 재조사 무변경, J 공개, 저장 복원, FINCH 독립 위치, 저장 실패 시 미완료, 스냅샷 상한·오류 기록 거부를 확인했다.
- `check_corporate_traces_play.gd`: 실제 원정의 E 입력·공동 저장·지도 반영·조사음·메뉴 차단·가동부·J와 미리보기 재선택을 확인했다. 항성계·카메라·시각을 고정한 검수용 위치 이동을 사용한다. 은하에서 세 장소까지 전 구간을 수동 항해한 검사는 아니다.
- 도감 재선택 뒤 960px로 줄일 때 긴 설명의 임시 최소 너비가 창을 밀어내는 문제를 발견했다. 설명 Label의 줄바꿈을 트리에 넣기 전에 설정하도록 수정했다. `check_corporate_trace_journal.gd`의 저장된 원정 재열기·재선택/축소 2항목은 실패 0이며 최종 카드/상세를 다시 렌더해 확인했다.
- 소리: 기존 ElevenLabs `sfx_orbital_scan`, `sfx_orbital_complete`의 게임 재생을 확인했다. 출처/재사용 기록은 `audio/manifests/corporate-traces-reuse.json`. 새 음원 생성과 주관적 청감 평가는 수행하지 않았다.

전체 지상 기본 루프·다중 클라이언트 실접속·모든 시드·장시간 성능 검사는 수행하지 않았다. 이번 변경과 직접 관련된 최소 확인만 수행했다.

## 저장 경계와 후속

기존 SP07 이하 은하에는 흔적 규칙을 소급 추가하지 않는다. 기존 거점·운항·개인 식별과 지상 SP02 기업 기록은 보존한다. 이 범위는 조사 가능한 활동 흔적이며, SP09 유실 화물 회수/인계, SP10 실제 정비 부품 운반, SP11 동일 ID의 지상 로봇 사건 연결은 미구현이다. CooperTech 봉인은 열지 않으며 우주 전투·플레이어 자동 운송·시장 재입고를 추가하지 않는다.
