## P00-A — FINCH 단독 이륙 (19번)

별도 1인 원정의 실제 `shuttle_board` 요청으로 기존 오류를 재현했다. 호스트 승인 후 `begin_launch()`가 비동기 FINCH 선체 교체를 기다리는 `_prepare_descent()`에서 카메라 생성 없이 돌아왔고, 바로 `landing_camera.position`에 접근해 Nil 오류가 발생했다. 이륙 상태만 남아 시야와 입력이 복구되지 않았다. 호스트가 지상에 남지 않았기 때문이 아니다.

`launch_preparing`을 추가해 지상 카메라/출발 위치를 유지한 채 선체 교체를 기다린다. 준비 완료 후 카메라·추진·지면 효과를 만들고 상승한다. 호스트/게스트의 이동·예측과 지상 장면 해제도 같은 준비 상태를 인식한다. 출동자의 영역이 우주로 바뀌어도 이륙에 필요한 지점의 지형 관심을 유지하고 원경 기준을 출발 위치에 고정했다. 우주 화면 인계 뒤 임시 관심과 지상 장면을 해제한다.

같은 실제 요청에서 발견한 `expedition_feedback.gd`의 운송 요청 타임스탬프 누락도 수정했다. 거래 결과를 바꾸지 않고 해당 요청의 대기 만료 처리만 정상화한다.

### 확인과 범위

- 재현: 기존 코드의 카메라 Nil 오류 및 이륙 인계 실패. 최초 검사 자체의 타입 선언/잘못된 음수 호출 시각은 검수 코드에서 수정하고 실제 재현과 구분했다.
- 첫 수정 확인: 실제 Godot 4.7.2 Metal Forward+ 1인 원정에서 14항목 통과. 배치된 FINCH 위치에서 상승·우주 시점 인계, 공동선의 원래 행성 유지, 철 7개 화물/출동 저장 재읽기를 확인했다. 이 실행에서 발견한 요청 타임스탬프 오류를 추가 수정했다.
- 최종 확인: **14항목, 실패 0, 실행 중 스크립트/엔진 오류 0**. 종료 시 ObjectDB 1개 잔존 경고가 있어 별도 기록한다. [수정 전 로그](media/playtest-feedback/finch-before.log) · [최종 로그](media/playtest-feedback/finch-after.log) · [상승](media/playtest-feedback/finch-ascent.png) · [우주 인계](media/playtest-feedback/finch-orbit.png). 검수 스크립트는 `tests/check_finch_takeoff_play.gd`, 격리 경로는 `/tmp/playtest-finch-takeoff`다. 기존 Blender FINCH/공동선 모델과 ElevenLabs 이륙 음원을 재사용한다.
- 새 Blender 모델/음원은 만들지 않았다. 실제 사용자 저장 재현, 모든 선체/지형·6인 외부망·Windows 실기는 수행하지 않았다. 사용자 실행/에디터가 함께 떠 있었으므로 이번 실행 시간을 단독 성능 측정으로 쓰지 않는다.

### 행동 범위

한 번의 FINCH 탑승 요청이 기존 소형선/개인 원장만 바꾸는 경로를 유지한다. 준비 타이머/카메라는 로컬 표시이며 별도 저장/추가 네트워크 요청을 발생시키지 않는다. 지형 관심은 출발지와 이륙 준비 지점으로 한정하며, 원경은 캐시를 재사용한다. 해당 화물 보존과 공동선 위치를 실제 한 번의 출동에서 확인했다. 전체 체크포인트의 기존 비용 자체를 제거한 변경은 아니다.
