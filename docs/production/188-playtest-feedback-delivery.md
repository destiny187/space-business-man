## P00-A — FINCH 단독 이륙 (19번)

별도 1인 원정의 실제 `shuttle_board` 요청으로 기존 오류를 재현했다. 호스트 승인 후 `begin_launch()`가 비동기 FINCH 선체 교체를 기다리는 `_prepare_descent()`에서 카메라 생성 없이 돌아왔고, 바로 `landing_camera.position`에 접근해 Nil 오류가 발생했다. 이륙 상태만 남아 시야와 입력이 복구되지 않았다. 호스트가 지상에 남지 않았기 때문이 아니다.

`launch_preparing`을 추가해 지상 카메라/출발 위치를 유지한 채 선체 교체를 기다린다. 준비 완료 후 카메라·추진·지면 효과를 만들고 상승한다. 호스트/게스트의 이동·예측과 지상 장면 해제도 같은 준비 상태를 인식한다. 출동자의 영역이 우주로 바뀌어도 이륙에 필요한 지점의 지형 관심을 유지하고 원경 기준을 출발 위치에 고정했다. 우주 화면 인계 뒤 임시 관심과 지상 장면을 해제한다.

같은 실제 요청에서 발견한 `expedition_feedback.gd`의 운송 요청 타임스탬프 누락도 수정했다. 거래 결과를 바꾸지 않고 해당 요청의 대기 만료 처리만 정상화한다.

### 확인과 범위

- 재현: 기존 코드의 카메라 Nil 오류 및 이륙 인계 실패. 최초 검사 자체의 타입 선언/잘못된 음수 호출 시각은 검수 코드에서 수정하고 실제 재현과 구분했다.
- 첫 수정 확인: 실제 Godot 4.7.2 Metal Forward+ 1인 원정에서 14항목 통과. 배치된 FINCH 위치에서 상승·우주 시점 인계, 공동선의 원래 행성 유지, 철 7개 화물/출동 저장 재읽기를 확인했다. 이 실행에서 발견한 요청 타임스탬프 오류를 추가 수정했다.
- 최종 확인: **14항목, 실패 0, 실행 중 스크립트/엔진 오류 0**. 종료 시 ObjectDB 1개 잔존 경고가 있어 별도 기록한다. - 새 Blender 모델/음원은 만들지 않았다. 실제 사용자 저장 재현, 모든 선체/지형·6인 외부망·Windows 실기는 수행하지 않았다. 사용자 실행/에디터가 함께 떠 있었으므로 이번 실행 시간을 단독 성능 측정으로 쓰지 않는다.

### 행동 범위

한 번의 FINCH 탑승 요청이 기존 소형선/개인 원장만 바꾸는 경로를 유지한다. 준비 타이머/카메라는 로컬 표시이며 별도 저장/추가 네트워크 요청을 발생시키지 않는다. 지형 관심은 출발지와 이륙 준비 지점으로 한정하며, 원경은 캐시를 재사용한다. 해당 화물 보존과 공동선 위치를 실제 한 번의 출동에서 확인했다. 전체 체크포인트의 기존 비용 자체를 제거한 변경은 아니다.

## P01 — 연구 진입·건설 목록 (17번)

착륙선 `station_action`에 두 개의 `research` 분기가 있었으며 먼저 걸리는 분기가 J 탐사 기록을 열었다. 이를 실제 연구 장치의 공동 설비 탭으로 연결했다. 공동 설비 안에 다시 들어가야 했던 설비 연구를 최상위 탭으로 펼치고 생산 효율을 별도 탭으로 옮겼다. 기존 생태 작업의 탭 순서는 유지한다.

건설 목록은 제작소 연구·설비 설계도·기초 기술 해금으로 가시성을 판단한다. 해금됐지만 재료가 부족한 카드는 보유/필요 수량과 함께 유지한다. 카드 노드를 재생성하지 않고 해당 카드의 가시성과 비용만 갱신한다. 연구 권한·비용·호스트 저장은 그대로다.

실제 Forward+ 960×640에서 착륙선의 연구 카드 입력, 공동 설비 직접 노출, 600 Cr+철20/구리10 연구 구매, 기존 카드 ID 유지한 해금, 재료 부족 상태의 노출·저장 재읽기를 **16항목, 실패 0, 실행 오류 0**으로 확인했다. 첫 확인의 재료 전송 직후 버튼 상태 검사는 스냅샷 도착을 기다리지 않아 실패했으며, 실제 데이터 수신 후 버튼 활성화를 확인하도록 검수 코드를 바로잡았다.

## P02-A — T 공통 스캔·5초 항로 표시 (11번 입력·20번)

우주/지상 스캔 기본키를 T로 합쳤다. Q/E 롤·F 접근/회수는 유지하며 화물 최초 식별은 T, 이후 연결/인계는 F다. 행성·기업 시설도 T를 유지해야 처음 분석한다. 기존 키 설정과 충돌 검사를 재사용하고 튜토리얼·신호 안내를 갱신했다.

빈 우주를 같은 방향으로 5초 바라본 뒤 화면 안의 항로 후보를 표시한다. 준비 중 허용 각도 12도, 표시 후 선택 허용 55도는 데이터 설정이며 실제 대상·메뉴·전투·장면 전환 시 초기화한다. 항로 검색은 항성계/항속거리/항로 개정 키로 캐시하고 숨긴 표식은 입력에서 제외한다. 타이머는 로컬이며 저장이나 네트워크 요청을 만들지 않는다.

격리 Forward+ 원정의 행성 주시만으로 분석되지 않음, T 진행/해제/완료, 4.9초/5초·시선 변경·대상 진입·선택 여유를 **13항목 실패 0, 최종 실행 오류 0**으로 확인했다. 첫 실행의 입력 클래스 중복 접두사 오류를 수정하고 다시 확인했다. 실제 장면에서 입력과 타이머를 제어한 검사이며 모든 신호/게스트 실기 검증은 아니다. 표면 효과·결과 패널과 1번 안내 수명은 다음 묶음이다.

## P02-B — 대상 스캔·안내 정리 (1·7·9·10·11)

정거장/목표 천체·활동 신호·SOS 표식은 5km 안의 최초 안내 4초 후 조준 재조회로 전환한다. 원정/캐릭터/대상별 로컬 기록이며 신호 단계 변경은 새 안내다. 항성 위험 경고는 예외로 계속 표시한다. 일반 광물의 우측 단서 목록을 제거하고 레이더의 가까운 자원 표시는 유지했다.

광맥 호버는 이름·잔량/총량만 표시한다. R의 로봇 지시 우회와 우선 로봇 버튼을 없애고 실제 선택 로봇의 광물 카드→작업 시작을 사용한다. 연구·작업 요청의 호스트 권한은 그대로다.

지상 발견물/사건 모델에도 기존 광맥·생물의 표면 스캔 재질을 연결했다. 대상이 없는 경우 임의 구체로 대체하지 않는다. 우주 천체/시설/화물/활동 신호도 실제 메시를 재사용한다. 지상·우주 결과창은 공통 연결선·네모 프레임·계측 띠를 사용하며 지상 결과는 대상의 화면 위치를 따라간다. 임시 재질은 해당 대상에만 부착하고 취소 시 이전 재질로 복구하며 월드/지형을 재생성하지 않는다.

Forward+ 광맥 메시 표면 스캔·원형 대체 없음·원래 재질 복구·960 화면 결과 배치를 **7항목 실패 0, 실행 오류 0**으로 확인했다. 비동기 모델 로딩을 기다리도록 검수 코드를 보정했으며 카메라 이동이 계속 적용되던 캡처도 고정했다. 지상 스캔 효과와 패널 렌더는 격리 원정의 실제 모델에 제어된 스캔 상태를 주입한 확인이다. 모든 사건/6인 실기 확인은 아니다. 우주 T 검사에는 실제 행성 메시 부착 확인을 추가했다.

## P03 — 자동 접근 부스트·견인·항해 표시 (2·3·5)

행성/정거장 자동 접근은 기존 조향·회피를 유지하면서 Shift 부스트를 받아들인다. 일반 비행과 동일한 에너지 고갈/회복 규칙을 쓰고 목표 근처 제동 속도를 제한한다. 항성계 이동의 m/s는 은하 좌표 변화가 아닌 연출용 지역 속도였으므로 항로 진행률·남은 초로 교체했다. 같은 항성계 내 수동 이동은 가능하며, 수동 비행으로 다른 항성계에 진입하는 경로는 없다.

유실 화물은 T 식별 뒤 정지(5m/s 이하) 상태에서 F 2초 유지로 견인 연결한다. 거치대 안으로 넣는 연출을 선체 뒤 65m의 견인선·추종으로 바꿨다. 선회 시 로컬 보간이며 화물 위치를 매 프레임 저장/발행하지 않는다. 기존 화물 소유/한 개 한도·항만 인계·저장 실패/중복 지급 방지는 유지한다. 정비 카트리지 작업은 별도 기존 단계로 유지했다. 기존 저장의 운반 중 화물도 견인 표시를 사용한다.

관련 도메인 검사 **29항목 실패 0**, 접근 부스트/제동/표시 **5항목 실패 0**, 실제 Forward+ 견인·메뉴 취소·인계·음원·저장 **18항목 실패 0**. 기존 검사에 새 출항 연출이 개입한 문제와 첫 안내장이 다시 열리는 검사 준비 문제를 바로잡고 확인했다. 기존 Blender 포드/선박·ElevenLabs 윈치/고정 음원을 재사용했다. 실제 사용자 저장과 6인 실기는 미확인이다. 접근은 도메인 경로 확인이며 실제 모든 행성/정거장 자동 비행을 반복한 검사는 아니다.

## P00 조사 — SOS와 생산 거점 (4·16)

SOS라고 직접 표시되는 현재 경로는 유실 화물과 정지 작업장이다. 둘 다 단계별 호스트 저장 후 마지막 단계에서 공동 자금을 지급하며, 완료 뒤 F 추가 작업을 거절한다. 화물의 실제 인계에서 350 Cr 지급·저장·재지급 방지를 확인했다. 정비 경로는 동일한 마지막 단계 저장/지급 코드의 분기 확인이며 실제 전체 정비 재현과 구분한다. 전투 후 착륙 구조 현장은 별도의 구조 연계 사건이다.

사용자가 대상명/저장 위치를 특정하지 못했으므로 **당시 무반응 자체는 재현하지 못했다.** 화물 연결 후 다음 목표가 항만으로 바뀌거나 최종 단계에서 추가 상호작용을 끝내는 정상 경로와, 완료 안내를 놓치는 문제를 구분해야 한다. 조사 단계에서 SOS 전체를 지급 버그로 단정하거나 자동 보상을 추가하지 않는다. 앞선 진행 공유의 ‘완료 대상 제외’는 후보 원인이었으며 코드상 완료 화물도 조준 재조회가 가능하다는 점으로 정정한다.

생산 거점 이용권은 복원 계약을 정산한 뒤에도 **그 행성의 시설·창고·생산을 보유**하기 위한 권리다. 선박 안의 공장을 뜻하지 않는다. 세션이 켜진 동안 다른 행성/항해 중에도 생산하며 재료·전력·창고 제약과 직접 운송을 따른다. 착륙선 단말은 호스트의 이용권 관리 접점이다. 이용권 삭제나 자동 운송 추가는 이번 조사에 포함하지 않는다.

## 나머지 묶음

P00 조사 보고와 P02~P07은 아직 완료하지 않았다. SOS는 조사 결과를 먼저 보고하며 현재 문서를 전체 20항목 구현 완료로 해석하지 않는다.

## P04 — 지도 좌표 캐시·산지 표시 (6·15)

실제 행성 지형·자원 생성은 변경하지 않았다. 지역지도는 고정 월드 좌표/배율 타일을 작업자에서 만들고 최대 192개를 재사용한다. 확대·축소마다 화면 전체 지형을 다시 굽지 않으며 준비된 이전 배율도 유지한다. 중앙 가까운 타일부터 준비하고 새 타일은 원형으로 드러난다. 미준비 구역에는 ‘궤도 지형 데이터 수신 중 · 지역 지질도 복원’과 진행률을 표시한다.

시점 기준으로 가까운 여섯 군집을 매번 고르던 산지 타원·텍스트를 제거했다. 고정 지질 구역의 실제 지표 광맥 표본 위치에 자원 아이콘을 표시하고 좌표를 캐싱한다. 이는 모든 개별 광맥을 전수 그린 지도가 아니다. 실제 지형에 원형 언덕이 존재하는 경우 높이 지도에도 남는다. 지형 유지라는 사용자 정정을 따라 가짜 산맥을 그리지 않는다. 중복 환경·복원 레이어는 삭제하고 테라포밍 탭을 유지했다.

Forward+ 960×640에서 지도 생성·캐시 재방문·광물 좌표 안정성을 확인했다. 같은 좌표/배율 복귀에서 텍스처 인스턴스가 같으며 기존 월드 변경은 없다. 로컬 타일 이미지와 지도 아이콘만 갱신한다. [지도 화면](media/playtest-feedback/map-geology.png), 검사 `check_map_weather_play.gd`의 지도 관련 6항목 성공.

## P05 — 비구름과 실제 시야 거리 (8·13)

강우 전 20초 동안 구름층이 형성되고 종료 뒤 15초에 걸쳐 걷히도록 했다. 로컬 강수는 충분한 구름이 형성된 뒤 나타나며 구름층은 하늘·태양 원반/후광을 가리고 일광을 줄인다. 기존 강우 빈도·피해·지형·네트워크 날씨 시간은 변경하지 않았다. 구름 보간과 기존 비 모델/음원은 클라이언트 표현만 갱신한다.

Forward+ 격리 원정에서 비구름 선행·맑을 때 강수 대기·구름과 240개 강수 입자의 동시 렌더를 확인했다. [비구름 화면](media/playtest-feedback/rain-clouds.png). 지도와 합친 관련 검사 **12항목 실패 0**, 최종 실행 오류 없음. T1 검사 장면에 로컬 강우 상태를 주입한 렌더 확인이며 자연 발생 전체 주기를 기다린 검사는 아니다.

시야의 실제 지형 범위는 **1.2 / 2.4 / 4.8 / 7.2 / 10 km**이며 설정 명칭에도 표시했다. 최대 설정의 카메라 원거리 평면은 16 km, 원경 지형 타일은 1,600개였다. 고정 위치에서 360도 회전해도 `build_count`가 증가하지 않았다. 최대 시야 최초 작업자 생성은 약 16.5초, 관측된 메인 처리 최대 44.1ms였다. 사용자 게임/편집기와 함께 실행한 측정이므로 단독 FPS 벤치마크로 해석하지 않는다. 회전만의 재생성 버그는 이번 조건에서 재현하지 못했고, 첫 원경 준비 비용은 남아 있다.

이 행성의 안개 밀도는 약 0.000316이었다. 지형이 10 km까지 있어도 대기/능선 가림·원경 단순화 때문에 식별 거리는 더 짧다. 근거리 개체/세부 지형의 범위는 별도 스트리밍이며 시야거리와 동일한 10 km 전수 상세 표현은 아니다. 최대값을 기본으로 올리면 최초 비용만 늘 수 있어 임의 상향하지 않았다. 실제 사용자 지점/하드웨어에서의 회전 지연 재현은 미확인으로 남긴다.

## P06-B — 발견은 기록, 실제 회수는 별도 (14)

소금꽃·노래하는 돌·결정/관측형 자연 발견은 T 스캔 완료로 조사 기록까지 남기며, 재료를 받기 위한 F 단계를 요구하지 않는다. 자연 발견 완료의 즉시 광물 지급과 무작위 내장 모듈 지급을 제거했다. 실제 굴착·표본·수로 개방 같은 현장 행동은 유지하고, 별도 부품 회수·설계도 복구는 고유 결과를 유지한다. 인간 담당자에게 도감을 제출하는 보상은 후속이며 이번에는 만들지 않았다.

기존 도감과 이미 받은 소유품을 지우지 않는다. 이전 저장의 미완료 자연 발견도 재스캔하면 새 기록 규칙을 따른다. 새 조사 기록만 변경하며 지급을 제거한 행동에 불필요한 새 전체 갱신을 추가하지 않았다. 소금꽃 완료/추가 F 없음·광물/모듈 미지급·발견자 보존·재스캔·회수 경계 검사 **6항목 실패 0**. 화면 효과는 앞선 T 표면 스캔을 재사용하며 모든 자연 발견을 실제 이동해 전수 조사한 검사는 아니다.
