2026-09-14 사용자가 [20항목 계획](../planning/19-playtest-feedback-september14.md)의 순차 개발·개별 커밋을 승인했다. 계획 커밋은 `2c9e7eed7`이다. 기존 작업 트리의 `check_solo_travel_commit.gd` 수정과 기존 미추적 UID는 포함하지 않는다.

## P00-A — FINCH 단독 이륙 (19번)

별도 1인 원정의 실제 `shuttle_board` 요청으로 기존 오류를 재현했다. 호스트 승인 후 `begin_launch()`가 비동기 FINCH 선체 교체를 기다리는 `_prepare_descent()`에서 카메라 생성 없이 돌아왔고, 바로 `landing_camera.position`에 접근해 Nil 오류가 발생했다. 이륙 상태만 남아 시야와 입력이 복구되지 않았다. 호스트가 지상에 남지 않았기 때문이 아니다.

`launch_preparing`을 추가해 지상 카메라/출발 위치를 유지한 채 선체 교체를 기다린다. 준비 완료 후 카메라·추진·지면 효과를 만들고 상승한다. 호스트/게스트의 이동·예측과 지상 장면 해제도 같은 준비 상태를 인식한다. 출동자의 영역이 우주로 바뀌어도 이륙에 필요한 지점의 지형 관심을 유지하고 원경 기준을 출발 위치에 고정했다. 우주 화면 인계 뒤 임시 관심과 지상 장면을 해제한다.

같은 실제 요청에서 발견한 `expedition_feedback.gd`의 운송 요청 타임스탬프 누락도 수정했다. 거래 결과를 바꾸지 않고 해당 요청의 대기 만료 처리만 정상화한다.

### 확인과 범위

- 재현: 기존 코드의 카메라 Nil 오류 및 이륙 인계 실패. 최초 검사 자체의 타입 선언/잘못된 음수 호출 시각은 검수 코드에서 수정하고 실제 재현과 구분했다.
- 첫 수정 확인: 실제 Godot 4.7.2 Metal Forward+ 1인 원정에서 14항목 통과. 배치된 FINCH 위치에서 상승·우주 시점 인계, 공동선의 원래 행성 유지, 철 7개 화물/출동 저장 재읽기를 확인했다. 이 실행에서 발견한 요청 타임스탬프 오류를 추가 수정했다.
- 최종 확인: **14항목, 실패 0, 실행 중 스크립트/엔진 오류 0**. 종료 시 ObjectDB 1개 잔존 경고가 있어 별도 기록한다. [수정 전 로그](media/playtest-feedback/finch-before.log) · [최종 로그](media/playtest-feedback/finch-after.log) · [상승](media/playtest-feedback/finch-ascent.png) · [우주 인계](media/playtest-feedback/finch-orbit.png). 검수 스크립트는 `tests/check_finch_takeoff_play.gd`, 격리 경로는 `/tmp/playtest-finch-takeoff`다. 기존 Blender FINCH/공동선 모델과 ElevenLabs 이륙 음원을 재사용한다.
- 새 Blender 모델/음원은 만들지 않았다. 실제 사용자 저장 재현, 모든 선체/지형·6인 외부망·Windows 실기는 수행하지 않았다. 사용자 실행/에디터가 함께 떠 있었으므로 이번 실행 시간을 단독 성능 측정으로 쓰지 않는다.

### 행동 범위

한 번의 FINCH 탑승 요청이 기존 소형선/개인 원장만 바꾸는 경로를 유지한다. 준비 타이머/카메라는 로컬 표시이며 별도 저장/추가 네트워크 요청을 발생시키지 않는다. 지형 관심은 출발지와 이륙 준비 지점으로 한정하며, 원경은 캐시를 재사용한다. 해당 화물 보존과 공동선 위치를 실제 한 번의 출동에서 확인했다. 전체 체크포인트의 기존 비용 자체를 제거한 변경은 아니다.

## P01 — 연구 진입·건설 목록 (17번)

착륙선 `station_action`에 두 개의 `research` 분기가 있었으며 먼저 걸리는 분기가 J 탐사 기록을 열었다. 이를 실제 연구 장치의 공동 설비 탭으로 연결했다. 공동 설비 안에 다시 들어가야 했던 설비 연구를 최상위 탭으로 펼치고 생산 효율을 별도 탭으로 옮겼다. 기존 생태 작업의 탭 순서는 유지한다.

건설 목록은 제작소 연구·설비 설계도·기초 기술 해금으로 가시성을 판단한다. 해금됐지만 재료가 부족한 카드는 보유/필요 수량과 함께 유지한다. 카드 노드를 재생성하지 않고 해당 카드의 가시성과 비용만 갱신한다. 연구 권한·비용·호스트 저장은 그대로다.

실제 Forward+ 960×640에서 착륙선의 연구 카드 입력, 공동 설비 직접 노출, 600 Cr+철20/구리10 연구 구매, 기존 카드 ID 유지한 해금, 재료 부족 상태의 노출·저장 재읽기를 **16항목, 실패 0, 실행 오류 0**으로 확인했다. 첫 확인의 재료 전송 직후 버튼 상태 검사는 스냅샷 도착을 기다리지 않아 실패했으며, 실제 데이터 수신 후 버튼 활성화를 확인하도록 검수 코드를 바로잡았다.

[검사 로그](media/playtest-feedback/research-after.log) · [공동 설비](media/playtest-feedback/research-960.png) · [연구 후 건설](media/playtest-feedback/build-unlocked-960.png). 새 모델/음원은 제작하지 않았다. 현재 작은 화면과 첫 제작소 경로 확인이며 전체 연구/6인 실기 검수가 아니다. 18번 튜토리얼 전체는 후속 P07이다.

## P02-A — T 공통 스캔·5초 항로 표시 (11번 입력·20번)

우주/지상 스캔 기본키를 T로 합쳤다. Q/E 롤·F 접근/회수는 유지하며 화물 최초 식별은 T, 이후 연결/인계는 F다. 행성·기업 시설도 T를 유지해야 처음 분석한다. 기존 키 설정과 충돌 검사를 재사용하고 튜토리얼·신호 안내를 갱신했다.

빈 우주를 같은 방향으로 5초 바라본 뒤 화면 안의 항로 후보를 표시한다. 준비 중 허용 각도 12도, 표시 후 선택 허용 55도는 데이터 설정이며 실제 대상·메뉴·전투·장면 전환 시 초기화한다. 항로 검색은 항성계/항속거리/항로 개정 키로 캐시하고 숨긴 표식은 입력에서 제외한다. 타이머는 로컬이며 저장이나 네트워크 요청을 만들지 않는다.

격리 Forward+ 원정의 행성 주시만으로 분석되지 않음, T 진행/해제/완료, 4.9초/5초·시선 변경·대상 진입·선택 여유를 **13항목 실패 0, 최종 실행 오류 0**으로 확인했다. 첫 실행의 입력 클래스 중복 접두사 오류를 수정하고 다시 확인했다. 실제 장면에서 입력과 타이머를 제어한 검사이며 모든 신호/게스트 실기 검증은 아니다. 표면 효과·결과 패널과 1번 안내 수명은 다음 묶음이다.
