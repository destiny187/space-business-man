# 로컬 초대·게임 내장 서버 — 2026-09-09

## 사용자 요청과 범위

IP 입력 대신 초대 코드로 참가하는 경로를 준비하면서 플랫폼 등록 전에도 로컬에서 협동 테스트한다. 처음 요청한 Docker와 후속 Python 직접 실행을 선택 경로로 남기고, 최종 요청에 따라 **방 만들기 시 해당 컴퓨터의 게임 프로세스가 서버를 자동 시작**하게 했다. 다른 컴퓨터에도 같은 Godot 코드를 포함할 수 있다. 실제 Windows 내보내기·기기 간 접속은 이번 확인에 포함하지 않는다.

Steam·스토브/EOS의 로그인과 플랫폼 로비·중계 어댑터는 별도 서비스 설정이 필요한 미구현 범위다. 현재 작업이 해당 플랫폼 연동 완료를 뜻하지 않는다. 구체적인 실행·친구 접속·전송 제약은 [로컬 서버 실행 안내](../../services/crew-relay/README.md)에 둔다.

후속 사용자 확정: 실제 사용·완료 확인은 **서로 다른 집의 인터넷 접속**을 기준으로 한다. 로컬 검사는 개발 확인에 한정한다. 같은 Wi-Fi 접속도 가능하지만 공인 주소로 돌아오는 경로는 공유기의 NAT loopback 지원이 필요하다. 외부 접속 절차를 실행 안내의 첫 번째 시나리오로 정리했다. 이 문서 변경을 위해 게임 테스트를 반복하지 않았다.

## 실제 연결

- 게임의 기본 협동 방식은 초대 코드다. 로컬 `ws://127.0.0.1:24680/relay`에서 방을 만들면 `FrontierCrewLocalRelay`가 게임 프로세스 안에서 서버를 연다. 이미 별도 서버가 같은 포트를 사용하면 그 서버에 접속한다. 외부 URL의 실패를 로컬 방으로 바꾸지는 않는다.
- `FrontierCrewRelayPeer`가 Godot `MultiplayerPeer`를 구현한다. 호스트 peer 1·채널 0~3·RPC를 유지하고 기존 `FrontierCrewAuthority`의 판정, 캐릭터 자격, 세계 저장과 준비→시작 흐름을 사용한다. 세이브 형식을 바꾸지 않았다.
- 코드 12자리 발급·복사, 잘못된 코드 안내, 연결 진행 표시, 중복 요청 방지, 대기실 나가기·재시도, P 승무원 메뉴의 코드 복사를 연결했다. IP 직접 ENet·단독 플레이는 계속 선택할 수 있다.
- 방마다 호스트 포함 6개 연결, 실제 소켓에서 지정한 송신자, 게스트→호스트 전용 전달, 방 사이 전송 차단을 서버에 적용했다. 기존 세계의 6명·재접속 예약·버전/콘텐츠 검사는 별도로 유지한다.
- 코드와 방은 호스트 연결 종료 때 폐기한다. 내장 서버는 이를 소유한 게임 프로세스 종료 때 끝난다. 독립 수명·컨테이너 운영이 필요할 때 같은 프로토콜의 Python/Docker 서버를 사용한다.
- 요청·패킷·방 수·연결 준비 시간·수신/송신 버퍼·전송량에 상한을 둔다. 공개 운영용 계정 인증·IP별 제한·TLS 서버는 구현하지 않았다. 로컬 기본값은 평문 WebSocket이다.

## 확인한 범위

- Docker 빌드·컨테이너 실행·health 및 두 Godot 프로세스의 입장·준비·시작·같은 캐릭터 재접속·호스트 종료를 확인했다. 작업에서 만든 컨테이너만 종료했다.
- macOS Python 3.13의 저장소 전용 venv를 첫 실행 스크립트로 준비하고 같은 두 프로세스 흐름을 확인했다. [네이티브 실행 기록](media/local-crew-relay/native-check.json).
- Python·Docker 서버를 종료한 뒤 **게임 프로세스의 내장 자동 서버**만으로 입장·호스트 판정·시작·재접속·호스트 종료를 확인했다. 임시 세계와 개인 프로필을 사용했다. [내장 실행 기록](media/local-crew-relay/embedded-check.json).
- Godot 4.7.2 Forward+ / Metal 실제 창에서 960×640 대기실·방 생성·코드 복사·나가기·잘못된 코드와 재시도를 확인했다. 첫 캡처는 창 크기와 내부 뷰포트가 달랐으므로 테스트의 `content_scale_size`를 맞춘 뒤 실제 이미지 크기를 확인했다.
- 검수 중 잘못된 코드의 WebSocket 종료 사유가 일반 연결 실패로 표시되는 문제를 발견해 종료 사유를 유지하도록 수정했다. 비동기 종료 중 소켓 해제가 겹칠 때 참조를 보존하고, 중계 끊김의 마지막 호스트 저장 실패는 종료 시 다시 저장할 수 있게 남긴다.

## 남은 제약

WebSocket/TCP는 비신뢰 RPC까지 순서 있는 신뢰 전송으로 전달한다. 인터넷 패킷 손실에서의 지연·채널 대기, 장시간·6인 성능, 서로 다른 기기·Windows·외부망은 미확인이다. 이번 변경은 지상 모델·도구·사운드를 바꾸지 않았으며 전체 지상 회귀를 실행하지 않았다.

출시 전에도 동일 빌드를 친구에게 전달해 테스트할 수 있다. 같은 LAN은 호스트 내부 주소와 방화벽 허용, 외부 인터넷은 서버 접근 주소·포트포워딩 등 네트워크 조건이 필요하다. **초대 코드만으로 공유기 제한을 해결하거나 로컬 서버의 IP를 숨기지는 않는다.** 게임 내장 서버와 자동 인터넷 중계는 구분한다.
