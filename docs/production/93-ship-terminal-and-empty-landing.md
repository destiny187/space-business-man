# 선박 보급 단말과 빈 첫 착륙지

2026-09-09 사용자 변경: L 단축키 보급을 선박 접촉 메뉴로 옮기고 처음 도착한 행성에 건물·창고가 이미 있는 상태를 제거한다.

- L 단축키와 상시 Lotus 버튼을 제거했다. 공동 원정선 또는 착륙한 FINCH에 접근해 F → 선박 관리 → Lotus 보급으로 신청한다. 기존 재료 카드·보급선·투하·상자 F 수령·저장은 유지한다. 메뉴를 연 뒤 멀어지면 닫고 호스트도 선박 범위 밖의 신청을 거절한다.
- 새 현장 원장에는 `base_deployed:false`를 기록한다. 착륙/개발 등록만으로 현장 창고 모델·충돌·무료 창고 칸이 생기지 않는다. 필요한 창고는 B로 직접 건설하고, 초기 물자는 선박 화물창에서 꺼낸다.
- 우주선 옆 연구대·증강 장치의 지상 복제 배치를 제거했다. 원래 선내 모델은 유지하고, 착륙 중에는 선박 관리의 연구/증강 카드로 해당 작업 화면을 연다. 호스트 작업 위치도 선박 단말 범위를 사용한다. FINCH에 연구·증강 장비를 추가하지 않는다.
- 기존 저장의 미사용 기본 창고(시설·로봇·제작·재고·보관 장비가 모두 없음)는 재개할 때 제거한다. 자원 고갈·탐사 기록은 보존한다. 직접 지은 시설, 기존 사용 중인 창고와 보관 물자를 삭제하지 않는다.
- 기본 창고가 없는 거점의 운반 로봇은 직접 건설한 사용 가능한 창고로 하역한다. 없으면 창고가 필요하다고 표시하며 화물을 보존한다.

## 확인

Lotus 관련 최소 규칙 검사와 실제 Forward+ 착륙/선박 메뉴/보급/투하/수령 흐름을 확인한다. 기존 3D·ElevenLabs 자산을 재사용하며 새로운 자산은 생성하지 않았다. 규칙 28개와 실제 Forward+ 보급 흐름 24개가 통과했다. 자동 창고/지상 장치가 없고 FINCH가 남는 것, 선박 메뉴 보급 호출, 투하/수령/저장, 창고 건설 전 0칸과 건설 후 수납 용량, 원거리 호출 거절을 확인했다. 단말 추가 확인 9개도 통과했다. L 호출 제거, 선박 메뉴의 연구/증강 진입과 호스트 접근 조건, 960×640 창에서 스크롤 가능한 선박 메뉴를 확인했다. 여러 실제 클라이언트 동시 접속이나 장시간 경제 검사는 수행하지 않는다.
