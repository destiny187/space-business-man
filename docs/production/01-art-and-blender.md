# 아트·Blender 제작

## 확정 요구사항

- 고품질 모델·굵은 검은 윤곽선·단계형 명암을 공식 스타일로 사용한다. 모든 후속 제작은 [고정 품질 기준 INK v1](06-rendering-quality-standard.md)을 따른다.
- 보더랜드를 표현 방향의 예시로 삼는다.
- Blender를 활용한다.
- **Blender가 작업 중 종료되면 재실행하여 작업을 이어간다.**

이 문서는 제작 방향과 절차다. 이후 Blender로 첫 모델 24종과 게임용 출력을 생성했다. [실제 생성 목록](../../art/blender/manifest.json)과 [구현·검증 현황](../planning/03-implementation-status.md)을 확인한다. 2026-09-06 로컬 실행판에 툰 재질·외곽선·4× MSAA, 지표면과 식생·물 변화, 채광 파편·로봇 작업/전투 빔·설비 수증기·동물 동작을 적용하고 실제 화면과 다중 로봇 성능을 확인했다.

## 시각 방향 — INK v1 기준 보조 설명

| 요소 | 방향 |
| --- | --- |
| 실루엣 | 멀리서도 제조사·역할·시설 종류를 알아볼 수 있는 굵은 형태 |
| 재질 | 넓은 색면, 통제된 거칠기, 손으로 그린 듯한 마모·가장자리 강조 |
| 음영 | 명암 단계를 정리하되 곡면·재질 차이를 읽을 수 있도록 유지 |
| 외곽선 | 거리·화면 크기에 맞게 두께 조절. 작은 오브젝트가 검게 뭉치지 않게 함 |
| 조명 | 주요 형태가 잘 읽히는 방향광과 절제된 환경광 |
| 효과 | 채광 파편, 전기, 먼지, 수증기, 테라포밍 변화가 기능을 전달 |
| UI | 산업용 원격 관제 장비의 명료함, 제조사별 작은 개성 |

고품질의 기준은 폴리곤 수만이 아니라 일관된 형태·색·조명·애니메이션과 조작 피드백이다. 보더랜드의 식별 가능한 캐릭터·로고·텍스처는 복제하지 않고 자체 세계관과 제조사 언어를 만든다.

### 색과 변화

- 초기 황무지: 낮은 채도의 회갈색·보랏빛, 위험 구역의 분명한 포인트 컬러.
- 장비: 도색된 금속, 반복 가능한 제조사 색상, 상태등.
- 테라포밍 중간: 먼지 감소, 하늘색·습윤도 변화, 국소적인 물과 식생.
- 안정화 이후: 밝아진 대기와 살아 있는 식생, 초기 황무지와 비교 가능한 풍경.
- 등급과 상태: 색상에 아이콘·형태·문자 표시를 함께 사용한다.

상태 변화는 [환경값](../game/04-terraforming-and-sales.md)에 연결한다. 산소 수치 하나가 올랐다고 즉시 모든 지형을 숲으로 바꾸지 않는다.

## 첫 아트 검증 세트 — 설계 제안

| 에셋 | 검증 목적 |
| --- | --- |
| 수동장비·채집 도구 | 플레이어의 원격 장비 정체성과 채집 피드백 |
| `mine` 보급형 채광로봇 | 로봇 실루엣·등급 표현·이동과 작업 애니메이션 |
| 철·구리·암석·얼음 노드 | 자원 구분과 채집 전후 상태 |
| 착륙 기지·보관함·충전 패드 | 초기 기지의 규모·접근 방향 |
| 발전기·제작기 | 전력·제작 가동 상태 |
| 대기·온도·물 설비 | 테라포밍 기능별 구분 |
| 유적 잔해 한 세트 | 탐험 랜드마크 |
| 지면·암석·기초 식생 | 황무지에서 정착 환경으로의 변화 |

전체 세트를 고품질로 만들기 전에 로봇 1종·자원 1종·설비 1종·지면으로 게임 내 화면을 검증한다. 단순 도형 프로토타입은 개발 과정에 쓰되 최종 아트 목표와 구분한다.

## 원본과 출력 구조 — 설계 제안

```text
art/
  blender/robots/          # 편집 가능한 .blend 원본
  blender/buildings/
  blender/environment/
  textures/source/         # 편집용 원본
  references/              # 참고 자료와 출처 메모
우주-비즈니스/assets/
  models/robots/           # 게임용 .glb
  models/buildings/
  models/environment/
  textures/               # 게임용 텍스처
  materials/              # Godot 재질·셰이더 자산
```

예시 이름은 `robot_mine_miner_basic_v001.blend`, 안정된 게임 참조 이름은 `robot_mine_miner_basic.glb`로 둔다. 고유 버전은 원본·이력에 남기고, 게임 코드가 매번 새 파일명에 종속되지 않게 한다.

## 제작·내보내기 — 설계 제안

1. 역할, 실제 게임 화면 크기, 충돌 범위, 필요한 애니메이션을 정한다.
2. 미터 단위로 블록아웃하고 플레이어·문·설비와 나란히 놓아 크기를 확인한다.
3. Blender 원본의 축·원점·스케일을 정리한다. 건물 원점은 배치 기준 바닥, 로봇 원점은 이동 기준으로 맞춘다.
4. 실루엣을 확정한 뒤 모델·UV·텍스처를 만든다. 발광·도색 마스크처럼 게임에서 바꿀 영역을 분리한다.
5. 로봇에 대기·이동·채광·운반·충전 상태를 구분할 애니메이션을 만든다. 등급마다 전체 모델을 복제하기보다 부품·도색·상태 표시로 차이를 준다.
6. `.blend`를 저장하고 게임용 `.glb`를 내보낸다. 복잡한 Blender 재질 노드가 그대로 재현된다고 가정하지 않고 필요한 텍스처를 베이크하거나 Godot 재질로 구성한다.
7. Godot 검증 장면에서 크기·방향·재질·그림자·애니메이션·충돌을 확인한다. 기본 모델 방향은 Godot 기준과 일치하도록 검증한다.
8. 실제 채집·로봇·건축 장면에서 효과와 UI까지 함께 확인하고 에셋 상태를 갱신한다.

수동 축 보정과 내보내기 축 변환을 중복 적용하지 않는다. 충돌은 가능한 한 단순한 별도 형태로 두고 복잡한 시각 메시를 무조건 물리 충돌에 쓰지 않는다.

## Blender 종료·충돌 복구 절차

1. 장시간 작업 전과 주요 단계 완료 시 `.blend`를 저장한다. 내보내기 성공 여부와 원본 저장 여부는 따로 확인한다.
2. **Blender가 사용 중 종료되면 먼저 Blender를 재실행한다.** 남은 작업이 있으면 종료 상태로 멈추지 않는다.
3. 최근 정상 저장본을 연다. 미저장 변경이 있었다면 Blender의 복구 기능으로 자동 저장본·이전 세션 복구 가능성을 확인한다.
4. 복구본은 정상 원본에 바로 덮어쓰지 않고 별도 이름으로 저장한 후 객체·재질·애니메이션을 비교한다.
5. 마지막 편집·내보내기가 실제 반영되었는지 확인하고, 누락된 단계부터 재개한다.
6. 같은 단계에서 반복 충돌하면 작업을 더 작은 단위로 나누고 원본을 보존한다. 재실행 불가, 복구 실패, 반복 충돌은 원인·복구 범위·남은 작업을 기록한다.

의도적으로 Blender를 종료한 뒤 추가 편집이 필요해진 경우에도 재실행한다. 최종 종료는 저장과 필요한 출력 확인 후에 한다.

## 게임 내 품질 확인 — 설계 제안

- 보통 플레이 거리에서 철·구리·얼음, 작업·고장·충전 상태를 구분할 수 있다.
- 주광·그늘·역광에서 형태가 읽히고 외곽선이 화면을 과도하게 덮지 않는다.
- 메시 틈, 역면, 흔들리는 그림자, UV 이음새, 애니메이션 발 미끄러짐을 확인한다.
- 여러 로봇·시설·식생을 함께 배치한 화면에서 성능을 측정한다.
- 폴리곤·텍스처·드로콜 예산은 목표 플랫폼과 대표 화면을 정한 후 확정한다. ‘고품질’만을 근거로 무제한으로 늘리지 않는다.
- 카툰 재질, 외곽선 방식, 광원·후처리는 작은 비교 장면에서 결정하고 [기술 설계](../technical/01-godot-architecture.md)에 반영한다.

## 1.1 동작과 카탈로그 보강

M-02 흡입기를 새로 구성하고, 수동장비·채광로봇·탐광로봇·경비로봇의 원본과 GLB를 갱신했다. `Anim_` 이름의 팬·피스톤·바퀴·포신·포탑은 병합하지 않는다. Blender에서 기구 부품을 분리하고 Godot에서 실제 입력·작업 상태에 맞춰 절차적으로 움직인다. 베이크된 캐릭터 모션 클립이나 인체 리깅을 추가했다고 기록하지 않는다.

1.1 당시 카탈로그는 Blender 별도 조명으로 17개 PNG를 만들었다. 현재 [카탈로그 렌더 도구](../../tools/render_ink_catalog.sh)는 게임과 같은 Godot 잉크 셰이더로 전체 31종을 촬영하고 도감 PNG를 갱신한다. 프레임은 메시 바운딩 박스를 카메라에 투영해 모델이 잘리지 않도록 계산한다. [1.1 적용·검증](../planning/05-interface-and-feedback.md)을 참조한다.

## 1.2 조명·재질·배경 보강

기존 장비 모델 24종에 추가로 Blender 암벽 3종을 만들었다. 기존 태양광 패널 1종은 원거리 잡무늬를 줄이도록 셀 받침·두께·간격을 수정하고 카탈로그 이미지를 갱신했다. 기존의 모든 표면을 동일하게 거칠게 처리하는 툰 재질을 재질별 하이라이트와 외곽선을 사용하는 혼합 표현으로 개선했다. 하늘 환경광·접지 음영·물결·물가 거품·지표 요철·화질 프리셋과 측정 범위는 [렌더링 품질과 성능](03-rendering-and-performance.md)을 기준으로 한다.

## 데모 이후 전체 아트 교체 — 확정 방향

2026-09-06 사용자는 기존 3D 모델 전체를 교체하고 배경도 고도화할 예정이라고 명시했다. 다음 품질 검토에서는 기존 모델을 유지한 전후 비교를 우선하지 않는다. 로봇·시설·지형·식생·물·하늘이 함께 읽히는 신규 대표 장면에서 전체 제작 목표를 검토한다. 기존 1.2 자료는 당시 구현의 이력이며 향후 아트 품질의 상한선이 아니다. [결정 기록](../planning/02-decisions-and-risks.md)을 참고한다.

## 탐험 확장과 생물 사례 제작 — 목표·미제작

행성의 지형·배치는 시드로 만들고, **생명체는 준비한 사례별 모델·재질·행동으로 렌더링**한다는 추가 사용자 방향을 따른다. 사례 선택·환경·변형 규칙은 [은하·티어·시드](../game/11-galaxy-tiers-and-seeds.md), 생물 효과는 [연구·생태](../game/09-discovery-research-and-ecology.md)에만 정의한다.

각 사례는 `.blend` 원본, 게임용 GLB·재질, 단순 충돌, 애니메이션/절차 동작, 거리별 표현, 환경 적응 단계, 생물실·도감 표시를 한 세트로 검수한다. 시드로 임의 관절·사지를 조합하지 않는다. 크기·색·표면 무늬는 리깅·충돌·실루엣이 깨지지 않는 검증 범위로 제한한다. 종의 골격이나 효과가 바뀌면 별도 사례로 제작한다.

| 제작 묶음 | 필요한 상태·대표 화면 | 검증 목적 |
| --- | --- | --- |
| 우주선·모듈 | 항해·도킹·손상·회수·생물실 | 역할과 장착 변화, 화물 크기의 일관성 |
| 지표·지하 | 절벽·층리·동굴 입구·굴착면·승강기 | 연결 경계·수직 길 찾기·시드 지형과 조합 |
| 생물 사례 | 휴면·활동·섭식·스트레스·번식/군집 성장 | 조건과 행동이 읽히고 재질·발광이 효과를 설명 |
| 연구·표본 | 스캔·용기·실험대·시험 서식지 | 살아 있는 개체와 데이터·비활성 시료 구분 |
| 문명 사례 | 환경에 맞는 거주·일·교역·갈등 상태 | 산업 단계와 문화 차이가 드러남 |
| 테라포밍 경관 | 같은 지점의 황무지·회복·안정·역효과 | 실제 환경 상태에 맞는 변화 |

가까운 생물은 모델·행동을, 먼 개체군은 단순 메시·군집 표현을 사용한다. 화면 개체 수를 줄여도 실제 생물량·종·연구 효과가 바뀌지 않는다. 수십 개의 복제된 동작이 동시에 재생되는 반복을 줄이되 중요한 경고 상태를 숨기지 않는다. 종의 소리도 사례·행동에 맞춰 연결한다.

제작 완료는 Blender 원본 저장·GLB 출력·매니페스트·Godot 실제 화면·상태 전환·성능 확인으로 판정한다. 초기 실증은 바위형 생물 한 사례와 지표↔지하↔생물실↔시험 이식 장면부터 제안한다. 이번 작업에서는 새 모델·애니메이션을 생성하지 않았다.

## 굵은 검은선 카툰 검토

2026-09-06 사용자가 제공한 참고 화면에 따라 굵은 실루엣·가는 내부 윤곽·단계형 명암을 가진 네 자산 예제를 제작했다. [굵은 검은선 스타일 연구](05-ink-style-study.md)에 모델·셰이더·실제 렌더와 실행 방법을 기록한다. 후속 요청에서 공식 스타일로 승인했다. [INK v1 기준](06-rendering-quality-standard.md)에 모든 필수 자산의 재렌더 범위와 후속 제작 완료 조건을 고정한다.

## 첫 생물 서브 작업 — 리소섬 시연

2026-09-06 사용자 요청으로 바위형 사례 `lithotherm`의 Blender 원본·근거리/원거리 GLB·네 가지 절차 동작·독립 Godot 관찰실을 제작했다. [제작물·실행·검증·남은 범위](07-lithotherm-specimen.md)를 따른다. 공통 렌더 목록의 상태는 `visual-prototype`이며 실제 행성 출현·생태·연구·운송·멀티플레이 연결 전이다. 기존 자산의 교체 또는 새 최종 품질 승인을 뜻하지 않는다.

## 생물 전체 렌더링 — 기본 형상 500개

2026-09-06 사용자가 생물 렌더링 전체와 공격 동물의 모션·효과를 맡기고 기본 모델 수를 최종 500개로 변경했다. [500개 형상·1만 외형 프로필의 제작 및 검수](08-bestiary-rendering.md)가 소관이다. 동물·식생·미생물 군락을 포함하며, 공유 체형·환경 형상·색상/크기 변형을 구분한다. 실제 출현·생태·피해 판정과 사용자 최종 형태 승인은 별개다.
