# SP10 — mine 작업장 정비와 재가동

2026-09-10 구현. [기업 우주 설계](../game/23-corporations-and-space-presence.md), [SP10 계획](../planning/16-space-corporations-commits.md)을 따른다.

새 세계의 실제 mine 산업 거점에 정지한 작업장을 배치한다. 고장 진단(E 3초, 650m) → 다른 행성 Space Y 중계항의 교체 카트리지 수령(E 5초, 220m) → 선박 외부 거치대로 직접 운반 → 작업장 설치(E 3초, 400m) → 정비·보정(E 7초, 350m)으로 연결한다. 설치 후에도 드릴은 멈춰 있으며 마지막 저장 성공 후 재가동하고 공동 자금 500 C를 한 번 지급한다. 수치는 신규 manifest의 `corporate_space.maintenance` 설정이며 밸런스 확정값이 아니다.

## 실제 표현과 저장

Blender로 카트리지·공급 거치대·소행성 고정 작업장 3종을 제작했다. 공통 INK 산업 재질, 드릴 슬라이드/회전축·클램프·정비 팔·광물 트레이·고장등 피벗을 사용한다. 원본과 GLB, 제작 해시는 `art/blender/ships/mine_maintenance.json`에 둔다. Blender Cycles와 Godot Forward+ INK 렌더, 현재 원정의 실제 배치를 확인했다.

`service-v1:<system>`은 기존 유실 화물과 동일한 외부 적재 원장을 사용한다. 각 선박의 거치대 한 칸을 공유하며 stage 2만 점유한다. stage 3은 설치·정비 대기, stage 4는 재가동 완료다. E 해제/메뉴/거리·주시 이탈은 진행을 취소하고, 저장 실패는 재가동·보상을 확정하지 않는다. 부품 수령 중에는 공급 항만을, 설치·정비 중에는 작업장을 따라 상대 정지한다. 추진 입력으로 해제한다.

J에 부품 모델·작업 단계·수령 행성/작업장 지도 버튼을 제공한다. 지도는 진단 후 별도 수령지를 표시한다. 기존 은하에는 설정을 소급 추가하지 않는다. 반복 부품 주문·플레이어 자동 운송·일반 재고 자원 소비·mine 기계 소유권·정비 후 경제 생산량은 이번 기능에 포함하지 않는다.

ElevenLabs 기존 제작음의 윈치·조사·정비 모터·클램프·완료음을 재사용했다. 매핑과 음량은 `audio/manifests/mine-maintenance-reuse.json`에 둔다. 실제 플레이에서 재생 상태와 메뉴 차단을 확인했으며 주관적 청음은 수행하지 않았다.

## 확인

- `check_mine_maintenance.gd`: 17개 확인. 시드/기존 저장, 공급지 공전 추적, 거치대 경쟁, 설치와 재가동 분리, 중단/저장 실패, 단발 지급과 재로드.
- `check_mine_maintenance_play.gd`: 현재 Forward+ 원정의 실제 E 입력 15개 확인. 진단·윈치/카트리지 이동·설치·정비 팔/음원·메뉴 취소·드릴 재가동·960px J 및 지도 저장.
- 공용 적재 로직 변경에 따른 기존 `check_freight_salvage.gd` 29개 확인. 모두 통과.
- 대표 캡처: `media/mine-maintenance/`. 장거리 비행 구간은 검사에서 접근 위치를 설정했다. 전체 지상 회귀·전체 시드/장시간 성능 검사는 수행하지 않았다. 실제 다중 클라이언트와 재접속은 SP11 통합 확인에서 수행한다.
