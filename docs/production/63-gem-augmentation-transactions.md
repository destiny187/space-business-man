# A02 — 보석 소비·신체 증강 거래

2026-09-08 [A01~A09 개발 계획](../planning/12-augmentation-and-research-commits.md)의 A02를 구현했다. **호스트 거래 기반 완료**이며, 실제 장치 배치와 플레이 화면은 A03~A04에서 연결한다. A02 당시 일반 게임에는 호스트 장치 제공자가 연결되지 않아 증강 요청을 거절했다. 이후 [A03](64-crew-stations.md)에서 실제 장치 제공자를 연결했으며 구매 UI는 A04에서 추가한다. 원거리 증강 버튼을 임시로 추가하지 않았다.

## 구현

- 계열별 `base_cost`를 데이터에 두고 목표 단계에 비례해 소비한다. 첫 값은 사파이어/루비/에메랄드 각각 **3·6·9·12·15개**, 최대 5단계다. 초기 밸런스이며 최종 확정 수량이 아니다.
- `augmentation_upgrade` 요청은 `station_id`, `field`, `expected_level`만 받는다. 증강 대상은 연결된 요청자이며 대상 캐릭터·가격·장치 좌표를 클라이언트가 지정할 수 없다.
- 호스트 장면의 `augmentation_station_provider(actor, station_id)`가 현재 실제 장치를 조회해 `{enabled, position: Vector3, area, body_id}`를 제공한다. `body_id`는 지상 서비스 장치에 필요하다. 제공자가 없거나 장치가 비활성/다른 공간/다른 행성이면 거절한다. 거리 3m는 데이터 값으로 검사한다. 실제 위치는 A03 모델 배치 때 정하며 가상의 고정 좌표를 선박 장치로 취급하지 않는다.
- 본인 배낭의 해당 보석만 차감한다. 공동 창고·선박 화물·다른 승무원 재고는 자동 소비하지 않는다. FINCH 출동 중에는 공동 원정선 장치를 사용할 수 없다.
- 호스트의 기존 복사본→원장 저장→공개 순서를 재사용한다. 증강 단계·보석 차감·요청 영수증은 함께 저장되며 실패하면 변경을 공개하지 않는다.
- 같은 요청의 재전송은 저장된 결과를 반환한다. 같은 순번의 내용 변경·지난 세계 리비전·현재와 다른 예상 단계는 거절한다. 새 순번으로 재클릭해도 이전 단계의 화면으로 다음 단계까지 소비하지 않는다.
- 성공 응답은 계열·이전/새 단계·소비 재료·배율·최대 체력을 제공한다. A04의 연출은 이 응답 뒤에 실행한다. 체력 상한이 증가해도 현재 체력은 그대로 둔다.

## 최소 실행 확인

`check_augmentation_transactions.gd`를 Godot 4.7.2 headless로 실행해 **32개, 실패 0**을 확인했다.

비용 증가, 호스트 장치 미연결/비활성·거리·공간, 요청 필드 위조, 저장 실패 원복과 같은 요청 재시도, 성공 응답 재전송, 예상 단계·리비전 충돌, 보석 부족·최고 단계, 생명/전투 증강, 게스트 본인 재고 소비, 공동/호스트 재고 보존, FINCH 문맥 거절, JSON 저장 재개와 원본 프로필 보존을 검사했다.

장치 위치와 보석은 테스트에서 준비한 격리 데이터다. 실제 장치 앞 조작·보석 채집부터의 완주·음향·원격 ENet는 이번 검사 범위가 아니다. 화면·모델·음원을 변경하지 않아 렌더/청음 확인을 반복하지 않았다. 사용자의 세계 저장과 별도 로딩 화면 작업은 변경하지 않았다.

[실행 로그](media/augmentation-a02/transactions.txt)

```sh
./tools/godot.sh --headless --script res://tests/check_augmentation_transactions.gd
```

## A03 연결 계약

기본선 증강 장치와 표본 연구대를 Blender로 제작·배치한다. 증강 장치 ID는 `ship:augmentation`을 사용한다. 장면은 매 요청 시 유효한 노드·활성 상태·현재 공간·실제 위치를 조회하는 제공자를 연결한다. 제거된 노드의 위치를 캐시해 접근을 허용하지 않는다. 선내와 착륙 중 서비스 장치는 하나의 개인 증강 원장을 사용한다. A04에서 실제 캐릭터·부위 선택·보석 슬롯과 완료/거절 연출을 연결한다.
