# 자연 진행·2단계·복원 정산 플레이 테스트 — 2026-09-07

후속 상태: 사용자 요청으로 아래의 확정 UI 차단과 부적합 배정을 수정하고 초반 철·얼음을 추가했다. [수정·재검증 기록](45-progression-repairs.md). 아래는 수정 전 테스트 기록이다.

## 판정

**현재 화면 조작만으로 2단계 성장 → 복원 완료 → 정산 → 다음 행성 사업을 자연스럽게 완료할 수 있다고 판정하지 않는다.** 강화·환경 처리·정산·이동의 내부 규칙은 연결되어 있으나, 계약 정산과 창고 보급/로봇 회수의 UI 진입 경로가 끊겨 있다. 이번 작업은 테스트와 기록이며 게임 코드는 변경하지 않았다.

사용자가 요청한 ‘2단계’는 현재 구현된 Mk.2 개인 장비·탐험복·로봇·시설과 원정선 첫 개량으로 해석했다. **T2 행성의 염류·토양 특수 목표까지 새로 검증한 것은 아니다.** 현재 판매 기능은 행성 전체 매각이 아니라 지역 복원 계약 정산이다.

## 방법과 환경

- Godot 4.7.2 / Metal Forward+, 실제 게임 창. 사용자 저장과 분리된 `/tmp/space-natural-play-20260907/` 사용.
- 메인 화면 → 새 은하 → 지구 안내 → 은하 지도 → 인근 Regulus 23952 → T1 Regulus 23952 b를 실제 클릭/키로 진행했다. 시드 `1593888608`, 행성 주소 인덱스 `191610`.
- 착륙 후 J 연구 화면에서 입문 로봇공학을 구매했다. 자금 6,000 → 5,700 Cr.
- 이후 이 저장의 복사본에서 실제 호스트 요청·재료 차감·배낭/창고 용량·거리/시야/배치 제한을 사용하는 검사를 실행했다. 자원·기술·시설·장비·환경을 직접 지급하거나 덮어쓰지 않았다. **플레이어 이동/조준은 검사 위치로 설정하고, 산업 대기는 틱으로 진행했으므로 수동 완주·실시간 소요시간·체감 밸런스 검증과 구분한다.**
- 획득한 Mk.2 저장과 복원 완료 저장을 실제 게임으로 다시 열어 장비/창고/지표 표현과 F 행동을 확인했다. 전체 음향 청취·다중 클라이언트·장시간 회귀 검사는 하지 않았다.

## 발견한 문제

### 1. 계약 정산 화면 진입 누락 — 진행 차단

`expedition_navigation.gd`의 착륙선 F는 `station_action("launch")`를 직접 실행한다. `business_panel.gd`에는 환경·계약 탭과 정산 확인창이 존재하지만, 이 탭은 `ship` 문맥에서만 노출되며 현재 게임 코드에 `open_station("ship")` 호출이 없다. B는 건설 문맥이다.

복원 완료 저장에서 실제 F를 눌러 즉시 이륙을 재현했다. 종료 저장에서 환경 목표를 모두 만족한 현장이 `active`, 보상 전 자금 500 Cr로 남았다. 출발 자체는 가능하지만 정산을 통한 후속 사업 진행은 막힌다.

### 2. 창고 개편 후 보급 구매·로봇 회수/재파견 진입 누락

`crew_expedition.gd:open_station()`은 `base`/`storage`에서 인벤토리 공동 창고를 열고 즉시 반환한다. 기존 사업 패널의 창고 보급과 로봇 회수·재파견 탭에 도달하지 않는다. 실제 공동 창고 화면에서도 배낭/창고 입출고만 확인했다. 로봇 본체 문맥은 작업 배정/정지/충전/개조만 제공하고 회수 UI는 숨긴다.

이번 금속질 T1 행성의 자원 구성에는 얼음이 없고, 보장되는 착륙 자원도 철·구리·암석뿐이다. 채집만으로는 생태 배양기의 얼음 30개에서 진행이 멈췄다. 다른 얼음 행성이나 정거장에서 운송하는 대안 전체를 검증하지 않았으므로 은하 전체의 영구 자원 교착으로 단정하지 않는다. 다만 현장 보급이라는 기존 대안과 그 안내가 현재 UI에서 사라졌다.

후반 검사에서는 **UI에서 접근 불가능한 `business_supply`와 로봇 회수/재파견 명령을 직접 호출**하여 나머지 규칙을 분리 확인했다. 보급·모듈 비용은 실제 시작 자금에서 차감했지만, 이 결과를 자연스러운 UI 완주로 계산하지 않는다.

### 3. 로봇의 부적합 광맥 배정 피드백

처음 선택한 지표 철 광맥의 배정 요청은 수락됐으나 180 산업 초 동안 운반량 0, 상태는 ‘광맥의 토대가 무너졌습니다’였다. 굴착을 하지 않은 저장이다. 시작 철 광맥으로 재배정하는 별도 검사에서는 64개가 정상 운반됐다. 로봇 전체 고장으로 단정하지 않으며, 선택 가능한 광맥의 토대 적합성·배정 전 표시를 보완할 필요가 있다.

## 최초 실행 오류와 제한

검사 도중 항해 소스가 다른 작업으로 갱신됐다. 첫 실행에서는 `FrontierStellarRoutes` 클래스 인식 오류, 다음 실행에서는 은하 지도 좌표 배열 접근 오류가 있었다. **최신 파일로 재실행한 실제 항해에서는 재현되지 않았으므로 현재 확정 차단 문제와 구분한다.** 이 테스트에서 해당 게임 코드를 수정한 것은 아니다.

영구 사용자 저장은 수정하지 않았다. 테스트 전용 창은 종료했다. 전체 UI 수동 채광·건설·모든 생산 예약·정산 완주는 미확인이고, 위의 확인 모드를 넘어서 완료로 기록하지 않는다.

## 증거

로컬 재생성 결과는 `test-results/natural-progression-20260907/`에 보존했다.

- `probe.log`: 재료 지급 없이 개인/시설 성장, 얼음 부족 지점.
- `downstream.log`: 보급/회수 명령 우회 후 환경·선박·정산·다음 행성 연결. `FAILURES 0`은 요청 성공 여부이며 첫 로봇 운반 0까지 성공으로 해석하면 안 된다.
- `robot.log`: 시작 철 광맥에서 실제 산업 물류 64개 운반.
- `pre-settle.json`: 복원 완료·정산 전 상태. `probe-world.json`: 내부 정산·다음 행성 도착 상태.
- `progression.gd`, `downstream.gd`, `robot.gd`: 임시 검사의 원본. `/tmp/space-natural-play-20260907/`의 입력 저장을 사용하는 실행 전제이며 일반 게임 테스트 묶음에 추가하지 않았다.
