# 단일 행동의 변경·갱신 범위 조사 — 2026-09-12

같은 날 후속 승인으로 일반 거래의 동기 파일 저장과 날씨·사건의 반복 전체 초안을 개선했다. [160 구현·측정](160-transaction-drafts.md)을 따르며 아래 목록은 후속 적용 후의 잔여 비용으로 갱신했다.

사용자는 하나의 행동이 관련 없는 전체 상태·화면을 바꾸거나 다시 처리하는 문제를 필수 검사 항목으로 문서에 넣고 다른 경로도 조사하도록 요청했다. [AGENTS.md](../../AGENTS.md)와 [Godot 기술 설계](../technical/01-godot-architecture.md#단일-행동의-변경갱신-범위--필수-검사)에 상시 적용 규칙을 추가했다. 테스트 최소화 기간에도 이 범위 검사는 생략하지 않는다.

## 조사 결과와 수정

| 경로 | 확인한 문제 | 현재 조치 |
| --- | --- | --- |
| 채집·운반 → 아이템창 | 수량 하나가 바뀌어도 닫힌 아이템창의 소유 장비·제작법·양쪽 화물 카드를 전부 제거하고 재생성 | 닫힌 창은 핫바만 갱신. 열린 탭만 목록을 반영하며, 장비/자원 중첩/화물의 안정된 키로 기존 카드를 재사용. 생긴 중첩만 추가하고 소모된 중첩만 제거 |
| 재료 변경 → 제작 탭 | 고정된 제작 카드 19개를 반복 생성 | 기존 카드를 유지하고 현재 재료에 따른 제작 가능 여부·상세 정보만 반영 |
| 실패·중복 요청 → 발행 | 권한 요청의 성공·실제 변경 여부와 무관하게 모든 승무원 스냅샷·지역 패킷 생성 호출 | 세계 revision·대기실 준비·진행 단계가 바뀔 때 발행. 변경 없는 실패/재전송은 응답만 반환. 오래된 클라이언트의 실패는 최신 승무원 상태로 복구 |
| 건설·FINCH 배치·Lotus 투하 공간 검사 | 매 검사에서 같은 주변 지표·지하 광맥과 고정 광맥 재생성 | 생성 결과를 지역별로 재사용. 행성/시드/규칙 변화 시 초기화, 고정 항목 포함 65개 캐시 항목으로 제한. 장애물 판정의 광맥 내용·배치 규칙은 유지 |
| 로버와 무관한 요청 | 모든 요청에서 로버 런타임 깊은 복사 | 로버 명령에만 복사. 로버 탑승 제한과 굴착/사건 도구 재사용 대기도 세계 복사 전에 검사 |
| 지형 편집 → 생물 접지 | 같은 geometry_changed 신호에 생물 캐시 무효화를 중복 연결 | 기존 생태 컴포넌트의 구독 하나만 유지 |

핫바는 닫힌 창에서도 장비 선택을 즉시 반영한다. 기존 카드의 클릭·드래그가 오래된 재고량을 쓰지 않도록 화물 payload도 최신 값으로 교체한다. 소유 장비의 정의·희귀도와 검색/필터를 보존한다.

## 남아 있는 구조적 비용

**전체 처리 문제가 모두 제거된 상태는 아니다.** 다음은 코드에서 확인한 후속 대상이다.

1. **남음 — 저장 전 전체 검증·작업 스레드용 스냅샷.** 일반 요청의 파일 저장은 비동기로 전환했다. 선택·장착·휴대 제작·장비/탐험복 개조 5개 명령은 개인 범위 초안을 사용하지만 다른 명령은 독립 전체 초안을 유지한다. `WorldStore.begin_commit`의 전체 도메인 검증과 가변 스냅샷 복사는 메인 스레드에 남는다. 원래 약 100KB 저장의 슬롯 선택은 37.91 / 33.79 / 34.69ms였고, 후속 국소 검사는 실행별 9.86~16.61ms였다. JSON 직렬화·임시 기록·읽기 확인·백업·교체는 순서 보장 작업 스레드에서 수행한다. 전체 처리 자체가 모두 제거된 것은 아니다.
2. **축소·남음 — 정기 시뮬레이션의 후보 복사.** 날씨·사건의 0.25초 전체 깊은 복사는 명시한 변경 범위의 독립 초안으로 교체했다. 저장이 없는 날씨 시계·사건 시간도 유지한다. 산업의 1초 전체 초안, 사건 목록의 얕은 복사·순회와 실제 저장 제출 시 전체 스냅샷은 남는다.
3. **중간 — 지표 패킷을 생성한 뒤 변경 여부 비교.** 지역 패킷은 이미 해당 행성·근처 생물·개인 화물로 제한되지만 재료 변화 하나에도 그 지역의 지형 편집·물·생태가 포함된 패킷을 먼저 만든다. 원격 지표 전송은 전체 지역 패킷이며, 승무원 스냅샷의 차분 전송과 다르다. 도메인별 revision/차분·재접속 복구를 함께 다뤄야 한다.
4. **중간 — 전체 재고 표본 정리·검증 순회.** 개인 장비 5개 명령에서는 `SpecimenItems.prune`를 생략한다. 나머지 거래 끝의 정리는 여러 보관소의 0개 표본을 검사한다. 세계 저장 검증도 모든 보유 기록을 순회한다. 표본이 있는 보관소의 변경 집합과 전체 체크포인트 검증을 나누는 후속이 필요하다.
5. **중간 — 지형 의존 캐시의 넓은 무효화.** 실제 청크 메시 재생성은 편집과 겹치는 청크로 제한되어 있다. 다만 원경 갱신 요청·근처 생물 접지·광맥 높이 캐시는 지형 변경 신호를 넓게 받는다. 중복 호출은 제거했으며, 편집 경계와 바닥 의존성을 유지하는 더 좁은 범위 처리는 별도다.

후속에서 공유하는 관련 없는 분기는 해당 동작이 읽기만 하며, 쓰는 분기는 독립 복사한다. 전체 저장 검증은 생략하지 않는다. 거래 결과·요청 영수증의 원자성, 저장 실패 시 원본 보존, 성공 전 발행 금지를 유지한다. 향후 도메인별 변경 기록/저장과 전체 체크포인트를 분리할 때 기존 저장·복구·협동 순서를 함께 전환해야 한다.

## 이미 범위를 제한하는 경로

- 지형 굴착은 `TerrainField.add_edit`가 반환한 영향 청크만 재생성하고 경계 청크를 함께 적용한다. 광물 하나를 캤다고 행성 전체 지형을 다시 생성하는 구조로 판단하지 않았다.
- 사업 현장·사건 모델은 ID로 기존 노드를 유지하고 추가/제거된 대상만 생성/제거한다. 상태 수신 시 주변 목록 순회는 남아 있지만 매번 모든 모델을 새로 만드는 것은 아니다.
- 사업 패널은 [147](147-ground-frame-budget.md)에서 보이는 탭 중심으로 갱신하며, 지표 생성 목록은 캐시를 사용한다. 승무원 네트워크는 이미 확인된 기준 스냅샷과 차분을 전송한다.
- 최초 적재·행성 전환·저장 이행·종료 체크포인트의 전체 처리는 의도된 경계다. 평상시 단일 입력과 구분한다.

## 확인 범위

실제 Godot 4.7.2 Forward+ / Metal / Apple M2, 1280×800에서 별도 저장 복사본을 사용했다. 자료는 [검사 근거](media/action-scope/)에 보존한다.

| 같은 행동의 국소 측정 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 닫힌 아이템창에서 자원 수량 +1 | 5.599ms, 모든 목록 노드 교체 | 확인 실행별 0.074~0.128ms, 모든 목록 노드 유지 |
| 같은 셀 안의 광맥 공간 검사 3회 | 6.167 / 6.033 / 5.282ms | 최초 5.436~8.687ms, 재사용 0.041~0.233ms |
| 변경 없는 건설 실패의 즉시 스냅샷 발행 | 1회 | 0회 |

이 수치는 해당 함수의 소요 시간이며 전체 프레임 시간이나 60 FPS 보장이 아니다. 최초 방문의 생성 비용, 세계가 커졌을 때의 최악 시간, 6인 실제 전송량은 이번 측정 범위가 아니다. 실제 창 종료 시 실행별 ObjectDB 1~4개 누수 경고가 관찰되어 경고 없는 종료로 기록하지 않는다.

실행 도구는 `tests/check_action_scope_ui.gd`, `tests/check_action_publication.gd`, `tests/check_mining_commit.gd`이며, 거래/캐시의 별도 검사 소스도 근거 폴더에 보존한다.

검사는 발견된 문제에 한정한다. 실제 창의 카드 유지·수량·입출고 payload·중첩 추가/제거와 제작 가능 여부, 요청 발행의 실패/재전송/최신 상태 복구, 기존 채광의 저장 실패/중복 지급 방지, 캐시의 셀 경계/시드 변경/상한을 확인한다. 테스트 전체 묶음·장시간 실행·6인 회귀 검사는 실행하지 않는다.
