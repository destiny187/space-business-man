# T3~T5 선박 항해 내성과 선체 개장

2026-09-10 사용자 승인 구현. T2까지 자유 진행, T3~T5는 조건을 갖춘 선박 구매/보유·운용, 후속 전투/무역 확장성이 요구사항이다. 게임 규칙의 단일 소관은 [우주 탐험·우주선](../game/07-space-exploration-and-ships.md)이다.

## 현재 구현

`data/vessel_access.json`에 성능 키/표시/아이콘, 티어별 요구치, 선체 기본 성능, 개장 단계/비용을 둔다. `FrontierVesselAccess`가 실제 운용 선체의 기본 성능과 선체별 영구 개장을 결합하고 장착 모듈의 등급별 `capabilities`를 합산한다. 현재 임무 모듈에 새 내성을 임의 부여하지 않았으며, 기존 추진 보조기만 개량해서 항속거리를 늘리는 것으로 고티어 조건을 대신할 수 없다.

| 접근 범위 | 입자 차폐 | 열 제어 | 항법 안정 |
| --- | ---: | ---: | ---: |
| T1·T2 | 조건 없음 | 조건 없음 | 조건 없음 |
| T3 | 1 | 1 | 1 |
| T4 | 2 | 2 | 2 |
| T5 | 3 | 3 | 3 |

은하 생성의 `band` 0/1은 기초 항로, 2/3/4는 T3/T4/T5 항해 환경으로 해석한다. 월드·분포를 재생성하지 않는다. 성간 진입은 항성권 환경, 항성계 내 자동 접근과 착륙은 개별 행성 티어를 검사한다. 따라서 외곽에서 우연히 나온 T3 행성도 착륙 조건을 피할 수 없으며, 안쪽의 T2 행성은 해당 항성권 진입 성능이 필요하다. 궤도 관측/수동 비행 자체에 즉사나 새로운 강제 물리 장벽을 추가하지 않았다.

`vessel.hull`이 운용 선체이고 `vessel.hulls`는 보유 목록이다. 미운용 선체는 항해 성능을 주지 않는다. 개장은 `vessel.navigation_refits[hull_id]`에 3~5로 저장하며, 선체 교체 후 돌아오면 그 선체의 개장을 그대로 복원한다. 기존 질량·원자로·로봇/차량 적재 검사와 모듈 슬롯은 유지한다. 선체 데이터에 역할 태그를 추가했으며 전투/무역 능력은 항해 티어와 별도 성능 키로 확장할 수 있다. 이번에 함포·전투 슬롯·무역 계약을 구현한 것은 아니다.

## 획득과 초기 밸런스

기본 KESTREL은 T2까지 가능하다. SWIFT(고속 탐사선)와 MULE(중량 수송선)는 구매 당시 T3 내성을 갖춘다. 기존 저장에 소유한 두 선체도 현재 운용하면 같은 판정을 받으며 추가 구매를 강요하지 않는다.

| 선택 | 공동 크레딧 | 가공 부품 |
| --- | ---: | --- |
| SWIFT 구매 | 24,000 | 정거장 선체 재고 1척 |
| MULE 구매 | 28,000 | 정거장 선체 재고 1척 |
| T3 현장 개장 | 12,000 | 고합금 프레임 8, 저온 전해 셀 4, 산업 코어 2 |
| T4 현장 개장 | 36,000 | 내식 합금 16, 순환 모듈 6, 지역 열교환 모듈 6 |
| T5 현장 개장 | 100,000 | 내식 합금 40, 순환 모듈 16, 지역 열교환 모듈 16 |
| T3/T4/T5 정거장 개장 | 18,000 / 54,000 / 150,000 | 정거장이 부품 공급 |

표의 금액은 **해당 단계의 비용**이다. 기본선에서 T5까지 정거장 개장하면 세 단계를 순서대로 구매한다. T3 성능 선체는 T4부터 시작한다. 호스트가 공동 자금으로 한 번 확정하며 승무원 수로 곱하지 않는다. 현장 개장은 착륙선 가까이에서 운영 중인 현장 창고 부품을 쓴다. 별도 정거장을 못 찾더라도 기본선의 현장 개장이 가능하다. 일반 정거장은 기존 항성계별 출현/선체 재고 규칙을 유지하고 부품 포함 개장 서비스를 제공한다. 태양계 고정 물류항의 서비스 범위는 그대로 보존한다.

T3 부품은 기존 T2 생산망만으로 준비할 수 있다. T4·T5는 현재 구현된 T3 부품을 쓰는 초기 구성이다. **T4 산업·전용 광물/생산망은 미구현**이므로 T5에 존재하지 않는 레시피를 요구하지 않는다. 해당 산업을 개발할 때 T5 부품 구성을 다시 맞춘다. 정거장 서비스는 무역 등 다른 수입 경로를 통한 성장을 허용한다. 특정 행성 판매 횟수·자동화·실시간 대기 타이머를 새 필수 조건으로 넣지 않았다.

가격은 시작 예산 6,000 Cr만으로 즉시 T3를 개방하지 못하게 한 첫 조정이다. [변경 전 측정](109-t3-progression-benchmark.md)의 24분 27초/23분 21초는 현재 버전의 시간 보장이 아니다. 90~120분/60~90분이라는 앞선 목표 제안도 아직 실증되지 않았다.

## 호스트·저장·복구

- `depart`와 `land`의 호스트 판정에 공통 평가기를 사용한다. 지도와 직접 항해 표식은 같은 판정으로 이유를 표시한다.
- FINCH의 임시 실행 문맥에 실제 공동선의 항해 성능만 전달한다. 소형선이 미운용 고급 선체의 소유 목록을 이용해 잠금을 우회하지 않는다. 공동선의 착륙 행성으로 돌아오는 복구는 허용한다.
- 개장/구매는 기존 호스트 초안→검증→저장→공개 경로를 사용한다. 재전송은 중복 차감하지 않으며 저장 실패는 자금·개장을 되돌린다. 성공 음원은 실제 호스트 결과 뒤에 재생한다.
- 새 설정은 협동 콘텐츠 해시에 포함한다. 선택적 저장 필드라 기존 선박/은하 해시를 바꾸거나 기본 선박을 재생성하지 않는다. 개장 기록의 보유 선체/범위/자료형을 검증한다.
- 이미 진행 중인 성간 항해는 완료한다. 부족한 선박으로 안쪽에 있는 기존 저장은 낮은 항성권으로 나가거나 같은 항성권 안에서 반경이 커지는 방향으로 이동할 수 있다. 기존 항속거리·승선·준비 조건은 계속 적용한다. 외곽 복구 예외는 고티어 착륙 권한을 주지 않는다.

## 화면과 확인

K 정비창의 **항해 개장** 탭, 일반 정거장의 **항해 개장/선체 구매/보유 선체**, 항성지도와 직접 항해 표식에 연결했다. 기존 Blender KESTREL/SWIFT/MULE 모델과 Godot INK 렌더를 사용한다. 새 선체 모델을 제작했다고 기록하지 않는다. 현장 가공 부품 아이콘·세 성능 막대·부족 수치·다음 개장 가격을 표시하고 실제 장착 슬롯은 유지한다.

최소 확인 결과는 아래 도구/캡처에 둔다. 준비된 좌표와 자금/재고를 사용하는 기능 검사이며 정상 시작에서 해당 자금을 버는 장시간 플레이와 구분한다.

- `tests/check_vessel_access.gd`: 49개, 실패 0. T1/T2와 T3~T5 경계, 자동 접근/착륙 거절, 항성권 진입/외곽 복구, 구매와 미운용 소유 구분, 선체 교체와 기존 모듈 보존, 순차 개장, 저장 실패/중복 요청, 두 승무원 공동 성능·호스트 거래, 직렬화, 잘못된 개장 기록, FINCH 우회/귀환, T2 부품을 이용한 현장 개장.
- `tests/check_vessel_access_ui.gd`: 실패 0. Godot 4.7.2 / Metal Forward+ / Apple M2의 실제 게임 창. 정거장 개장/선체 구매·교체, 현재 비행 모델, 승인 뒤 ElevenLabs 효과음과 메뉴 환경음 종료, K 정비창·잠긴 T4 항로, 960×640 버튼 위치와 스크롤 없이 보이는 항해 성능 비교를 확인했다. 새 화면 검수 중 발견한 정비창의 궤도상 공동 자금 0 표시를 최신 공용 자금 스냅샷으로 수정했다.
- 기존 정거장 검사 두 개의 선체 구매 준비 자금은 고정 20,000 대신 현재 선체 가격에서 계산하도록 고쳤다. 이번에 기존 전체 묶음·실제 네트워크 다중 클라이언트·장시간 진행을 반복 실행하지 않았다.
