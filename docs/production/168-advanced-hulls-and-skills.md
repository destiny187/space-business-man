# T3·T5 역할 선체와 전투 스킬

2026-09-13. 사용자는 KESTREL 균형 탐사·SWIFT 고속 탐사·MULE 수송 역할을 유지하면서 T3·T5 선체를 추가하고, 역할에 맞는 기본 스킬과 별도로 획득·장착할 수 있는 다양한 스킬을 요청했다. 역할별로 두 척씩 **새 선체 6종**, 기존 세 척을 포함한 **고유 능력 9종·공용 능력 5종**, 역할별 고정 패시브 3종을 현재 원정에 연결했다. 이름·가격·수량·성능은 이번 구현의 초기 선택이며 사용자 확정 밸런스가 아니다. 전투 규칙의 단일 소관은 [해적 전투](../game/28-pirate-interdiction.md)다.

## 선체·운용

| 역할 | 기존 | T3 신형 | T5 신형 |
| --- | --- | --- | --- |
| 균형 탐사 | KESTREL | ASTER — 공명 탐지파 | ORION — 성좌 유도탄 |
| 고속 탐사 | SWIFT | PEREGRINE — 벡터 산탄포 | SPECTRE — 위상 관통포 |
| 대형 적재 | MULE | OX — 견인 구속기 | ATLAS — 성채 충격파 |

선체 구매·소유·실제 교체는 기존 일반 정거장 흐름을 사용한다. T3 선체는 T2 이상 지역, T5 선체는 T4 이상 지역 정거장에서 구매할 수 있다. 해당 급의 지역에 먼저 들어가야 선체를 사는 순환 잠금을 피하는 배치다. T3 선체의 기본 항해 내성은 세 항목 각 1, T5는 각 3이다. 기존 KESTREL 개장, SWIFT·MULE의 T3 항해 능력과 기존 임무 모듈은 보존한다. 기존 SWIFT·MULE을 T1 항해 능력으로 낮추지 않는다.

화물 칸은 설명 수치뿐 아니라 실제 입출고·인양·승무원 공개 상태에 적용한다. 작은 선체의 용량보다 화물이 많으면 먼저 하역하도록 교체를 거절한다. 현재 선체·화물은 실패한 거래의 독립 초안에만 남고 원본은 바뀌지 않는다. 더 큰 실드 선체로 바꿀 때 실드를 무료로 채우지 않으며 작은 선체는 새 최대치까지만 유지한다. FINCH는 기존의 비무장 항성계 수송·독립 도주 역할과 적재량을 유지한다.

## 획득·장착·강화

좌클릭 함포, 우클릭 선체 고유 스킬, 1·2번 공용 장착 슬롯을 분리했다. 고유 스킬도 일반 정거장의 **전투 스킬** 탭에서 별도로 확보하면 다른 선체의 1·2번에 장착할 수 있다. 현재 선체의 고유 스킬은 별도 구매 없이 우클릭으로 사용·강화하지만, 추가 장착 권한은 별도 구매다. 같은 스킬을 현재 우클릭과 1·2번에 중복 장착할 수 없다. 기존 추진/공용 임무 모듈과 이 두 슬롯은 독립이다.

기초 스킬 **과출력 추진·전방 방벽**과 두 기본 슬롯을 제공한다. 강화는 스킬 ID별 +0~+4로 공유하므로 다른 선체의 고유 스킬로 사용해도 같은 강화가 적용된다. 장착 목록은 선체별로 보존한다. 스킬 설계 티어는 T1·T3·T5이며 UI는 표준·정밀·첨단 설계로 표시한다. 항해 내성·장비 희귀도와 별개다. 티어는 기본 위력·효과·획득/강화 비용을, 강화는 해당 능력의 대상 수·발사 수·피해·지속시간 등을 결정한다.

| 스킬 | 설계 | 실제 동작 |
| --- | --- | --- |
| 다중 유도탄 / KESTREL | 표준 | 전방 표적에 곡선 유도탄 분산 발사 |
| 이온 관통포 / SWIFT | 표준 | 짧은 충전 후 확정한 사선의 적 관통 |
| 방어 EMP / MULE | 표준 | 근처 적 피해·짧은 감속 |
| 공명 탐지파 / ASTER | 정밀 | 전방 적 피해·표시와 후속 공격 피해 증가 |
| 벡터 산탄포 / PEREGRINE | 정밀 | 펼쳐지는 실제 직진 이온탄 |
| 견인 구속기 / OX | 정밀 | 거리·가림을 유지한 한 적의 감속·실드 지속 피해 |
| 성좌 유도탄 / ORION | 첨단 | 더 넓은 각도·긴 사거리·높은 위력의 다중 유도탄 |
| 위상 관통포 / SPECTRE | 첨단 | 긴 충전 후 넓은 사선 관통 |
| 성채 충격파 / ATLAS | 첨단 | 주변 적 피해·감속과 자기 실드 일부 복구 |
| 과출력 추진 | 표준 | 가속·선회 증가, 발동 시 열 부담 |
| 전방 방벽 | 표준 | 기수 쪽 공격만 제한된 용량으로 차단 |
| 긴급 방열 | 표준 | 즉시 열 배출·과열 잠금 해제 |
| 미끼 비콘 | 정밀 | 실제 비콘 투하, 적의 다음 조준 유도 |
| 후방 기뢰 | 정밀 | 경로에 남기는 실제 기뢰, 준비 후 근접 감지·한 번 폭발 |

두 유도탄의 성장 순서는 `2대×1발 → 3대×1발 → 3대×2발 → 4대×2발 → 4대×3발`이다. 발사 순간 실제 표적을 정하고 미사일의 선회·장애물/기체 충돌·수명으로 피해를 확정한다. 표적이 부족하다고 남는 몫을 한 척에 몰지 않는다. T2/T3/T5 해적 편대는 각각 3/4/5척으로 확장하고 티어별 내구도를 연결했다. 적의 전진·감속 조준·통과·롤 이탈은 유지한다.

탐사형의 **추적 보조**는 함포 명중 뒤 5초간 표적의 후속 피해를 18% 높인다. 고속형의 **기동 냉각**은 1.5초 이상 부스트 후 종료하면 3초 방열을 강화하고 재발동 대기 12초를 둔다. 수송형의 **비상 차폐**는 실드 파괴 후 3초간 후속 피해를 절반 줄이고 재발동 대기 28초를 둔다. 패시브는 이번에 역할별 고정 능력이며 별도 장착·강화는 추가하지 않았다.

## 기존 저장·행동 범위 검사

`vessel.combat_skills`가 없는 저장은 읽을 때 기본 스킬/슬롯을 제공하고 거래 시에만 기록을 만든다. 기존 선체 소유·항해 개장·임무 모듈·원산 생물·행성/산업 상태는 바꾸지 않는다. 기존 정거장의 새 선체 항목 누락만 허용하고, 투영 시 해당 항목만 추가한다. 과거 구매로 0이 된 재고를 다시 채우지 않는다. 해적 규칙이 없는 과거 세계에 습격을 소급 활성화하지 않는다.

입력 10칸까지의 기존 형식을 보존하고 11/12번째 값에 1/2 스킬 입력을 추가했다. 호스트 조종사·승선·수동 항해·교전·조준 방향·표적·재사용 대기·준비/동시 효과 한도를 검사한다. 대기 시간은 선체 슬롯이 아닌 스킬 ID별로 선박 전투 기록에 저장하며 저장 재개·선체 교체로 초기화하지 않는다. 메뉴·포커스 차단은 기존 입력 수집 경로를 따른다.

**스킬 사용 한 번:** 운용 선박의 능력 상태, 현재 조우의 최대 5적, 필요한 투사체/최대 8설치물과 짧은 이벤트만 변경한다. 호스트 장애물 캐시를 재사용하고 다른 행성·산업·장비를 복사하거나 재생성하지 않는다. 충전/지속 효과·표적 상태는 같은 조우에서만 갱신한다. 대상 판정과 실제 피해는 호스트가 확정한다.

**정거장 스킬 정비 한 번:** 선박/스킬 기록, 공동 크레딧, 요청자·영수증만 독립 복사한다. 개인 인벤토리의 구버전 병합·빈 기록 정리·무관한 가방 생성도 거치지 않는다. 실패한 저장은 초안을 폐기한다. 닫힌 정거장 화면은 재구성하지 않으며, 열린 스킬 화면에서도 무관한 카드·현재 선체 모델의 인스턴스를 유지하는 것을 확인했다. 일반 선체 구매·교체는 기존 전체 거래 초안을 유지한다.

**남은 전체 비용:** 저장 전 전체 세계 검증·직렬화 복사, 원자적 파일 저장, 기존 협동 공개 스냅샷 발행은 유지한다. 모든 저장/네트워크 비용을 부분 갱신으로 바꿨다고 기록하지 않는다. 클라이언트 락온은 거리·각도의 표시 예측이며 최종 가림·대상 선정은 호스트 판정이다.

Godot 4.7.2 / Metal Forward+ / Apple M2에서 확인했다. 일반 전체 회귀·장시간 반복·6인 검사는 실행하지 않았다.

## 2026-09-13 후속 — 선체 내부 조사

후속 사용자 요청으로 [선체별 실내·창문·게스트 관전](171-vessel-interiors-and-observer.md)을 개발했다. 아래는 변경 전 조사 이력이다.

사용자는 선체·스킬 커밋과 함께 “선체 내부는 다른 게 있을까, 지금은 정면만 보인다”며 우선 조사를 요청했다. **이번 내부 작업은 코드·현재 모델 조사와 렌더이며 내부 기능·조작·선체 모델을 변경하지 않았다.**

현재 KESTREL·SWIFT·MULE과 신형 6척 모두 `kestrel_cabin.glb` 하나를 공유한다. 선체 교체는 외부 모델·능력/슬롯을 교체하며 실내 경로나 배치 선택 필드는 없다. [현재 실내 생성 코드](../../우주-비즈니스/scripts/app/crew_expedition.gd)의 `_build_cabin()`이 선체 ID와 무관하게 같은 모델·충돌·조명을 생성한다. [42 선체 교체 기록](42-space-stations-and-hulls.md)에서도 전용 실내는 후속으로 남겼다.

| 실제 위치 | 현재 구성 |
| --- | --- |
| 공통 객실 | 모델 기준 폭 8m·길이 16m·높이 약 4m의 단일 공간 |
| 앞 | 큰 정면 창과 좌우 항해 콘솔 |
| 좌우 | 각 3석, 총 6석과 벽·배선·조명 |
| 뒤 중앙 | 공동 화물 보관함과 기압문 외형 |
| 뒤 좌우 | 신체 증강 장치·표본 연구대. [장치 데이터](../../우주-비즈니스/data/crew_stations.json)의 ±3m, z=4.2 위치 |

우주에서 `C`는 외부/선내 전환이다. 선내의 마우스는 제한 없는 좌우 회전과 위아래 약 ±89도, WASD는 캐릭터 이동이다. 메뉴·오프닝·포커스/커서 상태에 따른 차단이 있다. 반면 수동 비행 조종사의 외부 시점에서 마우스는 기수 선회에 연결되고 `look_offset`을 0으로 유지한다. 항해 중이거나 조종사가 아닌 경우에는 제한된 외부 카메라 둘러보기가 있다. [입력 코드](../../우주-비즈니스/scripts/app/crew_expedition.gd)의 `_unhandled_input()`·`_mouse_look()`에서 확인했다. 물리 키보드 입력으로 현재 사용자 창을 직접 재현한 결과는 아니다.

정면 창은 별도의 외부 항해 뷰포트 영상을 평면에 표시한다. 실내 카메라가 유리 너머 같은 3D 우주를 직접 보는 구조는 아니다. 좌우·뒤에는 창이 없고, 머리를 옮기면 외부 시야가 위치에 맞춰 달라지는 창도 구현하지 않았다. 시작 위치가 객실 뒤에서 정면을 향하고, 최근 시작 흐름은 외부 비행으로 진입하므로 뒤쪽 작업 장치와 내부 이동을 알아차리기 어렵다. 이것은 코드·배치에서 추론한 사용성 원인이다.

현재 없는 것은 선체별 조종석·화물실/연구실, 독립 기관실·거주실, 실제 문 개폐로 이어지는 방, 외형과 같은 공간에서 직접 오가는 내부/외부 연결이다. ATLAS의 적재량과 ORION의 능력이 늘어나도 실내 크기나 가구는 변하지 않는다. 선체별 고유 실내로 완료 처리하지 않는다.

후속 **제안**은 균형 탐사형의 지도·표본 작업 공간, 고속형의 조종석·추진 상태 표현, 수송형의 화물 랙·하역 통로를 세 역할로 먼저 나누고 T3/T5에서 확장하는 것이다. 구현할 경우 외형 데이터에 실내/배치 정의를 추가하고, 현재 코드에 고정된 충돌·6인 시작 위치·창고/장치 위치와 호스트의 별도 실내 공간도 함께 바꿔야 한다. 선체 교체 한 번은 해당 객실과 그 안의 승무원·장치만 옮기도록 처리 범위를 제한하고, 행성·산업·무관한 공간을 재생성하지 않는 방향이 필요하다. 이 제안을 개발 승인으로 취급하지 않는다.

조사 렌더는 기존 모델·장치 위치와 현재 실내 조명/FOV를 사용해 앞·뒤·연구대를 Godot Metal Forward+에서 확인했다. 항해 영상·승무원·상호작용 UI는 제외한 모델 검토다. 전면 창이 빈 배경인 것은 이 렌더의 제외 범위이며 게임의 창 영상 누락을 뜻하지 않는다. 재생성은 `tests/render_vessel_interior.gd`, 원시 결과는 `output/advanced-hulls/interior-audit/`다.
