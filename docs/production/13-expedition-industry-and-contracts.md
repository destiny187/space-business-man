# 탐험에서 현장 산업과 복원 계약으로

[공동 지표 탐험](12-shared-surface-and-ecology.md) 이후, 같은 3D 행성에서 무료 개발 등록·자원 채집·현장 창고·시설·로봇 자동화·지역 환경 개선·정산·다음 원정 재투자를 연결한다. 기존 구매 기반 `campaign.json`을 그대로 복사하거나 개인 장비에 공동 자산을 지급하지 않는다. 혼자 방을 열어도 같은 규칙으로 플레이한다.

## 이번에 구체화한 사업 범위

초기 사업은 **착륙 거점 주변의 지역 복원 계약**이다. 행성 자체를 구매하지 않고 무료로 개발 구역을 등록한다. 한 번에 활성 사업 하나를 운영하며 다른 행성에서 생물과 표본을 탐사하고 돌아올 수 있다. 정산은 지역 시설·환경 성과를 인계하는 계약이며, 행성 전체의 소유권이나 아직 구현되지 않은 원주민의 권리를 매각하지 않는다.

신규 사업 장부의 초기 공동 자본은 6,000 Cr다. 등록 시 현장 광물 재고는 0이며, 자본은 세계당 한 번만 초기화한다. 기존 공동 선박 광물과 현장 산업 창고는 분리한다. 첫 생산 단계 지급과 최종 복원 계약 지급은 각각 한 번 확정한다. 수치·거리·개수 제한은 `data/expedition_business.json`, 시설/기술 비용·모델은 기존 `data/catalog.json`의 기초 항목을 사용한다. 모두 초기 밸런스이며 최종 경제값이 아니다.

## 조작과 자원 흐름

시작 화면의 **우주 탐험 · 사업 시작**으로 들어간다. 기존 단독 탐험 기록과 1.2 사업 저장은 별도 진입점으로 보존한다. 원정에서 행성을 선택해 착륙한 뒤 `B`로 사업 단말을 연다.

1. 착륙선 주변에서 무료 개발 등록을 한다. 시드 자원 스트림으로 유한 광맥을 만들고 철·구리·암석·얼음의 시작 광맥은 접근 가능한 착륙 구역에 보장한다.
2. 보이는 광맥 가까이에서 `F`로 채광한다. 고갈량과 실제 작업자의 사업 배낭이 함께 변한다. 현장 창고에서 `F` 또는 단말 버튼으로 반납한다. 일반 굴착으로 운반하던 암석도 현장 창고로 반납할 수 있다.
3. `B`의 건설 탭에서 시설을 고른다. 실제 모델의 반투명 미리보기를 지면에 조준하고 클릭하면 배치한다. 거리·토대·경사·시설/광맥/승무원 중첩을 확인한다. 취소는 `Esc`이며 재료를 소비하지 않는다.
4. 기초 기술과 태양광·충전기·제작소를 확보한다. 제작소에서 유한 재료를 소비해 고유 ID와 등급이 있는 로봇을 만들고 광맥을 배정한다.
5. 대기·열·수자원·생태 설비를 가동한다. 전력 부족·얼음 부족·배양 조건 미달·토대 손상을 구분해서 표시한다.
6. 계약 조건을 충족하면 필요한 로봇을 먼저 격납고로 회수하고, 현장 자원을 반납한 뒤 계약을 인계한다. 크레딧과 영구 기술·운송 로봇으로 다음 행성의 사업을 시작한다.

단말은 건설·기술/보급·로봇·환경/계약 탭으로 나눴다. 기술과 보급의 공동 자금 지출 및 정산은 호스트가 확정한다. 다른 승무원은 채광·운반·시설 운영과 로봇 배정을 분담할 수 있다. 기초 광물 보급은 실제 공동 크레딧으로 구매하며 무상 채집 보상과 구분한다.

## 자동화와 보존

로봇은 지형의 지지면 경로를 찾고 시설 장애물을 우회한다. 경로상의 바닥·기울기·몸체 공간을 재검사하며, 통로가 바뀌면 재탐색한다. 물리 엔진의 강체 차량을 완성한 것이 아니라, 호스트가 SDF 지형과 장애물을 검사해 확정하는 지면 경로 이동이다. 실제 모델·바퀴와 위치 보간으로 동작을 표시한다. 지상 사업용 채광 로봇과 기존 단독 지하 운반차의 구현을 구분한다.

광맥에서 실은 자원은 로봇 화물에 남고 현장 창고에 도착해야 재고가 된다. 이동과 작업에 배터리를 사용하며 부족하면 전원이 켜진 충전기로 돌아간다. 완전히 멈춘 로봇은 가까이에서 유료 긴급 충전할 수 있다. 충전기·제작소를 환경 설비보다 먼저 전력 배분한다. 제작 도중 제작소를 철거해 재료를 이중 환불할 수 없다. 일반 철거는 최초 건설 재료만 반환한다.

운송 회수는 회수 기술·빈 화물·창고 근접·격납고 여유를 요구한다. 같은 로봇 ID·등급·배터리를 다음 행성에 재파견한다. 현장/격납고에 같은 ID가 중복 존재하면 저장을 거부한다. 승무원이 사업 자원을 들고 이탈하면 해당 행성과 좌표에 사업 회수 화물을 남긴다. 출항 전에 배낭을 현장 창고에 비우도록 검사한다. 정산된 사업의 자산은 다시 채광·건설·철거·회수하거나 중복 정산할 수 없다.

호스트는 자동 생산 상태도 사본에 계산해 저장한 다음 공개한다. 개인 명령은 기존 세션/순번/리비전 검증을 사용한다. 생산 시간은 현재 착륙한 활성 사업에서만 진행하고 방문하지 않은 사업이나 종료된 게임의 시간을 따라잡지 않는다. 전송에는 현재 행성 사업·자기 배낭·공동 자금/기술·격납고만 포함하며 다른 행성들의 사업 전체를 매번 전송하지 않는다. 로봇 탐색 경로도 호스트 저장에만 남기고 위치/화물/작업 상태만 복사한다. [최대 크기 전송 검사](../technical/04-coop-networking-and-session-save.md#산업-로봇-경로와-패킷-상한)에서 경로 포함 시 발생했던 수신 한도 초과를 재현하고 수정했다.

## 환경 변화와 아트

환경 설비는 지역 계약의 온도·대기·물·배양 지표를 개선한다. 수자원 순환기는 얼음을 소비하며, 생태 배양기는 적합한 환경에서 허가된 표준 균주와 수분을 사용한다. 이 변화는 고유 외계 생명이 무생명 행성에서 갑자기 생성된다는 의미가 아니다. 시드 고유 생물·기존 시험 구획·이식의 규칙은 별도로 유지한다.

관리 범위 안의 지표 색이 생태 복원도에 따라 변하며 바깥 지형은 유지한다. 현재는 국소 지표 변화와 장비 가동 표현이다. 행성 전역 기후·해양·먹이망·실제 물질/열 회로가 완성됐다고 표시하지 않는다.

기존 Blender 시설·자원·채광 로봇과 INK v1 공통 재질·윤곽을 사용한다. 건설 미리보기에는 허용된 투명 혼합 재질을 적용한다. 기존 자산의 형태 수준과 최종 아트 승인 여부는 렌더링 품질 문서의 `legacy`/`approved-reference` 구분을 유지한다. 이번 기능 연결을 전 시설의 고품질 재모델링 완료로 합산하지 않는다.

후속 두 Metal 창 동시 실행에서 사업 모델 일괄 생성 구간의 게스트 연결 종료를 확인했다. 사업 모델도 요청 큐로 옮겨 비동기 리소스 요청은 최대 2개, 실제 모델 생성은 프레임당 1개로 제한했다. 최신 사업 상태로 생성 대기를 갱신하고 철거/고갈된 대상의 대기를 제거한다. headless의 더미 렌더러는 생태와 같은 이유로 리소스를 동기 로드하되 모델 생성 수 제한을 유지한다. 렌더링 품질 프리셋이나 모델 LOD 기준을 낮추어 해결하지 않는다. 수정 후 호스트·게스트 모두 실제 Metal 화면인 2인 사업/연구/정산/재시작 260개 검사가 통과했고 연결 종료와 런타임 오류는 없었다. ## 검증과 남은 항목

규칙 검사는 `res://tests/test_expedition_business.gd`, 실제 ENet 게임 장면은 `python3 tools/test_business_play.py`로 실행한다. 규칙 검사에서 건설/연구/자동화/정산/재투자를 확인하며, 네트워크 검사는 실제 입력·건설 미리보기·굴착과 구별되는 광맥 채광·재접속 화물·시설/로봇·환경·정산 일치를 확인한다. 테스트의 통제된 위치 배치와 시간 가속은 사람의 실시간 플레이테스트와 구분한다. 규칙 검사 53개, 실제 ENet 6인 사업 경로 254개, 960×640 조작/레이아웃 12개가 통과했다. 확장 회귀(`tools/test_expansion.sh`)와 기존 1.2 규칙·저장·경제·음향(`tools/test_game.sh`)도 오류 없이 통과했다. 6인은 같은 Mac의 Metal 호스트 1개와 headless 클라이언트 5개이며 서로 다른 회선/컴퓨터 또는 6개 GPU 렌더 성능 결과가 아니다.
