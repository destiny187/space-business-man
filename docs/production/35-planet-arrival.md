# 행성 진입·하강·착륙 연출

2026-09-07 사용자 확정: 선택한 행성으로 우주에서 자연스럽게 진입하고, 필요한 로딩을 전환 중 처리하며, 지상으로 하강해 특정 위치에 착륙한 뒤 플레이를 시작한다. 필요한 사운드는 ElevenLabs에서 제작한다.

## 기본 원정 연결

현재 혼자/협동 공통 `crew_expedition` 경로에 연결한다. 착륙 요청이 호스트에서 승인되어 빈 착륙 상태가 실제 행성 상태로 바뀐 뒤에만 시작한다. 착륙 불가 천체·거리·승무원 준비 등의 기존 거절 규칙은 유지한다.

1. **궤도 이탈**: 현재 항성계의 실제 행성과 KESTREL을 유지하고, 우주선을 행성 방향으로 회전·접근시킨다.
2. **진입 전환**: 행성 색을 사용한 움직이는 전환막이 화면을 덮는다. 이 동안 호스트 지표 기록·굴착 반영·착륙 구역 충돌 메시 준비를 기다린다. 임의 진행률을 표시하지 않으며, 지형이 늦어지면 대기 연출을 유지한다.
3. **하강**: 지형 준비 후 실제 지표 위 약 100m에서 우주선이 기존 착륙 지점으로 내려온다. 카메라가 선체를 추적하고 마지막 접근에서 감속하며 하향 추진·지면 먼지를 표현한다.
4. **접지와 조작 인계**: 선체의 모델 하단을 착륙 지표 높이에 맞춘다. 접지음과 추진 정지 후 지상 카메라로 부드럽게 이동하고 장비·HUD·이동 조작을 복구한다.

착륙 중 개인 이동·시선·장비·스캔·메뉴 입력을 차단하고, 호스트의 캐릭터 중력·지면 정착은 진행한다. 다른 승무원 모델은 조작 인계까지 숨긴다. 지표 이어하기·이미 착륙한 세션에 처음 합류할 때는 긴 진입 연출을 반복하지 않는다. 연결 종료나 착륙 상태 해제 시 카메라·효과·음원을 정리한다.

`planet_arrival.gd`가 연출을 담당하고 길이·고도·접근 오프셋은 `data/planet_arrival.json`에서 조정한다. 기본 길이는 접근 3.8초 + 지형 준비 대기 + 하강 5.5초 + 접지 1.2초 + 조작 인계 1초다. 이 값은 사용자 확정 밸런스가 아닌 현재 제작값이다.

## 에셋과 음향

Blender 원본 `art/blender/ships/kestrel.blend`와 기존 게임 GLB를 재사용한다. 새 선체 모델을 만들었다고 기록하지 않는다. 선체·장착 모듈은 기존 INK v1을 유지하고 Godot Forward+에서 접근·하강·착륙을 렌더한다. 먼지는 행성 흙색의 별도 비발광 투명 재질이며 추진광 재질과 분리한다.

ElevenLabs 웹 Sound Effects에서 세 종류를 각각 6초/영향도 30%로 생성하고 1번 결과를 WAV 48kHz로 내려받았다.

| 음원 | 연결 | 게임용 처리 |
| --- | --- | --- |
| `sfx_atmosphere_entry` | 궤도 이탈·진입 | 시작/끝 짧은 페이드, 피크 제한 |
| `sfx_landing_thrusters` | 진입 대기·하강 | 반복 생성, 50ms 순환 크로스페이드, 하강 중 피치·음량 감속 |
| `sfx_landing_touchdown` | 실제 연출 접지·엔진 정지 | 시작/끝 짧은 페이드, 피크 제한 |

프롬프트·원본·내보내기·선택본·SHA-256·길이·음량은 [제작 매니페스트](../../audio/manifests/planet-arrival.json)에 보존한다. SFX 버스로 사용자 음량 설정을 따른다. 착륙 실패에 성공음을 미리 재생하지 않는다.

## 범위와 제약

- 기존 지정 착륙 구역으로 연결한다. 자유 착륙 지점 선택 UI, 구면 행성 지리와 지표의 일치, 궤도부터 지표까지 물리적으로 연속된 비행은 이번 구현 범위가 아니다.
- 전환막은 축약된 진입 연출이다. 무대기 천체에 실제 구름이나 공기 마찰이 관측된다는 뜻이 아니다. 환경별 음향·전환 변형은 후속이다.
- 착륙 승인·지형 기록은 호스트 상태를 사용하지만 연출 시간과 로딩 대기는 클라이언트별로 진행한다. 느린 접속자를 포함한 전원 동시 조작 해제 장벽은 추가 구현 범위다.
- 모델에 새 착륙 다리·출입문·승무원 하선 애니메이션을 추가한 것은 아니다. 현재는 기존 선체 하강과 지상 시점 인계다.
- 초기 개발 테스트 최소화 지침에 따라 이번 전환의 실제 창·소리 재생·카메라·충돌 준비·조작 복귀·저장 재개만 확인하고 전체 회귀·다중 클라이언트 실행은 반복하지 않는다.

## 최소 실행 검수 결과

Godot 4.7.2 / Metal Forward+ / Apple M2의 실제 창에서 최종 전환 다섯 단계, 충돌 준비, 게임 카메라와 이동 복귀, 저장 후 지상 재개를 확인했다. 최종 실행 로그의 엔진 오류는 0건이다. 검증은 임시 저장에서 우주선을 허용 궤도로 옮긴 후 정상 착륙 요청을 사용했으며, 모든 항해 과정을 수동으로 플레이한 것은 아니다. 전용 세 음원의 실제 연출 호출·게임 가져오기와 PCM 길이/피크를 확인했으며 주관적 청감 승인과 구분한다.
