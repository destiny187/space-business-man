# 행성 진입·하강·착륙 연출

2026-09-07 사용자 확정: 선택한 행성으로 우주에서 자연스럽게 진입하고, 필요한 로딩을 전환 중 처리하며, 지상으로 하강해 특정 위치에 착륙한 뒤 플레이를 시작한다. 필요한 사운드는 ElevenLabs에서 제작한다.

## 기본 원정 연결

현재 혼자/협동 공통 `crew_expedition` 경로에 연결한다. 착륙 요청이 호스트에서 승인되어 빈 착륙 상태가 실제 행성 상태로 바뀐 뒤에만 시작한다. 착륙 불가 천체·거리·승무원 준비 등의 기존 거절 규칙은 유지한다.

1. **궤도 이탈**: 현재 항성계의 실제 행성과 KESTREL을 유지하고, 우주선을 행성 방향으로 회전·접근시킨다.
2. **진입 전환**: 행성 색을 사용한 움직이는 전환막이 화면을 덮는다. 이 동안 호스트 지표 기록·굴착 반영·착륙 구역 충돌 메시 준비를 기다린다. 임의 진행률을 표시하지 않으며, 지형이 늦어지면 대기 연출을 유지한다.
3. **하강**: 지형 준비 후 실제 지표 위 약 100m에서 우주선이 기존 착륙 지점으로 내려온다. 카메라가 선체를 추적하고 마지막 접근에서 감속하며 하향 추진·지면 먼지를 표현한다.
4. **접지와 조작 인계**: 선체의 모델 하단을 착륙 지표 높이에 맞춘다. 접지음과 추진 정지 후 지상 카메라로 부드럽게 이동하고 장비·HUD·이동 조작을 복구한다.

착륙 중 개인 이동·시선·장비·스캔·메뉴 입력을 차단하고, 호스트의 캐릭터 중력·지면 정착은 진행한다. 다른 승무원 모델은 조작 인계까지 숨긴다. 지표 이어하기·이미 착륙한 세션에 처음 합류할 때는 긴 진입 연출을 반복하지 않는다. 연결 종료나 착륙 상태 해제 시 카메라·효과·음원을 정리한다.

`planet_arrival.gd`가 연출을 담당하고 길이·고도·접근 오프셋은 `data/planet_arrival.json`에서 조정한다. 기본 길이는 접근 3.8초 + 지형 준비 대기 + 하강 5.5초 + 접지 1.2초 + 조작 인계 1초다. 이 값은 사용자 확정 밸런스가 아닌 현재 제작값이다.

## 에셋과 음향

Blender 원본 `art/blender/ships/kestrel.blend`와 기존 게임 GLB를 재사용한다. 새 선체 모델을 만들었다고 기록하지 않는다. 선체·장착 모듈은 기존 INK v1을 유지하고 Godot Forward+에서 접근·하강·착륙을 렌더한다. 먼지는 행성 흙색의 별도 비발광 투명 재질이며 추진광 재질과 분리한다.

ElevenLabs 웹 Sound Effects에서 세 종류를 각각 6초/영향도 30%로 생성하고 1번 결과를 WAV 48kHz로 내려받았다.

| 음원 | 연결 | 게임용 처리 |
| --- | --- | --- |
| `sfx_atmosphere_entry` | 궤도 이탈·진입 | 시작/끝 짧은 페이드, 피크 제한 |
| `sfx_landing_thrusters` | 진입 대기·하강 | 반복 생성, 50ms 순환 크로스페이드, 하강 중 피치·음량 감속 |
| `sfx_landing_touchdown` | 실제 연출 접지·엔진 정지 | 시작/끝 짧은 페이드, 피크 제한 |

프롬프트·원본·내보내기·선택본·SHA-256·길이·음량은 [제작 매니페스트](../../audio/manifests/planet-arrival.json)에 보존한다. SFX 버스로 사용자 음량 설정을 따른다. 착륙 실패에 성공음을 미리 재생하지 않는다.

## 범위와 제약

- 기존 지정 착륙 구역으로 연결한다. 자유 착륙 지점 선택 UI, 구면 행성 지리와 지표의 일치, 궤도부터 지표까지 물리적으로 연속된 비행은 이번 구현 범위가 아니다.
- 전환막은 축약된 진입 연출이다. 무대기 천체에 실제 구름이나 공기 마찰이 관측된다는 뜻이 아니다. 환경별 음향·전환 변형은 후속이다.
- 착륙 승인·지형 기록은 호스트 상태를 사용하지만 연출 시간과 로딩 대기는 클라이언트별로 진행한다. 느린 접속자를 포함한 전원 동시 조작 해제 장벽은 추가 구현 범위다.
- 모델에 새 착륙 다리·출입문·승무원 하선 애니메이션을 추가한 것은 아니다. 현재는 기존 선체 하강과 지상 시점 인계다.
- 초기 개발 테스트 최소화 지침에 따라 이번 전환의 실제 창·소리 재생·카메라·충돌 준비·조작 복귀·저장 재개만 확인하고 전체 회귀·다중 클라이언트 실행은 반복하지 않는다.

## 최소 실행 검수 결과

Godot 4.7.2 / Metal Forward+ / Apple M2의 실제 창에서 최종 전환 다섯 단계, 충돌 준비, 게임 카메라와 이동 복귀, 저장 후 지상 재개를 확인했다. 최종 실행 로그의 엔진 오류는 0건이다. 검증은 임시 저장에서 우주선을 허용 궤도로 옮긴 후 정상 착륙 요청을 사용했으며, 모든 항해 과정을 수동으로 플레이한 것은 아니다. 전용 세 음원의 실제 연출 호출·게임 가져오기와 PCM 길이/피크를 확인했으며 주관적 청감 승인과 구분한다.

## 2026-09-07 — 화면 준비 완료 후 하강

후속 사용자 확정: 하강 중 지형과 모델이 늦게 나타나 화면이 깨져 보이지 않도록, 실제 렌더 준비가 끝난 뒤 내려온다. 앞선 플레이어/선체 발밑 두 지점 검사만으로는 주변 청크와 비동기 모델 생성을 기다리지 못했다.

- 플레이어 주변 활성 지형 청크 전체의 최신 메시·충돌과 굴착 반영, 원경 작업 완료를 기다린다. 시야거리 전역을 충돌 청크로 생성하는 것은 아니다.
- 하강 경로의 카메라가 참조할 광맥 구역을 미리 요청하고 연출 동안 유지한다. 지형 준비 후 생물 후보를 다시 확인하며, 광맥 모델 요청/생성·생물 요청/생성·활성 지면의 자연물 타일 완료를 기다린다.
- 카메라·선체·효과를 불투명 전환막 뒤에서 구성한다. 준비 후 하강 시작/접지/플레이어 시점으로 실제 프레임을 그린 뒤 시작 시점으로 복귀한다. `warming` 단계의 기본값은 `planet_arrival.json`에 8프레임 이상·최소 0.5초로 둔다. 이 동안 새 생성 작업이 생기면 로딩 단계로 돌아간다.
- 준비 지연은 전환막 안에서 대기하며 시간 초과로 미완성 지표를 노출하지 않는다. 하강 시작 시 선체를 준비된 시작 위치에서 이동하고 기존 추진음·먼지·접지·조작 인계를 유지한다. 종료/취소 시 모델 사전 요청 범위를 해제한다.

`check_planet_arrival.gd`에 4096m 시야거리, 모델 요청을 의도적으로 보류했을 때 불투명 로딩 유지, 하강 직전의 모든 준비 조건·실제 렌더 프레임, 완료 후 사전 요청 해제 검사를 추가했다. 기존 착륙·이동 복귀·저장 재개까지 같은 실제 창에서 확인한다. 로그는 로컬 `test-results/landing-ready/run.log`에 둔다. 전체 회귀·다중 클라이언트·장시간 성능 검사는 수행하지 않는다.

최종 실제 창 검사 통과: `ARRIVAL MODEL WAIT PASS`, `ARRIVAL RENDER BARRIER PASS`, 착륙/카메라/이동 복귀 및 저장 재개 PASS. 엔진 스크립트 오류 없이 종료했다. 테스트 폴더 재사용으로 이미 착륙한 상태를 다시 착륙시키던 검사 준비 오류는 고정 시드의 새 테스트 세계를 명시적으로 작성하도록 수정했다. 실제 4096m 하강 캡처에서 원경과 지표 모델이 준비된 상태를 확인했다.

## 2026-09-07 — 선체가 대기층을 뚫고 내려오는 연결

후속 사용자 확정: 진입/하강 도중 비행체가 사라지지 않고, 대기층을 통과해 지상으로 내려오는 느낌을 유지한다. 불투명 전환막이 선체까지 가리던 구간을 분리했다.

- 전환막 앞의 투명 3D 뷰포트에서 기존 Blender KESTREL과 실제 장착 모듈·추진 효과를 INK v1으로 렌더한다. 정지 이미지로 대체하지 않는다. 공통 윤곽 셰이더에 투명 배경 옵션을 추가했으며 기존 장면은 기본값을 유지한다.
- 궤도 시점의 선체 투영을 이어받고, 대기층 안에서 하강 시점으로 부드럽게 회전/접근한다. 얇은 기류와 선수 주변의 흐름 효과를 더한다. 준비되지 않은 지표는 계속 불투명 대기층 뒤에 가려진다.
- 지표 준비와 실제 사전 렌더 조건은 유지한다. 구름이 걷힐 때 같은 선체/카메라 상대 좌표로 지상 모델을 표시하고, 전환용 선체를 정리한다. 완료/취소 때 원본 선체 표시와 카메라 상태를 복구한다.
- 기존 진입음·반복 추진음·접지음과 Blender 원본/내보내기를 재사용했다. 새로운 선체 모델·음원 제작 및 구면 궤도부터 지표까지의 물리 연속 비행은 이번 범위가 아니다.

실제 Metal Forward+ 창에서 모델 로딩 지연 중 전환막 앞 선체 유지, 하강 시작 시 선체 존재, 원본 선체 복구와 기존 로딩 장벽·착륙·조작·저장 재개를 확인했다. `test-results/arrival-vessel/run.log`의 검사 통과와 실제 `test-results/planet-arrival/atmosphere-vessel.png`, `descent.png`를 확인했다. 전체 회귀·다중 클라이언트 검사는 수행하지 않았다.

### 선체 앞 구름의 부분 가림 보강

후속 사용자 요청에 따라 선체 앞 기류층에 이동하는 두 크기의 구름 무늬를 추가했다. 선체 중심을 비우는 마스크를 구름에는 적용하지 않아 한쪽 엔진·동체를 부분적으로 가렸다가 드러낸다. 행성의 대기 전환 색을 따르고, 전경 합성 불투명도는 최대 0.65로 제한한다. 기존 대기층 이탈 강도에 함께 연결되어 하강하면서 걷힌다.

`render_arrival_foreground.gd`로 기존 INK 선체와 게임용 전경 셰이더를 Metal Forward+에서 0.0/0.8/1.6초의 세 위상으로 렌더했다. `test-results/arrival-foreground/`의 실제 출력에서 맑은 상태와 선체 일부가 구름에 가려진 상태를 확인했다. 새 음원·모델은 없으며 이번에는 착륙 전체 회귀를 반복하지 않았다.
