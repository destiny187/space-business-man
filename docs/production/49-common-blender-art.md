# Blender 공통 제작 규격과 그래픽 통일

## 방향과 점검 결과 — 2026-09-08

사용자는 게임이 **검은 선이 분명한 카툰 렌더링**임을 재확인하고, 로버와 기존 자산이 따로 보이는 문제를 지적했다. 기존 [INK v1](06-rendering-quality-standard.md)과 [Blender 제작 문서](01-art-and-blender.md)를 유지하면서 실제 제작 설정을 공통화한다. 새로운 스타일을 선택하는 문서가 아니다.

**높은 형태 완성도, 굵은 검은 외곽선, 3단 명암을 함께 유지한다.** 로버의 구조를 단순화해서 구형 모델에 맞추지 않는다. 승인 M-07·정제소와 SCOUT의 곡면·기구·역할 표현을 후속 제작의 기준으로 삼고 구형 자산을 순차 교체한다. 자연물까지 차량과 같은 형태나 제조업 팔레트로 바꾸지는 않는다.

현재 상태를 ‘전 그래픽 통일 완료’라고 표현할 수는 없다. 점검에서 다음 차이를 확인했다.

| 차이 | 확인한 증거 | 이번 조치 |
| --- | --- | --- |
| 제작자별 팔레트 | 정제소·구형 창고·로버의 크림/청록/프레임 RGB가 서로 다름 | 산업 재질 역할별 단일 데이터와 Blender/Godot 공통 연결 |
| 이름에 의존한 재질 추정 | `Soft graphite tyre`까지 graphite 거칠기 0.52를 적용 | 고무 역할은 거칠기 0.9, 작은 하이라이트 강도 0.1로 분리 |
| 베벨·법선 차이 | 승인 예제는 매끄러운 베벨, 로버 박스는 평면 법선과 3분할 베벨 | 로버에 공통 가중 법선·화면 크기에 맞는 3~4분할 베벨 적용 |
| 구형 형태 | 구형 창고는 상자·덮개·얇은 판 3개, 구형 로봇은 각진 바퀴 | 창고를 대표 교체. 구형 로봇 등의 형태 교체는 미완료 유지 |
| 촬영 조건 | 로버는 어두운 배경·별도 조명, 기존 카탈로그는 밝은 중립 스튜디오 | 같은 카탈로그 렌더와 혼합 장면에서 비교 |
| 부품별 출력 비용 | SCOUT의 부품 226개가 각각 메시로 출력 | 가동 부모와 재질별 정적 표면 병합. 원본은 개별 부품 유지 |

## 단일 설정과 사용법

- 산업 재질 원본: [`ink_materials.json`](../../우주-비즈니스/data/ink_materials.json).
- Blender 공통 함수: [`tools/ink_blender.py`](../../tools/ink_blender.py).
- 게임 재질 변환: [`FrontierInkStyle`](../../우주-비즈니스/scripts/actors/ink_style.gd).
- 선 굵기와 명암: 기존 `render_style.json`, `cel_light.gdshaderinc`, `contour.gdshader`를 유지한다. 이번 작업에서 선 굵기와 3단 명암 수식은 변경하지 않았다.

색 데이터는 **linear sRGB**다. Blender Principled와 GLB에는 그대로 쓰고, Godot의 `source_color` 입력에는 sRGB로 변환한다. 화면에서 뽑은 sRGB 숫자를 Blender의 선형 RGB에 그대로 넣지 않는다.

| 재질 역할 | 쓰는 곳 | 표현 |
| --- | --- | --- |
| `enamel_cream` | 큰 외장·지붕·보호 커버 | 승인 정제소 기준의 따뜻한 크림색, 절제된 반사 |
| `enamel_teal` | 장비 면·화물함·작업 패널 | 짙은 청록, 큰 면으로 역할 구분 |
| `safety_orange` | 손잡이·잠금장치·견인/주의 지점 | 소수의 주황 포인트. 전체를 빛내지 않음 |
| `structural_dark` | 하부 프레임·씰·부품 사이 틈 | 짙은 구조색. 실제 화면 윤곽선과 별개 |
| `edge_steel` | 축·경첩·마찰면·레일 | 작고 분명한 금속 하이라이트 |
| `rubber` | 타이어·완충재 | 낮은 광택. 철제 프레임과 구분 |

기존 산업 재질 이름은 데이터의 **정확한 이름 목록**만 호환한다. 임의의 `dark`, `green` 같은 부분 문자열로 자연물까지 재색칠하지 않는다. 발광 상태 표시, 정점색, 반투명 유리·고스트, 등록하지 않은 자연/제조사 재질은 원래 색을 유지한다. 신규 산업 재질 이름은 `INK::역할`로 통일한다. 새 역할이 필요한 경우 데이터에 등록하고 혼합 장면에서 확인한다.

```python
# Blender 생성기: 프로젝트 tools 경로를 sys.path에 추가한 뒤 사용
import ink_blender as ink
cream = ink.material('enamel_cream')
# 스케일을 먼저 적용하고 모서리 폭은 미터로 지정
ink.manufactured_edges(mesh_object, width=0.04, segments=4)
# 편집 가능한 원본을 저장한 다음, GLB 출력 직전에만 병합
bpy.ops.wm.save_as_mainfile(filepath=source_path)
ink.consolidate_static_surfaces()
```

현재 이 함수로 재생성한 모델은 **SCOUT와 창고**다. 기존 산업 모델은 이름 호환을 통해 게임에서 공통 팔레트를 받지만, 모든 예전 생성기가 새 함수로 전환된 것은 아니다. 구형 `build_assets.py`는 새 창고를 덮어쓰지 않으며 전용 생성기를 안내한다.

## 형태를 맞추는 제작 기준

수치는 제작 시작점이며 화면에서 읽히는지가 최종 판단 기준이다. 세부 볼트 개수를 맞추거나 서로 다른 물체의 폴리곤 수를 같게 만드는 규격이 아니다.

1. **큰 형태:** 멀리서도 역할을 구별한다. 차량은 실내·바퀴·화물부, 로봇은 센서·몸체·작업 도구, 시설은 주 장치·접근/정비 면·기초 구조를 먼저 만든다.
2. **중간 구조:** 하중을 받는 프레임, 보호 패널, 연결부, 문, 통풍구, 호스와 손잡이를 용도에 맞게 배치한다. 박스 위에 장식 선만 덧붙여 완료하지 않는다.
3. **작은 디테일:** 조작 지점과 주요 연결부 주변에만 둔다. 일반 플레이 거리에서 보이지 않는 볼트·양각 문자·촘촘한 홈은 줄인다. 넓고 조용한 색면을 남긴다.
4. **곡면과 모서리:** 장비 외장은 작은 라운드와 평평한 큰 면을 함께 쓴다. 3~4분할 베벨·가중 법선을 기본으로 하고 바퀴는 32~48분할부터 판단한다. 광물·파손면의 각진 실루엣은 의도대로 보존한다.
5. **색과 상태:** 크림 또는 청록이 큰 면, 구조색은 하부와 틈, 주황은 손이 닿는 지점과 주의 표식에 사용한다. 자원·상태 구분은 고유 실루엣과 보조 표시를 함께 유지한다.
6. **가동부:** 문·바퀴·피스톤이 왜 움직이는지 구조로 설명한다. 시각 교체 시 기존 `Anim_`, `Socket_`, 충돌 외곽과 원점을 보존한다. 새 기구를 만들었다는 이유로 연결하지 않은 모션을 구현 완료라고 쓰지 않는다.

SCOUT는 Blender +Y / Godot -Z 전방이다. 구형 시설은 Blender -Y / Godot +Z를 사용하는 경우가 있다. 기존 게임 자산을 교체할 때 임의로 축을 통일하여 게임 방향을 뒤집지 않는다. 매니페스트와 배치 코드의 계약을 따른다.

## 출력과 검수

`.blend`에는 개별 편집 부품을 보존한다. GLB에서는 **같은 부모 아래, 같은 불투명 재질을 쓰는 정적 표면만** 묶는다. `Anim_`/`Socket_` 노드, 자식이 있는 메시, 애니메이션·셰이프키, 투명 창은 병합 대상에서 제외한다. 묶은 메시의 회전/스케일은 메시 데이터에 적용하여 도감 바운딩 박스가 부풀지 않게 한다. 가동 부모의 변환은 그대로 둔다.

Blender 렌더는 형상·조립·법선을 확인하는 보조 자료다. **매끈한 Cycles 결과만으로 게임 카툰 품질을 승인하지 않는다.** Godot Forward+에서 실제 INK 선·명암·그림자·투명 유리까지 확인한다.

| 확인 장면 | 보는 것 |
| --- | --- |
| 같은 카탈로그 조명의 단독 비교 | 팔레트, 베벨, 실루엣, 내부 선 밀도 |
| 로버·시설·로봇·광물·풀 혼합 | 같은 세계의 물체로 읽히는지, 역할/색의 충돌 |
| 주광·약광·역광 | 검은 실루엣 유지, 어두운 구조가 뭉개지는지 |
| 근접 기구·조종석과 일반 거리 | 문/바퀴 분리, 유리와 실내, 디테일 가독성 |
| 현재 플레이 경로 | 실제 조작·상태 모션·사운드·고스트·미리보기 연결 |

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/build_scout_rover.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/build_locus_storage.py
./tools/godot.sh --headless --editor --import --quit
./tools/render_ink_family.sh
./tools/godot.sh --script res://tests/render_scout_rover.gd
```

초기 개발 테스트 최소화 지침을 따른다. 위 명령 전체나 전수 카탈로그·전체 회귀를 매번 반복하지 않는다. 바뀐 자산과 발견한 문제에 필요한 확인만 수행한다.

## 이번 적용과 남은 작업

- SCOUT: 공통 산업 재질, 고무 반사 분리, 베벨 법선 정리, 가동 그룹별 출력 병합. 원본·GLB·도감·기구/실내 렌더 갱신.
- 창고: 기존 3.6m 정사각 기초와 전방을 유지하면서 베이 3개, 씰·경첩·주황 손잡이, 측면 정비판, 적재 레일을 재제작. 기존 `storage` ID와 게임 미리보기에 반영. 도어 개폐 동작을 추가한 것은 아니다.
- 기존 산업 자산: 등록한 공통 재질 이름의 팔레트·반사 통일. 구형 형태를 새 모델로 간주하지 않는다.
- 검수 도구: 전후 단독 비교판과 실제 INK 혼합 장면, Blender 원본 확인용 렌더를 보존.

형태 교체의 다음 우선순위는 **자주 마주치는 채광 로봇 → 대기·열·물·생태 시설 → 제작소·충전기·기지 → 기타 배경/발견물**이다. 로봇은 실제 드릴 방향·관절 동작, 시설은 기존 가동 부품을 유지하며 교체한다. 이미 승인 형태를 활용한 다른 자산은 개별 점검 후 중복 제작을 피한다. 생물 수백 종은 형태·동작·군집 거리의 별도 검토가 필요하며 이번 공통 산업 재질 적용만으로 완료하지 않는다.

형태 상태의 원본은 `render_assets.json`이다. 이번에는 창고만 `legacy`에서 `ink-family-remodeled`로 변경했다. `visual-prototype`, `gameplay-prototype`, 남은 `legacy`는 후속 형태 검토 대상이며 개수 자체가 품질 완료율을 의미하지 않는다.

## 실제 확인 기록

2026-09-08 Blender 5.2.1 LTS와 Godot 4.7.2 / Metal Forward+ / Apple M2에서 SCOUT·창고를 렌더링했다. 단독 전후 비교와 혼합 주광·약광·역광, 로버 전후면·가동부·실내를 확인했다. 재질 수정은 고무와 가져온 GLB 역할 연결, 색 공간, 발광/정점색/투명 보존에 한정한 검사를 통과했다.

[혼합 주광](media/ink-family/mixed-day.png) · [약광](media/ink-family/mixed-shade.png) · [역광](media/ink-family/mixed-backlight.png) · [Blender 창고](media/ink-family/storage-blender.png) · [출력 비용·피벗 기록](media/ink-family/verification.json)

혼합 장면은 게임 모델과 공통 렌더러를 쓰는 **품질 검토용 장면**이다. 실제 캠페인의 성능 측정이나 낮밤 구현을 의미하지 않는다. 사운드 파일과 이벤트는 바꾸지 않았다. 이번 아트 변경 뒤 전체 착륙→채집→건설 흐름, 장시간 주행·멀티·원거리 LOD를 다시 검증한 것은 아니다. 그 범위의 기존 확인과 한계는 [C13~C15 기록](48-rover-and-transport.md)을 유지한다.

SCOUT의 가동/좌석 연결점 25개는 내보내기 전후 월드 변환이 동일했다. 메시 수는 226→45, 삼각형은 55,480→58,504로 바뀌었다. 곡면 보강으로 삼각형은 소폭 늘고 정적 표면 병합으로 메시 제출 수가 줄었다. 창고는 62개 편집 부품을 5개 메시·19,944개 삼각형으로 출력한다. 이는 자산 비용 기록이며 게임 FPS 개선 실측이 아니다.
