# 전투함 편대·곡선 유도 미사일·성간 탈출

2026-09-12 사용자 요청과 후속 정정. 규칙의 단일 소관은 [해적 전투](../game/28-pirate-interdiction.md)다. 교란선 중심 구도를 전투함 편대로 바꾸고, 기존 직선 연사와 별도의 고위력 유도 미사일을 연결한다. 사용자 최종 요청에 따라 왼쪽 상태 아이콘은 지상과 동일하게 사용하고 두 무장은 오른쪽에 둔다.

## 발견과 변경

기존 무장은 즉발 펄스포와 이동하는 적 에너지탄이었다. 실제 미사일 자산·발사·명중 폭발은 없었고 큰 폭발은 선체 격파 때만 재생했다. 기존 종료도 전체 적 격파 외에 교란 범위 이탈/시간 상한이어서, 추격 중 다른 항성계로 직접 출발하는 흐름을 지원하지 않았다.

- 원정선은 펄스포를 유지하며 좌우 개폐식 발사대를 추가한다. 우클릭은 조준 중심의 적 하나를 지정하고 두 발을 바깥/위로 사출한 뒤 제한된 각속도로 휘어 들어간다. 발사 후 조준점을 옮겨도 처음 지정한 적을 유지한다.
- 발사체는 호스트가 실제 위치·속도·시간·표적 ID를 보관한다. 충돌 때만 피해를 주고, 장애물에 막히거나 수명이 다하면 해당 위치에서 폭발한다. 표적이 먼저 파괴된 남은 탄은 마지막 방향으로 비행하며, 승리 이후에도 수명 종료까지 표시한다. 로컬 연출로 피해를 확정하지 않는다.
- 발사대 개폐·실물 미사일·추진 꼬리·개별 명중 섬광/분출·실드 파문·선체 격파 폭발을 구분했다. 펄스의 장갑 타격도 기존 작은 구체 대신 짧은 별 모양 섬광과 분출로 보강했다.
- 새 편성은 추격 전투함 2척과 미사일함 1척이다. 미사일함도 실전 공격을 하고, 그 함선 하나를 부숴도 남은 추격기가 계속 공격한다. 적 미사일함은 충전 중 정한 사선에 직진탄을 발사한다.
- 가속으로 추격 거리를 확보하면 원정선의 성간 출발 창을 연다. 같은 항성계 접근/착륙으로 교전을 취소할 수 없으며, 다른 항성계 출발의 저장이 성공할 때 탈출을 확정한다. 항속/항해 내성·승무원 준비·FINCH 회수 조건은 기존 항해 검사를 유지한다. 부스트는 점프 에너지를 남긴다.
- 원정선이 가만히 버티는 시간만으로 탈출을 주지 않는다. FINCH는 비무장·성간 이동 불가를 유지하고 실제 거리 확보로 현지 추격을 끝낸다.

## 모델·효과·음원

`tools/build_pirate_missiles.py`가 공통 `ink_blender.py` 경로와 기존 선박 제작 함수를 사용한다. `pirate_gunship`과 LOD, `expedition_missile_mount`, `ship_missile`의 편집용 `.blend`와 게임 GLB를 분리 저장했다. 좌우 `Anim_LaunchDoor_`·`Socket_Missile_`, 엔진 노즐·익면·보조 함포 연결점을 유지한다. 기존 교란선은 저장 호환용 자산으로 보존하며 신규 편성에서 제외한다.

[Blender 미사일함](media/pirate-missiles/pirate_gunship-blender.png), [INK 미사일함](media/pirate-missiles/pirate_gunship-ink.png), [Blender 미사일](media/pirate-missiles/ship_missile-blender.png), [INK 미사일](media/pirate-missiles/ship_missile-ink.png), [발사대](media/pirate-missiles/expedition_missile_mount-ink.png).

미사일 폭발은 기존 카툰 폭발 셰이더의 섬광·비대칭 분출·잔광을 작은 규모로 조합한다. 실드 피해와 미사일 폭발은 함께 보이되 함선 파괴로 오인하지 않도록 크기와 파편을 구분한다. 효과는 기존 180개, 호스트 발사체는 24개 상한을 유지한다.

음원은 ElevenLabs에서 이미 생성한 추진 발동/플라스마 원본을 짧게 편집해 별도 `sfx_ship_missile_launch`, `sfx_ship_missile_blast`로 연결했다. 새 합성 음원을 생성한 것은 아니다. 원본 출처·시작점·길이·페이드·해시는 [매니페스트](../../audio/manifests/pirate-missiles-reuse.json), 재현은 `tools/prepare_pirate_missile_audio.py`를 따른다. 카툰 조우 경고음은 143번 기록의 전용 음원을 유지한다.

## HUD

왼쪽 상태 세 줄은 지상과 같은 `shield.svg`, `health.svg`, `stamina.svg`를 재사용하고 `FrontierStatusMeter`의 20px 청록 아이콘·우측 수치·192px 게이지 규격을 그대로 사용한다. 여기서 값은 해당 선박의 실드·선체·추진 에너지다. 별도 선박 상태 아이콘을 만들지 않는다.

함포와 미사일은 오른쪽 아래의 두 무장 게이지에 둔다. 함포는 LMB와 열, 미사일은 RMB와 두 발/재사용 대기를 표시한다. 별도 설명 문장 없이 표적 고리·이탈 게이지와 성간 출발 표식을 사용하고, 출발 가능 전환은 원정선 항법의 짧은 교신으로 보인다. 메뉴는 무장 입력·진행 중 효과·소리를 막는다.

## 최소 확인과 한계

- `check_pirate_missiles.gd`: **26개, 실패 0**. 두 발의 외향 발사·곡선 추적·실제 충돌 피해·무표적 발사 제한·재사용 대기·표적 파괴 후 잔여 탄·저장 검증, 특정 미사일함만 파괴했을 때 전투 지속, 정지 대기로 자동 탈출하지 않음, 실제 부스트 입력과 재추격, 출발 저장 실패/성공을 확인했다. 대표 시드의 규칙 실행에서 출발 창 확보는 5.1초였으며 사람의 평균 플레이 시간은 아니다.
- 기존 `check_pirate_rules.gd`는 새 편성과 종료 규칙에 맞춰 확인 대상을 갱신했고 **43개, 실패 0**. 이전 저장 비활성 보존·두 이동 구간·인양/복구·FINCH·중복 요청과 저장 실패를 확인했다. 전체 게임 회귀는 실행하지 않았다.
- Blender 원본 렌더와 Godot Forward+ / Metal의 세 자산 INK 렌더를 확인했다.
- `render_pirate_missiles.gd`: **12개, 실패 0**. 실제 `crew_expedition.tscn`에서 호스트 입력으로 발사, 명중 폭발과 음원, 추격 편대, 상태/무장 배치, 부스트 이동, 기존 항해 UI의 성간 출발 및 메뉴 정지를 확인했다. 최종 지상 공통 아이콘을 적용한 [960px 교전 화면](media/pirate-missiles/combat-960.png), [발사 궤적](media/pirate-missiles/missile-trail.png), [명중 분출](media/pirate-missiles/missile-impact-plume.png), [출발 창](media/pirate-missiles/breakout-ready-960.png), [실제 성간 탈출](media/pirate-missiles/stellar-escape-960.png)을 보관한다.

첫 발사는 경고 중 정지한 표적의 곡선 발사·명중을 확인하며 이후에는 실제 AI가 움직인다. [검수 영상](media/pirate-missiles/flight-combat.mp4)은 고정 60 FPS 오프라인 캡처이며 실시간 성능 측정이 아니다. 직접 마우스 조준 감각의 장시간 평가, 여섯 원격 클라이언트, 모든 지형/선체의 회피·성능과 최종 청감 평가는 이번 확인에 포함하지 않는다.

## 기존 저장과 범위

전투 기록이 없는 세계는 계속 비활성이다. 기존 전투 저장의 교란선 ID·선체/실드/전리품은 보존한다. 새 미사일 상태는 선택 필드로 읽으며 기존 3/4/6개 비행 입력과 새 7개 입력을 수용한다. 콘텐츠 해시에는 원래 포함된 `space_combat.json` 변경이 반영된다. 종료 조건은 최신 규칙으로 적용한다.

원정선/FINCH 화물 보존과 긴급 복구는 유지한다. 독립 포탑·전투정 출격·다중 표적 분배·플레어/요격·대기권 전투는 이번 범위에 포함하지 않는다.

2026-09-12 후속 [성능 조사와 최적화](146-pirate-performance.md): 현재 전투의 불변 데이터·충돌·효과 자원·주기 저장 비용을 줄였다. 실제 프레임과 미해결 지연은 별도 기록을 따른다.
