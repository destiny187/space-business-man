## 제작소와 재료의 실제 구분

로봇은 Mk.2 이상의 제작소와 현장 창고에 있는 가공 부품을 사용한다. 개인 배낭 재료만으로 로봇 생산이 되지 않는 것은 별도 재고 규칙이다. 로봇 화면에서 현장 보유/필요 수량을 아이콘으로 보여 주고 부족하면 배낭 재료를 창고로 옮기도록 안내한다.

새 제작소 해금은 자동 조립 설비 연구 600 Cr + 철 20 + 구리 10, 건설은 기초 원료 철 40 + 구리 15 + 돌 20이다. 최초 제작소를 가공 부품으로 요구하는 순환 잠금은 없다. 발전·충전·대기·열·수질·생태 설비의 Mk.2 개조 연구는 각각 400 Cr + 정제 철 2 + 정제 구리 2다. 개조에 실제 필요한 부품은 별도로 소비한다. 기초 복원 시설 자체는 계속 바로 건설하며, 전문 설계도 획득 콘텐츠와 다른 세계 연구 계승을 새로 구현한 것은 아니다. 값은 `data/facility_research.json`에서 관리한다.

새로 직접 지은 Mk.2 제작소에는 `research_built`를 저장한다. 철거 시 내지 않은 과거 Mk.1→Mk.2 개조 재료를 환급하지 않는다. 기존 시설 환급은 유지한다. 기본 카탈로그 파일과 기존 규칙 해시는 바꾸지 않는다.

FINCH 소유·화물과 출동 중 상태는 보존한다. 이전 저장의 격납 상태는 다음 진입부터 지면에 자동 나열하지 않는다. 이번 호출 대상은 소유 FINCH/공용 FINCH이며 새 비행체를 추가한 것은 아니다.

## 채광 원인과 측정

동일한 기존 지상 저장을 복사하고 같은 시작 광맥에서 여섯 번 채광한 헤드리스 진단이다. M2, Godot 4.7.2, 사용자 저장과 분리된 파일을 사용했다.

| 측정 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 요청을 호출한 스레드의 처리 시간 | 평균 99.42ms, 범위 66.47~146.83ms | 평균 13.07ms, 범위 11.77~13.98ms |
| 수정 후 저장 확인까지 전체 시간 | 직접 비교하지 않음 | 약 20~30ms, 대기 중 화면 진행 가능 |

시작 광맥 ID 조회가 전체 주변 광물/동굴을 만들고 저장 검증에서 다시 반복됐다. 여기에 JSON 직렬화·본 저장·백업 교체가 메인 스레드를 막았다. 직접 조회와 순서 보장 저장 큐로 분리했다. 미확정 채광 중 같은 요청은 새 작업을 만들지 않고, 완료한 요청은 기존 영수증을 반환한다. 다른 거래·종료는 선행 저장을 완료한 뒤 처리한다. 움직임은 보존하고 실패 시 채광 결과를 공개하지 않은 채 세계를 정지한다.

실제 Forward+ 1,280×800 지상 창에서 채광하며 180프레임을 수집한 수정 후 값은 평균 30.87ms, 95백분위 64.37ms, 최대 86.56ms였다. 이 화면의 동일 조건 수정 전 프레임 기록은 없으므로 FPS 배율 개선이나 안정적 60 FPS 달성으로 해석하지 않는다. 원인 진단의 여섯 요청 시간과 전체 렌더 시간은 다른 측정이다. 요청의 상태 복사·도메인 검증 비용은 여전히 남는다. GPU 전용 프로파일·원격 다중 접속·장시간 검증은 이번 범위가 아니다.

## 지역지도의 경계

현재 지상 좌표는 X/Z 각각 ±8,192m, 약 16.4km 폭의 지역 범위다. 지도는 이 지역의 실제 높이와 지질 분포를 요약하며 구형 행성 전체 지표를 새로 생성한 것이 아니다. 광물 산지는 정확한 광석 좌표·남은 매장량·탐사 완료 보장이 아닌 지질 분포다. 기존 광물 위치·고갈량과 세계 경계는 바꾸지 않았다.

검사 중 임시 화면 검사 코드의 메뉴 메서드/컨트롤 속성 가정, 광맥에 가리는 배치 조준을 수정했다. 실제 발견된 호출 후 모델 미갱신은 지형 패킷이 변하지 않아도 승무원 스냅샷으로 모델을 갱신하도록 고쳤다. 재고/영수증 저장 비교는 축약 JSON의 부동소수점 오차를 제외하고 원래 전체 정밀도로 확인했다. 최종 지도·저장 재진입 확인은 [4개 실패 0](media/play-polish/map-verification.txt)이며 종료 때 ObjectDB 인스턴스 한 개 경고가 남았다. 지상 실제 동작의 스크립트 오류와 이 종료 경고는 구분한다. 주 실행 스크립트 파싱과 `git diff --check`를 확인했다. 결과를 통합 전체 회귀 통과로 확대하지 않는다.

새로운 Blender 자산·ElevenLabs 음원 제작은 없으며 기존 시설/FINCH·장비와 저장 성공에 연결된 효과음을 재사용한다. 소리 호출/재생 경로를 확인했고 신규 녹음·별도 청감 평가는 하지 않았다. 전체 자산 재검수·6인 협동·Windows 실기·모든 시드의 호출 장소와 별 표시 검수는 수행하지 않았다. 저장된 기존 원정 위치·활동 중 소형선과 기존 시설을 강제로 새 원정 상태로 바꾸지 않는다.
