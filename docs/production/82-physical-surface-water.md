# 굴착과 연결되는 물의 흐름·동굴 침수

후속: [완전 침수 시설 사용 중단](85-submerged-facility-lockout.md)을 추가했다. 아래 시설 피해 미구현 설명과 구분하며 부식·영구 파손은 여전히 추가하지 않았다.

2026-09-09 사용자는 바다·하천이 표시만 되는 기존 상태를 확인한 뒤 물리적인 물 처리를 구현하도록 요청했다. [앞선 시각적 물길](79-surface-scenery-and-hydrology.md)에 다음 계층을 추가한다. 기존 Blender 자산과 동시에 진행 중인 성능 변경은 유지한다.

## 구현 범위

- 호스트의 `FrontierSurfaceWater`가 행성별 1m 셀의 물 양과 바닥을 관리한다. 굴착 후 원래 높이 대신 **편집된 지형 밀도와 셀 사이 통로**를 확인한다. 막힌 인접 동굴에는 물을 생성하지 않고, 열린 곳으로 아래·옆 방향 흐름과 수위 상승을 계산한다.
- 수압은 작은 압축량을 사용하는 게임용 근사다. 통로로 연결된 낮은 공간이 찬 뒤 위쪽으로도 물이 전달된다. 셀 간 이동은 양을 보존한다. 바다와 지표 물길은 수원으로 취급하며 공급·흡수는 별도로 집계한다. 행성 전체 해양의 유한한 총량을 계산하지 않는다.
- 굴착 주변의 원래 바닷물, 시드 하천·분지, 복원 조건이 갖춰진 지역 물길을 수원으로 탐색한다. 하천 경로가 굴착에 끊기면 상류에서 유입되는 물은 새 밀도 지형을 따라 이동한다. 하천·분지 수원 탐색은 나누어 처리하므로 초기 탐색 중에는 반응이 늦을 수 있다.
- 물속 보행은 느려지고 수직 저항·부력이 작용한다. 깊은 물에서는 기존 점프 입력으로 위로 움직인다. 호스트가 이동 결과를 확정하고 클라이언트 예측은 전송받은 수심을 사용한다. 새 익사·산소·수압 피해 규칙은 추가하지 않았다.
- 가까운 물의 실제 셀을 한 개의 INK 메시로 표시한다. 이웃 수면 꼭짓점 높이를 공유하고 내부 셀 벽은 생략한다. 바다와 겹치는 수면도 생략한다. 기존 해수면에는 원래 지표 마스크를 적용해 육지 아래의 닫힌 동굴을 관통하는 수면을 억제한다.
- 침수된 곳도 기존 ElevenLabs 하천 음원의 3D 재생 위치가 된다. 동굴 물소리를 외부 바람처럼 전부 감쇠하지 않고, 잠겼을 때 지표 환경음에 저역 통과 필터를 적용한다. 새 음원이나 Blender 모델을 만들지 않았다.

## 성능·저장·협동

`data/surface_water_physics.json`에 계산량과 이동 계수를 둔다. 기본은 셀당 0.1초 이상 간격, 호스트 프레임당 최대 32셀, 약 1,200μs 작업 예산이다. 하나의 밀도 조회나 메시 업로드까지 강제 중단하는 엄격한 프레임 시간 제한은 아니다. 여러 행성에 분산된 승무원은 행성 계산 순서를 나눠 쓴다.

활성 반경은 승무원별 80m, 행성별 저장 한도는 16,384셀이다. 한도에 닿으면 기존 물을 지우지 않고 새 셀 확장을 멈춘다. 비활성 물은 보존하고 떠나 있는 동안 정지한다. 정확히 빈 셀만 해제하며 작은 잔량을 임의로 버리지 않는다. 변경이 없는 상태는 새 메시를 만들지 않는다. 굴착 이력이 없는 행성에서 물리용 하천 탐색을 실행하지 않는다.

세계의 선택 필드 `surface_water`를 기존 체크포인트에 함께 저장한다. 기존 저장에는 이 필드가 없어도 된다. 거래가 세계 사전을 교체해도 계산 직전에 최신 사전에 다시 연결한다. FINCH의 다른 행성도 호스트 세계의 같은 원장에 저장한다. 참가자에게는 현재 행성·52m 이내 가까운 순 최대 4,096셀만 기존 0.5초 지표 패킷으로 보낸다. 좌표·양·개수·버전을 검사하고 협동 콘텐츠 해시에 물리 설정을 포함했다. 클라이언트가 물의 양을 요청으로 결정하는 경로는 없다.

## 확인

`tests/check_surface_water.gd`: 막힌 동굴 유지, 통로 개방 후 아래로 유입, 낮은 공간을 채운 뒤 수위 상승, 이동 전후 총량 보존, JSON 왕복, 가까운 셀 복제, 비활성 상태 보존, 잘못된 좌표·양 거부, 캐릭터 부력·저항을 확인했다. **12개, 실패 0**. 접지 중인 캐릭터도 60Hz에서 부력으로 떠오르는 것을 포함한다. 격리 검사 수치는 별도 실행 로그를 따르며 실제 지상 비용은 아래 실행 기록과 구분한다.

`tests/check_surface_water_play.gd`: 별도 복사한 시드 71491의 저장을 Godot 4.7.2 Metal Forward+에서 재개해 해저 굴착을 호스트 지형 편집 경로로 전달했다. 원래 해저 아래로 들어간 물, 메시·충돌 갱신, 수심, 압축 패킷 검증, 세계 저장과 실제 ElevenLabs 스트림 재생을 확인했다. **14개, 실패 0·엔진 오류 0**이었다. 마지막 장면은 264셀, 기존 해저 아래 물 양 21.042, 압축 패킷 4,063바이트였다. 해당 실행에서 계산 최대 6.272ms, 물 메시 갱신 최대 1.624ms를 기록했다. 이 수치는 전체 게임 FPS 개선이나 엄격한 1.2ms 상한을 의미하지 않는다. [실행 수치](media/surface-water/verification.json), [물가](media/surface-water/excavated-shore.png), [굴착 안쪽](media/surface-water/flooded-cut.png)에 실제 확인 결과를 보존한다. 이는 별도 시험 코드로 편집을 넣은 확인이며 장비 제작부터 수동 클릭까지의 전체 플레이 반복은 아니다.

초기 확인에서 테스트 옵션 이름을 잘못 지정해 선택된 로컬 세계를 약 1분 실행·자동 저장했다. 원래 세계에 굴착은 하지 않았다. 이후 실행은 `--crew-ui-test`와 지정 임시 폴더를 동시에 검사하고 복사본만 사용했다. 원래 저장의 정확한 실행 전 상태 복원은 수행하지 않았다. 중간 시험의 굴착 목록 초기화 누락은 시험 코드에서 수정했다. 초기 렌더에서 발견한 중복 수면과 내부 셀 경계는 생략·공유 꼭짓점 방식으로 보완했다.

## 남은 제약

물리 해상도보다 작은 통로·얇은 벽과 부드러운 물보라는 정확한 유체 표현이 아니다. 연속 유체 방정식, 전 행성 해수면 변화, 증발·결빙·침식, 유한한 강 유량·유역 물 수지, 댐/펌프, 차량·아이템 부력, 시설 벽의 방수와 침수 피해는 미구현이다. 기존 작은 습윤 지표 패치는 재질·풍경 효과로 남는다. 원래 해저 아래의 자연 동굴은 바다 고도만으로 자동 침수하지 않는다.

분지·복원 수원은 코드에 연결했지만 이번 실제 화면 검사는 바다 굴착 중심이다. 6인 실접속, 서로 다른 행성의 동시 장시간 침수, 최대 셀 한도 장시간 부하, 전체 게임 FPS, Windows 및 직접 청감은 확인하지 않았다. 1m 격자의 형태와 순차 갱신은 가까운 화면에서 여전히 드러날 수 있다.
