# 전체 동물의 빠른 이동 제작·연결

2026-09-14 사용자 승인: [176 조사](176-creature-speed-and-gait-audit.md)의 남은 작업을 전체 진행한다. 동물 5,600종의 현재 골격을 활용해 체형별 빠른 이동을 제작하고 위치 보간·가속/감속·선회·도주/추격·공격 전환을 연결한다. 식물/미생물 2,400종과 새 수중/비행 전투 AI를 추가하는 범위는 아니다.

## 같은 날 후속 정정 — 이동속도에 맞춰 고속 모션도 가속

사용자 확인: 오른쪽의 새 모션도 실제 이동속도가 높아지면 왼쪽처럼 빠르게 움직여야 한다. 이 요청에 따라 애니메이션의 제작 기준 속도로 일반 추격/도주·돌진과 생물 사건의 최고속을 낮추던 제한을 제거했다. 종/티어/사건이 정한 게임 속도를 유지하며 기존 골격의 고속 클립을 실제 이동거리와 보폭에 비례해 재생한다. `max_playback` 제작 참고값을 이동속도 또는 재생속도 상한으로 사용하지 않는다. 표시 선회의 접지 보정에는 기존 참고값을 유지한다.

가속/감속·공격 전 감속·선회·표시 보간·돌진의 가속 구간 및 접촉 정지는 유지한다. 예를 들어 삼족형 T5 도주는 4.025m/s, 사족형 T5 돌진은 17.4m/s의 게임 설정을 다시 사용한다. 높은 속도에서 다리/몸통 주기가 빨라지는 것은 의도된 동작이다. 이 정정은 모든 종에 공통인 런타임 경로를 고친 것이며 Blender 원본/모션을 재제작한 것은 아니다.

[속도 복원 후 비교 영상](media/creature-gameplay-speed/comparison.mp4)과 [후속 검사 근거](media/creature-gameplay-speed/evidence.json)는 아래 최초 제한 적용 영상과 구분한다. 양쪽에 같은 게임 속도를 입력하며 왼쪽은 보행만 배속, 오른쪽은 새 고속 클립이다. 단일 행동의 처리 범위는 해당 개체의 속도 계산과 기존 모션 주기에 한정되고, 전체 종 목록·지형·저장 재생성은 추가하지 않는다.

후속 확인: 대표 2종을 Forward+에서 30fps·10Hz 위치 입력으로 총 720프레임 비교했다. 삼족형은 4.025m/s에서 새 고속 클립 약 2.82배, 사족형은 17.4m/s 돌진 속도에서 약 3.87배로 재생됐다. 같은 구간의 보행만 배속은 각각 약 10.20배·17.93배이며, 두 패널의 실제 표시 이동속도는 입력값과 0.02m/s 이내로 일치했다. 모션별 보폭이 달라 재생 배율 자체는 서로 다르다. 실제 호스트 이동/돌진 접촉/저장 22개, 생물 사건 65개 확인은 실패 0개다. 높은 속도의 새 전종 미적 검수·6인 외부망 검사는 추가로 실행하지 않았다.

재현: `./tools/godot.sh --script res://tests/render_creature_gameplay_speed.gd -- biota_spindle_armor_25 bio_quill_amphora_01`. 원시 프레임/주기 수치는 `output/creature-gameplay-speed`에 남긴다. 기존 Blender 골격·액션을 재사용한 런타임 속도 수정이므로 전종 Blender 재내보내기는 하지 않았다.

## 제작 방법과 보존 경계

기존 Blender 메시·웨이트·일반 보행·공격·피격·무력화 원본을 보존한다. 원본의 실제 사지 길이·부착 위치·관절 축으로 새 빠른 동작을 계산하고, 각 골격의 편집 가능한 `.blend` 액션 라이브러리와 게임용 압축 `.motion`을 별도로 저장한다. 라이브러리의 `original_model_source`는 함께 열어 편집할 원본을 가리킨다. 액션을 원본의 같은 `StudySkeleton`에 연결해 메시와 함께 검토한다.

게임은 첫 사용한 종의 라이브러리를 읽어 실제 Skeleton3D의 rest와 결합하고, 근/원거리 모델의 기존 AnimationPlayer에 새 클립을 추가한다. 골격 이름·부모와 본 수를 검사한다. 색·크기·ID만 바꾼 항목을 새로운 골격으로 세지 않는다. 종별 자연 이동속도와 최대 재생률을 작은 메타데이터에서 읽고, 실제 크기와 함께 호스트 이동 성능에 연결한다.

진행 단계는 제작 → 실제 원본/게임 렌더 → 일반/사건/비행 연결 → 규칙·저장/협동 확인으로 나눈다. 파일이 생긴 수를 전체 검수 완료 수로 합산하지 않는다.

## 제작·연결 결과

동물 **5,600종 전부**에 `sprint_loop`를 추가했다. 실제 돌진 행동을 가진 71종에는 머리를 낮추는 `sprint_charge_loop`도 추가해 총 **5,671클립**이다. 원본 골격을 다시 같은 형태로 바꾸는 작업은 하지 않았다. 각 종의 실제 관절 길이·부착 위치·추진 기관으로 동작을 만들었다.

| 추진 방식 | 종 수 | 빠른 동작 |
| --- | ---: | --- |
| 사족 질주 | 100 | 앞·뒷다리 순서, 척추·목의 반응, 넓은 보폭 |
| 다족 보행 | 4,233 | 좌우 지지군과 다리 수에 맞는 교대 |
| 중량·방사 지지 | 704 | 긴 접지 비율, 지지점 순환, 낮춘 자세 |
| 도약 | 36 | 함께 차기, 공중 수축, 착지 |
| 무족 파동 | 57 | 연속 몸통·꼬리 관절의 진행 파동 |
| 비행 | 165 | 좌우 대응 날개의 동시 추진, 말단 막/깃의 작은 후행, 접은 발 |
| 부유 | 245 | 부력 구조·막·추진 부속의 느린 파동 |
| 유영 | 60 | 몸통·지느러미·뒤쪽 추진 기관의 파동 |
| 합계 | **5,600** | 색·크기 변이를 별도 종으로 세지 않음 |

구형 목록에 이동 매질이 없는 85종은 제작 원본의 공중/수중 분류로 보완했다. 목록의 원산지·발견·저장 서명은 변경하지 않는다. 구형 달리기형의 `anatomical_type`도 읽어 도약형을 일반 이족 배속으로 취급하지 않도록 했다.

- 일반 보행 → 기존 달리기 → 새 빠른 이동을 실제 표시 이동량으로 선택한다. 전환에 히스테리시스와 기존 0.12초 블렌드를 사용하고, 보행 주기를 계속 이어 간다.
- 지상 추격/도주·돌진 최고속은 종/티어의 게임 설정을 사용한다. 최초 적용했던 `자연속도 × 1.18 × 실제 개체 크기` 상한은 위 후속 정정에서 제거했다. 실제 속도가 올라가면 새 고속 클립의 재생 주기도 비례해 빨라진다.
- 호스트는 출발 가속, 목적지 앞 감속, 선회 중 감속을 적용한다. 공격은 사거리뿐 아니라 상대를 향한 자세와 접근 감속을 확인한 뒤 시작한다.
- 돌진은 기존 예고 거리·충돌 경로를 유지하되 가속/감속 구간을 포함하도록 지속시간을 계산한다. 기존 주둥이/뿔의 접촉·엄폐·안전 구역·한 번만 피해를 주는 판정을 유지한다.
- 호스트 시각이 붙은 위치 두 개 사이를 표시용으로 보간한다. 보통 한 갱신 간격 정도 늦게 표시하며 앞을 추측해 이동하지 않는다. 기존 0.18m 표시 제한으로 매번 튀던 경로를 해당 이동 구간 길이에 맞췄다. 충돌용 루트와 피해 판정은 호스트 위치를 유지한다.
- 급격한 목표 방향 변경에서도 표시 회전속도를 체형의 선회속도와 발 이동 한계로 제한한다. 실제 호스트 선회와 강제로 방향을 뒤집는 검토 장면을 구분한다.
- 저장된 생물 사건도 사건의 게임 속도·가속/끝점 감속과 시각 보간을 사용한다. 새 `native_motion_clock`, `native_move_speed`는 선택 필드이며 기존 개체 정보·분석/보상 조건을 바꾸지 않는다.
- 지상 조류의 실제 이동량을 비행 동작에 전달한다. 이륙/착륙은 유지하고 빠른 비행 요구에서 새 클립을 고른다. 지역 새로고침 때 날던 개체를 홈 위치로 잠깐 돌려놓지 않는다.

## 실제 확인과 근거

수량·대표별 측정·실제 실행 기록은 [종합 검사 근거](media/creature-fast-motion/evidence.json)에 보존한다. 검토 자료 묶음은 `tools/package_creature_fast_review.py`로 생성하며 Pillow·imageio-ffmpeg와 해당 스크립트에 명시한 성공 실행 로그가 필요하다.

전수 파일 검사는 5,600종의 최신 제작 지문·원본 해시·압축 파일 해시·유한한 관절 값·회전 정규화·루프 접속·사지 이름을 확인했다. 기존 **11,200개 GLB의 골격 이름/부모/rest**와 비교했으며 두 LOD가 같은 관절 변환을 사용한다. 뿌리 하나만 움직이는 클립도 제외해 검사했다. 이는 전종의 화면 품질을 사람이 개별 승인했다는 뜻이 아니다.

- [5종 보행 배속 비교 영상](media/creature-fast-motion/comparison.mp4): 사족·여섯발·삼족·도약·무족, 30fps·10Hz 위치 입력으로 걷기/고속/방향 변경/감속/정지를 비교한다. 사족의 지속 돌진 구간은 속도 비교용이며 실제 타격 시험과 별개다.
- [추가 12종 근·원거리 영상](media/creature-fast-motion/types.mp4): 201본 다족, 136본 중량형, 파동형, 조류·부유·유영·구형 날개/도약/사족·방사형을 실제 Forward+ INK로 재생했다. 12종 지상 표본의 최대 접지 오차는 약 2mm 이내였다. 비행/유영/부유의 고속 입력은 검토용이며 새 전투 AI가 아니다.
- [Blender 원본 검토판](media/creature-fast-motion/blender-board.jpg), [편집 원본 검증](media/creature-fast-motion/blender-evidence.json): 저장한 액션 라이브러리를 원래의 웨이트 메시와 골격에 다시 붙여 17종×2자세를 Cycles로 렌더했다. 액션 자세와 게임용 내보내기 값의 최대 차이는 0.001 미만이다. Cycles를 INK 게임 렌더 대신으로 쓰지 않았다.
- [호스트 이동 수치](media/creature-fast-motion/host-movement-evidence.json): 5종의 실제 가속·최고속·180도 선회, 실제 새 T5 돌진의 속도/접촉 정지, JSON 왕복과 재개를 22개 확인 항목으로 검사했다. 별도로 기존 돌진·도약·충격파·연속 공격의 20개 판정 검사를 통과했다.
- 생물 사건의 원산지·분석/보상·기존 저장과 새 선택 필드는 65개 확인 항목을 통과했다. 예전 검사의 고정 100만 행성 순회는 현재 고유 원산지 목록 순회로 수정했다.
- 조류의 실제 월드 경로에서 휴식·이륙·순항·착륙, 연속 속도, 고속 클립 선택과 일시정지 7개 항목을 확인했다.
- 격리된 실제 T4 원정에서 선공 경고 → 추격 → 공격/피해 → 총기 피격/무력화 → 마지막 위치 저장·재개 및 메뉴 일시정지·기존 SFX를 14개 항목으로 확인했다. [경고](media/creature-fast-motion/native-warning.png), [공격](media/creature-fast-motion/native-attack.png), [무력화](media/creature-fast-motion/native-down.png), [실제 녹음](media/creature-fast-motion/native-runtime.wav)을 보존한다. 제작/렌더를 동시에 돌린 첫 실행은 제한 시간에 공격까지 도달하지 못했으며, 제작 작업을 잠시 멈춘 재확인에서 통과했다. 이 실행을 FPS 성능 측정으로 쓰지 않는다.

아래 최초 제작 자료의 `creature-fast-motion/comparison.mp4`는 제거 전 상한을 적용한 과거 수치다. 현재 속도 비교는 위 후속 영상으로 확인한다. 예를 들어 삼족형의 T5 도주는 조사 당시 4.025m/s에서 시험 외형 기준 약 1.48m/s로 낮아졌다. 새 보폭과 속도 조정을 함께 적용한 결과이므로 같은 속도에서 클립만 바꾼 개선율로 해석하지 않는다. 5종 영상의 모델 배율은 1이고 호스트 수치의 외형 배율은 0.88이다. 정속 구간과 강제 속도/방향 전환의 최대 재생률도 구분한다.

## 단일 행동의 처리 범위

입력/피격 → 기존 호스트의 해당 생물 상태 → 해당 생물의 속도·공격/위치 → 기존 저장·스냅샷 → 해당 배우의 표시 보간·관절 자세 순서다. 생물의 움직임마다 전체 5,600종을 순회하거나 원산지·지형·전체 도감을 재생성하지 않는다.

`creature_mobility.gd`는 처음 쓰는 종의 작은 JSON만 읽고 보관한다. 표시 클립도 해당 종의 첫 배우 생성 때만 읽는다. 애니메이션 라이브러리 조회 캐시는 96개로 제한하며 기존 배우가 참조하는 리소스를 강제로 해제하지 않는다. 배우별 자세·보행 주기와 접지 캐시는 분리한다. 깊은 복사는 첫 구성 시 해당 종의 작은 모션 프로필에만 추가했다.

새 시각/속도 필드는 기존 활성 생물 갱신과 해당 사건 행에 들어간다. 실패·막힘은 이동속도를 0으로 만들고 기존 공격 실패 동작을 사용한다. 메뉴 일시정지에는 주기를 진행시키지 않으며 재개/저장은 선택 필드를 허용하고 일반 교전의 일시 속도·돌진을 초기화한다. 기존 원자적 저장/검증·피해 중복 방지와 협동의 호스트 권한은 생략하지 않는다. 기존의 주변 후보 검사, 움직이는 배우의 관절 갱신, 정기 체크포인트의 전체 저장 비용은 남는다.

## 출력·재생성

Blender 라이브러리 약 934MB, 압축 게임 모션 약 242MB다. 둘 다 LFS로 보존하고 메타데이터/제작 코드는 일반 Git을 쓴다. macOS·Windows 내보내기 필터와 Windows 패키지 검사에 `.motion`을 포함했다.

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --python-exit-code 1 --python tools/creature_remodel/fast_motion.py -- --all
python3 tools/verify_creature_fast_motion.py
/Applications/Blender.app/Contents/MacOS/Blender --background --python-exit-code 1 --python tools/render_creature_fast_sources.py
./tools/godot.sh --script res://tests/render_creature_fast_motion.gd
./tools/godot.sh --script res://tests/render_creature_fast_types.gd
./tools/godot.sh --headless --script res://tests/check_creature_fast_movement.gd
./tools/godot.sh --headless --script res://tests/check_creature_fast_flight.gd
./tools/godot.sh --script res://tests/check_wildlife_combat.gd -- --play --crew-ui-test --crew-folder=/tmp/native-combat-play
```

추가 12종 선택은 `tools/creature_remodel/fast_motion_review.json`을 사용한다. 원시 프레임·전종 상세 검사 목록은 `output/creature-fast-motion`의 로컬 재생성 결과다. 대표 영상/판정 근거만 문서에 보존한다. 라이브러리를 편집할 때는 해당 메타데이터의 `original_source`를 열고 새 `.blend`의 Action을 Append해 같은 `StudySkeleton`에 지정한다. 액션 라이브러리는 메시를 포함한 독립 장면이 아니다.

## 남은 경계

- 전종 파일/골격 검사는 완료했지만 **5,600종 각각의 장시간·모든 경사/장애물·모든 변형의 미적 검수**를 완료한 것은 아니다. 화면 검토는 위 17종과 실제 원정의 별도 1종이다.
- **6인·실제 외부망 지연/손실** 검사는 이번에 실행하지 않았다. 새 필드는 JSON 저장/스냅샷 전달 형태와 호스트 소유권을 유지한다.
- 이 작업 당시 공중 생물의 새 도주·추격·공격 AI는 미연결이었으며 후속 [178](178-flying-wildlife-and-jetpack.md)에서 지표 비행종 140종을 연결했다. 수중 생물 교전은 해당 후속 요청의 범위가 아니다. 별도 전종 고속 추진 효과음과 전종 전투 난이도 조정은 완료하지 않았다. 기존 지상 행동을 가진 동물에는 이번 이동을 연결했다.
- 이번 코드로 macOS/Windows 배포 파일을 새로 만들거나 Windows 실기 확인을 하지 않았다. 내보내기 포함 규칙을 고친 것과 실제 배포 검증을 구분한다.
