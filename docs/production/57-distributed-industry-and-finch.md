# 부재중 생산과 FINCH 소형선 — 개별 개발 기록

2026-09-08 후속: [이탈 FINCH 회수·협동 패킷 개선](60-shuttle-recovery-and-snapshot-packets.md)을 구현했다. 아래 재접속해야만 공동 출항 가능·7.4KB 단일 스냅샷 제한은 해당 후속으로 대체된다. 실제 6인 인터넷·장시간 다행성 부하 등 나머지 미확인 범위는 유지한다.

2026-09-08 사용자 요청에 따라 두 작업을 순서대로 구현했다. [소관 규칙](../game/18-local-shuttles-and-distributed-industry.md)에 확정 방향과 첫 밸런스 선택을 구분한다. 이 기록은 현재 작업 트리의 구현이며 커밋·출시 패키지 배포를 뜻하지 않는다.

## 1. 부재중 거점 생산

현재 착륙지 밖의 운영 거점도 호스트 세션의 1초 생산 틱에서 진행한다. 비행 중에도 광맥·로봇 배터리/경로·전력·재료·창고 여유를 같은 생산 규칙으로 계산하며 거점별 입력/출력을 보존한다. 현재 거점의 중복 틱이나 운송에 따른 원격 재고 자동 이동은 없다. 호스트 종료 후 현실 시간 보상은 지급하지 않는다.

`FrontierPlanetSupply.context`로 거점 주소를 선택하고 `FrontierCrewAuthority.step_surface`에서 기존 산업 틱을 적용한다. `FrontierCrewSurface`의 최대 16개 지형 필드 캐시는 거점 전환 시 반복 생성을 줄인다. 별도 거점 전체 3D 장면을 렌더하지 않으며 기존 이용권 한도 안에서 처리한다. 저장 실패 시 기존 공개 상태를 보존하고 세션 진행을 정지한다.

재방문 목록/공급 재고 화면에 원격 운영을 표시했다. [960 화면](media/finch/remote-supply-960.png)을 확인했다. 관련 명령·생산/비행·저장 실패·재시작 45개, 실제 Forward+ UI 8개 확인에서 실패가 없었다. 대규모 다거점 장시간 성능을 측정한 것은 아니다.

## 2. 플레이어 직접 운송 소형선

FINCH는 Mk.2 이상 제작소의 **소형선** 탭에서 가방 부품으로 조립한다. 첫 값은 45초·강화 프레임 4/제어 회로 2/열전달 장치 2/철 30·개인 한 대·최대 6대·화물 4칸이다. `data/shuttles.json`에서 관리하며 확정 밸런스는 아니다. 제작소 전력이 있어야 진행하고 다른 제품·로봇·공학 작업과 조립을 겹치지 않는다.

조립 후 공동 착륙선 옆 FINCH에 접근해 F로 출발한다. 기존 W/S·마우스·Shift 조종과 Tab 지도를 통해 같은 항성계의 행성으로 이동·착륙한다. 동료는 원래 행성에서 작업을 계속한다. 행성 창고→개인 가방→FINCH 화물→귀환 후 인수 순서로 직접 운송한다. 공동 원정선의 항해/화물과 개인 소형선의 기록을 분리하고 성간 목표는 호스트에서 거부한다.

귀환 시 원정선이 있는 행성에 착륙해 가까이 접근한 뒤 소형선 탭의 **공동 원정선에 합류**를 사용한다. 필요한 화물을 먼저 직접 내린다. 합류 버튼이 자동 하역하지 않으며 남은 화물은 같은 FINCH의 다음 출동까지 보존한다. 출동 또는 조립 중에는 공동 출항을 대기한다.

각 소형선은 세계 저장의 소유 캐릭터에 연결한다. 연결 종료 시 입력을 멈추고 재접속은 동일 위치·가방·화물로 이어진다. 개인 프로필에 남의 세계 화물을 복제하지 않는다. 첫 운송 대상은 광물/자원·생산품·개인 장비이며 로버·공동 로봇 격납고·표본 연구/이식은 공동 원정선에서 수행한다.

### 호스트 동기화

`FrontierShuttles`가 개인 항해·착륙·화물 문맥과 명령 검증/저장을 담당한다. 세션은 승무원별 표면 패킷을 보내고 `FrontierCrewSpaces`는 다른 점유 행성의 실제 지형/시설 충돌 공간을 별도 World3D에 구성한다. 해당 캐릭터를 올바른 공간에서 이동시키며 다른 행성의 캐릭터/음향은 로컬 지표에서 숨긴다. 호스트가 소형선으로 이동한 경우에도 원래 행성의 기존 로버가 해당 충돌 공간을 참조하도록 연결했다. 이 로버 변형 경로의 직접 운전 실증은 이번 확인에 포함하지 않았다.

### 모델·연출·사운드

[Blender 원본 렌더](media/finch/blender-finch.png), [게임 제작 카드](media/finch/factory-960.png), [현장 탑승](media/finch/pad.png), [960 비행 화면](media/finch/flight-960.png)을 실제 렌더에서 확인했다. `tools/build_finch_shuttle.py`가 공통 Blender 제작 헬퍼/INK 재질로 1인 조종실·쌍발 추진기·양옆 화물 포드·착륙 다리·가동 캐노피/소켓을 만든다. 원본은 `art/blender/ships/finch.blend`, 게임 출력은 `우주-비즈니스/assets/models/ships/finch.glb`다. 비행 시 다리 접기·캐노피 상태·쌍발 배기·상승/착륙 선체와 카메라를 연결했다.

기존 ElevenLabs 효과음을 재사용했다. 조립 준비/진행/완료와 요청 실패, 추진·가속·제동·대기 진입·착륙에 연결한 ID와 출처는 `audio/manifests/finch-reuse.json`에 남겼다. 메뉴의 입력/작업음 차단과 실제 실행 스트림 연결을 확인했다. 신규 음원 생성·주관적 음색 청음 완료로 기록하지 않는다.

### 최소 확인과 수정

- `check_shuttle_sortie.gd`: 조립 작업 충돌, 출동 저장 실패의 원자성, 공동선 위치/화물 보존, 성간 거부, 같은 항성계 도착/착륙, 창고 인수/적재, 연결 종료/재접속, 영속 저장, 귀환/하역/합류 등 40개 확인 실패 0건. 격리 공급 거점 fixture를 사용했다.
- `check_shuttle_ui.gd`: 실제 Forward+ 제작 카드/현장 FINCH/상승 후 독립 비행/소형선 렌더/음원 연결/메뉴 차단/저장 등 10개 확인 실패 0건. 1280×800·960×640을 확인했다.
- `check_shuttle_two_peers.gd`: 실제 ENet 두 클라이언트를 동시에 실행해 원래 행성의 호스트와 다른 행성의 운송 담당자가 각자 실제 지형 위에서 이동했다. [호스트 화면](media/finch/two-planets-host.png), [운송 담당 화면](media/finch/two-planets-courier.png), [측정 요약](media/finch/verification.json)에 결과를 보존했다.
- 확인 중 발견한 원격 지표의 재질 초기화 오류, 작은 창의 비행 뷰 잘림, 종료 시 권한 객체의 자기 참조를 수정했다. 마지막 UI 실행은 스크립트 오류와 종료 자원 누수 경고 없이 종료했다. 두 클라이언트 캡처는 자기 참조 수정 직전 실행이며 해당 호스트 종료 경고는 이후 UI 종료로 좁혀 재확인했다.

## 남은 경계

실제 6인 인터넷/패킷 손실 환경·장시간 다행성 부하·Windows 실기는 미확인이다. 로컬 연결에서 7.4KB 비신뢰 스냅샷의 MTU 초과 경고가 관측됐다. 인터넷 품질을 위해 후속 패킷 분할/축소가 필요하며 이번 로컬 통과를 인터넷 품질 완료로 보지 않는다.

연결을 끊고 출동 중인 승무원도 공동 출항 대기에 포함한다. 현재는 해당 플레이어가 재접속해 귀환해야 하며 구조/강제 회수 UI는 후속이다. 다른 플레이어가 운항 중인 소형선의 전 외부 시각화·동일 착륙지 다수 방문선 주기 위치는 아직 기본형이며, 이번 렌더 확인은 출발지의 주기된 FINCH와 본인 비행/착륙 중심이다. 해적·전투·고급 생산 단계 확장은 포함하지 않는다.
