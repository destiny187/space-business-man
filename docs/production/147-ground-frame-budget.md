# 지상 프레임 지연 후속 개선 — 2026-09-12

사용자가 [종합 성능 보고서](../../output/performance-review-20260912/REPORT.md)의 우선순위에 따른 개선을 요청했다. 생물 접지, 자동 진행 저장, 지표 전송·사업 화면, 지상 지도 경로를 수정했다. **반복 CPU 비용과 지도 정지는 줄었으나 안정적인 60 FPS 달성은 아니다.** 그래픽 프리셋·렌더 해상도·모델·음원을 낮추거나 생산 주기를 늘리지 않았다.

## 구현

### 생물 보행·접지

- `bestiary_actor.drive_ground`에도 현장 가시성을 연결했다. 가까운 발소리 범위는 매 프레임 접지를 유지한다. 그 밖의 보이는 생물은 접지를 약 15Hz로 갱신하고 화면 밖 생물은 접지 탐색을 쉰다. 위치·충돌·전투 판단·보행 위상은 계속 진행한다.
- 다시 보이거나 가까워지면 접지를 다시 바인딩해 이전 위치까지 다리가 늘어나지 않게 한다. 카탈로그 미리보기는 기존 보행 경로를 유지한다.
- 발이 고정되어 있고 지형 revision이 같으면 반복 지형 탐색을 하지 않는다. 굴착 등 지형 수정 시 다시 탐색하고 높이 변화를 보간한다. 지하의 가까운 바닥을 찾는 기존 density 탐색을 유지했다.
- 거리 갱신 간격은 `data/ground_locomotion.json`의 `distant_contact_seconds`에 둔다.

### 자동 진행 저장

- 한 번의 지표 시뮬레이션에서 발생한 날씨·사건·생산·스캔 등의 저장 요청을 한 후보 세계로 모아 `WorldStore.begin_commit`에 제출한다. 기존 1초 생산 계산은 유지한다.
- 필수 자동 저장은 진행 중인 주기 체크포인트 뒤에 하나만 대기할 수 있으며 생략되지 않는다. 검증·독립 스냅샷 준비는 메인 스레드, JSON 인코딩·임시 파일 쓰기·읽기 확인·백업·교체는 작업 스레드에서 수행한다. 도메인 캐시나 장면 객체를 작업 스레드에서 사용하지 않는다.
- 저장 완료 전 후보 세계를 공개 세계로 교체하거나 스냅샷을 발행하지 않는다. 사용자 거래·참가 확정·연결 종료·마지막 저장은 이전 필수 저장을 먼저 완료한다. 실패하면 자동 진행 결과를 공개하지 않고 세션을 정지한다.
- 후보 생성에서 변경되지 않은 승무원과 로버의 런타임 기록만 공유하여 저장 중 발생한 새 이동·회복을 잃지 않는다. 작업 스레드는 그 전에 별도 복사본을 소유한다. 피해·구조 등으로 바뀐 승무원, 바뀐 차량과 해당 승무원이 탄 차량은 완료를 기다린다. 로버 적재 작업과 후속 자동 시뮬레이션의 진행도 저장 순서를 넘지 않게 한다.
- 메인 스레드의 반복 사업 규칙 서명은 원문과 카탈로그의 값 비교로 재사용한다. 원문/카탈로그 변경을 검사하며 짧은 해시 충돌로 검증을 생략하지 않는다. 검증에서 읽기만 하는 행성 정의는 기존 불변 캐시를 사용한다.

### 지표·사업 화면

- 같은 발행에서 같은 행성·선박 문맥의 공통 사업 자료를 한 번 생성한다. 개인 가방과 위치별 현장 환경은 별도로 만든다. FINCH와 원정선의 선박 능력을 섞지 않도록 문맥 키를 구분한다.
- 전송 직전 전체 JSON 정규화와 해시를 반복하는 대신 마지막 공개 패킷과 값을 비교한다. 바뀌지 않은 지표의 사업·생태 표현을 다시 적용하지 않는다. 원격 수신 검증과 압축 전송은 유지한다.
- 열린 사업 화면은 현재 보이는 탭을 갱신한다. 탭 전환 시 최신 자료를 즉시 그린다. 같은 선택 목록·생물/표본 목록·비용 표시는 컨트롤을 지우고 다시 만들지 않는다.

### 지상 지도

- 160×100 지도와 동일한 높이·음영·등고선·색 계산을 전용 작업으로 옮겼다. 작업은 독립 TerrainField/캐시와 CPU Image를 소유하고 ImageTexture 설치만 메인 스레드에서 한다.
- 동시에 한 작업만 실행한다. 드래그·줌·행성 전환 중 결과가 낡으면 버리고 최신 요청을 이어서 처리한다. 이동 중 기존 지도는 해당 좌표에 유지하고, 다른 행성으로 바뀌면 비운다. 창 해제 시 작업을 회수한다.

## 확인

기존 사용자 저장 대신 격리된 저장 복사본과 별도 사용자 설정 경로를 사용했다. 기존 변경 사항을 포함한 소스 복사본, 측정 코드와 로그는 [작업 폴더](../../output/performance-fixes-20260912/)에 있다. 초기 UI 메타데이터 경고와 보행/검사 코드의 오류를 수정한 뒤 해당 범위를 다시 확인했다.

- 기존 보행·발 접지·정지·LOD·순간 이동·동굴 바닥 검사 **87개** 통과.
- 기존 작업 스레드 저장 **14개**, 불변 세계·거래/백업 검사 **19개** 통과.
- 자동 저장 **22개** 통과: 필수 저장의 순서·병합·실패·미공개 상태, 사용자 거래 선행 저장, 새 승무원/차량 위치 보존, 규칙 서명 캐시 변경 감지. 차량 기록 공유는 작은 모의 상태 검사이며 실제 로버 주행 실측을 뜻하지 않는다.
- 표현 예산 **13개** 통과: 기존 지도 픽셀의 고정 해시 일치, 활성 지형 캐시 분리, 오래된 결과 폐기·종료 회수, 원거리 접지 생략·근거리 복귀·지형 변경 반영.
- 실제 Forward+ 창에서 지도 표시·연속 확대·제작소/로봇 탭·숨긴 창고·창고 복귀·저장 종료 **9개** 통과. [지도](../../output/performance-fixes-20260912/ui/map.png), [확대](../../output/performance-fixes-20260912/ui/map-zoom.png), [제작소](../../output/performance-fixes-20260912/ui/factory.png)를 확인했다. 전체 조작/전투·6인 회귀 검사는 실행하지 않았다.
- 완료된 두 지상 계측 실행과 최종 UI/저장/표현 검사 로그에 스크립트 오류·엔진 오류·종료 누수 경고가 없었다. 초기 중간 실행의 로그와 수치를 최종 통과 근거로 사용하지 않는다.

## 성능 표본

Apple M2, 1280×800, 보통 옵션·2× MSAA·100% 렌더, VSync/프레임 제한 해제. 기존 생물 16개 지상과 시설 7개 지역을 각각 정지 6초·보행 12초·메뉴 6초 실행했다. 함수 계측을 켠 표본이므로 비계측 최종 FPS와 구분한다. 다른 앱을 종료하지 않았으며 기존 조사와 동일한 PC라도 부하가 다르다. GPU 시간은 도구가 0을 반환해 미측정으로 남긴다.

성능 표본 후 FINCH 공통 자료 키와 로버의 저장 중 이동 보존 경계를 보완했다. 이 경계는 최종 집중 검사와 실제 UI 실행에서 확인했으며 FPS 표본을 다시 반복하지 않았다. 프로파일 원본 해시는 `final-source.json`, 최종 코드 해시는 `completed-source.json`으로 구분한다.

## 남은 경계

- 저장 제출의 메인 검증·복사만으로도 평균 약 22ms가 남는다. 열린 사업 화면의 반영도 약 21ms다. 검증을 작업 스레드에 무작정 옮기거나 내구성을 포기하지 않았다. 큰 세계의 검증 단계 분할과 실제 변경 영역을 사용한 패킷 생성은 추가 최적화 여지가 있다.
- 시설 보행에서 약 197ms의 프레임 1개가 남았다. 지형 처리 예산은 단일 엔진 호출을 중간에 끊는 상한이 아니며, 이번 표본만으로 모든 긴 프레임의 원인을 제거했다고 할 수 없다.
- 고해상도 우주·폭발 GPU 비용은 [146 기록](146-pirate-performance.md)의 후속 과제다. 이번 수정으로 1080p/1440p/4K, Windows, 6인 인터넷·독립 행성, 대규모 생산·로버 주행·장시간 열 부하의 성능을 보장하지 않는다.
