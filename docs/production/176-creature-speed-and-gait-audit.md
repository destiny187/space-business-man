# 생물체 고속 이동·도주·돌진 표본 조사

2026-09-14 후속: 사용자가 전체 개발을 승인해 [5,600종의 빠른 이동 제작·연결](177-creature-fast-motion-rollout.md)을 적용했다. 아래는 변경 전 조사 기록이다. 당시 런타임 수치를 재현하려면 조사 커밋 `ed8d653cc`를 사용하며, 현재 코드에서 실행한 결과와 구분한다.

2026-09-13 사용자 요청: 최근 로봇의 이동 개선을 생물체에도 대조하고, 기존 다리 동작의 배속만으로 빠른 도주·접근·공격을 자연스럽게 표현할 수 있는지 일부 체형을 골라 테스트한다. **이번은 조사와 비교 장면 제작이다. 게임 이동속도·모델·골격·전투 규칙의 수정은 하지 않았다.**

## 결론

걷기만 배속하는 방식으로 고속 도주·돌진을 처리하는 것은 권하지 않는다. 기존 생물에는 이미 `move_loop`와 `run_loop`가 있고 사족 돌진에는 `charge_loop`도 있다. 다시 전부 리깅하는 일보다 **현재 속도와 클립의 보폭/주기 불일치, 위치 갱신의 급한 추종, 체형별 빠른 이동의 방식**을 먼저 다뤄야 한다.

현재 달리기 클립도 모든 전투 속도를 감당하지 못한다. 평지의 발 고정이 유지되는 것과 동작이 자연스러운 것은 다른 조건이다. 특히 삼족형의 잦은 짧은 발 교대, 사족 돌진의 과도한 보행 주기, 큰 방향 전환 때 이동 방향과 몸 방향의 차이를 후속 대상으로 판단한다.

## 현재 경로 조사

- `wildlife_combat.gd`는 0.1초 간격으로 교전 위치와 상태를 확정한다. `move()`는 `info.speed × delta`만큼 이동하며 생물별 실제 보행 성능이나 가속 한도를 참조하지 않는다. 도주에도 같은 `info.speed`를 사용한다. 비공격형은 기본 3.5m/s이며 T5에서 4.025m/s다.
- `surface_ecology.gd`는 교전 기록의 위치를 읽어 현재 원정 배우의 `apply_combat()` → `drive_ground()`에 전달한다. 비전투 배회는 연속 시간의 별도 경로이므로 이번 10Hz 실험을 배회 전체의 측정으로 해석하지 않는다.
- `ground_locomotion.gd`는 표시 위치를 0.055초 시정수로 추종하면서 호스트 위치와의 거리를 0.18m 이내로 제한한다. 고속의 0.1초 위치 차이가 이 범위를 넘으면 한 프레임에 크게 따라잡는다.
- `remodel_motion.gd`는 실제 표시 이동 거리로 보행 위상을 진행하고, 평활화한 속도와 걷기 기준의 1.45/1.18배 경계로 달리기/걷기를 전환한다. 하지만 클립 진행량은 그 프레임의 이동량을 사용한다. 따라서 **상태 전환 완충만으로 프레임별 재생속도 출렁임이 없어지지 않는다.**
- 새 리모델링 경로는 `advance()`를 재정의한다. 구형 절차 보행의 `maximum_hz=5` 처리를 새 모델의 보행 상한으로 읽으면 안 된다. 현재 새 모델의 빠른 클립 재생률에는 같은 상한이 없다.
- 공격 준비/타격/회복은 호스트 시간을 따르며 전용 동작을 사용한다. `charge_loop`는 고개를 낮춘 달리기에서 만들어졌으며 돌진 전용 큰 보폭의 질주 동작을 새로 만든 것은 아니다.

## 표본과 조건

현재 런타임 레지스트리에서 실제 사용 중인 5종을 로드했다. 대체 구형 모델이나 제작 시안 배우를 쓰지 않았다. 각각 크기 1, 평지, near LOD, Godot 4.7.2 / Metal Forward+ / INK로 촬영했다.

| --- | --- | ---: | --- |
| sailhorn / `biota_spindle_armor_25` | 사족 | 23 / 12 | 추격과 고속 돌진, 머리 낮춤 |
| shearprowler / `biota_lobopod_armor_26` | 여섯발 | 33 / 14 | 빠른 접근과 여러 지지발의 교대 |
| pressureurn / `bio_quill_amphora_01` | 무거운 삼족 | 17 / 10 | 짧은 보폭과 빠른 도주 수치의 큰 차이 |

같은 속도·위치·방향 입력에 대해 왼쪽은 걷기 동작만 거리와 맞춰 배속하고 오른쪽은 수정하지 않은 현재 구동기를 사용한다. 왼쪽은 검토용 하위 클래스에서 달리기 전환만 제외해 접지 캐시를 보존한다. 게임용 `remodel_motion.gd`를 고치거나 공유 프로필을 변조하지 않았다.

각 12초: 걷기 기준 2초 → 달리기 제작 기준 2초 → T5 추격/도주 3초 → 사족 돌진 속도 또는 다른 유형의 180도 도주 방향 전환 2초 → 감속 1초 → 정지 2초. 위치를 10Hz로 전달하고 30Hz로 표시했다. 사족 돌진 구간은 속도 비교를 위해 2초 유지한 스트레스 장면으로, 게임의 실제 단일 돌진 지속시간이나 피해를 재현한 영상이 아니다. 도주 전환은 피격 후 이동 상황을 가정한 입력이며 총기 명중·경직을 실행한 것은 아니다.

위치 계단 현상과 클립 자체의 문제를 구분하려고 같은 5종에 30Hz 연속 위치를 넣어 한 번 더 측정했다. 원정·네트워크 코드를 개선한 버전으로 해석하지 않는다.

## 속도와 결과

아래 배율은 **일정 속도 구간의 평균 클립 재생률**이다. 영상 왼쪽/오른쪽의 ‘클립 배율’ 표시는 프레임별 값이므로 표보다 높거나 낮을 수 있다. 발 하나의 완전한 교대 주기와 양발 전체의 발걸음 수를 구분한다.

| 대표 | 걷기 기준 m/s | 달리기 제작 기준 m/s | T5 추격/도주 m/s | 걷기만 배속 | 현재 달리기 배속 | 판단 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 사족 | 0.97 | 2.68 | 3.84 | 3.96배 | 1.43배 | 접근은 현재 달리기 유지 가능성이 높음. 돌진은 별도 해결 필요 |
| 여섯발 | 0.74 | 2.13 | 5.63 | 7.58배 | 2.65배 | 걷기 배속은 잦고 짧은 교대. 빠른 지지 조합·보폭 확대 필요 |
| 무거운 삼족 | 0.39 | 0.75 | 4.03 | 10.20배 | 5.39배 | 현재 체중감과 도주 수치가 크게 어긋남. 우선 수정 대상 |
| 도약형 | 0.95 | 2.78 | 4.03 | 4.23배 | 1.45배 | 현재 빠른 도약이 더 적합. 도약거리·공중시간·착지 압축의 연동 필요 |
| 뱀형 | 0.71 | 2.02 | 4.03 | 5.64배 | 1.99배 | 파동 배속만 올리면 떨림이 강해짐. 진폭·파장·선회 곡률도 조절할 대상 |

사족 T5 돌진은 17.4m/s다. 현재 `charge_loop`를 평균 **6.50배**, 다리 한 주기를 약 **10.83Hz**로 재생해야 한다. 걷기만 사용하면 평균 17.93배다. 10Hz 위치 입력의 일정 돌진 구간에서 표시속도는 1.34~48.41m/s, 돌진 클립은 약 0.50~18.07배로 출렁였다. 이 수치는 **30Hz로 실행한 격리 비교의 프레임값**이며 모든 실제 프레임률·네트워크 조건의 상한은 아니다.

30Hz 연속 위치 비교에서는 같은 사족의 표시속도가 17.4m/s로 안정됐지만 클립은 여전히 평균 6.50배였다. 즉 위치 보간만 개선해도 보폭 부족은 남는다. 삼족형도 연속 입력에서 여전히 평균 5.39배, 약 6.74Hz 교대여서 동일 결론이다.

T5 추격/도주 구간에서 현재 사족·여섯발·삼족의 연속 지지발 프레임 간 이동은 최대 약 2mm 이하였다. 이 측정은 같은 두 프레임 모두 지지 상태인 표본에 한정하며, 발을 떼고 다시 디디는 동안의 이동·형태의 자연스러움·모든 메시의 지면 충돌까지 통과한 뜻은 아니다. 도약형의 무지지 프레임은 의도한 공중 구간이 있으므로 결함 수로 합산하지 않았다. 무족형은 발 IK 표본 자체가 없다.

회전 실험에서는 도주 위치가 먼저 반대 방향으로 바뀌고 몸 방향은 회전 한도로 뒤따른다. 정면 보행 클립만 쓰는 동안 옆/뒤로 밀리는 인상을 줄 수 있다. 독립 회전/방향 정렬·가속 처리가 필요하다는 판단이며, 실제 피격·지형 우회 전체를 검증한 결론은 아니다.

## 후속 제안 — 아직 적용하지 않음

1. **위치·속도의 연속성부터**: 기존 호스트 피해/저장 권한을 유지하면서 교전 위치·속도 표시를 연속으로 연결한다. 프레임별 위치 차이가 아니라 안정된 이동량과 접지 위상을 사용하되, 장애물 충돌 뒤 발이 계속 달리지 않게 한다. 보행 배율만 제한하고 몸을 계속 빠르게 이동시키면 미끄러짐으로 바뀐다.
2. **사족은 걷기/달리기/돌진 구분**: 기존 골격과 느린/보통 달리기는 보존하고, 빠른 돌진은 큰 보폭·앞뒤 다리의 다른 교대·골반/등 압축·준비와 제동을 갖춘 동작으로 제작한다. 필요한 본/웨이트만 보강한다. 모든 종의 리깅 재제작을 먼저 할 근거는 이번 표본에서 나오지 않았다.
3. **여섯발은 빠른 이동 패턴 보강**: 지지 묶음과 휘두르는 발의 간격·보폭·몸 높이를 속도에 맞춘다. 포유류의 질주를 그대로 복제하지 않는다.
4. **삼족은 이동 성능과 역할을 함께 결정**: 현재 무거운 몸과 짧은 다리를 유지하면 낮은 최고속이 적합하다. 현재 도주 속도가 꼭 필요하다면 다른 추진/큰 디딤 동작을 새로 설계해야 한다. 비공격 생물 전부를 같은 3.5m/s 기준으로 묶는 부분을 검토한다.
5. **도약·무족은 별도 속도 매개변수**: 도약은 한 번 이동거리·비행시간·착지, 무족은 몸통 파동의 진폭/파장/진행 속도와 방향 전환을 연결한다. 모든 유형에 보행 클립 배속 규칙 하나를 적용하지 않는다.

이 목록의 구체적 속도 상한·새 동작 제작은 제안이다. 사용자가 승인한 게임 밸런스 변경으로 기록하지 않는다.

## 후속 논의와 작업 순서

사용자는 시간이 오래 걸리더라도 모든 동물의 현재 리깅에 빠른 달리기 동작을 넣는 방향이 맞는지 물었다. 조사에 따른 권고는 기존 골격을 활용해 **체형별 빠른 이동을 실제 최고속에서 완성한 뒤 전체 동물로 확장**하는 것이다. 기존 `run_loop`의 존재나 전종에 같은 이름의 클립 추가만으로 완료를 판단하지 않는다. 이 후속 논의와 이번 커밋·푸시 요청을 전종 동작 제작 완료로 해석하지 않는다.

1. 대표 5체형에서 위치/속도 추종을 먼저 개선하고 가속·감속·방향 전환을 연결한다.
2. 사족의 질주/돌진, 다족·삼족의 빠른 지지 교대, 도약형의 추진/착지, 무족형의 빠른 파동을 실제 목표 이동량에 맞춘다. 필요한 자세가 나오지 않는 부위만 골격·웨이트를 보강한다.
3. 구조가 호환되는 종끼리 원리를 공유하되 사지 길이·몸 비율·공격 기관 차이를 반영해 전체 동물로 확장한다. 비행·유영형은 지상 달리기와 구분한 추진 동작과 전환을 사용한다.
4. 종별 제작·게임 연결·실제 검수 상태를 구분하고, 피격 후 도주/추격과 공격 준비·타격·회복의 연결을 확인한다. 경사·크기·LOD·협동 경계와 미완료 종은 별도로 남긴다.

**커밋 시 남은 작업:** 위 1~4의 실제 구현, 사족 돌진·삼족 도주의 속도/보폭 조정, 전종 확대, 실제 피격·충돌·저장·협동 확인과 음향 검수. 이번에는 조사 문서·재현 도구·대표 비교 영상만 정리했다.

- 기존 Blender 원본 5개를 읽어 골격/웨이트/클립과 걷기/달리기 10장을 다시 렌더했다. 원본을 저장하거나 재내보내지 않았으며 전후 SHA-256이 같다. [Blender 비교판](media/creature-speed-audit/blender-board.jpg)과 개별 결과 `output/creature-speed-audit-20260913/blender/`에 보존한다.
- 게임 캡처는 5×360=1,800프레임, A/B 각각 1,800개 배우 갱신이다. 연속 위치 대조도 같은 범위를 한 번 측정했다. 원시 프레임/접지 시계열은 `output/creature-speed-audit-20260913/`에 있다. 최초 A/B 하네스에서 걷기 강제 시 접지를 매 프레임 초기화하던 비교 오류를 발견해 하위 클래스로 수정한 뒤 최종 전표본을 다시 촬영했다. 중단한 최초 실행은 최종 결과에 포함하지 않는다.
- 영상은 무음이고 기존 발걸음 호출점을 관찰했지만 음원을 재생/청감 평가하지 않았다. 실제 총기 명중→피격→도주·호스트의 돌진 충돌/피해·게임 저장·협동·경사/굴곡·far LOD·크기 변이·전체 종은 이번 실행 범위가 아니다. 현재 5종의 결과를 5,600동물 전체의 리깅 승인이나 모든 8,000생물의 전투 완료로 확대하지 않는다.
- 한 행동의 범위: 비교는 두 배우의 위치·관절·접지 캐시만 진행한다. 카탈로그/모델은 종 로딩 때 읽고, 월드·승무원·재고·지형 생성·네트워크·게임 저장은 변경하지 않는다. 파일 출력은 검토 프레임·측정 JSON·영상뿐이다. 전종 순회나 전체 회귀를 추가하지 않았다.

실제 동물의 걷기/달리기 전환은 단순한 속도 배수뿐 아니라 사지 교대와 몸통 협응의 변화가 관찰된다([Maes & Abourachid, 2013](https://journals.biologists.com/jeb/article/216/12/2257/11423/Gait-transitions-and-modular-organization-of)). 다족의 빠른 움직임이 포유류처럼 반드시 공중 질주로 바뀌는 것도 아니다([거미 보행 연구, 2011](https://journals.biologists.com/jeb/article/214/20/3433/10466/Biomechanics-of-octopedal-locomotion-kinematic-and)). 외계 생물에 지구 종의 수치를 그대로 적용할 근거로 쓰지 않고 체형별 제작 원칙의 참고로 사용한다. Godot의 [AnimationTree 공식 문서](https://docs.godotengine.org/en/stable/tutorials/animation/animation_tree.html)는 동작 혼합·루트 모션의 구현 수단이며 자연스러운 보폭을 자동 보장하지 않는다. 이번에는 현재 AnimationPlayer/호스트 이동 경로를 유지했다.

재현:

```sh
./tools/godot.sh --script res://tests/render_creature_speed_audit.gd
./tools/godot.sh --script res://tests/render_creature_speed_audit.gd -- --smooth
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/audit_creature_speed_sources.py
/tmp/instagram-promo-venv/bin/python tools/summarize_creature_speed_audit.py
```

마지막 패키저는 Pillow와 imageio-ffmpeg가 설치된 Python을 사용한다. 이는 현재 로컬 실행 환경이며 해당 임시 가상환경 경로가 다른 기계에도 존재한다고 가정하지 않는다.
