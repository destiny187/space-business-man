# Windows 자동 저장 실패 시 진행 유지 — 2026-09-14

사용자 보고: 자동 진행 저장 제출 실패 안내 뒤 게임 전체가 정지했다. 사용자는 자동 저장 실패를 알리되 플레이를 유지하도록 요청했다.

## 원인과 확인 경계

`FrontierCrewAuthority.step_surface`는 `begin_commit`이 거절되면 `stopped=true`로 전체 세션을 중단했다. 검증 거절, 저장 큐 상태, 선행 파일 쓰기 실패가 같은 메시지로 합쳐졌으며 원인이 로그에 남지 않았다. 사용자 저장본과 백업은 유효했고 복사본 쓰기/교체도 성공했다. 당시 제출이 거절된 구체적인 이유는 복구할 수 없으며 파일 손상이나 디스크 부족으로 단정하지 않는다.

## 변경·행동 범위

- 자동 진행 제출/비동기 쓰기 실패는 미확정 후보를 발행하지 않고 기존 세계를 유지한다. 이동과 메뉴, 세션 연결을 유지하고 자동 진행은 5초 뒤 새 상태를 기준으로 다시 시도한다. 실패 구간의 생산 시간을 소급 지급하지 않는다.
- 대기 중인 거래의 쓰기가 실패하면 해당 요청은 실패 응답을 받는다. 성공 영수증과 재화 변경은 확정하지 않는다. 다음 요청과 재시도는 기존 확정 상태에서 처리한다.
- 주기/항해 체크포인트 실패도 세션을 끊지 않는다. 원자 저장·백업·기존 저장 보존은 유지한다. 저장 실패 중에는 최신 이동 등의 진행이 디스크에 남지 않을 수 있다.
- 종료 저장이 실패하면 실행 상태를 유지해 다시 시도할 수 있게 한다. 저장에 실패했는데 종료 완료로 처리하지 않는다.
- 화면에는 저장 실패·재시도 안내를, 로그에는 단계·실제 저장 오류를 남긴다. 같은 오류 알림은 10초 간격으로 제한한다. 호스트 알림은 게스트에게도 전달하되 연결 종료 신호로 보내지 않는다.
- 오류 처리에서 전체 세계 복사/재생성이나 UI 전체 갱신을 추가하지 않았다. 기존 후보 참조를 해제하고 실패 응답·알림만 전달한다. 기존 제출 검증·스냅샷 복사·파일 저장 비용 자체는 남는다.

## 확인

`check_autonomous_save.gd`에서 제출 거절, 존재하지 않는 경로의 실제 쓰기 실패, 실패 후 이동, 재시도 간격, 복구 후 결과 한 번 반영, 체크포인트/종료 실패 후 세션 유지와 기존 저장 순서·백업 검사를 확인했다. 사용자 원본 저장은 변경하지 않았다.

Windows Godot 4.7.1 / D3D12 Forward+ 실제 창에서 사용자 저장 복사본을 열고 자동 진행 제출을 강제로 거절했다. 실패 안내가 표시되고 `active=true`, `stopped=false`, 1초 동안 제출 1회임을 확인했다. 쓰기를 복원한 뒤 6초 후에도 세션이 유지되고 실제 체크포인트 저장이 성공했다. 검사 후 안내문만 짧게 정리했다. 종료 시 기존 ObjectDB 경고가 있었으며 저장 실패는 의도한 주입 로그로 구분한다. 전체 회귀·다중 클라이언트·장시간 디스크 장애 검사는 수행하지 않았다.
