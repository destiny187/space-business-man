# 지역 테라포밍·지표 공급·행성지도 구현

2026-09-09. 사용자 요청에 따라 [지역 테라포밍 설계](../game/20-regional-terraforming-and-surface-supply.md)의 첫 T1/T2 사업 묶음을 현재 원정에 연결했다. T3 이상 시설의 설계도 획득 콘텐츠는 다른 작업의 담당이며, 여기에서는 제작 권한의 잠금·등록 접점을 마련했다.

## 적용 범위

새 은하의 생성 설정에 `regional_rules`를 저장한다. 기존 은하는 미방문 지표까지 기존 규칙을 사용하며, 이미 있는 광맥·고갈·굴착·시설·계약·지하를 재배치하지 않는다. 기존 은하에서도 Tab 지도는 지형과 확인된 정보를 표시한다. 태양계 참조 천체에는 새 테라포밍 사업을 추가하지 않는다.

| 항목 | 이번 실제 구현 |
| --- | --- |
| 첫 T1 사업 | 착륙지 한 현장·복원 구획 한 곳, 기존 기본 환경 조건 |
| T2 사업 | 착륙 정착지·급수 복원지·토양 복원지 세 현장 |
| 현장 거리 | 외부 현장은 착륙지에서 약 520~650m, 시드·지형에서 평탄한 후보 선택 |
| 공간 단위 | 현장 반경 65m, T2 현장마다 중심/사방 28m 위치의 5개 복원 구획 |
| 시설 영향 | 시설에서 48m 이내 구획에 처리량 배분; 다른 현장의 환경은 변경하지 않음 |
| 현장 공급 | 현장별 창고·재고·보관 장비·전력·시설·로봇·제작 작업 분리 |
| 완료 판정 | T2 현장별 최소 3구획의 30초 안정화; 모든 현장이 완료되어야 계약 정산 |
| 중간 대금 | 두 외부 현장 각각 전체 계약 대금의 20%, 한 번만 지급 |
| 최종 대금 | 전체 대금 또는 생산 거점 유지 대금에서 중간 지급액 차감 |

거리·반경·구획·단계 지급 수치는 `data/regional_terraforming.json`에 둔 초기 밸런스다. 계약에서 요구하는 현장은 시드로 고정한다. 쉬운 한 현장에 시설을 몰아 다른 현장의 조건을 대신 충족할 수 없다.

착륙 정착지는 대기·온도·수자원 60점과 생태 20점의 기본 조건을 사용한다. T2 정착지의 염류/토양은 기본 목표에서 시작한다. 급수 현장은 수자원 60점·염류 20 이하, 토양 현장은 토양 60 이상을 요구한다. 외부 현장의 완료는 해당 문제의 해결이며, 그곳의 전체 환경 적합도 100%를 뜻하지 않는다. 원광·얼음·필터·토양 제품과 Mk.2 설비는 기존 레시피를 재사용한다.

## 수급과 화면

지표 광맥은 기반 지형의 고도·경사와 행성 지질에 따라 암반·분지·능선·빙결·열 지질 후보에 집중한다. 640m 단위의 공급 군집을 사용하고 밖에는 희소 광맥을 남긴다. 각 행성이 허용하는 광물 풀 안에서 선택하며 기존 보장 외곽 처리재도 유지한다. 군집 약 80%는 목표 비중으로, 전 시드에서 정확히 같은 비율을 보장하지 않는다. 지하 `ore1` 생성·ID·배치는 그대로 두고 새 지표에는 `surf1` ID를 사용한다. 실제 광맥은 소속 스트리밍 타일을 벗어나지 않는다.

Tab은 지상에서 행성지도를 열고, 우주에서는 기존 항해 화면을 연다. 지도에서 지형·자원 후보·복원 구획·실제 시설·승무원·착륙선·개인 목적지를 볼 수 있다. 휠/버튼 확대, 드래그 이동, 클릭 목적지와 현재 위치 복귀를 지원한다. 같은 지표의 약 ±8.2km 지원 영역을 표시하며 구형 행성 전체를 가상 지도로 꾸미지 않는다. 아직 확인하지 않은 광맥은 후보로 표시하고, 실제 E 스캔으로 확인한 지표 광맥만 정확한 지점을 표시한다. 지하 전체 좌표는 공개하지 않는다.

지역 재고와 전력을 분리했으므로 현장에서 쓸 물자는 직접 운반해야 한다. 로버·플레이어 운송과 기존 로봇 작업을 재사용한다. 지도 점선은 작업 현장 사이의 계획선이며 자동 운송망이 아니다. 현장 창고 용량도 현재 현장만 집계한다.

지표 셰이더·대기·풀/나무·습윤 표현이 지역 복원 구획을 읽는다. 외부 현장이 회복돼도 착륙지와 미처리 지표 전체가 동시에 녹색으로 바뀌지 않는다. 기존 Blender 모델·INK 재질·시설 동작·ElevenLabs 음원 연결을 재사용했다. 새 모델·음원 제작은 하지 않았다.

## T3 설계도 연결 계약

`data/facility_blueprints.json`에 현재 존재하는 **Mk.3 제작소**의 `facility_factory_mk3`를 등록했다. 새 은하에서 Mk.2→Mk.3 시설 업그레이드는 이 공동 사용권을 요구하고, 생산 화면에도 설계도 잠금을 표시한다. T1/T2 기초 개방·기존 재료·제작소 조건·예약은 유지한다. 기존 은하의 상위 제작 권한은 소급해서 잠그지 않는다.

획득 담당 코드는 호스트에서 다음 접점을 호출한다.

```gdscript
FrontierFacilityBlueprints.register(world, "facility_factory_mk3", "exploration", discovery_id)
# 정거장 거래라면 source는 "station", reference는 해당 거래의 식별자.
```

사용권은 `world.expedition_research.licenses[id] = {source, reference}`로 저장되고 기존 원정 저장 검증을 통과한다. 중복 등록은 false를 반환한다. 플레이어가 임의로 사용권을 주는 RPC는 추가하지 않았다. 획득 담당자는 발견 완료 조건 또는 정거장 지출 권한·가격·중복 여부를 확인하고, 같은 호스트 저장 트랜잭션 안에서 보상/크레딧 차감과 등록을 확정해야 한다.

현재 탐험 보상과 정거장 구매를 실제로 연결한 상태는 아니다. 따라서 새 세계에서 해당 사용권이 등록되기 전에는 Mk.3 제작소가 잠긴다. T3~T5 새 전문 시설을 추가할 때 정의 데이터·시설 업그레이드/건설 조건·획득 콘텐츠를 함께 등록해야 한다. 아직 없는 모든 T3 시설이 이미 구현·해금됐다는 뜻은 아니다.

## 확인한 범위

Godot 4.7.2, Apple M2, Forward+ / Metal의 실제 창에서 대표 새 T2 행성을 확인했다. `check_regional_terraforming.gd`의 27개 확인은 지역 창고 건설·실제 입고 거래·외부 건설 미리보기·지역 재고 분리·시설 영향 범위·다른 지역 보존·중간 보상 중복 방지·최종/보유 정산 금액·JSON 저장 검증·설계도 등록/중복/해금·기존 세계 권한 보존에 한정한다. 같은 타일의 변경 전후 지하 광맥 전체 데이터 일치도 확인했다.

`check_regional_play.gd`에서 착륙, Tab 열기/닫기와 조작 차단, 960×640 지도 배치, 외부 현장 스트리밍, 15개 독립 복원 구획의 실제 지표 렌더, 지역 저장 검증을 확인했다. 준비 로딩이 끝난 후 캡처하도록 확인 도구의 대기 조건을 보완했다.

이 검사에서 재료·이동 위치와 외부 현장의 완료 환경은 시험 데이터로 준비했다. 처음부터 수동 채집·가공·운반하여 T2 계약을 완주한 검증은 아니다. 6인 분산 접속·장시간 부재중 생산·전 시드 자원량/가격 균형·Windows 실행·주관적인 음향 청감은 확인하지 않았다. 문서만 바꾼 항목에 게임 검증을 확대하지 않았다.

## 남은 범위

T3 원인/유입원 처리, T4 극한 환경의 정격·전문 소모품, T5 광역 장부·유지 평가는 R05~R07의 후속 구현이다. 현재 T3 이상은 기존 사업 규칙을 사용하며 새 다지역 완료 조건을 적용하지 않는다. 자연 유역과 모든 지역의 실제 물 양 보존을 결합한 급수망, 자동 운송, 구형 행성 전체 지도, 기존 세계의 새 지역 계약 이행은 추가하지 않았다. 기존 물리 수면과 지역 복원 습윤 표현을 완전한 다지역 수문 시뮬레이션으로 설명하지 않는다.
