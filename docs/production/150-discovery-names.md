# 생물 발견 번호와 도감 이름 변경

2026-09-12 사용자 요청. 명명 규칙은 [생태 소관](../game/09-discovery-research-and-ecology.md)에 둔다.

## 구현

- `species_names.gd`가 원정의 생태 저장에 기본종별 영구 번호와 사용자 이름을 분리한다. 카탈로그의 제작 이름, 종 ID·형태·원산지는 수정하지 않는다.
- 지상 생물 스캔, 생물 사건의 실제 분석, 탐험 표본 확보, 거대행성 대기층 관측은 기존 `FrontierEcology.scan` 성공 경로에서 번호를 공유한다.
- J → 발견 도감 → 생물 선택 → 이름 바꾸기에 입력·저장·번호로 되돌리기·취소를 연결했다. 일반 열람에는 편집 입력란을 펼치지 않는다. 이름을 바꿔도 도감 정렬은 번호 순서를 유지한다.
- 입력 중 새 관측 페이지가 도착해도 입력과 한글 조합 포커스를 보존한다. 작은 창에서는 3D 미리보기 높이를 조정하고 편집 컨트롤을 스크롤 영역 안으로 보여 준다.
- 호스트의 `ecology_rename` 거래에서 발견 여부·길이·제어 문자·이전 이름을 검사한다. 다른 승무원이 먼저 바꾼 이름을 오래된 요청으로 덮어쓰지 않으며 저장 실패를 성공으로 표시하지 않는다. 재전송은 기존 영수증 규칙을 사용한다.
- 스캔 카드·도감·생물 사건 상세·표본 아이템·기초 연구/이식 선택·현장 공학 표시를 연결했다. 제작용 전체 생물 갤러리의 내부 이름은 보존한다.
- 클라이언트에는 현재 행성과 실제 소지/화물·연구에 필요한 이름만 전달하고 전체 도감은 기존 페이지 요청으로 읽는다. 이름 변경 번호로 UI 갱신을 알린다.
- 예전 저장은 검증을 통과한 후 기존 관측 순서로 번호만 추가한다. 관측·실물 표본·분석·이식 기록을 재생성하지 않는다.

## 확인

`tests/check_species_names.gd`의 최종 실행 30항목, 실패 0. 별도 저장의 자연 배정 동물에 실제 E 스캔을 수행해 `ANI-001`을 확인했다. 같은 행성의 저장에는 `ANI-002`, `PLT-001`, `MIC-001`도 부여됐다. 중복 관측의 번호 보존, 구 저장 이행, 도감에서 한글 이름 변경·번호 검색·번호로 복원, 스캔 결과 반영·4초 뒤 숨김, 저장 재로드와 다시 시작한 호스트의 도감 페이지를 확인했다. 미발견 종과 오래된 이전 이름으로의 변경은 거절됐다.

960×640 실제 창에서 이름 입력·선택 표본의 INK 미리보기와 변경 후 상세를 캡처했다. 처음에는 버튼이 스크롤 영역 아래로 일부 잘려 미리보기 높이와 편집 위치를 수정했다. 표본 이름 확인의 첫 실패는 잘못 만든 표본 ID 때문이었으며 실제 표본 주소 형식으로 수정한 최종 실행에서 통과했다. 입력 중 기록 갱신에 따른 문자열/포커스 보존을 확인했으며 운영체제별 IME 조합 전수 검사는 수행하지 않았다.

로그: `output/species-names-final-20260912.log`. 대표 화면: `docs/production/media/species-names/`. 새 모델·음원은 제작하지 않았다. 실제 다중 클라이언트, 대기층/사건별 전체 재생과 8,000종 전수 검사는 수행하지 않았다.
