# A04 — 시각적 신체 증강

2026-09-08 [A01~A09 계획](../planning/12-augmentation-and-research-commits.md)의 A04를 구현했다. **기본선 증강 장치에서 자기 캐릭터의 부위와 배낭 보석을 선택해 실제 증강을 실행**할 수 있다. 표본 분석·공동 연구·T3 해금은 A05~A07 범위다.

## 플레이 흐름

1. 선내 또는 착륙선 측면의 증강 장치를 보고 F를 누른다.
2. 장치 안 자기 탐험복 모델의 **다리·기동 / 팔·전투 / 흉부·생명**을 연결 표식으로 선택한다. 실제 개인 색상·관절 모델을 사용한다.
3. 내 배낭의 사파이어·루비·에메랄드를 클릭하거나 투입 슬롯에 끌어놓는다. 준비한 보석이 실제 장치 트레이에도 나타나고 스캔 헤드가 움직인다. 이때 재고는 소비하지 않는다.
4. 현재/다음 이동속도·피해 배율·최대 체력, 단계 눈금과 필요 수량을 보고 실행한다. 기본 값은 A02의 단계당 비용과 상한을 그대로 사용한다.
5. 요청 중에는 재실행·부위 변경을 막는다. **해당 요청의 호스트 저장 응답 이후에만** 완료 표시·입자·캐릭터 동작·완료음을 재생한다. 잘못된 보석·부족·거절은 별도 색·이유·효과음으로 표시한다.

I → **신체** 탭에서는 실제 자기 캐릭터와 세 계열의 현재 단계·능력을 열람한다. 이 화면에는 원거리 실행 버튼이 없다. 장비 장착을 바꿔도 증강은 같은 호스트 세계의 캐릭터에 유지된다.

## 구현 경계

- `augmentation_panel.gd`가 지역적인 준비·요청 순번·결과 상태를 소유한다. 보석 차감과 단계 저장은 기존 A02 호스트 거래만 수행한다. 다른 요청의 응답을 증강 완료로 취급하지 않는다.
- 창을 닫아도 발송한 요청의 결과는 처리한다. 닫힌 화면에서 완료음을 재생하거나 창을 강제로 다시 열지 않는다. 실패 시 준비 상태를 풀고, 성공 뒤 새 스냅샷을 기다린 후 다음 거래를 허용한다.
- `augmentation_body.gd`는 실제 모델에 연결된 부위 선택, `augmentation_slot.gd`는 보석 드롭을 담당한다. 공통 FIELD 색·폰트와 `FrontierItemTile`을 사용한다.
- A03 Blender 장치·리깅된 Surveyor 탐험복·기존 광물 모델을 재사용한다. 신규 3D 자산을 만들지 않았다. `crew_station.gd`의 트레이에 같은 보석을 배치하고 미리보기의 스캔/트레이 동작을 현재 이용 중인 장치에 연결했다.
- 선택/처리/성공 연출은 이용자의 로컬 화면에 표시한다. 다른 승무원에게 장치를 독점시키지 않는다. 다른 클라이언트에 짧은 장치 연출을 공유하는 기능은 이번 범위에 없다.
- 별도 SubViewport는 화면을 닫으면 렌더를 중단한다. 메뉴 입력 차단은 기존 공통 경로를 사용한다.

## 음향

기존 ElevenLabs 음원을 재사용했다. [출처와 매핑](../../audio/manifests/crew-stations-reuse.json)은 기존 생성 이력을 참조한다.

| 상태 | 음원 | 연결 |
| --- | --- | --- |
| 보석 준비 | `sfx_pickup_resource` | UI -12dB, 단발 |
| 응답 대기 | `sfx_robot_charge` | SFX -27dB, 반복; 응답/닫기에서 정지 |
| 저장 성공 | `sfx_factory_complete` | UI -12dB, 실제 성공 응답 뒤 단발 |
| 거절 | `sfx_build_invalid` | UI -12dB, 단발 |

실제 게임의 UI 버스에서 4.32초를 녹음했다. 48kHz 스테레오 PCM16, 정규화 피크 0.200, RMS 0.030으로 신호와 클리핑 부재를 확인했다. [게임 재생 녹음](media/augmentation-a04/augmentation-ui-cues.wav). 이 녹음은 UI 준비·완료·거절이며 SFX 버스의 대기 루프 녹음이나 모든 장치/환경의 청음 승인으로 확대하지 않는다.

## 최소 실행 확인

Godot 4.7.2 Metal Forward+ 실제 창의 **21개 확인, 실패 0**. 최신 로딩·항해 커밋 `320f4c9e` 위의 기본 원정 장면에서 확인했다.

자기 캐릭터/장치 화면, 클릭 준비의 비소비, 슬롯 드롭 경로와 잘못된 보석, 세 계열 실제 구매, 완료 효과/음원과 중복 클릭 방지, 호스트 거절, 960×640 화면, 장비 변경 뒤 I 능력, 구매 후 실제 지상 속도·장착 무기 피해·체력 HUD, 착륙 시 남은 보석, 저장 파일 읽기·호스트 재개를 검사했다. 늦은 응답·관련 없는 응답·닫힌 창의 음향 억제는 요청 순번/응답 fixture로 확인했으며 실제 지연 ENet 검사가 아니다.

초기 저장 검사는 종료 후 배낭이 비어 있는 것을 실패로 판정했다. 실제로는 기존 퇴장 규칙이 보석을 회수 상자에 보존하고 있었다. 저장 JSON의 숫자 형식을 고려해 단계별 정수 조회와 회수 상자 재고를 확인하도록 검사만 수정했다. **저장·퇴장 규칙이나 보석 거래를 바꾸지 않았다.** 발견 경로를 좁혀 재확인한 뒤, 병행 로딩 변경의 커밋 후 최신 진입 경로를 최종 확인했다.

검사에는 격리 세계와 준비한 보석·펄스 장비를 사용했다. 세 보석을 직접 채굴하는 전체 원정·원격 6인·장시간 지연/재접속·고티어 연구는 이번에 검증하지 않았다. 테스트용 보석은 일반 새 게임에 지급하지 않는다.
