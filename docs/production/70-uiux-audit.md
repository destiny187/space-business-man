# 자원 확장과 조작 편의 중심 UI/UX 조사

2026-09-08. 사용자의 요청은 현재 어색하거나 불편한 화면을 찾아 보고하는 것이다. 아래 개선안은 **설계 제안**이며 구현 완료 또는 신규 게임 규칙의 확정을 뜻하지 않는다. 기준은 [FIELD v1](22-uiux-guide.md)이다.

이후 사용자 승인: 전체 항목을 [UX01~UX03](../planning/13-uiux-renewal-commits.md)으로 나누어 개발한다. 아래는 수정 전 조사 기록이며 [UX01 완료 범위](71-resource-browser-and-cargo.md)와 구분한다.

## 결론

공통 색상과 이미지 격자는 마련됐지만, 자원 찾기·선택 상세·제작·운송을 이어 주는 구조가 부족하다. 콘텐츠마다 목록과 버튼을 추가하면서 화면 밀도와 진입 경로가 달라졌다. **자원 검색/분류와 선택 상세를 공통화하고, 현재 행동에 필요한 정보만 보여주는 작업**을 먼저 권한다.

## 확인 범위와 한계

- 현재 기본 `crew_expedition.tscn` 경로를 Godot 4.7.2 Metal Forward+ / Apple M2의 실제 창에서 촬영했다. 건설, 제작소의 표시 탭, J의 표시 탭, 아이템, 행성/선박 화물을 살폈다.
- 1280×800과 960×640을 확인했다. 기존 A06 검증용 세계/프로필의 복사본 `/tmp/uiux-audit-0908`을 사용했고 `--crew-ui-test` 및 전용 저장 경로를 검사했다. 실제 사용자 플레이 저장을 열지 않았다.
- 자원 증가 화면은 기존 광물 19종과 현재 병합된 제품 12종에 수량을 넣은 **인위적인 UI 관찰 상태**다. 가방/창고 용량을 초과하며, 정상 채집으로 이 상태까지 도달했다는 뜻이 아니다. 품목 증가에 대한 표시 구조만 확인했다.
- 조사 기록의 24개 제한, 항해의 자원 4개 제한, 정비·교역 구조, 일부 잘못된 안내는 코드 확인이다. 해당 한계까지 자연 플레이하거나 모든 거래를 수행하지 않았다.
- 이번에는 코드 수정·전체 회귀·패드·키보드 전용 조작·6인 검증을 수행하지 않았다. 조사용 임시 스크립트의 첫 실행은 함수명 오류로 장면 진입 전에 종료했고, 수정 후 촬영은 완료됐다.

## 먼저 개선할 항목

### U01 — 자원 격자에서 물건을 찾기 어렵다

**우선 / 실제 화면 + 코드.** 아이템과 화물에 검색·분류·사용자 정렬이 없다. 내부 ID 순으로 쌓이며 광석·보석·가공품이 섞인다. 수량이 있는 타일은 이름 대신 수량만 그리므로 낯선 광물은 하나씩 마우스를 올려 알아봐야 한다. 광물 증가가 곧 탐색 비용 증가로 이어진다.

제안: 기본은 보유 아이템만 표시하고 `전체 / 광물 / 보석 / 부품 / 장비` 분류와 이름 검색을 둔다. 정렬은 이름·수량·최근 획득 정도로 제한한다. 아이콘 아래 짧은 이름과 수량을 함께 표시하고 정확한 이름은 선택 상세로 보완한다. 가방의 실제 슬롯과 중첩 규칙은 유지하며, 도감의 품목 목록과 구분한다.

근거: [아이템 격자](../../우주-비즈니스/scripts/ui/equipment_panel.gd), [타일의 수량/이름 양자택일](../../우주-비즈니스/scripts/ui/item_tile.gd), [ID 정렬](../../우주-비즈니스/scripts/domain/item_inventory.gd).

![품목을 늘린 행성 창고](media/uiux-audit/cargo-many-resources.png)

### U02 — 건설·제작 상단에 모든 자원이 반복 나열된다

**우선 / 실제 화면 + 코드.** 창고와 배낭의 전체 사전을 `cost_text`로 출력하며 0개 품목도 포함한다. 현재도 작은 아이콘과 숫자의 긴 줄이고, 품목을 늘리면 여러 줄이 되어 카드가 아래로 밀린다. 건설은 가방 실물을 소비하는데 창고 전체 재고까지 동급으로 노출된다.

제안: 상단은 저장 위치·사용 칸 등 짧은 요약으로 고정하고, 선택한 시설/제품에 필요한 재료의 `보유 / 필요`만 본문에 표시한다. 전체 자원 조회는 창고 화면으로 연결한다. 재료를 펼쳐도 실행 버튼과 선택 대상은 보이게 유지한다.

근거: [사업 패널의 stock.value](../../우주-비즈니스/scripts/ui/business_panel.gd), [전 품목을 결합하는 cost_text](../../우주-비즈니스/scripts/domain/catalog.gd).

![자원이 늘면 건설 카드가 내려가는 화면](media/uiux-audit/build-many-resources.png)

### U03 — 화물 이동의 선택·수량·빠른 조작이 분산된다

**우선 / 실제 화면 + 코드.** 행성 창고에서는 왼쪽 상세 전체를 숨기므로 선택한 물건의 이름·수량 상세와 Shift+클릭 안내도 사라진다. 선박 화물에서는 같은 정보가 선체 아래에 나온다. 공통 상단 수량 입력은 기본 20이며 `선택 자원 입출고`가 선택 후 방향 버튼으로 바뀐다. 빠른 이동은 구현돼 있으나 화면만 보고 찾기 어렵다.

제안: 양쪽 보관함 제목을 고정하고, 공통 선택 줄에 `물건 이름 / 출발 → 도착 / 옮길 수량`을 표시한다. 기본 클릭은 선택으로 유지하고 Shift+클릭 안내를 항상 같은 위치에 둔다. `1 / 중첩 / 최대`와 숫자 입력을 제공하되 최대는 실제 보유량·받는 쪽 여유를 반영한다. 모든 자원 이동과 선택 품목 이동을 명확히 구분한다.

근거: [화물 선택 상세와 _refresh_storage](../../우주-비즈니스/scripts/ui/equipment_panel.gd).

### U04 — 작은 화면에서 공간 배분과 하단 배치가 깨진다

**우선 / 실제 화면.** 960×640에서 아이템 하단 안내를 번호 슬롯이 가리고, 선박 화물은 큰 제목·상단 조작 영역 때문에 격자의 한두 줄만 보인다. 아이템 화면은 미리보기·목록·상세 3열을 유지해 관리에 쓸 폭이 줄어든다.

제안: 좁은 화면은 목록 중심으로 두고 선택 상세를 접거나 전환한다. 미리보기는 필요할 때 확대한다. 장착 슬롯을 메뉴의 실제 하단 레이아웃에 포함해 안내와 공간을 공유하지 않게 한다. 제목/도구/실행 영역은 고정하고 목록만 스크롤한다.

근거: [아이템 _layout 및 별도 hotbar](../../우주-비즈니스/scripts/ui/equipment_panel.gd).

![960×640 아이템창 하단 겹침](media/uiux-audit/inventory-960.png)

### U05 — 조사 목록은 오래된 발견을 다시 찾는 도감이 되지 못한다

**우선 / 코드, 빈 화면 렌더.** 생태 조사 탭에 광물·생물 기록이 섞여 있고, 병합 배열의 마지막 24개만 보여 준다. 전체 기록 검색·페이지 이동이 없다. 두 기록을 합친 배열은 시간순 정렬도 없으므로 제목의 ‘최대 24개’가 최근 발견 24개를 정확히 뜻하지 않는다. 데이터 삭제가 아니라 UI에서 접근이 제한되는 문제다.

제안: 발견 기록을 모두 다시 찾을 수 있는 도감을 마련한다. `광물 / 생물`과 `현재 행성 / 전체 발견` 정도를 기본 필터로 두고 이름 검색을 공유한다. 보유 0개라도 이미 발견한 항목은 도감에 남긴다. 발견 위치·필요 장비·알려진 용도를 선택 상세에 둔다. 미발견 자원 위치를 노출해 탐험을 대신하지 않는다.

근거: [survey_journal.gd의 entries.slice 및 자동 선택](../../우주-비즈니스/scripts/ui/survey_journal.gd).

## 권장 개발 순서 — 제안

1. **자원 탐색 공통화:** U01/U03/U08. 이름·수량·분류·검색·선택 상세를 먼저 마련하고 아이템/창고에 적용한다. 품목 0개·다수 품목·이동 후 선택 유지·같은 자원 여러 중첩을 최소 확인한다.
2. **화면 배치 정리:** U02/U04/U09/U12. 전체 자원 나열을 제거하고 관련 재료만 표시한다. 작은 창의 겹침·카드 배경/제목·잘못된 안내를 정리한다.
3. **기록과 제작 동선:** U05/U06/U10/U11. 도감 전체 탐색, 제작 분류, 알려진 사용처/발견 위치 연결을 적용한다.
4. **성장 메뉴와 정비:** U07/U13. 신체·장비·공동 연구의 역할 및 작업 장소를 확정한 뒤 기능을 재배치한다.

기본 화면에는 단순한 선택지만 두고 검색·상세로 확장한다. 안내 문장을 더 늘려 복잡한 구조를 설명하는 방식은 피한다. 아이템 격자, 드래그와 클릭 병행, 실물 증강 장치, 발견한 광물만 로봇 작업에 표시하는 원칙, 이미 있는 항해 검색·즐겨찾기는 유지할 기반이다.
