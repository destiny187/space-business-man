# 용암 지표 품질과 환경 텍스처 효율

2026-09-11 사용자 요청: 남은 순수 성능 개선을 계속하고, 저품질로 보이는 용암 지표를 개선한다. M2의 높음 60 FPS를 맞추기 위해 품질을 낮추는 작업이 아니다. 기존 [프레임 안정화 P01~P06](130-frame-stability.md)의 후속이며 INK v1을 유지한다.

## P07 — 실제 복원 구역만 환경 텍스처로 전송

기존 코드는 환경 revision이 바뀔 때 행성 전체를 덮는 RGBAF 두 장과 R8 한 장을 새로 만들었다. 셀 크기 24m·extent 8,192m인 시설 표본은 실제 153칸인데 매번 684×684를 할당했다. 복원 칸의 최소 경계와 빈 테두리 한 칸만 담고, 월드 좌표 원점·크기를 셰이더에 전달하도록 변경했다.

- 셀 해상도·부동소수점 채널·온도/수질/토양/오염 판정은 그대로다. 시뮬레이션·저장 주기와 거래 확정 순서는 변경하지 않았다.
- 경계가 같으면 기존 ImageTexture를 갱신한다. 값이 같은 채널과 변하지 않은 마스크는 업로드하지 않는다.
- 재질이 캐시를 소유하므로 별도 월드의 같은 행성 ID/revision이 전역 캐시의 이전 픽셀을 공유하지 않는다.
- 해당 표본의 이미지 원시 데이터는 15,439,248→8,976바이트, 684×684→17×16이다. 멀리 떨어진 복원 구역으로 경계가 넓어지면 절감 폭이 작아지며, 모든 행성의 고정 절감량이 아니다.

### 확인

`check_terraform_atlas.gd`로 원본 153칸의 float 채널 일치, 빈 테두리, 온도 변경 시 텍스처/마스크 재사용, 재질 간 분리, 빈 구역, 이전 revision 복귀 6개를 통과했다. 별도 실제 Forward+ 창에서 원본 전체 텍스처와 축소 텍스처의 월드 투영을 비교했다. 음수 좌표의 복원 구역에 칸별 수질·생태·염도·오염을 다르게 지정했고, **1000×800 렌더의 픽셀 데이터가 완전히 동일**했다.

시설 7개·생물 0·야간 세계의 복사본을 같은 위치와 입력으로 짧게 측정했다. Apple M2 10코어 GPU/24GiB, Godot 4.7.2 Metal Forward+, 1280×800, 보통·배율 100%·MSAA 2×, VSync/상한 해제다.

평균 FPS의 큰 개선이나 끊김 해소로 해석하지 않는다. 공유 개발 환경의 짧은 단일 표본이며 P07 초기 구간에는 관련 headless 검사가 겹쳤다. 이동 구간에는 끝나 있었다. GPU 타이머는 지원되지 않아 특정 패스 시간을 확정하지 않는다. 종료 시 ObjectDB 경고 1개씩이 있었고 전체 회귀·다중 클라이언트 검사는 실행하지 않았다.
