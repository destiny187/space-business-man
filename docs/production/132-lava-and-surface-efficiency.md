# 용암 지표 품질과 환경 텍스처 효율

2026-09-11 사용자 요청: 남은 순수 성능 개선을 계속하고, 저품질로 보이는 용암 지표를 개선한다. M2의 높음 60 FPS를 맞추기 위해 품질을 낮추는 작업이 아니다. 기존 [프레임 안정화 P01~P06](130-frame-stability.md)의 후속이며 INK v1을 유지한다.

## P07 — 실제 복원 구역만 환경 텍스처로 전송

기존 코드는 환경 revision이 바뀔 때 행성 전체를 덮는 RGBAF 두 장과 R8 한 장을 새로 만들었다. 셀 크기 24m·extent 8,192m인 시설 표본은 실제 153칸인데 매번 684×684를 할당했다. 복원 칸의 최소 경계와 빈 테두리 한 칸만 담고, 월드 좌표 원점·크기를 셰이더에 전달하도록 변경했다.

- 셀 해상도·부동소수점 채널·온도/수질/토양/오염 판정은 그대로다. 시뮬레이션·저장 주기와 거래 확정 순서는 변경하지 않았다.
- 경계가 같으면 기존 ImageTexture를 갱신한다. 값이 같은 채널과 변하지 않은 마스크는 업로드하지 않는다.
- 재질이 캐시를 소유하므로 별도 월드의 같은 행성 ID/revision이 전역 캐시의 이전 픽셀을 공유하지 않는다.
- 해당 표본의 이미지 원시 데이터는 15,439,248→8,976바이트, 684×684→17×16이다. 멀리 떨어진 복원 구역으로 경계가 넓어지면 절감 폭이 작아지며, 모든 행성의 고정 절감량이 아니다.

### 확인

`check_terraform_atlas.gd`로 원본 153칸의 float 채널 일치, 빈 테두리, 온도 변경 시 텍스처/마스크 재사용, 재질 간 분리, 빈 구역, 이전 revision 복귀 6개를 통과했다. 별도 실제 Forward+ 창에서 원본 전체 텍스처와 축소 텍스처의 월드 투영을 비교했다. 음수 좌표의 복원 구역에 칸별 수질·생태·염도·오염을 다르게 지정했고, **1000×800 렌더의 픽셀 데이터가 완전히 동일**했다.

시설 7개·생물 0·야간 세계의 복사본을 같은 위치와 입력으로 짧게 측정했다. Apple M2 10코어 GPU/24GiB, Godot 4.7.2 Metal Forward+, 1280×800, 보통·배율 100%·MSAA 2×, VSync/상한 해제다.

| 항목 | 변경 전 | P07 |
| --- | ---: | ---: |
| 정지 12초 평균 FPS | 35.6 | 35.0 |
| 정지 p95 | 77.7ms | 77.3ms |

평균 FPS의 큰 개선이나 끊김 해소로 해석하지 않는다. 공유 개발 환경의 짧은 단일 표본이며 P07 초기 구간에는 관련 headless 검사가 겹쳤다. 이동 구간에는 끝나 있었다. GPU 타이머는 지원되지 않아 특정 패스 시간을 확정하지 않는다. 종료 시 ObjectDB 경고 1개씩이 있었고 전체 회귀·다중 클라이언트 검사는 실행하지 않았다.

로컬 자료: `output/lava-performance-20260911/{before,atlas}/results.json`, `atlas-test.log`, `atlas-render.log`, `atlas-render-{before,after}.png`. 테스트 저장과 설정은 output의 복사본이며 사용자 저장을 바꾸지 않았다.

## V01 — 판 구조와 고온부를 공유하는 용암 재질

넓고 반복적인 사인 곡선의 발광선을 제거했다. Blender에서 뒤틀린 주기적 보로노이 판 20개/4m, 갈라진 틈, 가장자리 융기, 식은 흐름 주름을 만든 `lava_crust.png`로 교체했다. R/G는 동일 높이장의 법선, B는 높이/명암, A는 거칠기다. 거칠기가 낮은 틈 바닥을 발광 영역에도 사용하므로 발광 전용 텍스처를 추가하지 않는다. 판의 넓은 어두운 면을 유지하고, 고온 중심과 식은 가장자리·지역별 활동 차이·느린 작은 밝기 변화를 적용했다.

- 제작 스크립트: `tools/build_volcanic_surface.py`; 원본: `art/blender/surface-materials/volcanic-crust.blend`; 생성 정보·해시: 같은 경로의 JSON.
- 기존 10개 레이어·1024×1024·RGBA8+mipmap 배열에서 용암 한 장만 교체했다. 기존 lava 원본은 비교용으로 보존한다. 저장된 지형·광맥·환경 수치와 충돌은 변경하지 않는다.
- 공통 INK 명암·윤곽선과 기존 월드 좌표 삼면 투영을 사용한다. Blender 검수 메시의 변위는 제작용 미리보기이고, 게임에서는 표면 법선·색·거칠기로 표현한다. 새 지형 메시나 용암 유체 시뮬레이션을 추가한 것이 아니다.
- 근접에서는 기존 암반 샘플을 재사용한다. 용암의 중거리 암반 샘플만 최대 140m까지 유지하고 70~140m에서 발광을 점차 줄인다. 원거리에는 추가 퇴적물 샘플을 하지 않는다. 미프맵과 픽셀 변화 폭으로 가는 선의 번쩍임을 억제한다. 계산 비용이 완전히 0인 시각 개선이라는 뜻은 아니다.
- 기존 지역/자유 복원 온도를 따르며 80°C에서 발광이 꺼진다. 식은 지각의 틈과 높은 거칠기는 남는다. 신규 파티클·효과음은 추가하지 않았다.

### 실제 렌더

Blender 5.2.1 LTS Cycles 원본 렌더 후 Godot 4.7.2 Metal Forward+에서 근접 주광·보행 거리 주광/야간·역광·원거리·냉각 상태를 확인했다. 첫 후보의 균일하게 강한 발광은 낮추고 판별/지역별 차이를 늘린 최종본으로 다시 확인했다. 원본과 최종본은 같은 카메라/조명에서 비교했다. 냉각 상태는 실제 지역 셰이더 입력을 80°C로 지정한 검수이며, 온도 설비를 장시간 가동한 전체 플레이 검사는 아니다.

최종 실제 이동 20초는 **26.4 FPS / p95 152.9ms / 최악 268.4ms / 100ms 초과 49회**였다. 정지 12초는 **33.1 FPS / p95 86.8ms / 비디오 메모리 701.5MiB**였다. 변경 전보다 이동 평균과 최악 지연은 나아졌지만 정지 평균은 낮아졌고, P07 단독보다 모든 지표가 좋아진 것은 아니다. 이를 용암 셰이더 단독 비용으로 확정하지 않으며 생산·세션·상태 적용 등 남은 CPU 지연도 해소됐다고 기록하지 않는다.

자료: `output/lava-performance-20260911/final/results.json`, `final.log`, `lava-final.log`, `lava-final/*.png`, `blender-v2.log`. 최종 실제 게임 측정은 정상 종료했고 로그에 스크립트/셰이더 오류와 ObjectDB 종료 경고는 없었다. 새로운 실패가 없는 전체 회귀는 실행하지 않았다.

정지 평균의 차이를 확인하려고 같은 시설 화면에서 시뮬레이션/노드 처리를 멈추고 재질만 원본→새 재질→원본으로 교환했다. 각 3초 준비 후 8초 측정은 66.6→60.7→60.1 FPS, p95 17.4→18.6→17.7ms였다. 그리기 호출 531·기본 도형 272,888·메모리는 세 구간이 동일했다. 새 재질의 p95에 약 1ms 차이는 관찰했으나 두 원본 평균 사이에도 편차가 있어 단독 비용을 확정하지 않는다. 이 60 FPS대 결과는 **게임 진행을 멈춘 렌더 비교**이며 실제 플레이 성능으로 제시하지 않는다. 자료: `shader-ab/results.json`. 첫 비교 보조 스크립트의 원본 UV 치환 문자열 오류는 수정 후 다시 실행했고 첫 자료는 제외했다.
