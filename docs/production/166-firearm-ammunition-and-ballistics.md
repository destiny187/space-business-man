# 총기·탄약·재장전·탄도 고도화

2026-09-13 사용자 승인. 사격 품질 조사 후 탄환과 장전용 탄약까지 준비하는 전투를 요청했고, 기본 권총류는 약한 대신 무한 탄약으로 정했다. 현재 8계열·15개 장비의 발사 경로에 적용했다. 에이펙스 레전드와 동등한 사격 완성도를 입증한 결과는 아니다.

## 플레이에 반영한 것

- **권총 계열 T1~T3**는 기본 피해 10/16/22, 10발 탄창과 무한 예비탄을 사용한다. R 재장전은 필요하다. 카빈 `pulse_1`은 권총에 포함하지 않는다.
- 다른 총기는 유한 예비탄을 배낭에 넣고 사용한다. **I → 탄약**에서 1~10묶음을 직접 제작하며, 같은 탄약을 기존 제작소의 제품 생산으로도 만들 수 있다. 제작소는 제품의 티어 조건을 따른다. 탄약은 배낭 칸을 차지하며 기존 선박/현장 창고 운송을 사용한다.
- 화면의 `탄창 / 예비탄`과 탄종 모델 아이콘, 장전 진행을 연결했다. 권총은 `10 / ∞`로 표시한다. 탄이 없는 자동 총기를 누르고 있어도 매 프레임 실패 요청을 보내지 않는다.
- 새로 제작한 유한 탄약 총기는 빈 탄창, 권총은 채워진 탄창으로 지급한다. 기존 소유 총기의 장전량은 보존한다. 전리품 총기의 첫 탄창 지급은 기존 규칙을 유지한다.

| --- | --- | ---: | ---: | --- |
| 경량탄 | 카빈·기관단총 | 60 | 180 | 철 2·구리 1 |

수치는 초기 밸런스이며 단일 원본은 `data/firearms.json`이다. 제작 비용과 저장은 기존 호스트 거래 경로를 사용한다. 탄창 상태를 제외한 예비탄을 총기별 개별 복사로 만들지 않는다.

## 탄약 보존과 저장 경계

장전 시작 때 실제 필요한 양만 배낭에서 빼서 해당 총기의 `reload_rounds`에 예약한다. 삽입 시점에 탄창으로 이동하고 작동부 복귀까지 사격을 막는다. 예비탄이 3발이면 3발만 장전한다. 탄창에 남아 있던 탄은 버리지 않는다.

장전 도중 무기를 바꾸거나 탑승하면 진행을 중단한다. 예약 탄은 총기에 보존하며 다시 그 총기를 장전하면 이어서 사용한다. 예약은 저장·창고 보관/인수와 함께 이동하고, 배낭이 가득 차도 환급 실패로 소실되지 않는다. 탄창과 예약 합계가 용량을 넘는 저장은 거절한다. 탄약의 칸당 수량에 맞춰 저장 수량 상한도 계산하므로 경량탄이 예전 일반 자원 4,800개 상한에 잘못 막히지 않는다.

구 저장의 이미 장전된 탄은 보존한다. 아직 상태가 없던 기존 소유 총기는 최초 한 탄창을 유지하며, 구 무한 예비탄 방식으로 진행 중이던 장전은 새 상태 초기화 때 취소한다. 새 저장의 예약 탄은 다시 읽어도 보존한다. 배낭을 현장 회수 상자에 남기는 기존 접속 종료/재개 규칙은 이번에 바꾸지 않았다.

비행 중인 총알은 호스트의 실행 중 상태다. 게임 종료·사수의 행성 이탈 때 비행을 종료하며, 진행 중 탄도 자체를 저장 후 복원하지 않는다. 탄창과 예비탄 소모는 저장한다.

## 발사·조준·명중

- 실제 호스트 발사는 유한 탄속과 중력을 사용한다. 카빈 470m/s, 기관단총 330m/s, 저격총 880m/s, 플라스마 32m/s 등 계열별 값을 분리했다. 플라스마는 이동이 보이는 느린 탄이며 충돌 후 주변 피해를 준다.
- 탄환의 이전 위치부터 다음 위치까지 선분을 검사해 얇은 엄폐물 통과를 막는다. 지형과 실제 물리 장애물, 제작 방벽을 검사하며 방벽 내구도를 소모한다. 플라스마 범위 피해도 지형·방벽에 막힌다.
- 쿠퍼테크 로봇은 실드의 연속 영역, 노출된 몸·머리·팔/다리·냉각 코어를 구분한다. 머리 1.4배, 사지 0.75배와 기존 냉각 약점 계열 효과를 사용한다. 일반 동물은 현재 모델/리모델링의 크기·바닥 보정·이동 자세를 반영한 몸체 범위를 쓴다. 8,000종의 관절별 정밀 명중 영역을 완성한 것은 아니다.
- 계열별 좌우 반동 패턴, 이동·공중 탄퍼짐, 정조준 전환 시간·시야각·마우스 감도와 무기 꺼내기 시간을 분리했다. 기존 총몸 반동과 감쇠, 실드/장갑/생물/약점/격파 피드백을 유지했다.
- 산탄은 8개 탄의 이동과 착탄을 각각 처리한다. 첫 산탄 착탄 때문에 나머지 비행 중 산탄을 지우지 않으며, 무기 교체 중에도 이미 발사한 탄의 표시를 유지한다.

`FrontierFirearms.fire`의 직접 호출에는 기존 검사/도구용 즉시 판정 호환 경로가 남아 있다. 현재 원정의 `surface_fire` 호스트 입력은 항상 새 탄도 경로를 사용한다. 독립 지속 레이저/빔 총기, 관통탄, 탄종 교체, 새로운 적·슬라이딩·PvP는 추가하지 않았다.

## 손·팔·총기와 소리

Blender로 좌우 탐험복 장갑/팔을 제작했다. 각 16관절과 `grip/open/trigger` 3클립, 원본 `.blend`와 게임 `.glb`를 보존했다. 게임에서는 손가락 관절과 왼손의 탄창 접촉 위치를 갱신하며 탄창 분리→삽입→작동부 복귀, 사격 검지, 무기 꺼내기와 마우스 흔들림을 연결한다. LMG의 무거운 인출, 플라스마 셀 회전과 계열별 지지 위치를 구분한다. 완전한 팔 IK나 모든 계열의 독립 수작업 애니메이션을 완성했다는 뜻은 아니다.

탄약 상자 5종도 Blender 원본과 GLB로 만들고 실제 모델 카드를 쓴다. 경량탄과 중량탄은 탄 크기·개수를 달리했다. 제작기는 `tools/build_firearm_support.py`, 출력 기록은 `art/blender/equipment/firearm-support.json`이다. Blender Cycles와 Godot Forward+ INK 렌더를 모두 확인했다.

발사·명중음은 기존 계열별 ElevenLabs 원본을 유지했다. ElevenLabs `reload_v1.wav`에서 탄창 분리·삽입·작동부 3개 구간을 편집해 실제 장전 단계에 맞춰 재생한다. 낮은 프레임에서 단계 소리가 건너뛰던 문제를 수정했다. 새 합성 음원으로 표기하지 않는다. 출처·해시·편집 구간은 `audio/manifests/firearm-reload-stages.json`, 재현 도구는 `tools/prepare_firearm_reload_audio.py`다.

## 입력·협동과 단일 행동 처리 범위

자동 진행 저장이 끝나지 않았을 때 클릭을 즉시 버리던 문제를 수정했다. 사수별 발사 요청 하나를 최대 0.8초 보관하고, 실행할 때 현재 소유 무기·입력 허용·발사 간격을 다시 검사한다. 오래된 요청은 발사하지 않는다. 클라이언트는 최대 4개의 발사 응답을 기다릴 수 있으므로 응답 하나를 받을 때까지 다음 연사를 무조건 막지 않는다.

탄별 발사와 착탄을 별도 신뢰 전송 이벤트로 같은 행성의 승무원에게 보낸다. 정기 스냅샷 사이의 자동 사격이 마지막 한 발로 덮이지 않는다. 성공 발사·명중 연출은 여전히 호스트 승인 결과를 따른다. 원격 입력 예측·서버 되감기 판정·지연 보상 전체를 새로 구현한 것은 아니다.

- 발사: 사수 총기/전투 상태, 탄도 기록과 작은 결과/영수증을 변경한다. 발사당 세계 전체 깊은 복사는 없다. 같은 물리 갱신의 산탄·연속탄은 사수의 근처 표적 목록을 공유하며, 진행 중 탄환은 총 256개로 제한한다.
- 명중: 실제 대상 체력·실드·방벽과 해당 사건/전투 상태만 바꾼다. 대상 목록 작성 시 등록 사건 기록을 순회하는 비용, 가까운 생물의 배치·자세 조회 비용은 남는다. 6명 전체 최악 부하를 실측하지 않았다.
- 탄약 제작: 사수·해당 배낭·영수증만 독립 복사한다. 성공 시 소유 재고 스냅샷은 발행하지만 지형/시설 전체 지표 패킷을 강제 재발행하지 않는다. 비동기 확정과 저장 대기 뒤 발사에도 이 구분을 적용했다. 일반 정기 동기화는 계속된다.
- UI: 5개 카드를 유지하며, 닫힌 탄약 창은 재고 계산/프리뷰 갱신을 하지 않는다. 열린 창도 선택·관련 재료·해당 탄약 수량이 바뀔 때만 갱신한다.
- 원자적 저장을 위한 전체 검증·직렬화와 기존 약 2초 전투 체크포인트 비용은 남는다. 저장 중 호스트 탄도 진행도 대기한다. 이 비용을 제거했다고 기록하지 않는다.

## 실제 확인과 남은 검수

Godot 4.7.2 / Metal Forward+ / Apple M2. 사용자 원정 파일 대신 `/tmp/firearm-upgrade-*`의 격리 세계를 사용했다.

- `check_firearm_upgrade.gd`: 탄약 거래·재료·중복 거절, 부분 장전/교체, 저장 대기 클릭, 탄속/낙차, 로봇 부위, 얇은 벽, 약한 무한 예비탄 권총, 예약 탄 저장/다시 읽기를 확인했다. 41항목 통과.
- `review_firearm_upgrade.gd`: 실제 원정 창에서 8계열의 호스트 발사/착탄, 양손 골격 연결, 재장전 3단계 소리, 카빈/저격 정조준, 960×640 탄약 카드와 제작, 메뉴 소리/효과 차단, 저장 종료를 확인했다. 수정 후 76항목 통과. CUA로 실행 창도 관찰했다.
- `check_firearm_transport.gd`: 실제 ENet 루프백 두 연결에서 120ms 요청 보류, 호스트 탄 소모, 정기 스냅샷 없는 연속 4발의 발사/착탄 이벤트, 중복 발사 재요청을 확인했다. 실패 0. 두 사람이 외부망에서 동시에 플레이한 결과와 구분한다.
- `check_firearm_integrity.gd`: 새 제작 총기 탄창, 예약 상태의 창고 왕복, 잘못된 저장 거절, 동기/비동기 탄약 제작의 지표 발행 생략, 무기 교체·산탄별 효과 보존을 확인했다. 실패 0. 큰 경량탄 묶음의 슬롯·저장 상한도 확인했다.
- `review_firearm_upgrade.gd --final-edges`: 탄이 없는 자동 총기의 반복 실패 억제, 예비탄 3발 보충 후 실제 부분 장전, 최종 탄약 UI/저장과 경량·중량탄의 서로 다른 카드를 확인했다. 10항목 통과. 첫 보충 검사는 교체 전 상태 참조를 읽어 실패했고, 실제 저장에 3발이 보존된 것을 확인한 뒤 현재 호스트 상태를 읽는 검사로 수정했다.
- 실제 SFX 출력 44.43초를 녹음했고 최대 -10.80dBFS, 클리핑 샘플 0이었다. 직접 귀로 들은 음색·공간감·연사 피로도 평가는 하지 않았다.

첫 창 검수는 9개 실패가 있었다. 격리 저장을 여는 기존 흐름이 배낭을 회수 상자에 남긴 상태여서 유한 예비탄 재장전/제작을 진행할 수 없었고, 장비 교체 요청에는 오래된 상태로 인한 거절이 섞였다. 실제 재장전 단계 소리 누락도 발견했다. 검수 세계의 상자 재료를 회수하고, 장비 변경 확정을 기다리도록 검사 절차를 고치며, 소리 누락은 게임 코드를 수정한 뒤 위 76항목을 통과했다. 첫 실패 로그도 보존했다.

현재 원정 창 종료 시 기존 검수와 같은 ObjectDB 2개 잔류 경고가 있다. 이번에 전체 회귀·Windows 실기·6인 외부망·장시간 FPS·직접 마우스로 추적하는 손맛을 검증하지 않았다. 자료는 `output/firearm-upgrade-20260913/`에 보존한다.
