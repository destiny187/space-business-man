# 행성 필드의 화면별 가려짐·모션 최적화

2026-09-09 사용자 승인: 렌더 거리는 개인 그래픽 설정으로 조절하고, 그 외에는 각자 보는 화면에서 보이지 않는 대상의 렌더와 시각 CPU 처리를 줄인다. [그래픽 설정](78-performance-and-simple-settings.md)과 [가려진 선내 렌더](84-covered-world-and-preview-rendering.md)의 후속이다.

## 적용

- 실제 표시하는 필드 뷰포트에 Godot 오클루전 컬링을 켠다. 여러 지형 사용자의 수를 세고 마지막 필드를 떠나면 기존 설정으로 복구한다. 호스트의 다른 행성용 렌더 중단 뷰포트와 headless 실행에는 추가 오클루전 자료를 만들지 않는다.
- 개방 필드의 판정 비용을 줄이기 위해 스레드당 가림 레이를 기본 512에서 128로 제한했다. 표시 해상도·거리·모델 품질을 바꾸는 값은 아니다. 저해상도 판정에서 경계가 애매하거나 큰 모션 경계 상자가 가림 면에 가까우면 대상을 보수적으로 남긴다. 그 경우 메시가 제외돼도 모션 통지는 계속 활성일 수 있다.
- 가까운 지형은 작업 스레드가 만든 정점/인덱스를 가려짐 판정에도 재사용한다. 지표와 동굴·굴착 구멍이 같은 형상이며, 메시·충돌·오클루더를 같은 청크 교체로 설치/제거한다. 빈 공간을 임의의 큰 상자로 막지 않는다.
- 시설·창고는 큰 불투명 고정 메시를 모델별로 한 번 수집해 오클루더를 공유한다. `Anim_*`/`FX_*` 분기와 투명·알 수 없는 셰이더는 제외한다. 움직이는 문·팬을 고정 벽으로 취급하지 않으며, 모델의 실제 틈을 보존한다.
- 시야 밖 또는 지형/시설에 완전히 가려진 메시의 제출은 엔진에서 제외한다. 그림자 등 별도 렌더 패스와 부분적으로 보이는 물체는 필요한 범위를 유지한다. 자연물 MultiMesh는 기존 타일/군락 단위로 판정한다. 풀 한 포기씩 노드·드로콜을 늘린 구현은 아니다.
- 생물은 화면 가시성 통지에 따라 관절/효과 갱신을 생략하고, 보일 때도 활성 LOD만 매 프레임 계산한다. 숨겨져도 경과 시간과 공격 표현 단계는 진행하며, 복귀 시 현재 시간의 자세와 선택된 LOD의 입 위치로 효과를 적용한다. 도감의 직접 `pose()` 호출은 양쪽 LOD 검수 동작을 보존한다.
- 시설·로봇은 시야 밖에서 팬·드릴·피스톤 등의 변환 갱신을 생략한다. 작업 시간과 이동 거리는 유지하여 복귀 때 현재 위상을 적용한다. 로봇 충돌체의 위치 보간은 계속한다.

원경 거리·그림자 거리·기존 자연물 거리 제한은 이번 변경에서 줄이지 않았다. 시야거리 옵션은 기존처럼 개인 설정이며 호스트의 시뮬레이션 범위를 줄이는 데 사용하지 않는다.

## 멀티플레이 경계

렌더러와 가시성 통지는 각 실행의 카메라/월드를 기준으로 한다. 상대가 보고 있어도 내 화면에서 보이지 않으면 내 모델 모션은 생략할 수 있다. 같은 프로세스에서 같은 월드를 여러 뷰포트로 표시한다면 가시성 통지는 해당 월드를 보는 카메라들의 합집합이므로 필요한 화면을 보호한다.

호스트는 다른 플레이어·로봇 주변의 충돌 지형과 권한 계산을 계속 유지한다. 생산·전투 판정·생태 상태·물리 물·저장·네트워크 복제·가까운 소리의 진행을 이 가시성 조건으로 중단하지 않는다. 이번 변경은 호스트의 모든 CPU 비용을 각 클라이언트로 분산하는 기능이 아니다.

## 확인

- `check_field_visibility.gd`: Metal Forward+의 독립 월드/카메라 두 개에서 가려짐과 표시 분리, 시점 회전/복귀, 비활성 LOD, 숨겨진 로봇 위치·시설 충돌·공격 표현 단계, 지형 개방 후 재표시, 뷰포트 설정 복구를 확인했다. 17개 확인 실패 0. 지형 뒤 생물·시설·로봇을 둔 검증 장면의 주 시점 그리기 호출은 오클루전 끔 69회 → 켬 1회였다. 일반 필드의 개선율로 해석하지 않는다.
- 최초 복귀 검사는 원래 정지해 있는 몸통을 비교해 실패했다. 실제 움직이는 머리 관절로 검사 대상을 바로잡아 복귀와 비활성 LOD를 확인했다.
- 128 레이에서 큰 생물 모션 경계 상자가 가림 면에 가까운 배치의 통지는 보수적으로 활성 상태를 유지했다. 완전 가림 검증 장면은 가림 면과 생물 사이 간격을 확보해 검사했고, 실제 게임의 모션 경계는 축소하지 않았다. 좁은 틈·경계에서 모든 대상을 반드시 제거한다는 보장은 아니다.
- 다중 ENet 클라이언트·6인 인터넷·Windows 실기와 전 생물/시설 전수 검수는 수행하지 않았다.

## 실제 필드 확인·측정

`check_field_visibility_play.gd`를 기존 진단용 저장의 별도 복사본에서 실행했다. Apple M2 / Godot 4.7.2 Metal Forward+, 1280×800, 보통·100%, FPS/VSync 제한 해제다. 생물 12개·사업 표시 객체 20개·최종 비어 있지 않은 오클루더 청크 33개였다.

- 실제 원정 로드·풍경 준비·필드 가림 켜짐, 숨김 중 호스트 시간 진행, 실제 지형 굴착과 현재 청크/오클루더 인덱스 일치, 원정 종료 후 설정 복구 등 **9개 확인 실패 0**, 최종 실행 엔진/스크립트 오류 0. 최초 CPU 대조 도구에서 시설의 메타데이터를 제거해 엔진 오류가 발생했으며, 대조 범위를 생물 콜백으로 한정하고 다시 확인했다. 잘못된 첫 CPU 수치는 사용하지 않는다.
- 생물 콜백은 동일한 상태에서 가시성 생략만 우회/적용해 각각 100회 동기 호출했다. 활성 LOD만 갱신하는 개선은 양쪽에 유지했다. 한 시점에서 **0.200→0.108ms**, 반대 시점에서 **0.339→0.093ms**였다. 가시성 생략 대상은 각각 6/12개, 9/12개였다. 전체 CPU 프레임이나 이전 체크아웃과의 비교가 아니다.
- 각 시점에서 오클루전 끔→켬→켬→끔 순서로 구간당 준비 25프레임·측정 120프레임을 실행했다. 안정된 두 번째 시점의 그리기 호출은 **319→309회**, 평균 프레임은 **25.91→25.57ms**였다. 구간 편차가 커 FPS 개선을 확정할 수 없다. 첫 시점은 풍경 상태 변화로 호출 수가 달라져 고정 장면의 렌더 절감 수치로 사용하지 않는다.
- 처음 기본 512 레이로 실행한 두 번째 시점은 끔 24.00ms / 켬 26.04ms로 가림 비용의 역효과가 있었다. 이를 확인한 뒤 128 레이로 비용을 제한했다. 모든 개방 지형에서 더 빠르거나 60 FPS를 달성했다는 뜻은 아니다.
- 실제 필드 두 방향과 분리 화면·가림 제거 화면을 직접 검수했다. [실제 필드 로그](media/field-visibility/play.txt), [최종 비교 원본](media/field-visibility/comparison.json), [512 레이의 비교 원본](media/field-visibility/default-rays.json), [분리 화면 검사](media/field-visibility/check.txt)를 보존한다. JSON의 확인 수는 종료 직전까지이며 마지막 복구 검사는 로그에 포함된다.
