## 방향과 적용 범위

2026-09-06 사용자 승인: 노맨즈스카이의 정돈된 탐사 인터페이스를 참고해 현재 웹 관리 화면처럼 느껴지는 UI/UX를 개선한다. **가능하면 텍스트로 디자인하지 않고 시각적으로 표현한다.** 이 문서는 앞으로 만드는 지상·항해·아이템·제작·건설·연구·우주선·협동·시작 화면의 공통 기준이다.

우리 게임의 표현 방향은 **차분하고 정밀한 우주 개척 장비**다. 크림·청록·주황의 산업 디자인과 기존 INK v1 카툰 월드를 연결한다. 노맨즈스카이의 로고·아이콘·화면을 복제하지 않는다. 참고한 공식 [Waypoint 인터페이스 개편](https://www.nomanssky.com/waypoint-update/)은 물건의 슬롯 표현과 정보 구조 참고이며 동일한 인벤토리 규칙을 강제하지 않는다.

아래 색·간격·슬롯 크기는 현재 구현 선택이다. 사용자 확정 사항은 시각 표현 우선, 깔끔한 공통 UI/UX, 기존 실제 플레이 유지다. 가이드가 적용 대상 전체의 개편 완료를 뜻하지 않는다.

## 시각적으로 먼저 전달하는 원칙 — 필수

표현 우선순위는 **실제 대상/모델 → 위치와 배치 → 아이콘·형태 → 상태 변화·동작 → 필요한 짧은 텍스트**다. 기능마다 설명문과 실행 버튼을 붙인 세로 목록을 기본 해법으로 삼지 않는다. 기능이 추가될 때 “어느 물건을 보고, 어떻게 선택하고, 무엇이 바뀌는가”를 먼저 정한다.

텍스트를 없애는 규칙은 아니다. 생소한 아이콘은 이름·선택 상세·키보드 포커스·툴팁으로 의미를 확인할 수 있어야 한다. 색만으로 상태를 구분하지 않는다. 수치·단위·실패 이유·위험한 행동의 결과는 명확히 쓴다. 이미지 위에 문장을 얹는 것으로 시각화 완료를 주장하지 않는다.

## 정보의 세 단계

1. **플레이 중**: 풍경·조작 대상이 중심이다. 현재 장비, 재사용 상태, 위치와 귀환 거리, 최소한의 빠른 접근만 둔다. 모든 메뉴·설명·재화를 상시 나열하지 않는다.
2. **조준/선택 중**: 대상 이름·자원 아이콘·잔량·필요 장비·지금 가능한 입력이 대상 가까이에 나타난다. 관심을 바꾸면 이전 대상 정보는 사라진다.
3. **메뉴에서 관리 중**: 넓은 화면에서 물건과 연결을 다룬다. 상세·레시피·공동 창고·정확한 수치가 필요할 때 펼쳐진다. 뒤의 개인 이동·발사·스캔 입력은 차단한다.

큰 게임 로고·모든 키 안내·정상 저장 문장은 지상 HUD에 반복 노출하지 않는다. 저장 성공은 작고 짧은 표식으로, 실패는 행동 결과와 이유가 보이는 별도 알림으로 전달한다. 협동에서 개인 메뉴를 열어도 세계가 멈춘다고 표현하지 않는다.

## 대표 화면과 조작

아이템창은 **왼쪽 검색/분류와 아이템 격자 → 오른쪽 3D 미리보기·선택 상세 → 고정된 실행 버튼 → 하단 장착 슬롯**으로 구성한다. 3D는 마우스로 회전한다. 긴 상세만 따로 스크롤하며 장비 선택 후 번호 슬롯을 클릭하거나 끌어놓으면 장착한다. 화물은 양쪽 보관함을 중심으로 전체 폭을 사용하고 장착 슬롯을 숨긴다. 미리보기·선택 자체는 소유/재료 상태를 바꾸지 않는다. 2026-09-08 [UX01 적용](71-resource-browser-and-cargo.md).

화물은 내 배낭과 공동 현장 창고를 명시적으로 선택한다. 자원별 큰 아이콘과 수량을 표시한다. 공동 크레딧은 별도 표시하며 개인 지갑으로 오해하게 하지 않는다. 실제 호스트 거래 규칙은 [아이템·장비](../game/13-inventory-and-equipment.md)를 따른다.

건설·연구·우주선은 이 시각 규칙과 입력 규칙을 공유하되 역할에 맞는 구성을 사용한다. 건설은 대상 선택과 배치, 연구는 표본과 연결/진척, 우주선은 실제 선체와 모듈 부착 위치가 중심이다. 모든 화면을 같은 목록·같은 그리드에 억지로 맞추지 않는다.

I/B/J/Tab으로 관련 화면을 열고 같은 키 또는 Esc로 닫는다. 하단의 작은 시각 아이콘은 처음 접한 플레이어를 위한 진입점이다. 메뉴 전환 시 이전 큰 패널을 닫아 겹침을 막는다. 선택·장착은 즉시 조작하며 판매·분해처럼 손실이 있는 행동의 확인 규칙은 소관 기능에 따른다. 슬롯 클릭과 드래그를 함께 제공한다.

## 피드백과 구현 규칙

- 선택·준비, 요청 대기, 성공, 실패를 구분한다. 네트워크 요청 전 성공 연출이나 수량 감소를 확정하지 않는다.
- 정상 발사는 펄스·반동·소리로 전달하고 매번 “발사” 문구를 띄우지 않는다. 광물 획득·거절·새 발견처럼 필요한 정보는 짧게 남긴다.
- 메뉴를 열어도 실패 알림이 뒤에 가려지지 않아야 한다. 정상 저장 표식은 작게 사라지고 반복 대화상자를 만들지 않는다.
- 사운드는 기존 ElevenLabs 음원을 우선 재사용하고, 새 제작은 [사운드 지침](02-audio-and-elevenlabs.md)을 따른다.
- 3D 모델은 Blender 원본/게임 내보내기를 구분한다. 미리보기도 실제 Godot INK 렌더를 사용한다. AI 그림으로 실제 장비 렌더를 대체하지 않는다.
- 공통 테마는 `FrontierInterfaceStyle`, 격자/장착 타일은 `FrontierItemTile`을 사용한다. 화면마다 색·글꼴·선택 표시를 복제 정의하지 않는다.
- 미리보기는 별도 월드의 SubViewport이며 메뉴가 닫히면 렌더를 중단한다. 카드마다 지속 실행하는 3D 월드를 만들지 않는다.

## 현재 적용과 남은 범위

**이번 적용**: 지상 HUD, 아이템/제작/화물 전체 레이아웃, 실제 회전 3D 미리보기, 장비 격자, 클릭/드래그 장착, 배낭·공동 창고 아이콘, 성능 막대·비교, 조준 대상 정보, 작은 저장 표시·실패 알림. 원정 공통 테마와 건설·선박 패널의 색·글꼴·기본 컨트롤 스타일도 연결했다.

**후속 구조 개편**: 건설/로봇 전체 작업 배정, 생태 연구의 표본/연구망, 우주선의 공간 기반 모듈 배치, 항해·대기실·시작 화면의 전용 레이아웃. 해당 화면의 테마가 바뀌었다고 시각적 구조까지 완료한 것으로 기록하지 않는다. 패드 전용 조작·전체 키 재설정·모든 해상도·UI 배율·색각/대비 전수 검수도 별도다.

사용자 지시에 따라 전체 회귀를 반복하지 않는다. 변경한 실제 화면·선택/장착·핵심 동작과 발견한 오류의 수정 범위를 확인한다. [이번 구현/검증](23-uiux-implementation.md)을 따른다.

## 공통 조사 결과

스캔 결과는 대상 아이콘/모델 → 정체·현재 수치 → 활용 경로 → 다음 행동 순서로 전달한다. 생물의 연구 활용과 실물 정착 용도를 구분하고, 미개발 배양/자유 배치를 가능한 행동처럼 표시하지 않는다. [공통 조사와 정착물](25-universal-survey-and-living-settlement.md).

## 2026-09-07 — 개인 아이템 격자 통합

개인 장비와 화물은 한 **아이템** 격자에 표시한다. **2026-09-08 확정: 없는 품목은 0개 아이콘이나 목록 자리로 남기지 않는다.** 실제 보유 물건만 중첩별 이름·수량으로 표시하고, 빈 공간과 한도는 사용 칸 요약으로 전달한다. 빈 보관함 영역에도 드래그할 수 있다. 제작 및 공동 창고는 같은 화면의 별도 탭을 유지한다. 필요 재료의 부족 안내와 이미 발견한 도감 기록은 보유 목록과 구분한다. 공통 칸 한도와 저장/이동 규칙은 [아이템 소관 문서](../game/13-inventory-and-equipment.md#2026-09-07--중첩형-통합-아이템창-현재-규칙)에 둔다.

## 2026-09-07 — 항해와 공통 메뉴 전환

항해도 지상처럼 우측 상단 지도와 대상별 상호작용을 중심으로 한다. Esc는 열린 작업창을 닫고, 플레이 중에는 계속하기·설정·종료 메뉴를 연다. 작업창 전환과 닫기에서 이전 포커스·마우스 해제 상태를 남기지 않는다. 적용 화면·조작·검증 범위는 [항해 간소화와 공통 메뉴](38-navigation-context-and-menus.md)에 둔다.

## 2026-09-08 — 도감·제작·생태·항해 탐색
