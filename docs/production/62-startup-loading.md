# 초기 실행·원정 로딩 — 2026-09-08

## 요청과 확인한 원인

사용자는 초기 실행의 심한 끊김을 줄이고 필요한 경우 별도 진행률 페이지를 요청했다. 기존 기본 시작은 홈 장면을 직접 읽고, 원정의 `_ready()`에서 선내 모델·UI·음원을 연속 생성했다. 우주 뷰는 초기 태양계를 생성한 다음 첫 항해 스냅샷에서 동일 항성계를 다시 생성했다. 저장 위치가 다른 항성계여도 먼저 태양계를 만들고 교체했다.

이 중복 생성은 확인된 불필요한 비용이다. 모든 끊김이 로딩 부재 때문이라고 판정하지 않으며 CPU/GPU 프로파일 전후 비교는 수행하지 않았다.

## 현재 구현

- 기본 시작 장면을 가벼운 `loading.tscn`으로 변경했다. 홈·혼자 시작/재개·협동 대기실 진입에 같은 페이지를 사용한다.
- 글꼴·대상 장면·원정 공통 선내/탐험복/기본 선체 모델을 ResourceLoader 백그라운드 읽기로 준비하고 참조를 유지해 실제 구성에서 재사용한다.
- 파일 읽기 진행률과 선내·화면/장비·음원/기록·항성계·첫 화면 렌더 단계로 진행 막대를 갱신한다. 단계별 비중은 표시용 가중치이며 전체 남은 시간의 예측값이 아니다.
- 무거운 초기화 단계 사이에 실제 프레임을 표시한다. 첫 화면의 6개 렌더 프레임을 가림막 뒤에서 준비한 후 페이지를 제거한다. 모든 방향·모든 자산의 GPU 컴파일 완료를 보장하는 방식은 아니다.
- 협동 대기실 이후 첫 플레이 스냅샷에서도 동일한 전체 화면 가림막을 사용한다. 준비 중 수신한 최신 스냅샷을 적용한 뒤 해제하며 네트워크 연결을 일시 정지하지 않는다. 로딩 중 입력·로컬 이동과 메뉴 기반 음원 재생을 차단한다.
- 우주 뷰의 선행 태양계 생성을 제거했다. 첫 실제 항해 상태가 가리키는 항성계만 생성한다. 모델 품질·행성 수·INK 설정은 변경하지 않았다.
- 기존 지표 착륙 로딩은 유지한다. 새 모델/음원 제작은 없으며 기존 Blender·ElevenLabs 자산을 사용한다.

## 최소 확인

Godot 4.7.2 / Apple M2 / Metal Forward+ 실제 창에서 확인했다.

1. 홈 로딩 → 혼자 새 원정 → `playing`, 태양계 행성 8개, 로딩 해제. 960×640 로딩 페이지와 설정 적용 후 원정 화면을 캡처했다. 마지막 실행 로그에 스크립트/엔진 오류 없음.
2. 대기실 → 호스트 시작 → 로딩 표시 → 태양계 8개 → 로딩 해제. 별도 두 클라이언트 접속 검증은 아니다.
3. 초기 검사용 임시 저장 폴더가 없어 호스트 시작이 실패한 실행을 확인했고 폴더 생성 후 같은 흐름을 재확인했다. 실제 사용자 세이브는 사용하지 않았다.
4. `git diff --check` 통과. 전체 회귀·6인/인터넷·Windows·장시간 FPS·콜드 GPU 캐시 비교는 수행하지 않았다. 초기화의 개별 동기 생성 단계 안에서는 진행 막대가 잠시 멈출 수 있다.
