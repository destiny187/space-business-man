# SP04 — 화성 항만과 지구 물류항

2026-09-10 사용자 요청으로 새 은하에 Space Y 화성 항만 `MARS Y-01`과 지구 물류항 `EARTH Y-02`를 연결했다. [SP03 복원 화성](110-restored-mars-sp03.md)에 이어 실제 우주 모델·접근·정지·기초 물자 거래를 제공한다.

## 플레이와 저장

항만은 태양계의 명시적 고정 예외다. 새 `settings.corporate_space.ports` v1에 두 주소·기준 행성·궤도·초기 재고·가격·매입 한도를 함께 고정한다. 이전 은하와 SP03까지 생성한 저장은 `ports`가 없으면 항만을 추가하지 않는다. 기존 무작위 WAYFARER의 시드·재고·선체 상품과 입문 추천/실제 첫 성간 목적지의 정거장 제외를 유지한다.

항만은 행성의 현재 공전 위치에 자체 궤도 오프셋을 더한다. 궤도는 게임 축척의 결정적 표현이며 실제 궤도 역학 계산이 아니다. 항성 지도·미니맵·우주 표지·주시 대상·직접 비행 충돌/제동·자동 접근·성간 출항 장애물에 같은 주소와 시간을 사용한다. 지도를 클릭하거나 항만을 조준해 F로 접근하고 안전 거리에서 정지한 뒤 F로 교역한다. 다른 행성에 가려진 항만은 주시 상호작용 대상으로 선택하지 않는다.

현재 정지는 항만 중심에서 기존 정거장 안전 거리 1,100m를 유지하는 **궤도 대기**다. 우주선을 갑판에 물리 결합하거나 내부를 걷는 접안은 아니다. 자동 접근은 목적지의 이동 기준을 따라 상대 속도로 감속한다. 정지 후 `station_docked`와 `station_id`로 공전 이동을 따라가며 거래 중 멀어지지 않는다. 수동 추진이나 다음 항로 출발로 이 기준을 해제한다. 다른 행성을 지도에서 골라보는 것만으로 거래 지점을 바꾸지 않는다.

`station_markets`는 기존 숫자 항성계 키를 보존하고 `solar_mars_port`·`solar_earth_logistics`의 독립 장부를 허용한다. 거래 요청은 항만 주소를 포함하고 호스트가 접근 거리·정지·소유 권한·금액·개인 가방·재고를 검사한다. 세계 복사본 검증과 저장 성공 뒤만 거래를 공개한다. 다른 항만의 재고를 원격으로 거래하지 못하며 재개방·저장 복구·재방문으로 재고를 다시 채우지 않는다.

## 초기 공급 범위

두 항만은 철·구리·암석·얼음만 거래하며 선체 판매와 T3 설계도 판매를 제공하지 않는다. 이미 보유한 선체의 교체는 기존 정거장 기능으로 유지한다. 상품 카드·운영사 심볼·단가/총액·추가 매입 가능 수량을 표시한다.

| 물자 | 구매 / 판매 Cr | 화성 초기 재고 / 최대 보관 | 지구 초기 재고 / 최대 보관 |
| --- | --- | --- | --- |
| 철 | 10 / 4 | 80 / 180 | 100 / 180 |
| 구리 | 14 / 5 | 60 / 140 | 80 / 140 |
| 암석 | 6 / 2 | 60 / 160 | 100 / 160 |
| 얼음 | 10 / 4 | 100 / 200 | 60 / 200 |

이 수치는 구현을 위한 초기 조정값이며 사용자 확정 밸런스가 아니다. 두 항만의 매입 단가는 Lotus 유료 보급 단가보다 낮다. 무료 출항 물자와 한정 무료 보급의 판매는 가능하되 추가 매입 한도와 유한 재고를 사용한다. NPC 운송에 따른 재입고나 시간 기반 무한 지원을 추가하지 않았다.

## 제작과 식별

`tools/build_orbital_ports.py`는 공통 `ink_blender.py`·산업 재질·기업 compact SVG를 사용한다. 화성의 환경 운영 드럼·기체 저장 용기와 지구의 화물 관제동을 구분하고, 양쪽에 개방 접안 갑판·유도등·크레인 관절·컨테이너/잠금장치·태양광 패널·통신부를 배치했다. 근접 표식은 운영사 Space Y를 뜻하며 제조사를 추정하지 않는다.

Blender 원본을 저장한 뒤 정적 표면만 병합해 내보냈다. 화성은 14 메시 / 90,000삼각형, 지구는 14 메시 / 63,664삼각형이다. 크레인 피벗과 두 선석 Socket을 보존했다. 이번에는 크레인의 실제 상하역 운용이나 무역선 운항을 연결하지 않았다.

실제 항만 접근 완료 또는 거래 때 Space Y를 J 기업 도감에 최초 한 번 기록한다. 화성과 지구 항만을 별도 자산으로 구분해 처음 만난 모델을 표시한다. 회사 정체성은 기존 공용 기록·저장 경로를 따른다.

## 실제 확인과 남은 범위

Blender 5.2.1 Cycles와 Godot 4.7.2 Forward+ / Metal / Apple M2에서 두 모델을 검수했다. `check_orbital_ports.gd`는 격리 저장 `/tmp/orbital-ports-play`의 실제 원정 앱에서 자동 접근·정지·거래·제한·기업 기록·작은 화면·양쪽 장부 저장을 확인했다. 궤도 대기 120초는 도메인 시간을 진행시킨 검사이며 실제 창에서 120초 기다린 것은 아니다. 첫 항만 접근은 실제 시간으로 진행했다.

첫 실행은 35항목 중 33항목을 통과했고, 두 거래 항목은 검사 초기 가방 10개가 재접속 개인 기록으로 대체되는 것을 놓친 기대값 오류였다. 검사값을 실제 진입 가방 기준 증감으로 수정한 뒤 `--trade-review`로 저장 재개·구매/판매·두 지도 주소·재저장 6항목을 확인했다. 해당 재실행과 두 INK 렌더에 엔진/스크립트 오류는 없었다. [플레이 기록](media/corporate-space/ports-check.txt) · [거래 재확인](media/corporate-space/ports-review.txt).

사운드는 [기존 정거장 ElevenLabs 매핑](../../audio/manifests/space-station-reuse.json)을 재사용했다. 실제 창의 거래 성공 재생 이벤트·항만 환경음 재생 상태를 확인했으며 신규 관제 음성 생성·청감 검수를 주장하지 않는다. 전체 회귀·다중 클라이언트·Windows·장시간 성능은 검사하지 않았다.

지표 도시/우주항 방문·NPC 상하역/경제 재입고·플레이어 자동 운송은 구현하지 않았다. SP05 무역선, SP06 전투기, SP07 이후 시드 기업 거점은 후속 단계다.
