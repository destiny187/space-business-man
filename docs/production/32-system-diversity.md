# 항성계 구성과 진입 풍경

## 확정 방향

2026-09-07 사용자가 항성계별 행성 수·간격, 소행성대·위성·고리, 특징이 보이는 진입 배치의 추가를 승인했다. 행성 개별 외형은 [행성 다양성](31-planet-diversity.md)을 유지하고 항성계 전체의 구성을 확장한다.

## 구현

새 은하는 항성계당 **4~12개 행성**, 총 **100만 행성·12만 5천 항성계**를 갖는다. 태양계와 그 주소 쌍은 8개씩 유지한다. 항성 크기, 각 궤도 간격과 항성계 크기를 시드로 결정한다. 바깥 저티어·중심 고티어 분포는 유지한다.

| 구성 계열 | 시각적 특징 |
| --- | --- |
| 넓은 항로 | 행성 수와 간격이 달라지는 기본 계열, 옅은 배경 먼지 |
| 소행성 회랑 | 첫 두 행성 궤도 사이의 소행성대, 따뜻한 먼지색 |
| 위성 군집 | 행성마다 1~2개의 공전 위성, 차가운 배경 먼지색 |
| 거대행성 성역 | 홀수 번째 궤도 슬롯에 가스 거대행성, 고리·위성, 보랏빛 먼지색 |

공통 은하 배경의 방향은 유지하면서 국소 먼지색·농도를 바꾼다. 성역마다 은하 자체를 임의로 회전시키지 않는다. 새 행성 수에 맞게 항법도·다음 항성계 선택·튜토리얼 목적지 탐색·항해 대상·충돌 판정·저장 주소를 갱신했다.

Blender로 소행성 3개 형상과 틈이 있는 4겹 고리를 제작했다. 소행성 420개를 3개 MultiMesh로 나눠 배치하고 매우 천천히 회전시킨다. 위성은 기존 Blender 충돌 고원 모델과 공통 INK 명암·표면 마스크를 재사용하며 호스트의 궤도 시간에 맞춰 공전한다. 위성은 행성 개수·100만 개 주소에 포함되지 않는 부속 천체다.

항성계 선택 시 거대행성 성역은 고리 행성을 대표 대상으로 선택한다. 도착 위치는 행성 바깥쪽 사선 방향이며, 고리·위성이 있는 경우 더 멀리서 접근한다. 초고속 항해의 마지막 표시 위치와 호스트의 도착 위치는 같은 함수로 계산한다. 이후 기존 자동 접근 또는 직접 조종을 이어간다. 태양계 출격 튜토리얼은 여전히 착륙 가능한 T1 행성을 우선한다.

항성 크기에 비례해 경고·피해 반경을 함께 변경했다. 직접 조종의 충돌 판정에 위성을 포함하고, 자동 접근은 목표 행성의 위성을 우회한다. 고리는 보수적인 구형 접근 반경으로 보호한다.

## 주소·저장

`system_diversity.json`을 새 은하 매니페스트의 `system_rules`로 보존한다. 인접한 두 항성계가 16개 행성 주소를 공유하며 시드로 4~12개와 나머지를 배분한다. 이 방식은 100만 주소를 빠짐없이 사용하고 누적 주소 표를 생성하지 않아도 항성계↔행성 주소를 상수 시간에 변환할 수 있다. `planets_per_system=8`은 기존 형식과 항성계 총수를 위한 평균값이며 새 생성에서는 실제 개수로 쓰지 않는다.

기존 저장에 `system_rules`를 삽입하거나 행성 주소를 재배치하지 않는다. 기존 은하는 고정 8개 배치(더 이전 버전은 기존 4개)를 유지한다. 새 구성 전체를 보려면 새 은하로 시작한다. 태양계 지구 출발과 태양계 착륙 제한은 유지한다.

## 현재 범위

- 소행성은 배경 지형으로 채광·개별 충돌·파괴를 구현하지 않았다.
- 위성은 시각·공전·우주선 충돌 대상으로, 착륙·개발 대상은 아니다.
- 행성 고리는 보수적인 구형 접근 제한을 사용한다. 고리 틈새 통과는 지원하지 않는다.
- 구성 계열은 4개이며 모든 항성계가 완전히 고유한 장면은 아니다. 같은 계열에서도 행성 수·외형·간격·항성·위성 배치가 달라진다.
- 고리 행성의 도착 구도는 실제 항해 함수로 확인한다. 소행성대 대표 캡처는 전체 배치를 확인하기 위한 별도 관찰 시점이다.
- 신규 음원은 제작하지 않았으며 기존 초고속 항해의 충전·감속·도착 음원을 유지한다.

## 확인

`test_system_diversity.gd`에서 전체 12만 5천 항성계의 주소 연속성·역변환, 총 100만 행성, 4~12개 분포, 태양계, JSON 재현, 기존 주소 보존, 궤도 순서·경계, 호스트 출항·도착·저장을 검사했다. Godot 4.7.2 Metal Forward+에서 4개 계열을 실제 항해 로더로 렌더했다. Blender Cycles 원본 형상과 게임의 고리·위성·소행성대를 확인했다. 전체 회귀나 다중 클라이언트 검사를 추가하지 않는다.

최종 확인: 규칙·항해 검사 14개 실패 0건, Forward+ 계열 렌더 4개. 작은 위성을 한 프레임 안에 통과하는 이동에서 기존의 ‘끝점이 더 가까운 경우만 충돌’ 조건이 충돌을 놓칠 수 있어, 이동 구간과 접근 방향을 기준으로 수정했다. 실제 위성 반경을 가로지르는 고속 이동을 재현하여 통과 방지와 선체 피해를 확인했다. 자동 접근 완료도 검사했다.

## 항성계 진입 시야 보정 — 2026-09-07

사용자 요청에 따라 성간 도착은 목표 행성에서 최소 12,000 게임 거리만큼 떨어진 사선 상공으로 옮긴다. 고리·위성 안전 여유와 항성계 경계 안쪽 제한을 유지한다. 시선은 목표 궤도의 35% 지점으로 향해 항성과 주변 행성을 함께 보여 준다. 수치는 `space_presentation.json`의 `entry_overview`에서 관리하며 기존 은하 주소와 생성 시드는 바꾸지 않는다.

성간 이동 완료 후 자동 행성 접근을 이어가지 않고 속도 0의 직접 조종 상태로 전환한다. 기존 방문/위치 기록과 승무원 준비 해제는 유지하며, 행성 주시 스캔 이후 E 접근 또는 직접 비행·근접 착륙으로 이어진다. 같은 항성계에서 명시적으로 요청한 자동 접근은 유지한다. 도착 연출과 호스트는 같은 위치·시선 계산을 사용한다.

최소 확인: 시드 61739의 첫 출격 도착·정지 유지·저장 검증·명시적 재접근 완료, 4개 항성계의 행성별 진입 위치 경계/천체 여유를 확인했다. Godot 4.7.2 Forward+/Metal 실제 1280×800 창에서 항성과 여러 행성이 보이는 시야를 검수했다. 전체 회귀·다중 클라이언트 검사는 수행하지 않았다.
