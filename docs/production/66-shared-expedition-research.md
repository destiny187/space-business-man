# A05 — 공동 탐사 연구 원장

2026-09-08 [A01~A09 계획](../planning/12-augmentation-and-research-commits.md)의 A05 기반을 구현했다. 첫 프로젝트 **심부 정밀 채집**의 발견 증거·개인 표본 기여·공동 분석 상태를 호스트 세계에 저장한다. 표본 조작/분석 화면·시제품은 A06, 현장 시험·Mk.3 제작 개방은 A07이다. 현재 연구대 F 화면은 기존 장치 열람이며 새 실행 버튼을 임시로 추가하지 않았다.

## 저장과 이전 세계

원장은 세계 최상위 `expedition_research`에 둔다. 개인 프로필·장비 `loadout`·개인 `augmentation`과 분리한다.

| 필드 | 현재 의미 |
| --- | --- |
| `version: 1` | 연구 원장 스키마 |
| `origin: new / legacy` | 새 세계와 연구 도입 전 세계의 구분 |
| `licenses` | 설계 사용권. A05에서는 이전 세계의 `miner_3: legacy`만 기록 |
| `projects.deep_mining.stage` | `unseen → discovered → analyzed` |
| `evidence` | 자원별 최초 발견의 행성·광맥·필요 티어·출처·발견자 |
| `contributions` | 실제로 표본을 낸 세계 캐릭터별 자원/수량 |

새 세계에는 연구 원장을 처음부터 넣고 사용권을 지급하지 않는다. **원장이 없는 이전 저장만** `legacy`로 이행하며, 같은 세계에 Mk.3 사용권을 기록한다. 원장이 이미 있으면 새 것으로 덮지 않는다. 기존 `crew.survey`의 해당 보석 스캔은 `legacy_scan` 증거로 가져오며, 알 수 없는 발견자는 빈 ID로 남긴다. 보유 재료만 보고 발견이나 기여를 추정하지 않는다. 기존 보유 장비·사업 제작 예약은 변경하지 않는다.

현재 `equipment.json`의 Mk.3는 `craftable: false`이므로 이전 사용권이 있어도 A05에서 새 제작이 열리지는 않는다. 사용권과 콘텐츠 제작 가능 여부를 구분한다. 이후 A07에서 제작을 제공할 때 이전 세계의 권한을 재잠그지 않는 기반이다. 연구가 이미 끝났다고 표시하거나 표본 기여를 만들어 주지는 않는다.

기존 스키마 검사를 통과한 뒤 읽기/호스트 시작에서 누락 상태를 이행하고, 다음 정상 저장에 기록한다. 미래 버전·잘못된 단계/증거·없는 기여자·음수/초과 표본·새 세계의 legacy 권한은 거절한다. 기존 유효 파일과 백업 보존 규칙을 유지한다.

## 발견과 표본 거래

- 실제 호스트 스캔 완료와 성공한 수동 채광의 확정 경로에서 증거를 기록한다. 기존 지하 광맥을 일반 스캐너로 투시 가능하게 바꾸지 않았다. 지하 보석은 실제 채집으로도 발견된다.
- 첫 증거는 사파이어·루비·에메랄드의 T2 이하 기록이다. 다이아몬드/T3 회수를 첫 연구 선행 조건으로 쓰지 않는다. 자원별 한 건으로 제한해 반복 광맥 발견으로 저장이 계속 커지지 않는다.
- 첫 조정값은 발견 기록이 있는 위 보석을 **합계 3개** 투입해 분석 완료하는 것이다. 같은 보석 또는 혼합 기여가 가능하고 비용은 `data/expedition_research.json`에 둔다. 생태의 살아 있는 표본 인벤토리를 이 보석 시료와 합치지 않는다.
- 요청 `research_contribute`는 `station_id`, `project`, `resource`, `amount`, `expected_stage`만 받는다. 클라이언트가 발견 증거·단계·사용권·대상 캐릭터를 지정할 수 없다.
- 호스트가 현재 실제 `ship:research` 노드의 위치를 조회해 같은 공간/행성·3m 거리를 확인한다. 증강 장치의 좌표와 구분하며 FINCH는 연구대가 아니다.
- 참가자는 자기 배낭에서만 기여한다. 공동 창고·선박 화물·동료 배낭은 자동 차감하지 않는다. 합계가 채워지면 누구의 기여든 같은 프로젝트가 분석 완료된다.
- 표본 차감·기여·단계·영수증을 기존 복사본→저장→공개 거래로 함께 확정한다. 중복 순번은 기존 영수증, 새로운 초과 기여·지난 단계/리비전은 거절한다. 저장 실패 시 양쪽 모두 원복한다.
- 공동 원장은 모든 승무원 스냅샷에 동일하게 포함한다. FINCH 문맥에서 얻은 새 발견도 주 세계에 보존하도록 문맥 반영 경로를 연결했다. 실제 분산 원정 검증은 A08에 남긴다.

제작 화면과 실제 제작·개조는 `FrontierExpeditionResearch.craft_reason`을 공유한다. 기초 T1/T2 개방과 기존 장착/사용을 유지하며 분석 완료만으로 Mk.3 사용권을 지급하지 않는다. A06/A07 전에 시제품·시험·완료 단계를 클라이언트 요청으로 건너뛰는 API는 없다.

## 확인 범위

Godot 4.7.2의 관련 규칙 **30개, 실패 0**. 새/이전 저장, 스캔 이행·멱등성, 잘못된 저장 거절, 발견 중복, 거리/필드/단계, 저장 실패 원복, 재요청, 초과/동료 기여, 공유 상태, 프로필 분리, FINCH 거절, 호스트 재개, 제작 권한 일치를 확인했다. 미래 제작 가능 상태의 권한 검사는 테스트에서만 Mk.3 설정을 잠시 바꾸고 복구했으며 제품 데이터는 계속 비활성이다.

실제 Metal Forward+ 원정 창에서 **6개, 실패 0**. 기본 진입·연구대 F·실제 소켓 제공자·내부 표본 요청/공개 상태·증강 장치 위치 구분·저장 재개를 확인했다. 이 확인에는 격리 세계의 발견 기록과 보석을 준비했다. 전체 직접 채굴 원정·지연 ENet·6인 인터넷을 검증했다는 뜻이 아니다.

새 모델·음향·화면 연출을 제작하지 않아 Blender 작업이나 전체 청음/회귀를 반복하지 않았다. A06에서는 실제 연구대의 표본 배치·분석·시제품과 호스트 결과 연출을 연결한다.
