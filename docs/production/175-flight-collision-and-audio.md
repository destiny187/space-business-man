# 선체 상호 충돌·물리 피해와 미사일 음향

2026-09-13 사용자 확정: 홍보 영상에서 발견한 실제 게임 버그를 우선 수정한다. 자연스러운 기체/유닛 이동, 미사일 음향 교체와 비행체끼리의 충돌·양쪽 물리 피해가 요청 범위다. 보행과 리깅의 원인·수정은 [174 기록](174-coopertech-locomotion.md)이 소관이다.

## 구현

기존 비행 AI에는 플레이어를 피해 선회하는 동작과 특정 접근을 중단하는 조건만 있었고 선체끼리 맞닿았을 때의 물리 반응·상호 피해는 없었다. 호스트의 현재 이동 구간에 연속 충돌 검사를 추가한다. 같은 항성계의 공동선, 출항한 FINCH, 현재 교전의 살아 있는 해적 기체를 대상으로 접촉 시점에 위치를 나누고 질량·반발 계수에 따라 두 속도를 변경한다. 실제 충돌 때 실드부터 양쪽 피해를 계산한다. 단순히 붙어 있는 동안 피해·소리를 반복하지 않으며, 충돌 후 남은 속도는 시간에 따라 감쇠한다. 빠른 한 프레임에 서로 지나쳐 버리는 경우도 판정한다.

플레이어 선체 9종·FINCH·해적 3종의 GLB 전체 경계와 게임 내 배율로 중심/반경을 계산했다. 첫 충돌 형태는 보수적인 구형 경계다. 날개별 정밀 충돌이나 회전 관성·선체 찌그러짐을 가진 완전한 강체 시뮬레이션은 아니다. 질량·반발·피해/회복 수치는 `space_combat.json`의 초기 조정값으로 관리한다. 기존 천체·정거장 장애물 검사는 유지한다. 평화로운 기업 교통 선박 전체에 상호 피해를 적용한 것은 아니다.

전투 밖 공동선–FINCH 충돌도 처리하며, 선체가 0이 되면 기존과 같은 기본 회복 시간/선체 수치를 사용해 제어를 복구한다. 화물은 잃지 않는다. 충돌 직후의 표시 위치는 호스트의 교정 위치를 따라가도록 해 화면 보간이 다시 서로 겹치게 만들지 않는다. 저장에 충돌 속도·접촉 순번·접촉 유지·긴급 복구 잔여 시간을 선택 필드로 보존하고 검증한다. 새 필드가 없는 이전 저장은 유지한다.

## ElevenLabs 음향

발사·폭발에 부스트음과 플라스마 총소리를 재사용하던 연결을 전용 신규 음원으로 교체한다. 발사 때 적용하던 1.3배 피치도 제거한다. 아군과 적의 미사일은 같은 새 발사/폭발 계열을 사용하고, 선체 충돌에는 폭발과 구별되는 금속 충격음을 연결한다. 부스트 스킬은 본래의 부스트음으로 분리한다.

ElevenLabs 웹에서 각 2초, 반복 없음, 프롬프트 영향도 30%로 생성했다. 발사 프롬프트가 중복 제출되어 두 묶음이 생성됐으며 이를 숨기지 않고 이력에 남겼다. 다운로드가 멈춘 페이지에서 추가 재생성을 하지 않고 새 기록 페이지로 원본을 받았다. 선택한 3개 WAV 원본·프롬프트·해시·게임 파일은 [생성 이력](../../audio/manifests/space-combat-20260913.json), 재가공은 `tools/process_space_combat_audio.py`에 보존한다. 게임 파일은 48kHz 모노, 1.65/1.25/1.1초이며 앞뒤 페이드·저역 정리·피크 조절을 적용했다.

현재 원정에서 실제 무기 발사→미사일 명중→선체 접촉의 새 스트림 재생과 메뉴에서 정지를 확인했다. 8.27초의 SFX 버스 녹음은 피크 0.341, 클리핑 표본 0이다. 청감의 주관적 품질 확인을 완료했다고 주장하지 않는다. 음향 검수 녹음은 `output/gameplay-physics-20260913/combat-live-sfx.wav`에 보존한다.

## 단일 행동의 처리 범위

충돌은 현재 운항 중인 소수 기체의 위치/속도와 기존 전투 실드·선체만 갱신한다. 전체 은하·인벤토리·건물·지형을 복사하거나 재생성하지 않는다. 각 접촉 쌍에서 전체 저장을 실행하지 않으며 피해가 발생한 호스트 결과만 기존 변경/저장 경로로 전달한다. 접촉 유지 상태로 중복 피해를 막는다. 렌더 효과와 음향은 기존 사건 순번을 한 번 소비하며 메뉴 중 과거 소리를 재생하지 않는다.

기체 쌍 비교와 충돌 위치가 천체에 막히는지 확인하는 기존 지역 장애물 검사는 유지한다. 아주 큰 편대나 외부망 6인에서의 성능 상한은 측정하지 않았다. 접촉 자체의 위치 교정은 네트워크 스냅샷/정기 저장을 따르며 피해가 없는 모든 프레임을 즉시 별도 저장하지 않는다.

## 영상

기존 지상 컷이 이전 코드인 문제와 실제 게임 버그를 구분한다. 수정된 주 프로젝트의 스크립트·데이터·모델·음원을 촬영용 복사본에 반영하고 해시를 `output/gameplay-physics-20260913/capture-source-hashes.json`으로 남긴다. 지상전·미사일 교차전 교체와 최종 인코딩은 실제 산출 후 아래에 기록한다. 고정 60fps 촬영/출력은 실제 장치에서 모든 상황이 실시간 60fps라는 뜻이 아니다.

최종 반영: 지상 4개 총기 컷과 비행 미사일 교차 컷을 현재 수정본으로 다시 촬영하고 16컷/48.4초 편집에 반영했다. 나머지 항성계 탐험·고속 항해·행성별 광물·굴착/보석/동굴 분석·건설부터 복원 완료까지의 컷은 유지했다. 출력은 다운로드 폴더의 `우주_비즈니스맨_이동충돌수정_48초_1080p60.mp4`다. 게임 화면 1280×720을 1920×1080으로 확대해 출력했으며 60fps·2,904프레임 전체 디코드, 검은 구간 없음, 연속 동일 프레임 없음, -16.23 LUFS / -1.36dBTP를 확인했다. 동굴 분석과 정지 건설의 낮은 화면 변화 구간은 의도된 내용이며 장치 실시간 60fps 검증으로 해석하지 않는다. 지상 촬영 종료의 ObjectDB 3개 누수 경고는 남았고 촬영 중 스크립트 오류는 없었다.

사용자의 마지막 지시에 따라 세 로봇의 추가 속도 튜닝과 나머지 생물 검증은 진행하지 않고 영상 완성을 우선했다. 네발 동물의 접근/근접 공격과 전체 생물 검증은 후속이다.

## 같은 환경의 테라포밍 컷 교체

2026-09-13 후속 요청에 따라 이미 적용된 지표 복원 반경 1.5배로 테라포밍 3컷만 다시 촬영했다. 시드 71491·행성 13·중심 (-27, -23), 8개 시설의 종류·좌표·건설 순서는 이전 촬영과 동일하다. 카메라 거리를 1.5배 늘려 빈 땅→실제 비용을 낸 순차 건설→환경 처리→녹지와 나무 정착→완료 전경을 담았다. 평가 진행 100%, 정산 불가 사유 없음, 복원 면적 2304→4608을 확인했다. 준비 재고와 시간 배속을 사용하는 촬영이며 반경·생산 규칙이나 게임 코드는 이번에 바꾸지 않았다. 반경 구현과 행동 범위 검사는 [134 제작 기록](134-terraform-surface-progression.md#2026-09-13--실제-지표-복원-반경-확대)이 소관이다.

새 파일은 다운로드 폴더의 `우주_비즈니스맨_테라포밍확장_48초_1080p60.mp4`다. 기존 최종 파일을 보존했다. 48.4초·1920×1080·60fps 출력, 전체 2904프레임 디코드, 검은 구간 없음, -16.23 LUFS / -1.36 dBTP를 확인했다. 1280×720 게임 화면을 확대했으며 실시간 60fps 성능 측정은 아니다. 축소 프레임 비교에서 고유 2859개·최대 연속 동일 3프레임이고, 정지 건설·분석 구간의 낮은 화면 변화는 남는다. 촬영 중 스크립트 오류와 세계 검증 오류는 없었다. 원본·동일 환경 비교·검사 결과는 `output/action-story-20260913/terra_radius/`에 보존한다.
