# 지하 운반 로봇과 실제 물류

2026-09-06 E0-B 후속 기능 실증이다. [자동화 목표](../game/03-robots-and-automation.md)의 지하 운반·경로 없음·화물 보존·재로드를 우선 연결했다. 기초 사업·제작·전력·충전·다중 로봇 정책까지 통합한 상태는 아니다.

## 형상과 움직임

승인 기준작 M–07의 원본을 보존하고 [새 Blender 원본](../../art/blender/robots/locus_courier.blend)에서 여섯 바퀴의 회전 중심을 분리했다. 외형을 새로 승인받은 모델로 표현하지 않는다. 원본 부품은 편집 가능하며 내보내기에서 회전부별 재질을 병합한다. [출력 기록](../../art/blender/robots/locus_courier.json): 219,740삼각형, 39개 병합 표면, 독립 회전 중심 6개. 실제 이동 거리로 바퀴를 회전시킨다.

[공통 INK 실제 스튜디오 촬영](media/ink-catalog/locus_courier.png)과 [지하 회수 화면](media/courier/pickup.png)을 확인했다. 공통 재질·윤곽 경로를 사용한다. 표시 모델과 단순 캡슐 충돌은 분리한다.

## 현장 물류

- 굴착으로 얻은 암석을 현장 휴대분에 기록한다. `R`로 로봇을 호출하면 물리적으로 접근한 뒤 적재하고 착륙 창고에 돌아가 하역한다. 휴대·로봇·창고의 합계가 유지된다.
- 경로는 지형의 바닥·경사·상부/측면 여유를 검사하는 제한된 A* 탐색으로 만든다. 고정 동굴의 경유 좌표 목록을 로봇에게 주지 않는다.
- 경로 생성은 작업 스레드, 실제 이동은 CharacterBody 충돌을 사용한다. 길이 막히거나 바닥이 없어지면 화물을 보존하고 재탐색한다. 메시가 준비되지 않은 구역으로 움직이지 않는다.
- 플레이어와 로봇의 관심 지역을 합쳐 스트리밍한다. 로봇이 지표에 남아도 지하로 내려간 플레이어 때문에 그 바닥이 사라지지 않는다.
- 행성별 물류 블록에 휴대 수량·로봇 위치/작업/화물·창고 수량·하역 횟수를 저장한다. 운반 중 재실행하면 현재 위치에서 경로를 다시 만들고 작업을 이어간다. 이 실증의 휴대분은 호스트 세계 자산이며, 개인 프로필의 영구 반출 장비가 아니다.

## 검증과 한계

`tools/test_expansion.sh --with-ui`에 지형 경로·물류 규칙·실제 운반 검사를 추가했다. 물류 규칙 17개, 실제 화면·굴착·적재·운반 중 재로드·귀환·하역 19개가 통과했다. 협소 통로·천장·제거된 바닥·화물 포화·반복 하역·잘못된 저장도 검사한다. 기존 100만 주소·지하 왕복·광원 검사를 함께 통과했다.

M2, 1280×800에서 로봇 1대의 지하 회수 측정은 최근 1,326프레임 평균 **18.74ms**, p95 **22.28ms**, 정적 메모리 **144.10MiB**였다. [측정 원본](media/courier/measurement.json). 같은 작업 중 이전 측정은 평균 42.21ms/p95 52.15ms로 차이가 컸다. 병행 작업이 있는 로컬 환경의 짧은 측정이며 6인·최소 사양 성능 보장으로 사용하지 않는다.

[별도 정지 장면 진단](media/courier/surface_profile.json)은 로봇/SSAO/손전등 그림자를 차례로 제외해 비용을 비교했다. 이 환경의 GPU 시간 API는 0을 반환하여 GPU 비용을 측정하지 못했다. 이를 GPU 비용 0으로 해석하지 않는다. 화면에서 로봇이 가려진 경우의 드로콜 비교도 전체 로봇 비용을 뜻하지 않는다. 시각 품질을 낮추는 설정 변경은 이 진단으로 확정하지 않았다.

충전·구조 장비·여러 로봇의 예약·시설 장애물 회피·일반 동굴망·협동 소유자별 휴대분은 후속 통합 대상이다. 현재 지표는 기능 실증이며 지질 조형·LOD 경계·최종 화면 구성의 제작도 남아 있다.
