# 동물 리모델링 R02 — 구조별 일괄 제작

2026-09-13 정리: 아래는 제작 당시의 이력이다. 현재 5,600종은 새 모델을 사용하며 구형 동물 파일·대체 로딩은 [172 자산 정리](172-retired-animal-assets.md)에서 제거했다. 저장 호환용 카탈로그는 보존한다.

2026-09-12. 사용자는 전체 작업을 계속 요청하면서, 몇 종씩 제작하는 속도로 전체 동물을 교체할 수 있을지 우려했다. [155 전체 제작](155-creature-remodel-rollout.md)의 승인 품질을 유지하면서 종별 형상·골격·동작을 함께 출력하는 제작 단위로 확장한다. **56종의 새 모델·골격·동작과 실제 게임 렌더를 확인했다.** 일반 원정 표시도 56종 추가 연결해 **누적 제작 65종·일반 원정 표시 62종**이 됐다. 전체 동물 5,600종 중 5,535종은 새 모델 제작 전이다.

## 이번 묶음

기존 동물 ID 56개를 대상으로 한다. 이미 제작한 고리형·방사형·현수형·압력낭형 네 종은 중복 제작 수에서 제외한다. 새 접판형과 분기형을 더하며, 식물·미생물의 종수나 기존 동물의 원산지는 바꾸지 않는다.

| 계통 | 이번 대상 | 실제 형상과 관절 차이 |
| --- | ---: | --- |
| torus_loom / 고리형 | 9 | 단일/쌍 고리, 고리 마디, 비틀림, 매달린 여러 여과관, 3~8개 지지 사지 |

여섯은 이번 계통 묶음 수다. 전체 리깅 종류의 상한이 아니며, 이 안에서도 사지·기관·분기 수가 다르면 골격이 달라진다. 기존의 `body_plan`을 읽어 실제 사지 수를 유지하고, 전체 크기·색만 다른 것을 새 모델의 차이로 세지 않는다. 감각공/렌즈는 각 외형의 보호 구조에 배치하며, 원본 카탈로그의 감각 수치가 이번 모델에 모두 일대일 재현됐다는 뜻은 아니다.

## 제작 도구의 변화

`tools/creature_remodel/recipes.py`는 원본 종 ID·계통·사지 수·기관과 체형 데이터를 제작 규칙으로 바꾼다. `build_batch.py`는 승인 모델의 연속 연조직, 곡면, 부위별 재질, 스킨 웨이트와 INK 출력을 재사용한다. 다리 IK는 매 관절마다 Blender 전체 의존성 그래프를 갱신하는 대신 부모/rest 행렬로 계산한다. 형상 세부를 줄여 처리 속도를 확보하는 방식은 아니다.

각 종에 Blender 원본, near/far GLB, 골격·소켓·클립·보폭 메타데이터, Blender 실제 렌더를 남긴다. 레시피/공통 제작 코드의 지문과 GLB 해시가 같고 원본·렌더가 있으면 다음 실행에서 건너뛴다. 원본 카탈로그에서 한 종의 제작 입력만 바뀌면 그 종을 다시 만들고, 공통 제작 코드가 바뀌면 영향을 놓치지 않도록 다시 출력한다. 공유 원본의 수동 편집까지 자동으로 병합하는 도구는 아니다.

전수 동물 목록 `queue.json`은 모델 제작·게임 렌더·일반 원정 교체를 따로 센다. 기존 92개 구조 구분은 빠뜨린 ID를 찾는 제작 색인이다. 이를 92개의 완성된 제작기나 승인된 리깅으로 기록하지 않는다.

## 움직임과 게임 연결

각 모델은 대기·걷기·달리기·섭식·공격·피격·방어 반동·정지·좌/우 선회·무력화의 11개 클립을 갖는다. 디딤 위상은 모델의 실제 사지별 값으로 전달하고, 기존 지형 보행 구동기가 실제 이동량과 종별 보폭에 맞춰 클립을 재생한다. 무력화 클립이 있는 새 모델은 하중을 내려놓는 동작을 재생한다. 예전 모델의 기존 동작 경로도 유지한다.

섭식의 입 움직임과 호흡이 반복 끝에서 처음으로 이어질 때 주기가 맞지 않는 문제를 제작 중 발견했다. 같은 전체 주기로 맞춘 뒤 다시 출력하며, 실제 GLB의 반복 클립 트랙 시작/끝 값도 확인한다. 중단 전 저장한 원본은 보존하고 Blender를 재실행해 출력한다.

각 구강은 자기 골격에서 계산한 소켓을 갖는다. 두 머리나 여러 밸브가 있는 경우 각각 따로 추적한다. 준비·방출/물기·회수 동작의 기관 위치를 보여 주며, 노란 타격 원은 추가하지 않는다. 이 종들의 기존 호스트 공격형은 별도로 확인하고, 공격 제작 클립이 있다는 이유로 새로운 공격 성향이나 피해를 켜지 않는다. 공격거리·이동 속도·피해량 밸런스는 변경하지 않는다.

## 확인 상태와 남은 범위

Blender 원본 56개, near/far GLB 112개, 종별 11개 클립(총 616개)과 Blender Cycles 렌더 56개를 제작했다. 관절은 종당 17~59개이며, 뼈 이름을 제외하고 부모/자식의 연결만 정규화해도 40가지 구조다. 전체 크기와 위치를 정규화한 형상 해시도 56개 모두 다르다. 이는 모든 종이 서로 다른 큰 계통이라는 뜻이 아니라, 같은 계통 안에서도 실제 형상과 관절 구조를 구분했다는 근거다.

Godot 4.7.2 / Metal Forward+ / Apple M2의 실제 원정 배우로 전 종을 실행했다. 각 종의 240개 보행 프레임을 진행하며 9개 자세/LOD 화면을 캡처했고, 대표 6종은 걷기→현재 T5 도주 속도 **4.025m/s**→감속→선회→섭식→공격 기관 준비/작동/회수→무력화를 연속 촬영했다. 검토에서 사용하는 빠른 이동은 기존 호스트 프로필에서 읽으며 게임 속도를 수정하지 않는다.

네 발 방사형 `bio_pentapalm_06`은 섭식 중 몸통 호흡에 따라 지지발이 실제 다리 길이를 약간 넘어섰다. 초기 최대 지지발 목표 오차 0.029325m를 재현하고, 길이가 부족해지기 전에 지면을 따라 발을 조금 안쪽으로 다시 디디도록 수정했다. 해당 개체는 0.007363m 이하로 줄었다. 수정 후 전 56종과 기존 승인 방사형 `pentafold`를 다시 확인했다. R02 전수의 최대 지지발 목표 오차는 **0.015156m 미만**, 권위 위치 오차는 0이었다. 이 수치는 검토 경사의 지지발 IK 오차이며 모든 지형이나 공중 발 궤적의 완전한 검증을 뜻하지 않는다.

저장된 무력화 개체가 일시적인 전투 상태를 잃었을 때, 자연 휴면과 같은 느린 대기 동작으로 돌아가는 표시 경계도 수정했다. 기존 `incapacitated` 상태로 무력화 완료 자세를 복원하며 저장 필드나 체력은 바꾸지 않는다. 자연 휴면의 기존 동작은 유지한다.

112개 GLB의 실제 스킨 가중치 합·뼈 참조·유한 좌표/애니메이션, 11개 클립과 반복 시작/끝을 검사했다. 원본 카탈로그 네 파일의 해시는 유지됐다. 동일 제작 명령을 재실행했을 때 **56개 모두 BATCH_SKIP**으로 건너뛰어 모델을 다시 출력하지 않았다.

제작/내보내기의 종별 중앙값은 약 11.7초, Blender 원본 렌더는 약 14.8초였다. 실행 중 부하와 GPU 초기 준비 실험의 영향을 받은 편차가 있어, 이를 전체 5,600종의 완료 시간으로 외삽하지 않는다. 이번 최종 자산의 원본 렌더는 CPU Cycles를 사용했고, GPU 시험을 완료된 가속 기능으로 기록하지 않는다.

전체 원정 플레이와 모든 지형, 멀티플레이, 저장된 생물 사건의 교체, 돌진/도약 대표의 호스트 공격 연결, 비행/착지, 전종 전투 판정과 새 전용 음원은 이번 묶음의 완료 범위로 확대하지 않는다. 기존 생물 사건과 보류 종은 기존 모델을 유지한다. 검토 영상은 무음이다.

최종 명시 목록의 62종은 차가운 시작에서 실제 임포트 모델 선로딩·far 지연 설치와 입 소켓을 확인했다. 기존 `native` 사건과 이전 `scavenger` 사건 경로는 교체를 명시적으로 제외하며, 보류한 돌진/도약 원본도 유지한다. 원정 전체를 수동 플레이한 확인과는 구분한다.

필수 행동 범위 검사도 수행했다. 같은 종의 두 원정 배우 중 하나만 이동·무력화 복원하고, 다른 개체의 골격 자세·모델 노드 ID·위상·접지 캐시가 그대로임을 확인했다. 거부된 공격과 같은 무력화 복원 입력의 반복도 새 동작이나 모델 생성을 만들지 않았다. 변경 경로는 기존 호스트 상태를 읽어 해당 배우를 표현하며 저장·네트워크 발행 함수를 추가하지 않는다. 보이는 배우의 골격 내부 갱신과 최초 등록 목록 읽기는 필요하지만 모든 행성·개체의 복사나 모델 재생성으로 확산하지 않는다. 숨겨진 배우는 기존 렌더 생략과 원거리 접지 조회 간격을 유지한다.

## 다음 제작의 단위

한 종마다 도구와 검토 장면을 새로 만드는 방식을 줄인다. 이후에는 기존 개체의 사지·기관·행동을 읽어 **구조 제작기를 확장 → 수십 종 출력 → 전수 렌더 → 문제가 있는 개체 수정 → 호환되는 원정 표시 적용** 순서로 진행한다. 현재 레시피로 처리할 수 없는 5,600종 전체를 단순 반복으로 출력할 수 있다고 주장하지 않는다.

다음 큰 대상은 많은 종이 속한 지상 체형과 기관의 조합이다. 같은 `construction` 값 안에도 공중 개체와 다른 행동이 섞여 있으므로, 계통 이름만 같다고 이번 지상 골격을 일괄 적용하지 않는다. 돌진·도약과 날개/착지처럼 실제 운동 방식이 다른 대상은 먼저 해당 움직임을 해결한다. 이번 묶음의 측정 시간은 이미 제작 규칙을 작성한 종들의 출력 시간이며, 남은 구조 설계·전투 연결·시각 수정까지 포함한 전체 완료 예상 시간이 아니다.

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --python tools/creature_remodel/build_batch.py
./tools/godot.sh --headless --editor --import --quit
./tools/godot.sh --script res://scripts/showcase/creature_batch_review.gd
./tools/godot.sh --script res://scripts/showcase/creature_batch_review.gd -- --video bio_torus_loom_02 bio_pentapalm_07 bio_pendulum_grazer_05 bio_quill_amphora_10 bio_hinge_book_08 bio_mirror_fork_09
/tmp/instagram-promo-venv/bin/python tools/creature_remodel/package_batch.py
python3 tools/plan_creature_remodel.py
# 화면 검토를 마친 뒤에만 명시적 적용
/tmp/instagram-promo-venv/bin/python tools/creature_remodel/package_batch.py --enable-reviewed
./tools/godot.sh --headless --script res://scripts/showcase/creature_remodel_field.gd -- --check-registry
./tools/godot.sh --headless --script res://scripts/showcase/creature_batch_review.gd -- --check-scope
```
