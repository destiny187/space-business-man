# 일반 거래 비동기 확정·지역별 초안 — 2026-09-12

사용자는 [158 조사](158-action-scope-audit.md)의 앞선 수정을 커밋한 뒤 일반 거래의 전체 동기 저장과 날씨·사건의 반복 세계 복사를 이어서 처리하도록 요청했다. 앞선 시작·현장 사용성 및 행동 범위 수정은 `00cc821a3`에 커밋했다. 이 기록은 그 후속이며 저장 JSON 형식과 기존 세계를 재생성하지 않는다.

## 일반 거래의 확정 순서

현재 세션의 일반 요청은 `WorldStore.begin_commit`으로 저장을 제출한다. JSON 직렬화·임시 파일 기록·읽기 확인·백업·원자적 교체는 기존의 순서 보장 작업 스레드가 담당한다. 파일 교체 전에는 변경된 재료·아이템·요청 영수증이나 성공 효과를 공개하지 않는다. 완료된 상태를 먼저 발행한 다음 해당 요청의 응답을 전달한다.

앞선 자동 진행·거래 저장이 있으면 입력 처리에서 스레드를 기다리지 않는다. 일반 요청은 원래 session ID·승무원·순번·revision을 보존한 최대 32개 대기열에서 기다린다. 같은 요청의 재전송은 작업을 추가하지 않고, 같은 순번의 다른 내용은 거절한다. 최신 상태와 맞지 않는 요청은 실패로 돌려주며 비용을 새 상태에 맞춰 임의로 재해석하지 않는다. 채광·연사 입력은 기존 재사용 대기 응답을 유지한다.

저장 작업 실패는 후보를 버리고 세계를 정지한다. 성공 응답이나 비용 차감·아이템 지급은 없으며, 대기 요청도 실패 처리한다. 접속자가 달라진 peer ID로 옛 요청이나 응답을 넘기지 않는다. 변경 없는 대기열 실패·영수증 재전송은 지표를 다시 발행하지 않고, 오래된 상태의 실패에는 최신 승무원 상태만 전달한다.

후보가 바꾸지 않은 승무원은 저장 중에도 움직인다. 개인 장비만 바뀐 경우에는 이전 장비로 계속 이동하고, 완료 시 새 장비와 더 최근 위치·상태를 합친다. 피해·구조·위치/탑승 상태를 거래가 바꾼 승무원은 해당 확정을 기다린다. 로버도 변경되지 않은 기체와 탑승자만 계속 움직인다. 저장 스레드는 별도 복사본을 소유하므로 이러한 런타임 갱신이 기록 중인 자료를 수정하지 않는다.

새 게임 시작·합류·이탈·종료와 명시적 체크포인트 경계의 동기 저장은 유지한다. 일반 입력의 비동기화로 전체 저장 계산이 모두 사라졌다는 뜻은 아니다.

## 명시한 변경 범위의 독립 초안

`persistence/world_draft.gd`는 해당 동작이 실제로 쓰는 분기만 독립 복사한다. 다른 분기는 그 동작에서 읽기만 한다. 변경 범위를 모르는 일반 명령은 기존 전체 독립 초안을 유지한다.

| 동작 | 독립 복사하는 데이터 | 보존하는 경계 |
| --- | --- | --- |
| 장비 선택·장착·휴대 제작·장비/탐험복 개조 | 대상 승무원, 개인 배낭, 영수증 목록, 해당 FINCH 기록의 상위 필드 | 생태·다른 재고·지형·다른 승무원을 복사하지 않음. 표본을 이동하지 않는 5개 명령에서 전체 표본 정리 생략. 연구 시제품 등은 전체 초안 유지 |
| 날씨 0.25초 진행 | 접속 승무원, 기상 시계·행성 목록, 현재 착륙 지역의 기상 기록 | 날씨가 발생하지 않아도 시계·체류/노출 시간을 진행. 피해와 구조 위치는 독립 승무원 기록에 적용 |
| 사건 0.25초 진행 | 활동 승무원, 사건 목록, 활동 지역의 사건 및 이탈 운반자가 있는 사건, 해당 지역 지형 편집, 현장 상위 기록과 엄폐물 | 사건 시간·단계·원주 생물 사건·로봇 공격·엄폐물 피해·지진 통로를 유지. 다른 지역의 이탈 운반자도 화물을 내려놓을 수 있음 |
| 같은 저장 후보 뒤의 물·생태 진행 | 현재 지역 물 기록·현장 침수 상태, 현재 생태 구획 | 후속 갱신이 아직 공개하지 않은 후보와 공유된 이전 세계를 먼저 수정하지 않도록 분리 |

기존 전체 초안과 날씨·사건 결과가 같음을 비교하고, 원본의 모든 중첩 Dictionary/Array를 읽기 전용으로 고정한 상태에서도 후보의 피해·구조·엄폐물·지형·물·생태 진행을 검사했다. 무관한 생태와 다른 현장은 같은 참조를 읽기 전용으로 공유한다. 새 동작이 쓰는 분기를 추가하면 이 변경 범위도 함께 갱신해야 한다.

## 실제 확인과 측정

Godot 4.7.2, Apple M2, Forward+ / Metal에서 별도 착륙 저장 복사본을 사용했다. [실행·측정 근거](media/transaction-drafts/README.md)를 보존한다.

| 국소 함수 시간 | 이전 | 후속 |
| --- | --- | --- |
| 장비 슬롯 선택 요청, 약 100KB 검사 저장 | 33.79~37.91ms | 국소 검사 9.86~16.61ms, 실제 창 입력 11.56ms |
| 작은 저장의 전체 초안 / 날씨 / 사건 | 같은 전체 복사 경로 | 전체 0.591ms / 날씨 0.036ms / 사건 0.079ms |
| 무관한 생태 이력 10,000건을 추가한 초안 | 전체 깊은 복사 9.338ms | 개인 장비 0.031ms / 날씨 0.030ms / 사건 0.062ms |

초안 시간은 5회 중간값이며 합성 이력은 복사 비용 비교용이다. 전체 플레이 FPS나 큰 실제 세계의 최악 시간은 측정한 것이 아니다. 슬롯 입력의 시간에는 저장 전 검증·스냅샷 준비가 남아 있다.

- 실제 1280×800 창에서 핫바 선택, 저장 완료를 의도적으로 늦춘 4개 렌더 프레임, 확정 뒤 슬롯 표시, 유료 장비 제작, 일반 전체 초안 명령과 최종 저장을 확인했다. 세 입력 모두 동기 저장 호출은 0회였다. 실제 제작 비용과 아이템은 함께 저장됐고 재전송해도 다시 지급하거나 차감하지 않았다.
- 국소 검사는 일반 요청의 대기·실패·이동 유지, 날씨/사건 결과 일치·원본 보존, 기존 채광의 영수증·중복 지급 방지, 체크포인트 순서·로버 이동과 발행 범위를 확인했다. 발견된 문제에 한정해 실행했으며 전체 묶음·6인 장시간 검사를 추가하지 않았다.
- 실제 창 종료에 ObjectDB 1개 누수 경고가 남았다. 경고 없는 종료나 전반적인 60 FPS 달성으로 기록하지 않는다.

## 남은 비용

`WorldStore.begin_commit`의 **전체 도메인 검증과 작업 스레드용 가변 스냅샷 복사는 메인 스레드에 남는다.** 장비 5개 명령 이외에는 권한 처리 단계의 전체 독립 초안도 유지한다. 산업의 1초 전체 초안, 사건 목록의 얕은 복사·순회, 변경된 지역 패킷을 구성한 뒤 비교하는 비용과 지형 의존 캐시의 넓은 무효화도 이번 두 문제의 수정으로 제거되지 않았다.

따라서 이번 결과는 일반 입력의 동기 파일 대기를 제거하고 개인 장비·날씨·사건의 불필요한 전체 초안을 줄인 것이다. 도메인별 검증·저장 기록과 전체 체크포인트를 분리하는 더 큰 전환은 원자성·기존 저장 복구·협동 순서를 함께 다뤄야 한다. 필수 [행동 범위 검사](../technical/01-godot-architecture.md#단일-행동의-변경갱신-범위--필수-검사)는 계속 적용한다.
