# 공동 원정선 내부와 6인 플레이 실증

2026-09-06 E0-C의 실제 접속·선내 이동·공동 항해를 구현했다. [실행](../../tools/show_crew.sh)하거나 시작 화면에서 `함께하는 원정 · 최대 6명`을 선택한다. 지표 분업까지 완성된 온라인 게임은 아니며, [협동 기술 설계](../technical/04-coop-networking-and-session-save.md)의 현재 구현과 남은 범위를 함께 확인한다.

## 실제 플레이

호스트가 방을 열면 자신의 세계를 읽거나 생성한다. 참가자는 자신의 캐릭터·소유 장비 ID·등급·특성을 유지한다. 이름이 같다는 이유로 다른 사람의 재접속 기록을 사용할 수 없다. 직접 UDP 주소로 접속하며 이번 검증은 한 Mac의 서로 다른 Godot 프로세스에서 수행했다. 친구 초대·중계·다른 인터넷 회선은 미검증이다.

선내에서 `WASD`로 이동하고 우클릭 드래그로 시선을 돌린다. `C`로 외부 시점과 선내를 전환한다. 승무원은 독립적으로 걸으며 호스트가 벽·좌석·창고 충돌을 계산한다. 좁은 통로에서 동료가 길을 완전히 막지 않도록 승무원끼리는 충돌하지 않는다. 다른 참가자의 위치는 보간하고 팔·다리는 이동 거리에 따라 움직인다. 개인 메뉴는 세계를 정지시키지 않는다.

호스트가 조종사를 지정할 수 있다. 조종사만 행성 주소를 설정하고, 모두가 출항 준비를 마친 뒤 항해를 시작한다. **100만 번째 행성까지 선택 가능**하며 실제 선체 위치가 성간 도약·궤도 접근 과정에서 변한다. 선내 창에는 같은 항해를 렌더링한 외부 영상이 보인다. 도착하면 이전 준비 상태를 해제한다.

뒤쪽 공동 보관함 근처에서 암석을 꺼내거나 넣는다. 단절된 사람이 들던 세계 화물은 마지막 위치의 회수 기록으로 남는다. 재접속해도 이미 옮긴 화물이 복제되지 않는다. 회수 기록과 연결한 독립 Blender 상자·수량 표식이 해당 위치에 나타나며, 호스트가 회수를 저장한 뒤 사라진다. `내 소유 장비`로 반입 장비를 확인하고, 호스트는 선택한 승무원의 접속을 종료할 수 있다.

[생성 도구](../../tools/build_crew_cabin.py)가 편집 가능한 원본을 먼저 저장하고, 회전부·재질별로 병합한 게임 파일을 내보낸다. Blender 5.2.1 LTS로 실행했다.

여섯 좌석·안전띠·갑판 판·프레임·배선 덮개·광원·기압문·조작 콘솔·공동 보관함을 제작했다. 탐사복은 압력층·흉갑·생명 유지 팩·바이저·공구 벨트·장갑·자기 부츠를 구분했다. 공통 INK v1 어댑터와 윤곽 셰이더를 적용하며 기준 스타일을 별도로 낮추지 않는다. 초기 화면의 과한 광량과 얇은 한국어 글꼴을 보정했다. 승무원·화물 이름표는 윤곽 처리 뒤에 그리도록 하되 깊이 검사는 유지한다. [Label3D의 투명 렌더 순서](https://docs.godotengine.org/en/stable/classes/class_label3d.html#class-label3d-property-render-priority)를 확인하고 실제 화면에서 가림을 수정했다.

선내는 고정된 별도 좌표 공간, 외부는 전용 3D 뷰포트다. 창 영상의 가로세로 비율을 보정한다. 공동 원정 장면의 선체는 기존 Kestrel 형상을 2배 크기로 표시하여 선내 공간이 외부 선체보다 커지지 않도록 했다. 기존 단독 항해의 크기를 소급 변경하지 않았다. 최종 선박 제원·문/좌석 상호작용·실제 출입 애니메이션 통합은 남아 있다.

- 항해·프로필 23개: 조종 권한·전원 준비·중복 출항·도약 중 저장/재개·마지막 행성·궤도 안전 거리·손상된 개인 장비 원본 보존.
- [실제 ENet 프로세스 검사](../../tools/test_crew_network.py) 26개: 호스트+게스트 5명, 일곱 번째 거부, 강제 단절과 재접속, 공동 창고, 개인 원본, 호스트 정상 종료.
- [실제 게임 장면 검사](../../tools/test_crew_play.py) 33개: 표시 호스트+헤드리스 게스트 5명, 독립 이동·벽 충돌·접속 종료 후 회수 상자/재접속/회수·항로 선택·전원 준비·공동 도약·같은 행성 도착. 한 머신의 검증을 다른 회선·Windows 실기·6개 그래픽 창의 성능 검증으로 해석하지 않는다.

## 남은 통합

공동 착륙·관심 청크 합집합·굴착 기록 전달·연구/생태 동기화·지표 재접속은 후속 [공동 지표 연결](12-shared-surface-and-ecology.md)에서 구현했다. 로봇/건설의 공동 운영·연료와 피해·일반화된 입력 예측·패킷 손실 조건·플랫폼 초대·인터넷/Windows 실기는 미완료다. 선내 세부 아트·보행 발 접지·손 도구·작업 애니메이션·확장 음향도 추가 제작과 실제 검수가 필요하다. 이 문서는 E0-C의 부분 실증 근거이며 전체 인수 항목의 완료 표시는 아니다.
