# 활동형 현장 미션과 티어별 난이도

2026-09-14 사용자 승인: 절벽 중계망 복구는 T2·T3만, 나머지 미션은 최소 등장 티어부터 상위 티어로 갈수록 어렵게 구현한다. [기획 이력](../planning/18-active-field-missions.md)과 [사건 소관](../game/21-exploration-incidents.md)을 따른다. 현재 구현 범위와 실제 확인 결과는 아래와 같다.

## 첫 연결 범위

| 미션 | 등장 | 구현한 목표 |
| --- | --- | --- |
| 절벽 중계망 복구 | T2·T3만 | 세 접시 회전·다음 수신부 방향/지형 가시선 판정, 실제 착지 발판과 암벽 지지, 정상 기록 회수 |
| 폭주 수송대 저지 | T2~T5 | 순환 주행·측면 구동부의 실제 총기 피해 또는 진로 차단, 기존 쿠퍼테크 순찰 호위, 정지 후 화물 운반/인계 |
| 분출 지대 이동 채굴 | T2~T5 | 지점마다 다른 분출 시각·전조·엄폐/거리 피해, 실제 채집기 조건과 개별 결정 회수, 전 지점 완료 후 정산 |
| 쿠퍼테크 재가동 시설 침투 | T3~T5 | 별도 외부 전원 차단, 실제 충돌 격실 개방, 유한 순찰과 코어 운반/인계 |
| 비행 생물 센서 회수 | T2~T5 | 실제 현지 `surface_air` 종의 선회/휴식과 거리·지형 시야 관찰, 날아간 틈에 센서 운반/인계 |
| 탐사 로버 구난 | T2~T5 | 지형 변환기로 실제 충돌 잔해 제거, 배터리 운반/연결, 출발·정지 및 근처 동행, 이동로 끝에서 정산 |
| 수송선 구조와 지상 회수 | T3~T5 | 일부 공동선 우주 조우에 구조선·목적지 결합, 실제 편대 격퇴 후 지상 기록 생성, 유실 화물 순차 운반과 분출 위험 |

기본 완료에 제한시간·무한 증원·전멸 조건을 넣지 않는다. 1인은 목표를 차례로 처리하며 협동에서는 각각 조작·엄호·운반할 수 있다. 인원에 따른 난이도 배율은 이번에 추가하지 않는다. 적과 목표 수는 행성 티어/현장 생성으로 고정해 중도 합류로 다시 생성하지 않는다.

## 초기 난이도와 보상

원본은 `data/active_missions.json`이다. 확정 밸런스나 실측 플레이 타임이 아니다.

로봇 자체 전투 능력은 기존 분대 티어 규칙을 사용한다. 로버는 수송기 기준 속도의 65%로 움직이며 동행자가 멀어지거나 앞에 장애물이 있으면 기다린다. 절벽 발판의 상승 간격은 T2 7m·T3 10m이며 기존 제트팩 성능을 낮추지 않는다. 비행 관찰 시간은 3/4/5/6초, 휴식 구간은 5/4.5/4/3.5초다. 난이도 상승이 체력 증가만으로 끝나지 않게 한다.

새 미션 기본 보상은 정제 소재·제어 회로·강화 프레임·보석이며 회수자 배낭에 들어간다. 기존 사건의 재료 보상이나 무기/모듈 추첨 규칙을 소급 변경하지 않는다. 새 전설 장비·T4/T5 총기 개발을 이번 미션 완료에 포함하지 않는다.

## 기획과 첫 구현의 차이

- 중계 복구의 미관측 광맥 정보 보상은 추가하지 않고 명시된 부품을 지급한다. 신호 연결은 회전 방향과 지형 가시선으로 판정하며 추가 건축물에 의한 전파 차단은 별도다.
- 생물 센서 관찰은 거리와 가시선을 일정 시간 유지해 진행한다. 별도의 E 진행 입력·생물 사건 전용 공격 AI는 추가하지 않는다. 현재 현지 비행종을 사용하며 새 기본종으로 세지 않는다.
- 호위는 사건 주변 기존 순찰/전투 경로를 재사용한다. 수송기에 딱 붙는 차량 대형이나 플레이어 제작 로봇의 동행 명령을 추가하지 않는다.
- 로버/수송선 구난의 이번 보상은 부품이다. 기업 평판·별도 계약 지갑·일일 반복 보상은 추가하지 않는다.
- 수송선 구조는 기존 우주 조우의 일부를 구조 상황으로 연결한다. 수송선 자체 체력 방어 목표·대기권 공중전은 없으며, 플레이어가 추격 편대를 상대해 격퇴하면 수송선이 이탈하고 착륙 현장을 기록한다. 지상 진입은 기존 행성 착륙을 이용한다.

## 자산과 음향

`tools/build_active_missions.py`로 편집 가능한 Blender 원본과 GLB 11종을 제작했다. 접시·차량 바퀴·격실 문·회수 화물 피벗과 기존 공통 INK 재질/가공 모서리를 사용한다. 기존 비행 생물 골격·쿠퍼테크 기체·운반함·배터리·신호기는 재사용한다. 각 미션 대표 모델은 실제 Godot Forward+ INK로 렌더해 J 카드용 투명 아이콘을 출력했다.

음향은 기존 ElevenLabs 구조 신호·조사 완료·제작 완료·굴착/작업·차량/로봇·분출음을 재사용한다. 접시 회전과 연결 성공, 운반과 최종 회수, 분출 시점은 호스트 상태 변경 후 재생한다. 신규 음원 생성으로 기록하지 않는다. 재사용 대응표와 원 생성 매니페스트는 `audio/manifests/active-missions-reuse.json`에 남겼다.

## 저장과 한 행동의 처리 범위

새 미션은 `active-missions-v1` 독립 난수로 배치해 기존 사건 난수열·위치·보상을 유지한다. 원래 사건과 겹치는 후보, 시설/착륙 안전 구역, 부적합 지형과 비행종 없는 행성은 제외한다. 일반 미션은 방문 중 새로 활성화되는 안전한 현장에 추가되며 기존 저장 전체를 재생성하지 않는다. 구조선 현장은 실제 승리할 때 한 번 기록하며 중복 승리 호출로 재지급하지 않는다.

새 미션은 대상 사건의 별도 변경 번호를 검사하므로 무관한 자율 진행으로 세계 버전이 올라도 같은 목표 조작을 거절하지 않는다. 실제 목표가 변경되면 거절하며 이전 요청 영수증으로 중복 회전·지급을 막는다.

F/도구 요청은 기존 호스트 조준·거리·엄폐·도구 간격·요청 영수증을 통과한다. 새 미션 요청에는 해당 사건, 회수자, 해당 재고만 깊은 복사하며 다른 사건·생태 표본 전체 정리를 건너뛴다. 실패한 저장은 원본 미션/재고를 바꾸지 않는다. 완료 후 목표를 제거해 중복 회수와 같은 요청 재전송을 차단한다.

자율 진행은 기존 주변 사건 초안을 재사용한다. 이동/분출은 근처에 승무원이 있을 때 진행하고 호스트 종료/부재중 시간으로 사건을 실패시키지 않는다. 운반자 이탈·구조 후에는 회수 신호기 옆 안전 위치에 화물을 복구한다. 내려놓은 구조 화물은 번호와 실제 위치를 유지하며 다른 상자를 대신 회수해 진행을 잃지 않는다. 전체 저장 검증과 직렬화용 복사, 기존 주변 사건 조회 비용은 남아 있으며 이를 제거했다고 기록하지 않는다.

## 확인 기록

- `check_active_missions.gd`: 실제 원산 비행종이 있는 T3 행성의 생성기를 사용한 7개 현장, 실제 호스트 요청/총기 피해 경로, 개별 완료·중복 회수 거부·저장 실패 원상 보존·해당 사건 복사와 JSON 저장 검증 **98개, 실패 0**. 티어 제한 확인 포함. 입력 대상까지의 이동은 검사 좌표 배치이므로 수동 원정 완주가 아니다.
- Blender/Cycles 11종 원본 렌더와 Forward+ 대표 7종·투명 아이콘을 생성했다. 접시·차량·격실 형태와 INK 명암/윤곽선을 확인했다.
- 실제 `crew_expedition` Forward+ 창에서 7종의 F/도구/총기 입력과 완료를 확인했다. 최초 검사에서 무관한 세계 버전 갱신에 F가 거절되는 문제를 재현해 대상 사건 변경 번호로 수정했다. 후속 원정 121항목 중 차량 검사 입력 5건이 실패했고, 장비 선택 직전 최신 상태 반영과 도구 간격을 지킨 차량 2종 재검사 **49항목, 실패 0**으로 완료했다. 전체 121항목이 무실패였다고 기록하지 않는다.
- `check_mission_request_scope.gd`: 사건 버전·중복 영수증·저장 실패·실제 거리/조준, 화물 내려놓기/재회수와 해당 번호 인계 **12항목, 실패 0**.
- `check_mission_rescue_play.gd`: 실제 구조선 표시, 호스트 마지막 포격→승리→J 현장 등록, 도주 시 미등록·중복 승리 방지·저장/재로딩 **11항목, 실패 0**. 전투의 마지막 적 체력/배치는 검사에서 설정했으며 통상 편대 전투 전체를 수동 완주한 것은 아니다.
- 절벽 암석을 층과 단차가 있는 Blender 모델/실제 충돌로 보완했다. 원 재질의 기본값으로 밝게 내보내지던 암석 4종은 Blender 노드에 색·거칠기를 명시하고 재출력했다. 수정 원본과 해당 Forward+ 모델·최종 절벽 원정 화면을 확인했다. 마지막 모델/화물 표시 확인 **14항목, 실패 0**에서 내려놓은 화물이 한 개만 표시되고 다시 인계됨을 확인했다.
- 작은 창 960×640의 J 사건 화면과 SFX 버스 재생을 캡처했다. 실제 창 검사는 이동 좌표를 배치하고 입력을 호출하므로 걷기·제트팩으로 전 경로를 수동 완주한 검수는 아니다. 차량/최종 화면 검사 종료에 ObjectDB 2~3개 잔존 경고가 있으며 게임 실행 중 오류와 구분한다.

## 남은 검수 경계

전 티어 수동 완주·6인/외부망·장시간 운용·Windows 실기·최종 청감은 아직 수행하지 않았다. 초기 3~25분 기획 시간을 실측 완료 시간으로 해석하지 않는다.
