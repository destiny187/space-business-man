# Q07~Q09 — 전투 표시·음향·협동 복귀

2026-09-14 [기존 플레이 고도화 계획](../planning/17-existing-play-polish-plan.md)의 세 번째 구현이다. 첫 두 묶음은 [181](181-polish-settings-input-and-industry.md)·[182](182-polish-production-and-restoration.md)에 기록했다.

## 플레이 변경

- 생물의 표시 시계가 같은 호스트 스냅샷을 반복 수신할 때 준비 동작을 되감지 않도록 했다. 최대 80ms만 보간하며 준비 끝·근접 접촉·연속 타격·충격파·회수 경계는 호스트 시각을 받기 전 넘지 않는다. 메뉴/정지에서는 진행하지 않는다. 실제 루트 이동·피해·속도·기존 Blender 클립은 변경하지 않았다.
- 확인된 피해 숫자는 화면 밖이나 조준점으로 밀리지 않게 배치하고, 가까운 다중 대상은 주변 열로 나눠 표시한다. 대상별 실제 합산·실드 파괴·격파 표식은 유지한다. 공간이 없으면 추가 표시를 생략하며 피해 계산에는 영향이 없다.
- 개인 효과음/환경음 설정을 실제 SFX/Ambience 버스에 연결했다. UI/음성/산업은 SFX 아래에 두며 신규 값 1.0은 종전 실효 음량을 보존한다. 음악의 기존 개인 배율은 그대로다.
- 산업음은 가까운 12개를 우선하고 채광 로봇의 실제 `창고로 운반`·`충전기 복귀` 상태에도 이동음을 연결한다. 동일 음원의 루프는 재사용한다. 일반 단발음은 활성 24개 상한에서 오래된 비경고음을 먼저 정리하며 우주전은 기존 전용 거리/발음 상한을 유지한다.
- 자기 피격·실드 소진 등의 경고 때 산업 -5dB / 환경 -3dB를 0.35초 유지하고 복귀한다. 사용자 음량과 일시 감쇠는 별도로 관리한다. 효과음 자체를 키우거나 세계를 다시 처리하지 않는다. 값은 `play_presentation.json`에 둔다.
- 승무원 화면에 조종자·선내/지표/FINCH·연결·준비를 구분하고 현재 선박의 실제 탑승/준비 대상을 이름으로 표시한다. 단독 FINCH와 연결이 끊긴 승무원은 공동선 준비 수에 넣지 않는다. 회수 보관 화물도 표시한다.
- 접속 검사에서 참가 확인 전 화면 준비가 8초 제한을 넘는 사례를 재현했다. 게스트는 초기 참가 제안으로 무거운 장면을 만들지 않고 확인 응답을 먼저 보낸 뒤 **호스트가 확정한 활성 스냅샷**으로 장면을 연다. 제한 시간을 늘리거나 미확정 참가자를 활성 처리하지 않는다.
- 기존 캐릭터 재합류는 호스트가 가진 위치/영역을 유지하고 신규 캐릭터만 시작 위치에 배치한다. 기존 연결 종료의 회수 상자·FINCH 화물 규칙은 유지한다. 저장/연결 중단 시 메뉴의 원인·재시도/나가기 경로를 열고 계속하기를 막는다.

## 실제 확인

Apple M2 / Godot 4.7.2 Metal Forward+, 1280×800와 960×640의 별도 원정에서 `check_polish_presentation.gd` **33항목**을 통과했다. 마지막 실행에는 스크립트 오류·정리 경고가 없다.

실제 localhost ENet 두 연결에서 참가 → 공동 화물 철 10개 중 3개 인수 → 준비 → 정상 연결 종료 → 동일 프로필 재합류를 수행했다. 공동 화물 7개·자금 6,000 Cr·장비·호스트 위치를 유지하고, 원래 규칙으로 회수 상자에 보관된 철 3개도 보존했다. 처음 검사는 배낭 3개가 그대로 남는다고 잘못 기대했으므로 회수 규칙을 확인해 검사 기대값을 바로잡았다. 화물을 새로 옮기거나 회수 규칙을 삭제해 통과시키지 않았다.

![960×640 재합류 승무원 상태](media/183-crew-960.png)

기존 생물 자산을 현재 Forward+ 장면에 별도 검수 대상으로 올려 준비/접촉 시계·같은 스냅샷·정지 시점을 확인했다. 접지/고속 이동/접촉의 도메인은 `check_creature_fast_movement.gd` 22항목으로 기존 게임 속도·돌진 충돌/피해 보존을 확인했다. 새 Blender 모델이나 클립을 제작하지 않았다. 선내 검수용 생물 배치는 실제 콘텐츠/스폰 추가가 아니다.

다중 숫자 12개를 같은 표시 위치에 주입해 화면 안 배치·비겹침을 확인했다. 이는 표시 스트레스 검사이며 동시에 12마리와 실제 교전한 결과가 아니다. 기존 지상/우주전의 같은 숫자 표시기를 사용한다.

![효과음·환경음 개별 조절](media/183-audio-controls.png)

기존 ElevenLabs 총기·실드 파괴음을 실제 SFX 출력으로 약 1.035초 [녹음](media/183-mix.wav)했다. 48kHz 스테레오, peak 0.2231 / RMS 0.0457(정규화), 포화 샘플 0개였다. 가까운 산업음 12개 선택·같은 루프 재사용·경고 감쇠/원복·메뉴 일시정지도 확인했다. 녹음 신호와 클리핑 확인은 **직접 청감·장시간 피로도·모든 스피커 믹스 승인**과 구분한다. 새 ElevenLabs 원본을 생성하지 않았다.

중단 메뉴는 표시용 실패 메시지를 주입해 확인했다. 실제 쓰기 실패의 세계 보존/성공 미공개는 첫 묶음의 국소 저장 검사에 근거한다. 마지막에 계속하기 버튼을 비활성화해 중단 화면을 닫고 복구 경로를 잃지 않게 했다.

## 행동 범위·저장·남은 검수

음량 변경은 해당 버스만 처리한다. 루프 선정은 현재 청취자 근처의 현장 소리만 다루며, 퇴장 중인 짧은 페이드가 있을 수 있다. 공격 표시 보간·숫자 배치는 해당 표시 인스턴스만 갱신하고 세계 복사/저장/피해를 만들지 않는다.

참가 확인은 기존 버전/토큰 검증→참가 상태 원자적 저장→활성 스냅샷 순서를 유지한다. 위치 보존은 기존 구성원의 저장 분기를 사용하며, 변경 형식/새 소유권/새 네트워크 메시지를 추가하지 않는다. 연결 종료 회수·저장 실패·기존 원정은 보존한다.

세 묶음의 초기 구현과 국소 확인을 마쳤다. 전체 체형 개별 미적 승인, 새 플레이어의 첫 파밍~최종 정산 시간, 자동화의 장시간 노동 감소, 전 시드 경제 균형, 외부망/6인·Windows 실기 검수는 남아 있다. 이번 작업을 GOTY 수준의 완성도나 수상 가능성 검증으로 취급하지 않는다.
