# 첫 착륙 자원·원경·통합 아이템 수정

2026-09-07 사용자 플레이 피드백에 따른 수정이다.

## 원인과 변경

- **광물이 안 보임:** `business_site_view.gd`가 사업 등록 전에는 즉시 반환해 광맥 모델을 하나도 만들지 않았다. 등록 여부와 자연 광맥 표시를 분리하고, 등록 전에는 B 무료 등록 안내를 표시한다. 자원 프로필별 광맥만으로 기초 철/구리가 빠지는 경우도 보완했다. 시작 광맥은 기존 ID에 덮어쓰지 않는 `landing:iron/copper/stone` ID이며 고갈량이 저장된다. 등록 전 채광 권한은 기존대로 제한한다.
- **원경 형태/갱신:** 큰 반지름 간격의 삼각형 대신 고정 월드 격자를 사용한다. 산 높이를 같은 좌표에서 계산하고 작업 스레드에서 새 배열이 준비되면 교체한다. 생성 중 기존 메시를 유지하고, 이전/현재 근거리 구멍을 모두 임시 지면으로 덮어 이동 중 틈을 방지한다. 최초 지표 준비에 원경 완료를 포함한다.
- **아이템:** 장비·광물·가공품을 같은 격자와 칸 한도로 관리한다. 배낭 원장은 중복 생성하지 않으며 표시 스택만 분할한다. 굴착 암석과 구 저장의 별도 암석을 합치고 제작·채광·인수·회수·선내 암석 입출고에 연결했다. 현재 수치와 소유 규칙은 [아이템 문서](../game/13-inventory-and-equipment.md)가 원본이다.

기존 Blender 광맥/장비 모델과 INK 미리보기, 기존 채광 음원/동작을 재사용했다. 신규 모델·음원 생성은 없다. 개발 중 다른 작업에서 추가된 항해 화면의 `landing` 누락 접근과 선내 창고의 잘못된 `storage` 키 접근도 실제 실행 중 발견해 기본값/실제 키로 보완했다.

## 확인

`tests/check_first_game_fixes.gd`를 Godot 4.7.2, Apple M2, Metal Forward+ 실제 창에서 별도 세계로 실행했다. 4096m 지표 로딩, 등록 전 3종 광맥의 모델 존재/접지, 카메라 회전 시 동일 메시 유지, 배경 생성 중 기존 메시 유지, 먼 지형의 높이 샘플, 등록 후 실제 채광을 확인했다. 실제 메뉴에서 100/100/1 및 기존 암석 7 표시, 48칸, 960×640 배치와 개체/수량 보존을 확인했다. 저장·종료 뒤 기존 회수 화물 규칙에 따라 철 204개와 암석 7개가 보존되고 광맥 잔량 397개가 재로드된다.

`tests/check_item_stacks.gd`는 꽉 찬 공통 칸의 마지막 1개 채움·신규 품목/초과량 거절, 구 암석 합산의 중복 방지, 선내 암석 입출고의 수량 보존을 확인한다. 로그와 실제 캡처는 로컬 `test-results/first-game-fixes/`에 둔다. 테스트는 사용자 저장·설정 파일을 덮어쓰지 않는다.

전체 회귀·다중 클라이언트·장시간 성능/모든 시야거리 검사는 수행하지 않았다. 동굴/지형 전반의 아트 교체, 모든 거리의 복셀 해상도, 수동 스택 정렬·드래그 분할, 생체 표본 보관 체계 개편은 이번 범위가 아니다.
