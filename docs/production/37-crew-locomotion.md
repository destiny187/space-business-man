# 탐험복 관절 리그와 협동 점프

2026-09-07 사용자 요청에 따라 현재 기본 혼자·협동 원정의 선내와 지표에 점프와 관절 모션을 연결했다. 기존 단독 탐험 장면에만 있던 점프를 현재 원정에서도 사용할 수 있다. 스타일은 [INK v1](06-rendering-quality-standard.md), 네트워크 경계는 [협동 기술 설계](../technical/04-coop-networking-and-session-save.md)를 따른다.

## 조작과 움직임

- 기본 Space를 눌러 한 번 점프한다. 점프 키 재설정을 따른다. 누르고 있는 동안 자동으로 다시 뛰거나 공중에서 추가 점프하지 않는다.
- 호스트가 접지·짧은 가장자리 유예·착지 직전 입력 버퍼·중력·천장/지형 충돌을 계산한다. 도약 준비, 상승, 낙하, 착지, 대기, 이동, 달리기를 구분한다.
- 메뉴·외부 항해 화면·착륙 전환·지형 충돌 준비 중에는 점프 입력을 받지 않는다. 메뉴에서 누른 키를 계속 유지해도 메뉴를 닫은 뒤 점프하지 않는다.
- 기존 이동 속도·질주 스태미나·낙하 피해는 유지하고 가속·감속을 연결했다. 기본 점프 속도 6m/s 등은 확정 밸런스가 아닌 조정 가능한 개발값이다. 원본은 `crew_locomotion.json`이다.

## Blender 원본과 게임 모델

`tools/build_crew_cabin.py --suit-only`를 Blender로 실행하면 다른 선내/화물 자산을 다시 내보내지 않고 탐험복을 재제작한다. `tools/surveyor_rig.py`가 골반·척추·머리, 좌우 위팔·아래팔·허벅지·종아리·발의 **13개 뼈**와 스킨 가중치를 만든다. 장갑/갑옷은 해당 뼈에 고정하고 무릎·팔꿈치의 압력복 연결부는 양쪽 뼈 사이로 변형한다.

- 원본: `art/blender/crew/surveyor_suit.blend`
- 게임 출력: `우주-비즈니스/assets/models/crew/surveyor_suit.glb`
- 27,892 삼각형, 5개 재질 표면. 기존 탐험복 외형·개인 도색을 유지했다.
- `FrontierCrewPose`가 실제 Skeleton3D를 구동한다. 미리 구운 모션 캡처 클립은 아니다.
- 이동 거리 기반 보행 위상, 속도별 보폭, 팔의 반대 방향 흔들림, 골반/척추의 작은 회전, 공중에서 다리 접기와 낙하 시 펴기, 착지 시 무릎 압축을 적용한다.
- 발마다 지형 레이와 두 관절 길이를 이용해 무릎/발목을 조절한다. 완전한 3차원 전신 IK·발 고정·모든 경사에서 무미끄러짐을 보장하는 구현은 아니다. 급경사·급회전·큰 단차는 후속 조정 대상이다.

## 네트워크와 저장

도약 요청 번호를 이동 입력에 반복 실어 짧은 입력이나 한 패킷 손실이 곧바로 점프 누락이 되지 않게 했다. 호스트는 같은 번호를 한 번만 소비한다. 위치, 속도, 접지, 동작 상태, 보행 위상, 방향, 점프/착지 일련번호와 처리한 입력 번호를 스냅샷으로 전달한다. 관절별 회전을 전송하지 않는다.

자기 캐릭터는 매 물리 프레임 이동을 예측하고 확정 스냅샷 이후 미확인 입력을 최대 90프레임까지 재적용한다. 카메라의 작은 보정은 완화한다. 다른 캐릭터는 약 100ms 지연된 같은 스냅샷 구간에서 위치와 모션을 보간한다. 외부 비행은 기존 20Hz 입력 경로를 유지한다. 인터넷 지연·패킷 손실 전 범위를 검증한 완성형 예측 시스템으로 표시하지 않는다.

성공 효과음/착지 먼지는 호스트의 일련번호를 따르며, 자기 캐릭터의 예측만으로 확정하지 않는다. 모션은 세션의 일시 상태다. 기존 세계 저장 형식은 바꾸지 않고, 재접속·지역 전환 때 리그 상태를 초기화한다. 콘텐츠 서명에 이동 설정을 넣어 이전 실행판과 혼합 접속하지 않는다.

## ElevenLabs

웹 Sound Effects에서 6초 폴리 원본을 생성하고 첫 번째 후보를 선택했다. 생성 결과는 프롬프트가 요청한 시간 순서와 정확히 일치하지 않아 실제 분리된 소리 구간을 선택했다. 도약 0.42초·착지 0.58초·발걸음 0.28초로 편집해 48kHz 모노 PCM16, 짧은 페이드와 음량 상한을 적용했다. 원본·프롬프트·구간·SHA-256은 `audio/manifests/crew-locomotion.json`에 보존한다.

승무원당 최대 3개 공간 음원, SFX 버스·거리 감쇠를 사용한다. 메뉴/외부 시점/포커스 상실 시 움직임 음원을 중단한다. 발걸음은 공중에서 새로 재생하지 않는다. 지표 착지에는 작은 먼지를 추가했다.

## 확인 범위

Blender 5.2.1 Cycles 원본 변형 렌더와 Godot 4.7.2 Metal Forward+ 실제 렌더를 확인했다. 두 실제 Godot 클라이언트의 ENet 연결에서 선내 보행/정지·예측 수렴·점프/착지·누름 유지·메뉴 차단·공동 착륙·지표 점프·달리기와 게임 내 음원 재생을 확인한다. 사용자 저장과 분리된 임시 세계를 사용한다. 재현 도구는 `tools/check_crew_locomotion.py`, 실제 결과는 [검증 기록](media/crew-locomotion/verification.json)이다.

두 클라이언트의 이동 확인 22개는 통과했다. 초기 검수 중 동시에 변경 중이던 항해 UI의 미생성 파일/미연결 속성, 이어서 새 선내 기록에 없는 선택 필드 `crew.landing` 직접 접근 때문에 UI 오류가 있었다. 해당 접근을 빈 사전 기본값으로 수정했다. 수정 후 960×640 실제 창에서 새 혼자 원정·점프·착지·저장 후 재시작을 따로 확인했으며 엔진 오류는 0건이다. 멀티 이동 결과와 마지막 시작/재개 검수의 범위를 합쳐 전체 회귀 통과로 표시하지 않는다. 전체 회귀·6인 장시간·인터넷 지연/손실·Windows 실기·모든 장비 작업 애니메이션·재접속 전수 검증은 실행하지 않았다.
