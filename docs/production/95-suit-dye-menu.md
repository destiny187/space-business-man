# 부위별 보석 염색 메뉴

2026-09-09 사용자 요청: 염색 메뉴를 완성하고 적은 보석으로 이용하게 한다. 후속 요청에 따라 부위별 보석을 다르게 배정하고 탐험 진행에 따라 꾸밀 수 있는 부위가 늘어나게 한다.

## 현재 규칙

I → 염색에서 헬멧·흉부·팔·다리·배낭·벨트를 선택하고 주색·보조색·포인트색을 색상 선택기로 바꾼다. 실제 현재 외장의 3D 미리보기를 회전할 수 있고 배낭 선택 시 뒷면을 보여준다. 미리보기·취소에는 비용이 없다. 부위 하나의 최대 3색을 한 번에 적용할 때 해당 보석 1개를 개인 배낭에서 소비한다. 기본색 복원은 무료이고 동일 저장색 재적용에는 비용이 없다.

| 부위 | 보석 1개 | 기존 채집 티어 |
| --- | --- | --- |
| 헬멧, 다리 | 사파이어 | T2 |
| 팔, 벨트 | 루비 | T2 |
| 배낭 | 에메랄드 | T2 |
| 흉부 | 다이아몬드 | T3 |

원본은 `data/suit_appearance.json`의 `dye_costs`다. 새 보석이나 채집 분포 변경은 포함하지 않는다. 현재 보석 4종을 재사용하므로 일부 부위는 중복된다. 티어 자체로 별도 잠그지 않고 해당 보석의 소유로 적용 가능 여부를 결정한다. 아직 추가되지 않은 강화 파츠도 같은 부위 도색을 물려받는다. 코어 발광색은 계열 식별을 위해 유지한다.

## 저장·협동

호스트 거래 `suit_dye`는 참가자 자신의 색상만 변경한다. 부위·색상 형식·기존 색상·세계 리비전을 검증하고 비용은 서버 데이터에서 계산한다. 저장 성공 뒤에 색상과 재료 소비가 함께 확정되고 기존 요청 영수증으로 중복 소비를 방지한다. 미리보기는 인스턴스의 임시 재질에만 적용한다. 성공 응답 뒤 해당 리비전의 스냅샷을 기다려 확정 표시하며 실패 이유를 보여준다. 기존 ElevenLabs 성공/실패 효과음을 재사용한다.

세계의 `crew.members[id].suit_dyes`에 선택한 부위/채널의 6자리 RGB 문자열만 저장한다. 이전 저장은 필드가 없어도 기본색으로 유효하다. 호스트 스냅샷은 다른 승무원의 색상을 포함하고 실제 배우·I 신체·증강 장치가 같은 재질 규칙으로 표시한다. 개인 프로필을 통한 다른 세계로의 색상 계승은 추가하지 않았다.

## 확인 범위

최종 실제 앱 11개·호스트 거래 13개 확인을 통과했다. 색상 선택기의 RGB 슬라이더·모드·프리셋을 접고 색상판과 HEX 입력을 유지해 960×640 창에 맞췄다.

Godot 4.7.2 Forward+/Metal 실제 앱에서 1280/960 화면과 색상 선택기, 무료 미리보기, 2색 동시 변경의 보석 1개 소비, 실제 배우 색상, 동일색 재적용, 재료 부족 거절, 보석 없는 무료 복원, 저장/로드를 확인한다. 거래 검사는 저장 실패 롤백·재전송 중복 소비 차단·잘못된 요청·다른 참가자의 보석/색상 격리·양쪽 스냅샷을 확인한다. 실제 다중 클라이언트 화면을 동시에 실행한 검사는 하지 않았다.

검사 중 fixture에 새 재료를 점 표기법으로 넣어 StringName 키가 생성되는 문제가 있었고 문자열 키로 수정했다. 작은 화면에서 하단이 잘리는 문제는 옵션 스크롤과 고정 적용부, 염색 탭의 불필요한 장비 하단 안내 제거로 수정했다. 전체 테스트 묶음은 실행하지 않았다.
