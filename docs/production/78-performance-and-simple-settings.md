# 현재 원정 최적화와 그래픽 설정 간소화

2026-09-09 사용자 승인: [성능 조사](77-performance-audit.md)에서 발견한 프레임 저하를 최적화하고 그래픽 설정을 일반 게임 수준의 품질 항목으로 정리한다. 기존 INK 윤곽선·3단 명암과 생성 지형·장비/조작을 유지한다.

후속: [원경 타일·충돌 준비·지형 CPU 최적화](80-terrain-streaming-optimization.md)를 적용했다. 아래 수치와 미구현 표기는 1차 작업 당시의 기록이다.

## 적용한 변경

- 팝업 차단 여부를 확인할 때 수천 개 노드를 반복 검색하던 처리를 최초 1회 검색과 Window 추가/제거 등록으로 바꿨다. 실제 표시 여부는 매 호출 읽으므로 같은 입력 이벤트에서 팝업을 열고 닫는 동작을 유지한다. 삭제된 창을 붙잡지 않도록 약한 참조를 사용한다.
- 원경의 월드 좌표별 높이·법선을 작업 스레드에서 재사용한다. 기존 16m/32m 격자와 산 형태는 유지하며 이동 범위 밖 캐시는 정리한다. 로딩 중 임시 지면도 표본을 재사용하고 표시 셀이 같으면 메시를 다시 만들지 않는다. 굴착 시 캐시를 무효화한다.
- 근접 지형의 설치를 프레임당 3ms 예산으로 나누고, 관심 청크가 바뀔 때만 작업 순서를 정렬한다. 굴착은 교체할 메시·충돌을 여러 프레임에 준비한 뒤 함께 교체하여 이전 바닥을 유지한다. 단일 청크 설치와 최종 일괄 교체는 예산을 넘을 수 있다.
- 우주 배경의 정적인 성운 잡음을 기존 하늘 큐브맵에 저장하고 별은 화면 해상도로 유지한다. INK 외곽선의 같은 반대 방향 깊이 표본을 중복 읽지 않도록 정리했다. 외곽선 두께와 내부 명암선은 유지한다.
- 설정은 전체 품질 **낮음/보통/높음**, 시야거리·그림자·효과·안티앨리어싱 품질, 렌더 해상도, 화면 선명도로 정리했다. 세부 묶음은 `data/client_graphics.json`에서 관리한다. [개인 설정 소관 규칙](18-client-settings-and-view-distance.md)을 따른다.
- 같은 프레임에 생성·삭제한 Viewport의 지연 설정 콜백이 해제된 객체를 받던 오류도 수정했다. 객체 ID를 전달하고 실제 존재 여부를 확인한다.

## 실제 측정

Apple M2 24GB, Godot 4.7.2 Metal Forward+, 1280×800, 렌더 100%, 프레임 제한·VSync 해제. 시드 71491의 현재 싱글 원정에서 우주→대기 행성 착륙→110m 보행을 수행했다. 일반 기본 설정의 60 FPS 제한은 유지하며 아래는 계측 중만 해제한 값이다.

| 조건 | 이전 조사 | 적용 후 |
| --- | ---: | ---: |
| 우주 정지 | 21.6~25.7 FPS | 29.8 FPS |
| 지상 정지 | 20.2~23.6 FPS | 34.5 FPS |
| 약 110m 지상 보행 평균 | 10.6 FPS / 93.96ms | 29.2 FPS / 34.26ms |
| 보행 프레임 시간 p95 | 522.63ms | 59.25ms |
| 보행 최대 프레임 시간 | 724.94ms | 374.75ms |

진행 중인 세계의 시간·장면과 다른 지표 작업도 바뀌므로 **고정된 동일 프레임의 A/B 성능 비교나 이번 변경만의 개선율은 아니다.** 우주/지상 정지는 각각 준비 30프레임 후 150프레임, 새 보행은 실제 110.03m·571프레임이다. 시간은 프레임 사이 벽시계 시간으로 계산했다. GPU 시간은 환경에서 제공되지 않았고, 엔진 process/physics 모니터는 이 측정 구간의 배타적 비용으로 해석하지 않는다.

반복 호출 비용은 팝업 확인 약 **2.494ms → 0.027ms**, 정착 후 임시 지면 갱신 약 **13.703ms → 1.462ms**였다. 이전은 개별 호출 중앙값, 이후는 연속 100회/10회 평균이므로 참고치다. [원본 측정과 검증 주석](media/performance-optimization/measurements.json).

## 확인과 남은 범위

- `test_terrain.gd`: 관련 지형 검사 20개 통과.
- `check_performance_settings.gd`: 실제 렌더러의 품질 묶음 적용·구 설정 보존·새 뷰포트/환경 상속·팝업 즉시 표시/숨김/재부착/삭제·화면 복구·960px 배치, 캐시 전후 지형 배열 일치·굴착 무효화·임시 지면 제거·굴착 교체 등 22개 통과. 같은 프레임 삭제 오류 수정 후 실패/엔진 오류 없이 확인했다.
- `benchmark_crew_current.gd --verify-optimization`: 실제 원정·착륙·보행·시점 입력·설정 중 입력 차단·로컬 지형 굴착 교체를 확인했다. 최초 장비 검사는 설정을 닫은 직후 장비 갱신 프레임 전에 확인해 실패했다. 검사에서 실제 표시 복귀를 기다리도록 고친 뒤 `--verify-controls-only`로 관련 8개를 재확인해 통과했다. 성능 측정값은 최초 실행 그대로 보존한다.
- 실제 우주와 지상 렌더, 960px 설정 화면을 확인했다. 장비 모델과 기존 음향/효과 컨트롤러 연결까지 확인했으며 이번 검사는 청감·실제 채집 거래·건설/로봇 전체 동선을 재검증한 것이 아니다. 진단 굴착은 격리된 로컬 메시/충돌 검사이며 호스트 저장 편집을 생성하지 않는다.
- 일반 사용자 세이브·설정 대신 `/tmp`의 격리된 테스트 저장을 사용했다. Windows 실기·6인·장시간 여행은 이번 확인 범위가 아니다.

**남은 성능 한계:** 현재 보통 설정에서도 안정적인 60 FPS에 도달하지 않았다. 원경은 표본을 재사용하지만 여전히 전체 메시 배열 작성·GPU 교체를 수행한다. 신규 지역/굴착 직후 임시 지면 표본과 단일 충돌 청크 설치도 순간 지연을 만들 수 있다. 완전한 원경 타일 교체, 청크 단위 충돌 준비 세분화, 지표 드로콜 감소는 후속 최적화 대상이다.
