# 구형 동물 자산과 임포트 작업 사본 정리

2026-09-13. 사용자는 전수 리모델링 뒤 남은 구형 동물·사용하지 않는 구버전과 불필요한 문서의 정리를 요청했다. 현재 플레이와 제작에 필요한 파일을 보존하고, 정리 결과를 커밋한다.

## 삭제와 보존 기준

[164 전수 완료](164-creature-production-and-native-integration.md)의 현재 동물 5,600종과 설치 LOD 11,200개를 대조한 뒤, 저장 카탈로그가 가리키는 **이전 동물 Blender 원본과 두 GLB**만 삭제한다. 해당 GLB의 `.import`와 전용 캐시는 함께 제거하며, 남는 자산의 임포트 목적지와 겹치지 않는 것을 확인한다. 같은 폴더에 있는 식물 1,585종·미생물 815종은 그대로 둔다.

`output/creature-remodel/import-project`와 `import-workers`는 제작 도구가 생성한 임포트용 사본이다. 진행 중인 임포터가 없고 현재 게임에 설치된 결과가 검증된 것을 확인한 뒤 삭제한다. 현재 게임의 `.godot` 전체, 다른 프로젝트·빌드·홍보 원본·개인 저장은 삭제하지 않는다.

구형 동물의 재생성 가능한 변형·조명·LOD 캡처 중 문서/코드에서 개별 파일명으로 참조하지 않는 것만 제거한다. 기본 형상 렌더·대표 비교판·승인 참조·UI 이미지·현재 동물의 전수 검수 근거는 보존한다. 단계별 `import-1778.json`부터 `import-5600.json`까지의 중간 임포트 파일 목록 8개는 [최종 전수 대조](media/creature-remodel/integration/final-coverage.json)로 통합하고 문서의 참조를 수정한다. 설계 결정과 과거 제작 당시의 확인/한계는 여전히 필요한 이력이므로 보존한다.

종 ID·원산지·외형 카탈로그·공격/이동 수치와 저장 해시는 변경하지 않는다. 카탈로그의 구형 `source`·`lods` 값과 원본별 JSON은 저장 호환 및 제작 이력용 정보로 남으며, 현재 자산 경로로 사용하지 않는다. 예전 제작기를 복구·재현할 필요가 있을 때는 해당 Git 버전의 자산과 함께 사용한다. 현재 동물의 검수는 `tools/creature_remodel/final_coverage.py`와 현재 모델을 사용하는 검토 장면을 기준으로 한다.

Git 이력·LFS 객체는 보존한다. 원격에 업로드됐는지 확인하지 않은 원본까지 지우는 LFS 정리나 이력 재작성은 수행하지 않는다. 이번 디스크 감소량은 작업 폴더와 전용 캐시 기준이며 Git 저장소의 과거 버전 크기가 없어지는 것은 아니다.

## 현재 표시 연결과 행동 범위

`remodel_registry.gd`는 등록된 동물의 현재 모델을 필수 자산으로 해석한다. 미임포트된 모델을 구형 경로로 바꾸던 처리를 없애고, 일반/사건 배우의 구형 표시 선택 인자도 제거한다. 기존 메타데이터의 종별 1회 읽기와 캐시를 유지하며 경로를 조회할 때마다 두 LOD의 파일 존재를 검사하지 않는다. 누락된 현재 자산은 정상 임포트/설치로 해결해야 하며, 필요한 종 등록이 없는 경우 명시적으로 검출한다.

삭제 전 조사에서 J 도감·I 표본·일부 시설 미리보기가 구형 카탈로그 경로를 직접 계산하는 연결 누락을 발견했다. `FrontierEcologyCatalog.model_key()`가 현재 등록을 사용하도록 고쳤으며, 표본 미리보기의 구도도 새 모델의 경계를 읽는다. 새 재질의 색 변이는 기본 재질에 대한 상대 변화로 적용하고 같은 표본을 반복 선택해도 색이 누적되지 않도록 원색을 보존한다. 기본 렌더 도구도 현재 near/far 경로와 지문을 사용한다.

영향 범위는 선택한 배우/미리보기와 해당 종의 메타데이터다. 저장 데이터·네트워크 발행·행성 전체 순회나 모델 전수 재생성을 추가하지 않는다. 같은 종 재선택은 모델을 재사용하며, 다른 미리보기의 노드와 숨겨진 화면의 렌더 생략을 확인한다. 기존 저장용 카탈로그를 깊은 복사해 새 모델 값으로 덮어쓰지 않는다.

Git 추적 파일 삭제는 **28,008개**이며 나머지는 로컬 생성 파일이다. 삭제 명세의 125,053개가 실제로 없어졌고, 보호 목록의 현재 모델/원본 24,003개가 남아 있는 것을 확인했다. 저장 카탈로그 4개의 SHA-256도 삭제 전과 같다.

저장소 전체의 `du -k` 집계는 **209,191,844KiB → 155,821,960KiB**, 약 **199.5GiB → 148.6GiB**다. 실제 폴더 집계 감소는 약 **50.9GiB**이며 파일별 할당량 합계를 그대로 디스크 여유 공간 증가로 해석하지 않는다. 집계 방식의 중복 제외와 정리 중 생성된 검수/편집기 파일이 있으므로 두 숫자를 구분한다. Git/LFS 이력의 용량은 포함된 채로 보존된다.

삭제 후 Godot 4.7.2 / Metal Forward+ / Apple M2에서 동물 5,600종과 식물/미생물 2,400종의 **현재 LOD 16,000개 경로**를 확인했다. 6개 리모델링 제작 묶음에서 동물 한 종씩, 식물/미생물 한 종씩을 실제 로드해 near/far 지연 설치·현재 골격·사건 연결·표본 아이템 ID 복원·도감/표본 미리보기와 같은 항목 재선택/다른 미리보기 보존을 확인했다. [실제 화면](media/asset-retirement/current-previews.png)에서 8개 형상이 정상 표시됐다. 투명 UI 이미지 제작 목록 400개도 현재 동물 경로로 바꿨으며 기존 UI 이미지를 삭제하거나 전수 재촬영하지 않았다.

기존 행동 범위 검사는 한 배우의 이동·무력화 복원/반복·거부된 공격, 다른 배우의 노드/골격/캐시 보존, 종별 메타데이터 1회 읽기와 현재 경로 유지로 통과했다. 최초 새 검사의 가상 표본 ID가 기존 64자리 hex 규칙과 달라 검사 준비 단계에서 실패했다. 게임 규칙을 바꾸지 않고 검사 표본을 정상 해시로 고친 뒤 다시 실행해 실패 0을 확인했다.
