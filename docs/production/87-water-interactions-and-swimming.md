# 수영과 물 상호작용의 그래픽·사운드

2026-09-09 사용자 승인: 기존 수중 부력·저항에 수영 자세, 입수·출수 소리와 물보라, 얕은 물 보행·수영의 잔물결, 수면 총격 효과를 모두 연결하고 품질을 높인다. 기존 Blender 에셋은 유지하고 진행 중인 필드 성능 최적화와 함께 사용할 수 있게 한다.

## 현재 동작

- 가슴 높이의 물에서는 이동 시 수영, 정지 시 떠 있기로 전환한다. 진입/해제 수심에 차이를 두어 물가에서 보행·수영 자세가 반복해서 뒤집히지 않는다. 기존 Surveyor Blender 리그의 팔 젓기, 몸통 기울기·회전, 발차기를 부드럽게 연결했다. 1인칭 장비도 낮아지며 수영 리듬으로 움직인다.
- `WASD`로 이동하고, 이동하면서 위·아래를 바라보면 상승·잠수한다. `Space`는 상승 동작이다. 수영 중 기존 이동 키 힌트가 이를 안내한다. 얕은 물에서는 기존 점프를 유지한다.
- 호스트의 물 접촉 순번과 실제 충격 속도로 입수·출수를 구분한다. 입수에는 퍼지는 물결, 가장자리가 솟는 물보라, 떨어지는 물방울을 사용한다. 걷기에는 작은 물보라, 수영에는 팔 쪽 잔물결과 이동 흔적, 깊이 잠기면 작은 기포를 만든다. 수중 접속·순간 위치 보정·작은 수면 경계 변동으로 입수음을 반복하지 않는다.
- 펄스 무기 요청이 성공한 뒤 호스트가 판정한 수면 위치에서 가늘고 높은 물보라와 전용 타격음을 낸다. 앞쪽 지형과 실제 정적 충돌체가 가리는 수면에는 효과를 만들지 않는다. 수면 앞에서 맞은 생물은 기존 타격을 유지하고, 수면 뒤 생물에는 물을 통과하는 동일 타격을 적용하지 않는다. 물에 맞은 탄착점에 기존 돌/불꽃 효과가 겹치지 않는다.
- 기존 수중 환경음 필터에 더해 새 물 접촉음은 수중에서 저음역 위주로 들린다. 눈높이가 잠기면 옅은 수중 색감을 천천히 적용한다. 음악 전체에 필터를 씌우지 않는다.
- 자연 하천·작은 호수의 높이 조회를 굴착 전에도 준비하고, 가까운 분석용 수면 열을 클라이언트에 보낸다. 물리 셀, 원래 해저 위의 바다, 기존 지질·시드의 하천을 이용한다. 육지 아래 밀폐된 동굴을 해수면만으로 물속으로 취급하지 않는다.

소관 파일은 `crew_locomotion.gd`, `crew_pose.gd`, `water_interactions.gd`, `surface_water.gd`와 호스트 요청·이동 복제 연결이다. 수치·한도는 `crew_locomotion.json`, `water_interactions.json`, `surface_water_physics.json`에 둔다.

## 소리 제작

ElevenLabs Sound Effects에서 입수, 출수, 발걸음, 수영 스트로크, 수면 총격 **5종**을 생성했다. 생성 원본은 `audio/source/elevenlabs/sfx_water_*_v1.wav`, 게임용 파일은 `assets/audio/sfx_water_*_v1.wav`이다. 실제 단일 동작 구간을 추출하고 모노 위치 음향으로 편집했다. 시작/끝 페이드와 −5dBFS 피크 상한을 적용했다. 발걸음 원본의 과도한 앞쪽 충격 구간은 사용하지 않는다.

[생성·편집 매니페스트](../../audio/manifests/water-interactions.json)에 프롬프트, 웹 이력 URL, 선택 테이크, 원본/출력 해시, 추출 구간, 길이와 음량을 보존했다. 재생 때 작은 피치 차이와 충격별 음량을 적용한다. 새 루프 음원을 추가하지 않고 기존 바다·하천 환경음을 유지한다.

## 비용과 협동

물결 48개, 물보라 외피 16개, 물방울 192개를 **세 개의 MultiMesh 묶음**에서 갱신한다. 38m 밖의 효과는 생성하지 않고, 낮은 효과 설정에서는 방울 수를 줄인다. 위치 음향은 8개 채널을 재사용한다. 메뉴·전환·비활성 창에서는 입자와 재생을 정리한다. 추가 그림자, 수면 반사 렌더 패스, 화면 블러를 만들지 않는다.

기존 물 계산의 셀 수/시간 예산을 유지한다. 자연 하천 조회는 기존 점진적 추적 예산 안에서 준비하며 캐시는 32,768열로 제한한다. 주변 복제는 한 명당 최대 2,401열이다. 캐시 상한 도달 후 관심 위치가 바뀌면 분석용 수면 조회를 다시 준비한다. 실제 저장된 물 양을 캐시 축소로 삭제하지 않는다.

입수 순번·수심·수영 위상·수면 총격은 기존 검증된 이동 스냅샷에 포함한다. 클라이언트 예측·보간에도 수영 상태를 연결하되 성공 연출은 호스트 결과를 따른다. 단일 은하 저장 형식과 기존 시설 침수 규칙은 유지한다. 새 동작/한도 정의는 협동 콘텐츠 해시에 포함한다.

## 확인한 범위

- `check_water_interactions.gd`: 수면 교차, 앞쪽 바위 차단, 허공 발사, 수중 출사, 자연 하천 수심, 수영/떠 있기, 잠수/상승, 입·출수 순번, 수면 경계 변동, 얕은 물 점프, 이동 상태 검증. **17개 통과, 실패 0**.
- `check_water_interactions_play.gd`: 임시 저장 복사본에서 실제 Godot 4.7.2 Metal Forward+ 실행. 물리 이동, 수영 자세와 지속되는 팔 동작, 요청 승인 후 수면 총격, 잠수 필터, 물 발걸음, 출수, 고정 효과/음향 한도, 메뉴 중 정리, 세계 검증·체크포인트. **19개 통과, 실패 0·엔진 오류 0**. [실행 기록](media/water-interactions/verification.json), [수영](media/water-interactions/swimming.png), [수면 총격](media/water-interactions/water-shot.png), [수중](media/water-interactions/underwater.png).
- 기존 Blender 리그를 같은 호스트 이동 상태로 구동하는 관찰용 복제 모델과 실제 INK 장면을 렌더했다. 시험 수위는 물 접촉/연출 확인을 위해 제어했다. 자연 유입·질량 보존 검사는 이전 [물리 물 기록](82-physical-surface-water.md)의 범위다.
- [실제 게임 혼합 음원](media/water-interactions/game-water-mix.wav) 9.40초를 기록했다. 피크 −11.87dBFS, RMS −34.34dBFS, 클리핑 0이다. 재생 연결·캡처 신호를 확인했으며 독립적인 주관적 청감 평가는 수행하지 않았다.

검수 중 수영 블렌드가 관절 갱신 자체를 약하게 하던 문제와 얕은 물의 점프 취소를 수정했다. 시험 코드의 스냅샷 호출 이름·초기 지형 준비 대기·입수 캡처의 이벤트 기준도 바로잡았다. 저장 경로는 `--crew-ui-test --crew-folder=/tmp/water-interactions-play-20260909`로 제한했다. 사용자의 실제 저장에 테스트 데이터를 넣지 않았다.

움직이는 물의 해상도는 기존 1m이며 하천 분석과 시각 메시 가장자리에는 표본화 차이가 있다. 유체 전체에 플레이어가 밀어낸 부피나 총알 충격을 전달하는 양방향 시뮬레이션은 아니다. 수영 중 충돌은 기존 캐릭터 캡슐을 유지한다. 산소/익사, 수압 피해, 차량 부력은 이번에 추가하지 않았다. 6인 실접속·전체 FPS 비교·장시간 전체 회귀는 수행하지 않았다.
