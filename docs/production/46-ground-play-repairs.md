# 지상 기본 플레이 개선 — C01~C08

2026-09-07. [커밋 계획](../planning/11-ground-commit-plan.md)의 C00~C08 실행 기록이다. C09 이후 탐험 분포·협동 사업량·로버·낮밤·성능 집중 개선은 이번 범위에 포함하지 않는다.

## C01 — 연속 채광

- 클라이언트는 채광 요청을 한 건만 진행하며, 호스트 응답 이후 실제 시간 기준 도구 간격과 최신 리비전을 기다린다. 물리 프레임 타이머와 요청 도착 시각의 차이로 재사용 대기 요청이 반복되지 않는다.
- 호스트는 요청 도착 시각과 마지막 성공 시각으로 간격을 계속 검증한다. 대기 응답은 남은 시간으로 재시도 간격을 보정하며 오류 소리·흡입 중단·실패 토스트를 만들지 않는다. 거리·등급·가방 용량 등 실제 거절은 기존대로 표시한다.
- 획득과 흡입 연출은 승인 응답에만 연결한다. 연속 입력 중 동시 요청과 과도한 채집 속도를 막는다.
- 확인: `check_field_tool_feedback.gd`를 격리 저장 경로 `/tmp/ground-c01-review`의 Forward+ 실제 창에서 실행했다. 2.1초 동안 매 프레임 채광을 요청해 3~4회 승인·대기 실패 없음, 광맥 감소·흡입 모델/ElevenLabs 루프 재생 상태·메뉴 중지·저장을 확인했다(실패 0). `suction.png` 화면을 검수했다. 소리의 재생 상태를 확인했으며 청음·다중 클라이언트 지연 실험은 수행하지 않았다.

## C02 — 가방 전용 건설과 불가 표시

- 건설 비용은 요청자의 가방에서만 차감한다. 창고 자동 보충을 제거하고, 거리·지면·충돌·기술·시설 한도·가방 수량을 호스트와 미리보기의 공통 판정으로 연결했다.
- 지상 HUD에 ✓/× 상태와 시설 아이콘·실패 이유를 표시한다. 고스트의 초록/빨강과 함께 표시하며, 건설 메뉴는 재료별 현재/필요 수량을 보여준다.
- `check_ground_construction.gd`를 `/tmp/ground-c02-review`의 Forward+ 실제 창에서 실행했다. 창고만 보유 시 거절·무차감, 가방만 보유 시 미리보기 허용·정확한 차감·빈 창고 유지·저장을 확인했다(실패 0). 불가/가능 고스트 화면을 검수했다. 초기 확인 중 테스트용 가방 필수 키와 시뮬레이션 교체 전 참조를 바로잡았다. 다중 클라이언트는 미실행이다.

## C03 — 창고 빠른 입출고

- 행성/우주선 창고에 Shift+클릭 한 묶음 이동, 선택 자원 수량 입출고, 자원 일괄 보관을 연결했다. 장비는 일괄 보관에서 제외하며, 소유 장비의 개별 이동과 기존 드래그는 유지한다.
- 빠른 이동은 호스트가 실제 재고·가방/창고 공간까지 수량을 제한한다. 일괄 보관은 한 요청에서 자원 ID 순서로 들어가는 만큼 옮기며 남은 자원은 가방에 둔다. 기존 거래의 리비전·중복 영수증·저장 규칙을 사용한다.
- `/tmp/ground-c03-review`에서 `check_warehouse_transfer.gd`로 실제 드래그·Shift 클릭·수량 버튼·일괄 자원 보관·장비 보존·행성/우주선 분리·저장과 기존 ElevenLabs 재생 상태를 확인했다. 작은 창의 두 번째 행이 잘리는 문제를 발견해 960px 창의 타일 높이를 조정한 후 선내 화면만 다시 확인했다(실패 0). 작은 창 캡처를 검수했다. 청음·다중 클라이언트는 미실행이다.

## C04 — 로봇 드릴 방향과 동작

- 기존 Blender `miner.blend`의 전방은 내보낸 GLB의 +Z이며, 실제 회전 부품은 `ToolRotor`다. -Z 이동 회전과 존재하지 않는 드릴 이름을 사용하던 표현을 수정했다. 이동은 진행 방향, 채광은 실제 대상 광맥을 바라본다.
- `ToolRotor`의 자체 축 회전과 드릴 끝 수집 지점을 연결했다. 자원 효과가 로봇 중심으로 들어가던 표현을 드릴 끝으로 이동했다. 기존 모델·재질·음원을 재사용하며 원본 자산 변경은 없다.
- Blender 원본을 다시 열어 임시 검수 카메라·조명으로 렌더링했다(`/tmp/ground-miner-blender.png`). 원본에 카메라/월드가 없어 검수 장면에만 추가했으며 파일을 덮어쓰지 않았다.
- `check_robot_work.gd`의 Forward+ 실제 창에서 드릴 회전·광맥 방향·끝 위치·호스트 자원 채집·ElevenLabs 위치 음원 재생 상태·저장을 확인했다(실패 0). 첫 캡처에서 검수용 캐릭터가 기복 아래로 떨어진 것을 확인해 검수 위치를 지면 높이에 맞추고 카메라를 고정했다. `/tmp/ground-c04-review/robot-drilling.png`를 다시 검수했다. 청음·다중 클라이언트는 미실행이다.

## C05 — 자동 채광과 등급

- 기본 자동 채광, 자원 종류 필터, 배치/재설정 중심 80m, 접근 가능한 가까운 광맥 탐색을 연결했다. 탐색은 데이터의 주기·후보 한도로 제한하고 실제 경로 거리를 비교한다. 고갈/붕괴/등급 부적합 대상은 화물 하역 후 재탐색한다.
- 기존 로봇 저장은 작업 옵션이 없으면 현 위치 기준 자동으로 보완한다. 기존 Mk.2 개조의 채집량·운반량·이동 성능과 채집 가능한 광물 등급을 연결하고 제작 품질은 작업·이동 속도에 적용한다. 품질이 높아도 Mk 제한을 넘지 않는다. 지하 로봇은 지원하지 않는다.
- 자동 정지/복귀, 충전과 운반을 유지한다. 새 옵션은 저장·공개 현장 패킷에 포함하며 새 규칙 데이터는 협동 콘텐츠 해시에 포함한다. 기존 사업 저장의 규칙 해시는 바꾸지 않는다.
- `check_robot_auto.gd`를 `/tmp/ground-c05-review`에서 실행했다. 기존 형식 로봇의 자동 시작→실제 채광, Mk1/Mk2 가능 등급, 품질 분리, 범위 밖 광맥 제외, 저장 유효성을 확인했다(실패 0). 첫 확인의 고정 대기 시간을 실제 채광 상태 대기로 바꿨다. 자동 설정 화면을 검수했다. 광범위한 시드/경로·다중 클라이언트 검사는 하지 않았다.

## C06 — 광맥 앞 로봇 한 대 지시

- 광맥 조준 후 R로 8m 안의 보이는 광맥에 한 대를 지시한다. 로봇 관리에서 우선 개체를 고르거나 자동 선정으로 되돌릴 수 있다. 선택 정보는 HUD에 표시하며 실제 대상·거리·경로는 호스트가 다시 판정한다.
- 자동 선정은 가능한 Mk→품질→실제 작업량→경로 기반 도착 시간→ID 순서다. 직접 선택한 개체가 불가능하면 이유를 반환하고 대체하지 않는다. 자동 선정은 충전/운반/개별 지시 중인 로봇을 건드리지 않는다. 직접 선택한 개체는 기존 충전·하역을 끝내고 이동한다.
- 광맥별 개별 작업 예약은 한 대이며 반복 요청은 기존 예약을 유지한다. 예약 광맥을 일반 자동 작업이 추가 점유하지 않으며 고갈/취소 후 자동으로 복귀한다. 로봇 설정 화면은 저장된 종류 필터를 표시한다.
- `check_robot_orders.gd`를 `/tmp/ground-c06-review`의 실제 창에서 실행했다. Mk/품질 선정·반복 예약 한 대·직접 선택 우선·잘못된 선택 무대체·실제 R 입력 경로·저장을 확인했다(실패 0). 초기 검수 카메라 앞에 겹쳐 둔 로봇을 분리해 지시 HUD를 확인했다. 다중 클라이언트·장거리 경로 실험은 미실행이다.

## C07 — 시설 상태·모션·ElevenLabs 사운드

- `active`는 전원 공급, `working`은 실제 환경/처리 진행을 뜻한다. 얼음 부족 시 준비 시간도 쌓이지 않고, 목표 도달·전력 부족·수동 정지 때 기구와 루프가 멈춘다. Mk.2의 별도 필터/토양 처리가 진행되는 경우에는 부분/보조 가동을 표시한다. 기존 계약 산식과 처리율은 유지한다.
- 기존 Blender 시설 4종에 팬, 펌프 피스톤, 배양 교반부를 추가하고 원본/GLB/생성 스크립트를 보존했다. INK 게임 렌더에서 움직임을 확인했다. 상태 표시는 모델 높이 위로 올리고 조준 HUD에도 가동/부족 이유를 표시한다.
- ElevenLabs 웹에서 물 처리·온도 조절·생태 배양 루프를 각각 6초, 반복 켜짐, 영향도 30%로 생성했다(각 80크레딧, 총 240). 1번 테이크 원본과 처리본·프롬프트·생성 링크·해시를 [음향 이력](../../audio/manifests/elevenlabs.json)에 보존했다. 대기 처리기·로봇·채집의 기존 ElevenLabs 음원도 유지한다.
- 새 루프는 모노 PCM16, 저역/고역 정리, 80ms 연결 크로스페이드, RMS -23dBFS로 정리했다. 위치 음원에 감쇠 기준 거리와 짧은 진입/정지 페이드를 적용하고 여러 기계가 같은 위상으로 반복하지 않게 시작점을 분산했다.
- `check_facility_operation.gd`의 실제 Forward+ 창에서 시설 4종의 처리→모션→위치 음원, 얼음 부족 정지·목표 정지·전력 부족·호스트 가동 전환·저장을 확인했다(실패 0). 상태 표식이 모델에 가려진 문제를 수정하고 화면을 재확인했다. [가동 화면](media/ground-play/atmosphere-working.png), [얼음 부족 화면](media/ground-play/water-waiting.png).
- 실제 게임 SFX 버스를 6.5초 기록해 루프 경계와 겹친 재생 신호를 확인했다. 기록 피크 -16.92dBFS, RMS -30.79dBFS, 클리핑 0샘플이다. **현재 도구는 오디오 입력 청음을 지원하지 않아 음색의 주관적 청음 평가는 하지 못했다.** 재생·음량·파형 확인을 청음 완료로 기록하지 않는다. 다중 클라이언트·장시간 성능 검사는 미실행이다.


## C08 — 종합 환경 적합도 HUD

- 행성명 바로 아래 막대 하나와 지역 범위·안정화 상태를 표시한다. H키로 대기·온도·물·생태의 모델 아이콘/막대/수치와 실제 온도·기압·산소를 펼친다. 평균이 높아도 필수 조건 부족 이유 하나를 표시한다.
- `FrontierEvaluator.environment_report`가 네 항목을 동등 평균한다. 현재 T2 염류는 물, 토양은 생태의 최소값에 반영한다. 미관측 필수 값은 점수 없이 ‘평가 중’으로 표시한다. 안정화는 평균과 분리하고 기존 계약의 30초 기준을 읽는다. 구 판매의 120초/가중치/보상과 T1/T2 계약 조건을 변경하지 않는다.
- HUD와 단말은 동일한 호스트 공개 환경값·공통 결과를 사용한다. 파생 점수를 저장하지 않아 기존 저장도 환경값으로 다시 계산한다. T3 이상 가스/광역 과정이나 새 안정화 프로필은 추가하지 않았다.
- `check_environment_hud.gd`로 평균·약점 경고·염류/토양 최소값·미관측 처리를 확인하고, 실제 Forward+ 창에서 공개 환경→HUD→H키 상세→960px 배치→단말 같은 점수→저장을 확인했다. 검수 코드가 저장 읽기 결과를 `{ok,state}`로 잘못 가정한 부분을 실제 월드 반환 형식으로 수정한 뒤 저장 읽기만 다시 확인했다(`--save-review`, 실패 0). [960px 상세 화면](media/ground-play/environment-details-960.png). 실제 창의 기능 검사는 통과했으며 전체 검사를 반복하지 않았다.

## 이번 전달 범위

C00 문서 기준점과 C01~C08 기능을 각 커밋으로 나눴다. 후속 범위는 [커밋 계획](../planning/11-ground-commit-plan.md)에 남겼다. 저장은 각 변경의 격리 경로로 확인했으며 사용자의 실제 저장 파일을 덮어쓰지 않았다. 변경별 최소 확인 기록을 전체 성장 완주·멀티플레이 실기·모든 시드의 회귀 검사로 해석하지 않는다. 음색 청음과 장시간 성능 검사는 미확인이다.
