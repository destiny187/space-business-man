# 채광 로봇의 2티어 진입·시드 동굴 — 2026-09-07

## 사용자 요청과 실제 변경

첫 자동 채집을 2티어 성장의 보상으로 옮기고, 행성 시드별 동굴 구조를 구현한다. [로봇 규칙](../game/03-robots-and-automation.md), [지하 목표 설계](../technical/07-seeded-underground.md)를 따른다. [행성 환경·첫 원정 제안](../planning/09-first-expedition-and-environment.md)은 문서화만 수행했다.

## 로봇 제작

- 기초 제작소에서 원광을 가공하여 보강 프레임 2·제어 회로 1로 제작소를 Mk.2 개조한다. 상위 채집기나 자동 채집이 선행 조건이 아니다.
- 최초 로봇에는 철 100·구리 10에 더해 보강 프레임 3·제어 회로 2·열전달 유닛 1을 요구한다. 원광 비용을 가공 부품으로 대체해 자동화를 더 싸게 만들지 않았다. 수량은 초기 조정값이다.
- 호스트의 `business_craft`와 실제 제작소 화면에 동일한 Mk.2 조건과 비용을 적용한다. 신규 예약은 `tier: 2`이며 출고 후 기존 Mk.2 채광·적재·이동·모델 개조 팩을 사용한다.
- 기존 로봇과 제작 중인 예약은 유지한다. 등급 필드가 없는 과거 예약은 기존 1티어로 완성하고, 이후 기존 개조 경로를 사용할 수 있다. 저장 사업 규칙 해시는 변경하지 않고 협동 콘텐츠 해시는 갱신한다.
- 기존 `robotics` 연구는 기초 제작소를 여는 선행 기술로 유지한다. 연구 구매만으로 자동 채집을 시작할 수 없다. 초기 MVP의 별도 구 실행판은 이번 원정 규칙 변경 대상이 아니다.

## 새 동굴 생성

- 새 은하의 생성 스냅샷에 `underground.json`을 보존한다. 기존 스냅샷에 키가 없으면 고정 통로와 높이 함수를 그대로 사용한다. 기존 은하에 새 동굴을 강제로 뚫지 않는다.
- 행성 지질 계열로 퇴적·용암관·빙하·균열 프로필을 고른다. 폭·천장 비율·굴곡·경사를 달리하고, 시드는 입구 방향·거리·주 통로 길이·분기 방향·공동 크기를 결정한다.
- 768m 수평 구역이 하나의 동굴계를 소유한다. 중심 구역에는 입구를 보장하고 나머지 구역은 70% 생성 확률을 사용한다. 동굴은 자기 구역 내부에 완결되므로 청크 로드 순서가 연결을 바꾸지 않는다. 여러 소유 구역을 잇는 초대형 동굴망은 이번 범위가 아니다.
- 입구는 착륙 중심에서 85~105m 떨어지고 주 경로는 4~6개 구간, 구간당 32m다. 현재 동굴은 수십 m 깊이의 초기 탐사용이며 130~180m 심층을 구현한 것은 아니다.
- 주 통로·분기를 빈 공간으로 합치고 바닥을 유지한다. 표면 골짜기가 통로를 자르지 않도록 필요한 덮개 지형을 생성한다. 그 최초 생성 지표를 200m 깊이 기준으로 사용한다.
- 새 생성기에서는 굴착 후 밀도에 기반암을 다시 합성해 경계 아래를 뚫지 못하게 한다. 호스트와 구 단독 도구도 기반암 타격을 거절한다. 새 지형의 스트리밍 절대 범위를 넓혔지만 로드하는 것은 플레이어 주변 청크뿐이다.
- 자원 시드는 기존 별도 스트림을 유지한다. 대표 동굴 보석은 새 공동의 바닥으로 연결하고 일반 매장 자원은 기존 규칙을 사용한다. 연속 광체·심층 자원 재배치·추가 보상은 구현하지 않았다.

## 표현과 확인 범위

게임의 기존 지형 메시·충돌 생성기, 지질 색상, INK 지형 셰이더·윤곽·조명 경로를 사용한다. 이번은 절차적 지형 구조 변경으로 새로운 Blender 모델·ElevenLabs 음원은 제작하지 않았다. 전용 암주·침전물·빙결 장식·열수·물 효과와 최종 동굴 아트는 후속이다.

- `test_seeded_caves_and_automation.gd`: 네 계열의 동일 시드/다른 시드, 로드 순서, 연결 여유·하부 지지·실제 경로 탐색기의 바닥 판정·착륙지 간격, 기반암 경계, 과거 생성 규칙 보존, 호스트의 1티어 제작 거절·2티어 개조·재료 소비·중복 예약 거절·Mk.2 출고와 저장 상태를 확인했다. 최종 43개 확인 실패 0. 최초 분기 캡이 본선 바닥을 파고들어 생긴 보행 실패는 통로/공동의 합집합을 하나의 연속 경사 바닥으로 자르도록 수정해 해결했다.
- `capture_seeded_caves.gd`: 실제 Windows Godot 4.7.2 / GTX 1070 / D3D12 Forward+에서 퇴적·빙하 입구/내부의 주변 75청크 로드와 내부 바닥 충돌을 확인하고 네 화면을 생성했다. 첫 캡처는 현재 청크만 기다려 주변이 비어 있었으므로 주변 전체 준비를 기다리도록 검증 도구를 수정했다.
- 렌더 출력은 `test-results/seeded-caves/`, 실행 로그는 로컬 `builds/local/`에 있다. 열린 사용자 게임과 저장은 수정하지 않았다.
- 전체 수동 원정, 모든 시드의 물리 보행, 6인 인터넷·장시간 성능, 기존 은하의 200m 기반암 이주는 수행하지 않았다. 렌더 범위 밖 청크의 노출과 동굴 장식 마감은 후속 시야·아트 개선 범위다.
