# 현재 화질의 프레임 안정화

2026-09-11 사용자 승인: 현재 그래픽의 성능 문제가 줄어들도록 최적화한다. INK v1·높음 프리셋·콘텐츠/충돌/저장을 유지하고 반복 계산과 렌더 비용을 줄인다. 울트라 확장은 이번 범위가 아니다. [선행 조사](129-performance-ultra-audit.md)의 병목을 기준으로 변경마다 확인하고 커밋한다.

## P01 — 광맥·시설 표시 재계산

광맥의 시드 기반 지역 목록과 고정 발견을 해당 지상 화면에서 재사용한다. 매장량·온도·채굴 가능 여부는 현재 상태로 판정하며, 노출 위치 캐시는 지형 revision이 바뀌면 무효화한다. 관찰 구역 밖 자료를 제거한다. 모델 하나가 준비될 때 전체 사업/지형 상태를 다시 적용하던 경로를 해당 모델의 라벨·작동·업그레이드 초기화로 바꿨다.

현재 세계 복사본의 실제 Metal Forward+ 지상에서 캐시 유무에 따른 세 위치의 광맥 ID/위치/매장량 동등성, 생성 직후 라벨 연결, 정지와 20초 보행을 확인했다. 생물 16개·MSAA 4×·렌더 배율 100%·1280×800 조건을 유지했다. 화면을 직접 검수했다.

동일 원본 저장에서 새로 시작한 비교에서 보행 평균은 19.9→24.3 FPS, p95는 136.6→98.1ms, 100ms 초과는 39→24프레임이었다. 최악 프레임은 아직 355.7ms였다. 짧은 공유 개발 환경 표본이므로 이 단계만으로 성능 완료를 뜻하지 않는다. 별도 조사의 9.9 FPS와는 시작/준비 시간이 다른 실행이며 직접 개선율로 사용하지 않는다.

자료: output/frame-stability-20260911/before-ground, p01-ground, p01-benchmark.gd. 양쪽 실행 종료에 ObjectDB 1개 경고가 남았다. 원본 사용자 저장·다른 작업 변경은 보존했다.

## P02 — 정확한 지면 샘플 재사용

지형 인스턴스별 높이/법선을 최대 각 8,192개 재사용한다. 작업자는 자신의 필드와 캐시를 소유하며 다른 스레드의 필드를 읽거나 수정하지 않는다. 좌표를 반올림하지 않고, float32 벡터 키로 정확하게 표현되지 않는 float64 입력은 캐시를 우회한다. 새 시드 설정은 모두 비우고 굴착은 법선 캐시를 무효화한다. 높이는 원래 지표 높이이므로 굴착 뒤에도 재사용한다.

생물 접지의 같은 수직 열은 이미 계산한 높이를 사용한다. 서식층별 계통 목록을 한 번 만들고 셀마다 재생성하지 않는다. 생태 배치 캐시도 작은 상한을 넘을 때 전부 지우던 방식을 가까운 후보를 보존하는 방식으로 바꿨다. 개체 수·모션·배치 결과·호스트 규칙은 바꾸지 않았다.

변경 전 소스 사본과 높이/밀도/법선의 정확한 일치, 굴착, 캐시 퇴출, 시드 재설정, 세 관찰점의 생물 후보와 순서 일치까지 5개 확인을 통과했다. 자료는 verify_samples.gd / verify-samples.log이며 아래 P03과 함께 실제 지상 보행도 실행했다.


## P03 — 임시 지면의 작업 스레드 생성

청크가 준비되는 동안 지표를 덮는 임시 메시의 높이·법선·동굴 판정과 배열 생성을 작업 스레드로 옮겼다. 메인 스레드는 완성된 메시만 설치한다. 연속 이동 요청은 최신 요청으로 합치며, 오래된 원경 고리가 새 위치에 구멍을 내지 않도록 새 덮개가 준비된 뒤 고리를 교체한다. 굴착 이전 결과는 폐기하고 기존 동기 API는 검수/도구용으로 보존했다.

check_streamed_fallback.gd의 배열 동등성·동일 메시 재사용·완성 청크의 덮개 제거·굴착과 진행 중 요청의 경합·최신 원경 교체 5개 확인을 통과했다. P01~P03을 적용한 실제 높음 설정의 20초 보행은 27.3 FPS, p95 64.6ms, 최악 132.0ms, 100ms 초과 2회였다. 지형 메인 처리의 누적 최대는 3.58ms였다. 이 표본이 모든 엔진 호출의 상한을 보장하지는 않는다.

자료: after-ground/results.json, after-ground.log, fallback-test.log. 이 실행의 게임 종료에는 ObjectDB 경고가 없었다. 정지 FPS는 여전히 약 30으로, 이후 렌더 비용을 별도로 조사했다.

## P04 — 광물의 정적 메시 묶기

움직이지 않는 불투명 광맥의 부품을 재질별로 묶어 재사용한다. 기존 삼각형·법선·정점색과 재질을 사용하고 회전·고갈 크기 변화·충돌은 원래 광맥 루트에 적용한다. 리깅·애니메이션·투명 재질·특수 변형·다른 가시성 설정이 있는 모델은 이 경로에서 제외한다. Blender 원본과 GLB는 수정하지 않았다.

철/암석/구리의 실제 Forward+ 비교에서 12m와 45m 모두 그리기 호출이 76→6이었다. 정규화 RGB 평균 오차는 각각 0.000043 / 0.000005, 큰 차이 픽셀은 전체 614,400개 중 478 / 41개였다. 가까운 화면의 실루엣·색·명암을 직접 확인했다. check_mineral_batch.gd 4개 확인이 통과했다.

전체 지상에서도 실행했고 정지 호출은 직전 표본의 약 1,224→764로 줄었다. 평균 정지 FPS는 29.8→30.4로 큰 차이가 없었다. 보행은 27.7 FPS / p95 61.5ms / 최악 124.8ms / 100ms 초과 4회였다. 호출 감소를 그만큼의 FPS 증가로 해석하지 않는다. 자료: mineral-test.log, mineral-batch.json, ore-*.png, final-ground/results.json, final-ground.log.

효과별 별도 진단은 높음 30.1, SSAO 제외 31.1, SSIL 제외 33.2, SSR 제외 32.5, 윤곽 제외 34.2, 그림자 제외 32.1, 높음 재측정 30.2 FPS였다. 각 8초 표본이며 이 효과들을 제품에서 끄지는 않았다. 하늘의 반복 구름 계산을 추가로 확인 중이다.
