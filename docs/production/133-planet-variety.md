# 행성 재질·지형·지역 다양성

2026-09-11 사용자 승인: 기본 재질 공유와 외형 계열 반복감을 줄이기 위해 재질 변형, 계열별 지형 형태, 한 행성 안의 지역 조합을 나눠 개발한다. 기존 INK v1과 성능 우선 방향을 유지한다. 아래 구체적인 수치와 구성은 이번 구현 선택이다.

| 단계 | 범위 | 현재 상태 |
| --- | --- | --- |
| G01 | 독립된 지질 재질 7종·시드별 선택·필요 재질만 로드 | 구현·최소 확인 완료 |
| G02 | 12개 지상 계열의 지형 형태·기존 저장 보존 | 구현·최소 확인 완료 |
| G03 | 같은 행성의 저지/암반/특징 지역과 재질·장식 연결 | 구현·최소 확인 완료 |

공유 재질 개선은 기존 은하에도 적용할 수 있지만 지형 생성과 지역 배치 규칙은 새 은하에만 넣는다. 저장된 `planet_rules`를 소급 교체하지 않는다. 시설·광맥·사건 좌표와 기존 굴착/동굴을 보존한다. 생성 외형 18종을 단순히 더 많은 이름으로 늘리는 작업이 아니며 태양계·거대행성·궤도와 착륙 지도의 정확한 대응은 이번 범위 밖이다.

작업 자료는 `output/planet-variety-20260911/`에 둔다. 단계별 실제 확인과 남은 범위는 구현 뒤 아래에 기록한다.

## G01 — 지질 재질과 행성별 선택

주상 절리 `basalt_columns`, 다공질 응회암 `porous_tuff`, 층상 사암 `sandstone_bedded`, 전단 빙암 `frost_fracture`, 염류 다각피 `salt_polygons`, 충돌 각력암 `impact_breccia`, 습곡 판암 `folded_slate` 7개를 추가해 기본 재질은 17종이다. 색만 바꾼 복제 대신 서로 다른 높이·균열·결·공극 함수를 사용한다. 기존 화산의 `lava_crust`는 보존한다.

현재 12개 지상 계열의 11개는 각각 2개 암반 후보에서 행성 시드로 선택하고 화산의 고온 암반은 용암을 유지한다. 기존 계열 ID·지형·자원 분포는 바꾸지 않는다. 기본 조합은 `surface_materials.json`에 두며 이번 변화는 지표다. 궤도 모델의 개별 행성 전용 지리 생성으로 해석하지 않는다.

Blender 원본 `art/blender/surface-materials/geological-variety.blend`와 생성 정보 JSON, `tools/build_geological_textures.py`를 보존한다. 1024² RGBA의 기존 법선 XY/높이/거칠기 계약을 유지한다. 원본 미리보기 변위는 제작용이고 게임 지형은 노멀·명암으로 표현한다.

전체 재질 배열을 계속 키우지 않고 현재 행성의 암반·퇴적물·눈·얼음만 배열에 넣는다. 중복 제거 뒤 3~4장이며, RGBA8+mip 원본 크기는 약 16~21.3MiB로 이전 10장 약 53.3MiB보다 작다. 전체 GPU 메모리 실측값이 아니다. 같은 조합은 재사용하고 사용 종료 뒤 배열을 붙잡지 않도록 약한 참조 캐시를 사용한다. 계열 수가 늘어도 모든 텍스처를 지상에 상주시킬 필요가 없다.

Blender 5.2.1 Cycles와 Godot 4.7.2 Metal Forward+의 공통 INK 렌더에서 7개 재질을 확인했다. 12개 계열의 24개 시드 선택 재현성, 3~4장 배열·살아 있는 배열 재사용을 확인했다. 실제 `CrewSurfaceScene`의 산화 사막·충돌 고원에서 스트리밍·Blender 자연물·임시 면 재질·착륙 바닥 높이 10개 확인을 통과했고 스크립트/셰이더 오류 없이 종료했다. 지상 전 계열의 실제 이동이나 장시간 성능을 확인한 것은 아니다.

## G02 — 계열별 지형 형태

새 은하의 `planet_rules` v5부터 저장된 `terrain_layout.landscape` v1을 사용한다. 산화 사막은 큰 단차의 고원, 대륙은 넓은 구릉, 충돌 고원은 분지와 둥근 테두리, 파쇄 지형은 긴 균열, 툰드라는 길게 늘어진 구릉, 동결 지형은 큰 빙상 단구를 만든다. 화산은 함몰된 정상의 원추, 염류 지형은 얕은 평저 분지, 황토는 작은 침식 단구, 퇴적 지형은 조밀한 층상 고원, 결정질은 좁고 높은 첨탑, 알칼리는 중앙이 용식된 탑 지형을 만든다. 12개 별도 메시를 복제하는 대신 8개 형태 계산을 계열별 크기·간격·잔여 요철로 조합한다.

형태는 수백 m 규모이며 시드별 위치·높이와 기존 미세 요철을 결합한다. 착륙 원점 110m까지 기존 형태를 유지하고 200m까지 점진적으로 연결한다. 근경 충돌 메시·원경·굴착·동굴은 같은 높이 함수를 사용한다. 각 생성 작업은 독립 캐시를 가지며 원형 지형 중심 캐시는 128개로 제한한다. 저장된 규칙이 없으면 새 계산에 진입하지 않는다.

12개 계열에 대해 원본 높이 코드와 기존 규칙의 **1,920개 높이가 정확히 일치**함을 확인했다. 새 규칙 JSON 왕복 재현성, 착륙 구역, 표면 밀도와 굴착 제거도 같은 검사에서 확인했다. 실제 Godot INK에서 [12개 높이 지형](media/planet-variety/landforms/report.json)을 렌더했고 [고원](media/planet-variety/landforms/oxidized.png), [충돌 분지](media/planet-variety/landforms/cratered.png), [화산](media/planet-variety/landforms/volcanic.png), [첨탑](media/planet-variety/landforms/crystalline.png)의 실루엣을 비교했다. 이 비교 화면은 실제 높이 함수의 간이 메시이며 전체 게임 플레이 화면은 아니다.

실제 `CrewSurfaceScene`의 충돌·화산 계열에서 착륙지 밖 좌표 (650,650)의 스트리밍·장식·재질과 착륙 높이 10개 확인을 통과했다. 첫 검사에서 카메라만 옮기고 호스트의 관찰 좌표를 착륙지에 남겨 장식 검사가 실패했다. 검사 도구의 호스트 좌표를 함께 이동한 뒤 해결했다. 원경 완전 로딩·모든 급경사의 이동·동굴 전 구간을 검수한 범위는 아니다. `g02-check.log`, `g02-play.log`와 캡처는 작업 자료 폴더에 보존한다.

## G03 — 한 행성 안의 지역 조합

새 은하 `planet_rules` v6는 각 지상 계열의 `surface_regions` v1을 저장한다. 실제 고도와 시드 위상의 넓은 지질 띠로 저지·기반암·특징 지대 세 영역을 조합한다. 예를 들어 화산재 평원/냉각 현무암/고온 화산구, 퇴적 저지/층상 암반/노출 고원, 설원/빙상 단구/노출 암봉을 표현한다. 이것은 **36개 독립 행성 모델이나 기후 생태계 추가가 아니라, 12개 계열 내부의 시드별 지질 조합**이다. 온도·위험·자원·서식종·테라포밍 판정은 기존 규칙을 따른다.

지역별 암반 재질·표면 배율·색조·퇴적량과 장식 밀도/크기를 연결한다. 낮은 지대에는 작은 파편을 드물게 두고 특징 지대에는 기존 Blender 장식의 큰 변형을 사용한다. 후보 좌표·난수 순서·4개 MultiMesh 종류를 유지하고, 지역 밀도는 기존 후보를 줄이는 방식이다. 건축물·굴착 구멍·수면·경사 검사도 유지한다.

지질 띠의 계산은 셰이더의 정점 단계에서 수행한다. 색조와 퇴적량은 점진적으로 연결하고, 미세 재질은 기존 노출 무늬를 따른 접촉면에서 선택한다. 경계에서도 기존과 같이 암반 재질 하나를 읽는다. 처음 구현한 여러 암반 동시 혼합은 실제 장면의 프레임 비용이 커져 이 방식으로 수정했다. 멀리서 식은 화산 영역은 고온 균열용 재질 읽기도 생략한다. 장식의 CPU 지역 판정과 GPU 정점 보간은 같은 수식을 쓰지만 메시 해상도 때문에 경계 위치가 미세하게 다를 수 있다.

지역 재질을 포함해 행성당 **4~6장**의 텍스처를 상주시킨다. 최대 6장의 RGBA8+mip 원본은 약 32MiB이며, 이전 전체 10장 배열 약 53.3MiB보다 작다. G01의 지역 없는 행성은 3~4장이다. 별도 렌더링 패스나 지형 메시를 추가하지 않았다. 전체 VRAM·게임 전체 성능을 뜻하는 수치는 아니다.

저장에 지역 규칙이 없으면 재질·장식을 새 지역으로 나누지 않는다. `planet_rules` 자체가 없는 오래된 저장의 빈 `terrain_traits`도 확인하므로, 현재 미리보기 외형 규칙만으로 과거 지상에 새 지역을 적용하지 않는다. 저장된 행성 규칙과 원정 파일을 수정하지 않는다.

12개 계열에서 세 영역의 도달 가능성·JSON 재현성·기존 저장 제외·최대 6장 배열을 확인했다. [지역별 근접 렌더와 기록](media/planet-variety/regions/report.json)은 실제 높이 함수와 게임 셰이더를 사용한 별도 검수 장면이며, 실제 지상 장식/스트리밍 확인은 별도로 기록한다.

최종 실제 지상 검사는 산화 사막·화산의 지역 경계에서 근경 75개 청크와 원경 100개 타일, Blender 장식(각 149/290개), 착륙 높이, 공유 재질 연결까지 **14개 확인을 통과**했다. 사용자 저장을 쓰지 않는 임시 호스트와 독립 설정 경로에서 실행했다. 고정 조명의 [산화 사막](media/planet-variety/regions/streamed-oxidized.png) · [화산](media/planet-variety/regions/streamed-volcanic.png)을 확인했다. 기존 카툰 윤곽선과 지형 LOD 경계의 거친 표현은 남아 있으며 전 계열의 걷기·건설·동굴 이동을 다시 검수한 것은 아니다.

Apple M2 / Metal Forward+ / 보통 / 1280×800에서 로딩 완료 후 장면 동작을 멈추고 동일 카메라로 지역 표현 끔→켬→켬→끔을 각각 120프레임 측정했다. [원시 결과](media/planet-variety/regions/frame-comparison.json)의 구간별 중앙 프레임 시간은 아래와 같다. GPU 시간은 이 환경에서 제공되지 않아 기록하지 않았다.

| 장면 | 끔 1 | 켬 1 | 켬 2 | 끔 2 | 드로 콜 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 산화 사막 | 16.91ms | 20.92ms | 22.12ms | 21.56ms | 모두 337 |
| 화산 | 23.13ms | 22.88ms | 23.00ms | 22.25ms | 모두 293 |

초기 산화 사막 구간과 후반 사이에 큰 시간 변화가 있어 이 짧은 측정으로 비용이 0이라고 단정하지 않는다. 화산 최종 측정에서는 지역 표현 켬/끔이 비슷한 범위였다. 동시 재질 혼합을 사용했던 첫 구현의 화산 켬 중앙값은 24.32/24.39ms였고, 수정 후에는 22.88/23.00ms였다. 서로 다른 실행 간 환경 변동이 있으므로 이를 게임 전체 FPS 향상률로 환산하지 않는다. 이 검사는 **정지 장면의 셰이더 비교이며 이동·전투 FPS가 아니다.**

새 지형 형태의 CPU 계산은 공짜가 아니다. 캐시 없는 기본 높이를 계열당 1만 번 계산한 마지막 단발 측정에서 기존 34~51ms, 새 지형 43~63ms였다. 게임의 캐시·동굴·메시·스레드 대기 비용을 포함하지 않는 함수 측정이다. 반복 배열 생성과 중복 거리 계산은 제거했고 12개 계열의 높이 합계는 정확히 유지됐다. 작업 자료의 `g02-sampler-cost.json`에 기록한다. 실제 이동 중 생성 지연과 장시간 성능은 후속 측정이 필요하다.
