# 행성 재질·지형·지역 다양성

2026-09-11 사용자 승인: 기본 재질 공유와 외형 계열 반복감을 줄이기 위해 재질 변형, 계열별 지형 형태, 한 행성 안의 지역 조합을 나눠 개발한다. 기존 INK v1과 성능 우선 방향을 유지한다. 아래 구체적인 수치와 구성은 이번 구현 선택이다.

| 단계 | 범위 | 현재 상태 |
| --- | --- | --- |
| G01 | 독립된 지질 재질 7종·시드별 선택·필요 재질만 로드 | 구현·최소 확인 완료 |
| G02 | 12개 지상 계열의 지형 형태·기존 저장 보존 | 구현·최소 확인 완료 |
| G03 | 같은 행성의 저지/암반/특징 지역과 재질·장식 연결 | 예정 |

공유 재질 개선은 기존 은하에도 적용할 수 있지만 지형 생성과 지역 배치 규칙은 새 은하에만 넣는다. 저장된 `planet_rules`를 소급 교체하지 않는다. 시설·광맥·사건 좌표와 기존 굴착/동굴을 보존한다. 생성 외형 18종을 단순히 더 많은 이름으로 늘리는 작업이 아니며 태양계·거대행성·궤도와 착륙 지도의 정확한 대응은 이번 범위 밖이다.

작업 자료는 `output/planet-variety-20260911/`에 둔다. 단계별 실제 확인과 남은 범위는 구현 뒤 아래에 기록한다.

## G01 — 지질 재질과 행성별 선택

주상 절리 `basalt_columns`, 다공질 응회암 `porous_tuff`, 층상 사암 `sandstone_bedded`, 전단 빙암 `frost_fracture`, 염류 다각피 `salt_polygons`, 충돌 각력암 `impact_breccia`, 습곡 판암 `folded_slate` 7개를 추가해 기본 재질은 17종이다. 색만 바꾼 복제 대신 서로 다른 높이·균열·결·공극 함수를 사용한다. 기존 화산의 `lava_crust`는 보존한다.

현재 12개 지상 계열의 11개는 각각 2개 암반 후보에서 행성 시드로 선택하고 화산의 고온 암반은 용암을 유지한다. 기존 계열 ID·지형·자원 분포는 바꾸지 않는다. 기본 조합은 `surface_materials.json`에 두며 이번 변화는 지표다. 궤도 모델의 개별 행성 전용 지리 생성으로 해석하지 않는다.

Blender 원본 `art/blender/surface-materials/geological-variety.blend`와 생성 정보 JSON, `tools/build_geological_textures.py`를 보존한다. 1024² RGBA의 기존 법선 XY/높이/거칠기 계약을 유지한다. 원본 미리보기 변위는 제작용이고 게임 지형은 노멀·명암으로 표현한다.

전체 재질 배열을 계속 키우지 않고 현재 행성의 암반·퇴적물·눈·얼음만 배열에 넣는다. 중복 제거 뒤 3~4장이며, RGBA8+mip 원본 크기는 약 16~21.3MiB로 이전 10장 약 53.3MiB보다 작다. 전체 GPU 메모리 실측값이 아니다. 같은 조합은 재사용하고 사용 종료 뒤 배열을 붙잡지 않도록 약한 참조 캐시를 사용한다. 계열 수가 늘어도 모든 텍스처를 지상에 상주시킬 필요가 없다.

Blender 5.2.1 Cycles와 Godot 4.7.2 Metal Forward+의 공통 INK 렌더에서 7개 재질을 확인했다. 12개 계열의 24개 시드 선택 재현성, 3~4장 배열·살아 있는 배열 재사용을 확인했다. 실제 `CrewSurfaceScene`의 산화 사막·충돌 고원에서 스트리밍·Blender 자연물·임시 면 재질·착륙 바닥 높이 10개 확인을 통과했고 스크립트/셰이더 오류 없이 종료했다. 지상 전 계열의 실제 이동이나 장시간 성능을 확인한 것은 아니다.

## G02 — 계열별 지형 형태

새 은하의 `planet_rules` v5부터 저장된 `terrain_layout.landscape` v1을 사용한다. 산화 사막은 큰 단차의 고원, 대륙은 넓은 구릉, 충돌 고원은 분지와 둥근 테두리, 파쇄 지형은 긴 균열, 툰드라는 길게 늘어진 구릉, 동결 지형은 큰 빙상 단구를 만든다. 화산은 함몰된 정상의 원추, 염류 지형은 얕은 평저 분지, 황토는 작은 침식 단구, 퇴적 지형은 조밀한 층상 고원, 결정질은 좁고 높은 첨탑, 알칼리는 중앙이 용식된 탑 지형을 만든다. 12개 별도 메시를 복제하는 대신 8개 형태 계산을 계열별 크기·간격·잔여 요철로 조합한다.

형태는 수백 m 규모이며 시드별 위치·높이와 기존 미세 요철을 결합한다. 착륙 원점 110m까지 기존 형태를 유지하고 200m까지 점진적으로 연결한다. 근경 충돌 메시·원경·굴착·동굴은 같은 높이 함수를 사용한다. 각 생성 작업은 독립 캐시를 가지며 원형 지형 중심 캐시는 128개로 제한한다. 저장된 규칙이 없으면 새 계산에 진입하지 않는다.

12개 계열에 대해 원본 높이 코드와 기존 규칙의 **1,920개 높이가 정확히 일치**함을 확인했다. 새 규칙 JSON 왕복 재현성, 착륙 구역, 표면 밀도와 굴착 제거도 같은 검사에서 확인했다. 실제 Godot INK에서 [12개 높이 지형](media/planet-variety/landforms/report.json)을 렌더했고 [고원](media/planet-variety/landforms/oxidized.png), [충돌 분지](media/planet-variety/landforms/cratered.png), [화산](media/planet-variety/landforms/volcanic.png), [첨탑](media/planet-variety/landforms/crystalline.png)의 실루엣을 비교했다. 이 비교 화면은 실제 높이 함수의 간이 메시이며 전체 게임 플레이 화면은 아니다.

실제 `CrewSurfaceScene`의 충돌·화산 계열에서 착륙지 밖 650m 위치의 스트리밍·장식·재질과 착륙 높이 10개 확인을 통과했다. 첫 검사에서 카메라만 옮기고 호스트의 관찰 좌표를 착륙지에 남겨 장식 검사가 실패했다. 검사 도구의 호스트 좌표를 함께 이동한 뒤 해결했다. 원경 완전 로딩·모든 급경사의 이동·동굴 전 구간을 검수한 범위는 아니다. `g02-check.log`, `g02-play.log`와 캡처는 작업 자료 폴더에 보존한다.
