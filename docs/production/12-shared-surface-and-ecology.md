# 공동 지표 탐험과 생태 동기화

2026-09-06 [공동 원정선](10-crew-cabin-and-playtest.md)의 항해와 [시드 생명체](11-seeded-ecology-integration.md)를 같은 실행 경로에 연결했다. 단독 탐험과 공동 원정의 저장 파일은 분리하며, 공동 원정에서는 호스트 세계가 지형·발견·연구·표본의 기준이다. 게임 전체 완성 또는 최종 경관 아트 승인을 뜻하지 않는다.

## 실제 플레이 경로

시작 화면에서 **함께하는 원정**을 열어 방을 만들거나 주소로 참가한다. 호스트 포함 최대 6명이 개인 캐릭터의 소유 장비로 같은 우주선에 합류한다. 조종사가 1~1,000,000의 행성 주소를 선택하고 전원이 준비하면 3D 항해·접근을 진행한다. 도착 후 다시 전원이 준비해야 공동 착륙할 수 있다.

- 같은 행성의 지표·지하를 독립적으로 이동한다. `WASD` 이동, 우클릭 시선, 클릭 굴착, `E` 유지 스캔, `Q` 근거리 표본 채집이다. 지하에서는 손전등이 자동으로 켜진다.
- 굴착한 광물은 실제 작업자의 배낭으로 들어간다. 우주선 주변에서 공동 창고에 넣거나 꺼낸다. 현재 공동 창고의 초기 광물 24개는 기존 원정 실증 설정이며 채집한 자원으로 간주하지 않는다.
- 한 명이 스캔한 생명체는 공동 발견 기록에 들어간다. 동시에 같은 개체를 채집해도 고유 표본은 하나만 생기며 모든 화면에서 원래 개체가 사라진다.
- 우주선의 연구 지원 범위에서 발견 목록으로 기초 분석·서식지 시험 구획을 선택한다. 격리 표본 목록에서 다른 행성으로 운송한 개체를 이식한다. 기질·환경·바닥 지지·승무원과의 간격이 맞아야 한다. 지원 팩 잔량과 생물량은 공동 상태다.
- 전원이 우주선 24m 안에 돌아와 준비해야 이륙한다. 같은 3D 선실로 복귀해 다른 행성으로 항해하며 연구·표본·광물은 호스트 세계에 보존한다.
- 지표에서 이탈하면 운반 중인 광물은 해당 행성·좌표의 회수 화물이 된다. 같은 캐릭터로 재접속하면 착륙선 근처에서 합류하고 화물을 직접 회수한다. 다른 행성의 같은 좌표에서는 회수할 수 없다.

거리·속도·적재·굴착/패킷 한도는 `data/crew_surface.json`, 생물 비용과 생태 규칙은 `data/ecology.json`에 있다. 화면의 구획·분석은 초기 소형 연구 루프이며 최종 연구실·산업 시설 모델을 대체하지 않는다.

## 호스트 판정과 전송

호스트만 캐릭터 충돌 이동·굴착 SDF 판정·스캔 유지 시간·수량·환경 적합성·생태 시간을 확정한다. 클라이언트가 보낸 위치나 즉시 스캔 완료 요청은 사용하지 않는다. 입력이 끊기면 미완료 스캔을 취소한다. 명령에는 세션·순번·세계 리비전이 붙으며 재전송·경합을 검사한다. 지형 변경, 관측 완료, 자원 소비, 표본 이동은 저장 성공 후 응답한다.

호스트 지형 스트리머는 연결된 모든 승무원 관심 영역의 합집합을 유지한다. 생물도 각 승무원 주변 후보를 합쳐 충돌체를 제공한다. 클라이언트는 자기 주변의 생물 수집/이식 상태와 현재 행성의 지형 변경 기록을 받는다. 100만 행성이나 다른 방문 행성의 전체 생태를 이동 패킷에 넣지 않는다.

현재 행성 지형 변경 배열은 신뢰 채널로 압축해 전달한다. **기록이 변경되면 현재 행성의 누적 배열을 다시 전달하는 초기 방식**이다. 행성당 4,096회 굴착, 압축 256KiB/해제 512KiB의 상한을 둔다. 대규모 월드에는 청크별 변경 번호와 증분 전송·압축 보관이 필요하다. 입력/위치 갱신과 생태 기록은 분리한다. 규칙·생물 도감·지형 해시와 착륙 회차를 검증해 다른 시드나 이전 착륙의 데이터를 적용하지 않는다.

네트워크 프로토콜은 2로 올렸으며 서로 다른 프로토콜/콘텐츠의 참가를 거부한다. 개인 장비 프로필 형식은 유지한다. 호스트 정상 종료·재실행 시 저장된 착륙 행성과 이식 개체를 복원한다. 호스트 자동 이전·플랫폼 계정 인증·인터넷 중계는 제공하지 않는다.

## 렌더와 검증 범위

기존 Blender 선체·탐험복·회수 상자와 600개 생물 도감의 INK v1 재질/윤곽을 재사용한다. 현재 매질에 맞는 209개 형태의 선정 규칙은 단독 탐험과 동일하다. 그래픽 창에서는 비동기 리소스 요청과 프레임당 한 개체 구성 한도를 유지한다. 화면 없는 Godot dummy 렌더러에서 발견한 RID 생성 충돌을 피하기 위해 해당 실행 방식만 리소스를 메인 스레드에서 로드한다. 모델·충돌·게임 규칙을 생략하지 않는다.

`tools/test_expansion.sh`는 공동 지표 규칙 검사도 실행한다. `python3 tools/test_crew_surface.py --players 2` 또는 `--players 6`은 각각 별도 ENet 프로세스의 실제 게임 장면을 실행한다. 호스트는 Metal 창, 기본 참가자는 화면 없는 실행이다. `--players 2 --render-guests`는 두 참가자의 Metal 창을 모두 켠다. 검사는 위치 배치를 통제하지만 실제 항해, 호스트 물리 이동, 굴착 충돌, 스캔 입력, 표본 경합, 재접속 회수, 행성 간 이식과 저장을 사용한다. 같은 컴퓨터의 검증이며 실제 인터넷·별도 Windows 장치·사람 6명의 장시간 플레이와 구분한다. 공동 지표 규칙 44개, 6인 실제 원정 120개, 두 Metal 화면의 2인 원정 72개, 기존 공동 선내 회귀 33개, 단독 생태 화면 회귀 30개, 960×640의 단독 공동 착륙/레이아웃 9개가 통과했다. 상세 명령·환경은 [검증 기록](media/crew-surface/verification.json)에 있다. [6인 착륙](media/crew-surface/six-landing.png), [공동 스캔](media/crew-surface/shared-scan.png), [행성 간 이식](media/crew-surface/shared-transplant.png)과 [960×640 지표 UI](media/crew-surface/surface-small.png)를 확인한다. 2인 경로의 지표 기록 압축 본문 누적은 9,493바이트였으며 위치 패킷·ENet 오버헤드는 제외한 진단값이다. 성능 보장이나 6인 대역폭 수치로 사용하지 않는다.

남은 연결은 지하 운반 로봇·충전/건설 자동화의 공동 운영, 분산 지역 장기 성능, 생물 이동/전투/먹이망, 나머지 매질 391개 형태, 사업 경제·문명·유적 연구, 실제 승강/격리실 연출, 고지연·손실·인터넷/플랫폼 검증이다. 공동 지표·생태 기능 실증의 통과를 이 항목들의 완료로 확대하지 않는다.
