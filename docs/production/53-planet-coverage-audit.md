# 행성 종류·지질·렌더링 적용 범위 감사

2026-09-08 사용자 추가 요청: 기존 암석/행성 분류를 모두 수용하는 지표 구조가 필요하며, 현재 행성 렌더링 자체가 전체 경우를 다루는지도 확인한다. **현재 정의된 콘텐츠의 연결 여부, 환경 표현의 충실도, 향후 확장 가능성을 분리하여 판단한다.** 구조의 원본은 [복합 표면 설계](../technical/09-planet-surface-materials-and-biomes.md)다.

## 1. 결론과 조사 기준

현재 게임의 기본 5종에 외형 계열 15개가 연결되어 있다. 착륙 대상은 가상 행성의 9계열이며, 거대행성 6계열과 태양계 참조 8행성은 착륙 불가다. **모델이 모든 계열에 있다는 것과 모든 지질·기후·상변화를 표현한다는 것은 다른 조건이다.**

이번 조사 시점의 파일에서 태양계 포함 23종의 Blender 원본과 근거리/원거리 GLB 46개가 존재했다. GLB 헤더·메시·정점색과 제공된 매니페스트 해시도 대조했다. [정적 조사 원본](media/planet-coverage/static-audit.json)은 기준 소스 해시를 포함한다. 저장소에 다른 아트 작업의 변경이 있어 조사 도중 추가된 원거리 모델·지표 `biome_style`도 최종 확인 대상에 포함했다. 첫 답변 당시 기록보다 최신 상태를 우선한다.

이번 요청의 ‘전체’는 우선 **현재 생성 규칙에서 선택 가능한 모든 계열·지질과 명시된 환경 상태**를 의미한다. 물리적으로 가능한 모든 외계행성 종류를 구현했다는 뜻은 아니다. NASA의 분류도 가스 거대행성·해왕성형·슈퍼지구·지구형처럼 크기/구조를 포함한다. 현재 게임의 `basalt/glacial/sulfur`는 암석·기후·화학 특성이 섞인 콘텐츠 분류이며 과학적 전체 분류가 아니다. [NASA 행성 유형](https://science.nasa.gov/exoplanets/planet-types/).

## 2. 실제 생성·표현 경로

`galaxy.json.planet_kinds` → `universe.gd`의 종류 선택 → `planet_traits.gd`의 같은 종류 외형 선택 → `space_flight.gd`의 GLB/재질 로딩으로 이어진다. 태양계는 `solar_reference` 분기로 `solar_planet.gd`의 전용 8종을 사용한다. 기본 행성 종류는 별도 항성 분광형·행성 티어와도 구분한다.

외형 후보는 정렬 후 시드로 선택하고, 색·수분·기압·온도·지형 진폭을 변형한다. 티어 1~5마다 별도의 구형 모델을 선택하는 분기는 없으므로 15×5개의 모델이 필요한 구조는 아니다. 이번 렌더는 계열별 대표 시드이며 모든 티어·시드의 전수 실행은 아니다.

‘조건부 수면’은 현재 `water > 15 && temperature > 0`인 경우의 y=-4 시각 수면이다. 현재 툰드라의 기본 -8°C에 변동 -8~+8°C를 더하는 범위에서는 이 조건을 넘지 않는다. 이름이 ‘해빙’이어도 실제 해빙·호수 얼음 상태가 구현된 것은 아니다.

지표 `biome_style`은 9개 ID를 받아 사막의 기존 전용 처리와 5개 추가 색면 처리로 표현한다. 습윤/툰드라·균열/설원·충돌/열수는 각각 일부 수식을 공유하고 염원·화산은 개별 색면을 쓴다. 전 계열 연결이지만 재질·환경 계산을 모두 개별 구현한 것은 아니다.

## 3. 지질 10종은 외형 15계열과 별도다

`mineral_world.json.profiles`는 주력/보조 광물과 보석을 정한다. 자원 규칙 v2에서 외형 계열의 `traits.geology`가 주 지질을 지정하고, **같은 기본 종류의 모든 지질 후보** 중 하나가 보조 지질로 합쳐질 수 있다.

| 지질 ID | 기본 종류 | 현재 새 세계에서의 역할 | 시각화에 필요한 지역 단서 제안 |
| --- | --- | --- | --- |
| `metallic` | 암석형 | 산화 사막의 주 지질·보조 후보 | 어두운 노두·산화 풍화면 |
| `weathered` | 암석형 | 습윤 대륙의 주 지질·보조 후보 | 풍화토·침식된 암반 |
| `pegmatite` | 암석형 | 충돌 고원의 주 지질·보조 후보 | 굵은 결정질 노두·밝은 암맥 |
| `sedimentary` | 암석형 | 현재 외형 주 지질 지정 없음·보조 후보 | 퇴적층·분지·자갈층 |
| `alkaline` | 암석형 | 현재 외형 주 지질 지정 없음·보조 후보 | 특유의 광화 흔적·노두 |
| `cryogenic` | 빙하 암석형 | 극저온 설원의 주 지질·보조 후보 | 빙하 퇴적물·노출 얼음 |
| `icy_basin` | 빙하 암석형 | 툰드라의 주 지질·보조 후보 | 결빙 분지·퇴적 가장자리 |
| `cryovolcanic` | 빙하 암석형 | 균열 빙원의 주 지질·보조 후보 | 얼음 균열·분출 퇴적 흔적 |
| `volcanic` | 황산 암석형 | 화산의 주 지질·보조 후보 | 용암 지각·재·냉각 균열 |
| `hydrothermal` | 황산 암석형 | 염원·열수대의 주 지질·보조 후보 | 침전 껍질·광물 띠 |

현행 v2 후보 조합은 외형별로 암석 3×5, 빙하 3×3, 황산 3×2의 **30개 외형/보조 선택 슬롯**이다. 주 지질과 같은 선택 9개는 혼합 없이 유지하고 나머지 21개는 보조 후보를 합친다. 실제 시드 선택 가능성을 설명하는 코드상의 조합이며 이번에 30개를 모두 렌더한 수치가 아니다. 원래 광물 후보가 겹치면 서로 다른 선택이 같은 결과를 줄 수도 있다.

현재 지표·행성 셰이더는 `mineral_profile`을 읽어 보조 지질의 지역을 배치하지 않는다. 보조 광물·보석 목록과 개별 자원 모델은 달라질 수 있지만 ‘그 지질 지대가 어디에 있는지’는 표면으로 표현하지 않는다. 새 구조는 10종을 모두 수용하되 광석마다 전용 행성 하나를 만드는 방식으로 확장하지 않는다.

## 4. 모델 유무와 별개로 남은 표현 공백

1. **궤도 결빙 판정 없음.** `space_flight.gd`와 항법 미리보기는 `water`에서 `sea_level`을 정하고 `planet.gdshader`는 이를 바다색·해안·거칠기로 표시한다. 기온·기압·얼음 피복 입력이 없어 차가운 행성에도 액체 바다와 같은 표현 경로를 사용한다. 실제 지상은 기온을 확인하므로 두 표현이 불일치할 수 있다.
2. **실제 지역 기후와 표면 분포가 분리됨.** 지표의 건습·눈/암반 색면은 계열과 노이즈로 정한다. 습도·지역 기온·공급 물질로 결빙/해빙하는 공통 상태 모델은 없다.
3. **구면 대륙·지상 지리 미대응.** 궤도의 FBM/정점 마스크와 지상의 높이/분포는 같은 지리 지도가 아니다. 우주에서 본 대륙·빙원이 특정 착륙 좌표의 풍경을 보장하지 않는다.
4. **지질 10종의 지역 시각 연결 없음.** 특히 `sedimentary`·`alkaline`은 별도 외형 계열이 없는 보조 지질로 등장한다. 자원 프로필을 읽는 공통 지질 분포가 필요하다.
5. **거대행성 6계열은 공통 대기 수식.** 색·형상·시드 차이는 있지만 `storm`만 폭풍 수가 늘어나는 식의 계열별 대기 프로필은 없다. 현재 여섯 계열은 같은 띠/폭풍/섬광 수식을 사용한다.
6. **기후·궤도 생성 관계가 느슨함.** 외형의 온도는 계열 기준값에 시드 편차를 더하고, 이후 천체 메타데이터를 붙인다. 생성 시 항성 일사·자전으로 기후를 재계산하는 모델은 아니다. 기후 일관성 개선은 기존 밸런스·세이브 보존과 분리해 설계한다.
7. **표현 코드가 분산됨.** 비행과 항법 미리보기에서 행성 재질 매개변수를 각각 설정한다. 새 얼음/대기 프로필이 한쪽만 갱신되는 일을 방지할 공유 표현 정의가 필요하다.
8. **완료 목록의 누락.** 조사 시 `render_assets.json`에는 가상 행성 15계열의 근거리 경로가 모두 미등록이었다. 전용 매니페스트와 런타임 로더는 존재하므로 ‘게임에 모델 없음’과 다르다. 공통 검수 목록으로 전체 커버를 보장할 수 없는 상태다.

## 5. 확장 구조에 반영할 기준

**기본 종류·지질·기후·표면 상태·생태·크기·티어를 독립 축으로 관리한다.** 기존 ID와 생성기는 호환 어댑터로 유지한다. `glacial`의 얼음 피복과 `basalt`의 암석 기질을 동시에 표현할 수 있게 하고, 지질을 교체하지 않고 테라포밍 상태만 바꿀 수 있어야 한다.

최종 적용 범위는 가상 궤도 15계열·태양계 8행성·착륙 지상 9계열·자원 지질 10종 모두다. 한랭 지역 한 개와 첫 재질 6종은 품질 실증용 시작점이다. 염원·화산·열수·퇴적·결정질을 빠뜨린 상태로 전체 지표 개선 완료를 기록하지 않는다.

향후 물로 대부분 덮인 행성, 용융 표면, 대기 없는 암석, 영구 동결, 동주기 경계대, 고밀도/대형 암석, 짙은 대기 등은 독립 프로필 조합의 확장 대상으로 분류한다. 이 목록은 전부 새 구현을 승인한 요구가 아니며 실제 우주의 완전한 경우 목록도 아니다. 얼음 거대행성을 얼어붙은 보행 지표로 취급하지 않고, 육지가 없는 지역의 착륙 가능 여부는 별도 능력 조건으로 관리한다.

생성 후보마다 궤도 근거리/원거리·미리보기·지표·지하·자연물·환경 변화·저장/구버전 대응의 결과 또는 명시적인 ‘대상 아님’ 사유를 기록한다. 매핑 없는 새 ID를 조용히 암석 기본색으로 표시하며 지원 완료로 처리하지 않는다. 정확한 제안 데이터와 전 계열 표면 조합은 [구조 설계](../technical/09-planet-surface-materials-and-biomes.md)의 전체 적용 절을 따른다.

## 6. 이번 실행 확인 기록

이번 추가 확인은 사용자 요청에 따른 계열별 렌더 감사다. 전체 게임 회귀나 100만 시드 전수 테스트가 아니다. 최종 결과는 [검증 요약](media/planet-coverage/verification.json)에 기록했다.

- 정적 자료: 23종 원본·GLB 46개, 지상 장식 9계열×4 경로, 생성/재질/자원 분기와 매니페스트 해시.
- 실행 환경: Godot 4.7.2, Metal Forward+, Apple M2. 기존 제작 검사에서 렌더 부분을 임시 스크립트로 분리하고 이 문서 전용 출력 폴더를 사용한다. 기존 승인 캡처를 덮어쓰지 않는다.
- 첫 실행에서 새 `*_lod1.glb`의 가져오기 캐시 누락으로 실제 로딩 오류가 발생했다. Godot 에디터 가져오기를 실행했다. 파일 존재 검사만으로 실제 로딩을 보장할 수 없는 사례다.
- 기존 `test_planet_diversity.gd`의 냉각 시험 데이터는 현재 시설에 필요한 `work` 필드가 없어 렌더 전에 실패했다. 이번 임시 감사는 해당 사업 시험을 제거하고 생성·실제 렌더에 한정했다. 이 오류를 실제 게임 냉각 실패로 단정하거나 기존 시험이 통과했다고 기록하지 않는다.
- 새 행성 종류·게임 규칙·Blender 형상·셰이더는 이 작업에서 수정하지 않는다. 제안과 확인 자료를 작성하며 발견된 표현 공백은 미구현으로 남긴다.
