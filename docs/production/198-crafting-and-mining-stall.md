# 권총 제작 멈춤과 채굴 완료 지연 조사

2026-09-15 Windows 실플레이 제보를 조사했다. 원본 저장 대신 `test-results/craft-mining-repro`에 복사한 원정과 프로필로 검사한다.

## 확인된 사실

- 실행 환경은 Godot 4.7.1 Forward+ / D3D12, NVIDIA GeForce GTX 1070이다.
- 제보 실행 로그 `test-results/play-latest.log`에 무기 상세창의 `element_id` 접근 오류가 반복되고, 이후 D3D12 버퍼 생성 실패 `0x887a0005`와 렌더링 자원 오류가 이어졌다.
- Windows 시스템 로그에는 16:35:31 `Display` 이벤트 4101로 NVIDIA 드라이버가 응답을 중지한 뒤 복구됐다는 기록이 있다. 원본 저장 확인 시 `crafted:3 = pistol_1`과 해당 총기 품질/탄약 기록이 존재했다. 제작 결과 저장과 그래픽 정지를 구분한다.
- 총기 제작 설계를 선택한 뒤 신체, 염색, 모듈, 탄약 탭으로 바꾸면 숨겨진 상세창에도 기본 총기 정의를 전달했다. 이 정의에는 개별 총기의 속성이 없어 같은 스크립트 오류를 재현했다. 이것만으로 드라이버 정지 원인까지 확정하지 않는다.

## 수정과 행동 범위

- 장비 상세 갱신을 아이템/제작 탭으로 제한했다. 화물과 나머지 탭은 각자의 상세 UI를 사용한다. 기존 총기 속성, 제작 비용, 저장 방식은 유지한다.
- 광맥 잔량만 달라진 지표 상태는 기존 지역/시설과 비교한 뒤 변경된 광맥의 크기 또는 고갈 제거만 반영한다. 아직 생성 대기 중인 고갈 광맥도 제거한다. 주변 광맥 재검색과 관련 없는 시설, 지표 장식, 대기, 식생, 물길 갱신을 건너뛴다.
- 지형 revision, 현장/지역 정보 또는 다른 현장 값이 바뀌면 기존 전체 현장 갱신으로 돌아간다. 지역 이동과 지형 편집에 잔량 전용 경로를 잘못 적용하지 않는다. 화물 상자는 기존 별도 갱신을 유지한다.
- 요청의 호스트 판정, 독립 거래 초안, 전체 저장 검증, 작업 스레드 저장 완료 후 보상/네트워크 발행은 보존한다. 메인 스레드의 전체 검증 및 스냅샷 생성 비용은 남는다.

## 검수 경계

`tests/check_craft_mining_stall.gd`는 별도 저장 경로가 필요한 국소 재현 도구다. 복사본에서 재료와 위치를 준비하고 권총 제작, 다른 탭 전환, 마지막 광석 한 개 채집, 관련 없는 모델 보존과 저장을 확인한다. 저장 작업을 강제로 기다리는 시간은 프레임 지연 수치로 사용하지 않고 실제 비동기 poll 시간을 따로 기록한다.

### 최종 실행

`test-results/craft-mining-final.log`: 실제 지상 및 대상 모델 적재 후 8항목 통과. 권총 1개 제작, 마지막 광석 지급과 고갈, 생성 대기 목록 제거, 관련 없는 적재 모델 유지, 복사본 저장을 확인했다. 다른 네 탭으로 전환한 뒤 스크립트 오류도 없었다. `craft-after.png`와 `mining-after.png`에서 권총 미리보기와 지상 채집 결과 효과를 확인했다. 시험 재료/위치는 복사본에서만 준비했다.

| --- | --- |
| 권총 요청 제출 | 17.705ms |

비동기 저장 경과 시간 동안 프레임을 계속 진행했다. 이 경과 시간을 단일 프레임 정지로 해석하지 않는다. 상태 발행 전체는 승무원/지표 패킷 생성, UI 반영과 완료 응답을 포함한다. 여기에 남은 비용과 전체 검증은 여전히 60 FPS의 16.7ms 예산을 넘을 수 있다. 초기 탐색 실행에서 채굴 발행 40.230ms가 관찰됐지만 준비 상태와 시뮬레이션 제어가 달라 최종 수치와 동일 조건의 개선율로 비교하지 않는다.

최종 실행에 렌더러 오류가 없었고 Windows `Display` 로그에 새 응답 중지 이벤트도 없었다. 제보 당시의 드라이버 정지는 재현하지 못했다. `git diff --check` 통과. 테스트 준비 중 재료/위치와 시뮬레이션 정지 범위를 보정한 실행은 최종 통과 수량에 포함하지 않는다.

전체 회귀, 외부망/6인, 장시간 플레이, 다른 GPU/드라이버와 배포 실행 파일은 검사하지 않았다. 새 모델이나 음원은 제작하지 않았다. 그래픽 드라이버 정지의 유발 조건과 전체 채굴 프레임 드랍 해소는 별도 확인이 필요하다.
