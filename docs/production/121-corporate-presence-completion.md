## 협동 실행에서 확인한 것

`tools/test_corporate_network.py`, `tests/test_corporate_network_peer.gd`로 독립 호스트 1개와 클라이언트 2개를 실행했다. 각 프로필/세이브는 운영 저장과 분리한 임시 폴더를 사용한다. 긴 비행·지상 이동은 검사에서 접근 위치와 장비를 설정하며 조사·운반·수리·교전·회수는 실제 네트워크 입력/요청과 호스트 저장으로 진행한다.

- 두 승무원이 조사해도 화물 기록은 하나다. 조종사가 아닌 원격 승무원의 회수 장치 조작은 거부된다.
- 실제 진행률/선박 소유 적재를 다른 클라이언트에서도 받는다. 운반 중 클라이언트를 강제 종료하면 입력이 만료되어 미완료 회수를 취소한다. 토큰 재접속으로 같은 캐릭터/작업 단계를 복원한다.
- 적재 후 재접속해도 포드 하나가 공동 선박 거치대에 유지된다. 인계 후 공동 대금이 모두에게 한 번 반영된다.
- mine 부품 수령·설치·정비·재가동 네 단계가 일치한다. 설치 시 지급하지 않고 재가동 성공 시 한 번 지급한다.
- CooperTech 우주 조사에서 같은 지상 사건 ID를 받는다. 원격 승무원의 실제 접근·무기 요청·부품 회수로 전원의 단서가 종결된다.
- 호스트 종료/재실행 후 유실 화물 stage 3, mine stage 4, 같은 로봇의 회수 기록과 총 단발 대금이 유지된다.

손상된 지상 사건 행을 단서 검사에서 먼저 읽지 않도록, 세계 로드 시 사건 행 형식 검증 후 연결 무결성을 검증하도록 순서를 보완했다. `check_corporate_link_validation.gd`로 정상 링크·잘못된 사건 행·없는 대상 참조의 세 경우를 확인했다. Godot 편집기 import/스크립트 로드에서도 오류가 없었다.
