# 지하 안전, 장비 손, 탄약과 지표 로딩

2026-09-15 사용자 요청. main `d7613f3e2`를 받은 뒤 네 항목과 추가로 제보한 착륙 FINCH/공동선의 보행 충돌을 수정했다. 비행 중 선박 간 충돌 추가 요청으로 확대하지 않는다.

## 변경

### 200m 기반암과 추락 방지

- 기존 측정 방식인 해당 수평 좌표의 최초 지표 높이에서 200m를 적용한다. 새 시드 동굴뿐 아니라 구 고정 동굴에도 최종 밀도에 기반암을 합친다. 반복/측면 굴착 부피가 경계를 넘어도 아래쪽 고체를 제거하지 못한다.
- 예전 저장의 `minimum_depth=-72`가 남아도 지표 아래 200m와 여유 청크를 읽는다. 수평 열별 최초 지표를 확인하며 기존 설정/해시와 동굴·광물 배치를 다시 생성하지 않는다. 구 절대 깊이에 의한 굴착 거절과 저장 위치 제한도 보완한다.
- 물리 충돌에서 놓친 틈을 통과해 떨어질 때, 캐릭터 발의 이동 구간을 실제 지형 밀도로 확인한다. 정상적인 물리 바닥 접촉은 그대로 사용한다. 안전 보정은 호스트 이동과 클라이언트 예측/재실행에 같은 함수를 사용한다.
- 이미 기반암 아래에 있는 캐릭터는 지형 준비 여부를 검사하기 전에 착륙 지점으로 복구한다. 로드 시에는 복구한 위치 주변을 먼저 준비한다. 기존 편집/시설/재고 기록은 삭제하지 않는다.
- 지상 깊이 표기도 절대 Y 대신 최초 지표 기준으로 맞춘다.

### 탄약과 R

- 현재 탄창/예비탄과 재장전 키를 우측 하단의 장비 정보 위에 배치한다. 기존 탄약 아이콘, 재장전 진행 막대와 레이저 열 표시를 유지한다. 키를 바꾸면 실제 설정 키를 표시한다.
- R 요청이 호스트의 저장 작업이나 아직 갱신되지 않은 조작 입력에 막힌 경우, 같은 총을 들고 조작 가능한 동안 최대 1.5초간 120ms 간격으로 재시도한다. 메뉴/장비 변경/기한 만료 시 취소한다. 재장전 소리·모션·탄 이동은 여전히 호스트 승인 이후에만 시작한다.
- 탄창 크기, 탄약 비용, 기존 총기 상태와 권총의 무한 예비탄 규칙은 변경하지 않는다.

### Blender 장비 손

- 채집기 기본/강화, 지형 변환기 기본/강화의 네 Blender 원본에 편집 가능한 기존 장갑 골격 조립본과 `Socket_HandRight/Left`를 보존했다.
- GLB에는 장비와 손 접점을 출력하고, 게임은 기존 두 손 GLB를 공통으로 인스턴스화한다. 장갑 메시를 네 게임 모델에 중복 저장하지 않는다.
- 기존 손가락·팔꿈치 골격과 IK를 재사용한다. 채집 흡입, 굴착 반동, 보행 흔들림과 같은 좌표계에서 손이 따라간다. 지형 변환기는 팔이 닿도록 휴대 위치를 조정했다.
- 재생성: 기존 장비 생성기를 실행한 뒤 `Blender --background --python tools/build_field_tool_hands.py`. 이 스크립트는 각 원본/GLB와 아래 Blender 검토 렌더를 갱신한다. `render_assets.json`에 후처리 생성기를 기록했다.
- 사운드는 기존 ElevenLabs 채집·굴착·총기 음원 연결을 유지한다. 새로운 음원을 생성하지 않았다.

### 로드 완료 조건

- 단독 시작/저장 재개 로더와 대기실 이후 첫 스냅샷 로더가 같은 행성 준비 함수를 기다린다.
- 주변 활성 지형 메시/충돌, 저장된 굴착, 원경, 생태/현장 모델, 지표 세부물과 근처 사건 모델, 착륙선 충돌 준비를 확인한다. 그 뒤 물리 프레임과 기존 렌더 준비를 거쳐 가림막을 해제한다.
- 로딩 중 로컬 이동을 시작하지 않는다. 네트워크와 지형 작업 스레드는 계속 진행하고 새 지표 패킷을 반영한다.
- 광활한 행성 전체를 메모리에 한 번에 올리는 방식은 아니다. 처음 보이는 원경과 플레이에 필요한 주변 활성 범위를 준비하며 이후 이동에 따른 스트리밍은 유지한다.

### 착륙 선체의 보행 충돌

- 공동선과 호출한 FINCH에 실제 선체 삼각형을 사용하는 충돌체를 추가했다. 하나의 큰 상자로 날개 아래 빈 공간까지 막지 않는다.
- 선체/장착 모듈 변경이 완료되면 해당 선박 충돌만 교체한다. 같은 스냅샷 반복은 충돌을 재생성하지 않는다. FINCH 호출 하강이 끝나면 충돌을 활성화하고, 회수 시 모델과 함께 제거한다.
- 호스트가 다른 행성 승무원을 계산하는 비렌더 공간에도 같은 선체와 충돌을 준비한다. 교체 중 해당 공간의 보행은 충돌 준비를 기다린다.

## 행동별 처리 범위

| 행동 | 실제 처리 |
| --- | --- |
| 굴착 한 번 | 기존 호스트 판정/거래/저장 후 영향받는 청크만 메시와 충돌을 교체. 기반암은 밀도 함수의 국소 계산이며 전 행성 재생성을 하지 않는다. |
| 캐릭터 낙하 | 정상 바닥 충돌이 없는 프레임의 이동 구간만 0.25m 간격으로 확인. 교차 지점만 이분 탐색한다. 정상 보행 속도를 낮추지 않는다. |
| 지형 관심 범위 이동 | 주변 수평 열의 하한을 캐시한다. 캐시는 1,024열을 넘으면 다음 관심 범위 변경에서 비운다. |
| R 재장전 | 한 총의 승인 대기만 유지. 실패한 요청으로 탄 이동/성공 모션을 확정하지 않는다. 호스트의 기존 저장 무결성은 유지한다. |
| 장비 변경 | 이전 휴대 모델/손을 제거하고 새 모델에 두 손을 연결. 프레임별로 전체 에셋을 찾지 않는다. |
| 선체 변경/FINCH 호출 | 해당 모델의 면을 한 번 읽고 충돌체를 설치. 초기 면 수집/물리 shape 생성은 메인 스레드 비용으로 남는다. 다른 지형/시설/재고를 갱신하지 않는다. |
| 로드 | 기존 비동기 준비의 완료 조건을 기다린다. 완료 전 성공으로 표시하거나 저장·네트워크 순서를 생략하지 않는다. |
