# 모든 행성의 근접 표면과 품질 옵션

2026-09-10 사용자 확정: 가까이에서 깨져 보이는 행성의 거친 무늬를 모든 행성에 개선하고, 그래픽 옵션에 성능 단계를 연결한다. [지역 복원의 우주 외형](112-orbital-terraforming.md)은 계속 유지한다.

## 적용

- 생성 행성 18종, 태양계 8행성, Space Y 복원 화성까지 27개 원형에 적용한다. 현재 원정의 실제 비행과 항성지도 미리보기가 같은 재질 설정을 사용한다. 시드별 색·물·지질·가스대·자전 및 기존 저장의 복원 상태는 유지한다.
- Blender 제작 함수의 연속된 지질/색 필드를 2048×1024 맵으로 평가한다. 낮은 정점 밀도에 의해 해안선과 지질 경계가 삼각형으로 늘어나는 현상을 줄인다. 지구·복원 화성의 해안색은 텍셀당 네 지점을 선형 색 공간에서 평균한다. 지구의 기존 Natural Earth 자료와 화성의 창작 지형을 재사용하며 새 관측 자료라는 뜻은 아니다.
- 확대되던 큰 얼룩의 대비를 줄이고 행성 로컬 좌표의 세 방향 투영으로 가까운 지질 무늬를 더한다. 공통 Blender 지면 재질의 높이 채널을 재사용한다. 암석·빙설·용암·퇴적암 등을 구분하고 가스/얼음 거대행성 및 금성에는 흐름 방향의 무늬를 사용한다. 가스 표면에 암석 요철을 만들지 않는다.
- 맵은 밉맵·선형/이방성 필터를 사용한다. 경도 이음선의 미분을 직접 계산하고 극의 샘플 위치를 제한한다. 절차 무늬의 경계와 행성 재질의 INK 3단 명암은 화면 픽셀 크기로 보정한다. 기존 공통 명암/외곽선과 실제 모델의 형태를 유지한다.

## 개인 설정과 비용

`F10 → 그래픽 → 행성 표면 품질`. 전체 품질 프리셋에도 포함한다. 개별 변경은 사용자 설정으로 표시하고 즉시 저장한다. 새 항성계·재방문·이미 열린 미리보기에도 클라이언트 공통 셰이더 값으로 적용한다. 호스트 세계나 다른 참가자의 설정을 바꾸지 않는다.

| 단계 | 표면 표현 | 가까운 픽셀의 추가 세부 맵 샘플 |
| --- | --- | --- |
| 낮음 | 새 표면 맵과 경계 보정 | 0회 |
| 보통·기본 | 지질 무늬 한 겹 | 최대 3회 |
| 높음 | 지질·미세 무늬 두 겹, 고체 표면의 작은 요철 | 최대 6회 + 미분 기반 법선 |

위 횟수는 세부 무늬의 추가 비용이며 전체 셰이더 비용이 아니다. 멀어져 한 픽셀에 무늬가 모이면 연속적으로 희미해지고 해당 샘플링 분기를 건너뛴다. 반지름·화면 점유율을 픽셀 미분에 반영하므로 행성 크기·해상도·미리보기 크기가 달라도 같은 기준을 사용한다. 새 폴리곤·상시 렌더 뷰·그림자 패스를 추가하지 않는다. 낮음에서도 2K 기반 맵은 유지하므로 이 옵션은 주로 계산량 차이이며 텍스처 메모리 절약 옵션은 아니다.

기존 `client_settings.json`에 값이 없으면 이전 전체 품질의 낮음/보통/높음을 따른다. 기존 사용자 설정이면 보통으로 시작한다. 수면 품질·시야거리·렌더 해상도 등의 개별 값은 보존한다.

## 제작과 확인

생성기: `tools/bake_orbital_surfaces.py`. 원본 모델 제작기의 `variant_fields`를 공용화해 모델과 맵의 규칙이 갈라지지 않게 했다. 기존 `.blend`/GLB 자체를 다시 만들거나 저장하지 않는다. 27개 맵의 해시·크기·좌표 규약은 `assets/textures/orbital/manifest.json`에 둔다. 맵 PNG는 Git LFS 대상이다. Blender 검수는 `tools/render_orbital_surface_sources.py`로 원본 메시 위의 새 맵을 렌더하며 임시 검수 원본은 `/tmp/orbital-*-review.blend`에 저장한다.

Godot 4.7.2 Forward+ / Metal 실제 렌더에서 27종·옵션 38개, 실제 원정 18개, 극/경도 이음선·원거리 LOD 6개 확인을 통과했다. 최종 세 실행 로그에 스크립트·셰이더 오류는 없다. Blender 5.2.1에서 산화암·지구·목성과 최종 해안 보정 후 지구·복원 화성을 렌더해 확인했다.

- [27종 전체](media/orbital-surfaces/all-planets.png), [27종 근접](media/orbital-surfaces/all-planets-close.png), [960×640 설정](media/orbital-surfaces/settings-960.png)
- [Blender 지구](media/orbital-surfaces/earth-blender.png), [Blender 산화암](media/orbital-surfaces/oxidized-blender.png), [Blender 목성](media/orbital-surfaces/jupiter-blender.png)
- `tests/check_orbital_surfaces.gd`: 실제 행성 생성 경로의 27종, 세 품질·프리셋·개별 저장·구 설정 이행, 같은 카메라/조명의 근접 비교. [실행 기록](media/orbital-surfaces/verification.json).
- `tests/check_orbital_surface_edges.gd`: 지구·산화암·가스 행성을 반지름 1.25배 거리의 극/이음선과 13배 거리의 기존 LOD에서 확인한다. [비교 화면](media/orbital-surfaces/poles-seam-far.png)과 [기록](media/orbital-surfaces/edge-verification.json).
- `tests/check_orbital_surface_play.gd`: 격리한 실제 원정에서 외부 비행·열린 항성지도·호스트 복원 갱신·태양계 미리보기·닫힌 미리보기 중단·기존 선박 소리 연결. 이전 지역 복원 검사의 준비된 성공 세계를 사용하며 새 경제 완주를 의미하지 않는다. [실행 기록](media/orbital-surfaces/play-verification.json).

실제 새 원정 확인 중 항만 운송 코드가 첫 착륙 전의 선택적 `crew.landing` 값을 필수로 읽는 오류도 발견했다. 빈 착륙 기록으로 처리하도록 한 줄을 보정했으며 같은 시작 흐름에서 오류 없이 실행되는 것을 확인했다.

프레임 간격 측정은 Apple M2 / Godot 4.7.2 Forward+ Metal의 단독 행성 장면 비교다. 다른 앱/개발 작업의 부하를 통제하지 않았으므로 품질 단계별 속도 향상 수치로 보고하지 않는다. GPU 처리 시간 또는 전체 게임 성능으로 해석하지 않는다. Windows 실기·장시간 항해·다중 클라이언트 성능과 모든 시드별 경관은 이번 확인 범위가 아니다. 지상 지형이나 위성을 다시 만드는 작업, 궤도와 실제 지표의 해안선 일치, 무한 확대 해상도를 구현한 것도 아니다. 신규 소리가 필요한 동작 변경은 없다.
