# 행성 시드와 생명체의 실제 플레이 연결

2026-09-06 생물 제작 완료 이후 메인 탐험에 연결한 기능 실증이다. 제작 기준은 `893175d1`의 600개 형태·12,000개 외형이며 [INK v1](06-rendering-quality-standard.md)의 공통 재질·윤곽·원본 색 변환을 유지한다. 이 문서는 생태 구현의 현재 범위이며 게임 전체 완성 또는 최종 아트 승인을 뜻하지 않는다.

## 실제 플레이

시작 화면의 **우주 탐험**에서 3D 우주선을 조종하고 행성을 선정해 착륙한다. 항법 패널은 선택한 행성의 가상 환경 추정 온도·압력을 표시한다. 현재 세 지형 종류의 생성 기후이며 실제 외계 생명 관측값이 아니다.

- `E`를 1.5초 유지해 조준한 생명체를 스캔한다. 사거리 18m, 시야 방향, 지형·다른 개체의 가림을 검사한다.
- 스캔 후 4m 안에서 `Q`로 고유 표본을 확보한다. 단순 스캔으로 화물은 생기지 않는다. 같은 개체를 다시 채집할 수 없다.
- `J`에서 발견 기록·서식 범위·연구·격리 화물을 확인한다. 우주선 24m 이내에서 기초 분석에 착륙지 창고 광물 3개를 사용한다.
- 광물은 지형 굴착으로 채집하고 `R`로 운반 로봇을 호출해 착륙지 창고에 운반한다. 이 지역 창고는 해당 행성에 남고, 격리 표본은 원정 우주선과 함께 이동한다.
- 분석한 환경과 현장 기질이 맞으면 광물 6개로 반경 18m의 관리 시험 구획을 설치한다. 다른 행성에서 운송한 표본을 적합한 구획에 이식한다. 같은 표본 ID가 화물에서 목적지 개체로 한 번 이동한다.
- 지원 팩은 탐사 시간 3,600초분이다. 고갈하면 관리 환경·생물량 증가가 멈추며 광물 3개로 여과·영양 팩을 보충해 재개할 수 있다. 우주선의 전력·물·급이 지원을 묶은 초기 운영 모델이며 실제 선체 에너지·화물 질량 계산은 후속 범위다.
- `L`은 손전등 자동/켜짐/꺼짐을 순환한다. 자동 모드는 지붕이 있는 지하를 비추고 낮의 생명체 색을 불필요하게 과노출하지 않는다. `F5`, 30초 주기, 정상 창 닫기, 출항 시 지형·생태 상태를 저장한다.

수치와 제작 비용은 `data/ecology.json`의 밸런스 초안이다. 기본 은하 시드 `71491`의 행성 번호 **16 → 22**는 같은 암반 서식 조건을 이용한 운송 검증 경로다. 게임은 이 순서를 강제하지 않는다.

## 생성·접지·생태 상태

100만 행성을 미리 만들지 않는다. 방문한 행성에만 `ecology-v1` 기록을 만들고 `body.streams.ecology`로 기후·고유 생명 기원·형태 ID·외형 ID를 결정한다. 형태/외형은 이름순 ID 풀에서 고르며 지형·자원 시드를 소비하지 않는다. 저장에는 도감과 규칙의 해시를 고정한다.

현재 실제 지형이 지원하는 환경은 **암반·건조·한랭 지표와 동굴**이다. 600개 중 이 환경 및 지상 이동 조건에 맞는 **209개 형태**가 선정 풀에 들어간다. 환경별 38/51/61/59개다. 행성마다 그중 최대 8개 계통을 고정하며 주변 실제 출력은 최대 12개다. 12,000개 외형을 독립 종으로 부풀리지 않는다. 제작 도감의 `spawn_enabled: false`는 유지하고, 메인 런타임의 명시적인 환경·구조군 허용 규칙으로 연결한다.

세포 주소·계층·개체 슬롯으로 개체 ID와 후보 위치를 고정한다. 지형 SDF에서 지표 또는 실제 동굴 바닥을 찾고 몸체 크기, 바닥 지지, 경사, 머리 위 공간을 검사한다. 몸체를 지면 법선에 맞추고 기본 물리 충돌체를 붙인다. 우주선 선체·승강 구역·착륙지 원점은 비워 둔다. 굴착 뒤에는 지지 조건을 다시 평가한다. 채집한 ID는 재방문·관심 영역 이탈·재로드에도 다시 생성하지 않는다.

고유 기원은 무생명/휴면/성립 상태로 시드에 고정한다. 무생명 행성의 고유 계통은 빈 배열이며 물이나 장치를 설치해도 동물이 새로 발명되지 않는다. 휴면 기원은 적합한 관리 환경 안에서 미생물 3초, 식생 10초, 동물 30초의 안정화 순서를 따른다. 숨겨진 동물 계통이 활성화되기 전 성체 모델을 지표에 세워 두지 않는다. 이식 개체는 외부 기원으로 별도 추적한다.

생물량은 관리 환경·고유 계통·이식 개체와 탐사 시간으로 계산하며 카메라, LOD, 화면에 보이는 개체 수와 분리한다. 닫힌 세계나 방문하지 않은 행성의 시간을 벽시계로 따라잡지 않는다. 고열 생물의 체온을 냉각 능력으로 취급하지 않는다. 실제 광물 산화·열원·열배출 장치 연결은 별도 개발 항목이다.

## 렌더·저장

두 LOD의 PackedScene을 비동기로 요청하고 프레임당 한 개체만 구성한다. 현재 관심 범위 밖의 인스턴스와 임시 로드 요청을 정리한다. 근거리/원거리 모두 기존 `bestiary_actor.gd`의 Blender 피벗·상태 모션·팔레트와 INK 셰이더를 사용한다. 모델과 원본 파일은 이번 연결에서 변경하지 않았다. [Godot 비동기 로더 규칙](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html)에 따라 완료 상태를 확인한 후 리소스를 받는다.

관측, 기초 분석, 채집, 설치, 이식, 보충은 사본에 적용하고 세계 저장이 성공한 뒤 실제 상태와 화면에 반영한다. 시드와 다른 계통, 잘못된 외형, 중복 화물/이식, 원산지 단절, 미관측 연구, 비정상 수치를 거부한다. 저장 실패 시 광물과 표본을 소비하지 않는다. 도감/규칙 버전이 다르고 유효한 백업도 없으면 원본을 보존하고 한국어 오류 화면을 표시하며 새 세계로 덮어쓰지 않는다.

## 검증과 현재 한계

검증 명령과 수치는 [검증 메타데이터](media/ecology/verification.json)에 기록한다. 실제 Metal 창의 [현장 스캔](media/ecology/native-scan.png), [연구·화물](media/ecology/research-cargo.png), [다른 행성 이식](media/ecology/transplanted.png), [960×640 기록 화면](media/ecology/journal-small.png)을 별도로 확인한다.

`test_ecology_workflow.gd`는 보너스 광물 없이 시작한다. 실제 굴착·메시/충돌 갱신과 로봇의 현장 왕복으로 총 9개를 생산하고 연구 3개·구획 6개를 소비한다. 출항→3D 항성계 이동/접근→선정 행성 착륙→표본 이식→저장을 검사한다. 자동화된 검사는 플레이어를 통제된 위치에 배치하고 비행 시간을 작은 단계로 진행한다. 사람이 실시간으로 전체 원정을 플레이한 검수와 구분한다.

아직 남은 연결:

- 나머지 391개 형태에 필요한 실제 수역·유영·비행·수관·열수·산성·결정 서식처. 적합한 매질 없이 마른 땅에 출력하지 않는다. 독립 리소섬 사례의 대사 열 모델도 별도다.
- 개체의 세계 이동 AI, 다리별 접지 IK, 먹이망 소비/번식, 공격 판정·피해, 장기 생태 안정성. 현재는 접지된 개체와 기존 상태 모션·기본 충돌을 제공한다.
- 격리실 내부의 실제 적재 연출·질량/부피·가스·전력·온도 회로, 단계별 연구 트리·시설·광물/유적/우주/문명 발견 통합. 현재 분석과 소형 대조 실험은 자원 소비 한 단계로 추상화한다.
- 생물량이 전체 행성 외형·매각 평가·사업 경제로 이어지는 연결. 현재 변화는 관리 시험 구획의 생물량과 생태 활성 상태다.
- 공동 지표의 관측·굴착·채집·표본/환경 동기화는 후속 [공동 지표 통합](12-shared-surface-and-ecology.md)에 연결했다. 단독 운반 로봇과 건설/사업 자동화의 공동 운영은 남아 있다.
- 다양한 지형·조명에서의 장시간 플레이, 대규모 성능, 실제 인터넷/Windows 검증 및 최종 경관 아트.
