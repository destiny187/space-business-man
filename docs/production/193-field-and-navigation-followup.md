# 현장 제작 분리와 항해, 스캔 후속 수정

2026-09-14 사용자 피드백 10항목과 후속 답변을 반영했다. 저장 실패 제보는 사용자가 발생 PC에서 분석하기로 했으므로 이번 조사와 수정 대상에서 제외한다. 해당 제보가 해결됐다는 기록이 아니다.

## 요청별 처리

| 번호 | 처리 |
| --- | --- |
| 1 | 성간 출발은 세제곱 거리 곡선으로 가속, 도착은 반대 곡선으로 감속한다. 새 이동은 정렬 포함 최소 18초다. 출발 직후 외부 카메라가 가까운 행성을 보여주고 도착은 목표 행성 중심을 바라본다. 진행률과 잔여 시간 대신 추정 속도를 표시한다. |
| 2 | F 행성 자동 접근의 목표 속도가 280m/s여서 일반 수동 비행의 700m/s에서 감속했다. 자동 접근도 기본 최고속 700m/s를 사용하도록 수정했다. 선체 성능, 부스트와 도착 제동은 유지한다. 부스트를 놓았을 때 부스트 최고속에서 일반 최고속으로 내려오는 동작은 유지한다. |
| 3 | 기본 장착된 채집기의 장착 안내를 생략한다. 광맥 스캔부터 시작하고 복원 안내 뒤 마지막 12단계에서 Lotus 보급 요청을 안내한다. 성공 요청을 공용 가이드에 기록한다. |
| 4 | 금속 가공 공장을 별도 설치형 건물로 추가했다. 선내 생산 거점은 운영 현장을 관리하는 메뉴이며 실제 가공은 현장 공장에서 한다. 혼동되던 요약 제목도 정리했다. |
| 5 | 게임 스크립트, 장면과 데이터의 중간점 구분자를 공백으로 바꾸고 AGENTS 및 FIELD v1에 재사용 금지를 명시했다. 역사 문서와 사용자의 저장 원본은 일괄 치환하지 않는다. |
| 6 | 이전의 I 휴대 장비 제작을 장비 제작대의 F 메뉴로 옮겼다. 기본 장비와 무기는 내 배낭 재료로 만들며 기존 소유품은 유지한다. 탄약의 기존 별도 제작 경로는 유지한다. |
| 7 | 초반의 작은 개량과 연구로 여는 T3 이상 전문 건물, 전력과 생태 효율의 상충 관계를 [별도 초안](../planning/20-special-discovery-and-facility-growth.md)에 정리했다. 새 고티어 외형과 패널티는 아직 구현하지 않았다. |
| 8 | 스캔 완료 결과가 입력 해제와 스냅샷 사이에 소실되는 경로를 보완했다. 화면 밖으로 돌아봐도 결과를 유지한다. 특수 도감, 현장 소리, 연구 후 장식과 효과는 위 별도 초안에만 정리했다. |
| 9 | 현장 차양과 접지 설비의 행성 티어 제한을 제거했다. 비용, 실제 지면 배치와 침수 등 시설 상태 판정은 유지한다. |
| 10 | 시야거리, 메시 LOD와 광물 생성 범위를 구분해 확인했다. 최대 설정의 원거리 지형 10km와 광물의 80m 타일, 반경 1칸, 3×3 타일 생성 범위는 별도다. 광물 모델은 로딩을 분산한다. 이번에는 스트리밍 범위나 성능 예산을 바꾸지 않았다. |

## 제작 건물

수치는 초기 구현값이며 장기 밸런스 확정값이 아니다. 단일 데이터 소관은 `data/field_manufacturing.json`이다.

| 건물 | 초기 건설 비용 | 운용 | 제작 대상 |
| --- | --- | --- | --- |
| 금속 가공 공장 | 철 45, 구리 20, 암석 30 | 전력 6kW, 현장 창고 | 정제 철, 정제 구리, 보강 프레임, 고합금 프레임 |
| 장비 제작대 | 철 15, 구리 8, 암석 10 | 무전력, 내 배낭 | 기존 장비와 무기 제작 설계도 |

B에서 직접 건설하고 F로 사용한다. 공장의 원료와 완성품에는 실제 현장 창고가 필요하다. 기존 연구와 재료 조건은 유지하며, 고합금 프레임은 기존 금속 가공 적성 현장 조건을 따른다. 다른 조립 부품과 로봇은 기존 현장 제작소를 쓴다. 금속 공장의 광석 가공에 현장 제작소 Mk.2를 별도로 요구하지 않는다.

기존 현장 제작소에서 이미 예약한 금속 제품은 끝까지 생산한다. 새 금속 생산 요청부터 금속 공장이 필요하다. 기존 장비와 슬롯, 로봇, 연구 이력을 제거하지 않는다. 새로운 건물은 기존 행성에도 플레이어가 직접 짓는다.

Blender 원본은 `art/blender/buildings/metalworks.blend`와 `equipment_workbench.blend`, 게임 모델은 같은 ID의 GLB다. 생성기는 `tools/build_field_manufacturing.py`이며 공통 산업 재질, 베벨과 정적 표면 병합을 재사용한다. 공장은 유도 가열로, 배기팬, 프레스, 롤러를, 제작대는 서랍, 도구걸이, 바이스, 조립 중인 도구를 갖춘다. 기존 ElevenLabs 제작 완료음과 공장 가동음을 연결했다. 신규 음악이나 특수 발견 소리는 만들지 않았다.

## 스캔과 공용 가이드

호스트는 완료 결과에 별도 일련번호를 붙여 입력 해제 뒤에도 6초간 발행한다. 영속 변경이 대기 중이면 성공 결과를 먼저 발행하지 않고 완료 확인 뒤 공개한다. 다음 스캔의 진행 중 표시는 새 대상을 우선한다. 사용자별 마지막 결과 하나만 보관하며 연결 종료 시 제거한다.

모든 지상 결과 종류에 대상 ID와 가능한 경우 위치를 전달한다. 위치가 없거나 뒤쪽 또는 화면 밖이면 고정된 화면 영역에서 이름, 설명, 용도와 J 조사 기록 안내를 보여준다. 아직 용도가 없는 대상을 구현된 효과가 있는 것처럼 설명하지 않는다.

가이드의 기존 `inventory` 기록은 호환용으로 보존하지만 장착을 요구하지 않는다. 이전 복원 완료 원정에도 보급 요청 단계가 표시된다. `supply_requested`는 실제 성공한 Lotus 요청에서만 공용 기록에 넣으며 클라이언트의 가이드 보고만으로는 완료하지 못한다. 먼저 성공한 보급 요청도 인정한다. 가이드 숨김과 편지 읽음은 개인 설정으로 유지한다.

## 텍스트 변경의 기존 원정 호환

일부 카탈로그는 설명문까지 버전 식별에 포함한다. 개발용 기존 원정에서 중간점 삭제만으로 생태와 사업 식별이 달라져 로드가 거부되는 문제를 확인했다. `content_text_identity.gd`와 `text_identity_compatibility.json`은 이번 문구 치환 전후의 정확한 해시 쌍에 한해서만 이전 식별을 보존한다. 일반 세계 지문 계산이나 변조 검증을 우회하지 않는다. 실제 가격, 콘텐츠 ID와 규칙이 달라지면 이 호환표에 일치하지 않는다. 원정과 은하 원본을 재작성하는 마이그레이션은 하지 않는다. 이 보완은 이번 텍스트 수정의 호환 범위이며 사용자가 별도 분석하기로 한 저장 실패 제보와 구분한다.

## 단일 행동의 처리 범위

장비 제작은 기존 개인 장비 거래 초안을 사용한다. 행동한 캐릭터와 배낭을 갱신하고 제작대는 같은 행성에서 거리와 상태만 조회한다. 닫힌 제작 화면은 상세 카드와 모델을 갱신하지 않는다.

금속 생산 요청은 해당 행성의 현장 초안만 복사하도록 좁혔다. 다른 행성, 생태 발견과 원본 은하는 읽기 전용으로 공유한다. 현장 내부는 기존 지역별 창고를 합치는 처리 때문에 현장 전체 복사를 유지한다. 실패한 요청은 발행된 재료와 예약을 바꾸지 않는다. 생산의 기존 호스트 확정, 저장 원자성과 중복 요청 방지는 유지한다.

스캔 표시 보완은 사용자별 마지막 결과만 복사해 발행하고 생물 모델이나 지형을 재생성하지 않는다. 스캔 기록과 Lotus 요청의 기존 세계 거래는 여전히 가변 상태 초안과 전체 무결성 검사를 사용한다. 이 잔여 비용을 이번 UI 보완에서 제거했다고 기록하지 않는다.

## 확인과 남은 범위

Blender Cycles 두 모델과 Godot Forward+ / Metal 두 모델의 INK 렌더 및 투명 건설 카드를 확인했다. 실제 행성에서 건설, 무기 제작, 가공 예약과 전력 가동, 완성품 출고, 스캔 결과와 가이드 표시를 확인했다. 좁은 규칙 검사 `check_field_followup.gd` 24항목이 통과했다. 장비 제작대 거리 검증, 금속 공장 분리와 출고, 스캔 확정 및 해제, 실제 보급 요청의 가이드 반영, 문구 호환과 변경된 가격의 식별, 생산 초안의 변경 범위를 확인했다. 실제 현장 검사 `check_field_manufacturing_play.gd` 31항목과 항해 검사 `check_followup_travel_play.gd` 13항목이 통과했다. 현장 검사는 기존 `check_field_research_play.gd`가 생성한 격리 원정을 복사해 사용한다. 960×640에서 전용 제작 메뉴, T1 차양 건설, 스캔 입력 해제와 뒤돌아보기, 마지막 보급 안내를 확인했다. 실제 사용자 저장은 이 실행의 입력으로 사용하지 않는다.
