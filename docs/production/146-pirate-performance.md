# 항해 전투 성능 조사와 반복 작업 제거

2026-09-12 사용자 요청: 최신 PC가 아니므로 보통 옵션에서 쾌적한 플레이를 우선한다. [전투 구현](144-pirate-missiles-and-breakout.md)의 모델·공격·폭발 품질을 유지하면서 현재 원정 전체를 측정했다. **반복 CPU 작업은 개선했지만 안정적인 60 FPS 달성으로 기록하지 않는다.**

## 발견과 적용

- 행성·위성·기업 활동을 포함한 기본 행성 정보를 항해와 매 발사체 충돌 검사마다 재생성하고 있었다. 세션에서 재귀적으로 읽기 전용으로 소유한 은하 원형에만 128개 행성 정의 캐시를 붙였다. 변경 가능한 입력은 기존 생성 경로를 유지한다. 편집용 `body()`는 독립 복사본을 반환하고 항해는 읽기 전용 정의를 사용한다. 공전 위치는 현재 시간으로 계속 계산한다.
- 호스트와 화면이 같은 읽기 전용 은하 원형을 사용할 수 있게 했다. 클라이언트는 수신 검증 후 자기 세션의 읽기 전용 사본을 소유한다. 저장 시 8,000종 원산지 전체를 다시 직렬화해 지문을 만들던 작업도 검증된 불변 원형의 지문을 재사용한다. 가변 데이터의 변조 검사는 생략하지 않는다.
- 같은 호스트 시각·항성계·예측 시간의 장애물 목록을 전투함과 여러 발사체가 공유한다. 다음 공전 시각이나 다른 항성계에는 다시 계산한다. 움직이는 천체·정거장·화물의 충돌 검사를 끄지 않는다.
- 전투 중 2초마다 하던 동기 전체 저장을 기존 단일 작업 스레드 체크포인트에 연결했다. 격파 등 결과 변화, 실제 성간 출발과 거래·정상 종료의 동기 저장은 유지한다. 제출 실패 또는 작업 완료 시 I/O 실패는 호스트에 전달한다. 결과 저장 때의 짧은 지연은 남는다.
- 폭발/미사일 꼬리용 메시와 재질을 공유하고 180개 자원을 비행 장면 준비 중 생성해 재사용한다. 수명·크기·색·분출 방향은 개별 인스턴스에 둔다. 선/충전 구체의 기본 메시도 공유한다. 기존 효과 상한·모양·분출 수량을 줄이지 않는다. 메뉴 진입 때 자원을 반환하고 숨긴다.

초기 세부 CPU 계측에서 14초 교전의 장애물 생성은 총 약 6.18초/698회, 전투 계산은 약 6.21초/91회였다. 공통 생성 캐시와 시각별 공유 이후 별도 세부 계측에서는 장애물 생성 약 1.07초/240회, 전투 계산 약 1.13초/120회였다. 실시간 진행과 프레임 수가 다르므로 이를 그대로 FPS 개선율로 환산하지 않는다. 전체 저장 약 126~145ms가 관찰됐고, 개선 후 주기 체크포인트의 메인 스레드 제출은 약 1.8~3.4ms였다. 결과를 확정하는 동기 저장은 별도이며 약 67ms도 관찰했다.

## 실시간 측정

Apple M2 / 메모리 24GB / Godot 4.7.2 / Metal Forward+, 현재 `crew_expedition.tscn`의 로컬 호스트다. 보통 옵션은 2× MSAA·SSAO·글로우·100% 렌더를 사용한다. FPS/VSync 제한을 해제했으나 macOS 표시 경로의 약 60Hz 간격이 남을 수 있다. 60 FPS 부근을 하드웨어의 최대 처리 속도로 해석하지 않는다. GPU 타이머의 0은 미측정 `null`이다.

항해 인덱스 준비와 3초 워밍업 뒤 대기 5초, 실제 세 함선 교전 14초, 동시 격파 4.5초를 측정했다. 프레임 시간은 실제 벽시계 간격이다. MovieMaker나 고정 60 FPS 영상을 성능 자료로 사용하지 않았다. 일반 UI·항성계 배경·민간선·호스트 계산·저장은 실행한다. 자동 조준 입력으로 두 무장을 사용하고, 계속 교전하도록 적 선체를 높이고 아군 실드를 보충한 부하 장면이다. 네 발의 미사일, 최대 180개 효과가 표시됐다. 자동 실행의 창 포커스 차단만 해제했다.

최종 공유 재질 코드의 대표 실행:

| 해상도 / 보통 100% | 대기 평균 | 교전 평균 | 교전 p95 | 세 함선 동시 격파 평균 |
| --- | ---: | ---: | ---: | ---: |
| 1280×800 | 60.1 FPS | 49.2 FPS | 38.1ms | 50.2 FPS |
| 1920×1080 | 35.1 FPS | 31.6 FPS | 53.7ms | 25.0 FPS |

[1280×800 원본](media/pirate-performance/medium-1280.json), [1920×1080 원본](media/pirate-performance/medium-1080.json). 1280 교전은 14초 중 33.3ms 초과 59프레임, 최대 79.8ms였고 동시 격파 최대 119.6ms였다. 따라서 평균만 보고 순간 끊김이 해결됐다고 하지 않는다. 앞선 자원 재사용 단계의 1280 교전 평균은 52.6~56.6 FPS, 동시 격파는 41.1~50.4 FPS로 변동했다. 공유 렌더·백그라운드 활동과 실시간 전투 진행이 달라 재질 변경만으로 평균 차이를 단정하지 않는다.

1080의 70% FSR 비교는 교전 39.3 FPS였다. FXAA 전환 실행은 더 큰 변동과 2초 이상 지연도 있어 성능 개선 설정으로 권장하지 않는다. 두 실행은 [업스케일 자료](media/pirate-performance/scaled-1080.json), [AA 전환 자료](media/pirate-performance/fxaa-1080.json)에 남긴다. 설정 전환 시 최초 렌더 준비와 공유 PC 부하를 완전히 분리한 A/B는 아니다. 조사 중 메모리 여유 약 48%·스왑 0으로 메모리 부족은 확인하지 못했다. 별 배경의 계산 생략 실험은 확실한 이득을 확인하지 못해 되돌렸다.

**이 PC에서는 보통 1280×800을 현재 출발점으로 삼는다.** 1080p 원본 해상도는 쾌적한 기준에 미달한다. 다음 성능 목표는 화면 전체 렌더 비용과 동시 격파의 긴 프레임을 줄이는 것이다. 사용자 개인 그래픽 설정 파일은 변경하지 않았다.

## 확인과 남은 경계

- `check_world_snapshot.gd`: **19개, 실패 0**. 캐시 전후 행성 정의·현재 공전 좌표 일치, 반환 결과 수정 격리, 가변 은하/원산지 변조 거부, 캐시 이탈 후 안전한 복사, 실제 체크포인트 독립성·거래 저장 실패를 확인했다.
- `check_pirate_performance.gd`: **9개, 실패 0**. 공전 시각/항성계/예측 시간/가변 원형에 따른 장애물 갱신, 주기 작업 경로, 격파의 동기 저장, 제출 실패 정지를 확인했다.
- `check_pirate_missiles.gd`: 최적화 이후 **26개, 실패 0**. 발사 궤적·충돌·저장·추격/재추격·실제 성간 출발 조건을 재확인했다.
- 성능 실행별 실제 미사일/효과 표시와 호스트 지속 **5개, 실패 0**. 좁은 장면 확인이며 전체 게임·다중 클라이언트·Windows·장시간 열 부하 검증은 아니다.
- `check_pirate_effect_reuse.gd`: **7개, 실패 0**. 실제 창에서 미사일 명중·세 함선 격파·공유 효과 재사용과 메뉴 회수를 확인했다. [미사일 명중](media/pirate-performance/missile-burst.png)과 [동시 격파](media/pirate-performance/three-ship-burst.png)에서 개별 분출·잔광·파편과 공통 상태 아이콘을 확인했다.

재현 명령의 `--crew-folder`는 전용 임시 저장만 사용한다. 플레이어 실제 저장 경로로 바꾸지 않는다.

```bash
./tools/godot.sh --script res://tests/measure_pirate_combat.gd -- \
  --crew-ui-test --crew-folder=/tmp/space-pirate-play --radio-preview \
  --measure-label=medium-1280 --capture-stills
# 1080p: --full-hd 추가. --write-movie / --fixed-fps는 사용하지 않는다.
```
