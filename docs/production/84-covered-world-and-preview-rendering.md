# 가려진 선내 렌더 중단과 정적 미리보기 재사용

2026-09-09 사용자 승인: 외부 비행 영상 뒤 선내 장면의 중복 렌더와 정지한 모델 미리보기의 매 프레임 렌더를 줄인다. [백그라운드 갱신 최적화](83-background-update-and-save.md)의 후속이다.

## 적용

- 실제 프레임을 그리기 직전에 외부 비행 영상의 표시·지상/전환 상태를 확인한다. 외부 영상이 화면을 덮는 동안 메인 뷰포트의 3D 패스를 중단한다. 우주와 UI 미리보기의 독립 SubViewport, 물리/호스트 진행은 유지한다.
- 선내 시점 복귀·외부 영상 숨김·원정 종료 때 메인 3D를 복구한다. 착륙/이륙 전환 중에는 지상 준비 렌더와 카메라 인계를 위해 중단하지 않는다.
- 공통 장비/시설/선체 미리보기는 `UPDATE_ONCE`로 렌더한 이미지를 재사용한다. 모델 교체/비우기, 드래그 회전, 카메라 위치·크기/투영 변경, 표시·크기 변경 때만 갱신한다. 숨긴 상태의 변경은 다음 표시까지 보류한다.
- 같은 선체의 장착 모듈 교체와 탐험복 색상 변경도 명시적으로 새 렌더를 요청한다. 재질/자식 모델 변경을 추가하는 후속 코드는 `request_render()`를 호출한다. 매 프레임 전체 메시/재질을 순회하지 않는다.
- 정거장 교역의 선체 미리보기도 선택 변경·다시 열기 때만 갱신한다. 연구/신체 증강의 실제 모션은 연속 렌더를 명시하며 숨기면 멈춘다. 움직이는 행성 미리보기의 셰이더 시간 표현은 유지한다.

## 실제 확인

Apple M2 / Godot 4.7.2 Metal Forward+, 1280×800, 격리 저장에서 확인했다.

- 같은 외부 시점에서 뒤쪽 메인 3D를 잠시 켠 대조는 메인 뷰포트 그리기 호출 **12회**, 중단 시 **0회**였다. 전체 우주 렌더나 게임 전체 드로콜이 0이라는 의미가 아니다. 우주 선체/배경과 UI는 화면에 유지됐다.
- `check_render_reuse.gd`: 외부/선내 전환·종료 복구, 전환 중 메인 렌더 허용, 정적 대기 중 재렌더 중단, 드래그·카메라·크기 변경, 숨김 중 교체/다시 표시, 빈 선택의 이전 이미지 제거, 연구 모션 지속/숨김 중단. 이미지 바이트 변화와 렌더 요청 상태를 포함한 15개 확인 실패 0. [로그](media/render-reuse/play.txt).
- `check_preview_details.gd`: 정거장 선체의 정지·교체 후 실제 이미지 변화·숨김/복귀와 동일 선체의 모듈 장착 변경 후 갱신. 7개 확인 실패 0. [로그](media/render-reuse/previews.txt).
- 구문 검사와 `git diff --check`를 확인했다. 외부 비행/선내 복귀 캡처를 직접 검수했다. 모델·음원·INK 품질 설정과 실제 사용자 저장은 변경하지 않았다.

이번 수치는 불필요한 렌더 제출 제거 확인이다. 전체 FPS·GPU 시간의 개선율은 측정하지 않았다. 착륙/이륙 전환의 렌더 허용 조건을 확인했으며 이번 턴에 전체 착륙 흐름을 재실행한 것은 아니다. 지형/건물 가림 최적화, 모든 미리보기 화면의 전수 검수, Windows·6인 검증은 포함하지 않았다.


## 2026-09-09 — 사용자 요청에 따른 같은 실행 내 성능 비교

`measure_render_reuse.gd`로 현재 `2c247058` 코드의 같은 장면에서 제거한 렌더만 다시 켜고 끄는 비교를 했다. 이전 체크아웃 전체와의 비교가 아니다. Apple M2 / Metal Forward+, 1280×800, 보통·100% 렌더, FPS/VSync 제한 해제, 격리된 우주 저장을 사용했다. 항성 인덱스 125,000개를 먼저 준비했다. 비교 중 권한 시뮬레이션과 우주 모션은 계속 실행된다.

장면마다 ‘불필요 렌더 켬 → 현재 최적화 → 현재 최적화 → 불필요 렌더 켬’ 순서로 360프레임씩 계측했다. 각 구간 앞 45프레임을 제외했으며 조건당 720프레임이다. 외부 비행은 뒤쪽 메인 3D만 토글했다. 조선소는 실제 K 메뉴의 589×405 선체 미리보기만 연속 렌더/이미지 재사용으로 전환하며 메인 3D 중단을 유지했다.

| 장면 | 불필요 렌더를 다시 켬 | 현재 최적화 | 전체 그리기 호출/프레임 |
| --- | ---: | ---: | ---: |
| 외부 비행 | 평균 50.17ms / 19.9 FPS | 평균 21.98ms / 45.5 FPS | 180 → 168 |
| 조선소 정적 선체 미리보기 | 평균 35.55ms / 28.1 FPS | 평균 28.82ms / 34.7 FPS | 249 → 212 |

평균은 같은 수의 프레임을 합친 프레임 시간이며 FPS는 그 역수다. 두 외부 비행 대조 구간 평균은 각각 36.51/63.83ms, 최적화 구간은 25.23/18.74ms였다. 조선소 대조는 35.70/35.41ms, 최적화는 25.89/31.76ms였다. **양쪽 비교에서 개선 방향은 일치하지만 편차가 크므로 일정한 개선율이나 안정적인 목표 FPS로 일반화하지 않는다.** 외부 비행 최적화 구간 최대 120.40ms, 조선소 최대 101.42ms의 순간 지연도 남았다. 지상 보행/굴착 성능은 이번 비교 대상이 아니다.

GPU 시간 API는 0을 반환하여 측정 불가로 처리했다. 정지한 미리보기의 개별 뷰포트 `target_draws`/`target_render_cpu_ms`는 마지막 렌더 값을 유지했다. 따라서 원본의 해당 필드를 현재 프레임의 실제 제출량/CPU 비용으로 해석하지 않는다. 실제 제출 감소는 **전체 렌더 카운터의 37회 차이**, 캐시 모드 복귀와 앞선 정적 렌더 중단 검사로 확인했다.

비교 후 선내 복귀, 미리보기 캐시 복귀, 원정 종료 시 메인 뷰포트 복구를 확인했고 이번 프로세스는 종료 코드 0으로 끝났다. 최종 스크린샷에서 우주 영상과 정비 화면의 모델·슬롯·텍스트 유지도 확인했다. [측정 원본](media/render-reuse/comparison/comparison.json), [실행 기록](media/render-reuse/comparison/run.txt), [정비 화면](media/render-reuse/comparison/shipyard-measured.png).
