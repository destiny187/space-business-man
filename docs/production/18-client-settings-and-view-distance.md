# 개인 설정과 원거리 지형 표시

2026-09-06 사용자 확정 요청: 시작·게임 중 설정에 쉽게 접근하고 그래픽 성능 옵션과 시야거리를 조절하며 Windows 테스트 ZIP을 다시 제공한다.

## 현재 구현

시작 화면과 원정 하단의 **설정**, **F10**으로 공통 설정 화면을 연다. Esc/F10/닫기로 돌아간다. 작은 창에서는 탭 내부가 스크롤되며 닫기·화면 복구 안내는 고정된다. 게임 입력·스캔은 설정 중 차단하지만 공동 세계와 산업·항해 시뮬레이션은 계속 진행한다. 혼자 시작·착륙 시 항해 패널 닫기는 유지한다.

| 탭 | 실제 적용하는 옵션 |
| --- | --- |
| 그래픽·시야거리 | 성능/균형/높음/사용자 설정, 원경 600~8,000m, 3D 렌더 배율 0.5~1.5, Bilinear/FSR 1.0와 선명화 감쇠, MSAA 끔/2/4/8×, FXAA, TAA, 모델 LOD 오차 1~8px |
| 그래픽·조명 | 태양 그림자 켜기, 1K/2K/4K 아틀라스, 40~500m 거리, Hard~Soft 최고 필터, 실내/손전등 그림자와 별도 아틀라스, SSAO/SSIL/SSR/Glow, 안개 강도 0~2 |
| 화면·성능 | 창/최대화/전체 화면, 창 해상도 5종, VSync, 무제한/30/60/90/120/144/240 FPS, FPS·프레임 시간 표시 |
| 조작·소리 | 시야각 60~100°, 감도, 세로 반전, 전체 음량 |

균형 기본은 원경 2,400m/100%/2×MSAA/태양 2K·180m다. 성능은 1,200m/75%/FXAA/1K·80m와 화면 후처리 해제, 높음은 4,800m/100%/4×MSAA/4K·300m와 후처리 활성화다. 원경 범위는 사각 링의 반경이며 카메라는 모서리가 잘리지 않도록 여유를 갖는다. 기존 우주 장면의 더 큰 카메라 범위는 보존한다.

UI 해상도는 3D 배율의 영향을 받지 않는다. 우주선 창의 별도 SubViewport, 새로 생성되는 조명·카메라·행성 환경도 개인 설정을 적용한다. 원래 그림자가 없는 장식 광원에 새 그림자를 추가하지 않는다. 지표의 매 프레임 안개 계산도 선택한 강도를 유지한다. INK 외곽선·단계 명암은 제거하지 않는다.

개인 `user://client_settings.json`에 적용 즉시 저장한다. 임시 파일 교체·백업, 수치 범위/자료형 검증, 손상된 주 파일의 백업 복구를 제공한다. 창 모드/해상도는 15초 안에 **화면 변경 유지**를 누를 때만 저장하며 미확인 상태는 이전 값으로 복구한다. 화면 해상도는 창 모드에만 적용한다. 기본값 복원은 화면 모드를 보존한다. 호스트 행성 매니페스트와 개인 장비·사업 저장은 수정하지 않는다.

## 지형 누락 수정

기존 원경은 서로 다른 높이의 정점을 연결한 삼각형 중간점으로 지형 밀도를 검사했다. 중간점이 계곡 위의 빈 공간에 있으면 동굴로 오인해 큰 지면을 삭제했다. 원경 링은 연결을 보존하며, 동굴 검사는 근접 링에서 실제 해당 좌표의 표면 높이를 기준으로 수행한다. 원경 범위를 선택한 거리에 맞게 확장하고, 로딩 중인 근거리 청크에는 임시 표면 타일을 표시한다. 실제 청크가 준비되면 임시 표면을 제거한다. 임시 타일은 충돌·굴착 권한을 갖지 않으며 동굴 진입부의 표면 구멍을 보존한다.

**범위 제한:** 시야거리는 원경 지형 표시 범위다. 모든 거리에 세밀한 복셀 충돌이나 생물 3D 모델을 생성한다는 뜻은 아니다. 굴착·생물 활성 범위는 기존 권한/시뮬레이션 규칙을 유지한다. 멀리서는 간략한 지형을 사용하며 최대 거리에서의 모든 GPU 성능을 보장하지 않는다. TAA는 움직임 잔상, FSR/낮은 배율은 작은 윤곽선의 선명도 변화가 있을 수 있다. 화면 반사·간접광은 해당 장면 재질과 화면에 보이는 정보에 따라 효과가 다르다.

## 검증

### 2026-09-07 시작 시 null root 오류 수정

일반 실행의 시작 장면 `_ready()`에서 루트에 공통 설정 노드를 즉시 추가하면, 루트가 자식 구성 중이어서 추가가 실패했다. 이어진 `apply_all()`의 `get_tree().root` 접근에서 null 오류가 발생했다. 시작 화면과 원정 장면의 설정 초기화를 지연 호출하여 루트의 장면 구성이 끝난 뒤 생성·적용하도록 수정했다.

`test_settings_startup.gd`를 Metal Forward+ 실제 창에서 실행해 시작 장면 초기화, 설정 버튼 열기, 설정 노드가 없는 원정 직접 진입을 확인했다. 오류 없이 통과했으며 로그는 `test-results/settings-startup/run.log`에 남긴다. 전체 게임·멀티플레이 회귀 검사는 수행하지 않았다.

### 기존 검증 기록

- `tools/test_solo_entry.sh`: 기존 실제 시작→항해→착륙→채집/사업→저장/재개 26개, 키보드 8개, 새 설정 30개 통과. Apple M2, Godot 4.7.2 Metal Forward+.
- 설정 30개는 실제 컨트롤 적용, 파일 재로드, 신규 SubViewport/광원/환경의 상속, FSR/TAA/아틀라스, 화면 모드 시간 초과 복구, 960×640, 지표 시야각·안개, 입력 차단, 600m/8,000m 실제 메시 범위, 원경 삼각형 보존, 임시 지면 생성/제거, 세계 매니페스트 불변성을 확인한다.
- `tools/test_expansion.sh`의 우주·지형·항해·사업·공학·생태 회귀 검사를 통과했다. 실제 ENet 호스트 1명+게스트 5명의 `tools/test_vessel_play.py --players 6`도 83개를 통과했다.
- Windows ZIP은 PE x64/PCK·GLB·음원·JSON·압축 무결성을 별도로 검사한다. Mac에서 Windows PCK를 읽는 검증과 Windows EXE의 실기 실행은 구분하며 Windows 실기는 미검증이다.

### 2026-09-07 홈·인터페이스 커서 유지 수정

사용자 확정: 홈과 조작 가능한 인터페이스가 열려 있으면 마우스 커서를 표시한다. 홈은 진입 시 한 번만 커서를 해제하던 처리를 보완해 메뉴·설정·팝업이 보이는 동안 표시 상태를 유지한다. 원정에서는 대기실·인사 편지·항해·인벤토리·사업·조선소·연구·설정뿐 아니라 장비 설명 같은 별도 Window 팝업도 마우스 캡처 차단 대상으로 포함한다. UI를 열 때 즉시 커서를 해제하고 시점 입력을 막으며, 팝업 중 이동·스캔도 차단한다. UI를 닫으면 기존 게임 시점 조작 조건으로 복귀한다.

`test_interface_cursor.gd`를 Metal Forward+ 실제 창에서 실행했다. 강제로 남긴 캡처 상태의 홈 진입·유지, 각 패널과 팝업·설정·대기 화면의 커서 표시 및 시점 차단, UI 종료 후 시점 조작 허용을 확인했다. 검사 실패와 스크립트 오류는 없었다. 기존 투명 SubViewport의 SSR 비지원 경고는 남으며 이번 수정 범위와 무관하다. 전체 플레이·멀티플레이 회귀 검사는 수행하지 않았다.
