# 자원 확장 UI/UX 개편 개발 계획

2026-09-08 사용자가 [조사 항목 U01~U13](../production/70-uiux-audit.md) 전체 개발을 승인했다. 범위가 많으면 나누어 개발한 뒤 다음 진행을 요청하는 방식도 승인했다. 이번 작업은 아래 3차로 나눈다.

## 확정 방향

- 쉽고 편한 인터페이스를 우선한다. 텍스트·탭·설명문을 계속 추가해 복잡성을 해결하지 않는다.
- **보유하지 않은 아이템은 0개 카드로 표시하지 않는다.** 보유 목록·화물·장치 투입 후보에서 숨긴다. 빈 실제 장착/드롭 슬롯, 제작 필요 재료, 발견 도감은 서로 다른 의미로 취급한다. 필요 재료가 없으면 ‘부족’을 표시하고, 이미 발견한 지식은 소지품이 사라져도 보존한다.
- 호스트 거래·개인 소유·실물 운송·제작 거리·연구 해금 조건을 유지한다. 선택과 조회는 재화를 소비하지 않는다.

## UX03 구현 계획 — 2026-09-09

사용자가 3차 개발을 요청했다. 기존 U07/U13 계획은 유지하고 아래 배치를 구현 기준으로 보완한다. 아래는 개발 전에 보완한 계획이며 [실제 구현·검증 기록](../production/73-growth-refit-and-market.md)과 구분한다.

1. **성장 동선**: I는 소유 장비·장착/휴대 제작·개인 능력 열람, J는 발견/공동 연구 기록으로 정리한다. 기존 보석 증강과 개인 장비·탐험복·채집/수납·운송 개조는 실제 증강 장치에서, 공동 설비 성능과 생태 작업은 실제 연구대에서 실행한다. 표본 연구대의 기존 보석 분석은 유지한다. 개조 비용·소유권·단계·기존 저장을 보존하며 지상에서만 가능했던 작업을 선내에서도 가능하도록 확장하지 않는다. UI와 호스트 모두 해당 장치 거리/공간을 확인한다. 기록 화면은 작업 장소로 안내하며 원격 구매하지 않는다.
2. **선박 정비**: 현재 선체와 실제 부착 모듈을 INK 미리보기로 보여 준다. 추진/공용 슬롯을 선체 위치에 연결하고 선택 슬롯에 맞는 보유 모듈/제작 설계를 고른다. 같은 슬롯을 교체할 때의 질량·전력·항속/접근·연구·격납고 변화를 실제 계산으로 비교한다. 제작·추첨·개량 비용과 추첨 확률/확정 횟수를 유지하고 분해는 구체적인 반환 부품을 확인한다. 호스트 결과 이후에만 장착 상태를 바꾼다.
3. **교역**: 물자 이름 검색·종류·내가 판매할 수 있는 품목 필터를 추가한다. 판매 가능한 개인 품목과 상점 판매 재고를 구분하고 양쪽 모두 없는 항목은 숨긴다. 선체 이름도 검색하며 단가·수량·총액·매입/매도 방향을 고정 상세에 둔다. 기존 거래 거리/호스트 자금 권한과 실제 개인 가방 출처를 유지한다.

최소 확인은 별도 저장 복사본으로 변경 화면/핵심 거래와 960×640 배치에 한정한다. 실제 게임의 기존 Blender 자산·INK 렌더·피드백을 재사용한다. 전체 회귀·6인 접속·장시간 검증은 관행적으로 추가하지 않는다.
