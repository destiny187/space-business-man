# 활동형 현장 미션 — 승인 범위와 최초 기획

2026-09-14 **후속 사용자 개발 승인**: 절벽 중계망 복구는 T2·T3에서만 등장한다. 나머지 여섯 미션은 최초 등장 티어부터 T5까지 난이도를 높여 구현한다. 아래 초안의 “구현 승인 아님”과 후속 미션 보류는 당시 상태이며 이번 승인이 우선한다. 실제 연결·초기 수치·원정 확인과 남은 경계는 [185 제작 기록](../production/185-active-field-missions.md)을 따른다.

2026-09-14 사용자는 다른 작업을 하는 동안 게임에 포함할 더 활동적인 미션을 기획해 달라고 요청했다. **이번 결과는 기획이며 구현 승인이 아니다.** 아래 종류·순서·소요 시간·보상·운영 규칙은 설계 제안이다. 시간은 목표 체감이며 실측값이 아니다.

사건 규칙의 소관은 [사건형 탐험](../game/21-exploration-incidents.md), 전투 경계는 [지상·비행 전투](../game/27-ground-and-flight-combat.md)다. 이 문서는 새로운 행동과 제작 우선순위만 구체화한다.

## 원하는 경험

**공장을 돌려 놓고, 근처 신호를 따라 짧게 출동하고, 직접 움직여 얻은 부품으로 생산과 탐험을 발전시킨다.** 자동화 전에도 선택할 수 있으며, 공장을 일부러 느리게 만들어 미션 시간을 확보하지 않는다. 전투·수직 이동·운반·기계 조작을 섞어 각 미션의 손맛을 구분한다.

예를 들어 합금 생산을 시작한 뒤 절벽의 끊어진 중계기를 발견한다. 제트팩으로 발판을 옮겨 다니며 안테나를 복구하고, 마지막 신호로 가까운 자원 위치를 알아낸다. 기지에 돌아와 생산된 합금과 회수한 부품을 다음 설비에 사용한다. 미션 실패가 생산 실패로 이어지지는 않는다.

| 길이 제안 | 역할 | 시작 방식 |
| --- | --- | --- |
| 3~6분 | 작업 사이 짧은 출동 | 현장의 소리·움직임·신호를 발견하고 직접 진입 |
| 8~12분 | 장비를 챙기는 소규모 원정 | 발견한 현장을 기록해 두고 준비 후 재방문 |
| 15~25분 | 우주와 지상을 연결하는 큰 사건 | 여러 단계의 출동을 선택하며 중간 성과를 저장 |

## 기존 기반과 새로 필요한 것

제작 기록상 신호 추적·지진 공동·이동 화물 드론·운반은 [99](../production/99-exploration-incidents-t2.md), 생물 추적/관찰은 [104](../production/104-native-biological-incidents.md), 기업의 인양·정비·지상 단서는 [121](../production/121-corporate-presence-completion.md)에 연결 범위가 있다. 폭풍 기록고와 T3 설계도는 [128 O08A](../production/128-performance-and-content-commits.md)에 기록되어 있다. 이를 이름만 바꿔 신규 미션으로 세지 않는다.

로봇 분대는 [167](../production/167-coopertech-squads.md), 비행 생물 교전과 제트팩은 [178](../production/178-flying-wildlife-and-jetpack.md), 해적 편대/탈출은 [144](../production/144-pirate-missiles-and-breakout.md)에 구현 기록이 있다. 아래의 수송대·연쇄 중계·이동 채굴·미끼 유도·구조 호위 목표는 별도 개발이 필요하다. 이번에는 코드나 게임을 실행해 연결을 재검증하지 않았다.

## 첫 세 미션의 구체적 흐름

### 1. 절벽 중계망 복구 — 이동 자체가 보상이 되는 짧은 미션

**발견:** 절벽 위 안테나의 끊기는 신호와 옆면 상태등이 보인다. 지상 중계기에서 경로와 보상을 확인한다. 이 확인만으로 타이머나 적을 발생시키지 않는다.

**진행:** 아래·중간·정상의 세 중계기를 직접 연결한다. 중간 발판에서 착지해 추진 잔량을 회복하고, 안테나를 회전시켜 다음 수신부와 시야를 맞춘다. 각 연결 성공은 접시 방향·상태등·신호음으로 보인다. 순서는 시야 연결에 따른 것이며 버튼 누르기 반응속도 시험으로 만들지 않는다.

**판단:** 짧은 공중 횡단과 넓은 착지점의 우회로 중 고른다. 기본형에는 시간제한과 적을 넣지 않는다. 이후 현지 비행종이 있는 경우에만 영역을 피해 돌아가는 변형을 제안한다. 정상에서 마지막 통신이 연결되면 아래 계곡의 실제 미관측 자원 후보 한 곳을 거친 범위로 공개한다. 유효한 후보가 없으면 생성 전에 다른 보상으로 고정한다.

**성공·중단:** 세 중계 연결로 완료한다. 마지막 착지점에서 내려올 경로도 확보하며, 떨어져도 이미 연결한 중계는 유지한다. 제트팩 미보유 상태에서는 필요한 장비를 알리고 현장을 기록할 수 있다. 건설로 닿는 것은 유효한 해결법이다. 보상은 원격 획득 가능한 부품/정보로 정해 운반 중 제트팩 허용 여부에 의존하지 않는다.

**필요 개발:** 안테나 회전과 가시선 판정, 중계별 저장, 발판 배치와 착지/귀환 경로 검증. 현행 제트팩의 초기 8초 추진·착지 회복을 기준으로 여유 있게 배치하되 실제 중력·장비 성능으로 도달성을 검사한다. 기존 추진 성능을 미션에 맞춰 낮추지 않는다.

### 2. 폭주 수송대 저지 — 뒤쫓기보다 앞질러 가로막기

**발견:** 버려진 쿠퍼테크 시험 구역의 수송기가 짧은 회로를 반복 주행하고 호위 로봇이 따라간다. 관측하면 굽이와 잠시 감속하는 지점을 알 수 있다. 일반 기업 무역선을 공격 대상으로 전환하지 않는다.

**진행:** 플레이어가 실제 차단 장치에 개입하거나 공격하면 교전이 시작된다. 수송기 측면 구동부를 손상시켜 정지시키거나, 앞쪽 경로의 현장 차단기를 먼저 내려 세울 수 있다. 호위는 수송기와 떨어질 수 있으며 적을 모두 처치하지 않아도 화물 접근이 가능하다. 수송기가 멈추면 다시 무한 재출발하지 않는다.

**판단:** 탁 트인 곳에서 사격해 빠르게 멈추거나, 엄폐가 많은 굽이에서 차단해 회수를 편하게 한다. 화물을 꺼낸 뒤에는 내려놓고 싸우거나 동료에게 넘기며 안전한 인계 지점까지 운반한다. 운반·사격의 현행 제약은 먼저 확인하고, 이를 우회하는 새 동시 조작을 전제하지 않는다.

**성공·중단:** 정지·화물 분리·인계 상태를 각각 저장하고 실제 인계 때 한 번 지급한다. 놓친 수송기는 다음 회로에 다시 접근할 수 있어 초반에는 제한시간이 없다. 플레이어가 먼저 사격해도 정상 개입으로 인정하며, 기록창 수락 순서를 강제하지 않는다. 후퇴하면 적은 사건 구역으로 돌아가며 기지를 추격하지 않는다.

**필요 개발:** 수송기 경로/정지 동작, 구동부 판정, 호위의 이동 목표, 국소 차단 장치와 회수 위치. 기존 드론 메시의 이름만 바꾸지 않고 차대·적재함·구동부가 읽히는 Blender 자산이 필요하다. 일반 생물이나 로봇 이동속도를 추격 난이도 때문에 낮추지 않는다.

### 3. 쿠퍼테크 재가동 시설 침투 — 싸움의 목표를 바꾸기

**발견:** 폐쇄 시설에 전원이 들어오고 실제 순찰 기체와 두 전력선이 보인다. 내부 코어와 출구를 밖에서 관측할 수 있어 진입 전에 경로를 고른다.

**진행:** 외부 전원 두 곳을 차단하면 화물 격실이 열린다. 적은 시설 주위를 순찰하며, 플레이어는 직접 만든 엄폐물을 이용하거나 돌아가 사선을 끊는다. 전원 차단은 격실/관측 장치에 영향을 주고 현장 로봇 전체를 일괄 삭제하지 않는다. 코어를 꺼내 실제 인계 지점까지 운반한다.

**판단:** 전원을 차단하며 안전한 경로를 만들지, 먼저 위협적인 기체를 처리할지 결정한다. 1인은 전원 차단과 운반을 순차 수행할 수 있다. 협동에서는 차단·엄호·운반을 나눌 수 있지만 동시 스위치나 고정 역할은 필수가 아니다.

**성공·중단:** 코어 인계로 기본 보상을 지급한다. 전멸·무피해·속도 목표는 완료 필수 조건으로 삼지 않는다. 실패해도 차단한 전원과 이미 회수한 물건을 보존한다. 코어를 바닥에 두고 떠나면 위치를 기록해 재개하며 지형 밖으로 유실된 경우 가까운 유효 지점으로 복구한다.

**필요 개발:** 전원별 상태와 격실 연결, 유한 순찰 배치, 운반 코어와 유실 복구. 최초에는 고정된 유한 적만 두며 무한 증원/시간 버티기는 추가하지 않는다. 시설 개방을 F 한 번의 전투 승리 처리로 대체하지 않는다.

## 발견·보상·협동 운영 제안

- 미션은 신호·실물·이동을 보고 발견한다. 기록한 현장은 기존 J 사건 기록과 Tab 지도로 다시 찾는다. 별도의 일일 숙제 게시판이나 상시 팝업은 첫 범위에 필요하지 않다.
- 기본 진행에는 시간제한을 두지 않는다. 긴급 변형은 위험과 실패 영향을 먼저 보여 주고 명시적인 현장 개입 이후 시작한다. 동시 위험은 활성 현장당 하나로 제한하고 해당 구역의 일반 날씨 추가 피해 억제 규칙을 재사용한다.
- 무시해도 생산과 복원 계약은 정상 진행한다. 미션 실패로 무관한 기지·창고를 파괴하지 않는다. 배치 후보는 기존 시설·착륙 안전 구역·200m 기반암·탐사 경계와 겹치지 않아야 한다.
- 재료·장비는 실제 회수하고 Cr는 인계로 정산한다. Cr는 공동 자산, 물건은 현행 소유권/운반 거래를 따른다. 참여 인원만큼 화물을 복제하지 않는다. 보상 범위는 시작 전에 보여 주고 이미 확정된 보상을 재접속으로 재추첨하지 않는다.
- 미션 보상은 제작 시간을 조금 줄이거나 특정 부품을 보완한다. 필수 기술이나 항해 접근권을 활동형 미션 전용으로 잠그지 않는다. T3 설계도 보상이 필요하면 기존 풀/중복 처리와 연동하고 신규 설계 체계를 만들지 않는다.
- 1~6인 모두 순차 완수가 가능해야 한다. 적/목표 구성은 개입 시 참여 인원을 기준으로 고정하고 중도 합류로 체력이나 보상을 재설정하지 않는다. 늦게 합류한 승무원도 같은 상태의 현장을 돕는다. 참여 인원 판정은 현장 거리와 실제 개입을 기준으로 후속 구현에서 정의한다.
- 짧은 미션은 단계 전환마다 재개점을 남긴다. 호스트 종료 시 사건 시각을 보존하며 오프라인 시간 때문에 실패시키지 않는다. 세계가 계속 돌아가는 협동 세션에서는 개인 메뉴나 이탈로 적·타이머를 멈추지 않는다. 운반자 이탈은 현행 화물 회수 규칙과 일치시킨다.
- 동일 현장의 완료 보상은 한 번이다. 반복 경험은 다른 미방문 현장에서 경로·엄폐·목표 순서의 차이로 만든다. 무생물 행성에는 생물 미션을 배치하지 않고, 비행종도 실제 현지 원산종만 사용한다.
- 수송선 구조는 기존 전투 초안의 확장 후보다. 첫 후속안은 우주 교전 후 별도 착륙 단계로 구성하며 대기권 공중전·독립 전투정·FINCH 무장·인간 적·수중 전투를 전제하지 않는다.

## 구현으로 넘어갈 때의 범위

첫 단계는 중계망 한 현장을 완성해 발견→접근→상태 변화→보상→재방문까지 잇는 것이다. 이후 수송대, 시설 침투를 각각 별도 단계로 추가한다. 미션 종류 수보다 다른 행동을 실제로 하는지 먼저 확인한다. 현재 변경은 문서뿐이며 아래 항목은 수행 예정 기준이다.

| 항목 | 필요한 최소 확인 |
| --- | --- |
| 실제 플레이 | 해당 미션 한 종류의 핵심 경로, 중단/재개 및 그 미션의 대안 경로만 확인. 넓은 회귀·반복 실행은 관행적으로 추가하지 않음 |
| 미션 간 차이 | 중계망은 착지점 선택, 수송대는 앞지르기, 침투는 차단/운반 경로 선택이 실제 성패를 바꾸는지 확인 |
| 아트·음향 | Blender 원본/내보내기·Godot Forward+ INK 렌더, 준비/진행/성공/실패의 동작·ElevenLabs 소리 확인. 신규/재사용을 구분 |
| UI | FIELD v1의 실제 대상·짧은 상태·보상 카드, 작은 화면에서 스캔 결과 우선과 메뉴 입력 차단 확인 |
| 저장·협동 | 해당 목표의 호스트 판정과 보상 원자성, 중복 회수 거부, 운반자 이탈·재개 상태를 가장 작은 관련 경로로 확인 |
| 행동 범위 | 중계기 회전/수송기 정지/전원 차단 한 번의 입력→대상 변경→복사·검증·저장→발행→UI·모델 갱신 추적. 실패/중복과 닫힌 기록창 포함 |

미션별 상태는 독립 시드와 인스턴스 ID로 생성해 기존 사건 난수열·보상을 보존한다. 도메인 변경과 전송/표시 갱신은 해당 사건·목표·참여자에 한정한다. 기존 전체 저장 검증/직렬화 비용까지 사라졌다고 가정하지 않고 실제 필요한 전체 처리와 남은 비용을 기록한다. 기존 저장에는 완료 현장을 재배치하지 않으며, 새 미션의 추가 배치는 버전으로 구분하고 최초에는 아직 생성되지 않은 현장을 대상으로 제안한다.

구현 단계에서 확정할 항목은 보상 수량·인원별 적 구성·도달 가능한 발판 간격·현장 생성 빈도다. 이번 작업은 세부 미션 개발이나 신규 자산 제작, 게임 실행 검사를 포함하지 않는다.
