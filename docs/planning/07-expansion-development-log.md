# 탐험 확장 개발 기록

2026-09-06 사용자가 설계 커밋 후 전체 고도화의 순차 개발을 요청했다. [고도화 계획](06-exploration-expansion-roadmap.md)의 인수 조건을 따른다. 부분 구현은 E0~E5 전체 완료가 아니다. 추가 렌더링은 사용자가 재확인한 [INK v1](../production/06-rendering-quality-standard.md)을 반드시 유지한다. 수상 수준의 완성도는 목표이며 수상·출시 준비 완료를 의미하지 않는다.

## 기준 커밋

- `1d8c091`: 기존 카툰 작업이 완료된 뒤 공통 INK v1 렌더링·필수 자산 재렌더를 보존.
- `eb316f1`: 탐험·단일 은하·티어/시드·발견 연구·문명·호스트 포함 6인 설계를 커밋.
- `e3f5540`: 사용자 수정인 100만 주소와 실제 3D 우주선 이동을 반영.

## 사용자 수정 — 현재 기준

사용자는 초기 성도 중심 실증 화면이 의도와 다르다고 명확히 했다. **주 경험은 우주선을 타고 이동하는 3D 우주 탐험**이며, 목적지를 선택하는 방식도 실제 3D 천체와 우주선 이동으로 표현한다. 성도와 목록은 보조 도구다. 이어서 시드당 행성 목표를 1억 개에서 **100만 개**로 줄였다. 1억 개와 초기 120개 후보 화면은 폐기된 중간안이다.

## E0-A — 100만 주소와 3D 항해 실증

구현: [은하 생성기](../../우주-비즈니스/scripts/domain/universe.gd), [탐험 저장](../../우주-비즈니스/scripts/persistence/world_store.gd), [3D 항해](../../우주-비즈니스/scripts/app/space_flight.gd).

- 한 은하에 논리 행성 1,000,000개, 항성계 250,000개, 성역 50개. 항성계당 4개 행성이다. [생성·비행 설정](../../우주-비즈니스/data/galaxy.json)에 수량·티어 분포·비행 수치를 둔다.
- 세계 원형에 전체 목록을 저장하지 않는다. 행성 번호 1~1,000,000 또는 고정 ID에서 필요한 천체를 즉시 생성한다. 같은 은하 시드·고정 생성 버전이면 같은 후보를 재현한다. 관측·변경 기록만 누적한다.
- 5개 권역에서 중심 방향의 티어 분포가 상승한다. 지형·자원·발견·생태·문명·티어는 SHA-256 파생 스트림으로 분리한다. 실제 착륙 지형과 생물 배치는 아직 후속 작업이다.
- 3D 현장에는 현재 항성계의 천체 4개와 실제 원정선 모델을 만든다. 추진·선회·기수 조절·제동·시점 전환, 천체 조준, 자동 접근, 먼 항성계 도약 후 접근을 연결했다. 궤도 접근 완료 때 조사 기록을 남긴다.
- 별도 저장 `exploration_world.json`에 원형 설정·관측 카탈로그·조사 기록·항해 위치·목표를 보존한다. 기존 `campaign.json`을 읽거나 변환하지 않는다. 손상·이전 형식 원본도 덮어쓰기 전에 별도 보존한다.

### 실제 자료와 표현의 한계

NASA PS의 TRAPPIST-1 d/e/f 기본 문헌 해 3개를 실제 취득했다. [카탈로그](../../우주-비즈니스/data/astronomy/nasa-ps-20260906/catalog.json)에 원본 해시·조회문·취득일·출처·단위·오차·한계·결측을 보관하고 원본과 스키마도 동봉했다. 런타임 천문 API 연결은 필요 없다.

이 실제 천체는 관측 자료 보기에서 구분한다. 현재 항해 공간의 천체·축척·배치·대기는 **가상**이다. 실제 관측에 맞춘 천체의 착륙 지형·기후 통합은 아직 구현하지 않았다. 평형 온도를 지표 실측 온도로 표시하지 않으며 지표 지도·생명 존재는 미확인으로 둔다.

100만 개는 선택 가능한 **논리 주소 수**다. 서로 다른 100만 종의 아트나 발견을 제작했다는 뜻이 아니다. 현재 3종 환경의 절차적 궤도 표현이며 발견·지질·생태의 다양성은 E2~E5에서 별도로 검증한다.

### 우주선과 렌더링

[KESTREL Blender 원본](../../art/blender/ships/kestrel.blend)과 GLB를 만들었다. 편집 가능한 압력 선체·곡면 장갑·전면 유리·외부 화물실·엔진·노즐·센서·출입 해치 구조를 보존한다. 출력은 59,904삼각형이며 재질별 병합으로 드로콜을 줄인다. 공통 INK v1과 [실제 도감 렌더](../production/media/ink-catalog/kestrel.png), 실제 항해 화면을 검수한다. 선내 공간·승무원·6인 탑승 시뮬레이션은 아직 연결하지 않았다.

원거리 항해에서도 화면 윤곽 패스가 카메라 근처에 유지되도록 선체에 연결한다. 지면용 조명 설정을 우주로 무조건 복제하지 않고 승인된 명암·윤곽·형상 기준을 실제 비행 화면에서 확인한다.

## 실행·검증

- 실행: 시작 화면의 **우주 탐험** 또는 `./tools/show_exploration.sh`. W/S 추진, A/D 선회, 위/아래 기수, Shift 가속, Space 제동, C 시점, F 자동 항해, Tab 패널, F5 저장.
- `./tools/test_expansion.sh --with-ui`: 천문 원본 해시·정규화, 주소의 처음·끝·권역 경계, 같은 시드, 10개 시드에 걸친 5,000개 후보, 저장 크기·복구, 실제 3D 이동·접근·도약·마지막 주소·4개 천체 유지와 저장.
- 100만 개 설정의 권역별 표본 평균 티어: **1.138 / 2.000 / 2.982 / 3.984 / 4.856**. 개별 천체의 단조 증가를 보장하는 결과가 아니다.
- 초기 기록 JSON은 약 **6.8 KB**다. 표본 5,000개 생성과 저장·검사까지 최근 검사에서 약 1.32초로 측정됐다. 이는 개별 생성 지연·전체 게임 FPS·방문이 누적된 세이브 성능의 보장값이 아니다.
- 실제 Metal 창에서 `test-results/space-flight/`에 출발·궤도·도약·먼 항성계·축소 화면을 촬영한다. 테스트 입력과 사람이 실시간으로 장기 플레이한 결과는 구분한다.
- M2·1280×800·240프레임 항해 측정: 평균 **16.67ms**, p95 **16.97ms**, 정적 메모리 **122.55MiB**, **62 드로콜**. 우주선 한 대·천체 네 개의 짧은 로컬 측정이며 GPU 전체 메모리·지표·6인 협동 성능을 뜻하지 않는다. `test-results/space-flight/benchmark.json`에 조건을 기록한다.
- 기존 1.2의 기본 게임 회귀 검사를 통과했다. 새 아트는 공통 렌더 계약 검사에도 포함한다.

## E0-B — 착륙·지표·굴착의 기능 실증

[지표 장면](../../우주-비즈니스/scripts/app/planet_exploration.gd)과 [지형 설정](../../우주-비즈니스/data/terrain.json)을 추가했다. 궤도에 접근한 뒤 항법 패널에서 착륙하면 같은 행성 ID의 지표로 전환한다. 지표에서는 WASD·마우스로 이동하고 클릭으로 가까운 지층을 굴착한다. 우주선 근처에서 Esc → 우주선 출항으로 항해 공간에 돌아간다. 대기권 강하·선내 출입 애니메이션까지 연결한 단계는 아니다.

- 근거리 2m 밀도 격자와 24m 청크, 원거리 높이 지형을 결합했다. 현장 주변 최대 75개 청크를 요청하며 백그라운드 작업은 기본 2개로 제한한다. 활성 청크 수는 행성 주소 100만 개와 무관하다.
- 지표 형상은 행성의 고정 지형 스트림으로 재현한다. 현재 동굴은 약 100m 통로와 지하 공간을 잇는 **고정 실증 배치**다. 시드별 다양한 동굴망을 완성한 것으로 취급하지 않는다. 지표 골짜기가 통로 바닥을 잘라 급경사를 만드는 문제를 발견해 동굴 위 암반을 보장했다.
- 작업 스레드는 CPU 메시 배열을 만들고 주 스레드에서 표시 메시와 동일 삼각형의 충돌을 설치한다. 굴착은 관련 청크를 모두 준비한 후 한 프레임에 교체한다. 오래된 작업 결과는 버전으로 폐기하고 장면 종료 시 모든 작업을 회수한다.
- 저장에는 지형 생성 설정·해시·행성별 굴착 구·현장 위치를 보관한다. 재실행 시 지하 위치를 복구한다. 잘못된 굴착, 미지원 생성 버전, 현장 범위 밖 위치를 저장 검증에서 거부한다.
- 관심 지점 6개가 겹치면 75개, 충분히 떨어지면 450개 청크 주소를 요청하는 검사를 했다. **네트워크 접속이나 6인 프레임률을 검증한 것은 아니다.**

검증: 지형 규칙 **20개**, 실제 Metal 창의 착륙·지하 보행·굴착·저장·장면 재로드·도보 귀환·출항 **22개**가 실패 0건이다. 검사에서는 약 20m 깊이에 도달하고 구조 기능 없이 지표로 걸어 돌아왔다. [착륙 화면](../production/media/surface/landing.png)과 [굴착 화면](../production/media/surface/excavation.png)은 기능 실증의 실제 출력이다.

공통 INK 조명에서 점·스포트 광원의 거리 감쇠가 방향광 그림자 경계처럼 잘리던 오류를 수정했다. 방향광 수식과 3단 각도 명암·윤곽 경로는 유지한다. 별도 GPU 검사 **3개**에서 3m/12m/소등의 밝기 차이를 확인한다. 기존 게임 규칙·저장·온보딩·음향 회귀 검사와 두 카메라의 INK GPU 검사 **7개**도 통과했다. GPU 회귀 캡처는 별도 출력 경로로 보내 진행 중인 생물 작업의 문서 이미지를 덮어쓰지 않는다.

**시각 제작과 E0-B 전체 인수는 아직 미완료다.** 현재 지형은 굴착·왕복 검증용으로, 자연스러운 암벽 조형·원거리 경계와 세부 선·지질 배치·탐사 도구·화면 구성의 추가 제작이 필요하다. 이 화면을 승인 기준작 수준의 최종 지형 또는 GOTY 수준의 완성도로 기록하지 않는다. 로봇의 지하 운반, 여러 지형 방식의 비용 비교와 대표 혼합 장면 성능도 남아 있다. 공통 셰이더 적용과 자동 검사 통과만으로 아트 품질을 승인하지 않는다.

## 최종 설계 대조와 E0-B 물류 연결

사용자의 전체 개발 지시에 따라 [최종 설계 대조표](08-expansion-execution-matrix.md)를 만들고 X-01~X-16, 아트·음향·저장·성능·플랫폼 조건을 연결했다. 현재 인수 상태와 다음 의존 단계를 구분한다.

[지하 운반 로봇](../production/09-courier-and-surface-logistics.md)을 연결했다. 실제 지형을 검사한 경로로 왕복하며 굴착 채집물 적재·운반 중 저장/재로드·하역을 수행한다. 물류 규칙 17개와 실제 운반 19개를 통과했다. 여섯 바퀴가 독립 회전하는 Blender 출력과 공통 INK 렌더를 함께 보관했다. 지형 아트·경계·전체 비용 비교와 충전/다중 로봇 정책은 남아 있다.

## 이어서 진행할 순서

1. **E0-B 잔여:** 지형 아트·원거리 경계 보강, 생성 방식 비용 비교, 충전·시설 장애물·다중 로봇 통합과 성능 측정.
2. **E0-C:** 호스트 권한·개인 프로필 분리·최대 6인·선내 이동·동시 명령·종료/재접속.
3. **E1:** 공동 항해에서 실제 착륙·무료 개발 등록·채집·자동화로 연결하고 구매 입문 흐름 전환.
4. **E2~E4:** 발견 연구·표본 운송/이식·선체 개발/추첨·사건·문명·계약 정산.
5. **E5:** 다른 원정의 재미, 전체 아트 형상·음향·입력·성능·실제 온라인·플랫폼 검증.

E0-B와 E0-C가 통과하기 전 E1 완료를 선언하지 않는다. Windows 실기와 서로 다른 인터넷 회선의 6인 검증은 해당 환경에서 측정한 근거가 필요하다.

## E0-C 실제 6인 접속·선내·항해

[공동 원정 실증](../production/10-crew-cabin-and-playtest.md)에 ENet·별도 개인 장비 프로필·호스트 거래·재접속 자리·3D 선내·승무원 이동·전원 준비·조종 권한·100만 번째 행성 공동 도착을 연결했다. 호스트 규칙 45개, 항해/프로필 23개, 실제 접속 26개, 실제 게임 장면 33개, 작은 화면 6개를 통과했다. Blender 원본과 게임 캡처를 남겼다. 기존 사업·단독 탐험 저장과 분리한다. 공동 지표 분업과 실제 인터넷/Windows 실기는 미완료이며 E0-C 전체 통과로 표시하지 않는다.

## E2/E3 생명체 완성 자산의 단독 탐험 선행 연결

사용자가 생물 모델 완성을 알리고 누락 작업의 진행을 요청해 [행성 생태 통합](../production/11-seeded-ecology-integration.md)을 추가했다. 도감 재제작 없이 시드별 계통과 실제 지형의 배치를 연결하며 스캔→재료 소비 분석→고유 표본 운송→관리 구획 이식까지 이어진다. 현 지원 매질에 적합한 209개 풀을 사용하고 다른 매질의 391개는 실제 수역/공중 경로 구현 전까지 보류한다. 숫자만으로 600개 전부의 게임 동작을 완료했다고 기록하지 않는다. 자세한 검사 수·원정 경로·실제 캡처는 소관 기록과 검증 JSON을 따른다. E0-C 공동 지표 및 E1 사업·자동화의 선행 조건은 그대로 남는다.

## 공동 지표와 생명체 연결 — 2026-09-06

생명체 모델 완성 후 단독 시드 생태 연결에 이어 공동 원정선의 착륙·지표/지하 이동·굴착·발견·연구·격리 운송·목적지 이식을 구현했다. 소관과 검증 범위는 [공동 지표 기록](../production/12-shared-surface-and-ecology.md)에 있다. 기존 Blender/INK 자산을 유지하며 프로토콜 2와 현재 행성의 압축 기록을 추가했다. 지표 화물에는 행성 ID를 고정하고 재접속·호스트 재시작에서 동일한 저장 상태를 복원한다.

단독 생태의 유효 매질 209개 풀을 공동 세계에서도 동일하게 사용한다. 나머지 매질과 이동/전투 AI, 산업 자동화, 사건/문명, 전 행성 테라포밍/경제, 실제 인터넷은 후속 작업이다. 이 단계는 기능 연결 실증이며 GOTY 수준의 최종 품질이나 전체 설계 완료로 기록하지 않는다.

## E1 — 공동 지표의 산업과 지역 복원 계약

미커밋 기준 렌더 캡처를 `df7e4899`로 보존한 다음, 구매 입문을 기본 메뉴에서 공동 3D 탐험으로 전환했다. 무료 개발 등록·시드별 유한 광맥·개인 사업 배낭/창고·시설 미리보기/클릭 건설·기술/보급·전력/제작·등급 로봇·실제 지형 경로 운반/충전·지역 환경·단일 계약 지급·격납고 회수/다음 행성 재파견을 연결했다. 산업 원형은 새 데이터 파일에 고정하고 생산도 저장 후 공개한다.

검증: 새 사업 규칙 53개, 실제 ENet 6인 사업 경로 254개, 축소 화면 12개 및 기존 확장/1.2 규칙 회귀가 통과했다. 공동 플레이 검사는 조준·F 채광·실제 미리보기/클릭 건설·화물 재접속·산업 동기화·호스트 재시작을 포함한다. 위치 배치와 생산 시간 가속을 사용하며 실제 인터넷이나 장기 사람이 플레이한 결과로 세지 않는다. [현장 사업 소관](../production/13-expedition-industry-and-contracts.md)에 캡처와 제한을 기록했다. 지역 계약은 행성 전체의 환경/소유권·외교 정산이 아니며, 기존 시설의 INK 연결은 전 시설 재모델링 승인과 구분한다.
