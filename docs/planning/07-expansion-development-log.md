# 탐험 확장 개발 기록

2026-09-06 사용자가 설계 커밋 후 전체 고도화의 순차 개발을 요청했다. [고도화 계획](06-exploration-expansion-roadmap.md)의 인수 조건을 따른다. 부분 구현은 E0~E5 전체 완료가 아니다. 추가 렌더링은 사용자가 재확인한 [INK v1](../production/06-rendering-quality-standard.md)을 반드시 유지한다. 수상 수준의 완성도는 목표이며 수상·출시 준비 완료를 의미하지 않는다.

## 기준 커밋

- `1d8c091`: 기존 카툰 작업이 완료된 뒤 공통 INK v1 렌더링·필수 자산 재렌더를 보존.
- `eb316f1`: 탐험·단일 은하·티어/시드·발견 연구·문명·호스트 포함 6인 설계를 커밋.

## 사용자 수정 — 현재 기준

사용자는 초기 성도 중심 실증 화면이 의도와 다르다고 명확히 했다. **주 경험은 우주선을 타고 이동하는 3D 우주 탐험**이며, 목적지를 선택하는 방식도 실제 3D 천체와 우주선 이동으로 표현한다. 성도와 목록은 보조 도구다. 이어서 시드당 행성 목표를 1억 개에서 **100만 개**로 줄였다. 1억 개와 초기 120개 후보 화면은 폐기된 중간안이다.

## E0-A — 100만 주소와 3D 항해 실증

구현: [은하 생성기](../../우주-비즈니스/scripts/domain/universe.gd), [탐험 저장](../../우주-비즈니스/scripts/persistence/world_store.gd), [3D 항해](../../우주-비즈니스/scripts/app/space_flight.gd).

- 한 은하에 논리 행성 1,000,000개, 항성계 250,000개, 성역 50개. 항성계당 4개 행성이다. [생성·비행 설정](../../우주-비즈니스/data/galaxy.json)에 수량·티어 분포·비행 수치를 둔다.
- 세계 원형에 전체 목록을 저장하지 않는다. 행성 번호 1~1,000,000 또는 고정 ID에서 필요한 천체를 즉시 생성한다. 같은 은하 시드·고정 생성 버전이면 같은 후보를 재현한다. 관측·변경 기록만 누적한다.
- 5개 권역에서 중심 방향의 티어 분포가 상승한다. 지형·자원·발견·생태·문명·티어는 SHA-256 파생 스트림으로 분리한다. 실제 착륙 지형과 생물 배치는 아직 후속 작업이다.
- 3D 현장에는 현재 항성계의 천체 4개와 실제 원정선 모델을 만든다. 추진·선회·기수 조절·제동·시점 전환, 천체 조준, 자동 접근, 먼 항성계 도약 후 접근을 연결했다. 궤도 접근 완료 때 조사 기록을 남긴다.
- 별도 저장 `exploration_world.json`에 원형 설정·관측 카탈로그·조사 기록·항해 위치·목표를 보존한다. 기존 `campaign.json`을 읽거나 변환하지 않는다. 손상·이전 형식 원본도 덮어쓰기 전에 별도 보존한다.

### 실제 자료와 표현의 한계

NASA PS의 TRAPPIST-1 d/e/f 기본 문헌 해 3개를 실제 취득했다. [카탈로그](../../우주-비즈니스/data/astronomy/nasa-ps-20260906/catalog.json)에 원본 해시·조회문·취득일·출처·단위·오차·한계·결측을 보관하고 원본과 스키마도 동봉했다. 런타임 천문 API 연결은 필요 없다.

이 실제 천체는 관측 자료 보기에서 구분한다. 현재 항해 공간의 천체·축척·배치·대기는 **가상**이다. 실제 관측에 맞춘 천체의 착륙 지형·기후 통합은 아직 구현하지 않았다. 평형 온도를 지표 실측 온도로 표시하지 않으며 지표 지도·생명 존재는 미확인으로 둔다.

100만 개는 선택 가능한 **논리 주소 수**다. 서로 다른 100만 종의 아트나 발견을 제작했다는 뜻이 아니다. 현재 3종 환경의 절차적 궤도 표현이며 발견·지질·생태의 다양성은 E2~E5에서 별도로 검증한다.

### 우주선과 렌더링

[KESTREL Blender 원본](../../art/blender/ships/kestrel.blend)과 GLB를 만들었다. 편집 가능한 압력 선체·곡면 장갑·전면 유리·외부 화물실·엔진·노즐·센서·출입 해치 구조를 보존한다. 출력은 59,904삼각형이며 재질별 병합으로 드로콜을 줄인다. 공통 INK v1과 [실제 도감 렌더](../production/media/ink-catalog/kestrel.png), 실제 항해 화면을 검수한다. 선내 공간·승무원·6인 탑승 시뮬레이션은 아직 연결하지 않았다.

원거리 항해에서도 화면 윤곽 패스가 카메라 근처에 유지되도록 선체에 연결한다. 지면용 조명 설정을 우주로 무조건 복제하지 않고 승인된 명암·윤곽·형상 기준을 실제 비행 화면에서 확인한다.

## 실행·검증

- 실행: 시작 화면의 **우주 탐험** 또는 `./tools/show_exploration.sh`. W/S 추진, A/D 선회, 위/아래 기수, Shift 가속, Space 제동, C 시점, F 자동 항해, Tab 패널, F5 저장.
- `./tools/test_expansion.sh --with-ui`: 천문 원본 해시·정규화, 주소의 처음·끝·권역 경계, 같은 시드, 10개 시드에 걸친 5,000개 후보, 저장 크기·복구, 실제 3D 이동·접근·도약·마지막 주소·4개 천체 유지와 저장.
- 100만 개 설정의 권역별 표본 평균 티어: **1.138 / 2.000 / 2.982 / 3.984 / 4.856**. 개별 천체의 단조 증가를 보장하는 결과가 아니다.
- 초기 기록 JSON은 약 **6.8 KB**다. 표본 5,000개 생성과 저장·검사까지 최근 검사에서 약 1.32초로 측정됐다. 이는 개별 생성 지연·전체 게임 FPS·방문이 누적된 세이브 성능의 보장값이 아니다.
- 실제 Metal 창에서 `test-results/space-flight/`에 출발·궤도·도약·먼 항성계·축소 화면을 촬영한다. 테스트 입력과 사람이 실시간으로 장기 플레이한 결과는 구분한다.
- M2·1280×800·240프레임 항해 측정: 평균 **16.67ms**, p95 **16.97ms**, 정적 메모리 **122.55MiB**, **62 드로콜**. 우주선 한 대·천체 네 개의 짧은 로컬 측정이며 GPU 전체 메모리·지표·6인 협동 성능을 뜻하지 않는다. `test-results/space-flight/benchmark.json`에 조건을 기록한다.
- 기존 1.2의 기본 게임 회귀 검사를 통과했다. 새 아트는 공통 렌더 계약 검사에도 포함한다.

## 이어서 진행할 순서

1. **E0-B:** 지표·지하·국소 굴착의 연결, 메시·충돌·경계·저장·로봇 이동과 비용 비교.
2. **E0-C:** 호스트 권한·개인 프로필 분리·최대 6인·선내 이동·동시 명령·종료/재접속.
3. **E1:** 공동 항해에서 실제 착륙·무료 개발 등록·채집·자동화로 연결하고 구매 입문 흐름 전환.
4. **E2~E4:** 발견 연구·표본 운송/이식·선체 개발/추첨·사건·문명·계약 정산.
5. **E5:** 다른 원정의 재미, 전체 아트 형상·음향·입력·성능·실제 온라인·플랫폼 검증.

E0-B와 E0-C가 통과하기 전 E1 완료를 선언하지 않는다. Windows 실기와 서로 다른 인터넷 회선의 6인 검증은 해당 환경에서 측정한 근거가 필요하다.
