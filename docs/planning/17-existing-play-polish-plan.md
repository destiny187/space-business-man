# 기존 플레이 완성도 고도화 계획

2026-09-14 사용자 후속 요청: [180 조사](../production/180-existing-game-polish-audit.md)의 보강 항목을 사용자 제보 없이도 추진할 수 있도록 문서로 구체화한다. 이 문서는 후속 개발의 작업 명세이며 **세 묶음 초기 구현·국소 확인 완료** 상태다. 개발자가 기존 요구 안에서 개선 방식과 순서를 정하고 직접 최소 확인한다. 사용자 플레이 기록은 개선을 시작하기 위한 필수 입력이 아니라 우선순위와 체감 품질을 보정하는 추가 근거다.

## 1. 목표와 보존 기준

목표 경험은 **직접 채집 → 필요한 설비 제작 → 반복 노동 감소 → 현장 환경 변화 → 정산과 다음 투자 선택**이다. 각 단계가 별도 메뉴의 기능으로만 존재하지 않고, 앞선 행동의 결과가 다음 행동을 이해하게 해야 한다. 자유 탐험과 직접 작업만으로 진행하는 선택을 유지한다.

| 구분 | 이번 계획의 결정 |
| --- | --- |
| 사용자 확정 방향 | 신규 콘텐츠보다 기존 플레이 고도화, 시각 표현 우선, 파밍·건축·자동화·테라포밍 중심, 개발자가 먼저 구체화 |
| 이번 문서의 설계 선택 | Q01~Q09 순서, 기존 화면에 연결하는 상태/행동 표현, 개인 입력 설정 통합, 단계별 완료 조건 |
| 구현 때 조정할 값 | UI 배율 단계, 음향 레벨/감쇠, 상태 전환 시간, 국소 처리 예산. 데이터로 관리하고 적용값을 제작 기록에 남김 |
| 별도 근거가 필요한 변경 | 가격·레시피·처리 시간·계약 보상 변경은 현재 경로의 실제 병목을 확인한 뒤 해당 값만 조정. 세계 구조·소유권·전투 범위·영구 손실 규칙은 이번 계획으로 바꾸지 않음 |

기존 [FIELD v1](../production/22-uiux-guide.md)·[INK v1](../production/06-rendering-quality-standard.md)을 유지한다. 모델/애니메이션 변경이 필요하면 Blender 원본과 내보내기·Forward+를 함께 확인한다. 음원은 기존 ElevenLabs 자산의 믹스부터 개선하고, 부족한 원본만 ElevenLabs로 제작한다.

첫 안내의 원정별 진행, 자동화 선택, 직접 운송, 개인/공동 재고 구분, 호스트 확정 후 성공 표현을 보존한다. 생물 동작을 맞추기 위해 실제 이동속도를 낮추지 않는다. 지상 대응법 설명 HUD·내부 T 표기·과장된 원형 타격 효과를 다시 도입하지 않는다. 실제 복원 전 환경을 연출만으로 개선하지 않는다.

## 2. 실행 순서와 작업 단위

Q01~Q03은 [181 구현 기록](../production/181-polish-settings-input-and-industry.md)에 연결했다. Q04~Q06은 [182 구현 기록](../production/182-polish-production-and-restoration.md)에 연결했으며 Q07~Q09는 [183 구현 기록](../production/183-polish-combat-audio-and-coop.md)에 연결했다. 각 기록의 실제 확인 범위가 아래 목표 검수 목록보다 우선하며 전체 체감 검수 완료를 의미하지 않는다. 단계마다 실제 변경과 검증 근거가 생긴 뒤 개별 제작 기록을 연결한다. 순서는 작은 확정 문제를 먼저 해결하고, 이후 핵심 루프와 표현을 다듬도록 정했다. 의존성은 작업 분할 기준이며 병렬 에이전트 실행 지시가 아니다.

## 3. Q01 — 설정 하나는 해당 대상만 바꾼다

현재 `client_settings.set_option()`은 감도/음량 변경에도 전체 장면 설정을 적용한다. [설정 코드](../../우주-비즈니스/scripts/ui/client_settings.gd)와 [수면 구독 코드](../../우주-비즈니스/scripts/world/surface_hydrology.gd)를 우선 수정 대상으로 삼는다.

| 변경 항목 | 적용 대상 | 저장·알림 기준 |
| --- | --- | --- |
| 감도·세로 반전·입력 방식 | 개인 입력 해석기 | 카메라/수면/조명 재적용 없음 |
| FOV | 실제 플레이 카메라 | 아이템 미리보기의 구도용 카메라에는 전파하지 않음 |
| 전체/음악/효과/환경 음량 | 해당 오디오 버스·기존 믹스 | 그래픽 신호 발행 없음 |
| 물 품질 | 수면 품질 구독자 | 동일 품질 값이면 메시 재지정 생략 |
| 그림자·후처리·렌더 해상도 | 해당 Viewport/환경/조명 | 변경된 필드만 적용 |
| 전체 프리셋·기본값 복원 | 실제 값이 달라진 항목의 합집합 | 묶어서 한 번 알림/저장 |

슬라이더의 체감값은 즉시 적용한다. 마우스 드래그 종료·숫자 입력 확정·설정창 닫기에서 최종 값을 저장하며, 키보드 연속 조정은 짧은 유휴 구간에서 병합한다. 정상 종료에서도 미저장 최종값을 반영한다. 프로세스 강제 종료 직전의 조정이 이전 값으로 돌아갈 수 있는 경계는 기록한다. 같은 값의 재입력은 적용·파일 쓰기를 생략한다.

기존 15초 화면 복구는 별도 흐름으로 유지한다. 확인되지 않은 해상도/화면 모드가 다른 설정 저장에 섞이지 않게 한다. 오류는 실제 실패했을 때만 표시하며 세계 거래/네트워크를 만들지 않는다. 새로 생성된 카메라·수면에는 등록 시 현재 설정을 한 번 적용한다.

**완료 기준:** 실제 원정에서 감도 드래그 한 번에 무관한 그래픽/수면 적용이 0회임을 확인한다. 최종값 저장·다시 열기, 화면 변경 취소, 수면 품질 변경의 정상 반영을 최소 확인한다. 재귀 순회를 없앴다는 코드 변경만으로 완료하지 않는다.

## 4. Q02 — 설정한 조작과 실제 행동·안내를 일치시킨다

`input_bindings.gd`의 기존 기반을 현재 `crew_expedition.gd`·`firearm_view.gd`·로버/관전 입력까지 연결한다. 모든 물리 키 검사를 이름 있는 행동 조회로 옮기되 기본 키는 그대로 둔다.

행동은 공통 메뉴, 선내/지상, 지상 총기, 비행, 로버, 관전 맥락으로 나눈다. 동시에 활성화될 수 있는 행동끼리만 충돌을 검사한다. 예를 들어 지상의 점프와 비행 제동은 같은 키를 허용하지만, 비행 중 함께 쓰는 두 기능은 충돌 사유를 보여 준다. 텍스트 입력 중에는 게임 행동을 차단하고 Esc의 닫기/취소 역할을 보존한다. 안내·툴팁·가이드의 키 표시는 같은 매핑에서 읽는다.

조준과 지상 질주는 각각 유지/전환 선택을 제공하고 기본은 현재 유지 방식이다. 전환 상태는 메뉴 열기·포커스 상실·탑승/시점 변경·사망·세션 이탈 때 해제하며 저장하지 않는다. 질주에 필요한 이동/스태미나 조건은 그대로 검사한다. 비행 부스트와 제트팩은 별도 동작이므로 이 옵션에 묶지 않는다. 제트팩의 점프 후 해제·재입력 유지 규칙은 그대로다.

UI 배율은 개인 설정으로 100/115/130%를 초기 설계값으로 둔다. 배율은 글자와 필수 클릭 영역을 함께 키우고 상세 영역을 스크롤/재배치한다. 960×640에서도 닫기·실행·필수 비용이 화면 밖으로 사라지지 않게 한다. 색만으로 부족·선택·위험을 구분하지 않되, 기존 상태 HUD에 상시 설명문을 추가하지 않는다.

기존 개인 설정에 없는 키는 현재 기본값을 적용한다. 구형 바인딩은 의미가 같은 행동만 이행하고, R처럼 맥락별 의미가 바뀐 키는 이름만으로 일괄 이행하지 않는다. 새 설정 버전과 이행 결과를 기록한다. 개인 설정 변경은 공동 세계 revision이나 저장을 바꾸지 않는다.

**완료 기준:** 지상 이동과 비행 행동 하나씩 키를 바꾸면 실제 동작·안내가 함께 바뀐다. 같은 맥락 충돌·기본값 복원·메뉴에서 전환 해제와 작은 화면을 확인한다. 전체 컨트롤러/플랫폼 지원 완료로 확대하지 않는다.

## 5. Q03 — 저장 무결성을 유지하면서 행동의 처리 범위를 줄인다

### Q03a. 현재 병목을 개발자가 먼저 확인

사용자 제보를 기다리지 않고 별도 원정 저장에서 장비 선택/제작, 채집, 산업 진행 중 보행, 저장 대기와 겹친 단발 입력을 짧게 살핀다. 기존 진단 도구를 우선 재사용하고 임시 계측은 기본 플레이에서 끈다. 기록은 로컬에만 두며 외부 분석 서비스는 추가하지 않는다.

행동 한 건에 입력 시각·대기 시작/종료·도메인 처리·검증/복사·저장 제출/완료·패킷·화면 적용을 대응시킨다. 중첩 함수 시간은 합산하지 않는다. 해상도·옵션·세계 크기·활성 현장 수·계측 여부를 함께 남긴다. 기존 147/160 기록을 현재 성능 기준값으로 재사용하지 않는다.

### Q03b. 확인된 전체 처리를 좁은 변경부터 제거

1. 개인 장비 부분 초안처럼 쓰기 범위가 명확한 명령을 우선한다. 대상 승무원/재고/영수증과 실제로 변하는 분기를 명시하고, 모르는 명령은 전체 경로를 유지한다.
2. 산업은 운영 중 현장의 생산 시간·재료·전력·결과·예약을 함께 다룬다. 실제로 진행해야 할 시간과 의무 저장을 생략하지 않는다. 현장별 초안을 도입하더라도 현장 간 공유 원장/완료 생산품을 한 번만 확정한다.
3. UI/모델은 영향을 받은 대상 ID와 필드로 갱신한다. 닫힌 화면은 최신 상태만 받아 필요할 때 그리며 카드·지형 전체 재생성을 피한다. 위치 이동만 바뀐 패킷으로 아이템 격자를 다시 만들지 않는다.
4. 부분 검증은 참조·소유권·잔량·영수증 등 관련 불변조건까지 포함해야 한다. 전체 검증은 시작/복구/명시적 체크포인트에 남긴다. 현재 검증과 동등한 안전성을 확인할 수 없는 분기는 전체 검증을 유지하고 비용을 기록한다.

스레드가 쓰는 가변 스냅샷과 공개 세계를 공유해 복사 비용을 숨기지 않는다. 범위 축소로 해결되지 않는 저장 형식 변경/이벤트 기록 방식은 첫 구현에 끼워 넣지 않고 별도 설계 근거를 남긴다. 체크포인트를 줄이거나 성공을 먼저 공개하는 것을 반응성 개선으로 취급하지 않는다.

### Q03c. 사격의 기존 보호를 유지하고 대기를 줄임

현재 사수별 한 건·최대 0.8초 입력 보관, 클라이언트 최대 4건 미응답 제한을 유지한다. 만료/가득 참/장비 변경/메뉴 차단을 구분해 계측한다. 저장 확정 중 탄도 진행 대기가 어느 구간에서 발생하는지 확인하고 Q03b의 원인 제거부터 적용한다. 표시 반동은 기존 예측을 유지하되 명중·피해·격파 성공을 선확정하지 않는다.

대기 중 다른 거래가 변경한 체력/탄약/위치와 충돌하는 전투를 무조건 계속 시뮬레이션하지 않는다. 이를 분리하려면 병합 규칙과 충돌 대상의 순서 보장을 먼저 증명해야 한다. 증명되지 않은 경우 해당 대기는 유지하고 남은 지연으로 기록한다. 버퍼를 늘려 반응성 문제를 가리지 않는다.

**완료 기준:** 수정한 한 행동의 처리 대상·복사량·시간을 전후 비교하고 실제 입력/표시를 확인한다. 같은 요청 재전송의 중복 차감/지급 없음, 저장 실패의 성공 미공개, 확정 중 이동 보존을 해당 변경 범위에서 검사한다. 평균 FPS만으로 순간 지연 해결을 선언하지 않는다. 특정 실행에서 개선된 사실과 남은 비용을 함께 기록한다.

## 6. Q04 — 첫 채집 후 기존 물건에서 다음 목적을 발견한다

새 원정의 01~07 기본 가이드는 유지한다. 끝난 가이드를 다시 강제로 켜거나 다음 설비 건설을 출항 조건으로 만들지 않는다. 이후 안내는 플레이어가 연 기존 화면의 선택 대상에서 제공한다.

| 플레이어가 보는 곳 | 보강할 정보·행동 | 표현 |
| --- | --- | --- |
| 재료/표본 선택 상세 | 현재 알고 있는 사용처와 작업 장소 | 기존 물건 카드 연결, 이름·용도 한 줄 |
| 건설 카드/배치 고스트 | 설비의 실제 역할·필요 조건·작업 범위 | 모델·작동부·범위, 부족 재료 아이콘 |
| 제작 레시피 | 연구/장치/재료/수납 중 실행을 막는 조건 | 주된 사유 하나와 해당 기존 화면/대상으로 이동 |
| 로봇/시설 조준·F 작업창 | 현재 상태와 지금 할 수 있는 조치 | 기존 상태 아이콘·모션, 선택 상세에 짧은 이유 |
| 지도/연구 기록 | 알려진 장소/설계와 현장 작업의 연결 | 선택 위치/관련 항목 강조 |

상태 계산은 호스트가 사용하는 접근/비용/해금 판단을 읽기 전용으로 재사용한다. UI가 별도 가격이나 조건을 추정하지 않는다. 즉시 해결 가능한 사유를 먼저 보여 주고 전체 조건은 선택 상세에서 펼친다. 이미 있는 검색·가능 필터·보급 계획을 유지하며 새 작업 대시보드를 중복 제작하지 않는다.

알려진 자원의 산지 표시는 관측된 지질과 기록만 사용한다. 미발견 광맥의 정확한 위치나 아직 모르는 종/설계를 미리 공개하지 않는다. 화면 이동은 비용 차감/자동 구매/원격 작업을 실행하지 않는다. 플레이어가 다른 목적을 고르면 기존 선택과 안내를 교체한다.

**완료 기준:** 개발자가 현재 기본 원정에서 첫 채집→기존 레시피 선택→부족 조건 확인→실제 작업 장소 도착을 한 흐름으로 확인한다. 미해금/재료 부족/정상 준비 중 해당 상태를 짧게 비교한다. 자연스러운 자유 선택은 사용자 관찰로 계속 개선하되 기능 연결 완료를 그 관찰까지 무기한 미루지 않는다.

## 7. Q05 — 자동화가 실제로 반복 노동을 줄이게 한다

제작·운반의 비용을 없애는 대신 불필요한 재조회와 잘못된 출처 선택을 줄인다. 설비 UI는 현재 레시피가 사용하는 재고를 명시하고, 개인 배낭에 같은 재료가 있어도 접근 가능한 현장 창고 수량으로 합산하지 않는다. 화물의 선택 품목·수량·방향을 유지하고 호스트 확정 뒤 남은 수량을 갱신한다. 가득 참·마지막 한 개·요청 대기는 같은 선택 상세에서 처리한다.

이미 있는 묶음 생산·이동 수량 조절을 현재 제작 화면에 일관되게 연결한다. 최대 제작량은 재료·출력 수납·예약·장치 조건을 포함해 산정하며, 실행 시 현재 호스트 상태로 다시 검사한다. 미확정 재료를 다음 제작의 보유량으로 표시하지 않는다. 수량 조절은 즉시 제작 요청을 보내지 않는다.

로봇은 기존 출고 후 대기를 유지한다. F 작업창의 **자동 전체 / 발견한 자원 선택 / 현장 한 광맥 지시**를 서로 다른 행동으로 구분한다. 작업 중지 사유는 실제 상태에서 추출하고 우선 원인 하나를 보여 준다.

| 실제 상태 | 보강할 표현과 해결 연결 |
| --- | --- |
| 수동 대기 | 정상 정지 자세, 기존 작업 선택 카드 |
| 채광·운반·하역·충전 | 해당 모델 동작·화물/배터리 변화, 선택 상세의 단계 |
| 수납 부족 | 목적 창고 표시와 기존 입출고 진입 |
| 전력/충전 조건 부족 | 관련 설비 위치와 조건 표시 |
| 대상 고갈·등급 부적합·경로 차단 | 해당 광맥/경로 상태와 작업 재선택. 비용 드는 구조를 자동 실행하지 않음 |

수동 생산과 자동 생산을 같은 재료 목표·현장 조건에서 짧게 비교해 직접 조작/왕복이 무엇 때문에 줄거나 늘었는지 기록한다. 그 결과로 필요한 경우에만 기존 작업 반경·생산 시간·재료량을 조정한다. 로봇을 얻는 시간의 임의 목표나 새 자동 운송을 도입하지 않는다. 기존 저장의 예약·화물·남은 전력은 보존한다.

**완료 기준:** 첫 로봇 출고→명시적 작업 선택→채광/운반/하역→정체 하나의 원인 확인과 해결을 직접 볼 수 있다. 기존 흐름에서 제거한 반복 조작을 명시하고, 실제 자동 작업 없이 UI 상태만 만든 것을 완료로 기록하지 않는다.

## 8. Q06 — 환경 변화와 사업 성과를 한 경험으로 연결한다

현재 현장 환경·설비 상태·계약 원장을 같은 시점의 확정 데이터로 연결한다. 기존 지면 습윤/토양/식생·시설 가동·우주 외형은 실제 진행을 표현하며, 각각 별도 성공 조건을 추정하지 않는다. 설비가 멈추면 가동부와 루프음도 해당 원인에 맞춰 전환하고 이미 복원된 지면은 기존 환경 규칙을 따른다.

테라포밍 탭에서는 선택한 설비/현장의 처리 범위·효과를 기존 환경 레이어에 표시한다. 부족 원료·전력·오염원/생존 조건으로 막힌 경우 해당 위치/입력 조건으로 연결한다. 정상 작동에는 긴 설명을 붙이지 않고, 선택한 대상의 멈춘 이유를 확인할 수 있게 한다. 작은 지역 완료를 행성 전체 완료처럼 표현하지 않는다.

단계 지급은 실제 지급 거래가 확정된 뒤 기존 알림에 현장·달성 단계·지급액을 짧게 묶는다. 인계/보유 선택은 현재 자산과 대금 규칙을 재사용해 다음을 비교한다.

- 받는 대금과 이미 받은 금액의 구분.
- 인계되는 현장 시설·로봇·재고, 남는 회수 자산·기술의 구분.
- 시설 보유 시 남는 생산 이용권과 기존 보급/가동 조건.

정산 완료 뒤에는 실제 보유 자금·해금·선체 성능에서 가능한 기존 연구/정비/다음 목적지 화면으로 연결한다. 새 구매를 자동 실행하거나 정산마다 모달을 연속으로 띄우지 않는다. 재접속 시 완료 연출을 다시 재생하거나 보상을 다시 지급하지 않는다.

**완료 기준:** 현재 규칙의 작은 현장에서 직접 준비한 설비가 실제 원료를 써 환경을 바꾸고, 단계 지급/선택 정산까지 연결되는 대표 흐름을 확인한다. 준비 데이터를 쓴 부분은 별도로 밝힌다. 같은 위치 전후 화면과 원장 수치가 일치해야 하며, 초보 평균 완료 시간이나 모든 시드 경제 균형을 검증했다고 확대하지 않는다.

## 9. Q07 — 공격·이동의 원인과 결과를 읽을 수 있게 한다

새 적/패턴을 추가하지 않고 기존 지상·지표 비행 생물·쿠퍼테크·우주전에서 준비→실제 이동/탄도→접촉→회수/반격 시간의 대응을 다듬는다. 호스트 공격 시각과 표시 보간 시각을 분리해 기록하고, 준비 동작이 스냅샷 사이에서 생략되는 사례부터 보정한다. 고속 모션은 실제 이동속도에 비례해 재생한다.

근접 공격 기관의 도달 위치·회수, 발 접지와 정지/선회, 제트팩 상승·해제 자세를 해당 기존 체형에서 확인한다. 실제 피해를 주는 순간과 접촉 효과가 어긋나면 판정/보간 원인부터 고친다. 피해 경고를 텍스트 대응 설명이나 과장된 원형 효과로 대체하지 않는다.

윤곽·파편·실드·피해 숫자가 표적을 가리지 않도록 거리와 중첩을 조절한다. 식생이 시설 접근 지점/필수 단말을 가리는 경우는 기존 배치/표현 경계를 보완하며, 미적 문제를 해결하려고 저장된 자원·시설 위치를 재생성하지 않는다.

**완료 기준:** 변경한 대표 공격에서 피할 수 있는 준비 시점과 실제 접촉/빗나감이 일치하고 기존 무기/도구 피드백을 유지한다. 모델을 고치면 Blender 원본과 Forward+를 확인한다. 대표형 개선을 전종 개별 미적 승인으로 합산하지 않는다.

## 10. Q08 — 생활 소리와 위협 소리의 우선순위를 정리한다

기존 믹스에 맞춰 전체→음악/효과/환경의 개인 조절을 정리한다. 기존 전체/음악 값은 이행하고 신규 효과/환경 값의 초기값은 종전 실효 음량을 보존하도록 잡는다. 더 큰 소리 자체를 타격감 개선으로 취급하지 않는다.

| 상황 | 믹스 기준 |
| --- | --- |
| 채광·로봇·설비·추진의 지속음 | 거리 감쇠·동시 발음 수·루프 연결을 조절하고 같은 원인의 중복 루프를 막음 |
| 자기 피격·실드 파괴·즉각적 위험 | 배경 지속음보다 식별 가능하게 유지. 필요한 경우 짧은 음량 완화 후 자연스럽게 복귀 |
| 적 명중·격파 | 실제 호스트 결과로 한 번 재생, 다수 명중의 과도한 중첩 제한 |
| 환경 복원 | 실제 물/식생/환경 상태와 현재 장소에 따라 기존 환경음의 비중 전환 |
| 메뉴·관전·장소 변경 | 기존 입력/재생 차단 규칙을 따르고 복귀 때 과거 사건을 몰아서 재생하지 않음 |

음향 우선순위·감쇠·동시 발음 상한은 중앙 설정/이력으로 관리한다. 처리 범위는 현재 청취자와 활성 음원으로 제한한다. 청감이 가능한 환경에서는 직접 듣고, 사용할 수 없는 경우 출력 녹음·재생 신호 확인과 청감 미확인을 구분해 기록한다. 사용자의 추가 제보를 음향 정리의 시작 조건으로 삼지 않는다.

**완료 기준:** 기존 채광/추진 반복, 교전의 명중/실드 파괴, 메뉴 복귀를 짧게 재생해 루프 단절·클리핑·누적 재생과 경고 식별을 확인한다. 파일 출력 정상과 장시간 피로도 평가는 별도다. 없는 음원을 생성 완료로 기록하지 않는다.

## 11. Q09 — 함께 일하는 상태와 돌아온 상태를 이해하게 한다

기존 승무원·시설·항해 화면에서 누가 조종 중인지, 어디에 있는지, 탑승/준비 중 무엇이 출항을 막는지 해당 대상에 붙여 보여 준다. 단순 권한 부족과 거리/선박 조건 부족을 구분한다. 읽기 전용 관전/조회에서 공동 자원이나 위치를 변경하지 않는다.

제작·운반·연구의 공동 결과는 대상 설비/재고에 반영하고, 같은 사건의 알림을 모든 스냅샷에서 반복하지 않는다. 새 역할 강제·승무원별 필수 직업·자동 작업 배정을 추가하지 않는다. 기존 FINCH 독립 활동과 호스트의 공동선 권한을 유지한다.

재합류는 저장/호스트가 확정한 위치·장비·화물·배치 상태부터 복원한다. 과거 공격/성공 효과는 소비된 상태로 시작한다. 접속 중이 아닌 승무원의 기존 회수 절차는 유지하고, 재접속 중인 사용자를 자동 구조하거나 자산을 조용히 다른 보관함으로 옮기지 않는다. 저장 실패로 세계가 멈추면 성공 표시를 중단하고 실패 원인과 가능한 종료/복구 경로를 기존 메뉴에서 명확히 전달한다.

**완료 기준:** 변경한 공유 행동 하나와 게스트 재합류를 최소 두 연결에서 확인한다. 공유 자금·개인 재고·위치의 전후 일치와 과거 연출 미재생을 본다. 외부망/6인 검증이 필요한 출시 단계와 이 국소 확인을 구분한다.

## 12. 단계별 마감과 상태 기록

문서만 수정한 단계에는 게임 테스트를 실행하지 않는다. 구현 시에도 기존 테스트 최소화 규칙을 따른다. 각 단계의 실행 확인을 가능한 한 같은 대표 흐름에서 연결하고, 버그나 새 변경 없이 같은 조건을 반복하거나 통과 수량을 늘리지 않는다.

각 제작 기록은 다음 다섯 가지로 마감한다.

1. 플레이어가 보는 전후 차이와 연결한 현재 원정 경로.
2. 한 행동의 입력→도메인→복사/검증/저장→네트워크→UI/모델 갱신 범위. 실패·중복·닫힌 화면 포함.
3. 기존 저장/설정의 이행 방법과 보존한 수량·진행·소유권.
4. 실제 확인한 실행·화면·소리와 필요한 국소 검사, 확인 조건.
5. 남은 지연·미적/청감·네트워크 한계. 기능 연결과 체감 승인 구분.

완료 기준은 검증 계획이지 이미 통과한 결과가 아니다. 성능 목표의 최종 하드웨어/해상도·출시 품질 약속은 별도 사양 결정에 따른다. 수상 여부 대신 현재 원정의 조작 신뢰, 선택의 이해, 노동 감소, 환경 변화의 성취를 실제 산출물로 남긴다.
