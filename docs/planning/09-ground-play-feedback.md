# 지상 플레이 피드백·개선안·확정 결정

2026-09-07 사용자 플레이 제보를 정리한 **초기 문서화 기록(C00)**이다. 아래 문제 7건과 개선 요청 5건은 사용자 관찰이며, 이번 작업에서 게임을 실행하거나 원인을 재현·확정하지 않았다. 과거 검증 통과 기록을 이번 제보의 해결 근거로 사용하지 않는다. 코드·모델·음원은 변경하지 않았다.

사용자의 후속 답변으로 Q1~Q7의 방향을 확정했다. 아래 결정 표는 답변 이력과 소관 문서로의 연결이며, 상세 규칙은 각 소관 문서에서 관리한다. 구체적 조작키·거리·산식·레시피·해금 시점 등 명시하지 않은 사항은 **설계 제안/구현 조정값**이다. 설계 확정이 구현 완료를 의미하지 않는다. 성능 안정화의 후순위 처리는 유지한다.

**최신 정정·위임:** 건설은 가방 실물만 사용하고 창고 자동 보충은 폐기한다. 로봇은 가능한 고등급/직접 선택을 우선한다. 첫 행성 10~20분과 성장에 따른 시간 단축, 현실 범위의 시드 낮밤이 추가 요구다. 환경·로버·운송의 개발 기본안을 위임받아 [개발 명세·시간 계산](10-ground-development-spec.md), [로버·강화 운송](../game/16-rover-and-transport.md), [천체 시간](../technical/08-seeded-planetary-cycles.md)에 구체화했다. 게임 코드는 변경하지 않았다.

**최종 문서 상태: 이번 변경 범위 정리 완료.** 마지막 협동 작업량 제안까지만 추가 승인받아 반영했다. [협동 소관](../game/12-host-coop-and-crew.md)의 입문/상위 티어 계수·시작 인원 고정·규모별 공동 보상 외의 새 페널티나 기능을 추가하지 않는다. 후속으로 C00~C08 구현을 승인받았다. **B1~B6·I1·I2는 구현하고 해당 핵심 동작을 확인했으며, B7·I3~I5는 후속이다.** [구현·확인 기록](../production/46-ground-play-repairs.md).

## 확정 방향의 구현 메모와 보완 제안

Q1~Q7에서 확정한 방향 외의 아래 세부 처리·연출·수치는 구현을 위한 제안이다.

### 채집·건설·창고

- B1은 입력 유지 중 작업이 실제로 재시작되는지, 채집은 되지만 알림만 반복되는지 구분해 조사한다. 준비→진행→성공/거절을 분리하고 정상 주기마다 준비 문구를 다시 띄우지 않는다. 획득은 호스트 승인 결과에만 연결한다.
- B2는 이전의 가까운 창고 자동 보충을 폐기하고 **요청자 가방만 소비**하도록 정정했다. [건축 소관](../game/02-planets-resources-and-building.md). 창고 물품은 먼저 실제 입출고로 가방에 넣어야 한다.
- 재료 미리보기·건설 가능 판정·실제 차감은 같은 가방 원장을 써야 한다. 취소·거절은 차감하지 않고 호스트가 가방 차감과 건설을 한 번에 확정한다. 철거 환급은 기존 현장 창고 규칙을 유지한다.
- B3은 색만 바꾸지 않고 금지 표식과 ‘철 부족’, ‘경사 과다’, ‘다른 시설과 겹침’ 같은 짧은 이유를 함께 보여 준다. 호스트 응답 대기는 성공으로 표시하지 않는다.
- B4는 **Shift+클릭으로 선택 묶음 빠른 이동**, 선택 후 입고/출고 버튼, 자원만 한꺼번에 보관하는 기능을 제안한다. 일괄 보관에서 장착 장비는 제외한다. 만재 시 옮길 수 있는 수량·남은 수량과 이유를 보여 주며, 기존 거리·용량·장비 소유권과 승인 후 수량 갱신 규칙을 유지한다. 세부 키는 내부 구현 선택으로 두고 필수 질문을 늘리지 않는다.

### 로봇과 시설 가동

- B5는 기본 자동 채광·원하는 자원 종류 선택과 함께, 플레이어가 광석 앞으로 가서 **‘로봇에게 채광 지시’**를 내리는 방식으로 확정했다. 명령 한 번에 한 개체만 배정한다. 선택/배정 로봇·대상 표식·거리와 후보가 없을 때의 이유를 보여 주는 세부 흐름은 [로봇 소관](../game/03-robots-and-automation.md)의 제안을 따른다.
- 자동 작업은 허용 범위 안의 접근 가능한 후보를 고르고, 고갈 후 다음 후보를 찾는다. 후보 없음·귀환 불가·창고 만재·충전 불가 사유를 표시한다. 반경 밖의 광맥까지 계속 따라가며 작업 영역이 확장되지 않게 한다. 기존 경로·화물·예약 규칙은 [자동화 소관](../game/03-robots-and-automation.md)을 따른다.
- 역방향 채광은 모델의 전방 축, 이동 방향, 작업 시 회전, 드릴 끝과 광맥의 접촉점을 나눠 확인한다. 이동 모션과 작업 모션을 구분하고, 자원 감소·드릴 동작·파편·작업음이 같은 대상을 가리키게 한다. 원인이나 단순 180도 회전 해법을 미리 확정하지 않는다.
- B6/I1은 시설이 켜져 있다는 사실과 실제 처리 중임을 구분한다. 대기 처리기의 팬/밸브, 물 공급기의 펌프/유량, 온도 설비의 회전부/열교환, 생태 설비의 순환부 등을 후보로 둔다. 전력·입력 부족이면 원인 아이콘과 감속/정지로 전환한다. 조준 시 짧은 상태·처리량을 표시한다.
- 신규/수정 모델은 Blender, 사운드는 ElevenLabs와 기존 제작 자산을 사용한다. 구현 단계에서 실제 Godot Forward+ INK 렌더의 방향·가동 동작·음향을 확인한다. 이 문서 작업에서는 제작·검수를 수행하지 않았다.

### 테라포밍 상태와 탐험 동기

- I2는 행성 이름 아래 **종합 환경 적합도 막대**로 확정했다. 앞서 추천한 계약 목표 달성률 막대는 채택하지 않았다. 상세 항목·산식·평가 범위와 완료 판정 구분은 [테라포밍 소관](../game/04-terraforming-and-sales.md)을 따른다.
- I3는 착륙지의 초반 필수 재료를 유한량 보장하고, 생산 확대에 유리한 대형 광맥·가공용 특수 재료·보석·유적·연구 단서를 지질과 지하 구역에 분산하는 안을 추천한다. 멀리 갈수록 같은 돌만 늘리는 방식보다 지도/스캔에서 목적을 파악할 수 있게 한다.
- 첫 자동화·기초 복원은 근거리, 생산 확대·T2 가공 재료부터 외곽/지하 탐험이라는 Q4 추천안을 승인했다. 분포 변경은 기존 지형·시설·고갈 이력을 보존하며 새 생성 규칙과 기존 저장의 적용 범위를 구분한다.
- I4의 첫 형태·제작·소형 화물칸은 [오픈월드 소관](../game/08-open-world-and-underground.md), 발전 후 한 대의 행성 간 운송은 [우주선 소관](../game/07-space-exploration-and-ships.md)에 확정 방향으로 반영했다. 첫 자동화 이후라는 정확한 제작 해금 시점은 이번 답변에서 확정하지 않았다.
- I5는 구름/안개 이동에 더해 낮밤·태양과 별의 이동까지 포함한다. 진공에는 구름을 억지로 만들지 않는다. 시간 공유·광원·그림자 연결과 주기·태양광 발전 영향의 제안/미정 범위는 [지상 하늘 소관](../production/41-surface-atmosphere.md)에 둔다. 날씨 시뮬레이션·위성 궤도 재현은 추가 확정 범위가 아니다.

## 작업 순서 제안과 확인 범위

### 최종 추가 승인 — 협동 작업량

첫 행성·입문 T1은 추가 인원당 +15%, T2 이상은 +30%의 사업량을 적용한다. 사업 시작에 인원·목표·보상을 고정하고 현재 사업의 합류/이탈에는 재산정하지 않는다. 보상은 실제 규모에 비례하여 공동 장부에 한 번 지급한다. 캐릭터/로봇 성능·개별 제작비·적 체력·안정화 대기시간에 별도 페널티는 붙이지 않는다. 수치 표·적용 대상·저장은 [협동 소관](../game/12-host-coop-and-crew.md), 구현 연결은 [개발 명세](10-ground-development-spec.md)를 따른다.

### 구현 순서

1. **기본 조작·진행 차단:** B1~B4. 채집 유지, 재료 사용, 건설 불가 표시, 빠른 입출고를 우선한다.
2. **자동화가 읽히는 상태:** B5·B6·I1·I2. 자동 배정 정책과 방향, 시설 동작, 복원 상태 표시를 연결한다.
3. **행성 탐험 확장:** I3·I4. 자원 분포와 이동 수단을 함께 설계하고 로버의 우주선 운송은 발전 후 단계로 연결한다. I5는 낮밤·태양/별·광원·공유 시간까지 포함한 별도 환경 작업으로 다룬다.
4. **성능 안정화:** B7은 사용자 요청대로 후순위로 둔다. 현재 원인·FPS·발생 구간은 측정하지 않았다. 추가 연출의 불필요한 상시 연산은 피하되 이번 범위에 전면 최적화를 끼워 넣지 않는다.

위 순서는 제안이며 일정·버전 확정이 아니다. 실제 수정 시 해당 제보를 가장 작은 상황에서 재현하고 수정된 동작·화면·소리만 확인한다. 같은 조건의 반복·전체 회귀·다중 클라이언트·장시간 성능 검사를 관행적으로 실행하지 않는다. 현재 작업의 검증은 문서 누락·상태 구분·상대 링크·변경 내용 확인에 한정한다.
