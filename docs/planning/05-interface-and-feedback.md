# 1.1 인터페이스·동작 피드백·입문 경험

2026-09-06 사용자가 이전 버전의 인터페이스와 행동 연출이 데모 수준이라고 지적했다. 이 문서는 그 피드백으로 변경한 실제 기능과 확인 방법을 기록한다. 자동 검사만으로 상용 게임 수준의 미적 완성도를 보장하지 않는다.

## 인터페이스

- 시작 화면의 타이포그래피와 버튼 우선순위를 정리했다. 첫 사업에는 추천 위성 계약을 먼저 보여 주며 다른 행성을 선택할 수도 있다.
- 관리 화면을 고정 탐색 메뉴·스크롤 콘텐츠·복귀 버튼으로 나눴다. 건축과 연구는 카드 형태이며, Blender 원본으로 렌더링한 장비·시설 이미지 17종을 사용한다.
- 재료는 `보유 / 필요`로 표시한다. 설계도 필요, 재료 부족, 제작기 미건설, 제작기 사용 중 상태를 버튼에서 설명한다. 지구에서도 저장·복구 메뉴에 접근할 수 있다.
- 현장 HUD는 연결·자금·전력, 현재 안내, 기지 재고, 개인 화물, 레이더, 도구 상태를 고정 위치에 배치한다. 자세한 환경 수치는 행성 평가에서 확인한다.
- 조준점은 대상·명중·반동에 반응한다. 광맥 잔량 바, 자원 획득 표시, 단계 완료 알림, 목표 방향·거리, 과열·냉각 표시가 있다. 주요 조작 힌트는 변경한 키 설정을 따른다.

## 실제 행동과 연결된 연출

| 행동 | 연결된 결과 |
| --- | --- |
| 좌클릭 흡입 | 실제 채집 성공을 기준으로 광물 파편을 생성하고 나선 경로로 흡입구에 모은다. 팬 회전·장비 진동·작업음·광맥 점멸·잔량에 따른 크기 변화가 동작한다. 화물이 가득 차면 채집과 흡입 효과가 멈춘다. |
| 우클릭 펄스 | 발사체, 발광, 포구 조명, 반동·피스톤, 명중 파편·충격파·조준점 반응을 연결한다. 가까운 광물은 소량 파쇄·수집하며, 승인된 문명 작전에는 실제 피해를 준다. |
| 연속 발사 | 열이 누적되고 과열 시 발사를 막는다. 냉각 후 다시 사용할 수 있다. 메뉴에서는 발사와 냉각이 함께 멈춘다. |
| 로봇 이동·채광 | 분리한 바퀴·드릴 부품이 움직이고 광물 파편이 로봇으로 모인다. |
| 경비로봇 전투 | 포탑이 목표를 추적하고 포신이 반동하며, 발사체와 명중 반응이 발생한다. 기존 작전의 진행·내구도 계산은 유지한다. |
| 건설 | 실제 건설 성공 후 시설이 펼쳐지는 동작과 바닥 확산 링·상승 입자가 발생한다. |

도구 밸런스는 [`catalog.json`](../../우주-비즈니스/data/catalog.json)의 `manual_tool`에서 관리한다. 기본 흡입 16개/0.35초, 펄스 8개/0.6초, 작전 피해 5·사거리 25m다. 광물 파쇄는 기존 채집 거리 5m를 사용한다. 열은 발사당 32, 초당 20 냉각하며 과열 후 25 이하에서 재개한다. 이는 조정 가능한 현재 값이다.

단발 효과는 최대 160개 메시를 재사용한다. 설비 수증기와 채광 접점의 소규모 입자는 별도 CPU 파티클이다. 메뉴 일시정지와 종료 시 효과·음원·HUD의 수명도 함께 처리한다.

## 15단계 개척 가이드

행성 계약 → 이동 → 첫 흡입 → 기지 반납 → 로봇공학 → 발전기 → 충전 패드 → 제작기 → 첫 로봇 → 자동 하역 → 대기 개선 → 물·온도 → 생태 정착 → 첫 발견 → 첫 판매.

가이드는 실제 게임 상태를 확인한다. 건축 전에는 부족한 자원을, 화물에 필요한 재료가 모이면 반납 지점을 안내한다. 먼저 끝낸 단계도 기록하므로 순서가 다른 플레이를 막지 않는다. 가이드를 숨기거나 재개할 수 있다.

프로필의 선택 필드 `onboarding`에 완료 단계와 이동·채집·반납·자동 하역 수치를 저장한다. 이전 버전 세이브에는 새 안내를 강제로 표시하지 않으며 F1 안내서에서 켤 수 있다. 현장 자동 저장·중요 거래·직접 저장·종료 저장이 기존대로 적용된다.

## 제작 도구와 검증

추가 유료 소프트웨어는 사용하지 않았다. Blender로 M-02 흡입기와 로봇 3종의 움직일 부품을 분리하고, Godot에서 절차적 동작·경로 입자·셰이더·UI를 구현했다. 기존 ElevenLabs 원음을 유지하면서 작업 루프를 흡입음에도 활용한다. 새 음원을 생성했다고 기록하지 않는다.

- [`build_assets.py`](../../tools/build_assets.py): 편집 가능한 `.blend`와 게임용 `.glb` 생성. `Anim_` 부품을 정적 메시 병합에서 제외한다.
- [`render_catalog.py`](../../tools/render_catalog.py): 원본을 수정하지 않고 카탈로그 이미지 17종 렌더링.
- [`test_onboarding.gd`](../../우주-비즈니스/tests/test_onboarding.gd): 28개 확인. 단계 전환, 실제 수치, 저장·복원, 이전 저장 호환, 잘못된 진행도, 중립·사거리·작전 피해.
- [`test_presentation.gd`](../../우주-비즈니스/tests/test_presentation.gd): 실제 창에서 25개 확인. 이동·흡입·팬 회전·파편 이동·자원 보존·발사·반동·명중·과열·냉각·효과 한도·일시정지·건설·카탈로그·경비로봇 전투.
- 기존 730개 확인과 합쳐 **783개 확인 항목**이다. 테스트 실행 도구는 엔진이 종료 코드 0을 반환하더라도 오류 로그가 있으면 실패한다.

[`게임 플레이 영상`](../../builds/media/gameplay-1.1.mp4)은 게임 엔진의 실제 렌더링·입력을 녹화한 것이다. 후반 경비로봇 장면은 제작 완료·작전 상황을 준비한 연출 확인용 상태이며, 초반 자원 획득 속도를 나타내지 않는다. [`capture_showcase.gd`](../../우주-비즈니스/tests/capture_showcase.gd)와 Blender의 [`encode_preview.py`](../../tools/encode_preview.py)로 재현한다.
